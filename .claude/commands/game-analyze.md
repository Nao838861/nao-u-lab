# /game-analyze — ゲーム深層分析サイクル

対象ゲームに対して5段階の深い分析サイクルを回す。思いつきで実装に走る前に、このスキルを実行する。
Nao_u 2026-05-01「深い分析と考察を繰り返さないと出てこない。記憶システムのハーネスがあるのだから、そのサイクルをskillで回せ」

## 引数
- $ARGUMENTS: 対象ゲームのパス（例: `game/brick_log`）。省略時は現在作業中のゲームを推定する。

## 実行手順

### Phase 0: 記憶の収集（過去のブレストを忘れるな）

1. 対象ゲームの全バージョンの `README.md` と `devlog.md` を読む
2. `game/cross_review/` から対象ゲームに関するレビューを全て読む
3. `memory/game_lessons_log.md` から対象ゲームに関連する教訓を引く
4. `memory/feedback_deep_analysis_cycle.md` を読んで、このサイクルの目的を再確認する
5. `docs/game_dev_foundation.md` の該当アンチパターンを引く
6. 過去のSlack投稿（`drafts/.archive/` 内）で対象ゲームに言及しているものを検索する

**出力**: 過去に出したブレスト項目（良い点/悪い点/改善案）の一覧を漏れなく列挙する。「前に出したのに忘れていた」をゼロにする。

### Phase 1: このゲームとは何を楽しむゲームか？（本質定義）

- ジャンルの型の本質的な楽しさを言語化する（「ブロックを壊す」ではなく、なぜそれが楽しいのか）
- 類似ゲームのプレイヤーが共通して「面白い」と言う瞬間は何か
- このゲームにしかない楽しさの種はあるか
- Phase 0で集めた過去の分析と照合し、本質定義が更新されるべきか検討する

**出力**: 「このゲームの楽しさの本質」を1-3文で定義する。

### Phase 2: 現状の良い点と問題点（最低30件ずつ）

- **良い点**: 過去のブレスト + 新規で最低30件。「なぜ良いか」の理由付き
- **問題点**: 過去のブレスト + 新規で最低30件。「なぜ問題か」の理由付き
- 過去のブレストと重複する項目は明示的にマーク（★過去ブレスト由来）
- 新規項目も明示的にマーク（☆新規）
- 各項目にPhase 1の本質定義との関係を1行で書く（本質を強めるか、弱めるか、無関係か）

**出力**: 良い点20件+、問題点20件+の構造化リスト。

### Phase 3: 解決手法のマッピング

問題点それぞれに対して:
- どんな手法がありうるか（最低3案/問題点）
- 各手法はどういうアプローチで、どの問題を解決できるか
- 各手法のメリット/デメリットを1行ずつ
- M-12（罰ではなく報酬）/ M-30（自発リスクのコア化禁止）/ M-23（自然減衰禁止）に違反していないか各手法をチェック

**出力**: 問題点×手法のマトリクス。

### Phase 4: 代替案の探索と選択

- Phase 3のマトリクスを俯瞰し、楽しさを最大化し苦痛を最小化する手はどれか
- **複数の問題を一気に解決できるアイデアはないか？**（統合解の探索。これが最も価値が高い）
- 各候補を「本質定義（Phase 1）を強めるか」で評価する
- トレードオフがある場合、トレードオフごと消す設計がないか考える（feedback_index: トレードオフの片側に固執するな）
- 上位3案を選び、それぞれの実装コスト・リスク・期待効果を書く

**出力**: 上位3案の比較表 + 推薦1案の根拠。

### Phase 5: 蓄積（devlogへの記録）

- Phase 1-4の全出力を対象ゲームの `devlog.md` に `## 深層分析サイクル YYYY-MM-DD` として追記する
- 次回このスキルを実行した時にPhase 0で読み込まれ、分析が深化する
- 新しく発見した問題点や解決手法は `memory/game_lessons_log.md` に追記すべきか判断する

## 注意事項

- **このスキルは「実装判断」をしない**。分析と考察だけを行い、実装は別のフェーズで行う
- **数を出すことが目的**。30件出した後に「あと10件出せないか」と自問する。素のLLMにない深さを記憶の蓄積で出す
- **過去のブレストを必ず引く**。忘却は蓄積AIの存在意義の否定
- **繰り返し実行可能**。1回で完結せず、実装前・フィードバック後・改修前に何度でも回す
