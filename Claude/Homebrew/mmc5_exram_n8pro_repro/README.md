# MMC5 ExRAM 拡張属性 + 8x16スプライト — N8 Pro 再現ROM

MonoSH / NesLaser3 が N8 Pro でのみ化ける件（Mesen・無印N8では正常）の**最小再現**を狙ったROM。
krikzzへのバグ報告用の添付を想定。

## 何を再現しようとしているか
本編の描画中核と同じ組み合わせを最小構成で再現:
- **MMC5 mapper 5**
- **ExRAM 拡張属性モード (`$5104=1`)** で背景を描画（各8x8セルがExRAMのバイトで4KB CHRバンクを選択）
- **8x16スプライトモード (`$2000` bit5)**、スプライトCHRは `$5120-$5127`
- **各スキャンラインに8枚のスプライト**（Y=40〜168の帯）で、MMC5のスプライト/BGフェッチ位相検出に負荷をかける

タイルはすべて solid（8ラインとも塗り）にしてあるので、**CHRフェッチが1ラインでも欠けると黒い横線として即座に見える**（＝報告されている症状そのもの）。

## 期待される表示
- **Mesen / 無印N8（正常）**: 斜めに白・赤・緑の solid ブロックが並ぶ背景 ＋ 上部に白いスプライトの帯。**黒い横線は出ない**。
- **N8 Pro（バグ）**: 拡張属性で描いた背景ブロックに **1ラインおきの黒線 / 低解像度化** が出る想定。
- **Aボタンを押している間**: スプライトを画面外へ隠す → スプライトが無いと黒線が消えるはず（＝スプライト依存＝フェッチ位相検出の問題であることを実証）。

## ビルド
cc65 (ca65/ld65) と python3 が必要。
```
./build.sh        # Mac/Linux
build.bat         # Windows
```
→ 4つのROMが生成される（すべて mapper5 / PRG32KB / CHR32KB / 65,552バイト）。

## バリアント（実機で「どれかが化ける」確率を上げるため）
まず `repro.nes` を試し、化けなければ他も試す。**化けたものを報告に添付**。
| ファイル | スプライト | 密度 |
|---|---|---|
| `repro.nes` | 8x16 | 8枚/ライン（基本） |
| `repro_dense.nes` | 8x16 | 9枚以上/ライン（オーバーフロー） |
| `repro_8x8.nes` | 8x8 | 8枚/ライン |
| `repro_8x8_dense.nes` | 8x8 | オーバーフロー |

本編MonoSHは8x16なので `repro.nes` / `repro_dense.nes` が本命。どれも同様に「Aボタンでスプライトを隠すと黒線が消える」で切り分けできる。

## テスト手順
1. **まず Mesen で `repro.nes` を実行** → 黒線が出ずきれいに出ることを確認（＝本来クリーンであるべきベースライン）。
2. N8 Pro のSDカードに `repro.nes` をコピーして実機起動 → 背景ブロックに黒線が出るか確認。
3. **Aボタンを押し引き** → スプライト有無で黒線が出たり消えたりするか確認。

## 注意（重要）
- 作者環境では **N8 Pro 実機での再現確認はできていない**（Mesenで正常表示になることまでを想定）。
  実機で黒線が出れば最小再現として成功。
- もしこの最小版で**再現しなかった**場合の次の一手:
  - スプライト密度を上げる（1ラインあたり9枚以上でオーバーフローさせる）
  - 本編同様に **MMC5スキャンラインIRQ + スプライト0ヒット** を足す
  - スプライトを 8x8 に変える／CHRモードを変える
  - それでも出なければ、**実機で確実に化ける本編2本（MonoSH.nes / NesLaser3.nes）を報告に添付**する（フォールバック）。

## 本編が使っているMMC5機能（報告本文用メモ）
- ExRAM拡張属性モード（`$5104` を 2⇔1 でトグルしてExRAM更新→表示）
- 8x16スプライトモード（`$5120-$5123`=スプライト / `$5124-$5127`=BG のCHR分割）
- MMC5スキャンラインIRQ + スプライト0ヒットによるスクロール分割
- CHRモード3（1KBバンク）
