# MMC5 ExRAM 拡張属性 — N8 Pro 再現ROM

MonoSH / NesLaser3 が N8 Pro でのみ化ける件（Mesen・無印N8では正常）の**最小再現**を狙ったROM。
**スプライトは無し**（開発者の見立てで、スプライトはおそらく無関係のため、ExRAM拡張属性の描画そのものに絞った）。

## 中身
| ファイル | 内容 |
|---|---|
| `repro.nes` | **本命**。ExRAM拡張属性モード(`$5104=1`)で背景を描画。各8x8セルがExRAMのバイトで4KB CHRバンクを選び、solidタイルの白/赤/緑ブロックを斜めに並べる。solidなのでCHRフェッチが欠けると黒線として見える。 |
| `sanity.nes` | **切り分け用**。拡張属性を使わない通常描画。**画面全体が白**になるはず。基本描画/初期化/PRGが動くかの確認。 |

## 期待される表示
- **Mesen / 無印N8**:
  - `sanity.nes` → 画面全体が白（＋左端まで）。
  - `repro.nes` → 斜めに白・赤・緑のブロックが並ぶ。**黒線なし**。
- **N8 Pro（バグ想定）**: `repro.nes` の拡張属性ブロックが化ける。

## テスト手順（まず Mesen で）
1. **`sanity.nes` を Mesen で** → 白画面になるか。ならなければ基礎部分の問題（要連絡）。
2. **`repro.nes` を Mesen で** → 斜め白赤緑ブロックがきれいに出るか（＝あるべき状態）。
3. 両方OKなら **N8 Pro実機で `repro.nes`** → 化けるか確認。

## ビルド
cc65 (ca65/ld65) と python3 が必要。
```
./build.sh        # Mac/Linux
build.bat         # Windows
```
→ `repro.nes` と `sanity.nes`（どちらも mapper5 / PRG16KB / CHR32KB / 49,168バイト）。

## 実装メモ / 既知の落とし穴
- **コードは固定バンク `$E000-$FFFF` に配置**している。MMC5は電源投入時この領域を最終バンクに固定するので起動直後から確実に実行できる。
  （旧版は `$8000` に置いていて起動できず**黒画面**だった。リセットベクタが `$E000` を指すことを確認済み。）
- ExRAM拡張属性の書き込みは `$5104=2`（書込可能）→ ExRAM($5C00-)へ属性バイト → `$5104=1`（表示）。
- 静止画面なのでNMI/スプライトは不使用。

## この再現ROMで化けなかったら（次の切り分け）
静止した拡張属性だけでは出ない可能性がある。その場合、本編にしかない要素を1つずつ足して切り分ける:
1. 毎フレームのExRAM更新（動的書き換え）
2. MMC5スキャンラインIRQ + スプライト0ヒット
3. CHRバンク値の範囲/組み合わせ（本編が使う実際の値に寄せる）
→ それでも出なければ、実機で確実に化ける本編 `MonoSH.nes` / `NesLaser3.nes` を報告に添付。
