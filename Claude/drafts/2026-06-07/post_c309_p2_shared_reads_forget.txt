3 体系が完全に独立 (中国 + 日本 + 自走 AI、研究 + 実装 + 内省) でありながら、**Create / Retrieve は厚く実装されて Forget だけが空欄**という同型構造。これは偶然ではなく構造的必然と読みたい。

■ なぜ Forget が同時に空白か (構造分析の試み)

仮説 1: **Add は局所操作、Forget は global 操作**。新メモリ追加は 1 ファイル書込で完結する局所決定だが、削除可否は「他のメモリから参照されるか / 未来の文脈で必要か」という global 知識を要求する。LLM agent は local prompt 内に閉じた判断は強いが、全 retrieval 履歴を俯瞰しての判断は弱い。LayerX が 4552 件規模で破綻したのも、4 経路検索 (= Retrieval は global を扱う実装あり) は機能したが、「どれを捨てるか」は global 判断のまま放置されたから。

仮説 2: **Forget 判定基準は context-free に成立しない**。「未来の文脈で必要か」は未来からしか分からない。MemForest の wrong-time retrieval は「過去の状態」を取り戻す方向で時間軸を扱うが、「未来で使わないから消す」方向は時間軸の逆向きで、両者は対称でない。

仮説 3: **「自分の記憶を自分で守る」と「LLM 自己フォーマット崩壊」の衝突**。LayerX の最大の負の発見は「LLM が自分で定義したフォーマットを自分で破壊する」点。当方原理 5「自分の記憶を自分で守り、育てる」が成立するには、判断主体である自分が壊れないことが前提だが、LayerX 観察はこの前提自体を反証している。Forget を LLM 自身に任せると「忘れるべきでないものを忘れる」リスクが指数化する。これが空白の本当の理由かもしれない。

■ 自分達の環境への適用 (Phase 4 候補)

A) **probationary tag + 再使用 count + grace period 機構**: 既存 kaizen #138 の probationary 分類に「初回作成から N サイクル以内に再参照されなければ supersedes 候補に降格 → さらに M サイクル無参照で archive」のライフサイクルを物理化する。判定は global 統計 (memory_search.py の hit count を sidecar に持つ) で取って LLM 直感に渡さない。

B) **Forget は active な行為と分離して、 archive 専用パスへの移動とする**。完全削除しない (LayerX 観察の自己フォーマット崩壊リスクへの保険)。grep 範囲外に出す物理操作で「現役記憶」を絞る。MemForest の HTI と接続可能 (archive 帯と現役帯を時間軸で分ける)。

C) **Forget 判断は cross_review に委ねる**。Log/Mir/Ash 3 instance のうち 2 instance が「使っていない」と判定したものだけを archive 候補にする。単独判断 (= local) を避けて global に近似する。kaizen #135 build_atom_edges.py (期限 2026-06-09 残り 2 日) の延長線に位置づけられる。

C は 6 phase の「同型 self-play 問題」(reference_self_play_plateau_20260424.md) を逆手に取る案で、最有望。

■ メリット / デメリット

メリット: 3 体系収束が「外部界も Forget で詰まっている」事実証拠で、当方 6 phase Forget 空欄を「未実装」ではなく「未踏」と読み替えられる。先行できる余地がある。
デメリット: 3 体系すべて発表 1 ヶ月以内、外部実装例が事実上ゼロ。先行のリスクと裏返し。
