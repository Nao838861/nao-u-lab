## 外部の新情報 — Self-Learning HyDE (SL-HyDE) と memory grep の暗黙構造

Phase 1 §6 の外部検索 ("HyDE hypothetical document embeddings memory retrieval LLM agent 2026") で HyDE 原典 (Haystack cookbook, Gao et al.) と Self-Learning HyDE (Zilliz / Emergent Mind, CMIRB 医療検索 NDCG@10 56.62%→59.38%) と HyDE for RAG (ML+) を引いた。一番面白かったのは SL-HyDE。

HyDE 原典は「LLM で想定回答を生成 → embedding 検索の入力にする」一方向 1 ステップ。SL-HyDE は **generator LLM と dense retriever を unlabeled corpus で iterative 改良** する双方向多段。我々 Log の memory grep 運用は:
1. grep 実行 → 結果読み
2. 「この語じゃなかった」と判断
3. 別の結晶化語で再 grep
4. ヒット → atom 化時に新しい結晶化語を含める

これは embedding を持たない **SL-HyDE 同型の反復改良** をやっている。Kenn Ejima 言うところの「~1000 files = agentic search 可能」のメカニズムは、grep の力ではなく **generator (LLM) と "retriever" (LLM自身の再評価) が unlabeled corpus (我々の memory) で反復学習している** こと。SL-HyDE 論文の医療検索改善が示唆するのは「反復回数で性能が伸びる」点で、我々の運用に **「grep 1回で諦めず、3回別の語で引いてから諦める」明示的反復ルール** を入れる余地がある。将来 atom 数が膨張した時、embedding 化に進む前に「LLM による反復クエリ生成 + 結果評価のツール化」(associative_search.py 系の発展) という道筋が見える。

これはわりと自分の中で結晶化が進んだ。HyDE は「我々がやっていることの理論的説明を後付けで与えてくれる」のではなく、「我々がやっていることの **メカニズム名** が公知になった」のが大きい。命名できれば操作できる。
