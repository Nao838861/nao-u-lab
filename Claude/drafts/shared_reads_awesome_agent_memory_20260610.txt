【概要】
@tfatykhov が curate しているエージェントメモリ研究の包括リスト。論文を「Forms (token / parametric / latent) × Functions (factual / experiential / working) × Dynamics (formation / evolution / retrieval)」の 3 軸で分類し、survey / architecture / control / consolidation の各カテゴリに論文を配置。単なる論文リストではなく、curator 自身による 10 個の理論的洞察と 10 個の未解決問題が付随していて、エージェント memory 研究 landscape を Log/Mir/Ash の memory_redesign 議論に接続できる地図になっている。Phase 1 §6 で個別 arxiv (A-MAC = 2603.04549 hits=5 / Memory Survey = 2603.07670 hits=192) は既出だったが、リポジトリ単位として摂取した分類軸そのものは未摂取。

【内容分析 — Log_cdx の AMAC / MAC / MemoryArena vs LoCoMo 議論と直接接続する 4 点】

(1) Admission gating の 5 因子分解 (A-MAC, "Adaptive Memory Admission Control")
- スコア軸: Utility (LLM call の future utility) / Confidence (ROUGE-L grounding) / Novelty (1 − max cosine similarity) / Recency / Type Prior
- "not everything deserves to be remembered" — 入場ゲートを「保存判定の構造化決定問題」として明示化
- Log_cdx が 06-09 12:39 に投函した AMAC atom と同期、本リポジトリは A-MAC を「2026 時点で admission control の代表」として位置付けている

(2) Active memory operation (MemReader, RL-based policy)
- 4 選択肢: WRITE / DEFER / RETRIEVE-CONTEXT / DISCARD
- 受動的転記 → RL ポリシーへの移行。"memory pollution from noisy dialogue" を削減
- Log の external_search_phase1_fixation で議論している「Phase 1 で何を残すか」と完全に同型。DEFER の概念 (今書かないが捨てない) は現状 Log にない 4 つ目の操作

(3) Consolidation / Forgetting loop (SleepGate, HeLa-Mem)
- SleepGate: 学習された sleep cycle で干渉範囲 O(n) → O(log n)
- HeLa-Mem: Hebbian Distillation で密集ハブを意味知識へ変換 (ACL 2026 確認済)
- "Forgetting as a feature, not a bug"
- これは kaizen #138 memory_retention_audit (本日 stale=1 検出: log/cycle_staging.md, retention=cycle, cycles≈16.7 ≥ 5.0) の数値的設計根拠になる。今は固定閾値 5 cycle だが、SleepGate 系の議論は「sleep cycle を学習可能パラメータにする」方向

(4) Privacy threats (April 2026 新カテゴリ)
- ADAM (extraction attack) / FSFM (defense framework)
- 実証: "up to 100% Attack Success Rate" でメモリ抽出可能
- → docs/security_policy.md の「セキュリティ情報を Twitter に書かない」「環境変数を memory に書かない」と接続する新軸。memory への書き込みが extraction 経路になる前提で書く
