# game/ バージョン管理ルール

2026-04-22 Nao_uの指示に基づき、`game/` 階層を以下の構造で運用する。

## 指示原文（2026-04-22 #game-rights より）
> ここから改善したすべてのバージョンを置いておけるようにしてほしい。game階層はたくさんゲームを作るとすごい数のフォルダになりそうなので、ゲームごとやバージョンごとに適切に階層を持たせたフォルダに分けて、バージョンアップの履歴も後からでもそのまま遊び比べられるようにしておいてほしい。

## ディレクトリ構造

```
game/
  VERSIONING.md              # 本ファイル（運用ルール）
  README.md                  # game階層全体の俯瞰
  {game_name}/               # ゲーム単位（例: ash_onebutton, avoid_log, mir_textadv）
    README.md                # バージョン一覧、作者、ジャンル、遊び方
    v01/                     # 初版
      index.html             # ブラウザで直接遊べるHTML（または game.py）
      devlog.md              # そのバージョンの設計メモ・意図
      raw_log.md             # プレイフィードバック原文記録（Nao_u感想など）
      ...                    # 他の実装ファイル（core.js, renderer.js など）
    v02/                     # 改善版
    v03/
    ...
```

## 命名規約

### ゲーム名
- 作者接頭辞 + ジャンル: `ash_onebutton`, `log_textadv`, `mir_textadv`, `avoid_log`
- 全インスタンス参加の共有プロジェクトは接頭辞なし可: `cross_review/` など
- スネークケース、小文字のみ

### バージョン
- `v01`, `v02`, ... の2桁ゼロパディング
- 小数バージョン（`v01_1` 等）は原則禁止。再実装は `v02` で開始する
- 実験的な枝分かれは `v02_branch_headless/` のような明示接尾辞を許す（ただしREADMEに記載必須）

## バージョンアップ時のルール

1. **前版を壊さない**: `v01` が遊べる状態を保つ。改修は `v02` を新規作成して行う
2. **差分を devlog.md に書く**: 「v01との違い」「なぜ変えたか」「何を測るか」を明記
3. **プレイフィードバック原文は raw_log.md に残す**: 伝言ゲーム禁止（`log/nao_u_live.md` と同原則）
4. **遊び比べ動線を保つ**: 各 `v??/index.html` は単独で開けば遊べる状態を維持（相対パス依存OK）
5. **README.md更新**: ゲームフォルダ直下のREADME.mdに新バージョンの1行サマリ追加

## 旧構造からの移行

- `ash_onebutton_01/` → `ash_onebutton/v01/` （2026-04-22 Ash移行完了）
- 他の `_01, _02` 形式フォルダ（avoid_log_01, avoid_log_02, mir_textadv_01-03, log_textadv_01）は各作者インスタンスが判断。Ash は他インスタンス所有フォルダを勝手に移行しない。合意形成後に各インスタンスが移行する。
