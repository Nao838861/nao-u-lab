# brick_log v03 — 完全予測ガイド + 目標再設計の余地

## 起点（Nao_u 2026-05-01 04:10 #game-rights）

> 前回よりは良くなった。ここからは遊ばないとわからないフィードバック。
> ガイドが出る時間が長くはなったが、それでも1秒程度しか出ず、狙い通りに飛ばすのが難しい為、活用するのはけっこう難しい。このアイデアが出たときから思っていたが、ガイドは常時表示に近づける方が良いと思っている。「予想する楽しさ」は減少するが、それでも操作は必要なのでゲームとしては成立していて、上級者にしかできなかった「狙ったところに飛ばせる楽しさ」が味わいやすくなるという効果は出る。
> ブロック崩しは「静止した目標に対して、熟練すると目標に狙って当てることを楽しむ」ゲームで、過去に他に楽しいゲームがなかったころはその上達そのものを楽しむゲームで、上級者でも静止目標を狙う事しかできないゲームだったが、完全予測で上級者にしかできないプレイを誰でもできるようにすると、目標をもっと違ったものにする余地が出てくる。そういう方向はどうか？みたいなことを自発的に考えてほしかった。

## 自発的に考えられなかったことの分析

### 何が起きたか

v02 で `PREDICT_TRIGGER_DY` を 130→260 (0.5→1.0秒) に伸ばしたとき、「Nao_u が『予測に使えない』と言ったから時間を増やす」という反応的修正で止まった。ガイドの量を増やすという方向は捉えていたが、**「常時表示まで突き抜ける」という方向と「常時化が完成すると目標設計の余地が開く」という上位レイヤを自分で出せなかった**。

### なぜ出せなかったか — 構造的原因の仮説

1. **「どこまで助けると面白さが消えるか」の境界感覚を持っていなかった**: pull_not_force_reading（読まないと損な構造）への警戒が「ガイドを増やすのは依存リスク」一辺倒に固まり、「ガイドを足切りでなく溢れさせると別レイヤが出る」発想が抑制された。
2. **「予想する楽しさ」を聖域化していた**: feedback_pleasure_element_first 系の延長で「予想する楽しさは守るべき快感」と扱っていた。Nao_u は「減少するが操作は必要、別の楽しさが立ち上がる」と等価交換として扱っている。**等価交換の選択肢を私は出さなかった**。
3. **上位レイヤ思考の不在**: v02 までの私の思考は「現在のゲーム機構を維持してガイド表示パラメータを調整する」内に閉じていた。「ガイドが完成すると Breakout の標的設計そのものが時代遅れになる」という上位レイヤ移行を Nao_u 投下まで開けなかった。これは feedback_index #5「知識の存在 ≠ 行動」に近い症状（守破離の守の中での思考停止＝守の内側でしか動けない）。

### 処方の枝分かれ

| 案 | 内容 | 採否 |
|---|---|---|
| α | 単に `PREDICT_TRIGGER_DY` を更に伸ばす（300, 400...） | **不採用**。Nao_u の「常時表示に近づける」を文字通り受ければ「距離閾値そのものを廃止」が直接の処方 |
| β | 距離閾値を撤廃し、ボール飛行中ほぼ常時で予測線を表示 | **採用**（v03 本体） |
| γ | β に加えて、ボール上昇中も予測（壁/天井反射を再帰的にシミュレートしてパドル平面到達まで描画） | **採用**（β を完全形にする） |
| δ | 標的を動かす / 反応する / 連鎖する設計に変更（Nao_u 言う「目標を違うものにする」） | **v04 以降の検討対象**。v03 では実装しない（理由は下記） |

## v03 仕様

### 1. 完全予測ガイド（v02 の Spec E + Spec H を発展）

- `PREDICT_TRIGGER_DY` 廃止。play 中は常時、ボール現在位置から壁/天井反射を再帰的にシミュレートし、軌道全体を描画
- ボール → パドル平面到達点（phase 0、薄水色）と、パドル反射後 → 次衝突点（phase 1、オレンジ）を別色で表示
- phase 1 軌道がブロック群上端 (y<BR_Y0) を抜ける場合は **裏抜け軌道**として金色表示（v02 の Spec H 継承）
- パドル外接触（届かない位置に飛ぶ）は **赤い ✕ マーカ**で「届かない」を明示
- 最大 600 ステップ × 2px = 1200px の ray-march（画面対角の約2倍 = 余裕あり）
- 機構介入なし: ボール速度・パドル幅・スコア・ライフ・クリア条件は v01/v02 と同一

### 2. パドル角度メーター（v02 から無変更継承）

縦縞 3本 + tick mark 上端 4px 突出。中央＝薄水色、左右＝白。v02 で「気付かなかった」→04:50改修で気付ける水準に調整済の設定をそのまま使用。

## 次の問い（v04 以降の検討素材、実装しない）

Nao_u 04:10 末尾「完全予測で上級者にしかできないプレイを誰でもできるようにすると、目標をもっと違ったものにする余地が出てくる」への枝分かれ：

### 枝1: 動く標的

ブロックが横にスライド / 上下に揺れる / 隊列で動く。狙う技術が完成した上で「動く相手に当てる」へ移行。Arkanoid 系の Doh It Again / 弾を撃つボスブロック / Krakout 系。

### 枝2: 連鎖標的

ブロックを特定順序で破壊するとボーナス / 連結ブロックの根を断つ / 色合わせ。狙えるからこそ「どれを先に狙うか」の選択が意味を持つ。

### 枝3: 反応標的

ブロックがボール接近を察知して回避 / 当たりにくくなる位置に逃げる / 一定時間後に消える。狙う技術が完成すると「相手が応答する」関係が成立する。

### 枝4: 手数の制約

弾数制限・時間制限・反射数制限を入れて「狙えるなら少ない手数でクリアしろ」型。

### 枝5: 完全予測の代償

予測が長く伸びるほどパドルが遅くなる / 視野が狭くなる / ガイド ON で点数倍率が下がる。「狙える代わりに何かを失う」二択構造。

→ v03 の Nao_u 評価結果次第で、どの枝に進むか（または別枝）を着手前批判レビュー対象とする。**v03 段階で枝を選ばない**（実プレイ感覚を見ずに枝を選ぶのは希望的観測の素人思いつき＝feedback_pre_impl_critical_review 違反）。

## ヘッドレス自己評価（コード読み）

### 機構非介入の確認

- `computeFullTrajectory()` は `state.ball/paddle/blocks` を **読み取りのみ**、状態を書き換えない（`update()` 関数内に介入なし）
- パドル衝突 / ブロック衝突 / 速度保持 / 壁反射 / ライフ / クリア判定は v01/v02 から完全に同一値（パドル幅72px、ボール速度4.2px/f、ライフ3）

### 描画レイヤの分離

- 予測線描画はブロック描画の後、パドル描画の前。視覚的な前後関係はパドル＞予測線＞ブロック＞背景
- パドル角度メーター（縦縞）は予測線と独立、v02 と同じ位置に同じパラメータで描画

### 再帰反射シミュレートの境界条件

- 最大 600 ステップ（1200px）で画面対角（≒750px）の 1.6倍 = 通常の Breakout プレイ範囲を完全カバー
- 壁/天井反射時、step 内で交差点を線形補間せずに `nx, ny` をそのまま使用 → 反射点が最大 2px ずれる可能性。視認上は無視可能
- ブロック衝突時、phase 1 中なら `phase1StartIdx` から最終 segment まで全部 phase 1 として描画される

### feedback_won_playtest_is_kusoge / M-15 遵守

self-playtest しない。コード上の通過は実プレイ快感を保証しない。実プレイ感覚部分は cross_review (Mir/Ash) と Nao_u 評価に委ねる。
