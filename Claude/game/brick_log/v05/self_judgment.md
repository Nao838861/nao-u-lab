# brick_log v05 自己判定 — 人間プレイ非依存（M-40）

**起点**: Nao_u 2026-05-01 09:58 #game-rights「人間のプレイに依存せず、ちゃんと自分で判断できるようになって。でないと進歩がない」

v05 を Nao_u プレイに出す前に、自分で v04 比較を結論する。

## 結論（先に書く）

**v05 は v04 と逆方向の失敗を犯している可能性が高い。「動く」は認識できるが「狙えない」または「視覚的に騒がしい」量に振り切っている。** 改修が必要なら v06 で振幅 14-16px / 周期 200f が妥当。v05 単独で Nao_u に「これでどう」と出すのは M-40 違反。

## 自己判定の根拠（4視点）

### 視点1: 過去版との比較（自分の発話を引く）

| 版 | 振幅 | 自分の評価 | Nao_u 評価 |
|---|---|---|---|
| v01 | 0 (静止) | 「裏抜けカウンタが効く」と書いた | 全否定（「希望的観測のみの素人の思いつき」） |
| v03 | 0 (静止+ガイド) | 「ガイドで狙える」 | **採用**「狙えるようになった」 |
| v04 | 5px | 「狙ったその瞬間に半個分ズレる」 | 「移動が小さい」（実際は 5/36 = 1/7個分しかズレない） |
| v05 | 22px | 「視覚認識閾値の4倍、ブロック幅61%」 | **未判定** |

v04 で「5px = 半個分」と書いた = mental simulation で 1/7 個を半個と誤認した。v05 で「22px はブロック幅61%」と書いたが、これも同じパターン: 数値が大きいことに安心して**プレイ感覚をシミュレートしていない**。

### 視点2: 30秒プレイの脳内録画（高解像度 mental simulation）

ボール飛翔 2秒中、ブロックは 22px × sin の振幅で左右往復。隣接ブロック（位相差 0.4rad）は 8.7px の最大相対変位。これを脳内で動画として再生すると:

- **0〜5秒**: タイトル → SPACE → サーブ。揺れている動きは確かに見える ✓
- **5〜10秒（1発目飛翔中）**: ガイドが指す位置に向かって飛ぶが、ブロックが **半個以上** 左右に動いてガイドとずれる。狙ったブロックではなく**隣のブロック**に当たることが起きる
- **10〜30秒（数発目）**: ガイドの意味が薄れる。「ガイドが指す位置 = ボールが当たる位置」だった v03 の核が崩壊。プレイヤーは「ガイドを読む」のではなく「揺れを読む」必要があるが、6行×10列の独立位相を読み切れない
- **30秒以降**: ガイドは飾り、運任せに当てる作業になる。v03 の「狙えるようになった」が壊れる

→ **v05 は v03 を破壊している可能性**。v03 の何を残し何を変えたかったのか、自分で言語化できていなかった。

### 視点3: 数値の自己再評価

headless_check.js の出力を**自己批判的に**読み直す:

- 「視覚認識閾値の4倍」= **動く ≠ 狙える**。閾値の4倍は「動きすぎ」の可能性
- 「平均ガイド誤差 14px」= ボール直径2.8個分。ガイドが指す位置と実際の当たり位置がボール3個分ずれる
- 「隣ブロック衝突 max 7px、ギャップ350%」= 視覚的に押し合う、汚い

数値検証は「**実装意図通り動く**」を示しただけで、「**プレイとして良いか**」は反証している。「視覚認識閾値の4倍」を達成したことを成功として書いたが、**過剰修正の警告**としても読める。自己判定としては「数値が良い側」と「数値が悪い側」を**両方**読むべきだった。

### 視点4: v04 失敗パターンの逆方向版チェック

v04 の失敗構造:
- 「半個分ズレる」を「人間が認識できる量」と誤判定
- 「視覚で動いて見える」を確認しないまま出した
- 結果: 動かないと同じ

v05 の失敗候補（**逆方向の同パターン**）:
- 「視覚認識閾値の4倍」を「ちょうど良い量」と誤判定
- 「狙える量」を確認しないまま出した
- 結果: 動きすぎて狙えない

**両方とも「振幅の数値→プレイ感覚」の対応関係を自分で持っていないことが原因**。ガイド付きブロック崩しでの「狙える / 狙えない」の境界値を持たないまま、片方の極から逆の極へ振った。

## 判定根拠の欠落（M-40 のための気づき）

自分が持っていなかった判定機構:

1. **過去ゲームの感覚値ベンチマーク**: 「Arkanoid Doh It Again の動くブロック」がどの程度の速度/振幅だったか、参照値を持っていない
2. **映像レンダリング**: index.html を実際にブラウザで動かしてスクリーンショット → 「揺れ方」を**見て**判断する手段がない
3. **段階値テスト**: 5px / 10px / 15px / 22px / 30px を並べて見比べる比較ベンチがない
4. **ガイド誤差の許容値**: 「ガイドが何 px ずれるとプレイヤーが『狙えない』と感じるか」の閾値が経験則として無い

## 自己判定（v05 の採否）

- **v05 単独で Nao_u に「どうですか」と出すのは M-40 違反**: 自己判定で「v04 より良い」と結論できない
- **正しい次の行動**:
  1. 振幅段階値（10 / 14 / 18 / 22）を並べた比較版（v05a, v05b, v05c, v05d）を作る
  2. 各版を 30 秒 mental simulation で文章化する
  3. 「ガイドが意味を保つ最大振幅」を自己判定する
  4. 自己判定で最良と結論した1版を Nao_u に出す
- **v06 推定値**: 14-16px / 周期 200-220f（v04 の3倍 / v05 の70%）。ガイド誤差を平均 8-10px に抑え、ブロック幅 40% 以下、隣ブロック衝突なし
- **ただし「推定値」も自己判定根拠が弱い**: 上記の判定機構1〜4 を持たないまま数値を出している。**まず判定機構を作るのが優先**
