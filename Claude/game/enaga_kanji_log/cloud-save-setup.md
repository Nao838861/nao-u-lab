# 家族で共有するセーブの初回設定

普通のURLは今まで通り、その端末だけの記録を使う。共有リンクで開いた場合だけオンラインの記録を使う。既存の端末内記録を上書きしない。

## 1. Firebaseの保存先を作る（最初の1回だけ）

1. [Firebaseコンソール](https://console.firebase.google.com/)にGoogleアカウントでログインし、プロジェクトを新規作成する。無料のSparkプランを使う。Google Analyticsは不要。
2. 左メニューの「構築」または「Databases & Storage」から **Realtime Database** を開き、「データベースを作成」を選ぶ。Cloud Firestoreではない。
3. 保存場所を選び、ロックモードで作成する。
4. 「ルール」タブを開き、同じフォルダの [database.rules.json](./database.rules.json) の内容をすべて貼り付け、「公開」を押す。期限付きのテストモードは使わない。
5. 「データ」タブの上部にあるURLをコピーする。例えば `https://プロジェクト名-default-rtdb.firebaseio.com`、または `https://プロジェクト名-default-rtdb.asia-southeast1.firebasedatabase.app` の形。

Googleでのログインが必要なのは保存先を作る人だけ。家族がゲームで遊ぶときはログイン不要。サーバーや自宅PCの常時起動、APIキー、秘密鍵の入力も不要。

## 2. 今の記録から家族用リンクを作る

1. **移したい記録のあるPC・ブラウザ**で、いつもの [漢字の森](https://nao838861.github.io/nao-u-lab/Claude/game/enaga_kanji_log/) を開く。
2. 左下の「この端末に保存」を押す。
3. コピーしたFirebaseのURLを「保存先のURL」に貼る。
4. 「この端末で開いている記録をコピーする」をチェックしたまま、「家族用リンクを作る」を押す。空の記録で始めたい場合だけチェックを外す。
5. 「リンクをコピー」または「家族に共有」でリンクを渡し、「このリンクで はじめる」を押す。
6. iPadでも**同じリンク**を開き、ブックマークする。名前・学習履歴・森・称号などが共有される。

リンクには `#save=長い共有キー&db=保存先URL` が付く。共有キーは自動生成する。同じ保存先URLでも、新たに「家族用リンクを作る」を押すと別のセーブになるので、2台目ではリンクを作り直さず、最初のリンクを開く。

「共有に保存済み」がオンラインへの保存完了。「送信待ち」「通信待ち」は端末に未送信の記録がある状態。通信が戻るか、次に同じリンクを開いたときに再送する。端末の保存容量不足などで端末にも保存できない場合は表示が変わるため、保存ボタンから記録を書き出す。

## 3. 別の端末の更新と重なったとき

同じ家族用セーブを複数の端末で同時に編集すると、勝手な上書きや不確かな統合はしない。共有先にある分と、この端末内にある分を残し、選択画面を表示する。

- **別のリンクに残す**：この端末の分を新しいオンライン保存先へコピーする。
- **書き出して最新を開く**：この端末の分をJSONファイルに保存し、端末内にもバックアップを残してから、共有先の最新記録を開く。
- **この端末で続きを遊ぶ**：この端末内で続ける。競合を解消するまで共有先への送信は止めたまま。

端末を切り替えるときは、元の端末で「共有に保存済み」を確認し、次の端末で同じリンクを開くと分かりやすい。別端末の変更は起動時・画面に戻ったとき・約15秒ごとの確認で取得する。問題を解いている最中には画面を切り替えず、タイトルまたはホームに戻ったときに反映する。

## 管理用メモ

- 共有リンクだけで読み書きできる、家族向けの方式。共有キーを知らない状態での保存先一覧の取得は許可しない。リンクを知っている人には、そのセーブを編集できる。
- Firebaseには `enagaKanji/<共有キー>` ごとに保存。漢字・名前・空配列をそのまま扱えるよう、記録本体はJSON文字列にする。
- FirebaseのETagと条件付きPUTで更新を確認し、HTTP 412なら上書きを止める。応答だけが失われた場合は、保存済みの本文を照合して重複送信を避ける。
- 共有用の端末内キャッシュは、従来の `enaga_kanji_v1` と別キー。共有をやめて通常URLに戻れば、元の端末内記録を使う。
- `cloud-config.json` の `databaseURL` を設定して公開すれば、保存先URLを省略した `#save=共有キー` 形式も使える。未設定でも、アプリが作る家族用リンクには保存先が含まれるので動作する。
- 料金・無料枠は [Firebaseの料金表](https://firebase.google.com/pricing) を参照。
- 条件付き更新の仕様は [Firebase RESTの保存処理](https://firebase.google.com/docs/database/rest/save-data#section-conditional-requests) を参照。
