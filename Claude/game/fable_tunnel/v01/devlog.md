# FABLE TUNNEL v01 devlog

2026-06-11 / Fable 5（fable_swing に続く2作目、Nao_u 指示「今度は3Dのゲームに」）

## なぜトンネルランナーか

3D の固有価値は「奥行き方向の速度感」。2D では絶対に出せない快感はそこにある。トンネルランナーは:

- **速度の快感が画面構造そのものから出る**(壁が流れる、リングが迫る、FOVが広がる)
- 操作は実質1軸（壁面上の角度）だけ。3D 酔いしやすい自由視点を持たず、カメラが常にプレイヤーの「下」を向くので姿勢が安定する
- 先行作: Tempest (1981)、TxK、Race The Sun、Boson X、Velocity 系 WebGL デモ群——「筒の中を走る」は40年検証され続けた型

## 設計判断

| 判断 | 理由 |
|---|---|
| スレスレ通過 → 加速ボーナス | リスクテイクが報酬（速度＝快感の源）に直結する。罰ではなく報酬で危険に誘う |
| 結晶はゲートの隙間へ誘導する配置 | 「取りに行く」＝「正しい回避ラインに乗る」が一致。収集と攻略が同じ動作になる |
| 隙間位置は前ゲートからの連続ドリフト | 完全ランダムだと高速時に物理的に届かない配置が出る。最大ドリフト幅は角速度上限から逆算し、難度上昇に応じて縮める |
| 初回ゲートの隙間はプレイヤー初期位置 | fable_swing v02 の教訓（操作理解前に死なせない）。最初のゲートは「何もしなくても抜けられる」位置から始まる |
| カメラ up = トンネル中心方向 | 回り込むと世界が回る Tempest 型。プレイヤーは常に画面下部に固定され、視線移動が不要 |
| 死因はゲート接触のみ | 死因1つ、ルール1つ。「赤いリング = 当たると死ぬ」は初見で伝わる |

## 実装メモ

- Three.js r160 (CDN, ES module)。index.html 単体、インラインモジュール
- トンネル中心線は重ねた正弦波 `(18sin(0.013s)+12sin(0.0071s), 14sin(0.011s)+9sin(0.0053s), s)`。ゲーム論理は全て path 空間 `(s, θ)` で行い、描画時のみ 3D 座標へ写像（衝突判定が角度比較だけになり頑健）
- トンネル骨格は LineLoop リング64本のプール再配置、ゲートは TorusGeometry の arc パラメータで「欠けたリング」を直接生成
- ダスト粒子 350 個 + トレイル + 爆発スプライトで速度感と死の演出
- WebAudio: ノイズ→バンドパスの風音（速度連動）、結晶=音階上昇、スレスレ=ジング、死=低音ブーム
- スコア/ベストは fable_swing と同じ構造（localStorage）
