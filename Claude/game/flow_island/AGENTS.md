# AGENTS.md — flow_island AI協業規約 (Claude/Codex共通)

このディレクトリのゲーム「流通の島」は複数のAI CLIが交互に開発する。
**どのAIも、作業前にこの順で読むこと**: 本ファイル → [CONTEXT.md](CONTEXT.md) → [WORKLOG.md](WORKLOG.md)末尾 → 必要に応じてREADME.md(版履歴)と `../../projects/production_consumption_sim/design/`・`dialogue/`(Nao_uの指示の逐語原文)。

## 協業プロトコル(Nao_u指定・2026-07-18)
1. **交互ターン制**: Nao_uが各CLIに交互に依頼する。各セッション=1ターン
2. **セカンドオピニオン義務**: ターン開始時、まず前任AIの直近作業(`git log`とWORKLOG末尾)をレビューし、
   同意/懸念をWORKLOGの自ターン欄に短く書く。おかしいと思ったら遠慮なく指摘・修理する(それがこの体制の目的)
3. **セッションの終わりは必ずgitにpush**(未pushで終わるのは禁止)。終了前チェック:
   - [ ] 全テスト実行(`node smoke.mjs`; `node ui_test.mjs`; `node audit.mjs`)。auditは既知FAILを隠さず、直前基準のPASSを後退させない
   - [ ] CONTEXT.mdに新知識を追記(このセッションにしか無い情報をゼロにする)
   - [ ] WORKLOG.mdに自ターンのエントリ追記
   - [ ] Nao_uの指示があった場合はdialogue/に逐語で記録
   - [ ] commit & push(prefix規約は下記)
4. **実行は自走、設計判断は確認**: 承認済み仕様内の実装方法・調査手順・テスト・commit/pushはNao_uへ逐次許可を求めず、ターン終端まで自走する。一方、ゲーム体験・仕様・優先順位・経済原理・大きな構造変更など、結果を左右する未決の判断は勝手に確定せず、推奨案と判断材料を示してNao_uへ確認する。質問中も、独立して進められる計測・probe・レビュー・負債修理は進め、ターン全体を停止しない。CodexのOS/sandbox/command approvalはNao_uの設計判断ではないため、利用可能な権限プロファイル・自動レビュー・既承認prefixで処理し、対話上の許可確認に置き換えない

## 同時編集の衝突防止(2026-07-18追加——実際にE14巻き込み・CONTEXT不一致の2件が起きた)
- ターン開始時に必ず`git pull`。作業中も長考の後は再pull
- **engine.jsを編集するのは同時に1エージェントだけ**(並走時はWORKLOG冒頭に「engine編集中: <名前>」を宣言、終わったら消す)
- 他エージェントが編集した可能性のあるファイルへのパッチは、適用後に必ず実行確認(文字列アンカーのズレは黙って壊れる)
- pushは小刻みに(大きな未pushの塊が衝突の温床)

## 再発防止の6つの網(2026-07-18——「Nao_uに指摘されて初めて気づく」事象クラスの分類と防御)
このセッションでNao_uが捕まえた問題12件の型と、対応する防御。新機構の実装・レビュー時に必ず照合:
1. **ラベルの嘘・見えない機構**(30日収入=売上/賃金=公費調達/分家/人口動態): 新機構には「プレイヤーはこれをどこで知るか」を必ず書く(commitかREADMEに)。表示名は中身と一致させる
2. **自動系のバイパス**(配給/公費/BAIL/分家/移民の蛇口): 金・物・人の湧きと消えは「プレイヤーの選択」か「明示の外部境界(本土)」を必ず通す。**保存則と嘘発見器(貨幣assert+監査E20物資出納)が自動検出**——E20は初運転で麦の記帳漏れ17.6%を検出した実績
3. **数値の裏取りなし設計**(市場3x3のマス数): 実測してから設計(教師データN=49)。容量・サイズ・閾値は現行シムの計測値を根拠に
4. **工程の空白**(通貨フェーズW14/教程W19——同型2回): フェーズ名・見積もりには対応する設計文書が存在するかを確認。「名前だけのフェーズ」は即興=場当たりの予約
5. **原典との乖離**(荷車の商人・鉄チェーン・船の日・独立の定義が原典にありv2仕様から欠落していた): 設計・仕様を書く時は必ず原典(dialogue/kickoff+design/構想文書群)と突合する。意図的な進化には承認記録をリンク。「散文にだけ存在」「原典にだけ存在」の両方向を見る
6. **implemented=correct バイアス**(過払い350%/絶滅職/P汚染): 定期の敵対的スイープをレンズ・ローテーションで(金流→人口・自動系→可視性→整合→性能)。シロも記録する

## 作業規約
- **commit prefix**: ゲームコード=`game:` / 設計・対話記録=`project:` / エージェント運用規則=`rule:`。ゲームと規則の変更は別コミットに分ける
- **エピサイクル禁止**(最重要・Nao_uが繰り返し明示): 場当たりのルール・特例・罰則・閾値いじりを足さない。個別症状より構造で直す。監査の閾値すれすれFAILをパラメータ調整で追わない
- **実測してから設計**: 数値(サイズ・容量・閾値)を提案する前にヘッドレスで現行シムを測る
- **検証はヘッドレス優先**: ブラウザ確認の前にsmoke/audit/ui_testと書き捨てprobe(`.probe*.mjs`、コミットしない)
- **engine.js変更時**: `VERSION`定数とindex.htmlの`?v=`キャッシュバスターを両方上げる(デプロイ=push、GitHub Pages 1-2分)
- 貨幣保存則assert(エンジン内蔵)を絶対に殺さない。違反が出たら喜んで原因を掘る(最強の検証装置)
- 大きい構造変更(盤・道・経済モデル)は実装前に`design/`へ検討文書を書き、Nao_uの裁可を待つ
- インラインコメントを複数定数の行に追記しない(定数を飲み込むNaN事故の前科)
