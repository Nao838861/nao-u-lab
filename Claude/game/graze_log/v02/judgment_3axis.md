## 1. graze_log の core fantasy を3軸で言語化

graze_log は **shooter / bullet-hell 系**。ootamato が悩んだ clicker と**主ベクトルが逆向き**のジャンル。

### graze_log の core fantasy
- **核**: 弾を**かすめる (graze)** 触覚 — near-miss を能動的に取りに行く瞬時判断
- **快感源**: ギリギリで死を回避しながら報酬 (gauge / score) を取る、リスクと報酬の同時発火
- **進行軸**: graze で gauge → Lv1→Lv2→Lv3 の段階的パワーアップ → 弾密度上昇 → 再び graze 機会増 のループ

### 3軸での位置づけ

| 軸 | graze_log の主ベクトル | 補足 |
|---|---|---|
| **介在度の時間方向** | **↑（時間と共に上昇）** | wave 進行で敵密度上昇、弾速上昇、判断頻度↑が報酬。clicker と真逆 |
| **連続-離散** | **連続（フレーム単位の判断）** | 60fps のリアルタイム回避、graze 判定もフレーム単位 |
| **プレイヤー位置** | **操縦者・身体感覚プレイヤー** | 戦略家でも観察者でもなく、手の延長として機体を動かす。Cave/Touhou と同型 |

### autonomy-genre との対比

knowledge/20260509 §接続4 で観察した「autonomy-genre 共通法則 (clicker / embodied-AI / 自律サイクル)」は**介在を足すほど自分を消す**ジャンル。graze_log はその**逆形**で、**介在を足すほど自分が立つ**ジャンル。

→ ootamato 3軸を graze_log に適用すると、「介在度↑」方向の追加は**強化**になり、「介在度↓」方向の追加は**逆向き衝突**になる。clicker と判定基準が反転する。

## 4. 総括 — なぜ無自覚衝突を回避できたか（1段落）

5箇条のうち**逆方向衝突は0件**。これは偶然ではなく、5/5 Nao_u 訂正で確立した **「守段階の削除可能改良1個刻み」制約**（feedback_clone_strategy.md, t:5）が機能した結果である。削除可能改良という縛りは、本質的に「コア体験を変えないこと」を保証する設計上の檻で、戦略レイヤーの philosophizing（v03 着手可否 / Lv 上限拡張 / time-attack mode 追加）を排除する。それらの大きな機構こそが ootamato 機構希釈ジレンマで「無自覚にコアベクトルを引っ張る」リスクの源だが、5/5 訂正で取り下げ済み（post_ash_game_rights_20260505_..._RETRACTED_15-11_no_strategy_philosophize.py）。本cross_review 5箇条は守段階の制約に**強制的に**収まったため、結果としてベクトル方向衝突が物理的に発生しえないレイヤー（数値1段tuning + meta-layer 4件）に留まった。**ただし「逆向き衝突なし」は「強化もしていない」と表裏一体**で、self_judgment.md §4 で指摘した「コア快感天井が低い疑い」は5箇条では解決しない。守段階の安全さは、コア快感天井を上げる作業を構造的に後回しにする副作用を持つ。これは ootamato の悩みと**裏返しの構造**であり、ootamato は「足すと薄まる」状態、graze_log v02 cross_review は「足しても強くならない」状態。両者ともに「コアベクトルとの整合判定が事前に立っていない」ことが共通の上流原因で、本3軸フレームを cross_review 起草時に手元に置いていれば、5箇条のうち提案1と提案2の差（同方向強化 vs 直交）が起草時点で識別できた可能性が高い。次回 cross_review 起草前にも本フレームを引く運用候補を `feedback_clone_strategy.md` に追記候補として残す（即追記はしない、複数事例で再確認されたら昇格）。
