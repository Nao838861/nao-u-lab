## 1. Q1: v03（候補A 実装後）は v02 より面白いか？

**結論**: **Yes（条件付き）** — ただし「候補A の grazeStreak 閾値 5 が tuning ハマった場合」の条件付き Yes。tuning が外れた場合は v02 と同等 or v02 より混乱が増える可能性 30%。

**理由**:

### v03 候補A が v02 より面白くなり得る根拠（mental simulation 由来）

- v02 の **「Lv3 到達後 graze を取りに行く動機が消失」**（v02/predicted_play.md §停滞、Nao_u 5/4 評価で的中）が v03 では構造的に打開される。grazeStreak 経路で「graze する理由」が gauge とは独立に再生成される設計
- 30秒以降の区間で「graze で gauge 復活 → BOMB → graze で active 防御 → ...」のループが発生すれば、v02 で「単調」と評価された区間に**継続的な意思決定**が乗る
- brainstorm.md §3 比較表で「graze_log v03（候補A 採用）は brick_log 同等以上」仮説を立てた。これは「達人プレイの軸」が graze タイミングに加えて「active 防御の発火タイミング選択」が乗ることで成立する想定

### v03 候補A が v02 と同等以下に終わる根拠（裏目）

- SPACE 文脈切替（gauge 状態で B/D が変わる）が**認知負荷として疲労**を生む可能性 30%（predicted_play.md §解釈負荷）
- grazeStreak 閾値 5 が tuning 外しだと「乱発される安いスキル」or「一度も発火しない」のどちらかに転ぶ
- 自然終局装置は v03 でも未追加（戦略レイヤー除外）→ 「面倒になって自殺」で終わる確率は v02 と同様 60% 残る

### 既往ゲームとの快感天井比較（自分のゲームのみ）

| ゲーム | コア快感天井 | 達人軸 | 30秒以降の動機 | Nao_u 評価 |
|---|---|---|---|---|
| avoid_log | 低 | 避ける反射神経のみ | なし | 評価済（壁） |
| brick_log | 中 | 反射ガイドで「読んで打つ」 | あり | 評価済（壁の一段上） |
| graze_log v02 | avoid_log と brick_log の中間 | graze 反射神経 | **なし**（Lv3 後消失） | 「面白くはないがぎりぎりゲーム」 |
| **graze_log v03（候補A 採用、tuning ハマる場合）** | **brick_log 同等以上** 仮説 | graze + active 防御発火タイミング選択 | **あり**（grazeStreak 経路で再生成） | 未確定 |

→ v03 が brick_log 同等以上に届くかは**「tuning が当たって達人軸 2 本目が成立するか」一発勝負**。Yes と書けるが確信は限定的

### v01〜v02 の自分の予測精度を踏まえた校正

- v02/predicted_play.md §2 で 6/6 項目が遡及で的中していた。私の mental simulation は「Nao_u プレイで何が起きるか」を**遡及では概ね当てられる**精度を持っている
- ただし「面白いと思うか」の予測精度は別。v01 出荷時に私は Nao_u が「面白くはないがぎりぎりゲームにはなっている」と但し書きをつける強度までは予測しきれなかった（v02/predicted_play.md §2 末尾）
- 校正後の Q1 答え: **「Yes だが、Nao_u が『面白い』と but 書きなしで判定する確率は別途 Q2 で評価する」**

## 2. Q2: 狙えるか確信度% — Nao_u プレイで「面白い」（but なし）と判定される確率

**結論**: **30%** — v02 出荷時の自己想定 20% から +10pt。

**確信度の内訳**:

| 想定経路 | 確率 | 想定 Nao_u 評価 |
|---|---|---|
| 候補A tuning ハマる + 30秒後ループ発生 | 25% | 「ループが面白い、もう少し続きが欲しい」 |
| 候補A tuning ハマる + 60秒以降に良さが見える | 5% | 「面白い、Lv 上限が物足りない」 |
| 候補A 動機継続するが but 付き | 30% | 「面白くなったが疲れる/混乱する」 |
| 候補A 機能するが v02 同等 | 25% | 「v02 とそれほど変わらない」 |
| SPACE 文脈切替が事故起因の混乱を主にする | 10% | 「混乱する、v02 のほうが素直」 |
| その他（active 防御強すぎ等） | 5% | 「ぬるい / 死ねない」 |

→ **「面白い」(but なし) 判定確率 = 25% + 5% = 30%**。M-40 の 95% ラインには **65pt 未達**。

### v02 確信度 20% との差分 (+10pt) の根拠

- v02 は「ゲーム挙動を変えていない」だった（v02/self_judgment.md §1 Q1）。confidence 増分の余地ゼロ
- v03 候補A は「コア体験そのもの = graze する理由の継続性」に直接介入する → 増分はある
- ただし brainstorm.md §4 確信宣言の「候補A 採用確信度 70%」と本ファイルの「Nao_u 面白い判定 30%」は**別物**：
  - brainstorm.md 70% = 「候補A が v02 の Lv3 動機消失問題を打開する仮説の確信度」
  - 本ファイル 30% = 「Nao_u プレイで but なしの面白い判定が出る確率」
  - 70% × （tuning 一発で当たる確率 ≒ 50%） × （Nao_u が but なしで評価する確率 ≒ 85%）≈ **30%** で一貫

## 3. Q3: 出荷判断 — 出すべきか / まだ出さないべきか

**結論**: **出すべき（条件付き）** — ただし以下の条件を v03 出荷前に満たす:

### 出荷条件 A: 削除可能性の保証

- v03/index.html は v02/index.html からの**追加分が削除可能**であることを README に明記
- 追加箇所: `grazeStreak` 変数 / `triggerActiveDef()` 関数 / SPACE input 分岐 / HUD 1〜2 行
- 削除すれば v02 に戻る

### 出荷条件 B: 出荷文書の役割明示

- README v03 で「**コア体験出荷 = Nao_u プレイ依頼**」と明記。v02 のような「装置追加だけ」ではない
- 削除可能改良の枠で「graze する理由を継続させる」 1 機構のみを足したことを明記
- headless.py は v02 のまま流用、ただし**判定根拠には使わない**ことを README で明記

### 出荷条件 C: 予測責任の事前明示

- 本ファイル + predicted_play.md（実装前作成）が v03/index.html より**先に commit されている**ことを README で参照
- これにより M-39 + M-40 を遡及せずに踏んだ最初の事例として残る

### 出荷判断の根拠

- Q2 = 30% は M-40 95% ラインに届かない。**だが** v02 自己判定 20% で出荷した過去判断との比較で +10pt の改善は意味がある
- M-40 95% ラインは「自己判定だけで判断する場合」の閾値。v03 は **「自己判定 30% + 出荷文書による役割明示」で Nao_u に判断材料を渡す出し方**を取る
- これは v02 で「装置追加だけのつもりで Nao_u プレイ依頼ではなかった」が伝わらなかった反省を活かした出し方
- **守段階の制約**（feedback_clone_strategy.md t:5）下で、削除可能改良 1個刻みの試行を回し続けることが守の通過には必要。30% でも出して評価を受けるサイクルを早く回すべき

### 出さないべきと判定する場合の代替

もし Q2 = 10% 以下なら出さない。30% は「出して Nao_u 評価で下振れたら次サイクル v04 で別候補に切り替え」の強度
