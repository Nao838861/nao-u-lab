## 2. 設計判断

### 2-1. なぜ rng 比率を 60/25/15 にしたか

- **straight 60%** = 「基準パターン」を多数派に置く。プレイヤーは v05.1 までの medium 挙動 (= aimed) ではなく **「真下直線」** を最も多く見る。これは graze_log v05.3 で「基準弾 = 真下直線」と定義し直すことになる。aimed (v05.1 までの基準) はむしろ低頻度の「狙撃」へ役割変更。
- **spread 25%** = 「視野拡張要求」を中頻度に。3way は左右隣接スペースに同時侵入するので、player は単に 1 弾を避けるのではなく **「左右どちらに逃げるか」** の判断を要求される。
- **aimed 15%** = 「即時反応要求」を低頻度に。発射タイミングが短い (50-80f) ので頻度を下げる必要、また「自機狙い」は視覚的に予測しづらく難度を底上げするので低比率に抑える。

合計 60+25+15 = 100% で偏りなし、複数 medium が同 wave 内に出現すれば自然に複合学習段階が成立。

### 2-2. なぜ aimed (= v05.1 までの medium 挙動) を「基準」から外したか

v05.1 までの medium 弾は **全部自機狙い** で、player は「敵を見る」必要がなかった (どの敵から撃たれても自機方向に飛んでくるため、敵の位置だけ把握すれば良い)。aimed を低頻度に下げることで **「自機狙い弾は予想すべきイベント」** になり、敵の見た目 (シアン色) から弾の追尾性を予告する視覚アフォーダンスが成立する。

### 2-3. なぜ spread を長めクールダウンにしたか

3way 同時発射は瞬間的に弾密度を 3 倍にする。クールダウンを基準と同じにすると弾幕が雑になり、(視覚, 応用) セルが ✗ になる (色分けしても密度で見分けがつかない)。長めにすることで **「spread 敵は時々大きく撒く」** という時間アフォーダンスを成立させる。

### 2-4. なぜ evolve は straight のみに残したか

evolve (v05.1 由来 ±10% 弾速変動) は「同じ弾を撃つ敵が時間で速度を変える」効果。spread/aimed は弾パターン自体が違うので、evolve まで適用すると識別軸が混乱する。straight 1 種類に絞ることで evolve の意味 = **「同じ見た目の敵でも、しばらく観察すれば加速する」** が成立する。

## 7. 既知の限界 / 未解決事項

- **headless 自動評価では type 分散の正当性が判定不能** — type 別の dodge 難度が体感閾値で異なるかは実プレイ判定が必要 ([[feedback_headless_unfit_for_unfinished_eval]] 順守)

- **spread の 3way クールダウンが他 type と独立** — spread 連続発生時に画面が spread だらけになる可能性 (rng 偏り) は wave 単位の type cap が必要かもしれない、観察マトリクス (構成, 応用) を確認しながら次バージョンで判定
