## §2 設計判断

### graze→火力の直接接続

「攻撃で稼ぐ感」を測る軸として、最短のフィードバックループを採った:

```
graze 1 回 ──┐
graze 2 回 ──┤
  ...        ├── 10 回到達で BOOST 5 秒 → 敵 hp 1.5 倍速で削れる
graze 10 回 ─┘
```

graze→ブースト→敵が早く落ちる、の 3 段で完結。v06a の「致命hit→stock消費→救援」3 段と同じ層数だが、頻度が違う (graze 10 回は 30-60 秒に 1 回ペース、致命hit は run 中数回)。

### 差分軸を damage に絞った理由

候補は (a) damage 倍率、(b) 弾数増、(c) cooldown 短縮、(d) 弾速向上、の 4 つ。複数軸を混ぜると「何が効いたか」評価できない。staging 指示文 (Phase 3 §着手手順) も「damage × 一定時間」を明示。

medium 敵 hp=3 が 2 発で落ちる (vs 通常 3 発) のがブースト体感の核。small 敵 hp=1 は元々 1 発で落ちるので影響なし → 「ザコは関係ない、medium がサクサク落ちる」プレイ感に集中する設計。

### 自動発火の理由 (操作介入を入れない)

staging 指示文「受動: graze 蓄積による自動発火」順守。v06a も自動発火 (致命hit時)、v06b も自動発火 (graze TH時) で「3 軸並列比較のうち b 軸」の差分要因を「引き金 (致命hit vs graze TH)」に絞る。能動操作版 (例: 蓄積後 SPACE 長押しで発火) は次サイクル以降の bridge 案として保留。

### 5 秒 / x1.5 の数値根拠 (弱い)

staging 指示「例: 5 秒、1.5x ダメージ」を採用。チューニングではなく初期値 (例値) を採る。実プレイで「短すぎる / 効きすぎる」が出たら次サイクルで再調整。今は **3 軸ライブラリの揃え** が目的、個別軸のチューニングは後段。

## §3 実装詳細

### 触らなかった既存機構の確認

```
v05.1 → v06b の touch:
- onGraze 内: grazeBoostCount++ と TH 分岐 (3 行)
- update 内: boostT decrement (1 行) + damage 計算分岐 (1 行) + ヒットパーティクル色分岐 (1 行)
- draw 内: 機体色分岐 + 銀リング描画 (約 8 行)
- drawHUD 内: 行末 BOOST 表示 (1 行差替) + 残時間バー (約 15 行)
- drawTitle / drawOver: 文言 2 箇所
- 新規関数: triggerBoost (約 8 行) + logRunEvent (約 18 行, v06a 移植)
- 定数 / state 追加: 約 10 行
```

active def (`triggerActiveDef`) / BOMB (`fireBomb`) / 救援 stock (v06a) / 弾速 evolve は **一切触っていない**。v06b の boost と v05.1 の active def は独立に発火する (graze 5 連続→DEF READY と graze 10 累積→BOOST が同時進行)。

### 浮動小数 hp の扱い

`e.hp -= 1.5` で medium hp=3 が:
- 1 発: 3 → 1.5 (生存)
- 2 発: 1.5 → 0 (撃破、`<=0` 判定)

整数比較に依存していた箇所は `e.hp<=0` のみで、float でも安全。`fireBomb()` 内の `Math.max(1,Math.ceil(e.hp/2))` も float 入力で正しく動く (Math.ceil で整数化)。

### 視覚フィードバックの強度

ブースト発火は **3 系統** で告知:
1. 中央ポップアップ `BOOST x1.5` (50 フレーム≒0.8 秒)
2. プレイヤー位置から放射する銀リング (36 フレーム)
3. 以降ブースト中ずっと: 機体色 銀 + プレイヤー周囲の脈動銀リング + 画面上の残時間バー + 弾ヒット時の銀パーティクル

「気付かないうちに終わってた」を避ける設計。terminate (boost 終了) には特に演出なし。次サイクルで `boostT===1` 時の残響演出を入れるか判断 (今回は最小差分原則で省略)。

## §4 事前予測 (実プレイ前に書く)

`memory/sense_prediction_log.md` N=21 と同期。要旨:

**「v06b は v06a に勝る」**。理由:
1. **頻度**: graze 10 回 ≒ 30-60 秒に 1 回 ブースト発火 vs v06a stock 消費は run 中 0-2 回。プレイヤーが恩恵を体感する機会が桁違い
2. **接続感**: graze (擦る能動操作) → boost (報酬) が直結。v06a は致命hit (失敗) → stock 消費 (救済) で「失敗起点」のため快感ループにならない
3. **判断余地**: ブースト中は medium を集中して落としに行くプレイ動機が生まれる (= 敵選択の意思決定発生)。v06a は完全に受動

**反証可能性**: もしブースト発火が頻発しすぎて「常時 boost 状態」になると緊張のグラデーションが消える → v06a の方が「ここぞ」感で勝つ可能性。BOOST_FRAMES=300 と GRAZE_BOOST_TH=10 のバランス次第で逆転しうる。
