# lights_out_ash v01 — Lights Out 3×3 clone + ヒント機能 ON/OFF

Ash の clone+1 守の段階の v01。base = Lights Out (Tiger Electronics 1995, 3×3)、独自要素1個 = ヒント1セル光らせモード ON/OFF（削除可能性 ✓）。

設計詳細は [`projects/ash_next_game_planning.md`](../../../projects/ash_next_game_planning.md) §2 / §3 / §4 を参照。本 README は v01 の仕様サマリ + Stage 4 自己判定チェックリストを物理化する。

## clone 仕様 (削除可能性 ✓ — 削除すれば素の Lights Out)

- **盤面**: 3×3 グリッド、各セルは ON / OFF
- **操作**: セルクリックで自分 + 隣接4マス（上下左右、斜め含まず）をトグル
- **勝利条件**: 全セル OFF
- **表示**: 移動カウンタ、リセットボタン
- **盤面生成**: 全 OFF からランダム回数の操作で生成（可解性保証付き）
- **状態空間**: 3×3 = 2^9 = 512 状態（決定的・離散・小）

## 独自要素1個: ヒント機能 ON/OFF (削除可能性 ✓ — フラグ1個の切替)

- ヒント ON 時: BFS solver が現状から全 OFF への最短経路を計算し、最初の1手のセルを淡く強調表示
- ヒント OFF 時 (既定): 強調表示なし、素の Lights Out として機能
- 切替: トグルボタン1個。プレイ中いつでも ON/OFF 可能
- 削除すれば素の Lights Out に戻る — 守の clone+1 として独自要素は最小限

**設計意図** (planning §2 独自a より): 経験層は OFF で挑戦、初見層は ON で学習、両層が**同一メカニクス**から別経路の楽しみ方を引き出せることを仕様レベルで保証する。@nakamuraou のサイフォン例の構造的相同。

## 良点 12 / 悪点 13 (`feedback_clone_strategy.md`「最低十数個ずつ」)

planning §2 から転記。

### 良点 12

1. ルール1行で説明可能（= 初見層フックが軽い）
2. 状態空間小で headless 親和性高い
3. 解の存在は線型代数で判定可（経験層フック）
4. 1980-90 年代 Tiger Electronics の物理玩具で歴史検証済み
5. 5×5 への拡張で長寿命化可能（守を抜けた段階で破の余地）
6. 連鎖反応の visual feedback が即時報酬になりうる
7. ヒント1セル光らせで難度勾配が連続化（難しさを離散ステージに分けなくて良い）
8. UI が grid 1個で完結（描画コスト最小）
9. AI 自プレイ Stage 4 が「最短手数 + ヒント無で何問解けるか」で言語化可能
10. ジャンル内の代表作が1本（Lights Out）で論争にならない（= base 選定の philosophizing を回避）
11. 既存ライブラリ依存ゼロで実装可能
12. 「全消し」というゴール状態が universally readable（文化文脈不要）

### 悪点 13

1. 派手さがない（visceral 報酬が控えめ）
2. 状態空間が小さすぎて30分以内に飽きる懸念
3. 5×5 にすると難度ジャンプが急（3×3 = 512 状態 → 5×5 = 33,554,432 状態）
4. ヒント機能を切ると初見層が即詰まる懸念（ON/OFF の切り替えタイミング設計が要）
5. 連鎖反応の visual を派手にすると「visceral 過多→reflective 不在」になり経験層フックが消える
6. ランダム生成盤面の可解性保証アルゴリズムを実装ミスると詰み盤面が混入
7. 「最短手数」表示が攻略済プレイヤーには不要、初見層には plot spoiler
8. 1人プレイ専用で対戦・協力の拡張が限定的
9. クリア演出なしだと達成感が物理ボタン版より薄い（Tiger 物理玩具の触感が補っていた）
10. mobile UX（タッチ）を想定すると 3×3 では指のサイズで誤タップ率高
11. 「ヒント光らせ」を実装すると「経験層は ON で甘え、初見層は OFF で投げる」逆転リスク
12. headless で「最短手数到達率」を計ると、Solver が完璧に解けてしまい「面白さの欠如」を切り分けられない（校正前 headless 不適合の構造）
13. 後追いの駄作 perception (knowledge/20260509_ns7) に対する免疫が弱い（= ジャンル代表作1本に対するアレンジ自由度が狭い）

悪点 #12 は §校正前提との整合 で処理。残り12件は v01-v02 改良対象として記録。

## 自動化可能層 / 厚み層の分離 (`feedback_prediction_responsibility.md` 二層分離)

### 自動化可能層: BFS solver = 校正不要な難度分布計器

- v01 着手時に BFS solver を実装予定 (3×3 = 512 状態の全探索、計算量 O(2^9) で頭打ち)
- ランダム生成盤面 100 個に対し「最短手数の分布」を取る (期待値: 平均 4-5 手、最大 9 手)
- 判定軸: 最短手数分布が「2-7 手帯に 80% 以上が入る」 = 守の最低再現成立。「1 手で解ける盤面が 30% 以上」 = 簡単すぎ、「8 手以上が 30% 以上」 = 難しすぎで離脱予測

**校正前提との整合** (`feedback_headless_unfit_for_unfinished_eval.md` t:5):

BFS solver は「面白さの計器」ではなく「盤面難度分布の計器」。出る数値は最短手数の整数で、ルール定義から決定的に出る論理量。**校正不要** (= 計器の前提が「面白さを測る」ではなく「ルール上の解の存在と長さを返す」のため)。

ただし「最短手数分布が良い → ゲームが面白い」の換算は厚み層 (Ash 側自プレイ判定) で行う。BFS solver の数値を直接「面白い」「面白くない」の判定根拠にしない。`[Calibrated? No — solver は難度分布計器、面白さ計器ではない]` を分布出力の脇に明記する。
