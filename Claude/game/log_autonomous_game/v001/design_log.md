## Q-A: 中心入力ゲート

**方針**:
- 中心入力 = `Space` (1秒先予測ロック発動)。プレイヤー位置を「1秒後の予定座標」として記録、1秒後に到達できれば成功フィードバック
- 副入力 = `矢印キー` または `WASD` (移動、1つの入力系として扱う = 4キーで1機能)
- タイトル開始: `Space` 単押し
- リトライ (Game Over / Time Out / Clear): `Space` 単押し
- Space 連打を防ぐため、1ロック中はロック解除まで再ロック不可

**禁則**:
- Shift / X / Z など追加機能キーを増やさない
- マウス / クリック / 画面内ボタンを作らない
- 「リトライボタン」を画面内ボタンと誤読しない
- 矢印キーと WASD 同時対応は許容するが、Space 以外の機能キーは追加しない

**検証手段**:
- ヘッドレス: イベント検出ログで「Space 以外のキーが機能を発火していない」確認
- 視覚レビュー: タイトル画面に `PRESS SPACE` 1行 + 副題 1行のみ、操作説明の長文がないこと
- self_judgment.md で「中心入力が Space であることが体験で伝わるか」を 5 段階自己採点

## Q-B: 特殊システム3状態ゲート

特殊システム = **1秒先予測ロック**。

**方針**:
- 状態1 (発動不可): ロック中、まだ1秒経過していない → プレイヤー周辺に細いリング (動かないと意味薄)
- 状態2 (発動可能だが意味薄い): ロック解除済、しかし周囲に敵弾予測軌道なし → プレイヤー側表示控えめ、敵弾ゴーストも控えめ
- 状態3 (発動可能で意味あり): ロック解除済、周囲に敵弾予測軌道あり → 敵弾予測ゴーストの輪郭強調 (シアン)、プレイヤー側リング少し強める
- ゲージはゼロから始める (起動直後は状態1 = ロック中扱い、1秒経過で状態2 へ)
- 状態区別は **対象物側 (敵弾の予測軌道ゴースト)** で行う (Pulse Relay 教師差分 §6 準拠)

**禁則**:
- 常時 `LOCK READY` 文字を画面に出さない
- クールダウン秒数を文字で常時表示しない
- 3状態を同じ画面表現にしない
- 説明文を画面下部に常時出さない
- 発動可能だが意味がない状態と、押せば意味がある状態を同じ表示で済ませない

**検証手段**:
- 視覚レビュー: 3状態それぞれでスクショ取得、Log 自身で判別可能か 5 段階自己採点
- ヘッドレス: `lock_state=0/1/2` を 100ms 刻みでログ、1プレイ内で 3 状態全てが発火することを確認
- 「Pulse 発動などのボタンは Space だけ」(Nao_u 原文) を Log 文脈で「予測ロック発動は Space だけ」に翻訳して適用

- 推理ゲーム log_mystery で fact-list → hook 駆動 に書き直した教訓 (commit d6637271323d) を踏まないこと

## Q-成功FB ゲート — 3層階段判定 (新規 / Mir 5/25 千葉集 planetary_gear 構造より)

**方針**:
- 予測ロック結果を 3 状態で返す:
  - 状態1: **予測当** (ロック位置に到達 + 敵弾予測軌道を回避できた) → 強い光 + シアン爆発 + Relay 進行
  - 状態2: **予測外** (ロック位置に到達できなかった or 敵弾予測軌道と重なった) → 短い赤フラッシュ + Relay 停止
  - 状態3: **予測未立** (ロック使用なし期間が 3 秒以上続いた) → 画面端の Relay ゲージが灰色化、「予測を使わない時間が長い」サイン (= 千葉集「予測そのものを立てなかった時」の可視化)
- 1秒ごとに状態1/2/3 のいずれかに必ず判定が落ちる連続性

**禁則**:
- 状態1と状態2を同じ画面反応で済ませる
- 状態3を「何もない」=ノーフィードバックにする (= 千葉集分析の本義「予測未立を可視化する」が失われる)
- 派手なエフェクトで状態の区別を曖昧にする
- Relay ゲージを常時文字で説明する

**検証手段**:
- 視覚レビュー: 状態 1/2/3 を各 3 回ずつ意図的に発生させ、スクショで区別可能か
- ヘッドレス: `feedback_state=1/2/3` のログを発火タイミングごとに記録、1プレイで全状態が発火することを確認
- 悪いプレイ方針検証: 「ロックを一度も押さない」プレイで状態 3 が連続発火し、Relay が灰色のまま終わることを確認

## Q-C: 敵出現/退場ゲート

**方針**:
- 敵種は **4 種** (v001 では大型 E を省略してスコープ縮小):
  - A: 直進小型 (学習用、撃たない/1発撃つ)
  - B: 編隊小型 (V字/斜め列、役割でずらして射撃)
  - C: ダイブ敵 (予告軌道 0.3-0.8s → 突入 → 退場)
  - D: 横断敵 (左右端から入り反対側へ抜ける、中央付近でのみ射撃)
- 各敵に `出現 -> 見せ場 -> 攻撃 -> 退場` フェーズ
- 退場方向は入場方向と整合 (上→下/斜め下、左右→反対側)
- 70-90 秒カーブ準拠: 0-4s タイトル / 4-12s 学習 (A 中心) / 12-25s 基本混合 (A+D) / 25-40s 予測価値提示 (B+ロック対象弾) / 40-58s 中盤圧力 (C+B) / 58-75s 終盤 (A+B+C+D 同時) / 75-90s 終端

**禁則**:
- 画面下部に来たら急加速して退場 (Pulse Relay v003/v002 共通の失敗パターン、絶対回避)
- 退場理由のない `y` 速度追加
- ワープに見える移動
- 画面下端に来たから消える処理
- `y > 画面高さの0.56` のような条件で突然速度を足す処理

**検証手段**:
- `enemy_behavior_audit.js` (Pulse Relay v003 から流用): 敵ごとの最大フレーム移動量ログ → 退場直前の跳ね検出 = 0
- 画面内滞在時間ログ: 非ボス敵が **15 秒以上画面内に居ない**
- 視覚レビュー: ステージ通し再生で各敵の `出現 -> 退場` の意図が読めるか

## Q-D: 弾/攻撃元ゲート

**方針**:
- 敵は **画面内かつ可視状態** でしか射撃しない (射撃可能矩形を明示: 敵中心が `y in [0, screen_height * 0.85]` かつ退場フェーズでない)

- 弾速 (BULLET_SPEED=2.0 / 120 px/s) は人間が本体の動きを目で追える速度域に維持

**禁則**:
- 敵の中心が画面外にあるのに射撃
- 退場中の射撃 (退場フェーズに入ったら射撃停止フラグ)
- 弾発生地点が画面内に見えるかを検証しない
- 1秒先計算結果を画面に流出させる (予測軌道線・×マーカー・ゴースト末端表示は禁止。Nao_u 2026-05-26 06:10「軌跡+×印が邪魔で逆によけにくい」批判の構造処方)
- 弾速が速すぎて本体の動きを読み取れない

## Q-G: 計測ゲート — agent 難易度プロキシ runner (新規 / C242 Phase 4)

**方針**:
- 「素朴良手 agent」(Space を約2秒に1回 castLock + 中央バイアス nospecial 移動 + 微小ノイズ) を 30 試行 (各 60秒 = 3600 frame) headless 実行し、4 指標中央値を JSON で出す
- 4 指標: `median_clear_wave` (到達 wave 数) / `median_residual_hp_ratio` (生残率、v001 は 1-hit kill のため binary) / `median_play_time_sec` (生残秒数) / `median_graze_count` (弾本体外殻 30px 圏に入った distinct 弾数)
- v001 ⇄ v002 で同じ runner を回し、4 指標差分を「人間体感難易度の変化の代理」として読む
- 出典: Chang Xiao & Brenda Z. Yang "LLMs May Not Be Human-Level Players, But They Can Be Testers" (arXiv:2410.02829, 2024-10-01) — Wordle agent 推測回数 vs 人間 Pearson r=0.624、Slay the Spire Act 1 agent 残存 HP 比率 vs 人間ボス突破率 r=0.871

**禁則**:
- 本 runner の数値だけで採点 5 を確定しない (確定 5 は実機判定依存)
- 人間体感との Pearson 相関を測らずに「proxy が人間体感と一致する」と書かない
- v001 単独計測値を絶対値として読まない (差分の lever として使う)
- 論文の Wordle/Slay (ターン制) と v001 (リアルタイム弾避け) の構造差を無視して相関保証を主張しない
- 良手 agent の cadence/policy を後から黙って変えない (cadence 変更時は v001 / v002 双方を再計測してから比較)

**検証手段**:
- `node agent_difficulty_proxy.js` で 30 試行完走、JSON に 4 中央値 + death_cause_breakdown + all_trials が出ること (exit 0)
- v001 baseline 値: median_play_time_sec=10.0 / median_graze_count=5.5 / median_clear_wave=1 / survival_rate=0 (素朴良手でも wave 1 内で bullet 死 → 5 体同時発射時の認知負荷が Q-D-1 失点と整合)
- v002 改修後の再計測で 4 指標がどう動くかを差分読み、Nao_u 体感ランキングと proxy ランキングを 3 サイクル運用後に対照
- 一致なら proxy 採用継続、不一致なら `feedback_*` に負の知見として書き戻し proxy 装置撤去

**What this proves**:
- v001 が「素朴良手でも 10 秒前後で死ぬ」baseline 値 = v002 改修 lever として絶対値で参照可能
- 4 指標 × 中央値で v001/v002 比較が JSON 差分のみで読める = ヘッドレス出力が「次の playable diff 候補のランキング」化に進む (Nao_u 5/22 批判「ヘッドレス検討で頭止まりは流速低下の予兆」への構造的応答)

**What this does NOT prove**:
- 人間体感難易度との Pearson 相関 (本サイクルでは未測定、3 サイクル運用後判定)
