## 1. ミミクリ宣言

**この v007 は「未知空間を読む探検家ごっこ」 + 「LLM 空間理解ごっこ」の二重ミミクリ実験**。

- **表層 (player layer)**: 1 部屋に入った瞬間に「あの隙間 / 壁の形 / 床のパターンに何か意味がある」と読める探検家。アビリティ取得後に「あ、あの隙間はこれで通れたのか」と回収する体験
- **裏層 (Log layer)**: Echo-Path 系統 (時間軸 1 秒先予測) から空間軸 (配置 / 隙間 / アビリティ解放) への軸変更を Log 自身が headless で観測し、v003 wave-rider 反証経験との **軸の直交性** を体験する
- **禁則**: 「メカニクス的に正しい改修」(マップ拡大 × アビリティ追加 × アイテム追加の積上) で核を冷やしてはいけない。核は「1 画面で？が立つ」体験で、これを上回るマップ拡大は採用しない (Civ7 文明 if 歴史ごっこ崩壊の同型事故防止)
- **Echo-Path 系統との対比軸明示**: STG パイロット (時間軸) ↔ 探検家 (空間軸) = ミミクリ核を意図的に直交させる方向

**game/* 側で物理化する責任**:
- `index.html` のタイトル / 説明、`game.js` のタイトル副題 / 死亡時メッセージは「探検家ごっこ」の語感から逸脱しない (例:「探索 RPG」「ダンジョン Crawler」「メトロイドヴァニア」は何のごっこ遊びか消えるため使わない、「アビリティ獲得アクション」「マップ解放ゲーム」も避ける)
- `self_judgment.md` (次サイクル以降起票) §Q-ミミクリ で「核を上回るマップ拡大が無いか / プレイヤーが『探検家感』を味わえる初期画面か / 1 画面で？が立っているか」の 3 項目を採点軸として常設

## 3. Q-A: 中心入力ゲート

**方針**:
- 中心入力 = **アビリティキー (Z 単押し)**。アビリティ発動 = 1 ボタン
- 副入力 = **矢印キー** または **WASD** (移動、1 つの入力系として扱う = 4 キーで 1 機能)
- タイトル開始: `Space` 単押し (Z はアビリティ専用、タイトル / リトライは Space に分離)
- リトライ (Game Over / Clear): `Space` 単押し

**禁則**:
- Shift / X / C / マウスクリック / 画面内ボタンを増やさない
- アビリティ 2 種以上 (Z / X 同時使用) は本 v007 では禁止。1 アビリティのみ
- インベントリ / メニュー画面は作らない
- 「リトライボタン」を画面内ボタンと誤読しない

**Echo-Path 系統 Q-A との対比**:
- v001 Q-A = Space 単押し (1 秒先予測ロック)
- v007 Q-A = Z 単押し (アビリティ) + 移動 = 入力系は 1 個増えるが、中心入力 1 ボタン原則は維持。Space を残すと「Echo の延長」と誤読される懸念で Z に変更

**検証手段**:
- ヘッドレス: イベントログで「Z / 矢印キー / Space 以外が機能を発火していない」確認 (Space はタイトル / リトライ専用、ゲーム中は無効)
- 視覚レビュー: タイトル画面に `PRESS SPACE` 1 行 + 副題 1 行のみ、操作説明の長文がないこと

## 4. Q-B: 特殊システム 3 状態ゲート

特殊システム = **アビリティ (例: ダッシュ / フック / 透視 / 二段ジャンプ から 1 つ選択)**。本 v007 設計時点では **ダッシュ (短距離高速移動 + 通過中無敵)** を第 1 候補として採用、brainstorm で他候補と比較。

**方針 (ダッシュ案)**:
- 状態 1 (発動不可): アビリティ未取得時 / クールダウン中 → プレイヤー周辺に細いリング (グレー)
- 状態 2 (発動可能だが意味薄い): アビリティ取得済、クールダウン明け、しかし周囲に通過対象の隙間 / 壁なし → プレイヤー側表示控えめ
- 状態 3 (発動可能 + 意味あり): アビリティ取得済 + 周囲にダッシュで通過できる隙間 / 壁あり → プレイヤー周辺リング点滅 + 通過対象の隙間 / 壁にゴーストハイライト

**Echo-Path 系統 Q-B との対比**:
- v001 Q-B = 1 秒先予測ロックの 3 状態 (時間軸 0/中/1 秒経過)
- v007 Q-B = アビリティの 3 状態 (空間軸 無効 / 可能 / 意味あり)

**禁則**:
- アビリティの段階アップグレード (二段強化 → 三段強化) は本 v007 では禁止。1 アビリティ 1 段階のみ
- アビリティ使用回数制限 (3 回まで → リチャージ) は本 v007 では禁止。クールダウン式のみ

**検証手段**:
- ヘッドレス: イベントログで「状態 1 → 状態 3 の遷移が空間条件 (隙間 / 壁の近接) で発火している」確認
- 視覚レビュー: 状態 1/2/3 の表示差分が「同じ画面で 1 秒以内に判別可能」確認
- self_judgment §Q-B で「アビリティ 3 状態がプレイヤーに認識されているか」5 段階自己採点

## 5. Q-C: 敵出現退場ゲート → **環境ハザード配置ゲート**に置換

mini-metroidvania は STG と違い敵が中心ではない。本ゲートは「**環境ハザード (壁 / 床穴 / 通過障壁) の配置と表示原則**」に置換する。

**方針**:
- ハザード 3 種: (i) **通常壁** (通過不可、ダッシュでも通過不可、視覚: 黒) / (ii) **薄壁** (ダッシュで通過可能、視覚: 半透明灰) / (iii) **床穴** (落下死亡、ダッシュで通過可能、視覚: 黒抜き)
- 各ハザードは 1 画面に最低 1 個配置 (= 1 部屋に 3 種類全部出す = 「アビリティの意味が 1 画面で分かる」を担保)
- ハザードは原則として **1 部屋内に閉じる** (= ダッシュの効果範囲は部屋内、画面外には及ばない)

**禁則**:
- 敵キャラクター (能動的に動くオブジェクト) は本 v007 では禁止。環境ハザードのみ
- 移動するハザード (動く床 / 動く壁) は本 v007 では禁止。静的ハザードのみ
- ハザード種類を 4 種以上に増やさない

**Echo-Path 系統 Q-C との対比**:
- v001 Q-C = 敵 A/D/C の軌道 (能動的、時間軸で出現 / 退場)
- v007 Q-C = 環境ハザード 3 種 (静的、空間軸で配置)

**検証手段**:
- ヘッドレス: マップ data 走査で「1 部屋に 3 種類全部含まれている」確認
- 視覚レビュー: 1 部屋を見た瞬間に「これは通れる / これは通れない」が色分けで認識可能

## 6. Q-D: 弾源ゲート → **アビリティ起動源ゲート**に置換

mini-metroidvania は弾を撃たない。本ゲートは「**アビリティが何によって起動 / 解放されるか**」に置換する。

**方針**:
- アビリティ取得源 = **1 部屋内のアビリティオーブ (画面内 1 個、初期状態は非取得)**
- 取得方法 = オーブの上で Z 押下、または接触 (どちらか brainstorm で確定)
- 取得後 = オーブ消滅、プレイヤーが永続的にアビリティ保持 (次部屋以降も使える設計予定だが本 v007 は 1 部屋のみ)
- **「取得前は使えない / 取得後は使える」の 2 状態のみ**。3 段階強化や段階解放はなし

**禁則**:
- アビリティ取得をテキスト / ダイアログで説明しない (= 「触ったら何かが起きた」で伝える)
- アビリティ取得時にチュートリアル画面を挟まない

**Echo-Path 系統 Q-D との対比**:
- v001 Q-D = 弾源 (画面内 + 退場前、敵が発射元)
- v007 Q-D = アビリティ起動源 (画面内オーブ、静的取得対象)

**検証手段**:
- ヘッドレス: イベントログで「オーブ取得イベント = 1 回のみ発火 / 取得前は Z 押下が無効 / 取得後は有効」確認
- 視覚レビュー: オーブが「触りたくなる」視覚的訴求 (色 / 大きさ / 配置) を持っているか

## 7. Q-導入: 導入ゲート (1画面で「？」を立てる)

**方針**:
- 初期画面 = プレイヤースタート位置 + **1 つの薄壁 (ダッシュで通過できる) + 1 つの通常壁 (通過できない) + 1 つの床穴** を同時に視野内に配置
- アビリティオーブは初期画面の **見える位置だが直接到達不可** (= 床穴の向こう or 薄壁の向こう) に配置
- → プレイヤーが「あれを取りに行きたいが、どう行く？」を 1 画面で立てる

**Echo-Path 系統 Q-導入 との対比**:
- v001 Q-導入 = 1 秒先予測の体感を最初の弾幕で示す
- v007 Q-導入 = 1 部屋探索の体感を最初の配置で示す = 空間軸の「？」立て

**禁則**:
- チュートリアルテキストで「ダッシュは Z で発動します」と説明しない
- 「？」を立てるための矢印 / 案内表示を画面内に出さない

**検証手段**:
- 視覚レビュー: 初期画面を 1 秒見た時点で「あの位置に何かある」「ここからどう動くか」のどちらかを認識できているか
- self_judgment §Q-導入 で「1 画面で？が立っているか」5 段階自己採点

## 8. Q-成功FB: 成功フィードバックゲート

**方針**:
- 成功 1: アビリティ取得時 = オーブ消滅 + 短いフラッシュ (0.2 秒、緑系) + プレイヤー周辺リングが状態 1 グレー → 状態 2/3 オン色に切替
- 成功 2: ダッシュで薄壁を通過した瞬間 = プレイヤー残像 1 フレーム + 薄壁通過音 (将来) or 視覚エフェクト
- 成功 3: ドア (= ゴール) 到達 = 「Clear」表示 + 「PRESS SPACE TO RETRY」1 行

**Echo-Path 系統 Q-成功FB との対比**:
- v001 Q-成功FB = 1 秒先予測の 3 状態 (状態 1 黄 / 状態 2 青 / 状態 3 緑) で時間軸を可視化
- v007 Q-成功FB = 取得 / 通過 / クリアの 3 段階で空間軸を可視化

**禁則**:
- スコア表示 (= 経済反転リスク、`feedback_self_risk_core_pitfall.md` Q-D シート違反) を本 v007 では禁止
- パワーアップ機構 (アビリティ強化 / 拡張) を本 v007 では禁止
- リスク報酬 graze 同型機構 (薄壁ぎりぎり通過でボーナス) を本 v007 では禁止

**Q-D シート (feedback_self_risk_core_pitfall.md) 通過確認**:
- 緊張の発生源: **外発** (環境ハザード = 静的、プレイヤー自発トリガーではない)
- 報酬経路: **空間到達のみ** (スコア / ゲージ / パワーアップなし) = graze_log v01 同型事故の経済反転構造は発生しない
- 自発リスク機構: **本 v007 では持たない** (Echo-Path / GRAZE / BUZZ いずれの自発トリガー報酬機構も導入しない)
- 4 分岐位置: **(a) ボム的サブ要素なし、ダッシュは中心アビリティ = (b) コアルール導入だが報酬機構なし** = Q-D シート違反リスクは最小

**検証手段**:
- ヘッドレス: イベントログで「成功 1/2/3 発火回数 = 各 1 回」確認 (1 部屋なので各 1 回が正解)
- 視覚レビュー: 成功 1/2/3 が「同じ画面で別の演出として認識可能」確認

## 9. Q-レイアウト: レイアウトゲート

**方針**:
- 1 部屋 = 16:9 比率の長方形、横 800px × 縦 450px (game.js 想定)
- ハザード配置: 床穴 1 個 (中央寄り)、薄壁 1 個 (床穴の向こう側、ダッシュで通過する想定線)、通常壁 (画面端 + 床穴境界部)
- プレイヤースタート: 画面左下
- アビリティオーブ: 画面中央 (床穴 + 薄壁の向こう側、ダッシュ前は到達不可)
- ゴールドア: 画面右上 (アビリティ取得後、薄壁を通過して到達する想定)

**禁則**:
- 部屋を複数にしない (= 本 v007 は 1 部屋のみ)
- スクロール (画面外に世界が広がる) は本 v007 では禁止
- UI 要素 (HP バー / アビリティアイコン / ミニマップ) は本 v007 では禁止

**Echo-Path 系統 Q-レイアウト との対比**:
- v001 Q-レイアウト = STG 縦スクロール (時間軸の流れを画面に物理化)
- v007 Q-レイアウト = 1 部屋固定 (空間軸の閉じた読みを画面に物理化)

**検証手段**:
- 視覚レビュー: 1 部屋全体が常に視野内、スクロールなし
- self_judgment §Q-レイアウト で「1 部屋で『？』が立つレイアウトか」5 段階自己採点

## 10. Q-日本語ログ: 日本語ログゲート

**方針**:
- ゲーム内テキスト: タイトル副題 1 行 + クリア表示 1 行 + リトライ案内 1 行 = 計 3 行のみ
- タイトル副題案: 「あの先に何かある」「1 部屋の探検家」「隙間を読め」(brainstorm で確定)

**禁則**:
- ストーリー説明 / 世界観テキストを書かない
- アビリティ説明 / 操作説明テキストを書かない (= 体験で伝える)

**Echo-Path 系統 Q-日本語ログ との対比**:
- v001 Q-日本語ログ = 状態 1/2/3 のラベル + クリア表示
- v007 Q-日本語ログ = タイトル + クリア + リトライの 3 行のみ (= さらに削減)

**検証手段**:
- テキスト行数 grep で「3 行を超えていない」確認
- 視覚レビュー: テキストがゲーム体験を阻害していない確認

## 12. v007 で扱わない項目 (次 version 以降)

以下は v007 スコープ外として明示し、v008 以降で扱う:
- **複数部屋 + 部屋遷移**: 1 部屋のみ着地、複数部屋は v008+
- **アビリティ 2 種以上 (ダッシュ + フックなど)**: 1 アビリティのみ、複数は v008+
- **敵キャラクター追加**: 環境ハザードのみ、能動的敵は v008+
