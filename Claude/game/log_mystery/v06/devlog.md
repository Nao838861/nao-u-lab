# log_mystery v06 — devlog (C233 Phase 4)

## 1. 章間再対称化設計

v05 で章 2 場所鐘のみ 3 値化 (鳴った / 鳴らない / 保留中) を導入 = 章間で値域が局所非対称化していた。v06 は **章 1 動機鐘も 3 値化** することで「章 1 と章 2 で 3 値鐘 1 つずつ」の再対称構造に戻す:

- 章 1: 容疑者鐘 (2値) / 場所鐘 (2値) / **動機鐘 (3値)** ← 新規
- 章 2: 共犯者鐘 (2値) / 共犯動機鐘 (2値) / **共犯場所鐘 (3値)** ← v05 から継承

実装は `evalWhy(wy)` 関数を `evalPlace2(p2)` と同型構造で追加:
- wy ≠ ANSWER_CH1.why → `{hit: false, pending: false}` (鳴らない)
- wy = P かつ C3 既読かつ C10 既読 → `{hit: true, pending: false}` (鳴る)
- wy = P かつ C3 既読かつ C10 未読 → `{hit: null, pending: true}` (保留中)
- wy = P かつ C3 未読 → `{hit: false, pending: false}` (鳴らない)

CLUE は C10 を新規追加 ([補強] タグ付き、isExtra: true、文面: 「司書・七尾の自宅から押収された日誌に、解雇通告の翌日付で『二十年積み上げた仕事を、一片の紙で奪われた。金で済む話ではない』と書かれていた。動機が金銭でも相続でもなく怨恨であることがこれで確定する。」)。既存 C3 は「怨恨と直接結論」する文面を「動機方向の候補列挙、決め手は別途」に書き換え、C10 を決定打として分離。

`chapter1Deduced` フラグ追加、CLUES_CH1 クリック時に `if (chapter1Deduced) reDeduceCh1();` を発火。`reDeduceCh1` は `bellState.why.value` を維持したまま `evalWhy` を再呼びして `renderResult1` を再描画する。これは v05 の `reDeduce()` (現 `reDeduceCh2`) と完全同型。

`deduceChapter1` は v05 の即時 hit 判定型から、v05 の `deduceChapter2` + `renderResult2` 分離型に refactor し、`renderResult1` を新規切り出し。章 2 unlock は `hits === 3` 判定 (動機鐘も hit) のときのみ発火、保留中は unlock しない。

UI 側は v05 の `.bell-pending` クラス + ⏸ アイコン + 「追加手がかりで再判定」ラベル + `.result-pending` 結果ボックス + `[補強]` タグを章 1 にもそのまま再利用 (CSS / クラス名一切変更なし)。
