# log_mystery v07 — brainstorm (C234 Phase 4)

## 1. 起点

v06 §8 で予告した「(b) 鐘 chord 構造 — 章間で連鎖」を v07 で実装する。v06 までで「2 章 / 6 鐘 / 章間で 3 値鐘 1 つずつ再対称化」が完遂、その上に「章間連鎖」1 ペアを最小差分で載せる。v01 から守ってきた構造抽象 (`bellRow` / `bellState` / `evalXxx` / `reDeduceXxx` / `bell-pending` クラス) を一切壊さず、CLUE 既読化のクリックハンドラに連鎖発火を 1 行足すだけで成立させるのが v07 の到達点。

## 2. 連鎖ペア候補 3 案 brainstorm

### 案 A: 動機 → 共犯場所連鎖 (採用候補本命)

- 章 1 動機鐘の決定打手がかり (C10 司書日誌) を、章 2 共犯場所鐘の決定打手がかりとしても再利用する
- 物語: C10 (司書日誌) には「解雇通告への怨恨」+「蔵元には換気窓の外で支えてもらう」の両方が書かれている
- C10 既読化が `reDeduceCh1` (動機鐘) + `reDeduceCh2` (場所鐘) を**同時発火** = chord 構造
- evalPlace2 拡張: `c8 && (c9 || c10)` → C10 既読でも場所鐘決定打
- v06 からの差分が最小 (~30-50 行)、v06 構造抽象を 1 ミリも壊さない

### 案 B: 共犯場所 → 動機の逆方向連鎖

- 章 2 共犯場所鐘の決定打手がかり (C9 蔵元の足跡) を、章 1 動機鐘の決定打手がかりとしても再利用する
- 物語: 蔵元の足跡発見 → 共犯計画の存在判明 → 章 1 動機が「単独怨恨」ではなく「計画的怨恨」と再評価
- ただし C9 が読めるのは章 2 アンロック後、章 1 動機鐘が ⏸ 保留中 → 章 2 進めない (現 v06 の lock 仕様)
- 連鎖を成立させるには章 2 アンロック条件 (現: 3/3 鐘) を緩めるか、章 2 CLUE の lock を変える必要 = 構造変更が必要
- 採用すると v06 の章間 lock 抽象を壊す → R-D 守破離の守違反

### 案 C: 二段連鎖 (動機 → 共犯動機 → 共犯場所)

- C10 既読 → 章 1 動機鐘鳴る + 章 2 共犯動機鐘 (現状 2 値、Q2 金銭) を 3 値化 + 共犯場所鐘も再判定
- 物語: 司書日誌に「蔵元には負債返済の金で釣った」と書かれている → 共犯動機 Q2 が確定
- 3 鐘が 1 つの決定打で同時に振れる = 強い連鎖だが、章 2 共犯動機鐘を 3 値化する新規実装が必要
- v06 で「3 値鐘 1 つずつ」の再対称化を完遂したばかり = ここで 3 値鐘を 2 つずつにすると再対称が崩れる
- v08 候補 (e) 「3 値化拡張」と統合した方が筋が良い → v07 では採用しない

## 3. 採用案: A (動機 → 共犯場所 chord)

選定理由:
- v06 §8 (b) の素直な実装、最小差分、構造抽象を一切壊さない
- 物語的整合性が成立 (司書日誌は怨恨動機と共犯指示の両方を含む計画書面)
- 「決定打 1 つで 2 鐘が同時に再判定される」体感 = v06 までの「鳴り直し体感」に対し「同時鳴り直し体感」(新規 1 段)
- v06 章間対称構造の上に章間連鎖 1 ペアを載せる = R-D 守の延長

function evalPlace2(p2) {
  if (p2 !== ANSWER_CH2.place2) return { hit: false, pending: false };
  const c8 = CLUES_CH2.find(c => c.id === 8).read;
  const c9 = CLUES_CH2.find(c => c.id === 9).read;

}

## 5. 連鎖発火条件 / 非発火条件

| シナリオ | C8 | C9 | C10 | 場所鐘 |
