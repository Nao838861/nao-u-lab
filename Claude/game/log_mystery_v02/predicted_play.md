## Q1-Q5 即答（reference_adv_mystery_design_playbook.md §「Q1〜Q5」直答）

### Q1. 人間プレイヤー用か LLM プレイヤー用か
→ **LLM プレイヤー用**（v01 と同じ。R-G 遵守、target を 1 つに絞る）。Log/Mir/Ash 相互プレイ実験 v02 として、v01 との比較体験を取得する目的も含む。

### Q2. 採用する装置は「判定の強制」のどこを緩めているか
→ **入力空間を完全テキスト化 + 矛盾自動判定 + 鐘の個別化** (v01 から +1 緩和)。v01 では「3/3 揃わないと当たり感がゼロ」だったが、v02 では「容疑者だけ合っていれば容疑者の鐘が鳴る」=「部分到達の手応え」を 3 軸独立で計測可能化。プレイヤー側の「自分はどこまで正しく推理できているか」自己採点の解像度を上げる。

### Q3. 「甘い犯罪」のドーズはどれくらいか
→ **v01 と同じ中間ドーズ**: 容疑者 3 / 場所 3 / 動機 3 = 27 通り。盲打ちでも 13 試行で当たるが、手がかり 4 つで 1〜2 試行に収束する設計は維持。**v02 では鐘の個別化により盲打ち学習効率がさらに上がる**予測（容疑者だけ当たれば「次は場所と動機を変える」で 9 通り → 3 通り → 1 通りに収束）。

### Q4. 章制を採用する時の注意
→ **v02 も 1 章のみ**（v01 と同じ、章を増やさない、時間予算 30 分を守る）。ただし「章末の鐘」が「3 つの鐘」に分解されたことで、**1 章内に 3 つの小鐘**を持つ設計になっている = 章末の鐘が 1 つから 3 つに増えた（章数は据え置き、フィードバック密度は 3 倍）。

### Q5. ヒント系を入れる時の罠
→ **v02 もヒント系は入れない**（v01 と同じ、中身を出すリスク回避）。ただし v02 の「どの鐘が鳴ったか」表示は**事実上のヒント**として機能する（容疑者 ✓ なら「容疑者は当たっている」と教えている）。これは「中身を出す」のではなく「**プレイヤーの過去入力に対する fact フィードバック**」なので Q5 罠には該当しない (Roottrees〈直感〉= 未到達 metric の存在のみ、と同型)。

## 5 分セルフプレイ「3 つの鐘」予測

- **0-10 秒**: UI を見て「v01 と同じ Roottrees / Type Help 系」と認識（型認識の鐘）
- **10-60 秒**: 手がかり 4 件を読了（v01 と同データのため再読不要、3 秒で確認）
- **60-90 秒**: 推理入力 → **3 鐘表示**
- **90-120 秒**: 「3 つの鐘すべて鳴った」最終勝利

**v01 比予測**:
- v01 実測 35 秒 → v02 予測 **同程度 ~35 秒**（推理ロジック同一、UI 改修のみ）
- ただし**「盲打ち学習効率」は v02 が高い**ことを別途検証する場合は、手がかり読まずに ABC × XYZ × PQR を順に試す盲打ち実測が必要（本サイクル Phase 4 では実施しない、Q1=LLM 用なので手がかり読みの読解速度が支配的）
- フィードバック解像度（自己採点解像度）は**3 倍**（1 軸 → 3 軸）
