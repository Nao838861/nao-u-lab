「強度」は **本レポート時点での Log 評価** で、Nao_u/Mir/Ash 実プレイで上書き可。判定基準:

- **低**: 既に明示的に緩和されている (該当なし)

## 3. 最重要障壁: (2) 探索障壁

### 3-A. 選定理由

3 候補 (能力 / 判定 / 試行) と比較し、**探索障壁が最も改修価値が高い**:

1. **強度評価が「高」で唯一**: 他 3 つは「中」、探索障壁のみ「高」
2. **コード上の明示的盲点が確定済**: devlog §10(b) で「Z キー未気付き = 赤信号 #2」、踏みやすさ「高」評価。C1 (Z 常時 HUD 表示) は実装済だが、**SHIFT 自体の発見経路は HUD 静止表示のみ**
3. **S1 撤回トリガーに直接接続**: 「30 秒以内に SHIFT が押されない」= 探索障壁強度「高」の現場測定。S1 発火 → v02 案 B (graze→resource 変換) 転換判定の引き金 = 探索障壁解消が v02 採用継続の前提
4. **改修コストが低い**: 5-15 行の HUD/popup 追加で前進可能 (機構の追加でなく **既存機構の発見可視化**)
5. **CLAUDE.md「ゲームを動かして出す — 積み上げはその副産物」原則と整合**: コード変更 = playable diff、ドキュメントだけで終わらない

### 3-B. 既存緩和策の棚卸し (重複実装回避)

v02 では既に探索障壁を下げる試みが 4 つ実装済:
1. タイトル画面で SHIFT/Z の効果説明 (line 966-971): ただし player がタイトルを 5 秒読むかは保証なし
2. HUD line 922-924 で `(SHIFT FOCUS)` 常時表示: 「押すと何が起きるか」までは伝わらない
3. C1 (C219 Phase 4) で `Z (need TOKEN 3)` 常時表示 (line 935): TOKEN 機構の発見経路。SHIFT 機構には対応無し
4. wave 4 (focus tutorial) で縦長 medium 3 体 (line 373-379): focus を **使うべき場面** の物理設計 — ただし「SHIFT を押す」発見が事前に起きていないと wave 4 でも気づかれない

→ **欠落している経路**: 「ゲーム開始直後に SHIFT を押すきっかけを player に与える」直接的な hint が無い。タイトル画面と HUD は **静止情報** で、in-game の動的注意誘導 (点滅 / 短時間 popup) が存在しない。

## 4. 改修方針 (実装可能粒度)

### 4-A. 採用案: wave 1 開始直後の「SHIFT / Z hint popup」

**位置**: `spawnWave1()` (index.html line 348-359) の最初に、`state.popups.push(...)` で 3 秒表示の hint を 1 つ追加。

**コード方針** (5-7 行):
```javascript
function spawnWave1(){
  // v02 探索障壁緩和 (C225 Phase 4 Mir 4分類診断): wave 1 開始直後に SHIFT hint を popup
  state.popups.push({x:W/2,y:H-60,text:'HOLD SHIFT = FOCUS (narrow shot)',life:180,c:'#80c0ff'});
  spawnEnemy('small',W*0.30);
  ...
}
```

**「次回プレイで何が変わるか」観測可能粒度**:
1. **0-3 秒**: 画面下に薄い青字で `HOLD SHIFT = FOCUS (narrow shot)` が 3 秒表示される (現状: 表示なし)
2. **3-30 秒**: タイトル画面を読まなかった player も、wave 1 中に SHIFT を押すきっかけを獲得 (現状: タイトル文字 + 静止 HUD のみ)
3. **30 秒時点**: S1 撤回トリガー「30 秒以内に SHIFT が押されない」発火頻度が低下 (測定: 次サイクル実プレイで Nao_u/Mir/Ash の 30 秒以内 SHIFT 押下有無を観測)

### 4-B. なぜ「これだけ」か (過剰実装回避)

CLAUDE.md「個別指摘を即ルール化しない」「絶対にやる」5 原則の「ゲームを動かして出す — 積み上げはその副産物」+ 「個別指摘を即ルール化しない」と整合させるため、本サイクルは:
- **(1) 能力障壁の追加緩和** はしない (現状段階導入で十分、改修すると wave 4 tutorial 設計と干渉)
- **(3) 判定障壁の graze 両立修正** はしない (S3 撤回トリガー実プレイ判定後でないと方向が決まらない)
- **(4) 試行障壁の死因 feedback 強化** はしない (4 候補のうち最も大規模、別サイクル)
- **(2) 探索障壁の SHIFT 発見 hint のみ** = 1 機構 / 5-7 行 / 既存 popup システム流用

3 案を捨てて 1 案を選んだ理由を本ファイルに残すことで、implementation-notes.md の「迷って捨てた判断の記録」原則と整合 (3 層分離試行の 2 層運用例)。

### 4-C. Z hint は本サイクル対象外の理由

SHIFT を押す → focus mode 体感 → 撃破→ TOKEN 蓄積 → Z 発動可、の連鎖の **最初の 1 段** が SHIFT。Z は TOKEN 蓄積 (= SHIFT 中の撃破) を前提とするので、SHIFT 発見が解決すれば連鎖で Z 発見も改善する。本サイクルは「鎖の最初の 1 環」だけ改修し、Z hint は次サイクル以降で実プレイ観察後に判定する。
