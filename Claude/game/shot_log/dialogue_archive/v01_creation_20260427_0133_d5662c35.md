### A. 音源ファイル方式 (mp3/ogg/wav)
- `<audio>` か Web Audio で再生
- 質感は高いが、SE 約10種＋BGM のアセット調達が必須（フリー素材 or 自作）
- 単一 index.html の自己完結性が崩れる、ファイルサイズ 2–5MB

### B. Web Audio API による合成 (procedural)
- オシレータ＋フィルタ＋エンベロープでコード上で動的生成
- 外部依存ゼロ、追加コード ~10KB で済む
- 旧 STG の FM 系「ピューン」「ドカン」と相性◎ ＝**爽快感の方向と合致**
- BGM は厳しい（楽曲としての作曲労力が高い）

### C. ハイブリッド
- SE: B（合成）
- BGM: A（外部ファイル1本）

## 推奨

**SE = B から着手、BGM は別フェーズで判断**。理由：

1. shot_log v01 はビルド不要の単一 HTML → 外部ファイルを増やすと管理コストが上がる
2. STG の爽快 SE は「短い・パンチ・反復パターン」 → 合成と相性が良い
3. まず SE だけで「音アリ vs 音ナシ」の体験差を測る。BGM 無しでも SE が刺されば十分爽快な可能性
4. BGM を入れるなら音楽素材1本（OGG ~500KB）を `game/shot_log/v01/assets/` に置く形が自然
