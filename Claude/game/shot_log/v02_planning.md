#### 1/30: Touhou Project（東方Project, ZUN / 上海アリス幻樂団, 1997-）

- **(a) 出典**: 同人 STG シリーズ。紅魔郷以降 graze がスコアシステムに統合。https://en.touhouwiki.net/wiki/Graze （graze_log v04 prior_art_30 事例1 詳細調査済）
- **(b) 独自要素軸（破した1点）**: 「弾の隙間を**攻める動機**をスコアに与えた」= 弾幕回避を「逃げる」から「擦る」に反転させた。grazing が PIV (Point Item Value) を増加させ Point アイテム取得時の得点を底上げする（紅魔郷型）／妖々夢 Supernatural Border 中の graze は大ボーナス／地霊殿は graze 自体がスコア源、と作品ごとに重み振動。
- **(c) コア快感天井評価**: 強結合型 = graze スコア倍率の天井は「全パターンの最適 graze ルート暗記」まで伸びる。スコアラー文化を生む天井の高さがあるが、初心者には「graze は無視してもクリアできる装飾」と扱われ二極化（v04 事例1 (4)）。**天井 = 高 / 底辺アクセシビリティ = 低**。
- **(d) shot_log v01 との差分**: v01 は close-call/カスリ完全未実装 (Q-D ○ の根拠 = self_judgment.md L48「自発リスク (close-call / カスリ) は v01 に**未実装**」) ↔ Touhou は graze をスコアコアに据えた強結合型。v01 ゲージ経済（撃破→ゲージ増→弾増の単線）に対し、Touhou は graze 経路を並走させる「2経路設計」になっている点が決定的差分。
- **(e) §2 採用可否**: **不採用（参照）**。§2「カスリでゲージ加速のみ、スコア倍率なし」は明示的に Touhou 型強結合を避ける設計 = 同じ強結合を採れば M-31 コア化罠を直行で踏む。Touhou は「やってはいけない実装例」ではなく「やったら何が起きるか」の参照モデル。

#### 2/30: DoDonPachi DaiOuJou（Cave, 2002）

- **(a) 出典**: DonPachi シリーズ4作目、Cave の代表作（業務用、White Label / Black Label の2版）。https://shmups.wiki/library/DoDonPachi_DaiOuJou （v04 prior_art_30 事例3）
- **(b) 独自要素軸**: 機体ヒットボックスを画面表示より極小化し「graze し放題」状態を作りつつ、graze 自体のスコア加算は限定的に留めた。Hyper System（火力倍化＋短時間無敵＋隠し rank 上昇）の溜め経路の副産物として graze を位置付けた = 「弾幕回避が先に立ち、graze は明示的報酬を持たない」設計（v04 事例3 (4)）。
- **(c) コア快感天井評価**: 副産物型 = graze がスコアコアでない分、初心者は graze を意識せず弾幕回避コアで進行可能。スコアラー層は Hyper 発動タイミング最適化に天井を伸ばす。Cave 流のジャンル王道として定着 = **天井 = 高 / 底辺アクセシビリティ = 中〜高の両立例**。
- **(d) v01 との差分**: v01 ヒットボックス設計は graze 前提でない (L48)、Hyper 相当の「火力倍化＋短時間無敵」装置は v01 では BOMB (gauge=208 → 弾消し+小中敵全滅+gauge=35) として実装済だが「rank 上昇とトレードオフ」設計ではない。ただし v01 BOMB は C195 で「ハイリスクハイリターン」と判明済 (本ファイル §0) で構造的に Hyper に近い側に動いた。
- **(e) §2 採用可否**: **採用（最良参照）**。§2「graze にゲージ加速のみ、倍率/無敵時間なし」は DDP 流「graze は Hyper 溜め経路の副産物」とほぼ同型。本 v02 §1 Q-H-3 一般要素5 (BOMB 強化済) が DDP Hyper に近いので、§2 をその溜め経路の自発リスク版として位置付ければ DDP 設計が v02 に移植可能。**本5本中、§2 案の最直近実装モデル**。

#### 3/30: Psyvariar（Success / Skonec, 2000-）

- **(a) 出典**: Medium Unit (2000, 業務用) → Revision (2003) → Delta (2018) → Psyvariar 3 (2026予定)。https://tvtropes.org/pmwiki/pmwiki.php/VideoGame/Psyvariar （v04 prior_art_30 事例2）
- **(b) 独自要素軸**: BUZZ システム = 弾の縁を機体スレスレで通過すると EXP 加算 → EXP 満タンでレベルアップ → **短時間無敵** → 無敵中に大量 BUZZ → 連鎖レベルアップ。高ステージ解禁が rank 依存 = **BUZZ なしでは進行不可能**（v04 事例2 (2)(4)）。
- **(c) コア快感天井評価**: 進行ゲート型 = graze をコアにした極致。爽快さの天井は「BUZZ 連鎖でステージ早回し」まで突き抜けるが、底辺は「BUZZ 前提に弾幕が組まれており、自殺的接近を強要される」設計のため敷居が極めて高い（v04 事例2 (4) 批判: ジャンル外プレイヤーには敷居が高すぎ）。**天井 = 超高 / 底辺アクセシビリティ = 極低**。
- **(d) v01 との差分**: v01 は段階式被弾ペナルティ (Q-H-4) で「被弾したら段階が降りる」罰経路を持つが、Psyvariar の「BUZZ 連鎖でレベルアップ→短時間無敵→更に BUZZ」のような**正フィードバックループ**は持たない。v01 ゲージは正フィードバック（撃破→way 数増→さらに撃破）が緩く、Psyvariar 型の暴走ループは設計から排除されている。
- **(e) §2 採用可否**: **不採用（反面教師）**。§2 で「graze に短時間無敵を付けない」と書いた根拠を Psyvariar が体現している。BUZZ→無敵→BUZZ の連鎖は M-31 コア化罠の典型 = §2 案が「ゲージ加速のみ」に絞った経緯の証拠。Psyvariar は v02 が**踏んではいけない道**として記録（M-31 への抗体設計の反例参照）。

#### 4/30: Ikaruga（Treasure, 2001）

- **(a) 出典**: NAOMI アーケード→Dreamcast→GameCube→各種HD再販。https://en.wikipedia.org/wiki/Ikaruga （v04 prior_art_30 事例4）
- **(b) 独自要素軸**: 黒/白の極性切替で同色弾を**吸収**（被弾せず）→ エネルギーゲージ充填。同色敵を3連続撃破でチェイン成立。「擦る」ではなく「吸収して回避」という別解で graze の機能（リスク報酬経路）を置換した。
- **(c) コア快感天井評価**: 別解型 = 回避＝得点が直結する設計のため、コア快感は「極性切替の同期精度」に天井がある。「パズル的すぎて反射神経より暗記寄り」という批判（v04 事例4 (4)）はあるが、ジャンル内では graze 抜きで risk-reward を成立させた数少ない例の1つ（Battle Garegga と並列）。**天井 = 中〜高 / 初心者には極性概念の学習コスト**。
- **(d) v01 との差分**: v01 は単一系統武装（3way 拡張のみ、self_judgment L152 power-routing △）に対し、Ikaruga は2極性 + 3連撃破チェインの二層構造。v01 が「ゲージ MAX で BOMB」の単一発動装置を持つのに対し、Ikaruga は「極性切替」が**毎フレーム判断**の連続装置として動く点が決定的差分。
- **(e) §2 採用可否**: **不採用（方向違い、参照価値あり）**。§2「カスリでゲージ加速」は graze の機能を保つ路線、Ikaruga は graze を別装置に置換する路線で方向性が逆。ただし「risk-reward を graze 以外で実装可能」という存在証明は §2 案以外の選択肢（v02 §2 第2案=装備選択、第3案=wave grammar）を裏付ける参照価値あり。

- **(a) 出典**: Xbox360 → Windows/Switch 移植。Judgement Silversword 系列。https://shmups.system11.org/viewtopic.php?t=37266 ＋ https://moegamer.net/2017/03/25/shmup-essentials-eschatos/ （v04 prior_art_30 事例27）
- **(b) 独自要素軸**: graze は「**存在しても得点化が薄い**」（プレイヤーコミュニティが「graze 何ポイント？」と疑問を持つレベル、v04 事例27 引用）。Normal Mode のスコアコアは「敵編隊を逃さず全滅で multiplier +1、1体逃すと multiplier 減」の編隊撃破ルート設計。意図的に graze を弱化＝シンプル化を選択した現代 STG（設計者はせ氏の意図）。
- **(c) コア快感天井評価**: 意図的弱化型 = 「graze を消すまでは行かないが、コアから外す」中間案の代表。Qute 流「graze は薄く存在するが意識しなくて良い」がコア快感の上限を編隊撃破ルートに集中させる。**天井 = 中（編隊撃破ルート最適化） / 底辺アクセシビリティ = 高（graze 学習不要）**。
- **(d) v01 との差分**: v01 は graze 完全未実装 (Q-D ○) で「graze は薄く存在する」状態すら作っていない点が Eschatos との差。v01 のスコア源は「撃破スコア」単線、Eschatos は「編隊撃破 multiplier」+「graze 微少加算」の二層。v01 が graze 層をゼロから足すなら、Eschatos の「足したが意識させない」設計が最直近の前例。
- **(e) §2 採用可否**: **採用（強参照）**。§2「カスリでゲージ加速のみ」は Eschatos「graze は存在するが意識しなくて良い」の延長線上にある。§2 案を実装する際の落とし所として、Eschatos のように「カスリ加速はあるが、それを意識せず avoid に集中してもクリア・スコア競争に支障ない」設計を目標とすれば、強結合（Touhou）と弱化（Eschatos）の中間で M-31 コア化罠を回避できる。
