## 核の楽しさ（1行で）

AIと並んで弾を避ける——軌跡差分が「AIと自分の違い」を認識装置として浮かび上がらせる。

（出典: `game/avoid_log/v01/devlog.md` Phase 2「攻略AI差分がコンテンツの芯になるか」「攻略AIは敵でもガイドでもなく"認識装置"——人間の動きを浮かび上がらせる背景」）

## 最低限の構成要素（ゲームループ / 入力 / 状態 / 失敗条件 / 成功条件）

- **ゲームループ**: プレイヤー（青）とAI（橙）が同じ画面で並走、上から降る弾幕を避ける。両者死亡まで継続、軌跡を薄い色で描画して死後に重ね表示（v01 devlog「両者死亡後：軌跡重ね表示＋生存秒数。勝ち負けを『秒』で判定」）
- **入力**: 左右移動（押しっぱなし `keys[]` dict 管理、v01 devlog「pygame `key.get_pressed()` と対応して書けた」）。v02 で SPACE 追加（極性反転＝撃ち返し、v02 devlog「`mode: iron/weapon/returned` の3状態で弾の意味が変わる」）
- **状態**: プレイヤー位置 / AI位置（v02 以降は吸収量 absorbed meter） / 弾幕（v01=直線+弱ホーミング、v02=鉄片の3 mode） / 軌跡 / 各自の生存秒数 / 地雷（v02 後期、画面下到達鉄片が固定位置で残存）
- **失敗条件**: 弾／鉄片／地雷の直撃。AI 側は overload（v02 吸収過多で崩壊、v01 では存在せず）。**L-04 該当**: overload 90F 自動死は受動的自滅タイマーで dodger seed=43 で p=35.1s/score=150 の抜け穴を作った（v02 devlog「過充電モード=全弾一斉解放+無敵」に差替えで根切り）
- **成功条件**: AI より長く生きる（生存秒数比較、両死で over）。v02 では chain スコアも併用（最終 concept 19.45s/709pt vs dodger 8.32s/4pt の生存×スコア二重評価で設計成立判定）

## 派生ポイント（ここから独自性が出る。チェックボックス式）

- [ ] **AI挙動の自律化軸** — v01=最近傍脅威を検出して退避＋プレイヤーへの緩いミラー / v02=磁石（吸引＋極性反転）/ 次候補=「鉄片密集点を独立目的関数で狩る捕食者」。v02 devlog「`index.html:143 tx = W*0.5 + (W*0.5 - state.player.x)*0.5` 完全にプレイヤーの対称移動」のバイナリーランド指摘から、プレイヤー座標を参照しない目的関数が次の独立性軸
- [ ] **「近づく動機」設計** — 磁力場内 vs 場外で報酬が変わる。v02 devlog 案A「プレイヤーが磁石圏内にいる時だけ撃ち返しチェイン倍率」。**M-12 報酬設計**ど真ん中、ただし v02 では「磁石は鉄を引く」メタファーがゲーム性と衝突（**X-01 表現層がメカ層を食う**）して未解決

## 30秒オンボーディング候補（game_design_principles.md 準拠）

- **0-5 秒**: 自分が動かしているのは画面下中央の青い円 / もう一人いる橙の円は AI (操作対象ではない) と画面で分かる
- **5-15 秒**: 上から弾が降ってきて当たると死ぬことを体験で覚える (テキスト説明禁止)
- **15-30 秒**: 自分の軌跡と AI の軌跡が同じ画面に薄く重なって描かれ、「並走している」が視覚で立つ
- 派生時は本テンプレ「核の楽しさ」(軌跡差分が認識装置) が 30 秒以内に画面に立たない設計を禁則とする (`docs/game_design_principles.md` 30 秒オンボーディング原則)

## 評価基準の事前固定 vs 実行時開放（このテンプレの立ち位置）

- **事前固定側** (テンプレ採用時に一意に決める指標):
  - 生存秒数 (両者死亡まで、AI との差分)
  - chain スコア (v02 以降の派生で連鎖メカが入る場合)
  - 衝突座標分布 (ヘッドレス指標、grid 滞在率と隅張り付き検出)
- **実行時開放側** (プレイテスト後に Nao_u / cross_review が拾う指標):
  - 「並走している感」(軌跡差分が認識装置として機能しているか)
  - 「一番楽しい瞬間」(v02 では SPACE 撃ち返しの連鎖、派生先で固有値)
  - 「次やる気が起きるか」(終端 85-90 秒時点の余韻)
- **汚染回避** (npaka123 由来): 「1 分クリア型」評価で生存秒数のみを最大化する設計に逃げない。avoid 系は「生存秒数 = 長いほど良い」軸が罠になりやすく、軌跡差分の体験を潰す方向に圧力がかかる (`projects/game_templates_design.md` 2026-04-24 C114)

## 負荷種別（メモリ/CPU/描画/入力、ニカイドウ由来）

avoid 系で立ちやすい負荷軸:

- **描画**: 弾 / AI 軌跡 / プレイヤー軌跡 を全て薄色で重ね描きする設計上、弾数 × 軌跡履歴長で描画コストが指数的に重心へ張り付く。派生時は弾上限 N と軌跡履歴フレーム数 F を事前固定 (例: N ≤ 80 / F ≤ 600)
- **CPU**: 衝突判定 N × M (弾 × プレイヤー) の二重ループが派生先で爆発しやすい。grid / spatial hash を事前置くか、N の上限自体を低く保つ
- **入力**: v02 で SPACE 追加した経緯から、連射 / hold 系を加えると入力 polling が重心を奪う。`key.get_pressed()` 系の dict 管理で 1 フレーム内 1 回参照を厳守
- **メモリ**: ヘッドレス trace logger は frame 単位で座標蓄積するため、長時間プレイで GB 級になる罠あり。log 蓄積上限フレーム数を事前固定

## 改修の性質（構造的 vs 摩擦的、ABA「圧力設計 vs 禁止追加」と同型）

- **構造的** (核の楽しさの圧力を高める改修): 重心に押し込む方向。
  - 例 (成功): v02 「掃除をサボると散らかる」型脅威追加 = 鉄片が画面下到達で地雷化 (S-06)。罰ではなく自然な結果として核を強化
  - 例 (成功): v01 軌跡重ね表示 = 両者死亡後の比較が「死因マーカー」として機能、認識装置を補強
- **摩擦的** (望ましくない遊び方を後付けで禁じる改修): 圧力設計の代替として禁止を積む方向。
  - 例 (失敗): v02 の 5 連禁止 (drag / hitbox / 弾幕激化 / 90%スポーン / 地雷) で v3 全マイナス、v2.5 で全撤回 (M-11)
- **運用**: **改修コミット前に 1 行で性質判定**。「構造的: 〜を強化」または「摩擦的: 〜を禁止」と明記。**2 個以上連続で摩擦的側に寄ったら重心審問をやり直す** (`feedback_game_center_of_mass.md`)。avoid_log v02 の 5 連禁止を手前で検出する仕組み

## 初期プレイテスト観点（ヘッドレス指標 / 人間プレイ注目点）

- **ヘッドレス指標** (v01/v02 `headless.py` 系を継承):
  - concept / slacker / dodger の 3 AI 比較 (生存秒数 + スコア)
  - ARC (action-reaction coupling): プレイヤー行動と AI / 環境応答の結合度
  - unfair_death: プレイヤー操作に依存しない死亡率 (L-04 受動的自滅検出)
  - phase variety: 時間軸層フェーズ間の状況多様性
  - **盲点警告 (L-05)**: 指標は concept AI の動作条件で取られるため、人間プレイ条件と乖離する罠あり。指標導入時に「この指標は誰のどんな行動で最大化されるか」を 1 行先書き必須
- **人間プレイ注目点**:
  - 開幕 30 秒で「並走している感」が立つか
  - 中盤 (45-65 秒) で死ぬ位置に分布があるか (一箇所集中は重心の局所最適化サイン)
  - 終盤の山 (65-85 秒) で「ここを越えたい」気持ちが立つか
  - クリア / GAMEOVER 後に「もう一回」気が起きるか

## 時間軸層（60-90 秒カーブのフェーズ区切り、罠 #2 反映）

avoid 系の 1 セッション時間設計。Pulse Relay v003 教師差分の **70-90 秒カーブ構造** を初期値として埋める運用（`projects/game_templates_design.md` 2026-05-31 罠 #2 = Design Skeleton in 7 Steps + Pulse Relay v003 の 2 source 収束）:

| フェーズ | 目安秒 | 状態 / 目的 | avoid 系での具体 |
|---|---|---|---|
| 学習 | 0-15 | 入力 / 移動 / 死ぬ条件を体験で覚える | 弾密度低・速度低、AI も静観気味 |
| 基本混合 | 15-30 | 弾種 2-3 種を同時提示、軌跡差分判断が成立する最小密度 | 直線弾 + 弱ホーミング併存、AI と並走線が画面に立つ |
| 価値提示 | 30-45 | 並走している AI / 群挙動が画面に見える瞬間、avoid の核が立つ | 軌跡比較の薄色重ね描画が認識装置として機能、「ああ AI と並んでいる」が体感 |
| 中盤圧力 | 45-65 | 弾密度 / 種類が増え、判断速度が試される | 鉄片 / 地雷 / 連鎖などの拡張メカが入り、死ぬ確率が一段上がる |
| 終盤の山 | 65-85 | カーブ最高潮。並走 + 圧力 + 軌跡差分が同時に最大化 | AI も追い詰められる局面、両者死亡が起きやすい時間帯 |
| 終端 | 85-90 | クリア演出 / GAMEOVER 演出、次セッションへの記憶残し | 両者軌跡重ね表示 + 生存秒数比較、死因マーカー提示 |

派生時はこのカーブを参照点として **自作カーブで上書き** する (継承ではなく置換、罠 #1 順守)。Pulse Relay v003 値そのまま流用は **Q-4 禁則**。

## 動的要素（wave 推移 / 状態遷移 / 段階的開示、罠 #2 反映）

静的構造のみ blueprint 化すると時間軸が抜ける (Design Skeleton in 7 Steps の限界、罠 #2)。派生時は以下を必須:

- **wave 推移**: 上記時間軸層のフェーズ遷移条件 (秒 / スコア / 撃破数 のいずれを軸にするか) を派生先で **事前固定**
- **状態遷移**: TITLE / PLAYING / GAMEOVER 等を `step()` 内分岐で扱う場合、遷移条件を **1 箇所に集約**。状態フラグを update / render の双方に散らばらせない
- **段階的開示**: 弾種 / 敵種 / メカを一気に出さない。各フェーズで 1 種ずつ追加、プレイヤーが学習する余地を残す。v02 の磁石軸 (iron → weapon → returned → chain) は 1 軸 3 段の派生が成立した型 (S-05)

## Q-X ゲート群（派生時の独自性 1 軸禁則）

派生時に **「独自性を 1 軸だけ立てる」** ためのゲート群。Pulse Relay 系の Q-X ゲート構造を avoid 系に適応:

- **Q-1 派生独自性**: 派生先 `game/<id>/v<NN>/` で本テンプレに対する独自性軸を **1 つだけ宣言**。2 軸以上の独自性は禁則 (重心が分散、M-11 の 5 連禁止と同型構造を手前で阻止)
- **Q-2 既出失敗ゲート**: 着手前に [`memory/game_lessons_log.md`](../../../memory/game_lessons_log.md) 冒頭 R-A〜R-I を必ず読み、該当 M-XX 詳細を引いて派生先 README に「回避する失敗 ID」を 1 行明記
- **Q-3 並走の他者**: 「何と並走しているか」(AI / 群 / 連鎖 のどれか) を 1 行で書けない派生は avoid 系を名乗らない。「弾を避けるだけ」は別ジャンル扱い (本テンプレ「核の楽しさ」軌跡差分認識装置の根)
