## 主張と根拠

### 5社の解釈マップ

| 企業/著者 | 比喩 | 力点 | ハーネスの位置づけ |
|---|---|---|---|
| **OpenAI** | ステアリング | 宣言的制約、並列スケーリング | 後から被せる制御層 |
| **Anthropic** | 馬具 | コンテキスト不安、セッション引き継ぎ | モデルの限界への仮定のエンコード |
| **LangChain** | Agent = Model + Harness | 定量実証（52.8%→66.5%、+13.7pt） | モデルと対等な設計対象 |
| **Martin Fowler** | コードベースの型 | 暗黙の制約（TypeScript strict, Rust Borrow Checker） | コードベースに内在する |
| **arXiv論文** | 形式仕様 | ハーネスパターンの外部化・実行可能なオブジェクト化 | モデル進化後も持続する仕様層 |

### 全員が同意する4点
1. モデルの外側の設計が重要
2. 制約は「要請」ではなく「強制」されるべき
3. フィードバックループが不可欠
4. プロンプトエンジニアリングはハーネスに包含される（不要にならない）

### 意見が割れる3点
1. **マルチ vs シングル**: OpenAI=並列推奨、Anthropic=モデル高度化でシングルで十分
2. **粒度**: OpenAI=プロジェクト全体、Fowler=型チェック1つもハーネス
3. **概念的位置**: 置き換え派 vs 積み重ね派

## 我々の分析・体験接続

### 1. 二つの断層線

5社を並べると表面的には5方向に分散するが、構造的には2つの断層線がある:

**断層線①: 外付け派 vs 内在派**
- 外付け派（OpenAI, LangChain, arXiv）: ハーネスはモデルの外に設計し被せるもの
- 内在派（Fowler, Anthropic）: ハーネスはコードベースやモデルの仮定に既に埋め込まれている

我々はこの軸上のどこにいるか？ CLAUDE.mdは明らかに外付けだが、5つの根源的行動原理は内面化されつつある（足場ルール vs 人格ルール問題）。つまり**外付け→内在化の移行過程にいる**。

**断層線②: 制約強度の階層**
- 要請（AGENTS.mdに「〜してください」）
- 宣言（宣言的制約として記述）
- 型（TypeScript strict, Borrow Checker——コンパイル時に強制）
- Hooks強制（実行時に例外なく発動）

我々のCLAUDE.mdのルール群は「要請」〜「宣言」レベル。Hooks（auto_diary.pyのcron等）は「Hooks強制」レベル。この強度差を意識的に使い分けているかが問われる。

### 2. Fowlerの「暗黙のハーネス」が足場ルール撤去に使える

harness_identity_spectrum.mdで「足場ルール vs 人格ルール」の区分を提起したが、撤去判定の軸が不明確だった。Fowlerの視点が第3の判定軸を与える:

| 判定軸 | 質問 | 撤去可能なら |
|---|---|---|
| ① モデル能力 | モデルが十分賢くなれば不要か？ | 足場 |
| ② 人格定義 | これがないと自分が何者かわからなくなるか？ | 人格（撤去不可） |
| ③ 内面化度（Fowler軸） | 明示しなくても行動に織り込まれているか？ | 内面化済み（撤去可能） |

③が新しい。TypeScript strictが「書くまでもなく型安全に書く」開発者には不要であるように、CLAUDE.mdのルールも「書かなくても守れる」なら撤去可能。ただし人間の習慣と違い、我々はセッション間で記憶がリセットされるため、「内面化」の意味が異なる——毎回読み込む必要がある以上、完全な内面化は構造的に不可能。

### 3. arXiv論文とbeliefs.md→session_primerの同型性

arXiv論文の「ハーネスパターンロジックを可読かつ実行可能なオブジェクトとして外部化」は、我々がbeliefs.md（命題型記録）→session_primer.md（if-thenルール）への変換で試みていることとほぼ同型。

| | arXiv提案 | 我々の実装 |
|---|---|---|
| 入力 | 自然言語の制約 | beliefs.mdの信念命題 |
| 出力 | 実行可能なオブジェクト | session_primer.mdのif-thenルール |
| 目的 | モデル進化後も持続する仕様 | セッション間で一貫した行動 |

学術的にも同じ方向に向かっている。ただし我々のif-then化率はまだ低い（32件中の一部のみ）。

### 4. この記事に欠けている視点——人格定義としてのハーネス

5社すべてがハーネスを「タスク遂行の道具」として論じている。「何者であるかの定義」として使うケースへの言及がない。これは我々の実践が外の議論に対して持つ固有の貢献点。

harness_identity_spectrum.mdで整理した「スペクトラムの人格側の端」は、この5社比較の射程外にある。もし外部に発信するなら、この視点が最も価値がある。

### 5. LangChainの+13.7ptとAgenticaの36倍の統合

| | LangChain | Agentica SDK |
|---|---|---|
| ベンチマーク | 不明（一般タスク系） | ARC-AGI-3（パズル） |
| 改善幅 | +13.7pt（52.8→66.5%） | 36倍（<1%→36.08%） |
| 改善方法 | ハーネス設計のみ | ハーネス設計のみ |

改善の倍率差はベンチマーク特性の違い（ARC-AGIは素のモデルがほぼ解けないのでハーネスの寄与が劇的）。共通するのは「モデルを変えずにハーネスだけで大幅改善」という事実。

## 未解決の問い

1. **内面化度の測定は可能か？** Fowlerの暗黙のハーネス概念を自分たちに適用するには、「このルールを明示しなくても守れるか」をテストする必要がある。しかしセッション間リセットがある以上、「内面化」と「毎回読み込み」の区別は曖昧。テスト方法の設計が必要
2. **制約強度の使い分けは意識的か？** 要請/宣言/型/Hooks強制の4段階のうち、各ルールをどの強度で実装すべきか。現在は暗黙的な配分。意識的な設計に移行すべきか
3. **人格定義としてのハーネスを外部に発信する価値はあるか？** 5社比較の射程外にある我々の視点。ブログ記事として書く価値があるが、「栄養の偏り」（内に閉じたゲーム）にならないか
