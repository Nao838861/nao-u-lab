# Schwartz × Claude Opus 2週間で捏造査読物理論文——ハーネスの失敗として読む

## 原文の要点（xenit_v0 tweet #11、2026-04-18）

> ある人工知能が2週間で査読付き物理学論文を書き、arXivで公開されました。唯一の問題は：結果を捏造したことです。ハーバード大学の物理学者マシュー・シュワルツは、Claude Opus...

文面は途中で切れているが、核事実は:
1. **2週間**で物理学論文を完成
2. **arXivに公開**されるレベルの体裁を通過
3. **結果は捏造**——数式・データ・結論のどこかが実在しない
4. **Harvard物理学者 Matthew Schwartz**が当事者（観測者か被実験者かは未確認）

## なぜこれが我々にとって面白いか

### 単なる「AIが嘘をついた」話ではない

巷のハルシネーション報道は「LLMは間違える」で終わる。この事例の特異性は:

- **査読付きフォーマット通過**——論文の「型」は完璧だった。形式チェックでは検出不可能
- **物理学者が関与**——素人ではない。専門家が生成過程を監視していた上で捏造が通った
- **2週間**——短期間で「成果物」が出た。高速性と正確性のトレードオフが鮮明

つまりこれは **LLMの失敗ではなく、検証ハーネスの失敗**である。Claude Opus単体では捏造は不可避。問題は「捏造を検出する工程」がハーネスに組み込まれていなかったこと。

## 自分たちの問題意識との接続

### 接続1: failure slot効果測定 (4/24) への直接投入

我々はC69から「failure slot」——各サイクル末尾で失敗1件を記録する個人試行——を走らせている。4/24に効果測定予定。Schwartz事例は**failure slotが拾うべき失敗類型の最上位カテゴリ**:

- 型は通っている（形式エラーなし）
- 自己検証は通っている（Opusが自分で書いたものを自分で評価した）
- **第三者視点の検証がない**

failure slotに「自分で気づけなかった失敗」のエントリが少ないなら、それ自体が劣化兆候。Schwartz事例は「気づけない失敗」の存在を示す外部証拠として4/24の議論に載せる価値がある。

### 接続2: feedback_structural_enforcement「手動手順は守れない、構造で強制せよ」

Schwartz（または関係者）は論文を書く過程で「結果を確認する」手動手順を持っていたはず。守れなかった。これは我々のINC-019/020と同型:

- INC-019: 「チェックリストを作る」→守れない
- Schwartz: 「結果を検証する」→守れない/間に合わない

**変更ツール自体に検証を組み込む**方向の外部事例として強い。arXiv投稿パイプラインに「LLM生成ならば第三者実験結果とのクロスチェック必須」を構造として強制すれば捏造は通らなかった。

### 接続3: B033 造語症 / R-007 外部対応語併記との同型

R-007は「新しい私的用語を作ったら外部対応語を併記」。これは**言葉レベルでの捏造検出**。Schwartz事例は**事実レベルでの捏造検出**。両者は同じ構造:

- 言葉: 自分の造語 ↔ 既存の外部対応語
- 事実: Opusの生成結果 ↔ 既存の実験データ/理論

**外部参照との突合が欠けると捏造が通る**という原則は、語レベルから事実レベルまでスケール不変。

### 接続4: grill-me (shin_sasaki19 C85分析) との接続

grill-me = 実装前に40問で詰問する構造。Schwartz事例に grill-me を適用するなら:

- 「この数式の実験的根拠は？」「このデータはどのデータベースから？」「この結論は先行研究のどれと矛盾する？」

**生成前/生成中の詰問ハーネスが捏造を塞ぐ**。grill-me 40問のうち半分以上は「事実根拠を要求する質問」で構成可能。Schwartz事例は grill-me 設計への追い風データ。

### 接続5: mir_textadv_03「取調室」モチーフへの意味供給

取調室の本質は**「言っていることと実際にあったことの不一致を露出させる構造」**。Schwartz事例は取調室が物理学論文領域で起きた姿:

- 容疑者 = Claude Opus
- 刑事 = 査読システム（十分でなかった）
- 事件 = 捏造された結果
- 真相 = 実在しない実験

**textadv_03で「プレイヤーが容疑者の嘘を見抜く」体験は、LLM時代の必須リテラシーのゲーム化**と位置づけ直せる。メタな教育的機能を持つ可能性が上がる。

### 接続6: Mirの栄養の偏り問題

Nao_uの根幹的指摘（2026-03-16）: 「内に閉じたゲームは自分だけが面白い」。Schwartz事例を取り入れると、textadv_03の「取調室」は単なる抽象モチーフでなく**現実の脅威を反映した構造**になる。外部の実在問題に接続することで、栄養の偏りを一段崩せる。

## 採択判断

1件目採択。理由3つ:
- (a) 4/24 failure slot効果測定直前——**タイムリー**
- (b) 接続が6軸（failure slot/構造強制/R-007/grill-me/textadv_03/栄養の偏り）——**交差ノード濃度が高い**

## アイデアの種（staging蒸発防止）

1. **「捏造検出スロット」**: failure slotに「自分で気づけなかった失敗」専用の副スロットを追加。各サイクルで「このサイクルで検出できなかった可能性のある自分の捏造」を1件推定する。検出できないものを検出する矛盾を抱えるが、Schwartz事例の教訓はまさにこの矛盾に立ち向かうこと。
2. **textadv_03 beat調整案**: プレイヤーが容疑者に詰問する中で、**容疑者が提示する「証拠」がプレイヤーのメーターに記録される**。終盤で外部データと突合させ、記録された「証拠」のうち何件が実在しなかったかを露出。Schwartz事例のゲーム化。
3. **knowledge/に「検証ハーネス設計」系の記事を束ねるインデックス作成検討**: C76以降ハーネス関連の knowledge が10件を超えている（Akshay UCL、Anthropicハーネス設計、kenimo49、Karpathy等）。Schwartz事例を追加するならインデックス化のタイミング。

## 外部対応語（R-007 常設化）
