### MLB 死球（Hit By Pitch, HBP）罰則の制度史

野球の公式規則では、投手の投球が打者の体に当たり、打者がそれを意図的に避ける動作を取らなかった/避けられなかった場合、打者は一塁に進塁する（公認野球規則 5.05(b)(2)）。設計意図は明確で、「投手は打者を狙うな」という抑止——投手側に「当てたら相手にベースを与える」という罰を課すことで、投球の暴れを抑え、打者の安全を担保する。

ところが100年スパンの記録は、この罰則が **罰として機能しない局面** が繰り返し発生したことを示す:

1. **Hughie Jennings (1893-1903) の 287 career HBP**: 当時の最多記録。意図的にプレートに体を近づけ、当たりに行く戦術が初期から成立していた
2. **Ron Hunt 1971シーズン 50 HBP**: 単一シーズン最多。Hunt自身が「I came to play」と称して当たりに行くスタイルを公言
3. **Don Baylor 1970-80年代キャリア 267 HBP**: 体格を活かし内角投球に体を被せる打撃フォームで継続的に出塁
4. **Craig Biggio 1990-2000年代 285 HBP**: protective elbow guard（肘当てパッド）の普及で打者側コストが下がり、当たりに行く戦術が **道具で支えられた**。MLBは2002年に肘当てサイズを規制したが、HBP率の歴史的増加（1980年代0.3 per game → 2020年代0.5 per game、約1.7倍）は止まらなかった

この一連の事象が示すのは、設計者（ルール起草者）が前提にした「打者は当たりたくないので避ける」という **制度的行動予測レール** が、現実のプレイヤー（プロ選手）の utility 計算と乖離した瞬間、罰則条文（「打者を一塁に出す」）の符号が抑止装置から exploit装置に **反転** したという事実だ。

打者の utility 計算は単純: 通算打率0.250 = 4打席に1回しか塁に出ない打者にとって、1打席を確実に一塁出塁に変える HBP は **打率4倍の効率**。痛みや怪我リスクを差し引いてもなお打者側にとって正の期待値であれば、当たりに行くのが合理的になる。Hunt と Biggio が示したのは「痛みコスト < 出塁効用」という個人差を活用した最適化だ。

### R_Nikaido レール（knowledge/20260427_r_nikaido_design_rail_explains_m12.md）の institutional 拡張

本日午前に Phase 2 で書いた R_Nikaido 記事は「死にゲー設計者は『プレイヤーは攻撃するやろ→反撃するやろ→そこに罠』という頭の中の予測軌跡上に罠を置く。レールから外れると罰は機能せず、レールに乗ると罰は機能する」を扱った。これは個人設計者 vs 個人プレイヤーの射程だった。

野球の死球罰則は、同じ構造を **制度設計者集団 vs プレイヤー集団** の射程に拡張した実例として読める:

| R_Nikaido レール（個人設計） | 野球死球罰則（制度設計） |
|---|---|
| 設計者の頭の中の「典型プレイ軌跡」 | ルール起草者の頭の中の「規範的打者像」 |
| 軌跡外プレイで罰が空振りする | 規範外打者（当たりに行く）で罰が exploit 化する |
| 罰の質量と快感の連鎖が一致 | 罰の質量（一塁進塁）と打者効用（出塁率向上）が一致してしまった |
| レールを観測ベースで引き直せる | ルールを統計ベースで再設計できる（MLB 2002 肘当て規制 = レール再描画の試み） |

つまり @ponzutigers2 が指摘した「罰が甘いことを悟った玄人」は、R_Nikaido が個別ゲームで観察した「レール外プレイで罰が空振り」の現実版であり、しかも **意図的にレールを外しに行くプレイヤーが熟練者として勝つ** という入れ子構造になっている。死球罰則は罰として機能していないどころか、報酬への変換器として exploit されている。

### memory/game_lessons_log.md M-12 / M-19 / M-23 への補強

我々の game_lessons_log を本事例で再点検すると、3つの教訓が institutional 規模で並列して再現していることが見える:

**M-12「罰ではなく報酬で設計せよ」（avoid_log v03/v04 ベース）**: 我々が avoid_log v03/v04 で「鉄片を撃たないと地雷化する」「自然減衰で減点」を入れて失敗したのと、MLBが死球を「打者一塁進塁」として罰した結果 Hunt/Baylor/Biggio に exploit されたのは **完全に同型** だ。罰の数値設計が罰側コスト < プレイヤー利得になった瞬間、罰は推奨装置に転じる。M-12 の言い換え「行動予測レール不在のまま罰を置くな」（本日の R_Nikaido 再解釈）は、レールがあったとしても **レール上のプレイヤー utility 計算を見落とすと罰は反転する** と更に補強される。

**M-19「フレーバーR-007回避」と異なる軸の exploit**: M-19 は「私的造語が外部に通じない」という告知文の問題だったが、HBP exploit は「ルール条文の意図と数値が外部に通じすぎて、外部側がルールの隙間を熟達した」という逆方向の問題。M-19 は **設計者→外部** の伝達失敗、HBP は **外部→設計者** の意図解釈成功と utility 最適化。両方とも「設計者が制御できると思った領域が制御できていない」点では同じだが、向きが逆。罰設計は両方向の検証が必要ということ。

**M-23「自然減衰は完全に不要」（2026-04-25 Nao_u対面）との接続**: 自然減衰が罰として機能しない理由は「プレイヤーの能動行動と紐づいていないので学習の手がかりにならない」と Nao_u が指摘した。HBP 罰則は逆に「打者の能動行動（当たりに行く）を罰側コスト（痛み）と直接紐づけたが、痛みコストを下げる外部要因（肘当て等）が出ると罰側だけが下がりレールが反転する」。**罰のコスト変動を能動的にプレイヤーが下げに行ける場合、罰は時間とともに無力化する** という新しい教訓を立てられる。

### ash_onebutton v04（本日 Phase 3 実装済み）が拓く道

本日 Phase 3 で実装した ash_onebutton v04 は seed固定リプレイログ + ゴースト軌跡 + press統計を最小1パッケージで搭載した（game/ash_onebutton/v04/devlog.md）。当初の設計意図は「@R_Nikaido が言う設計者の頭の中の予測レールを観測ベースで引き直す道具」だったが、本記事の HBP exploit 事例に照らすと、観測装置のもう一つの用途が見える:

- **罰の符号反転の早期検出**: ある罰メカ（avoid_log v05 想定の自然減衰や地雷化）を入れた直後、複数 trace の press パターンを集めて「罰を意図的に踏みに行くプレイヤーが現れていないか」を検出できる。死球罰則は MLB 100年で気づくのに遅れたが、3人 + 過去/未来の自分の trace 比較なら数日〜数週で検出可能
- **utility 反転点の数値推定**: trace に press 位置 + 罰発生時点 + 残機 + score を全て記録すれば、「罰側コストがどの数値で報酬を下回ったか」をプレイ後に逆算できる。MLB は HBP 率の歴史的増加を可視化するのに30年かかったが、我々は v04 の JSON download → 集計で1サイクルで可視化できる

つまり v04 は「個人レベルでの予測レール構築装置」として始めたが、HBP 事例を通すと「**罰の符号反転を sample 数百〜数千の規模で早期検出する装置**」として再定義できる。

### Pot v03 / avoid_log v05 への含意

`memory/game_lessons_log.md` M-12 の改訂条文「**罰のコストはプレイヤーが能動的に下げに行ける外部経路を持つか確認せよ。持つ場合、その経路を遮断するか、罰そのものを撤去するか、どちらかを選ぶ**」を Pot v03 / avoid_log v05 のチェックリストに追加する根拠が立つ。

具体的には:
- avoid_log v03 自然減衰罰: プレイヤー側に「画面端に弾を流さない」という回避路があった = 罰が能動回避可能 = HBP の肘当て相当 = 反転候補。実際反転していた（Nao_u プレイで「やらされている感」発生）
- Pot 016b midpoint 寿命: プレイヤーが「最初から完璧タイミングを目指す」という回避路を取れた = 寿命減衰罰が能動回避可能 = 反転候補。実際反転していた（2回目以降ほぼ満点）

事後分析だが、**「能動回避路の有無」を罰メカ採用前のチェック項目にすれば** 同じ轍を踏まない。これは M-23（自然減衰禁止）と M-12 の両方を統合する一段上の判定基準になる。

## 未解決の問い

1. **罰の符号反転は時間スケールで不可避か**: MLB 100年、avoid_log 1週間、両方で反転が観測された。スケール非依存だとすると、罰そのものを設計から撤去するのが最も安全な道だが、死にゲー（SEKIRO/IWBTG）の罰は機能している。差は「能動回避路の有無」だけか、他に隠れたパラメータがあるか
2. **観測ベース反転検出の最小 sample 数**: HBP は MLB レベルで30年×30球団×162試合の標本があって統計的に見えた。個人ゲームで同等の検出を狙うとき、3人プレイヤー×何 trace で反転が見えるか。v04 の JSON 集計で実証可能
3. **罰の utility 反転は M-12 とは別の独立教訓として立てるべきか**: M-12「罰ではなく報酬で」+ M-23「自然減衰禁止」の派生として処理するか、新規 M-28「罰の能動回避路チェック」として独立させるか。次の cross_review で判定
4. **「玄人」プレイヤーは反転を加速させるか減速させるか**: @ponzutigers2 が言う「悟った玄人」は exploit を最大化する側だが、同時に「これは exploit だ」と外部にラベルを付ける機能も持つ。observability 観点では玄人プレイは反転検出の早期サインだが、放置すれば反転を完成させる。Pot v03 / avoid_log v05 で熟達プレイヤー（過去自分含む）の trace を区別記録すべきか
