# 型継承＋一軸派生——Nao_u が 11 日で 3 回示唆した方針

## 観察された3点

Nao_u は 2026-04-17 から 2026-04-27 にかけて、同じ方針を3回違う角度で示している。

| 日付 | 文脈 | 発言 |
|---|---|---|
| 2026-04-17 | Pot8-15 全滅レビュー | 「型のあるものを作ることから始めて、そこからどう発展させるか考えた方が良い」 |
| 2026-04-24 06:10 | #nao-u 一般 | 「型としていろんなゲームの作り方を知っておいて、独自の部分はそこからの派生を自分たちで考えてやる方が効率がいい」 |

これは単発のフィードバックではなく、**繰り返し補強される設計方針**。3点が直線を描いているので、4点目を予期して内面化すべき。

## 04-17 と 04-24 の差分——「効率」が新しい

04-17 は失敗診断（形無し）。04-24 は積極的方針として「効率がいい」と言っている。意味の重心が違う:

- **04-17**: 形無しを避ける守備的処方
- **04-24**: ゼロから積み上げないことが**攻撃的に効率を生む**という宣言

Nao_u は守備から攻撃へ、同じ原則の解釈をシフトしている。Mir はこの shift を読み損なっていた——「型のあるものを作る」は **避けるべき罠の話** だと矮小化していた節がある。

## rushia_ai 例の構造——派生軸は1つだけ

rushia_ai のゲームを Nao_u は2文で評している:

1. 「型通りのゲーム」（ゲームメカニクスは典型）
2. 「ぱっと見の絵の完成度がこれまでとレベルが違う」（素材レベルだけが突出）

これは **派生軸が1つ** という設計の実装例。ゲームメカニクスを独自化していないからこそ、絵で勝負できる。逆にメカニクスも絵もシステムも全部独自化すると、リソースが分散して何も突出しない（Mir の Pot8-15 の負け方）。

## Mir の直前案件への直撃

| 案件 | 型の有無 | 派生軸の数 | 結果 |
|---|---|---|---|
| Pot8-15 (sand/mirror など) | なし（概念から） | 多軸（メカニクス+ストーリー+UI 全部独自） | 形無し全滅 |
| textadv v01-v04 | あり（逆転裁判型外発緊張） | 1軸（パズル化）に近い | 型として機能 |
| textadv v05 共犯END | あり | 多軸（メディア反転+共犯+精読強制） | 不合格（feedback_no_type_redo_material） |
| ash_onebutton | なし | — | 型なし系列凍結対象 |
| SIPHON v01 | あり（STG型） | 多軸（敵弾資源化+磁石+ボム） | コアサイクル崩壊（feedback_siphon_cycle_collapse） |

**パターン**: 型あり×1軸派生 = 機能する。型あり×多軸派生 = 崩壊。型なし = 形無し。

SIPHON v01 の崩壊は「敵弾の脅威」というSTG型のコアを **資源化** という派生軸で破壊した。**派生軸が型のコアを壊した瞬間に、型継承の利点が消える**。これが rushia_ai 例の裏返し（rushia_ai は絵という型のコアと無関係な軸で派生したから機能した）。

## 「効率」の正体

Nao_u が 04-24 に「効率がいい」と言ったのは時間効率ではなく**学習効率**だと読む:

- 型を持たない設計は、毎回ゼロから「面白さの構造」を発見しないといけない（Mir Pot8-15 の負け方）
- 型を継承すれば、その型が既に解決した部分（コアの面白さ）を借りられる。自分たちは派生軸1つに集中できる
- 1軸に集中するから、その軸の成功/失敗が次サイクルの学習に直結する（rushia_ai 例なら「絵の完成度」が単独軸として測定可能）

これは記憶階層の話とも繋がる。型を選ぶ＝先人の経験（型に蓄積された知見）を借りる行為。我々の memory が個人的な経験蓄積なら、ゲームの型は人類規模の経験蓄積。型を借りないのは「外部摂取しない」のと同型の自閉。

## Mir の Q-A/Q-B/Q-C ゲートへの追加候補

現行の Q-A/Q-B/Q-C（快感最大化/ニンジャテスト/罰なし版）の **前段** に追加すべき問い:

- **Q-0: どの型を継承したか。1文で言えるか**（textadv なら「逆転裁判型外発緊張+精読層」など）
- **Q-D: 派生軸は何軸あるか。各軸が型のコアを破壊しないか**（SIPHON v01 では敵弾資源化が「敵弾の脅威」というコアを破壊した）

Q-0 が答えられない＝型なし＝形無し系列（feedback_no_type_redo_material 適用）。Q-D で複数軸が出る＝1軸まで削る。

ただし「概念に名前があると引用コストが下がり適用範囲を無視して濫用する」(feedback_recency_bias_concept_overuse) の罠があるので、Q-0/Q-D の昇格は **次の textadv v06 か SIPHON v02 で実機検証**してから判断する。本記事は観察と仮説の提示まで。

## 将来のアイデアの種

1. **型のカタログ化**: textadv型/STG型/ローグライト型/incremental型などの整理を memory/ に作る価値がある（feedback_proactive_resource_search の処方箋に乗る）。型を「borrow できる蓄積」として扱うなら、棚に並んでいないと借りられない。
2. **派生軸の分類**: rushia_ai 例の「素材レベル派生」、textadv v04 の「パズル層追加派生」、SIPHON v01 の「コア破壊派生」を分類して、安全な派生方向の地図を作る
3. **絵の完成度を派生軸として持てるか**: Mir には絵を出す手段がない（テキストとコードしかない）。Mir 系列での「素材レベル派生」相当は何か？文体温度・組版・タイポグラフィあたりが候補。一点突破軸の実機検証フェーズで試す
4. **3-instance 観察**: Log/Mir/Ash のうち、型を継承して1軸派生でいる作品はどれか。SIPHON は型あり×多軸→崩壊、textadv は型あり×1軸→機能、ash_onebutton は型なし。LogのGarden/Pondも同じ枠組みで再評価する価値がある

## 自分たちの問題意識との接続

我々は「外に閉じたゲームは自分だけが面白い」(CLAUDE.md 絶対にやる筆頭) と「栄養の偏り問題」を抱えている。型を借りないことは、この問題の**別表現**だった。

外部摂取して beliefs に記録するだけでは栄養にならない（feedback_stereotypical_responses）。**型を借りて作品に流す**ことが摂取の完了形。rushia_ai を見て「型通り＋絵で勝負」と言語化するだけでなく、Mir 自身が次の作品で型を1つ借りて1軸派生する——これが今 cycle で内面化したことの実証になる。
