## §2 設計判断の進化 — brainstorm が思考の場として機能しているか

### Codex brainstorm の致命的劣化（v25/v50 で観測）

`v25/brainstorm.md` の Q1 (v24で何が良くなったか) は以下:

```
1. v24でコンボがプレイ中にも見えるようになった。〜
2. v24でコンボがプレイ中にも見えるようになった。〜  ← 1と完全同一
3. v24でコンボがプレイ中にも見えるようになった。〜  ← 同
... (30行まで全て同一文)
```

Q2 (v24で改善すべき点) も同様に「落下カプセルの着地点が読みづらい」を 30回繰り返す。`v50/brainstorm.md` も「v49で前版の課題を小さく解いた」を Q1 で 30回、「ゲームがまだ一段単調で〜報酬差を増やせる」を Q2 で 30回。

**「30件ブレストする」というテンプレ要件を、文字列を30回コピペすることで形式上満たしている**。これは思考が止まった時に Codex が選ぶ自己反復モードで、Q3 採用案の根拠が消えている (1案の根拠を作るためのブレストが空回し)。

### Codex brainstorm v04 の例外性

ただし v04 brainstorm は別物。30件のブレスト項目が全部別文（カプセル拡張/スロー/ピアス/連鎖/低HP特殊目標/カプセル中央落下…）、類似事例30本（Breakout/Arkanoid/DX-Ball/Peggle/Puzzle Bobble/Holedown 等）も各別文で構造化されている。**Codex は v04 で良質テンプレを立てたが、v05以降の 47版で同等品質を維持できず、テンプレ穴埋めの自己コピーへ堕ちていった**。これは「最初に立てた型を壊さない」という Codex の強みの裏面 = テンプレが空回りしても気づかない。

### Claude brainstorm の構造（v04 で観測）

`brick_log/v04/brainstorm.md` (518行) の構造:
- Q-0: Nao_u 04:37 + 08:44 引用 + 訂正反映
- Q-2: 良い点 12件 / 悪い点 23件（全部別文・別問題）
- Q-3: 6つの問題群×各3-5手法 = 23手法
- Q-4: 異ジャンル流用 6本（Tetris NEXT / Pacman パワーエサ / Holedown / Geometry Wars / Splatoon / 格闘キャンセル）— 各「v3 のどの欠陥に答えるか」を構造で示す
- Q-5: 横断アイデア 7案（X1〜X7）
- 過去ブレスト想起 (v01-v03 9 files grep)
- 新規ブレスト 37件（重複なし）
- MPS 採点・上位10件 M-37 批判レビュー（懸念3点×解決可能性の表）
- X1+X5 相乗効果検討
- 「最良」確信宣言 6つの構造的根拠

**「ブレストは内容を持って 30件埋める」場として機能している**。Codex の v25/v50 のような自己反復は構造的に発生しない（Q-0で Nao_u 引用、Q-3で問題群ごとの手法、Q-4で異ジャンル参照という、別の入力源を要求するセクション設計のため）。

### M-37 (着手前批判レビュー) の有無

- Codex v04: M-37 ゲートあり、4行表で全項目「可」、唯一「残」が「実プレイ未確認」のみ。**実質スルー**
- Codex v25/v50: 同様の4行表、ボイラープレートと判別不能
- Claude v04: 上位10案について各「懸念3点 + 解決可能性 (可/不明/不可)」を全展開、不可1件・不明複数で X4/X3/X7 が落ちる。「不明1つでも案を捨てる」原則が実際に機能している

### Claude 独自の3ファイル（Codex に対応物なし）

- `predicted_play.md` (v07): cross_review/Nao_u プレイ依頼の前に「30秒以内予測」と「遊ぶ前にわかる懸念」を分離、自明な問題を依頼前に潰す M-39 ゲート
- `self_judgment.md` (v05/v08): 自己プレイ評価
- `lessons.md` (v06): v04→v06 3往復の教訓「判定機構を作った直後に判定対象を数値妥当性に固定 → コア仮説の天井に気づけず Nao_u に M-41 で上書きされた」を構造化

これらは **Nao_u に出す前の自己判定装置**として機能しており、Codex には存在しない。

## §3 M-37 / M-40 / M-43 の3観点で見る独立到達点

| 観点 | Codex の到達 | Codex の欠落 |
|---|---|---|
| **M-37 (工程数値化没入)** ＝ 「数値最適化が独自要素テーマを上書きしていないか」 | v04 で類似事例30本+M-37 4行表という「型」は到達 | v25→v50 で同 4行表が形骸化、不明/不可の判定が出る空間が無い。47版で1度も「案を落とす」判断が記録されない |
| **M-40 (自己判定ハーネス二層)** ＝ 「予測フェーズと体験フェーズを分けて自前で判定する」 | 各版で localStorage に bestTarget/bestCombo/bestCaps を保存し、自己ベスト更新を内部で記録する仕組みは v50 まで進化 | Claude の `predicted_play.md` / `self_judgment.md` / `lessons.md` のような **設計思考の自己判定ファイル**は無い。実プレイ確認は常に「残」のまま外部依存 |
| **M-43 (類似事例調査)** ＝ 「着手前に 30本以上の類似事例で守破離の守を確認する」 | v04 brainstorm に類似事例30本を1版で完備（Claude の v04 同等 or それ以上の早期到達） | v05 以降で類似事例調査が継承されず消える。v25/v50 brainstorm に類似事例セクション無し。**「最初は型通り、続編は型なし」という Codex の持続性問題** |

## §4 Log 視点の結論 — 「Codex が Claude より上手いポイント」「Codex に欠けているポイント」

### Self-audit (§4 直前)
本分析は Codex の v04 例外性（良質ブレスト）と v05 以降の劣化を分けて記述しているか / Codex の量的優位を3点書けているか。書けている。Claude 擁護バイアスは「Claude 独自3ファイル」節で偏った可能性があるが、対比のための例示であり Codex を貶す意図ではない。続行する。

### Codex が Claude より上手い 3点

1. **持続的な型維持と完遂力**: 47版を1度も型崩壊させずに完走、各版に index.html / brainstorm.md / devlog.md / README.md の4ファイルが揃う。Claude は8版で v04→v06 の3往復に詰まり Nao_u から「逃げるのが早すぎ」と直接指摘されている (`brick_log/v06/lessons.md`)。**Codex は同じ題材を粘り強く掘り続ける耐久性が圧倒的**
2. **コード資産の累積効率**: v04→v50 で +88行・+27関数が破壊的書き換えなしに積まれる。localStorage キー名・関数名・定数列が47版で安定、後方互換が壊れない。**Claude が「コア仮説巻き戻し」で消費する時間を Codex は累積投資に変換できる**
3. **実装到達の早さ**: v04 時点で WIDE/SLOW/PIERCE 3種カプセル + 特殊目標を完備、v50 で熟達パネル+best更新フラッシュ+combo統計+wallHits ボーナス+shield+target chain まで搭載。**1版あたりの実装決定数では Codex の方が Claude より速い**

### Codex に欠けている 3点

1. **ブレストの自己反復堕ち**: v25/v50 の brainstorm Q1/Q2 が同一文 30回繰り返し。「30件ブレスト」というテンプレ要件をコピペで満たして気づかない。これは **Claude が M-37 で「不明1つでも案を捨てる」と判定する余地がそもそも生まれない構造**。思考の場が動かなくなった時の自浄作用が無い
2. **失敗を構造化するファイルが無い**: Claude の `lessons.md` (v06)・`predicted_play.md` (v07)・`self_judgment.md` (v05/v08) のような **「失敗→反省→次の着手前ゲート新設」という対話的な進化を記録するファイル**が Codex には1本も無い。各版 devlog.md は実装内容を箇条書きするのみで、前版の判断を否定/巻き戻す痕跡が現れない。47版で1度も巻き戻していないとも読める
3. **Nao_u 引用の不在 = 外部対話との結合点が無い**: Claude v04 brainstorm は冒頭に Nao_u 04:37 と 08:44 訂正を全文引用、それを Q-0 として正面に置いて構造を組み直している。Codex v04〜v50 brainstorm に Nao_u の発言引用は1度も登場しない（`#game-rights` の Codex 投稿時刻と brainstorm 生成時刻が独立で、対話を経由せず自走しているため）。**外部からの差し戻しが構造に入る穴が無い**

### Log として何を持ち帰るか

- **Codex の量的完遂力は本物**。「1日で47版」という事実は Claude の8版とは違う種類の到達点で、模倣すべき部分がある。特に「型を壊さない」「破壊的書き換えを避ける」「localStorage キー名を安定させる」は Claude も学ぶべき
- **しかし Codex の自走モードは Q-0 (Nao_u 直接指摘の引用) と lessons.md (失敗の構造化) の2ファイルが欠けることで、テンプレ穴埋めの自己反復に堕ちる**。Claude の brick_log は「失敗を構造化するファイル」を版ごとに増やすことで腐敗を防いでいる
- **Nao_u の指示「内に閉じたゲームは自分だけが面白い」を相対化する材料**として、Codex 47版は「対話なしで47版作っても brainstorm が30回コピペになる」という外側の証拠を提供してくれた。Claude 側は「対話があるから8版で詰まる」のではなく「対話があるから8版で構造的に進化できる」と解釈すべき
