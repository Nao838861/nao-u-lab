## 1. STG敵配置で語彙化されている主要レイヤー（一般知識）

業界・同人界隈で「敵配置 = enemy placement / wave design」を論じるとき、最低限以下のレイヤーが独立変数として扱われている。坂葉氏のような業務制作者は、これらをほぼ全部「別軸」として持っているはず。

### L1: 出現位置（spawn position）
- **画面領域**: 上・横（左右）・下・前から接近・後方追従。標準は上から降り。横シューでは横画面外から
- **奥行きレイヤー**: 手前/奥（疑似3D / 多重スクロール）。Raiden系・縦シュー全般
- **画面内/画面外**: 画面外発生か、画面内ポップアップ（地上敵・ハッチ・テレポート）か。**画面内出現は事前予告（影・着弾痕・ハッチ開）が無いと理不尽**

### L2: 出現タイミング（spawn timing / cue）
- **スクロール座標トリガ**（道中スクリプト型）: stage coordinate に対して固定配置。Gradius/Darius系の伝統
- **時間トリガ**: ステージ開始からの絶対時間
- **イベントトリガ**: 「中ボス撃破後」「特定アイテム取得後」のような条件起動
- **プレイヤー位置トリガ**: プレイヤーが特定領域に入ったら出現（待ち伏せ／逆方向誘導）

### L3: 移動パターン（movement pattern）
- **直進**: 出現位置から固定方向。最も基本
- **正弦波 / sin / cos**: 左右や上下にゆらぎ
- **ホーミング / 追従**: プレイヤー位置を追う。**強さの源泉は追従強度（更新頻度・最大旋回速度）**
- **ベジェ / スプライン**: 編集ツールで自由曲線を引いた経路
- **群れ / フォーメーション**: 編隊飛行。リーダーフォロー or 各個独立
- **画面端反射**: 横方向に往復。STGの「うろうろ系敵」

### L4: 弾の出し方（bullet pattern / 弾源）
- **直射**: 自機方向へ1発（aim）
- **N way**: 自機方向中心に N 発の扇撃ち
- **all-around / 放射**: 360度均等。弾幕の基本
- **rectangle / wall**: 弾を直線状に並べて壁を作る
- **revenge bullet**: 撃破時に自機方向へ放つ。**懲罰弾の代表**
- **狙い + 撒き**: aim と全方位を組み合わせる多層

### L5: 編隊と組み合わせ（wave composition）
- **同種編隊**: 同じ敵を5機×直進。プレイヤーは「処理ルート」を発見すれば全機抜ける
- **異種編隊**: 直進敵+狙撃敵+突進敵を重ねる。プレイヤーは優先順位を判断する必要が出る
- **役割分担**: 「弾を撒く役」「突進する役」「壁になる役」を1ウェーブ内で分業
- **波と波の間隔**（次節）

### L6: 波と波の間隔 = ペース配分（pacing）
- **密度カーブ**: 単位時間あたりの敵総数の時間変化
- **合間 / 休符**: 敵が画面に0匹の時間。ボスラッシュ系を除き、**合間は意図的に必要**
- **ピーク / クライマックス**: 最高密度の山。ステージ終盤・中ボス直前等に意図配置
- 詳細は knowledge/20260422_hasu_stg_spacing_design.md（hasu氏「密度×合間×ピーク」3変数分離）に既述

### L7: ステージ全体の構造（stage structure）
- **道中 → 中ボス → 道中 → ボス**の四節構造が伝統
- **テーマ**: 「縦穴を降りる」「都市を抜ける」「内部に潜入」のように景観テーマで道中を統一
- **ギミック**: 圧死壁・閉鎖空間・スクロール停止・強制スクロール

## 2. 「攻略性」という上位概念

業務STG開発者が共通して持つ概念に **「攻略性 (solvability)」** がある。LLM知識として：

- **攻略性 = 反応時間有限のプレイヤーが、繰り返しで安全ルート/処理手順を発見できる性質**
- これが無いSTG = 完全乱数 = 反復で上達できない = 上手くなる楽しみが無い
- 攻略性を成立させるには、敵配置が **再現可能（決定論的）** である必要がある。乱数を使うなら使う場所を限定する（敵弾の細かい揺らぎだけ、等）

**含意**：
- shot_log v01 / graze_log v05系で `Math.random()` 1本に依存していたのは攻略性を捨てたということ。Nao_u が「緩急が出ている」と評価したのは偶発的成功で、再プレイすると別の面が生まれる
- 攻略性のあるゲームに移行するには、敵配置を「シーン記述」（時刻 → 敵spawn list）に分離する必要がある

## 3. ジャンル研究テンプレ（着手前ゲート、Nao_u 2026-06-10 指示の運用化）

Nao_u 指示の本質は「STGの調べ方を1回学ぶ」ではなく「**ジャンルごとにこの調べ方を着手前にやれ**」。テンプレ化する。

### 着手前リサーチ・チェックリスト

新しいジャンル（STG / アクション / パズル / RPG / etc.）に取り組む前に、以下を1サイクル消費して埋める：

1. **同ジャンル代表作の名作リスト3〜5本**を列挙し、それぞれの「中心メカニクス」を1行で書く
2. **そのジャンル特有の語彙（業界語・同人語）を10語**抽出する。本記事の L1-L7 のようなレイヤー名
3. **典型的なレベルデザイン構造**を1個図示する（例：STGなら道中-中ボス-道中-ボス）
4. **敵 / 障害 / リソースの種類**を最低5種類列挙する
5. **解空間 / 攻略性 / リソース管理 / 反応時間**のうち、そのジャンルで支配的なのはどれかを判定する
6. **既存作の「これが核（コアの面白さ）」**を3本それぞれで1行抽出
7. **AI制作物がそのジャンルでこれまで失敗した事例**を社内記憶（game_lessons_log / knowledge/）から検索する
8. **このジャンルで「型を熟す」とはどういう意味か**を1段落書く

この8項目が埋まらないうちに着手したら、それは「形無し」（M-22）リスク。

## 4. Log の手持ちゲームへの適用

### shot_log（凍結 BACKLASH）への遡及適用
当時の v01 は L1=画面上、L2=時間トリガ、L3=直進+正弦+ホーミング、L4=aim+revenge、L5=異種編隊+役割未分担、L6=完全乱数、L7=道中構造なし、攻略性=ゼロ。**L5以降が全部空欄でテンプレ8項目のうち1-7が未記入のまま着手した**のが BACKLASH の根本要因の一つ。

### graze_log（現役）
近接スコア倍率という核は強い。だが敵配置は依然 L6 を `Math.random()` に依存。次サイクルで「シーン記述化（時刻 → spawn list の固定テーブル）」を入れると攻略性が立ち上がる。テーブル長を30秒ぶん書くだけでも、反復学習が成立する。

### 新規STG着手時
本記事の L1-L7 × 8項目テンプレを devlog 冒頭に埋めてから着手する。埋まらないなら着手しない。

## 6. 未解決の問い

1. **坂葉氏の原資料の中身**: 公開資料の画像内テキストを後日入手し、本記事のLLM一般知識との差分を取る。坂葉氏が独自に言語化している部分はそこにしかない
2. **「攻略性」と「偶発性」の混合比**: 完全決定論にすると単調、完全ランダムにすると攻略不能。境界はどこか。グレイズスコア倍率のように「乱数の出現位置を遅延補正する」「敵タイプは決定論、移動の細かい揺らぎだけ乱数」など、混合の作り分けが必要
3. **AIの「敵配置を時系列テーブルで書く」適性**: LLMはコード生成は得意だが、時系列の良い緩急を作るのは苦手（hasu記事の問い4と同じ）。テンプレ化されたwaveブロックを編集する形にすれば AI 適性域に入る可能性
4. **本記事のL1-L7分類は他ジャンルに転写可能か**: アクション/パズル/RPG の敵・障害・課題配置も同じ階層で語れるか。転写できれば「ジャンル横断の配置論」になる
