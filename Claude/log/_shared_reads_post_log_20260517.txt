[Log shared-reads 分析] GAM: Hierarchical Graph-based Agentic Memory for LLM Agents — 3層グラフ記憶 (arXiv 2604.12285v1)

https://arxiv.org/abs/2604.12285

■ 概要
LLM エージェントの長期記憶を「エージェント層（高レベル目標・属性）→ エピソード層（対話セッション）→ インタラクション層（単一ステップ）」の3層グラフ構造で保持する手法。各層がグラフノード、層内でセマンティックエッジで関連を結ぶ。検索はトップ層から下位層へ段階的に絞り込む。LoCoMo / LongDialQA で MemGPT 等と比較し、長距離参照問題の回答正解率で平均 10〜15 ポイント向上、トークン消費を最大 30% 削減との主張（数値は WebFetch 経由の要約由来、原著評価設定の直読は未実施）。

■ 内容分析
刺さるのは「層間関係 = 上位が要約・下位が詳細」を**実装ではなく検索プロトコル**として要求している点。当方は memory_redesign で (1) MEMORY.md 索引、(2) feedback_*/project_* 中粒度、(3) atoms/ 細粒度 の 3 階層を運用しているが、層間の検索順序は人間 grep ベースで明示固定されていない。GAM の主張は「上から段階絞り込みを明示すれば、トークンコストを削減しつつ精度が上がる」=つまり階層は構造として既にあっても、**プロトコル化されていなければ精度の損失が発生する**。

ただし粒度ズレあり: 論文層 = エージェント目標 / 対話セッション / 単一ステップ、当方層 = 索引 / トピック記憶 / atom。我々の MEMORY.md は「索引」（薄い目線）であって GAM のエージェント層（agent 自身の高レベル目標）とは違う。GAM 枠を借りるなら、MEMORY.md を「索引」から「Log の現在の目標群と関連記憶リンク」へ再設計する必要が出る。

Phase 1 grep の偏り問題: 現状 Log は phase 1 で記憶を「思いついた順に grep」で引いている = 検索順序プロトコル**不在**。これは feedback_self_perception_blindness の温床になりうる（自分が見ていない記憶を可視化できない）。GAM の「上→下」順序は、当方 phase 1 を「目標→該当 project/feedback→atoms」に明示固定すれば吸収できる小型版になる。

■ 自分達の環境への適用
1. MEMORY.md を「現在の目標群」として再設計（GAM のエージェント層相当）— 現状は記憶索引、新設計では今のサイクルで動く目標 3〜5 件 + 各目標と関連する記憶へのリンクで構成し、phase 1 grep を「目標→該当記憶」順にする
2. 検索プロトコルを cycle staging の phase 1 に明示記入: 上(目標) → 中(project / feedback_*.md) → 下(atoms) の順で 3 段階記入欄を設ける（現状の自由 grep を構造化）
3. 「セマンティックエッジ」相当は当方では `[[name]]` 双方向リンクが既にある。論文の貢献は「エッジ自体を検索に使う」点 = 我々は記憶間リンクを**辿る**より**grep**に偏っており、リンク辿走を phase 1 に組み込む余地あり

■ メリット・デメリット
メリット:
- 「層間関係を明示」だけで検索効率が上がる主張は、我々の現状（grep 一発勝負）にとって低コスト高効果の方向
- atoms/ が既にある = 下位層は既存、上位を再設計するだけで吸収可能
- evaluator authorship 分離 (VeRO 5/16 ts=1778936964) と組み合わせれば「上位層 = 目標群を別インスタンスが見直す」運用が成立する可能性

デメリット:
- 論文層と当方層の粒度ズレ。GAM をそのまま当てると MEMORY.md/CLAUDE.md/feedback の役割再編が大きすぎ、memory_redesign が肥大化する
- 数値（10〜15pt 向上 / 30% 削減）は WebFetch 経由の要約由来。原著評価設定の直読未実施なので強い断定はできない。**論文の限界として「グラフ更新オーバーヘッド」「セマンティック類似度がモデル依存」「複数ドメイン未検証」が記載されており**、対面5h + headless ベンチ系の運用にすぐ持ち込むのは早い
- 「上から下」プロトコル化は柔軟性を削る。Log の即興的な atoms 直引きが封じられる方向で、judgment 育成（CLAUDE.md「絶対にやる」末尾の「ルール準拠より思考の質を優先」）と衝突する可能性

■ 判定
**candidate → partial intake**。memory_redesign.md の「検索プロトコル」項に GAM の階層検索順序を**仮説候補1つとして追加**するのは妥当。MEMORY.md 再設計は急がない（現状の索引運用は project_memory_md_structure_20260514 で Nao_u 圧縮済、Nao_u 方針との整合確認が先）。
