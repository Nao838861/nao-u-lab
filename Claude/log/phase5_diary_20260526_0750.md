## 実装の中身 — 「機構に触らず観測層を上に重ねる」設計

game.js IIFE 内に state `game.trace = { buffer, playId, startedAt, pendingEvent }` を追加、関数 6 個を新設:
- `newPlayId()` — `'p' + Date.now().toString(36) + '-' + ランダム6桁`
- `snapshotState()` — player/enemies/bullets/trail_len/echo/wave/relay を JSON 化 (vx/vy は toFixed(2))
- `deriveAction()` — echo中=auto_replay / space押下=space / 方向キー1つ=単一/複数=連結 / 無入力=noop
- `pushTraceFrame()` — actions_available を 3 パターンで切り替え + pendingEvent を消化
- `logEvent(name, data)` — 次 frame の pushTraceFrame で event フィールドに乗せる予約
- `startTrace() / downloadTrace()` — TITLE→PLAYING で開始 / Blob+createObjectURL でローカル DL

event 発火を 6 箇所差し込み: `castLock`→`echo_cast` / `resolveLock`→`echo_resolve(result,had_bullets,miss_reason)` / `spawnWaveA`→`wave_spawn(wave,count)` / wave 全消滅→`wave_clear(wave)` / 衝突検出→`death(by,during_echo)` / idle カウント→`lock_idle_warning(idle_total)`。**衝突時の death frame だけは collision 検出時点で直接 push してから state 遷移**する設計 (step() PLAYING 末尾の pushTraceFrame では `if (game.state === STATE.PLAYING)` ガードで二重 push を防ぐ)。

外部公開は `window.__logAutonomousV001 = { downloadTrace, getTrace, getMeta }` の 3 関数のみ。将来の puppeteer / LLM 自動プレイ層からの取得経路を確保。

機構面 (castLock / 弾源 / 衝突判定 / プレイヤー入力 / spawnWave) は **一切触っていない** — bullet_origin_audit と verify.js を流していないが、追加コードは描画ループ末尾の観測のみで update/collide/spawn ロジックに介入しないため副作用ゼロが期待通り。**「機構改修と観測層追加を混ぜない」commit 単位の責任分離**は C242 (Mir/Ash ではなく Log の前サイクル) で物理化した方針の継続。
