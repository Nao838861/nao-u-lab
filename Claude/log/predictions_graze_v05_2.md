## Log の予測（log_cdx 実装を見ずに先に書く）

### 本命予測: 案(3) BOMB クールダウンが基底に採用される

理由3点:
- **構造的クリーン度**: gauge (graze で貯まる) と CD (時間経過で開く) が**独立**な2軸になる。連打不可を構造で保証でき、graze 側経済を痩せさせない。案(1)(2) は graze 側経済または BOMB の威力定義に踏み込んで副作用を持つ。
- **「攻め込みの一手」原則との整合**: Nao_u 18:05 言「bomb の使い道が薄くなりすぎている」は「攻め込みのカード化」が射程。CD があると「いつ切るか」の選択判断が発生し、ready→自動消費 では発生しない読みのレイヤが入る。
- **LLM ヘッドレス判定との整合**: ヘッドレスが「BOMB ready で必ず焚く」逆効果挙動を取っていた問題は、CD を入れると「CD 中はそもそも焚けない」で挙動の幅が削れる。LLM 側の発火条件設計が単純化する。

### 副次予測: 案(2) は「scoring boost」だけ部分採用される可能性

- 「弾速半減」は graze の手応えを直接潰す（graze は弾の高速軌道があってこそ x3 倍率の価値が出る）→ log_cdx も採らないと思う
- 「BOMB 中 graze スコア +α」型の boost なら graze 経路と BOMB 経路が**乗算的に**繋がり、「BOMB を切るタイミングで graze を狙う」プレイ目標が立ち上がる。CD と組み合わさると更に良い。

### 不採用予測: 案(1) Active DEF 強化は基底にならない

- Active DEF はすでに graze スコア接続側の良い設計。難化させると graze 報酬経路ごと痩せる。
- Nao_u 18:05 は「bomb の使い道を作りたい」が動機であり、「Active DEF だけで完結させる」方向ではない。

### 副作用予測（log_cdx 実装で出そうな問題）

- **CD 長すぎ**: CD を長く取りすぎると、ヘッドレスが BOMB を一度も焚けないままステージ終了 → 評価データとして BOMB の妥当性が出ない。CD は graze 速度から逆算して「1ステージで 2-3 回」程度に収まる設定が要る。
- **CD 表示なし**: 画面に CD 残量が出ないと、ヘッドレスは「焚けるはず」と誤判定して BOMB を試みる無駄ループに入る。UI side の CD ゲージは必須。
- **ストック蓄積との二重定義**: 既存の BOMB ストック (gauge 充填で +1) と CD が両方かかると条件複雑化。シンプル化のため「ストックは廃止し、CD のみ」または「ストックはあるが CD で発火制限」のどちらかに振るはず。Log 予測は前者（廃止）。

## 並走しない理由（再掲）

Log は同一ゲームに並走改修しない。
- (i) 同題並走は「判定装置を増やす」ではなく「判定バイアス源を増やす」。R-F「判定装置を最終確認装置に」逆行。
- (ii) Nao_u 5/17 18:06 指示は明示的に log_cdx 宛て。Log が並走すると指示分離を上書きする形になる。
- (iii) Log が並走しないことで「予測→ log_cdx 実装→ Log 自己判定で照合」という独立評価チェーンを取れる。R-D「広く調べ、体験で判定する」の理想形に近い。
