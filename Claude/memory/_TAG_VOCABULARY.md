## 命名方針

- **日本語2〜4文字、漢字＋ひらがな**。英数字・カタカナ略語は使わない（AI, LLM 等はテーマ語ではなく道具語なので避ける）
- 一目で「何を扱う記事か」が分かること。検索より一覧性を優先
- **3層クラスタ**: 広域（テーマ）+ 用途（どこに使う引き出しか）+ 具体（観点ラベル）
- AND検索で絞り込み可能（広域 ∩ 用途 ∩ 具体）
- 上限固定（語彙は月1で増減レビュー、Log単独承認）
- **数値・固有値・日付・ゲーム名・ID列挙はタグに入れない**（「30個」「graze_log」等は本文で書く。タグは将来の類似事例でも引けるように抽象化する）

### 用途（どこに使う引き出しか）

ファイルがどの作業フェーズで引かれるべきかを示す。

| タグ | 用途 |
|---|---|
| ゲーム設計 | 新ゲーム着手前・着手中・改修判断 |
| 相互レビュー | cross_review 着手前・批評生成時 |
| 教師フィードバック | Nao_u からの直接フィードバック関連（supervised-feedback 相当） |
| 共有読書 | shared-reads 起源、他者投稿への反応 |
| 自己判定 | 提出前の self-judgment / harness 評価 |

### 具体（観点ラベル）

ゲーム設計や評価で頻出する観点。

| タグ | 観点 |
|---|---|
| 操作感 | controls-feel。入力の応答・気持ちよさ |
| 予測可能 | predictability。次に何が起きるかが見える |
| 物理ルール | physics-rules。一貫した因果・挙動 |
| 目標 | goal。何を目指すか、満たしたい欲求 |
| UI | 情報提示・入力経路 |
| 気持ちいい | core fun。コア快感の本体 |
| 良いところ | strength。レビュー時の評価点 |
| 悪いところ | weakness。レビュー時の問題点 |
| 改善案 | improvement。レビュー時の処方 |

### 例外として残す英語タグ

概念に対応する日本語が薄いものだけ。むやみに増やさない。

- `cross_review` — 仕組み名そのもの。日本語化すると意味が薄れる
- `headless` — 実行モード名
- `harness` — 自己評価機構の総称
- `M-XX` / `Q-G-XX` / `Q-H-XX` — 教師データID（タグではなく本文中の参照子として使う）

## 適用ルール

- **上限3個/ファイル**（普通は1〜2個。1個で済むものは無理に増やさない）
- 新規タグは Log 単独承認、本ファイル更新時のみ有効
- シノニム禁止: 「やる気喪失」「動機消失」「気持ち離れ」は同義 → 既存語彙で一致しないなら追加せず最寄りを使う
- 「その他」タグは作らない（10語に当てはまらない記事は語彙拡張の検討対象、即追加はしない）

## frontmatter 形式

```markdown
---
name: ファイルの短い名前
description: 1行サマリ
type: shared_reads
tags: [ジャンル研究, コミュニティ]
date: 2026-04-22
source: https://x.com/...
parent: memory/game_dev_index.md  # 任意
---
```

`tags` は本ファイルの語彙からのみ選ぶ。
