# 加減思考から組み合わせ思考へ — M-46 候補

## ルール

新しい機能を加える時、**「他の何を引くか」を考える前に、「既存要素 A と新要素 B が組み合わさって何が生まれるか」を1ステップ問う**。

具体的には brainstorm.md / README に「相乗効果」セクションを必須化:

| 既存要素 | 新要素 | 単純加算 | 相乗効果 |
|---|---|---|---|
| (例) ガイド線 | 敵キャラ | 情報過多になりそう | 民主化された予測精度の上で「移動目標を狙う」が現実的タスクになる |

「単純加算」だけ書いて「相乗効果」が空欄のまま機能を引く判断を下したら違反。

## Why

**Nao_u 2026-05-02 07:45 #human-steering**:

> ガイドがある達人プレイができることを前提に、敵やボスがいる状態で面白くするにはどうするか考えて。できれば君たちだけでこの結論に到達して欲しかった。
> 現状の君たちには良いアイデアを含む仕様の提案はできても、その中のどれが筋が良さそうかを選ぶセンスがない、と感じている。

直前の brick_log v08（2026-05-02 早朝）で、Ash は「敵キャラ + 動くボス」を入れる時に「情報過多になる」と判断してガイド線を除去した。

しかしガイドと敵/ボスは**互いに補完する組み合わせ**だった:

- ガイドだけ → 静止ブロックを誰でも狙える → 「上達」の余地が消える（Nao_u 05-01 04:10 指摘）
- 敵/ボスだけ → 移動目標は実行精度ゲームになり、上級者しか楽しめない
- ガイド + 敵/ボス → 民主化された予測精度の上で「移動目標を1ショットで撃ち抜く」「敵A→ブロック→敵B のコンボ経路を設計する」がスキルゲームとして成立。スヌーカー / ビリヤードのトリックショット型と同じ構造

これは **2026-05-01 04:51 #game-rights**:

> 「よいアイデアは複数の問題を解決する」し、複数のアイデアの相乗効果は豊かで奥の深いゲームを生む土壌になる

の直接違反。指摘の翌日に同じ違反を再発した = ルールを刻んでも体感に落ちていない。

## How to apply

1. **機能追加判断の前**: brainstorm.md / README の「相乗効果」セクションが空欄なら、まずそこを埋める。少なくとも 2x2 で組み合わせ表を作る
2. **「情報過多」「複雑になる」と感じた時**: そう感じた瞬間が罠の入口。**それは A と B が干渉しているだけかもしれないし、相乗するかもしれない**。「単純加算で困る」と「相乗効果で何が生まれるか」を別々に書き分ける
3. **過去事例で検証**: 「ガイド + 移動目標 + 1ショット解決」の系譜（ビリヤード / スヌーカー / Snooker Loopy / Strikers 1945 弾道予測 / Worms / Angry Birds 軌道予測）を引いてから判断
4. **「Aを足したらBを引く」癖の検出**: 機能追加コミットで一緒に何かを引いている場合、引いた理由が「組み合わせを試さずに不安で引いた」になっていないか self_judgment.md で1問記す
5. **触発側のチェック**: 単一要素の調整・削除・追加だけで brainstorm.md を埋めた時は、**「組み合わせ案が1件も出ていない」が黄信号**。M-38 brainstorm.md に「組み合わせ案を最低3件」セクション必須化を検討
