# 快感審問を重心審問の前に置け

## ルール

ゲーム実装/改修の判断ゲートに、**「快感審問」を「重心審問」より上位**に置く。

1. **快感審問**（最上位）
   - このゲームで一番嬉しい瞬間は何か
   - それを支えている操作・フィードバックは何か
   - この改修でその快感は消えるか／残るか／増えるか
2. **重心審問**（feedback_game_center_of_mass.md）
   - このゲームの重心は何か
   - この改修は圧力設計か禁止追加か
3. **解空間審問**（feedback_solution_space_rollback.md）
   - 改修案 / 巻き戻し案 / 別解 を並べる

ヘッドレス指標の改善は、快感審問でNoが出た改修の採用根拠にならない。

## Why（なぜこのルールが必要か）

**Nao_u 2026-04-25 #game-rights 09:35（avoid_log v04 凍結原因）**:

avoid_log v01 で2点を改変——(a) 攻撃発動を磁力場160px近接限定 (b) 攻撃が AI周囲180pxの鉄片を範囲全滅。これにより「弾で狙い撃つ」「ゲージで弾増えて当たりやすい」というシューティングの核快感が**丸ごと消えた**。

それに気づかずに v02（地雷）→ v03（dirBias圧力）→ v04（nearBias圧力）と二次問題への対処療法を積み重ねた。Nao_u指摘原文:

> 「このゲームはこれが快感」という要素を削るのは非常に危険。もともとあった「弾を撃って敵を壊すことで、快感を得ながら危険を排除する」「ゲージを貯めることで弾がたくさん飛ぶので、たくさんの快感とたくさんのリターンを得る」という要素が丸ごと消えた。

私（Log）の自覚:
- M-10（ヘッドレス✅人間❌）/M-11（対処療法の積み重ね）を game_lessons_log に**自分で書いていながら**、新作 avoid_log で同じ轍を踏んだ
- 「圧力設計 vs 禁止追加」の重心審問は v03/v04 devlog で言語化していたが、それより上位の「快感は残っているか」を飛ばしていた
- 知識の存在 ≠ 行動の変化（feedback_index.md #5/#26）。重心審問だけでは快感の消失を捕捉できない

## How to apply（いつ・どこで発火）

### 新ゲーム v01 着手時

`game/<game_id>/v01/devlog.md` の**冒頭**に必ずこのブロックを書く（index.html を1行も書く前）:

```markdown
## 快感審問（v01）
- 一番嬉しい瞬間: ___
- それを支える操作/フィードバック: ___
- この瞬間が出るまでに必要な手数（30秒以内が目標）: ___
```

このブロックが書けない時点で、設計が固まっていない。実装着手しない。

### 改修着手時（v02以降）

改修案を出すたび、devlog に1行追加:

```markdown
- 改修案: ___
- 消える快感: なし / ___（具体的に）
- 残る快感: ___
```

「消える快感: なし」と書けない場合、改修案を見直す。書けても、消える快感が核なら不採用。

### cross_review

他インスタンスの新作レビュー時、最初に問うのは「快感は何か」。重心や圧力設計の議論はその後。

### ヘッドレス比較

ヘッドレス指標が改善しても、快感審問でNoが出た改修は採用しない。指標は手段、快感は目的。

## 検証

- 次の新ゲーム着手時に devlog 冒頭の快感審問ブロックが存在するか
- 改修ごとの「消える快感」記録が devlog にあるか
- Nao_u フィードバックで「快感が消えた」指摘が再発しないか（再発したらこのルールが機能していない）
