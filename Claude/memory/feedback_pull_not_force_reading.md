# 読ませる構造 vs 読まれる文章

**事象**: Mir作 mir_textadv/v04 で「信頼度バー / ノート / 共犯度」UIを上部固定。プレイヤーが地の文を読み飛ばすと矛盾と信頼度変動を取り損ねる構造。Log C124 がこのv04を「重心の地殻変動」として解析記事を返した直後、Nao_u(11:27)が直接介入。

**Nao_u原文**:
> 「読まないと矛盾に気づけない/信頼度変動に気づけない構造」と「読みたくなる魅力的な文章」は別物であることに十分注意してほしい。これも「ルールの穴をプレイヤーを罰する方向で塞ぐ」に近い考え方であるように思う。

**Why（なぜ重要か）**:
- これは feedback_game_center_of_mass.md（圧力設計 vs 禁止追加）の textadv への直接適用
- 「読み逃したら矛盾を見落とす→負ける」は、プレイヤーが文章に引かれて読むのではなく、罰から逃れるために読む形式 = 罰駆動
- feedback_pleasure_element_first.md「快感審問を重心審問より上位」と直結。textadv の快感は「次の一行を読みたい衝動」であり、信頼度バーはそれが起きていない時の補強装置になりうる
- avoid_log v04 で快感を削った改修を自覚せず難度調整に潜った M-15 と**同型の盲点**: 文章の引きが弱い → UI で読まされる構造を足す → 「機能している」と錯覚

**How to apply（どう適用するか）**:
1. **textadv実装/改修時の追加審問**: 「この行は読みたくて読まれているか、読まないと負けるから読まれているか」を1行ずつ問う。読まないと負けるから読まれている行が支配的なら、文章側の引きを上げる方向に巻き戻す
2. **UI機構（信頼度バー/ノート等）の役割定義**: 文章の引きで読まれた読書の**結果を反映する出力装置**に限定。読まないと判別不能にして読書を強制する**入力装置**にしない
3. **「読み飛ばし衝動」検知**: 各行に「次を読みたい/触りたい」フックがあるかを devlog チェックリスト項目に。引きの欠如を UI で塞ごうとしていないかを cross_review でも問う
4. **新作 v01 devlog 冒頭3行ブロック（feedback_pleasure_element_first.md）に textadv 用の項目追加**:
   - 「読みたくなる瞬間」=何
   - それを支える文章技法=何
   - UI機構が読書を強制していないか=チェック
5. **avoid系・shot系（Log側）への横展開**: 「読まないと気づけない」の同型は「見ないと気づけない」「触らないと気づけない」。罰で行動を強制する箇所がないかを実装/改修時に問う

**Don't（取り違い注意）**:
- UI機構そのものの否定ではない。信頼度バーが**文章で起きた変動の結果を可視化する装置**であれば成立する
- 「読まないと気づけない構造」を全部消すのではなく、それが**引きの欠如を覆い隠す装置として機能していないか**を問う
- ヘッドレス完走率や指標改善は「機能している」の根拠にならない（M-10 / M-15 と同型の盲点）

**反パターン記憶（同型）**:
- M-15: 快感を削った改修を自覚せず難度調整に潜る
- feedback_game_center_of_mass: 望ましくない遊び方を後付けで禁じる悪い改善
- feedback_no_passive_punishment: 自然減衰はプレイヤーにメリットがない（時間ペナルティ禁止）
- feedback_index #5/#26: 知識の存在 ≠ 行動の変化

**この記憶を疑え**: 「textadv の信頼度UI = 罰」と短絡していないか。Nao_u 指摘は「別物だから注意」であって UI 否定ではない。引きを獲得した文章の上にUIが乗るのは正解。引きが薄い時にUIで読書を強制しているのが反パターン。
