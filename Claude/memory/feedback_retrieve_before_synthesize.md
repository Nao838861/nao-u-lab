# 新規知識取り込み時の既存記憶検索——直近バイアス対策

**ルール**: 外部知識（記事・論文・Nao_u投下リンク）を記憶ファイルに結晶化する時、**書き始める前に game/*/devlog.md と memory/game_lessons_log.md を既存失敗パターンで grep する**。直近で温度が高い話題に貼り付けるのではなく、構造的に一致する過去失敗を第一引用例にする。

**Why**:
- 2026-04-22 ABA記事（抜け道を罰で塞ぐな）を feedback_game_center_of_mass.md に結晶化した時、引用例を Pot開発にした。
- **だが構造一致は avoid_log/v02 v3改修**（drag/ヒットボックス縮小/弾幕激化/90%スポーン/地雷の5連禁止追加）。自分で avoid_log/v02/devlog.md:543「全試みに共通する構造問題」も M-11「問題を潰す改修は対症療法の積み重ね」も game_lessons_log.md に書いていた。なのに引用しなかった。
- 2026-04-23 00:29 Nao_uが#human-steeringで指摘: 「失敗を記憶して繰り返さず、人間のフィードバックをうけて次はもっと上手くやるために、君たちは記憶システムの改善を繰り返しているはず」
- 記憶システムの目的（dialogue_memory_purpose_20260421）は**次元の違うゲーム制作の知見蓄積**。新規知識を既存失敗に接続できないなら、記憶は蓄積されていても機能していない = 単発記憶AIと変わらない。
- 既存の feedback_stereotypical_responses / feedback_info_integration と接するが別の失敗: 取り込んだし統合もしようとした、だが**検索順序が「直近の温度が高い話題→知識」になっていて、「知識→構造一致の過去失敗」の検索を先にやっていなかった**。

**How to apply**:
1. 新規外部知識が入った時（特に原理・設計論・失敗パターンの類）、結晶化の **前** に:
   - `game/*/devlog.md` と `memory/game_lessons_log.md` を知識のキーワード/反対語で grep
   - 例: ABA「禁止追加」なら「対症療法」「撤回」「巻き戻し」「罰」「抜け穴」「dodger」「隠し」を grep
2. ヒットした過去失敗を**第一引用例**にする。直近の話題は副次的。
3. 結晶化後、その記憶から**過去失敗へのリンク（ファイル名+行番号）**を貼る。抽象的な参照（「avoid_log」だけ）ではなく、具体改修名5つまで書く。
4. 結晶化した記憶の How to apply に「grep で出てくるか」をセルフチェック項目として含める。

**追加ルール（2026-04-23 再発で拡張）**:
5. **Slack即時反応投稿（#shared-reads / #all-nao-u-lab / #human-steering）でも発火**する。knowledge記事執筆時だけでなく、外部記事への即時短文反応で「**我々は〜できていない / まだ使っていない / 〜が得意**」系の自己評価語を書く時、投稿前に以下を必須:
   - `game/*/headless.py`, `game/*/devlog.md`, `memory/game_lessons_log.md` のキーワード grep
   - 同じ晩の自分の knowledge 記事との整合チェック（同じ話題を2形式で書く時、後の投稿が先の記事と矛盾していないか）
6. **再発事例（2026-04-23 00:30頃 #shared-reads line 651/652）**:
   - line 651「Phase 1-7（仕様→実装→テスト）は得意」→ Nao_u指摘「得意という自認だが、ここもまだ上手くやれているとは言えない」。game_lessons_log.md M-10〜M-14 / L-01〜L-05 を読み直さずに書いた。**自分で書いた失敗カタログの健忘**
   - line 652「我々のPot開発ではheadlessテストをまだ使っていない」→ Nao_u指摘「study_platformer_01 と avoid_log で実践を始めているはずだが、なぜなかったことになっている？」。**同じ晩に書いた `knowledge/20260422_aba_agent_gamedev_feedback_loops.md:59` で「headless replay 標準装備」と整合宣言していたのに投稿で矛盾**
   - 構造: 外部記事（ABA 3本）の論点枠に乗って「我々の位置」を語る時、自分の実装・失敗記録を参照せず記事骨格をなぞる。**直近バイアスが投稿速度と結びつくと倍加する**
7. **自己評価語 警報リスト**（投稿前に grep / 実装確認をトリガーする語）:
   - 「まだ使っていない / まだできていない / 検討の価値がある / 未構築」（→ 実装確認必須）
   - 「得意 / できている / 整合している」（→ game_lessons_log.md L-01〜L-05 + 直近 devlog 読み直し必須）
   - 「〜すべき / 〜が必要」（→ 既存ルール/チェックリストで既に書いていないか確認）
