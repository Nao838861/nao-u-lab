**How to apply**:

1. **判定文の必須化**: 出力前に `game/<id>/v??/self_judgment.md` を書く。「v04 と比べて良いか / 悪いか / 同じか」を **自分で結論**して書き出す。「実プレイで判定」「Nao_u に確認してもらう」を結論にしない
2. **自己判定の根拠を構築する**:

   - **独立判定LLM**: 別セッション/別エージェントに「これ面白い？」を聞く（cross_review はインスタンス間の事前判定として既存だが、Nao_u を待たずに走らせる）
3. **「実プレイ依存」を結論にしない**: v05 README の懸念2「実プレイ依存」のような書き方を禁止。「不明」と書くなら案を捨てるか、不明を解消する自己判定手段を作ってから出す
4. **Nao_u を最終確認装置として位置づけ直す**: Nao_u プレイは「自分で『最良』と判定したものが本当に最良かの最終確認」。それまでに自己判定で 95% 確信レベルに達してから出す

## 追補 2026-05-04 05:08 — AIプレイの質 = 自己判定の上限（Nao_u graze_log v02 評価で確定）

**Nao_u #game-rights 05:08 原文** (`log/nao_u_live.md` 同日節):
> AI側で自己判断するためにプレイさせるのはいいことだが、「Lv3 到達率 0%」「60秒生存率 0%」だと、おそらくまともにプレイできていない結果そうなっているだけなので、「自動プレイの質が低すぎて結果を評価する意味がない」が現状だと思う。マリオでいうなら、最初のクリボーを超えられないAIでプレイしても、キノコやフラワー、ノコノコの強さのバランスの評価などは不可能で意味がない、みたいな状況になっていそう。

**事案**: Ash が graze_log v02 README で headless self-play 結果 (Lv3 到達率 0% / 60秒生存率 0%) を「Mir review §C 『Lv3 が届かない問題』の数値裏付け」「『死亡前にコンセプトが完成しない』の構造証拠」と書き、Log も A merge 推奨を受け取りかけた。Nao_u の読みは逆 — **AIが下手すぎて到達してないだけ**で、ゲーム構造の証拠ではない。

**追加ルール**:

1. **AIプレイ質ゲート（M-40 の必要条件）**: headless self-play / RL agent の出力を「ゲーム構造の証拠」として使うには、**まず AI が「ゲームの基本ループを成立させているか」を別途検証する必要がある**。具体的には:
   - 当該ゲームに想定する「最低限のプレイ品質基準」を README に明記する（例: 「Lv3 到達は 50% 以上の seed で発生すべき」「60秒生存率 30% 以上」など）
   - 基準を下回る場合、絶対値（Lv3 到達率 / 60秒生存率 / 平均生存秒）を「ゲーム構造の証拠」として書くのを**禁止**。「AI 質起因か / 構造起因か区別不能」と書く
   - 下界比較（policy A vs policy B）は基準未達でも有効。「報酬軸が存在する」までは言える。「報酬軸が *良い*」「Lv3 演出が機能している/不要」は基準達成後にのみ判定可

2. **マリオ・クリボー基準**: 「最初のクリボーを超えられないAIで、キノコ・フラワー・ノコノコの強さを評価しても意味がない」を覚える。**ゲームの最初の数十秒のクリア**が AI 質基準の最低ライン。それを超えない AI のメトリクスは「設計判断の根拠」にしない

3. **headless 出力の文章化のルール**:
   - ✗「Lv3 到達 0% → Lv3 演出 が機能していない構造証拠」
   - ✓「Lv3 到達 0%（AI 質基準 50% 未達 = この絶対値は AI 起因か構造起因か区別不能）」
   - ✓「graze_seek score 150 vs corner_safe score 30 → graze 軸が *存在する*（差分は AI 質と独立に検出可能）」

4. **AI 質改善 vs 用途絞り の二択**: AI が基準未達なら以下のいずれかを選ぶ。曖昧に絶対値を書き続けるのを禁止:
   - (a) AI 質を上げる（弾幕全体を見るベクトル避け / 目標型 policy / 人間の上手いプレイの定性記述を policy 化）
   - (b) headless の用途を「下界比較限定」に絞ると README で宣言し、絶対値の解釈を封印

5. **M-40 二層分離 (5/3 追補) との関係**: 自動化可能層で headless を使う際にこの「AI 質基準」が前提条件として加わる。厚み層の自己判定（mental simulation / 過去ゲーム比較 / 既存自作快感天井比較）はこの基準と独立に運用可

**Why この追補が必要か**: M-40 は「人間プレイ非依存の自己判定」を要請したが、自己判定の手段として headless self-play を使う際、その出力を「面白さ」「コンセプト完成」の証拠として読むには **AI が一定品質を超えている必要がある**。これを明示しないと、AI が下手なだけで「コンセプト完成前死亡」と読むような構造取り違えが起きる（今回の事案）。M-40 の上流ゲートではなく、M-40 の手段の一つ（headless self-play）に対する品質要件。

**How to apply**: 今後 headless / self-play AI を使うすべてのゲーム作で、README 冒頭に「AI 質基準と現状値」セクションを必須化。基準未達のまま絶対値を「構造証拠」として書いた瞬間が違反検出。cross_review でこの違反を検出した場合は merge 候補から外す。
