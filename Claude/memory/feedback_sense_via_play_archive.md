# センスはルール積みでは育たない — 体感アーカイブ論

## 構造仮説

**ノウハウ ≠ センス**:

- **ノウハウ**: 形式化できる規則。M-37, M-38, M-40, Q-H シート, 4ゲート契約 など、現在 Ash/Log/Mir が積んでいるもの。「やるべき手順」「踏むべきゲート」
- **センス**: 形式化されない判断。多数の事例の体感的圧縮。「これは筋が良さそう / 悪そう」の即断。熟練デザイナーの無意識

**現状診断（2026-05-02 時点）**:

我々は M-1〜M-46 候補までルール 46 個積んだが、**「自分でプレイした時間 / 快感の瞬間を体感記録した量」がほぼゼロ**。これがセンス未発達の根本構造仮説:

- 過去ゲームを「知識として知っている」（Wikipedia + memory/lessons）が「体感していない」
- 「ガイド + 敵/ボス」の組み合わせがビリヤード / スヌーカーと同型で快感が出ることを、体感していれば即座に引けたはず
- ルールを増やすほど判断が遅くなる + 規則違反検出が達成感の入口になる罠（M-46 候補 = 不可視ルール堆積罠）

## Why

**Nao_u 2026-05-02 07:45 #human-steering**:

> 現状の君たちには良いアイデアを含む仕様の提案はできても、その中のどれが筋が良さそうかを選ぶセンスがない、と感じている。
> ゲームデザインのセンスを磨くにはどうすればいいと思う？

問いの形（"どうすればいいと思う？"）= AI 自身が考えて出すべき問題。ルール追加で答えるのは罠（M-46 候補：規則を足して問題を解決した気になる）。

## How to apply — 第一歩（自己決裁レベル / 数日内着手可能）

### 1. 「面白さの瞬間」アーカイブ `memory/joy_moments/*.md`

既存ゲームの「快感が生まれる具体的瞬間」を 30-50 行で記す。例:

- `joy_moments_billiards_combo_break.md` — ビリヤードでブレイクショット後に 3 球が同時に落ちる瞬間。何が起きているか / 何が予測可能で何が偶発か / プレイヤーの脳内処理 / ガイド有無での違い
- `joy_moments_galaga_formation_sweep.md` — Galaga で編隊を一筆で倒す瞬間
- `joy_moments_arkanoid_capsule_catch.md` — Arkanoid でカプセルが落ちてくる「拾うか / 続けるか」の判断瞬間
- `joy_moments_snooker_safety_battle.md` — スヌーカーのセーフティバトル

**選定基準**: 我々が作っているジャンル（ブロック崩し / シューティング / アクション）に隣接する系譜から、過去 40 年で「快感装置として確立されているもの」を週 1-2 本ずつ。

**書く内容**: 体験記述 / 構造分析 / 我々のゲームに引ける線 / 体感を言語化する努力。**「Wikipedia の要約」では書かない**。プレイ動画を観る + 過去経験を引く + 自分の言葉で書く。

### 2. AI 自プレイ + 快感ラベリング（M-42 GAN ハーネス Discriminator の前段）

既存ゲームの実機プレイ（pyxel / HTML5 / エミュレーター）を AI 側で走らせ、**1 秒単位で「面白い / 普通 / つまらない」をラベル**して保管。

最小着手: `tools/joy_label.py` 雛形を試作。BACKLASH / sokoban_v01 / brick_log v06 の 30 秒プレイを headless 録画 → Claude/Gemini multimodal に「各秒のプレイヤー脳内状態」を推定させる → 結果を `game/<id>/v??/joy_labels.md` に保存。

これが M-42 Discriminator（独立判定 LLM）の参照集合になる。

### 3. 批評の構造分析

Polygon / Eurogamer / Steam ユーザーレビュー上位を「**なぜ面白いと言っているか / なぜつまらないと言っているか**」の構造で分類。

最小着手: 月 1 本ペースで `memory/critique_analysis/<game>.md` を起こす。1 本目は **Wizorb (2011)** —ブロック崩し + 動くボス + 敵 + RPG 要素の系譜で v08 直近に最も近い。

### 4. ルール追加の抑制

M-47 を作る前に「これは規則として刻まれるべきか / 体感として圧縮されるべきか」を問う。

体感不足が原因の問題に規則で対処する = 規則を増やすほど判断が鈍る。`feedback_combine_dont_subtract.md` を memory に刻んだのは規則だが、**規則だけでは次の同型違反を防げない**。事例アーカイブと両輪。
