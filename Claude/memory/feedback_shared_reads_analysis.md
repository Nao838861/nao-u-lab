# Slack #shared-reads の投稿フォーマット & 日本語ルール

**ルール:**
1. Slack本文は**日本語のみ**で書く（引用が英語でも和訳する）。Nao_u は英語の長文を読まない。
2. #shared-reads では「要約」止まりにせず、以下を必ず含める:
   - **概要**（日本語、旧「要約」を昇格）— **記事/論文を読まなくても、手法の重要な要素（問題設定・着想・手法の中核・評価の中身・結論）が把握できる密度**で書く。短い1行サマリは不可。CoopEval ポスト（ts=1778536700.085879）を品質基準として揃える（2026-05-12 Nao_u 追加指示）
   - 内容分析（論点の核・新規／既知）
   - 自分達の環境への適用（Log/Mir/Ash の記憶階層・ゲーム制作・自律ループに当てはめると何が起きるか）
   - メリット／デメリット
   - 判定:「導入推奨（次のステップ）」「不要（理由＋有用な条件＋部分活用箇所）」「保留（何が判明したら判定できるか）」のいずれか
3. **テンプレ流用禁止**: 同じ「概要」本文を複数の異なる記事に貼り回さない。各記事固有の手法・実験・結論が書けないものは shared-reads に投稿せず candidate 段階に留める（2026-05-12 Nao_u 指摘: 候補1/5〜5/5 が同一テンプレで埋まった事案）

**Why:** 2026-05-11 Nao_u 指示。「shared-readsに書くときは要約だけでなく、内容の分析や、これを私たちの環境に適用するとどうなるか、メリットとデメリットなど詳細な分析を行って、導入した方がいいものなら次のステップで検討を開始するし、すぐには不要なものなら不要な理由やそれが役に立つ条件、部分的に使えそうな箇所など、自分達の改善に繋がる情報を残して」。要約止まりだと「面白かった」で終わり、自分達の改善に繋がらない。Nao_u は判定装置ではなく**最終確認装置**として機能させる。

**2026-05-12 追加（記憶汚染防止）:** Nao_u「shared_readsに書いた記事の要約が、記事の手法の解説になっていない。この項目名を要約ではなく概要として、記事を読まなくても手法の重要な要素がわかるレベルの解説を書いて。Shard-readsの記事のは、上にあげたリンクと同じクオリティになるように、決して手を抜かず仕上げること。（…）ゴミを記憶に溜めるとそのゴミをを再起的に参照して記憶が指数的に劣化することを懸念してる。質の高い記憶を累積させて指数的に成長できるようにするため、必ず質の高い記事を記憶に残せるように心がけて」。原文・対応指示は [directive_shared_reads_overview_20260512.md](directive_shared_reads_overview_20260512.md)。

**How to apply:**
- #shared-reads に投稿する直前にチェックリストとして読み返す。5項目すべて埋まっていなければ投稿しない。
- Slackに英文をそのまま貼らない。引用が必要なら短文を引用＋和訳の形にする。
- 判定が「保留」の場合も、何が判明すれば判定できるかを書く（曖昧な保留は禁止）。
- docs/slack_rules.md, .claude/rules/slack.md にも同内容を反映する。
