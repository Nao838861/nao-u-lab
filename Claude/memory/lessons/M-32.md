### M-32: HUD は挙動の鏡である（ash_onebutton v04 ↔ graze_log v01 / 2026-04-28 C141 Phase 3 Ash 刻印）

**事象**: ash_onebutton v04 で Nao_u が「プレイヤーの下に何か出ているが、数回プレイしてもそれが何なのかはまったくわからなかった」（22:04）と言ったのは画面下のグラフ HUD への指摘。同日 Log が公開した graze_log v01 の画面下ゲージバーは構造的に同じ位置・同じサイズを占めているが、こちらは初見プレイヤーにも意味が伝わる。違いを取り出すと **HUD と挙動の接続関係** に行き着く。

**根本原因**:
- ash_onebutton v04 のグラフ: プレイヤー下に「紙一重で光る」採点曲線を描画していたが、画面内の挙動（敵の動き / 自機の被弾 / スコア表示）と接続が弱い → 数値が動いても何が変わるのかプレイヤー側にフィードバックされない → 「意味不明」と判定された
- graze_log v01 のゲージ: Lv1/Lv2/Lv3 の段差を区切りで見せ、Lv が上がると **射撃 way 数が即座に増える**。ゲージの上昇 = 自機弾の本数増加 = 画面挙動の変化として直接プレイヤーに返る → 数秒以内に「これはレベル制ゲージだな」と読める
- HUD は単独で意味を持たず、**画面の挙動に対して「何が変化するか」のキー**としてのみ機能する。挙動と切れた HUD は計測器（dev tools）であり、プレイヤー向け表示ではない

**[M-25](M-25.md)（UIで示せばわかるはず）との関係**:
- M-25 は「説明テキストや UI ラベルを足しても、認知枠組みがなければ伝わらない」という認知側の指摘
- M-32 は「HUD の数値が動いても、画面挙動の変化と接続していなければ伝わらない」という挙動側の指摘
- 重なる部分: 両方とも「プレイヤーの中の解釈装置に届くか」を問う。M-25 は外部知識フレーム経由、M-32 は内部因果フレーム経由

**次回の規則 — 新ゲーム着手前 Q-E（HUD 接続審問、必須シート）**:
- **Q-E-1**: 表示する HUD 要素ごとに「これが上下する時、画面のどの挙動が同時に変化するか」を1行明文化
- **Q-E-2**: 接続が弱い HUD は **完成版から外す or 開発者トグル化**（dev-only）。ash_onebutton v04 のグラフが該当
- **Q-E-3**: 「数値だけ見える HUD」を残す場合、それが計測器（dev）であってプレイヤー向け表示ではないと明示する。混在は混乱の元

**処方箋として graze_log の構造を分解**:
- ゲージ上昇 → Lv 上昇 → way 数増加（射撃挙動の変化）→ 弾幕密度の変化（画面挙動の変化）= 4段の連鎖が即時に可視
- ash_onebutton v04 のグラフは「採点」自体が独立計算で、画面挙動との連鎖が無かった → 連鎖0段の HUD = 計測器
