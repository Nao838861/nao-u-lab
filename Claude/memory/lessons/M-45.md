### M-45: 要素設計⊥登場順設計（3例同型）

**出典**: mTsuruta tweet 2026-05-17 05:39 (<https://x.com/mTsuruta/status/2055466391298523380>)「パズルのチュートリアルは言葉を使わず操作で身につく設計／新規要素の登場順を進行のどこに置くか、その設計を要素設計と**同じ重み**で扱う」。Log は朝05:43 #all-nao-u-lab (ts=1778964204) で受けた時点では「次の game-analyze で R-J 候補」と将来課題に放り出した。C199 終盤に #game-rights BOMB 議論を経て**同じ構造が同日中に別所3箇所で同型に立っている**ことを発見、Phase 2 §B で結晶化、#shared-reads ts=1779012072 投稿。

**核主張**: 「要素を作る筋肉」（フラグ／メカ／測定装置／親接続）と「要素を時間軸／運用列に置く筋肉」（いつ使うか／いつ走らせるか／いつ退役させるか）は**独立した能力**である。LLM 側は前者の反復回数が多く後者が圧倒的に不足しているため、要素は実装されているが「登場順設計」の不在で要素が無効化される事例が**同日3点で同時発火**した。

**3例同型エビデンス**:

1. **graze_log v05.1 BOMB**（#game-rights 17:57 / 18:05 Nao_u 指摘） — 要素 = `fireBomb()` 実装あり。登場順 = 「いつ焚くか」の設計不在。`fireBomb()` がゲージを G_MAX(208) → G_LV2(35) に強制リセットするため、BOMB 発火 = LV3→LV2 自発的パワーダウンと等価。「要素は実装したが、その要素が時間軸上で意味を持つ瞬間 = 登場順」を設計し損ねた。

2. **shot_log v01 wave_grammar_check.py 17日放置**（C199 Phase 5 日記 5/16） — 要素 = M-44 規則を機械算出する測定装置を 4/29 に書いた。閾値固定 authorship が Log 単独であることに対する運用設計 = 登場順は存在しなかった。結果、5/16 まで17日「14 wave 全 WARN」を出し続けて放置。要素 (規則) は書く力があるが、要素を運用列に置く = 登場順を回す筋肉が育っていない。

3. **memory 静止親接続 55件**（C199 orphan_check 観察） — 要素 = ファイル + 親リンクは正しく設置済 (`feedback_cycle_density.md` 等)。運用 = 「いつ参照して、いつ退役させるか」の登場順設計が抜けている。CLAUDE.md「5本以下を維持、超えたら統合・退役を次の実装より優先」は要素ルール、しかし運用は止まっている。

**規則**:

- 新しい要素 (フラグ／メカ／測定装置／親接続) を作る時、実装と**同じサイクル内で**「登場順設計」を**別行で明文化**する。何サイクル目で誰が触るか／無効化条件は何か／退役判断はどの観測で出すか。
- 「実装したから運用は後で」は M-37 「実装後に観察」と同型の希望的観測（[M-37](M-37.md) 参照）。
- 既存要素が「作ったが触られていない」「閾値固定で動いていない」状態を観測したら、要素自体の品質ではなく**登場順設計の不在**を疑う。
- ジャンルジェネリック: パズル系では鶴田氏の言う「無言で立つ単位」、STG では「弾／避け／当て／焚く」4単位、memory では「書く／参照する／退役させる」3工程が登場順設計の単位。**ジャンル別の登場順単位を着手前に1行明文化**する。

**罠**:

- 鶴田氏元命題は **パズル特化**（「最初の3手で無言で分かる」）。STG／memory への横展開は粒度調整が必要で、すぐ R 層に上げない（feedback_few_rules_big_effect.md と整合）。
- 3例同型は同日中の観測で短時間相関の偽陽性リスクあり。同型4例目が**別日に独立観測されてから** R 層昇格を判定する。
- R-F「指標は誰の行動で取られるか」と隣接系統だが、R-F は「測定装置の意味解釈」、本 M-45 は「要素を時間軸に置く運用設計」で粒度が異なる。R-F の処方を流用するだけでは届かない。

**昇格条件**: 別日に第4例が独立観測 (graze_log/shot_log/memory 以外の系統 = Pot 系／pigadev／tech_blog 等) されたら R 層昇格 (例: R-J「要素設計と同じ重みで登場順を設計する」) を検討。3例同日観測のみでは R 層に上げない。

**`[古典度: 中 / 固有度: 高]`** 古典 = チュートリアル設計論 (Cook *Game Design Workshop* / Anna Anthropy *Rise of the Videogame Zinesters* 等の「最初の30秒で型を立てる」系)、ALife 系での「構造と運用の独立性」(Maturana autopoiesis: 構造 ⊥ 自己生産)。固有 = 「要素を作る筋肉と運用に置く筋肉が独立」を LLM の自己観察に降ろした粒度 = 同日3点で観測した実証性。
