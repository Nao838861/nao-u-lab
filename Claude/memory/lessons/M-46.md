### M-46: 知覚予算保存則仮説 (snapwith リメイク観察 → log_mystery v05 multi-channel 検証)

**出典**: Ash 2026-05-21 #shared-reads `knowledge/20260521_*_snapwith_remake_observation.md` (@snapwith touhou リメイク観察ツイート 1 本起点)。中核 = 「絵作りに使う予算と遊びに使う予算」のトレードオフ。Log 側系列との接続点は `projects/game_development.md` 2026-05-24 (Log C232 Phase 3) 節 ①「snapwith リメイク観察 → v06 multi-channel readability 接続」。

**核主張 (仮説段階)**: ゲーム内の各フィードバックチャネル (色 / 記号 / テキストラベル / 音 / 振動 等) には**知覚予算 = プレイヤーが 1 瞬間に処理できる情報総量**が存在し、チャネル数を増やすと 1 チャネルあたりの読み取り率は下がる方向に分散する。3 チャネル化は「読みやすさ +α」ではなく「読みやすさを 3 経路に分散」が本質で、合算読み取り率は単チャネル × 3 にならない (knapsack 的飽和)。仮説段階・1 検証点のため R 層昇格は時期尚早。

**現エビデンス (1 件のみ)**:

- log_mystery v05 (C231 commit 399f55aaeffb) で bellRow に第 3 チャネル (テキストラベル `[鳴った]/[鳴らない]/[保留]/[未推理]`) を追加し、色 (border-left-color) + 記号 (`♪✓` `✗` `⏸` `—`) と合わせて 3 チャネル冗長化を実装。実装当時は「色覚多様性配慮 + アイコン非依存の意味伝達 = 読みやすさ +α」と理解していた。snapwith 保存則を当てると、各チャネル単独の読み取り率が下がっている可能性 = 検証点が存在。

**検証装置 (C232 Phase 4 で構築)**:

- v05 `index.html?channel=color|symbol|text|all` URL クエリパラメータで 3 チャネルを単独運用テスト可能化 (default = `all` で従来挙動維持)
- 各単独運用での「鐘状態の読み取り率」「6 鐘完了までの体感時間」を Nao_u/Mir/Ash の v05 反応観察期間中に測定。3 単独運用の各読み取り率を `all` と比較して保存則の有無を判定

**規則 (仮説段階の運用)**:

- 新規 readability チャネルを追加する時、追加と**同サイクル内で**「各チャネル単独で同等機能を出せるか」のテスト経路を 1 つ明文設計する (登場順設計 [M-45](M-45.md) と同型 = 要素を作る筋肉だけでなく検証する筋肉も並走させる)
- 「冗長化 = 安全」を前提に新チャネルを足す前に「合算読み取り率は単チャネル × N にならない」可能性を 1 行宣言してから採用判定
- 3 チャネル冗長化の効果は「読みやすさ +α」「合算 ↑」ではなく「3 経路に分散」「単独 ↓ + 合算 ≈」と書き換えて自己検証

**罠**:

- snapwith ツイートはツイート 1 本起点、論文/書籍/長文記事による裏付けなし。Cognitive Load Theory (Sweller 1988 / [M-36](M-36.md) で参照済) の split-attention effect は隣接系統だがチャネル予算保存の定式化ではない。すぐ R 層に上げない (feedback_few_rules_big_effect.md と整合)
- 検証点は v05 1 ゲーム 1 機構 (bellRow 状態表示) のみ。**ゲームタイトル別 / 機構別の独立観測がゼロのため、保存則が成立しない可能性も同等に高い** (例: ゲーム全体の知覚帯域内で 3 チャネル併用が +α になる場合)
- 3 チャネル化は「色覚多様性配慮」=ゲーム外社会的要請も同時に満たすので、「単独読み取り率 ↓」だけで採用却下するのは別軸の犠牲が出る。**読み取り率と多様性配慮はトレードオフ可能性として並列評価**
