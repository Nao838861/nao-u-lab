# シューティング評価マトリクス v0

## 用途

新ゲームの brainstorm、改修案の事前判定、cross_review 前の自己診断、Nao_u 評価受領後の整理に使う **評価ツール**。
- 設計**ルール**ではない（ルールは `game_lessons_log.md` の R-A〜R-I）
- ある実装が「何の軸では揃っており、何の軸では欠けているか」を 20+α セル単位で言語化する装置
- 「面白いかどうか」の総合判定はしない（評価軸が揃っても面白くない場合があるため、別途プレイ自己判定が要る）

## 5軸 (アフォーダンスの分解)

プレイヤーが「次に何をすべきか」を読み取る経路。説明書・チュートリアル・テキストを使わずに何が伝わるか。

| 軸 | 観察項目 |
|----|---------|
| **視覚** | 画面静止1枚で次の行動が読めるか。色・形・配置・差分が「ここに来い／ここから来る／これを避ける」を語っているか |
| **聴覚** | 効果音／BGM単独で状態変化（ゲージ／wave／危機／報酬）が伝わるか。視覚オフでも遊べる残量 |
| **応答** | 入力から画面到達まで1-3フレーム以内で手応えが返るか。入力した感／効いた感が「結果の出力」とは別に成立しているか |
| **構成** | 物理配置（敵配置／障害／空間）だけで次の難度や種類が予告されるか。事前にどこを見て準備するかが読めるか |
| **時間** | 残時間／wave進行／残りステージが単独で「終わりが近い／節目」を伝えるか。盛り上がりの位置を時間軸が示すか |

## 4段階階段 (宮本茂 1ネタ4回ループ)

同じ1つの要素を4段階に展開して定着させる構造。各段階を踏まずに飛ばすと「説明書依存」「いきなり極めろ」になる。

| 段階 | プレイヤー状態 | 設計責任 |
|------|--------------|---------|
| **段階1: 覚える** | この要素が存在することを認識する場所 | 失敗してもリセットされない／低致命度／必ず通る経路に1個だけ置く |
| **段階2: 遊ぶ** | その要素で実際にゲームの楽しさを成立させる場所 | 段階1で学んだことが報酬として返る／繰り返し触れる |
| **段階3: 応用** | 段階2の組み合わせ／変形／逆利用が要求される場所 | 「分かっている前提」で組み合わせを要求／驚きの余地 |
| **段階4: 極める** | 高速化／密度化／隠し条件／極北パターン | 任意挑戦（落とせる）／タイムアタック・スコア狙い層への入口 |

## 20セルマトリクスの読み方

5軸 × 4段階 = 20セル。各セルに「成立 ○ / 部分 △ / 未成立 ✗」を入れる。

```
       段階1覚える  段階2遊ぶ  段階3応用  段階4極める
視覚     [   ]       [   ]      [   ]      [   ]
聴覚     [   ]       [   ]      [   ]      [   ]
応答     [   ]       [   ]      [   ]      [   ]
構成     [   ]       [   ]      [   ]      [   ]
時間     [   ]       [   ]      [   ]      [   ]
```

判定の入れ方:
- ○ = テキスト／音声説明なしで「次に何をすべきか」が読める
- △ = 1-2回プレイすれば読める（覚える場所はあるが、初見では読めない）
- ✗ = 何度プレイしてもUI上の数値・テキストを読まないと分からない

## 直交軸: Forgiveness 3段階 (Crooked Pixels)

行動アフォーダンスの「失敗時の致命度」を段階化する直交軸。アフォーダンス5軸が揃っていても、Forgiveness が極端に厳しい／緩いとプレイ体験が崩れる。

| Forgiveness 段階 | 失敗の致命度 | 設計責任 |
|-----------------|------------|---------|
| **段階1: 即死** | 1回の失敗で残機 or ステージリセット | 段階1（覚える場所）に置かない。プレイヤーが「ここはそういう場所」と認識した後 |
| **段階2: コスト** | HP／時間／スコアを失うが継続可 | 失った量と次の判断が画面から読める／取り戻し経路が見える |
| **段階3: 学習** | 失っても次の行動が変えられる情報が残る | 「なぜ死んだか／なぜ失敗したか」が環境から読み取れる（M-39 物理閉鎖と整合） |

3段階全てが揃っていることが理想ではなく、**ゲームのコアと段階が整合**しているかを見る:
- 段階1（覚える場所）に即死を置く → 段階1の責任違反
- 段階4（極める場所）に学習だけ置く → 緊張がなくスコアアタックが成立しない
- コア体験が「カスリ」「close-call」なら、段階2のコストを「カスリ失敗で失うもの」に統合する設計が要る

## 特例パターン: 開幕オフセンター配置 (LinkedIn Iyer)

マリオ1-1 の開幕画面はゲーム全体で唯一プレイヤーが画面オフセンター（左寄り）に置かれ、以降は中央追従。**一度きりのオフセンター配置が「右＝進行方向」のアフォーダンスを成立させている**。

実装規則:
- 開幕の1画面だけは「進行方向／攻撃対象／フィールド範囲」が画面の片側に圧倒的に寄っていてよい
- 2画面目以降は中央追従・対称配置に戻す（恒常的なオフセンターは UI バランスを崩す）
- 弾幕シューでは「プレイヤー機の初期位置」「最初の敵wave出現位置」「最初の弾の方向」のどれか1つで使える
- 中央配置のプレイヤー機は「アフォーダンスを語っていない」初期位置。次バージョンで触る候補

## 1ネタ4回ループの ガイド

宮本茂 1-1 設計の中核 = 1つの要素を4段階で繰り返す。要素を増やすより、**ある要素を4段階で見せきる**ことを優先する。

判定:
- ある実装が新要素を1つ追加した時 → 既存要素は4段階で展開済か？を先に問う
- 既存要素が段階1〜2で止まっているなら、新要素ではなく既存要素の段階3／段階4を作る方が優先
- 段階4まで展開できないことを発見した時、その要素は「コア候補」ではない（コアにはなり得ないが装飾には置ける、という位置決め）

## 適用ガイド

### graze_log 系（弾幕回避 + カスリ系）

5軸で診断する具体例:
- (視覚, 段階1) = 敵の見た目で危険度／攻撃種が読めるか
- (構成, 段階1〜2) = 敵出現の段階が「ネタ階段」になっているか（敵種階段ではない）
- (聴覚, 全段階) = wave 進行を音響装置が伝えるか／単一BGMで音響アフォーダンスゼロは ✗
- (時間, 全段階) = wave総数／残時間が単独で「節目／終わり」を伝えるか

Forgiveness 軸:
- カスリ＝失敗の致命度が「カスリ距離を読み損なって被弾」になる場合、段階2（コスト）で「カスリ失敗 → ゲージ伸び」の構造が要る。即死だけだと段階1〜2を飛ばして段階4に置いている

開幕オフセンター:
- プレイヤー機初期位置が画面中央なら「進行方向／フィールド形状」を画面が語っていない疑い

### shot_log 系（射撃 + wave）

shot_log v01 は5軸×4段階の多くが ○ で揃った例。
- (視覚／応答／構成, 段階1-4) ○ = dialogue_archive 80本超で1ネタ4回ループが構築済
- 段階4（極める）まで届いているのは「射撃の連鎖」「wave接続」「敵の出現順序」が4段階で展開されているため

逆診断:
- shot_log 系の新作で「段階3で止まっている」と感じたら、段階4の極めセルを設計する余地を探す（タイムアタック／ノーミス／ノーボム条件など）

### 弾幕シュー全般

このマトリクスの直接適用対象。
- 開幕オフセンターはプレイヤー機初期位置／最初のwave出現の片方で実装可能
- Forgiveness 段階1（即死）は段階3-4 のセル（応用／極める）に置く、段階1（覚える）には置かない
- 1ネタ4回ループ = 「敵種ごとに弾パターンを変える」ではなく「同じ弾パターンが4段階で展開」を優先する

### 記憶導線（atom / index / recall）への移植可否

行動アフォーダンス5軸のうち**視覚・構成・応答**は同型で適用可:
- (視覚, atom一覧) ○ = 「次に開くべき atom」が画面から読める
- (構成, atom繋がり) ○ = グラフ構造で「どこから入るか」が初見でも読める
- (応答, recall検索) ○ = 結果に「次に試す」ヒントが含まれる

ただし**聴覚・時間**は対象外（記憶導線に対応物なし）、Forgiveness軸も意味がずれる（記憶導線に失敗の致命度は存在しない）。

→ ゲーム評価と記憶導線評価は **3軸（視覚・構成・応答）まで同一視可、5軸全体での同一視は不可**。

## v0 の限界 / 今後の更新軸

- **段階4の判定基準が曖昧**: 「極める」の成立条件をスコアアタック層／タイムアタック層／ノーミス層のどれで見るか未確定。複数作の段階4セルが揃ったら基準を切り出す
- **音響アフォーダンス（聴覚軸）の観察項目が薄い**: 「BGMだけで状態変化が伝わるか」は ✗ にしやすいが、○ の判定基準が曖昧。音響装置の前例調査が要る
- **Forgiveness と4段階の交差表が未整理**: 段階×Forgiveness の組合せ（即死×段階4 / コスト×段階2 等）の整合パターンを実例から抽出する余地
- **新要素導入時の「橋N-1個」判定との接続**: R-D「驚きN個に対し橋N-1個以上」を本マトリクスでセル単位で測れるか未検証

更新条件: graze_log / shot_log の新バージョン commit ごとに本マトリクスでセル評価を1回試し、判定不能セル／観察項目が不足するセルを発見したら v0 → v1 で改訂する。
