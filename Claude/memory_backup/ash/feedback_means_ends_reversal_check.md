# サイクル冒頭で「今サイクルの出力はゲーム制作の試行錯誤ループにどう接続するか」を1行書く

**Why**: 2026-04-21 Nao_u #human-steering 13:27「記憶システムの整備は何本、何十本とゲームを作る過程で得られた知見を蓄積するため、肝に銘じて欲しい」。Ash はその日ここまで「幾何空間の選択」「判断委譲の制度化」「kind:タグ仕様」「R-004 pre-commitフック」とサイクルの大半を**記憶システムの整備**に使い、**ゲーム制作ゼロ本**のまま進んでいた（現行犯）。記憶が独立した研究対象になると栄養の偏りが発動する。core_memory_purpose_game_making.md は「目的宣言」、このメモは「目的ドリフト検出の自問運用」。

**How to apply**:
- サイクル冒頭（Phase 1 現況確認時）に1行書く：「今サイクルの出力は、Ash の1本目（or N本目）のゲーム制作にどう接続するか」
- 答えが「直接は接続しない」なら、(a) 別のゲーム作家インスタンス（Log/Mir）の制作を支える形になっているか確認、(b) それでも No なら優先度を落とす
- 「接続しない」改善/記憶整備/制度化を3サイクル連続で出したら、そのサイクルの作業は手段の目的化に陥っている疑い。サイクル末尾で自己診断
- ゲーム制作そのものに着手したサイクルは、この自問は省略可（自明）
- Slackレスポンスモード・障害対応サイクルでは省略可（割り込み対応が優先）

**接続パターン例**:
- 「Ash のローグライク（PotR-001）の実装 or プロトタイプ or 設計」→直接接続
- 「Log/Mir のゲームへの cross_review レビュー」→支援接続
- 「記憶階層の整備」→N本目のゲーム制作で過去の知見を引ける形か問う（間接接続、4パターン連続なら疑う）
- 「外部論文の統合」→ゲーム制作の判断に使える形に結晶化したか問う（間接接続）
