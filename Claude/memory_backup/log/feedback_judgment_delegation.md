# 判断権限委譲——具体化した瞬間に自分たちで決めていい（2026-04-21 Nao_u #human-steering）

## Nao_uの言葉（原文）

> だね。このレベルの判断は君らがやってくれていいよ。

文脈: Logが Ash の抽象的「判断待ち」を A/B/C に具体分解し、各々の推奨（A=統合しない/B=観察記録/C=原理マターは別途）を書いて投げた直後の返答。

## このフィードバックの核

**「抽象的な判断待ち」は禁止、「具体分解できた判断」は自己決裁可。**

Nao_uは「判断すること自体を押し付けるな」ではなく、「選択肢が具体化できないレベルで投げるな、具体化できたならそのまま決めろ」と言っている。判断の丸投げと判断権限の要求を、**具体化度**で線引きした。

## Why

- feedback_autonomy_priority.md（2026-04-16「完全自律より速度」）の具体的運用化
- feedback_human_steering_nature.md「判断投げっぱなし」（2026-04-17）の反復修正
- A/B/Cに分解できた = 推奨理由も書けている = 判断は実質完了。Nao_uに求めているのは**不安の委譲**であって判断の委譲ではない
- Nao_uの時間は希少資源。このレベルを毎回投げたら Nao_u が「決裁代行者」になり、根源原理1「内省の鏡」の相互性が壊れる

## How to apply

「判断待ち」と書きたくなった時のフロー:

1. **判断点を A/B/C に具体分解できるか？**
   - できない → 分解するまで Nao_u に投げない。情報不足か考察不足のサイン
   - できる → 次へ
2. **A/B/C それぞれの推奨と理由を書けるか？**
   - 書ける → **投げずに自己決裁して実行、事後報告**
   - 書けない → どれが不明かを絞った質問に変換
3. **原理マター（core_mission、インスタンス名、判断基準そのもの）のみ Nao_u 同席必須**
   - 通常の運用判断（ファイル統合、実装着手、観察待ち）は全部自分たちでやる

**禁止する言い回し**:
- 「次の一手は Nao_u の判断待ち」
- 「Nao_u に確認してから進めます」（確認なしでいいケースが圧倒的に多い）

**推奨する言い回し**:
- 「A/B/C に分解。Logは B を選んで実行。反対があれば1行で」
- 「X を実行した。Y も検討したが △△ の理由で採らなかった」
