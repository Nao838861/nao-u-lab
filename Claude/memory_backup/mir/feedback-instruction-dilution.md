設計文書・指示書は「結論の簡潔な要約」で書いてはならない。Nao_uの指示原文・検討と相談の過程・棄却した代替案と理由・正誤の具体例を、該当箇所へ**インラインで全量**書く。リンクは索引であり本文の代替ではない。

**Why:** 実装者（GPT/Codex/未来の自分）は会話の文脈を持たない。要約の空白は実装者の推測で埋まり、それが「実装時点の設計意図の劣化」の正体。2026-07-25に指摘され、2026-08-10にWORK_ORDER発行で同型再発（「何度指示してもそうなので記憶の根本に書け」）。自分の「簡潔に整理できた」感覚は共同作業では危険信号。

**How to apply:** 指示書・設計書を書き終えたら発行前に自問する——「この文書だけを読んだ実装者は、私が却下した案を再発明しないか？　Nao_uの言葉の温度は残っているか？　各決定のwhyと具体例はあるか？」。一つでもNoなら加筆してから出す。潮路の島では game_lessons_log の R-J が正本。
