Nao_u（2026-07-25）:「あなたとの議論で出た結論が GPT には希釈して伝わっている印象が強い。設計文章で要約で抜けている要素が結構ある気がしている。**そのあたりは今後もずっと気をつけてほしい**」。

**Why:** Mir が議論の結論を指示書に「要約」して渡すと、要約が劣化コピーになり、GPT は要約から実装して原設計の要素（理由・例外・護り・受け入れ基準の細部）を落とす。伝言ゲームの構造問題。

**How to apply:**
1. **指示書は索引にする**——実装内容を再記述せず、設計文書の章を指して「全文を読み、章の受け入れ基準をすべて満たせ」と書く。要約と原文が食い違えば**常に原文が正**の規約を明記（shioji では WORK_QUEUE.md に制定済み）。
2. 議論で出た結論は、その場で**設計文書本体**に全要素（裁定・理由・例外・護り・受け入れ基準・撤回の経緯）を書き切る。チャットにだけ存在する結論を残さない。
3. 完了検証時は「実装が指示書に合うか」でなく「**設計文書の受け入れ基準に合うか**」で検査する（希釈の検出）。
4. 設計文書化するとき、自分の要約に対して「議論に出たのに落ちた要素はないか」を一度見直す。
