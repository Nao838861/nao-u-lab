# アイテムの抽象化と画面表示 — 「荷」単位と財の山の見せ方

作成: 2026-07-13（Mir） / 状態: 叩き台
親: [../README.md](../README.md) / 発端: Nao_u「丸太も魚も一ユニット？市場の資材置き場に数百〜数千のユニットをどう並べる？並べない？」

前提: 市場=積み上がる財の山（確定）/ 実体は抽象化しない（確定）/ わかりやすさ優先 / 無主の在庫なし（確定）

参照作: The Settlers（財が地面に見えて1個ずつ運ばれる魅力の原典）/ A列車（資材=標準化された1単位の先例）/ Factorio（大量の財が見えて流れる）

---

## 1. データの抽象化: 全財共通の「荷」単位

**1荷 = 人が担いで運べる量**。全ての財を同じ単位で数える（整数）:
- 丸太1荷=丸太束 / 麦1荷=俵 / 魚1荷=篭 / 材木1荷=板の束 / 炭1荷=炭俵 / 鉄1荷=延べ棒の束…
- **輸送容量の階段が自動的に立つ**: 徒歩=1荷 / 手荷車=4荷 / 荷馬車=16荷 / 川舟・沿岸船=50荷〜 / 廻船=数百荷（数字は仮）
- 価格・取引・消費すべて荷単位の整数（世帯の食料消費=パントリーから1荷がN日もつ、で整数のまま回る）
- 例外は**畜産のみ**: 荷にならない——**自分で歩く**（生体流通・確定済み）。1頭=1単位で群れごと追われて動く
- 実装上の御利益: 在庫=（財種, 荷数, 所有者）のタプルだけ。端数・重量・体積の三重帳簿を持たない

## 2. 財ごとの視覚アイデンティティ

1荷=1個の見えるオブジェクト（シルエットと色で財種が読める——遠目で判別できることが計器としての要件）:
| 財 | 見た目 |
|---|---|
| 丸太 | 茶の丸太束 |
| 材木 | 明るい板の積み |
| 麦 | 俵（黄） |
| 野菜 | 篭（緑） |
| 魚 | 篭（銀・尾が覗く） |
| 干物 | 吊り連（干場の絵と連続） |
| 炭/石炭 | 俵（黒）/ 籠（黒光り） |
| 鉄鉱石/鉄製品 | 籠（赤茶）/ 延べ棒束（鈍色） |
| 木製品 | 木箱 |
| 畜産 | **動物そのもの（歩く）** |
- 荷車の荷台にはこのオブジェクトがそのまま載る（4スロットに4荷が見える——「荷車が何を運んでいるか」が一目で読める=フロー計器の要件）

## 3. 大量表示の答え: 段階集約（並べる、ただしデフォルメで）

数百〜数千荷を1個ずつ並べない。**山の見た目を量に応じて段階的に集約する**:

| 量 | 表示 |
|---|---|
| 〜20荷 | **1荷=1個**、実数で並ぶ（The Settlers の解像度。日常の市場はほぼこの帯域） |
| 〜100荷 | 定型の「山」メッシュに段階昇格（俵の山・丸太の井桁）。高さ∝おおよそlog(量) |
| 数百荷〜 | **ランドマーク級の山**（蔵前の米山・貯木場の丸太山）。豊作の壮観・買い占めの異観として意図的に見せる |

- **正確な数はホバー/クリックで**（山=計器の針、数字=目盛り）。山の高さで「多い/少ない/消えかけ」が遠目で読めることが本務（価格の直感表示・崩壊の可視化=既定の三役）
- 極端な山は隠さない——**豊作の米山は写真を撮りたくなる見せ場**であり、「山が消えて地面が見える市場」は崩壊の絵。表示レンジをクランプしないことがドラマの条件
- 描画コストはGPUインスタンシングで自明に安い（静的メッシュの反復。Nao_uの本業圏）

## 4. 市場の並べ方: 河岸方式（財種で区画し、所有はデータで）

- 市場広場は**財種ごとの区画**に分ける（魚の列・米の列・材木の列——魚河岸・米河岸の史実そのもの）。遠目に「この市場は何が豊富で何が払底か」が縞模様で読める
- 所有者（どの世帯の在庫か）はデータで保持（無主なし原則）。表示は財種優先、クリックで所有者内訳
- 各売り手の「店」を独立に描くのは中期以降の演出（常設店の創発と合流）
