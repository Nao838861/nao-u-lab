# 買い物と距離 — 職住一体世帯の日常物流（小売レイヤー）

作成: 2026-07-13（Mir） / 状態: 叩き台
親: [../README.md](../README.md) / 発端: Nao_u「買い物できる場所や納める場所が遠いと仕事の効率が落ちるようにしたい。市場とは別に行商人もいてもいい。買い物とその範囲、店が離れてる影響を詰めたい」

前提: 職住一体（確定・仮置き）/ 距離コスト=時間の物理（確定）/ 行商人=資本組合せの一役割（確定）/ パントリー=世帯の手元在庫（確定）

---

## 1. 核となる仕組み: 世帯の時間予算（新しい数値を発明しない）

各世帯の1日 = **労働 + 移動 + 取引** の時間予算。効率とは労働時間の割合のこと。
- 「店が遠いと効率が落ちる」を**ペナルティ係数で書かない**——買い出しに費やす往復時間が、そのまま働けない時間になる（開幕Phase 2のきこりの買い出しと同じ原理の一般化）
- 遠さは二重に効く: (1)時間の損失 (2)文化財へのアクセス困難（木製品が届かない山奥の世帯は文化Lvが頭打ち→効率上限も低い）
- **観測**: 世帯をクリックすると時間予算の内訳（労働/移動/取引）が見える。島内報「山の農家、買い出しに一日」

## 2. 買い方の三段階（すべて創発・世帯は価格と時間を天秤にかけるだけ）

| 手段 | コスト構造 | 出現条件 |
|---|---|---|
| **市場へ自分で行く** | 最安値・ただし往復時間を払う | 最初からある（市場0号=商館） |
| **行商人から買う** | 玄関先まで来る・**マージン上乗せ** | 散在世帯×距離があると行商ルートが採算化 |
| **常設の店で買う** | 近所・品揃えは店主の仕入れ次第 | 世帯密度が閾値を超えた集落に三次産業として出店 |

- 世帯の選択は「価格＋自分の時間コスト」の比較だけ（新しいAIを書かない）。忙しい季節ほど行商から買う=**時間の価値が価格に翻訳される**
- **小売の発展史が創発する**: 市場だけ→行商が隙間を埋める→密度が上がった所に店が生える。**村の店=三次産業の入口**（居酒屋より先に「よろず屋」が生えるはず——三次産業創発の第一号は多分これ）

## 3. 納め方（売り側）も同じ構造の鏡像

| 手段 | コスト構造 |
|---|---|
| 市場へ担いで行く | 最高値・時間を払う |
| **仲買人（行商の買い側）に庭先で売る** | 庭先価格（安い）・時間ゼロ |
| 近くの問屋の蔵に納める | 中間 |

- 行商人は「売り」と「買い」を同じ巡回で担える（御用聞き+仲買。荷車は往路復路とも積まれる=行商の採算性の実体）

## 4. 波及効果（この仕組みが勝手に生むもの）

1. **集落の形成圧**: 市場・店から遠いクレームは効率が低い→入植者が選ばない→**人は自然に市場の周りに集まる**。プレイヤーの区画が遠すぎると立て札が残る=都市計画へのフィードバック
2. **チューネンの輪の完成**: 日持ち（前決定）×買い物距離で、鮮魚=浜、野菜=近郊、麦=遠方、の輪が閉じる。山奥世帯の魚は干物（行商が運べる唯一の魚）
3. **パントリーの二役目**: 文化Lvヒステリシスのクッション（既定）に加えて**買い出し頻度のバッファ**（遠い世帯ほどまとめ買い・週次市場参加）。同じ在庫が2つの意味を持つ
4. **行商人の顧客網**: 巡回ルート=画面に見える小売網。道が良くなるとルートが伸びる（インフラ投資の効果が行商の足で見える）

# 追記（2026-07-13）: 実装難度への回答 — エージェント最小主義

Nao_uの懸念: 「エージェントの意思決定や、行商人がどこで発生してどこに何を流通させるかの選択は実装難度が高そう。人は不便をどこまで我慢するのか、行商人はどんなきっかけで発生するのか」

## 0. 設計スタンス: エージェントは賢くしない。賢さは市場が担う

学術的な後ろ盾がある: **Gode & Sunder (1993) のゼロ知能トレーダー実験**——ほぼランダムに入札するエージェントでも、予算制約+ダブルオークションだけで市場全体はほぼ効率的な価格に収束する。**個の知能ではなく市場構造が賢さの源泉**。つまり実装すべきは「賢い商人AI」ではなく「単純な規則+信念テーブル+市場」であり、難度の見積もりを下げてよい。

## 1. 「不便をどこまで我慢するか」— 我慢パラメータは作らない

- 世帯は選択肢を **価格 + 移動時間 × 自分の時間単価** で比較するだけ。時間単価=その世帯の最近の稼ぎ（機会費用。新しい数値でなく実績から出る）
- 貧しい世帯は時間が安い→遠くまで歩いて我慢する。稼げる農家は時間が高い→行商から買う。**「我慢の限界」は性格パラメータでなく所得の関数として創発**
- どの選択肢も高すぎる時=未充足需要→パントリー取り崩し→文化Lv低下（ヒステリシス）→衰弱→移住検討（全て既存システムの連鎖）。**我慢の限界=既に設計済みのカスケードであり、新規実装ゼロ**

## 2. 行商人の発生 — きっかけは「既に旅している人」

コールドスタートの心配は不要。**Phase 2の通勤者（自分で買い出しに行くきこり）が、山と港の両方の価格を自分の目で見ている**——最初の行商人の候補は構造的に必ず存在する（元・通勤者 or 元・商会荷駄員（のれん分け案））。発生の実装は既存の転職機構に1本の不等式を足すだけ:

```
(観測した価格差 × 荷車容量 − 往復時間 × 自分の時間単価) が
現職の日収を N日連続で上回る → 荷車を買って転職
```

- 価格の観測 = (a)自分が旅先で見た価格（自分の信念テーブルに記録） (b)市場での噂（同じ市場の参加者からK件の価格観測をサンプルコピー=「情報は徒歩速度」の実装形）
- これは価格信念・職業信念と**同じテーブル・同じ更新則**。新しい機構ではない

## 3. どこへ何を運ぶか — 一段先読みの貪欲で十分

行商人のAIは3規則だけ:
1. **貪欲**: 今いる場所から、自分の知っている価格観測の中で「1往復あたり期待マージン最大」の(財,行き先)を選ぶ。経路最適化はしない（一段先読みのみ）
2. **信念更新**: 行った先で実際の価格を見て記憶を更新（古い情報で損する旅→自動修正）
3. **習慣**: 儲かったルートを再訪しやすくなる（強化1変数）。巡回路は計画でなく**習慣の堆積として創発**
- ボイドと同じ構造（3規則→複雑に見える群れ）。「賢い流通網」は個の計画からではなく反復から生える

## 4. 検証ラダー — 怖さを falsifiable な小ステップに分解する

実装難度の懸念への構造的な答えは「作る順番」。ヘッドレスで:
| # | 実験 | 合格条件 |
|---|---|---|
| 1 | 1市場・N世帯・ダブルオークションのみ | 価格が発振せず収束（BazaarBot再現） |
| 2 | 2市場+人為的価格差+荷車許可 | 裁定が発生し価格差が縮む |
| 3 | 開幕Phase 2再現（山のきこり+港） | X日以内に最初の行商人が創発。我慢カスケードが観測可能 |
- 失敗した時のフォールバックも規律化: **新システムを足さず、既存のつまみを回す**（噂のサンプル数K↑=情報流通を増やす / 摩擦↓）。それでも駄目な時に初めて機構を疑う

## 5. 原則昇格の提案

**設計原則10: エージェントはバカでいい——賢さは市場が担う**（ゼロ知能原則）。個々の意思決定は「小さなテーブルからmaxを取る」以上に賢くしない。複雑さの予算（原則2）のエージェント版。

## 6. 反映（2026-07-13 Nao_u）: 原則10・検証ラダーとも仮置き確定。行商3規則への複雑さ指摘→**2規則に削減**

Nao_u「行商人の3規則は十分複雑では？仕方ないとも思うが」——正当な指摘で、**規則3（習慣）は削除できる**:
- **信念テーブルが習慣を兼ねる**: 行商人は自分が行った場所の価格しか知らない→知っている場所にしか行けない→**再訪は知識の偏りから勝手に生まれる**。強化変数は不要（情報の局所性が暗黙の習慣）
- MVPの行商人=**2規則**: (1)知っている価格観測から1往復マージン最大を選ぶ (2)見た価格で記憶を更新。習慣変数は検証ラダーで「挙動が落ち着かない」と観測されてから足す（つまみを回す規律の適用）
- 複雑さの基準線: 農夫のAI=働く・食う・市場で売買（信念参照）。**行商人=農夫+1判断（行き先選択）だけ**。全世帯が同じループ（働く/動く/取引を信念から決める）を回し、職業=読むテーブルの違い——**エージェントのアーキテクチャは全職業で1つ**
