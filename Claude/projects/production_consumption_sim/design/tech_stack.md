# 技術スタック決定（2026-07-16・Nao_u「設計と実装はお任せ」を受けMir決定）

## 決定
| 項目 | 決定 | 理由 |
|---|---|---|
| コア | **ピュアTypeScriptモジュール**(描画非依存・決定論・検証assert内蔵) | 同一コードがブラウザ(遊ぶ)とNode(Mirのヘッドレス検証)で動く=one engine, two fidelities |
| 描画 | **PixiJS**(WebGL 2D) | 軽量・アイソメ実績・ブラウザ第一 |
| 配布 | ブラウザ第一 → **Steamは後からTauri/Electronラッパー**(Web製Steamゲームの定石) | 夢を殺さず今のコストを最小に |
| 絵 | **2:1アイソメトリックの2Dドット絵/スプライト**(C3ルック) | 3D地形は切る(高低差の8割は段差タイル+陰影で偽装=C3方式)。AI生成と最相性 |
| AI資産管理 | スタイルバイブル先行: カメラ角固定(2:1)・光源固定(NW)・パレット固定・タイル寸法固定(128×64)・プロンプトテンプレート | 一貫性が唯一の敵。バリエーション(季節4×手入れ3状態×tier)はAIパワーで押す |
| 道 | **ロジック=グリッド・見た目=オートタイル平滑化**(角丸め・幅混ぜ) | 自由曲線は経済に寄与せずコスト大。C3もグリッド |
| 獣道 | **敷かない・歩行頻度から自動発生**(タイル通行カウント→草が剥げる) | desire pathの創発=道の三段の最下段がタダで生える |
| 歩行 | **フローフィールド**(目的地=市場/港ごとに方向場を前計算・道変更時のみ再計算・エージェントは毎歩O(1)) | 行き先が共有されるゲーム構造に最適。数百世帯でも地図サイズ×市場数で頭打ち。道の速度差はコスト重みで自然に |
| 経済と絵の分離 | 経済に要るのは所要時間のみ(フィールドから即算)・歩く姿は経路上の補間=見た目の砂糖 | 「歩行が重くて経済が回らない」を構造的に排除 |

## 段階
- **モックv0**: プレースホルダタイルのブラウザ版。コマンドAPI+空間エンジンのTS移植。遊べる最小
- v1: AIスプライト一括生成でC3ルックへ(スタイルバイブル→GPT 5.6にMirが発注)
- Steam: ヒットの兆しが出てからラップ(捨て作業なしの順)
