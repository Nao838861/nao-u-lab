# ビジュアル仕様——ドット絵に落とせるレベルの検討 (2026-07-18)

Nao_u: 「最終的な在庫可能量とビジュアライズをドット絵を書けば落とせるレベルで検討しておいて。3x3にどう収めるつもりなのか興味がある。あなたのビジュアル設計を私はあまり信頼できていない。いろんな考察が抜けたまま実装に進もうとしているように見える」

**根拠データ(v0.20標準村4年の実測)**: 商館在庫ピーク=麦238・道具75・保存64・炭59・塩59・漬物31・布37(計~560荷)。
同時屋台エントリ最大281(財×売り手の重複)。屋台の財別最大在庫: 菜1019・肉851・保存463・塩312。

## グリッドとスプライト規格
- タイル: 菱形40x20px(現行)。スプライトは**足元菱形+高さ**の規約で統一
- 規格: 1x1(山・屋台・小屋)=40x44px(足元40x20+高さ24) / 2x2=80x64 / 3x3=120x84 / 人=8x14
- 深度ソート規約(先に固定・アイソメの定番バグ穴): key=南角タイルの(x+y)、同値はlayer(地面<道<広場<山<建物<人<煙)
- ヒットテスト: フットプリント矩形(タイル座標)で判定。スプライトのピクセルでは判定しない

## 蔵(3x3)——「積み上がる資材」の担当
```
平面図(グリッド座標・南角が画面手前):
 [ス1][ス2][ス3]      ス=山スロット(1品目・50荷)
 [ス4][ス5][ス6]      事=事務小屋(搬出入口・帳場)
 [ス7][ス8][事 ]      C3倉庫と同じ文法
```
- **容量: 8スロット×50荷=400荷/棟**
- スロットのドット絵: 品目カテゴリ×充填4段階(≤12/25/37/50荷)+空(パレットのみ)
- 実測との突き合わせ: 標準村中盤の総在庫~560荷→**2棟目が中盤に必要**(保管容量がゲームになる正しい閾値)。麦238=蔵の5スロット=「村の食の重さ」が絵で見える
- 満杯時: 買上げが止まる(商館パネルに「蔵が満杯」表示)。→蔵を建てる動機
- **蔵に入るのは非生鮮のみ**(麦・保存食・漬物・塩・炭・道具・丸太・布・油・石・鉄・粕)。魚/菜/肉は保管不可(腐敗財の在庫上限は腐敗そのもの、の原則を制度化)
- 山カテゴリのドット絵(8種): 俵(麦)/袋(塩・粕)/炭俵(炭)/丸太組(丸太)/木箱(道具・鉄)/樽(保存・漬物・油)/反物(布)/石積(石)

## 市場核(3x3)+市の広場(可変)
- 核: 井戸+秤+常設屋根の装飾スプライト1枚(120x84)。**物資は一切持たない**
- **屋台は世帯単位**——実測281は「財×売り手」の重複エントリで、財単位の屋台は物理化すると破綻する。
  物理屋台=店番を出している世帯数(実測15-25)で**1世帯1台・定位置**(常連の店の並びが読める)
- 広場: プレイヤーが敷く舗装タイル。屋台は核に近い広場から安定割当。必要面積: 中盤16-24タイル
- 屋台のドット絵: 台+日除け(2色)+品目ミニアイコン(13種・8x8)+盛り3段階。
  過剰在庫(菜1019等)は絵にせず数字バッジ——絵はE7の病理を吸収しない(病理は病理として見せる)

## 港複合(4x3・岸接)
```
 [水][桟橋][水 ]        桟橋: 2タイルが水にせり出す(船の接舷点)
 [水][桟橋][ヤ1]        ヤ=荷揚げヤード(スロット2: 出荷待ち/輸入荷が見える)
 [事][ヤ2 ][道接続]     事=商館事務所(注文状の帳場)
```
- 船スプライト: 沖行き/接舷/積み下ろしの3状態(+帆で入出港の向き)
