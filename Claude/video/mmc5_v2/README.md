# MMC5Racing 解説動画（v2・ゼロから作り直し）

1920×1080・60fps、約6分10秒。目的は「見た人に驚きと納得を得てもらう」こと。制作の型は `../sfc_fx2_explainer`（SFC版スペースハリアー解説）に揃えた。

## 構成
| 場面 | 驚き → 納得 |
|---|---|
| S01 | ファミコンなのにコースが丸ごと回る（ランキング1位の走り、取りこぼし0） |
| S02 | 回せないはずの理由：SFCのモード7との対比、タイルのマス目、1ドット約1.2サイクル |
| S03 | 種明かし：回していない。128方向の絵。走行と同期して「いま出ている1枚」を光らせる |
| S04 | そんな量が入るのか：そのまま27.6MB → タイルにまとめて約6万種類 → CHR 95%使用、ROM 2MB |
| S05 | 壁1：1画面60種類の模様が28の棚に散らばる → MMC5拡張RAMでタイルごとに棚を選ぶ |
| S06 | 壁2：864バイトを毎コマ。休み時間は300バイト弱 → 黒い帯＝書き込み時間 → ループなしの書き込み → 実測の書き込み時間グラフ |
| S07 | 壁3：1ライン114サイクル。168で処理落ち、243万通りの検査、右8ドットと引き換えに184、残り102サイクル |
| S08 | 木が少ない理由：スプライト8個 → 木1本＝128通りの絵 → 18本版のガタつき → 8本 |
| S09 | 右の4つの円：GRIP1位の走りに4輪の値を同期表示 |
| S10 | まとめ |

台本は `narration/script.json`（edge-tts ja-JP-NanamiNeural、1行ずつ生成して正確なタイミングを `src/timing.json` に出す）。

## 素材の作り方
- **走行**：Web版ランキング DRIFT 1位（2217 tick）と GRIP 1位（Nao_u、3443 tick）のリプレイを公開APIから取得し、Web版と同じWASMコアで再生（`tools/record_replay.mjs`）。画面・音・毎フレームのRAM（向き・書き込みコスト・4輪の値）を記録。リプレイの互換世代4は MMC5RacingWeb の `origin/codex/mobile-ui3-top300` から `webcore/` に取り出したもの（作業ツリーは未変更）。両リプレイとも記録どおりのタイムで完走を再現。
- **128方向の絵**：同じコアで、カウントダウン中に自車の位置と向きを書き換えて画面を撮り、敷き詰めて組み立てた（`tools/make_pictures.mjs`）。最新ROMの実画面そのもの。CPU車は位置を変えた3回の撮影の多数決で消した。
- **図データ**：`tools/make_data.py`。タイル重複の色分け、木1本の128通り、模様の棚（10/15版ROMの復号）、回転を打ち消したガタつき比較（18本版は10/15以前の開発ROMの復号データ）。

## 未確認・注意
- 「ファミコン最大の市販ソフトは1MB」は一般知識（メタルスレイダーグローリー 8Mbit）で、出典は未添付。
- DRIFT 1位はNao_u以外のプレイヤーの走り。名前は画面に出していないが、公開前に扱いを確認すること。
- 棚の図（S05）とガタつきの18本版（S08）は開発中ROMのデータ。画面に注記あり。

```sh
node tools/record_replay.mjs rec/replay_drift1.json rec/drift1
node tools/make_pictures.mjs
python -B tools/make_data.py
node tools/tts.mjs
node tools/stills.mjs
npm run render
```
