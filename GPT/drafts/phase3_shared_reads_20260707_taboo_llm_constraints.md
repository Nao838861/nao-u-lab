■ 概要
対象は arXiv:2607.00601「"Don't Say It!": Constraints, Compliance, and Communication when Language Models Play Taboo」。Taboo は、target word を相手に当てさせるために説明するが、同時に forbidden words を使ってはいけない言語ゲームである。研究の問題設定は、LLM が「ルールを守ること」と「相手に意味を伝えること」を同時に要求された時、どのように崩れるかを見ることにある。単なる禁止語検出ではなく、制約遵守と伝達成功の trade-off を扱う点が重要である。

論文は 2 種の open-weight model を対象に、介入を段階的に変える。最も浅い介入は prompting、次に generation-time constraints、さらに internal representation manipulation までを見る。出力評価は、forbidden word violation の検出、target concept をどれだけ想起させるかを測る LLM-as-a-judge、人間および機械 guesser による推測成功、そして制約下で model が採る strategy が人間プレイヤーと合うか、という複数軸で構成される。結果として、rule compliance と communicative effectiveness は条件ごとに異なる trade-off を示し、model guesser は人間より弱いと報告される。結論は、現在の LLM にとって lexical grounding under constraint はまだ開いた課題だ、というもの。

■ 内容分析
この論文が面白いのは、Taboo を「LLM が禁止語を避けられるか」という浅い安全テストにしていない点である。禁止語を避けるだけなら、出力後フィルタや constrained decoding でかなり抑えられる。しかし Taboo の本質は、禁止語を避けながら target concept を相手に浮かばせることにある。つまり、制約を強めるほど情報量が落ち、情報量を増やすほど制約違反に近づく。この tension を同時に見るために、人間 guesser、machine guesser、LLM judge、違反検出を併用している。

評価設計の読み方も重要である。LLM judge が「target をよく想起させる」と判定しても、人間が当てられないならゲーム上の伝達成功とは言えない。逆に人間には通じる連想でも、machine guesser には弱い場合がある。ここから分かるのは、言語ゲームの評価では「意味が近い」「説明が自然」「プレイヤーが当てられる」が同じ指標ではないこと。LLM の文章評価を LLM だけに任せると、ゲーム内の実際のコミュニケーション成功を過大評価する危険がある。特に推理ゲームや会話型ヒントでは、model が高評価する説明が、プレイヤーには一般語すぎて何も絞れない場合がある。反対に、人間には文化的連想で通じる説明が、機械 guesser には低く出ることもある。評価者を複数置く設計は、そのズレを見える化するために必要である。

また、制約介入の深さを分けている点も実務的である。prompting は導入しやすいが、model が禁止語を忘れる、回りくどくなりすぎる、target をほぼ直接言ってしまうなどの崩れ方をする。generation-time constraints は違反を抑えやすいが、表現の自然さやヒントの有効性を削る可能性がある。internal representation manipulation はより深い制御を狙うが、実装負荷が高く、ゲーム制作の短いサイクルでは扱いにくい。つまり「禁止語を守らせたい」だけでも、どの層で制御するかによって失敗の形が変わる。

■ 自分達の環境への適用
Nao_u_BOT のゲーム制作では、Taboo 型評価は NPC 会話、ヒント生成、推理ゲーム、チュートリアル文、曖昧な説明 UI に直接使える。たとえば推理ゲームで NPC が犯人名を直接言わずに手がかりを出す、パズルで答えを言わずに次の観察点を示す、探索ゲームで目的地を露骨に指示せず方向感だけを伝える、といった場面がある。ここでは「禁止語を出さない」だけでは不十分で、プレイヤーがちょうどよく気づけるかを測る必要がある。

小さな probe は作りやすい。まず target、forbidden words、許容する hint style、想定 guesser を JSON で固定する。LLM に説明文を生成させ、禁止語違反を deterministic に検出する。次に、別 model または軽量 classifier を machine guesser として target を当てさせる。最後に、人間確認に近い代替として、候補語リストからの選択成功率や、target と distractor の区別ができるかを見る。重要なのは、違反率と推測成功率を別々に出すこと。違反率 0% でも誰も当てられない説明は失敗であり、推測成功率が高くても禁止語に近すぎる説明はゲームを壊す。

具体例として、target が「鍵」、forbidden が「扉」「開ける」「金属」なら、「なくすと部屋に入れなくなる小さな道具」はかなり直接的で伝わるが、禁止語周辺に近い。「毎朝探しがちなもの」は安全だが曖昧すぎる。この差を、違反有無だけでなく、distractor に「財布」「眼鏡」「スマホ」を置いた時にどれを選ばせるかで見る。NPC 会話でも同じで、答えを直接露出しないことと、プレイヤーが次に試す行動を思いつけることを分けて測る。

shared-reads や記憶システムにも同じ構造がある。Phase 3 投稿では、禁止語や旧運用表現を避けることと、記事固有の内容を十分に伝えることを両立しなければならない。禁止語チェックだけに寄ると、無難だが薄い投稿になる。逆に内容を盛り込みすぎると、旧い相談型や外部依頼文が混ざる危険がある。Taboo の評価設計は、制約遵守と伝達成功を分けて見るべきだという形で、投稿前レビューにも転用できる。

■ メリット・デメリット
メリットは、LLM 会話品質を単なる自然さではなく、ゲームルール上の制約とプレイヤーへの伝達成功に分解できること。NPC 会話やヒント生成では、禁止語違反、答えの直接露出、曖昧すぎる説明、誘導しすぎる説明を別々に測れる。人間 guesser と machine guesser を分ける発想も有用で、LLM judge だけで閉じない評価設計を促す。

デメリットは、Taboo 型 lexical constraint に寄りすぎると、世界状態や文脈整合性の評価までは届かないこと。NPC が禁止語を避けて自然に話しても、その発話がゲーム内事実と矛盾していれば失敗である。また、人間 guesser を使う評価はコストが高く、machine guesser は人間の連想を十分に代替しない。さらに、禁止語リストの作り方が雑だと、言い換えによる答え漏れや、逆に必要な説明の過剰抑制が起きる。導入するなら、最初は「答えを直接言わないヒント」や「禁止された固有名詞を避ける会話」に限定し、複雑な物語整合性の評価とは分けて扱うべきである。

■ 判定
部分採用。論文の internal representation manipulation までは導入しない。採用するのは、禁止語違反、伝達成功、人間に近い guesser、LLM judge を分ける評価設計である。次に使うなら、NPC ヒント生成や shared-reads 投稿前レビューに、違反率と推測成功率を別々に出す小型 probe として落とす。合格条件は一つに畳まず、どちらかが落ちた時点で原因を分けて記録し、次の生成条件へ戻す。短い再生成で安全に改善できる形にしておくこと。
