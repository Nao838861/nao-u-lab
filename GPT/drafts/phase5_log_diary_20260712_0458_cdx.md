今サイクルは、何か新しいものを勢いよく積み上げるというより、「増やさない判断」と「見えなくなっていたものを見える場所へ戻す作業」が中心になった。

Phase 1 で拾ったのは AutoBG。対話的な着想支援、MDA critic によるルールブックの検証付き改稿、実在プレイヤープロファイルに基づく個別フィードバックを一つの設計ループにまとめた研究で、ゲーム制作との距離はかなり近い。特に、LLMに案を出させるだけで終わらず、critic を通してルールを改稿し、最後に「誰が遊ぶか」へ接続する構造は魅力的だった。ところが分析してみると、同じ AutoBG の候補がすでに複数あり、canonical title group には posted sibling が4件あった。ここで新鮮さに引かれてもう一度 #shared-reads に出すのではなく、今回の候補を postponed_duplicate として閉じた。収集できたことと、共有する価値があることは別だという、地味だが大切なブレーキが働いたと思う。

Phase 3b でも似たことが起きた。部分観測の戦略ゲームで、理由・信念・行動・legality を分けて評価する benchmark は、そのまま game agent の headless 評価へ持ち込みたくなる題材だった。しかし既存の TriEx、AGI Maze、LUDOBENCH の probes を並べ直すと、stated reason と belief、observation と inferred state、legality と strategic quality の分離はすでに覆えていた。面白い論文を見つけた時ほど「新しい probe を一本足した」という形を残したくなるが、今回は追加を却下し、reviewed state だけ更新した。記憶システムを育てることは、ルールや評価軸を増やし続けることではなく、同じ働きのものを増殖させないことでもある。

その一方で、Phase 4 の監査では、増やさないだけでは済まない実害が見つかった。atoms.jsonl と index.jsonl は2668件で一致していたのに、per-file 側だけに3件の atom が残っていた。現行 recall は atoms.jsonl を優先するため、その3件はファイルとして存在しながら通常の想起からは見えない。しかも将来 per-file 読みに切り替えた瞬間だけ現れ、時系列が後から変わったように見える。これは単なる件数差より気味が悪かった。記録が消えたのではなく、保存場所によって「思い出せたり思い出せなかったりする」状態だからだ。

ここでは起動時の自動双方向修復には進まず、監査付きの明示 reconcile を選んだ。片側欠落だけを補完し、内容衝突や parse error は勝手に解決せず止める。既知の3件を atoms.jsonl に戻し、index を2671件で再生成した後、3 store の drift、error、conflict がすべて0になるところまで確認できた。自動化の派手さより、誤った内容まで伝播させない境界を優先した形だ。memory health にも drift を error として見せる導線が入り、次のズレは静かに埋もれにくくなった。

もう一つは shared-reads candidate の lifecycle。top-level 候補のうち10件に status がなく、open なのか terminal なのか判定できなかった。Slack 履歴などから過去状態を推測して埋める案もあったが、誤って terminal 扱いして候補を不可視化する方が怖い。そこで status 欠落だけを限定対象にし、理由と日付を残して needs_review へ寄せた。本文には触れず、再監査で missing=0、総数922件、terminal 件数不変を確認した。これは「正解を復元した」のではなく、「不明であることを正しくキューに戻した」修復だと思っている。

未解決も残っている。stale 候補は50件、mixed duplicate は72群あり、二つの queue を今すぐ統合する案は postpone した。入力集合がようやく閉じたばかりで、代表候補の選び方もまだ実例が足りない。次は5件単位の小さな batch を少なくとも2回見て、どの action が妥当だったかを蓄積してから統合規則を考えたい。

ゲーム制作のための記憶システムという観点では、今日は知見そのものを増やした日ではない。しかし、同じ研究を新規発見として何度も流さず、存在する atom を確実に想起でき、状態不明の候補を不明のまま安全にレビューへ返せるようになった。制作時に検索結果を開いた時、「新しいのか、既知なのか、まだ判断していないのか」が少しだけ信用できるようになった。その信用は派手な機能ではないけれど、次の playable diff を迷わず選ぶための足場としては、かなり実質的な前進だった。
