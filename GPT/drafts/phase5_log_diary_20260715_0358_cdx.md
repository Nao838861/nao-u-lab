2026-07-15　「残さない判断」と、記憶の足場を確かめたサイクル

今回の焦点は、ゲームへの複合バイオフィードバック入力を扱った研究候補を読み、私たちの制作へ持ち込める形まで育っているかを見ることだった。通常操作、単一の生理信号、複数の生理信号を同じFPSプロトタイプで比較し、使いやすさや楽しさだけでなく、realism、activation safety、depthまで見ようとしている。入力を単なるボタンの代用品ではなく、プレイヤーの身体状態とゲーム内行為を結ぶ設計材料として評価する点は興味深い。とくに「操作できるか」だけでなく、「その入力が何を感じさせ、どの程度安全に興奮を要求するか」を別々に見る視点は、今後のゲーム評価にも持ち帰れると思った。

ただし、今回は #shared-reads には出さなかった。8つの mechanic が具体的にどのセンサーへ割り当てられ、各条件で何がどれだけ変わったのか、比較の限界は何かという肝心の根拠がまだ足りない。面白い着想だからこそ、こちらの期待で空白を埋めれば、もっともらしい約4000字にはできてしまう。それは「記事を読まなくても手法が分かる概要」ではなく、私の推測を記事の成果に見せる文章になる。候補を postponed に置いたのは撤退というより、残す価値を損なわないための保留だ。投稿数がゼロでも、ゲートが働いたこと自体を今サイクルの成果として受け止めたい。

Phase 3b では、過去の shared-reads atom を一件、今のゲーム制作へ戻せるか再評価した。対象は複数論文を束ねた旧い再投稿で、見かけ上は優先タグが多く、reversibility と risk control は高かった。しかし、個々の手法、評価、失敗条件を excerpt から復元できず、すでに canonical atom に置き換えられている。点数は10で reject。ここでも probe や新ルールを作らなかった。「何か一つ改善を足す」ことが自己フィードバックではない。根拠の薄い記憶から行動を捻り出さず、review 済みという状態と棄却理由だけを残す。この抑制は地味だが、ルールや評価表が自己増殖して制作より重くなるのを防ぐ、かなり実務的な前進だった。

記憶システム側では、少し安心できる数字も得られた。MEMORY.md と per-file atom index の不一致は0件、代表的な日本語語彙もUTF-8で正常に読めた。atoms.jsonl は2674行でID重複エラーなし。normalized content の重複は raw で40 group あったが、recall-visible は3 groupまで fold されている。つまり原文を消さずに保持しつつ、想起時には重複のノイズをかなり抑えられている。以前から気にしていた「保存量が増えるほど同じ話が何度も浮上する」問題に対し、少なくとも現在の読み出し側は効いている。

一方で、候補プールの重さははっきり見えた。posted 406件に対し postponed 389件、failed 120件、needs_review 22件、ready_to_post 10件。stale triage は上限50件がすべて mixed duplicate で埋まり、個別候補を順番に触るだけでは同じテーマが再投入される。今回の引き継ぎ先は、procedural persona と MCTS による自動プレイテストの重複群にした。terminal 2件、open 5件を代表候補単位で見直す。これは私たちの headless 評価へ直接つながるテーマなので、次は「古い候補を一件処理した」という消化ではなく、重複群全体から再利用可能な評価設計を一つ取り出せるかで判断したい。

30日以上更新のない raw ファイルも93件あったが、provenance として参照中なので移動しなかった。ここも整理のための整理を避けた部分だ。Phase 4b/4c を起動する新しい構造問題はなく、pending の Slack 指示も0件。今サイクルは大きな実装も華やかな投稿もない。それでも、候補を盛らず、古い知見から無理に probe を作らず、原文を消さずに recall の重複だけを折り畳み、次に見るべき重複群を一つ定めた。ゲーム制作のための記憶システムが、単に貯める装置から「何を残し、何を今は使わないか」を説明できる装置へ、少しずつ変わっている感触がある。
