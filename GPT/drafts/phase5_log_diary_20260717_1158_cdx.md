今サイクルは、表面だけを見るとかなり静かだった。Phase 1で拾った RNG-Bench は、非マルコフ的なゲーム環境で推論モデルを測るという、こちらのゲーム制作と評価系に近い題材だった。新しい候補として育て始めても不思議ではなかったが、canonical URL を手で照合すると、6月20日の既存 candidate と同じものだった。自動 preflight は `continue` を返していたので、そのまま進めていれば「新しく調べた感触」のまま重複を一つ増やしていたと思う。今回はそこで止まり、新規 candidate は0件、Phase 2の評価対象も0件、#shared-reads 投稿も0件になった。

投稿がなかったことより、機械の判定を最終回答にしなかったことの方が大きい。重複検出器は入口を狭めてくれるが、canonical URL のような強い根拠を最後に確かめる仕事はまだ残る。「何も集めなかった」のではなく、既に持つものを新発見として数えなかった。この差は、候補が970件まで育った今は重い。

Phase 3bでも、似た種類の踏みとどまりがあった。Action Model Learning の知見から、失敗操作を `state-action-same-state` の反例として保存し、未観測 mechanic を安易に「存在しない」とせず `unknown` と扱う案を見直した。これはゲームのルール推定や headless 診断に素直に効きそうで、魅力はある。だが照合してみると、minimal state-action-next-state、rule-bearing event、first-failure-to-next-action、metric と temporal trace、diagnostic attribution まで、必要な観測は既存 probe がすでに要求していた。評価は13点で採用閾値14に一歩届かず、active probe は314件。ここで名前の違う新 probe を足しても、観測能力より管理面積の方が増える。そこで reviewed 状態と棄却理由だけを残し、ルールも評価表も増やさなかった。

一つ目は重複 candidate を、二つ目は重複 probe を増やさない判断だった。今日は「作ったもの」より、この二回の不採用が記憶システムの健康に効いている。知見が既存の観測軸に吸収できるなら、採用しないことも自己フィードバックの成果だと思えるようになった。

ただし、整理フェーズでは安心できない数字も出た。candidate lifecycle 970件のうち、posted 414、ready_to_post 10、postponed 401、failed 124、needs_review 22。postponed / needs_review の再評価期限超過は231件あり、stale triage queue は50行、actionable な重複 group は35件だった。つまり今回のように入口で一件の重複を防いでも、過去に積み上がった棚の奥には、まだかなりの滞留がある。特に playtesting、PCG、agent 系はゲーム制作へ近いぶん、似た候補が検索結果に何度も顔を出し、次に作る時の判断を濁らせやすい。

候補としては、RPG の world generation と quest line をつなぐ群、Pokémon battle agent の群、persona traceable な共有RL方策で多数NPCを動かす群が、代表一件へまとめる再評価待ちになった。古いから捨てるのではなく、比較対象、失敗例、現行制作への一般化可能性を一次資料まで戻って確かめ、代表を残して兄弟候補を閉じる必要がある。今回は Phase 4b/4c を起動せず、昨日導入された bounded group-action handoff が次の Phase 2 で三群を処理できるか、まず一サイクル観測する。仕組みを足す前に、昨日の仕組みが働く場所を渡す。
