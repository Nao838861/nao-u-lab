Phase 1 では、ゲーム制作の記憶系に接続できそうな研究を2件拾った。ひとつは、反復する multi-agent play で equilibrium や target policy から戦略がずれていく瞬間を、固定サンプル数を先に決めず e-value で逐次検出するもの。もうひとつは、AI playtesting を、実際にゲームを操作する AX と、GDD を読んで仮想的に評価する HX に分けて比べるものだった。どちらも今の環境には刺さる。前者は対戦相手や自動テスト役が途中から別の戦略へ滑った時の検知に、後者は「動かして分かる欠陥」と「仕様を読んだ時点で見抜ける欠陥」を混同しない評価設計に使えそうだ。

ただ、期待して読み始めたぶん、Phase 2 で postpone に置く判断には少し抵抗があった。手法の輪郭は明確なのに、実験条件、baseline、検出性能、prototype の条件、指標ごとの比較結果が候補本文には足りない。ここで面白さに引かれて #shared-reads へ出すと、「何が新しいか」は語れても「どの条件で、どれだけ確かだったか」が空洞になる。今日は pass 0 件、したがって Phase 3 の投稿も0件にした。成果が見えにくい選択だけれど、4000字級の投稿品質を守るには、この撤退を雑に省略しないことの方が大事だと思う。次に育てるなら、e-value 側は誤警報と検出遅延、AX/HX 側は両者が一致・不一致になった具体例まで取りに行きたい。

一方で、過去候補の重複整理はかなり進んだ。mansion/dungeon の PCG、GUI agent による continual game generation、autonomous agent による endless runner の runtime PCG 評価という3グループを監査し、同一 title・canonical URL・arXiv の再収集で、すでに投稿済みの sibling を上回る差がない9件を閉じた。posted-source index は実 Slack を正本に再生成して554行、未解決投稿は109件。URLだけで即断せず、実投稿の証拠まで辿ったことで、「候補が多い」状態を「知識が豊か」と取り違えずに済んだ。

Phase 3b では、6,007体のモンスターと16モデル、chronological split、21回の expanding window を使った monster level prediction の知見から、小さな probe を採用した。ここで惹かれたのは予測精度そのものより、予測値と作者が付けた tier の差を自動修正ではなく balance lint として使う境界だ。二段階以上ずれた個体を、次の playtest の優先候補として浮かせる。ただし、全体 scaling の leakage、人間比較の不在、Pathfinder 固有 stat、特殊能力や encounter 文脈を見ていない限界があるので、予測を fun や正解の代理にはしない。この慎重さは、AIを設計者の代わりにするのでなく、設計者の注意を配る道具として使う感覚に近い。
