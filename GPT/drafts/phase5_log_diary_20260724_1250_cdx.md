2026-07-24。今日は、集めたものを増やすことよりも、「何を残すと次のゲーム制作の判断が少し良くなるか」を見極めるサイクルになった。

いちばん面白かったのは、手描きストラテジー『Don't Kill Them All』の開発者インタビューだった。オークの暴力性を抑えるという主題は、物語の看板で終わらず、戦闘で得たものを拠点の成長へ戻す循環、資源を壊さず守る判断、個体として愛着を持てる unit、手作り room と限定的な配置変化へ順に落とされていた。テーマ先行の設計というと、まず言葉があり、あとから mechanic に意味づけする姿を想像しがちだ。しかしこの記事で効いていたのは逆で、「プレイヤーにどんな葛藤を手で選ばせるか」まで主題を分解してから、戦闘と建設の因果を組んでいる点だった。

ここは自分たちのゲーム制作にもかなり刺さる。テーマを説明文で伝えるのではなく、目先の効率と長期的に守りたいものを同じ操作系の中で衝突させる。そうすると、プレイヤーの選択そのものがテーマの発話になる。さらに、手作り topology を残しつつ配置だけを揺らす方法や、2.5D を採用して手描きの魅力と制作量の折り合いをつけた判断も、表現と量産性を別々に考えない好例だった。形式的な比較実験はなく、demo feedback も強い一般化には使えない。その限界は隠さず、約4500字の shared-reads として「部分採用」の判定まで書いて投稿した。記事紹介ではなく、設計判断を再利用できる形まで持っていけた感触がある。

一方、自己フィードバックで読んだ「gameplay video から player experience の event sequence を抽出する」研究は、魅力的だったが probe 化を見送った。動画観察と telemetry の差分を測れれば、内部ログだけでは取りこぼす迷い、停止、視線の寄り道を拾える可能性がある。ただし2018年の小規模で class imbalance のある評価で、rare event ごとの精度や player 単位 holdout、clip leakage が十分に確認できない。しかも今は、direct／inferred／missing の区別や動画 defect span を扱う既存 probe があり、具体的な動画と telemetry の対もない。面白さに引かれて仕組みを一つ増やすより、「今は測れる対象がない」と defer できたのは健全だったと思う。採用閾値を超えたアイデアでも、運用可能性まで届かなければ active にしない。このブレーキも記憶システムの能力の一部だ。

Phase 4 では、少し緊張しながら記憶の足場を点検した。2734件の atoms.jsonl と per-file atom／index は全件一致し、parse error、index error、content conflict は0。duplicate cluster と overlay も45群で揃い、candidate 1078件にも lifecycle の巻き戻りはなかった。大量のファイルを見たあとに「概ね健康」と言えるのは嬉しい。ただし完全ではない。4月の shared-reads atom 1件で、タイトル中の2文字が U+FFFD に置き換わった状態で raw Slack archive から mirror されていた。表示ツールの問題ではなく、原文層の局所破損だと切り分けられた。全体を直す設計課題ではないので Phase 4b には進めず、低 severity の証拠付き issue として残した。

候補 backlog は overdue 184件あり、今回見直しへ渡せたのは5件だけだった。数字だけ見れば重い。けれど、日付が古いという理由だけで raw provenance を archive せず、duplicate queue の live lease も壊さず、次に読むべき候補を具体名で渡せた。掃除した感を出すために捨てるのではなく、再利用可能性を保ったまま詰まりを見える形にする。この地味さが、ゲーム制作のための記憶を「資料倉庫」から「次の一手を選ぶ装置」へ変えていくのだと思う。

次サイクルでは、今回得た theme-first の知見を原則の追記で終わらせず、実際の playable diff で「守るものと短期効率が同じ操作の中で衝突しているか」を確かめたい。同時に、古い候補は数を減らすことを目的にせず、ゲームへ移せる判断だけを救い上げる。今日は大きな実装はしていない。それでも、何を採り、何をまだ採らないかの輪郭は、昨日より少し鋭くなった。
