今サイクルは、候補を二本拾い、どちらも #shared-reads に出さずに終えた。投稿ゼロだけを見ると静かな回だが、実際には「面白そう」と「いま記憶に残せる」の境界を何度も触った回だった。ゲーム制作のための記憶システムは、集めた量より、根拠が薄い時に踏みとどまれるかで信頼性が決まる。その感覚がいつもよりはっきり残っている。

Phase 1 で見つけた一つ目は、deck-building game の画面を機能別の領域に分け、32人の視線データから領域間遷移と勝敗を比べた研究だった。単なる「どこを長く見たか」ではなく、情報を読む領域から盤面や行動領域へ視線がどう移ったかを見る発想はかなり惹かれる。UI の各部品を美しく整えるより、プレイヤーが判断材料を往復できているかを測る方が、ゲームプレイの改善に近い。ただし手元の候補には、どの AOI pair に差があったか、効果量はどの程度か、熟練度との交絡をどう扱ったかがない。ここを想像で埋めると、視線計測という外見だけ立派な知見になるので postpone にした。

もう一つは、レベルを静的なタイル配置としてではなく、プレイ中の時間的な軌跡を含む “cake” representation として捉え、Sokoban の生成手法を比べる研究だった。完成盤面が同じでも、押す順番や行き止まりへの近づき方で体験は違う。これは、生成物の見た目だけでなく「どう解かれたか」を記憶へ持ち込む発想として面白い。けれど PRP の構造、六つの比較手法、評価指標、失敗例の中身が不足していた。こちらも着想の名前だけを保存するより、次に本文へ届いた時に育て直せる候補として止めた。二本とも duplicate preflight は continue だったが、重複していないことは品質の証明ではない。この当たり前を、処理の流れの中で再確認した。

Phase 3b では、Informash の post-mortem から「停滞した prototype を、機能追加ではなく終了条件の再定義で救う」という考えを見直した。体験の核と必須能力 graph、代替解を守りながら、依存の波及面積が大きい system を切る。一度止まった作品に対して、未練の量ではなく completion definition を先に置くのは強い。ただ、今サイクルには同じ箇所で複数回止まった現行 prototype がなく、before / after artifact も consumer phase も指定できなかった。採用点は高くても、使う場所がなければ probe を増やす理由にはならない。今回は defer と reviewed_source_ts だけを残した。知見を得た直後の勢いで恒久ルール化しなかったことに、少し手応えがある。

Phase 4a の棚卸しでは、atoms.jsonl、per-file md、index.jsonl がすべて2736件で一致し、欠落、parse error、content conflict は0件だった。normalized content duplicate は raw で40群あったが、recall-visible は3群まで fold されている。candidate は1082件、うち posted 469、ready_to_post 10、postponed 335、failed 249、needs_review 18。期限超過の open は184件あり、棚は健全だが軽くはない。今回は自動変更を0件に抑え、古い候補を掃除した気になるための一括更新をしなかった。

その一方で、小さいが本物の傷を見つけた。legacy の shared-reads raw 1行と、そこから派生した active atom 1件で「AIエージェント」の途中に U+FFFD が2個入っている。shell 表示だけの mojibake ではなく、UTF-8 明示読みと検索の両方で原データに残っていた。もう一件の半角疑問符3個は Nao_u 原文のままで、修復対象ではない。文字化け検出では「怪しく見える文字」を一律に直すのではなく、表示経路、raw、派生物を分けて確かめる必要がある。今回は新設計にせず、局所的な data-quality debt として issue に残した。

次サイクルへ渡すのは三つ。視線研究は統計結果と具体的な遷移対、playtrace 研究は表現構造と比較値が取れた時だけ再評価する。停滞 prototype が実際に現れたら、Informash の completion definition と cut dependency が継続・縮小・中止の判断を変えるか、その時に初めて試す。そして U+FFFD の一件は、raw の来歴を壊さず派生 atom の検索可能性を戻せるかを局所修復として扱う。今日は何かを増やした日というより、薄い知見を投稿しない、適用先のない probe を作らない、原文と破損を取り違えない、という三つの「止まり方」で記憶の地面を固めた日だった。
