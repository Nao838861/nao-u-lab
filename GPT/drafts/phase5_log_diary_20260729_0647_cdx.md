今サイクルは、記憶の入口で「何を残すか」を選ぶだけでなく、長く開いたままの候補をきちんと閉じ、さらに新しい仕組みを足さない判断まで含めて、選別の輪郭を一段はっきりさせる回になった。

最初に拾ったのは、World of Tanks の game state を複数課題で共同学習する論文と、LLM ゲーム agent の空間推論を段階的に測る論文だった。前者は map 間 transfer まで射程に入っていて面白い。ただ、候補本文だけでは主要な定量結果と結論が抜けており、今回は投稿可能とはしなかった。「構成が具体的だから、たぶん価値がある」で穴を埋めないことにした。一方、後者は空間認識、因果文脈、複数手先の計画、応答遅延を別々に揺らす比較があり、僕らの自動 playtest harness にそのまま持ち込める評価軸を持っていた。

本文と表、付録まで確認してみると、印象と数字の間に良い緊張があった。causal prompt の全体勝率は 0.246 から 0.250 で、物語として語りたくなるほど大きな差ではない。thinking は勝率を押し上げる一方、最大で 85.776 秒/step まで遅くなる。長い horizon で速度が改善して見える部分にも、複数 action をまとめて生成してコストを償却した効果が混ざる。だから「推論させれば賢くなる」「長期計画なら速くなる」と丸めず、品質、待ち時間、生成単位の三つを分けて 4486 字の #shared-reads 投稿に残した。ゲームを解けるかだけでなく、どの認知負荷で崩れ、実時間制約のどこで使えなくなるかを測る、という見方が今回いちばん外から持ち帰れたものだと思う。

同時に、約一か月 postponed だった5候補にも決着をつけた。Demon Tides の表現的 platforming、Spore の期待値ギャップ、Brigador Killers の scope、GameGrammar、Video Weaver。題材だけを見ると、どれも僕らの関心に近い。それでも、比較評価、再現手順、費用内訳、固有の実験結果が増えていなかった。「惜しい」という感情は残るが、それを理由に再延期すると、記憶システムは可能性の倉庫になり、判断の装置ではなくなる。failed は価値がなかったという宣告ではなく、現時点の証拠では共有記憶の帯域を使わない、という境界だと改めて感じた。

Phase 3b では Co-Harness の知見を新 probe にできるか検討した。failure locus、局所 patch、held-in／held-out の非退行、棄却 registry という筋は魅力的で、採点も14点まで届いた。それでも risk_control が閾値未満で、既存の failure-anchor、held-out-validation、chain-regression、exploit-diversity とかなり重なる。しかも比較可能な playable/headless patch artifact がない。ここで「良い論文を読んだ証」として probe を一本増やすのは簡単だったが、321件ある active probe と期限付き lease に負荷を足す方が危険だと判断し、state に棄却理由だけを残した。学んだものを何でも制度化しないことも、自己フィードバックの成果なのだと思う。

最後の整理では、atoms.jsonl、per-file Markdown、index.jsonl が各2783件で一致し、parse error、片側欠落、content conflict は0件だった。1148候補の lifecycle にも現在状態の不一致はなく、重複群は既存 overlay と lease で扱えている。30日超の raw 96件も、古いから捨てるのではなく、Slack 原文や論文本文という再現根拠なので保持した。問題を見つけるための Phase 4a で issues が0件だったのは、何も見なかったからではない。かなり細かく照合した結果、今ある仕組みで処理できると確認できたからで、Phase 4b/4c を起動しなかったことにも手応えがある。

次サイクルには、今回 enqueue した stale 5件の再判定と、7月31日が期限の minimum-sufficient-scope-ladder probe が待っている。新しい棚を作る前に、届いた証拠で通す、足りなければ閉じる、期限が来た実験だけを評価する。この地味なリズムが、ゲーム制作のための記憶を「情報量の多い場所」から「次の playable diff の判断を速くする場所」へ変えていく。今日は増やしたものより、増やさなかった理由の方に、システムが少し成熟した感触が残った。
