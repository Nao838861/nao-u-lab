### 改善案 30件

1. 1プレー単位に絞る。
2. オフェンス5人にする。
3. ディフェンス5人にする。
4. プレーは3種類にする。
5. ルート線を常時表示する。
6. LOS を黄色の点線で表示する。
7. ファーストダウン目標線を緑で表示する。
8. Snap ボタンを目立たせる。
9. ルート編集は終点ドラッグから始める。
10. 守備はマン、ゾーン、ラッシュの3種にする。
11. QB は一定時間で最も開いた相手へ投げる。
12. プレッシャーが近いと早投げする。
13. 捕球判定はセパレーションとプレッシャーで決める。
14. 結果にはターゲット名を出す。
15. 失敗には最寄り守備を出す。
16. プレー選択は左パネルに置く。
17. 分析は右パネルに置く。
18. フィールドは中央に大きく置く。
19. 背景をリッチだが暗すぎない芝にする。
20. プレイヤーはアイコンで表す。
21. ボール軌道を表示する。
22. キーボード操作も入れる。
23. 状態を `window.__playbookLab` で覗けるようにする。
24. README を残す。
25. 自己評価を残す。
26. 検証スクリプトを置く。
27. モバイルでは1カラムへ落とす。
28. 用語説明を常時長文にしない。
29. UI はカードを入れ子にしない。
30. v002 候補を自己評価へ残す。

### 筋の良い案

「プレー設計 -> Snap -> 守備反応 -> 捕球窓分析」を1画面に閉じ込める。解決できる問題は、フル試合実装の重さ、元ネタの核の喪失、結果の不透明さ。懸念は、フルゲーム感と長期目標が薄いこと。

2. フィールドは中央の最大領域にする。

### 筋の良い案

## サイクル3: 実装範囲固定

| 3 | 検証スクリプトを置ける | 実ブラウザ目視までは自動化しない |
| 4 | 1プレー完結で小さい | ドライブ制はない |

| 6 | 守備3タイプで反応差が出る | 守備選択はない |
| 7 | 結果がログに出る | リプレイ保存はない |
| 8 | ルート編集がある | 中間点追加はない |
| 9 | キー操作がある | タッチだけでは弱い |
| 10 | 画面が現代的になる | リアル 3D ではない |
| 11 | 選手能力を入れられる | 能力表示はない |

| 20 | CSS でリッチにできる | 色テーマが偏る危険 |
| 21 | 既存差分を触らず作れる | リポジトリの未同期問題は残る |
| 22 | コードが1ファイルで追える | 将来は分割したい |
| 23 | 自己評価が次版に繋がる | 評価は主観も含む |
| 24 | ルール説明が短い | 初回はまだ分かりづらい可能性 |
| 25 | 画面内の因果が見える | 戦術の深さはこれから |

### 改善案 30件

1. `playbook_football_lab/v001` として新規作成する。
2. `index.html` に3カラム UI を置く。
3. `styles.css` でフィールドを大きくする。
4. `game.js` にプレー定義を持つ。
5. `README.md` に操作を書く。
6. `design_log.md` に3サイクルを残す。
7. `self_judgment.md` に弱点を書く。
8. `verify.js` で構造チェックする。
9. プレイ選択カードを生成する。
10. 状態は `state` に集約する。
11. ルートは相対座標で持つ。
12. 編集差分は `routeOverrides` に持つ。
13. 守備挙動は trait で分ける。
14. QB の投球時刻は1.62秒にする。
15. ラッシュ接近で早投げする。
16. ターゲット選択は距離、深さ、捕球力で決める。
17. 捕球判定はセパレーション、捕球力、プレッシャーで決める。
18. 結果は成功/失敗カードに出す。
19. ログは原因と次の見直し点を書く。
20. ルート終点ドラッグを pointer event で実装する。
21. フィールド座標へ変換する。
22. 編集中の終点は大きく描く。
23. 実行中は `requestAnimationFrame` で動かす。
24. `window.__playbookLab` を公開する。
25. CSS はレスポンシブにする。
26. Canvas の最小高を決める。
27. ボタンの hover/focus を設定する。
28. 画面内テキストは短くする。
29. v002 は保存、守備選択、ドライブ化を候補にする。
30. commit は自分の追加ファイルだけにする。

### 筋の良い案

v001 は「作戦ゲームの核」だけを実装し、試合運営、保存、ロスター、複雑な AI を後回しにする。解決できる問題は実装爆発、操作核の不明瞭化、現代風 UI と元ネタの分離。懸念は完成品としての物量不足。
