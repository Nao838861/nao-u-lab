# Playbook Football Lab v014 設計ログ

日付: 2026-06-24

## v014 自律サイクル

### 現状観察

v013 で holding は表示され、Coach score にも軽く反映された。ただし、反則として画面に出るのにダウン距離や獲得ヤードへ影響しないのは不自然。ここを放置して作戦保存へ移ると、ブロック周りのルールが中途半端に見える。

### 判断

v014 では holding を試合進行へ入れる。accept/decline の選択までは入れず、まず攻撃側 holding は10yd罰退、獲得取り消し、次ダウンへ進む簡易処理にする。

### 実装

- `holdingPlayers()` / `hasHolding()` / `enforceHoldingPenalty()` を追加。
- 捕球後ラン終了時に holding があれば通常獲得ではなく罰退処理を優先。
- `HOLDING` バナーと結果カードへ反映。
- snapshot に `holdingPlayers` を追加。
- Coach score の holding 減点は維持。

### 残った弱点

holding の accept/decline、複数反則、守備側反則はまだない。ただし反則としての最低限の一貫性は出たため、次は作戦編集の実用性、特にルート点削除とプレー保存へ進むのが妥当。

## v013 自律サイクル

### 現状観察

v012 で `blockQuality` により「良い角度で入ったブロック」と「近いだけの接触」は分けられるようになった。ただし結果はまだ減速量やリングの太さでしか表現されず、プレイヤーから見ると押し込んだのか、抜かれたのか、反則気味に絡んだのかが読みにくい。

### 判断

v013 ではブロック結果を分類する。ここで即ペナルティヤードまで入れるとゲーム進行への影響が大きいため、まず `drive / shed / holding / engaged` の状態を画面、HUD、snapshot、Coach scoreへ薄く接続する。

### 実装

- `classifyBlockResult()` と `setBlockResult()` を追加。
- 高品質かつ前方なら `drive`。
- 長く絡んで品質が低い場合は `holding`。
- 低品質で時間が経つと `shed`。
- その他は `engaged`。
- 結果に応じてリング色を変更。
- HUD と snapshot に block result を表示。
- holding がある場合は Coach score に軽いペナルティ。

### 残った弱点

holding は今は Coach score の軽い減点だけで、実際の反則としてダウン距離や獲得ヤードを戻す処理はない。次は holding をゲーム進行へ入れるべきか、先にプレー保存へ進むべきかを判断する。

## v012 自律サイクル

### 現状観察

v011 でスクリーン壁はできたが、接触は距離と前後関係に依存していた。これだと、ブロッカーが相手を向いていない横接触でも強く効いてしまい、ユーザーが以前指摘した「接触判定がアメフトっぽくない」に戻りやすい。

### 判断

v012 ではブロックの接触品質を導入する。完全な物理ではなく、まず「肩が相手に入っているか」「相手がブロッカーの前にいるか」「守備者が正面から来ているか」を使い、正面で作ったブロックだけが強く効くようにする。

### 実装

- `facingDot()` と `blockContactQuality()` を追加。
- パスプロの接触成立を距離だけでなく `contact.quality` で判定。
- ブロック品質が高いほど rusher の速度が落ち、shed までの抵抗も強くなる。
- スクリーン壁の減速も `blockContactQuality()` を使う。
- `blockQuality` を player/replay/snapshot に保存。
- blockQuality に応じてリングを太くし、HUD に最大値を表示。

### 残った弱点

角度と前後関係は入ったが、ブロック結果はまだ「止める/減速する」に寄っている。次は押し込み、抜け、ホールディングのように、接触結果を分ける必要がある。

## v011 自律サイクル

### 現状観察

v010 で H はパスプロから遅れてスクリーンへ出るようになった。ただし捕球後は H が単独で走るだけで、スクリーンプレーらしい「前に出たOLの壁」がない。そのため Blitz へのカウンターとしての手触りはまだ弱い。

### 判断

v011 では Draw Screen 成功後の前方ブロッカーを追加する。ここで求めるのは完全なブロック物理ではなく、まず画面上に LT/C/RT が H の前へ抜け、守備を遅らせる構図を作ること。

### 実装

- `activeScreenCatch()` と `screenWallTarget()` を追加。
- Draw Screen で H が捕球した後、LT/C/RT は通常パスプロへ戻らず H の前方へ走る。
- H の前方にいる OL に近い守備者は `screenWallSlowdown()` で追跡速度が落ちる。
- 前方へ出る OL は緑リングと矢印で表示。
- スクリーンに引っかかった守備者は赤リングで表示。
- replay frame と snapshot に `screenLead` / `screenPick` / `screenPicked`、`screenWall`、`screenPicks` を追加。

### 残った弱点

守備者の減速はまだ距離と前後関係による簡易判定。次はブロック接触を、体の向き、進行方向、肩が入っているかで分けると、よりアメフトらしくなる。

## v010 自律サイクル

### 現状観察

v009 でスロー、停止、リプレイ、コマ送り、イベントマーカーが入り、判定を確認する基盤は一段落した。次に残っている大きな違和感は、Draw Screen が「Blitzを誘ってRBへ逃がす」プレーとして実際には動いていないこと。H は最初から普通のルートを走り、パスプロから遅れて出るスクリーンの文脈がなかった。

### 判断

v010 はゲーム性側に戻し、Draw Screen の中核である RBパスプロ/スクリーンリリースを入れる。これにより Blitz へのカウンター相性が、スコア計算上の設定だけでなく、画面上の動きとQBのターゲット評価にも反映される。

### 実装

- Draw Screen 時、H はリリース前に `screenProtectPoint` へ入り、LBラッシュをチップできる。
- `blockerFor` で Draw Screen のリリース前だけ H が LB のブロッカー候補になる。
- H の `power` を追加し、チップブロック時は青リングで表示。
- リリース前の H は QB ターゲット評価を大きく下げ、リリース後は Blitz 相手にスクリーン評価ボーナスを得る。
- リリース時に `SCREEN RELEASE` バナーとログを出す。
- snapshot に `screenReleased` と `screenReleaseTime` を追加。

### 残った弱点

H がスクリーンへ出るようになったが、捕球後に前方のOLが壁になる動きはまだない。次はスクリーン成功時に LT/C/RT が前へ抜けてブロッカーになる処理を入れると、アメフトらしさがさらに上がる。

## v009 自律サイクル

### 現状観察

v008 でリプレイのスライダーとコマ送りは入った。ただし、重要なフレームを自分で探す必要があるため、サック、hit-as-thrown、捕球、タックルの検証にはまだ手間が残る。

### 判断

次はイベントマーカー。既存の `showBanner` は重要イベントの発生点をすでに集約しているため、ここにフックしてリプレイマーカーを記録するのが最小で確実。ゲームルールを変えずに、判定の理解と検証を強くする。

### 実装

- フィールド上に `markerStrip` を追加。
- `showBanner` 発生時に `replayMarkers` へ `kind / label / detail / frame` を保存。
- マーカーをクリックすると該当フレームへジャンプ。
- スナップ開始/リセット時に古いマーカーを消す。
- snapshot に `replayMarkers` を追加。

### 残った弱点

マーカーはイベント発生時点の近似で、接触直前の数フレーム前へ自動補正しない。観察基盤はかなり整ったので、次はゲーム性側の RBパスプロ/スクリーンリリースへ戻すのが筋が良い。

## v008 自律サイクル

### 現状観察

v007 のリプレイは、結果後にプレーを見返せる点では前進した。ただし再生開始から眺め直すだけなので、サック判定、hit-as-thrown、捕球、タックルの直前フレームへ戻るにはまだ不便だった。接触判定を今後詰めるなら、問題の瞬間をフレーム単位で見られる必要がある。

### 判断

v008 はゲームルール追加ではなく、リプレイを検証道具として完成させる。スライダーとコマ送りを入れることで、プレイヤーの納得感だけでなく、次サイクル以降の接触/ブロック改善の確認精度も上がる。

### 実装

- `Replay` の横に `-1` / `+1` ボタンを追加。
- リプレイフレーム用の range slider を追加。
- `,` / `.` キーで1フレーム戻し/送りを追加。
- フレーム保存数に合わせて replay controls を有効化/無効化。
- snapshot に `replayIndex` を追加。

### 残った弱点

任意フレームには戻れるが、サック/捕球/タックルなどのイベント位置を自動で示すマーカーはまだない。観察性をさらに伸ばすならイベントマーカー、ゲーム性を進めるなら RBパスプロ/スクリーンリリースが次候補。

## v007 自律サイクル

### 現状観察

v006 で速度制御と一時停止を入れたため、接触や捕球の瞬間を見やすくなった。ただし、見逃した後に戻れない。特にサック、hit-as-thrown、捕球、タックルはプレーの成否を決める瞬間なので、結果後に同じシーンを再確認できる必要がある。

### 判断

次の改善はリプレイ。ゲーム状態をもう一度進める再シミュレーションではなく、実行中の座標フレームを保存して描画だけ再生する。これにより、Replay を押してもダウン、ボール位置、Coach score が二重に進まない。

### 実装

- 実行中に攻撃、OL、守備、ボール、捕球マーカー、読み線、バナーをフレーム保存。
- 結果後に `Replay` ボタンを有効化。
- `Replay` ボタンまたは `L` キーで直前プレーを先頭から再生。
- replay中は `REPLAY` 表示をHUDに出す。
- debug snapshot に `replayFrames` と `replaying` を追加。

### 残った弱点

リプレイは先頭からの再生のみで、コマ送り、巻き戻し、シークバーはない。次に観察性を伸ばすなら replay scrubber、ゲーム性を伸ばすなら RBパスプロ/スクリーンリリースが候補。

## v006 自律サイクル

### 現状観察

v005 までで、QB接触時のサック、hit-as-thrown、OLの簡易ブロック、ポケット幅、捕球後ランは入った。ただしユーザーが繰り返し指摘していた核心は「何が起きたか分からない」ことでもある。接触判定やフットボールらしさを直しても、発生瞬間を見逃すと評価不能になる。

### 判断

次の改善はルール追加ではなく、観察性の改善を優先する。理由は、以降の50サイクルで接触、ブロック、守備AI、ルート編集を直す時に、プレイヤーと開発者の両方が同じ瞬間を確認できる必要があるため。

### 実装

- フィールド下部に `0.45x / 1x / 1.45x` の速度切り替えを追加。
- `Pause` ボタンと `P` キーで一時停止/再開できるようにした。
- シミュレーション時間を `dt * speedScale` で進め、判定ロジックを変えずに観察速度だけ変えるようにした。
- `SACK`、`HIT AS THROWN`、`POCKET COLLAPSE`、`PASS`、`CATCH`、`INCOMPLETE`、`TACKLE` のフィールド上バナーを追加。
- デバッグ snapshot に `speedScale`、`paused`、`banner` を追加。

### 残った弱点

スローと停止は入ったが、任意リプレイはまだない。接触や捕球の瞬間を後から見返すには、次サイクルでフレーム履歴を保存して replay を実装するのが筋が良い。

## v005 方針

50サイクルすべてを個別のv番号に分けると検証不能になるため、v005では「短い自己レビュー50件 -> 重要度の高い修正を実装 -> 残課題を明文化」の形にまとめる。今回の実装では、ポケットペナルティだけで `hitPenalty` が発生した時に `qbContact` を参照して落ちるバグを直し、接触によるhit-as-thrownとポケット崩壊のログを分離した。

## v004 追加方針

v003は守備読みのゲームにはなったが、QB周辺の動きがまだ直線的だった。アメフトらしさを出すには、ラッシャーがQBへ直接走るのではなく、OLに受け止められ、ポケットが保つ/崩れる/抜けるという中間状態が必要。

## 実装

- LT/C/RT のOL3人を追加。
- N/LBなどのrush担当は、QBへ直行する前に対応OLと接触する。
- ブロック中はrusherの速度を落とし、一定時間後にshedする。
- Blitz時はshedが早くなる。
- ポケット幅を算出し、狭いほどhitPenaltyへ加算する。
- 画面上にポケット楕円を表示し、緑/黄/赤で余裕を示す。
- ブロック中/抜けた瞬間を選手リングで表示する。

## 追加修正: 接触判定と選手形状

ユーザー指摘:

> 接触判定が全然アメフトっぽくない。QBがNとかに潰されてるのにボールを投げたり、人の動きがそれっぽくなかったり。あと、人の向きをみせるために長方形にして縦長にするのは直感に反するのでは？

原因:

- QBとラッシャーの接触が、投球可否ではなくpressure数値にしか影響していなかった。
- `pressure < 18` でも早投げでき、実際には潰されているように見える距離でも投球処理が続いた。
- 選手を長方形で描いたため、向きは見えるが「人」や「駒」として直感に反した。

修正:

- 投球前にラッシャーがQBから22px未満へ入ったら即サック。投球は発生しない。
- 34px未満で投げた場合は hit-as-thrown とし、捕球窓へ強いペナルティを入れる。
- サック時はloss、次ダウン、Coach scoreを更新する。
- 選手描画を丸型に戻し、向きは前方ノッチ、腕/足の線、カット表示で示す。
- ResetでCoach score、snap、連打状態も初期化する。

## 追加修正: プレー終了が早すぎる問題

ユーザー指摘:

> なぜ1秒くらいでプレーが終わるの？

原因は、デフォルト投球時刻が1.6秒で、投球後のボール進行が `dt * 1.7` の固定進行だったため、飛球が約0.59秒で終わっていたこと。さらに Blitz ではプレッシャー距離30未満で予定より早投げするため、体感では1秒前後で判定が出ていた。

修正:

- デフォルト投球時刻を2.2秒へ変更。
- 投球スライダーを1.1から3.6秒へ拡張。
- ルート進行基準を2.85秒から3.6秒へ延長。
- 飛球時間を距離ベースの0.75から1.25秒に変更。
- Blitzの早投げ閾値を30から18へ下げ、かなり近づいた時だけ早投げするようにした。
- 最大プレー時間を6.2秒に延長。

## 追加修正: Hへの投球直後に何が起きたか分からない問題

ユーザー指摘:

> QBがHにボールを投げた直後に終わるが、これはパス失敗？Hが敵もいないのに走るのを止めてる？何が起きてるのかよくわからない

原因は、捕球成功時もボール到達判定の瞬間に `finishPlay` でプレー全体を停止していたこと。つまりHが空いていても「捕った瞬間に全員停止」していたため、成功なのか失敗なのか、Hがなぜ止まるのかが画面上で読めなかった。

修正:

- ボール到達時は `resolveCatch` で成功/失敗を分ける。
- 捕球成功時は即終了せず、`CATCH` マーカーを出してキャッチ後ランへ移行する。
- 守備が20px以内に詰める、1.55秒走る、または右端近くへ進むまでプレーを続ける。
- 終了時は「捕球、キャッチ後何yd、誰がタックルしたか」を結果カードに出す。
- パス失敗時は `incomplete` と原因守備者を明示する。

## 追加修正: 動きがフットボールらしくない / 向きの概念がない問題

ユーザー指摘:

> 全然動きがフットボールらしくないのと、この人たちって向きの概念はある？

原因は、選手を丸い駒として描き、目的地へ直線的に `moveToward` していたこと。`angle` も旋回制限もなく、ルートカット、バックペダル、レバレッジ、ボールキャリアの前傾が存在しなかった。

修正:

- 選手に `angle`、`turnRate`、`stride`、`cutFlash` を追加。
- 移動時に目的方向へ瞬間回転せず、徐々に体を向ける。
- 体の向きと移動方向がずれると速度が落ち、カットらしい間が出る。
- 守備のゾーン担当はボール側を向いたまま下がる `backpedalToward` を使う。
- 選手を丸ではなく、進行方向が分かる胴体と頭つきの形で描く。
- カット時に短い弧を表示し、方向転換が見えるようにした。
