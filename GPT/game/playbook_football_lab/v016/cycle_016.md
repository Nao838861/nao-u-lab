# サイクル016 自己判断

日付: 2026-06-24

## 観察

v015 でルート点の削除と保存が入ったが、保存先がプレーごとに1つだけだった。作戦を作るゲームとしては、同じプレーの複数案を残して比較できないと、調整している感覚が弱い。

## 判断

このサイクルでは、フットボールの接触モデルをさらに深掘りする前に、作戦盤としての保存体験を固める。1つの保存を上書きするだけではなく、名前付きスロットを作れるようにして、プレイヤーが自分の試行錯誤を残せる状態にする。

## 実装

- v016ディレクトリを追加。
- 左パネルに `Save name`、`Save slot`、`Delete slot`、保存スロット一覧を追加。
- 保存形式を `playName -> { activeId, slots }` に変更。
- v015の旧保存形式を `Saved 1` として移行する `normalizeSavedRoutes()` を追加。
- `routeRelative()` が選択中slotをベースにするよう変更。
- `Quick save` は選択中slotを上書きし、`Save slot` は新規slotを作るようにした。
- snapshotに `savedSlots` と `activeSavedSlot` を追加。
- verifyに保存スロットUIとv016保存ロジックの検査を追加。

## 次の候補

保存案のrename/import/exportを入れるか、守備側にも編集可能なプレーブックを入れる。今の流れなら、作戦盤としての往復を強めるためにimport/exportより先に守備側編集へ進む価値がある。
