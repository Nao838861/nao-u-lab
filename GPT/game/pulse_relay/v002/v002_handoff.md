# Pulse Relay v002 引き継ぎメモ

v002 は v001 の最終状態を開始点として作成した。v001 は「なんとなく遊べる」段階まで到達したが、細かい敵移動のメリハリ、横編隊の密度判断、shot_log 的な小隊リズムの再現は、人間の指摘で何度も補正された。

## 次回は指示なしで作れるか

完全にはまだ足りない。作れる範囲は広がったが、放っておくと次の失敗を繰り返す可能性が残る。

- 重なり検査を守ること自体はできるようになった。
- ただし、重なり検査を過剰適用して「密な編隊感」まで殺す傾向があった。
- shot_log の良さを「重ならない」「smooth」「速い」などの単語へ劣化要約し、実際の小隊文法である「短い入場、射線に乗る時間、掃け、次小隊との重なり」を取り落としやすかった。
- ヘッドレス評価の数値を見ても、見た目のテンポ、編隊感、撃ちやすさの判断へ変換するところが弱かった。

## 原因

1. 指標の目的を毎回再確認せず、指標を禁止ルールとして扱いがちだった。
   - overlap check は「不自然な重なりを見つける」ための検査であり、「敵を常に大きく離す」ためのルールではない。
   - 今回の横オレンジでは `24F / 80F` が安全側すぎた。`18F / 60F` でも overlap は 0 で、編隊感が増す。

2. teacher 実装の分析を、行動単位まで落とし切れていなかった。
   - shot_log は単に敵が多いのではなく、小隊ごとに「入る、撃たせる、倒させる、掃ける、次が重なる」を作っている。
   - v001 では経路 primitive は改善したが、block 内の小隊密度と時間差の設計はまだ弱い。

3. 人間の視覚評価を先回りするためのチェックが不足していた。
   - `timeline_eval` は秒ごとの密度を見られるが、横編隊の「見た目に詰まっているか」は別途、同一 route の最近接距離、spawn gap、画面内同時数を合わせて判断する必要がある。

## v002 で最初にやること

1. v001 の `enemy_overlap_check.js` を維持する。ただし、結果を「0/1」だけで見ず、最小距離と画面内同時数を見て、過剰に間隔を空けていないかも確認する。
2. 各 block について、敵を 1 体単位ではなく小隊単位で設計する。
3. 小隊ごとに次を明記してから実装する。
   - 何秒に入るか
   - どの射線へ乗るか
   - プレイヤーに何を撃たせるか
   - いつ掃けるか
   - 次の小隊と何フレーム重なるか
4. 評価時は `enemy_overlap_check.js`、`wave_grammar_check.js`、`verify.js`、`timeline_eval.js`、`shot_log_motion_compare.js` を回す。
5. 数値が通っても、密度を削った結果ではないかを確認する。特に序盤 0-10 秒の横編隊と縦列は、重なり 0 だけでなくテンポと撃ち切り感を確認する。

## v001 からの具体的な到達点

- `opening_curve_train`: 縦列は `16F / entry 130F`。
- `mirror_answer` の横オレンジ: `18F / entry 60F / exit 60F`。
- route 方針は clear し、overlap は 0。
- ただし、細かいメリハリはまだ人間評価に依存している。v002 では「最小安全距離を守りつつ、どこまで詰めると気持ちよいか」を自分から探索する。
