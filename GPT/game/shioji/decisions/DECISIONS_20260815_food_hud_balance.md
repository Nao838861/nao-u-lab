# 決定ログ 2026-08-15 — 食料HUDに生産収支と診断を載せる（Nao_u指示）

**状態**: 凍結・v004.59.0で実装済み
**Nao_u原文**: 「輸入が必要な状況かどうかがプレイヤーに伝わらない。一等地に出している島の食料に、生産と消費のバランスを出すべきでは？生産が足りていないのか、生産しているが流通していないのか、などはわかりたい。少なくとも私は現状で何が問題か読み取れなかった」

**背景（day2262セーブの診断確定）**: 6年運転で食料職が麦1・漁2に痩せ（人口52）、生産<消費の恒常赤字で在庫全滅。輸入は08-13の裁定で明示発注制になっていたが「必要だ」という信号が無く、誰も注文せず緩慢に餓えた。**責任をプレイヤーへ移した機能には計器が義務**（R-C）。

**決定（食料HUD＝一等地の拡張）**:
1. **収支の常設1行**: 「生産◯ − 消費◯ ＝ ±◯荷/日」（島全体・30日EMA）
2. **診断の1語**（検証可能な分類・断定の一語は禁止の原則に従い分類は事実ベース）:
   - **作る量が足りない**（生産EMA<消費EMA）→ 手当ての合図「畑・漁を増やすか、本国から麦を注文できます」＋既存の注文/輸入UIへの1タップ導線
   - **作れているが届いていない**（生産≥消費なのに市場在庫が薄い）→ 原因可読パックの原因別表示へ連結
   - **資源が痩せている**（漁場・森の枯渇由来で生産が落ちている）→ 該当資源の表示へ連結
3. 冬予報（季節の備蓄）とは別枠。identifier: 日々の収支はこちら、冬の備えはあちら
4. 識字原則: 結論だけ言う（数式の羅列にしない）。境界跨ぎ（黒字→赤字転落）は一言で事件化、常時は静かな計器
5. 受け入れ: day2262セーブを読み込むと「作る量が足りない（−◯荷/日）・本国から注文できます」が一等地に出ること。識字テスト「何が問題か3秒で言えるか」「次の一手がわかるか」

## 実装・受け入れ（2026-08-15）

実消費EMAだけでは飢餓で食べられなかった量が消えるため、engineへ一日の必要食料量と30日EMAを追加し、HUDの「消費」は実消費と必要量の大きい方を使う。輸入は一切自動化せず、生産不足時のHUDクリックだけを既存の麦発注欄へ結んだ。流通不全は食料需給、資源低下は魚の資源表示へ結ぶ。
