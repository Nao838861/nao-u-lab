### 2.5 道と距離の経済仕様(補足・ここは両者とも未完成領域=本エンジンで初めて完成させる)
flow_islandにあるもの: 経路コスト場(道0.6/草1.0/森1.4)・**移動速度=経路コストの逆数の不変条件**(罠図鑑#9・v0.16の実害修理)・距離による市場トリップのまとめ買い(tripCost=min(max(10,dist×2.2),haul×0.8))・遠距離ほど大きい貯蔵。
flow_islandに無いもの(=物理層の道路グラフで本エンジンが初めて実装する):
- **接続の概念**: 会社物流(荷車)は道路接続が必須(§5.3)。世帯の徒歩は接続不要だが道上1.5倍速
- **距離の経済効果は全て「時間の物理」から導く**(原典retail_and_distanceの原則): 移動に費やした時間=働けなかった時間。ペナルティ係数を発明しない。世帯の1日=労働+移動+取引の時間予算
- 経路長: 徒歩=道路優先の実経路長(道路グラフ+野歩き)/荷車=道路経路長のみ。tripCost等の距離は**実経路長**を使う(直線距離ではない——flow_islandは直線だった。ここが改善点)
- テスト: `testRoadShortensTrips`=道を敷くと同じ2点間の実効移動時間が短縮され、世帯の労働時間が増える(=道の価値が時間として実測できる)

### 2.5.1 距離と時間の詳細仕様(実装可能レベル)
**API(物理層が提供・経済層はこれ以外で距離を測らない)**:
```js
pathLen(a, b, mode)   // a,b=タイル座標。mode='walk'|'cart'。単位=移動コスト合計(タイル換算)
                      // walk: 全地形可。タイルコスト 道0.6/獣道0.85/草1.0/森1.4/水∞。8方向・対角×1.4
                      // cart: 道路タイルのみ(コスト0.6・非接続なら∞=Infinity を返す)
```
**時間の物理(1日=30tick)**:
- キャリアは1tickに「コスト1.0ぶん」進む(道0.6のタイルなら1.67タイル/tick相当)。徒歩の道上1.5倍速は上記コスト差で表現済み——**別の速度係数を足さない**
- 市場トリップ所要tick = pathLen(家,市場,'walk')×2(往復) + 2(取引)。**その日の生産倍率 = max(0, (30 - トリップ所要tick)/30)**——「移動時間=働けない時間」はこの1行で実装する(flow_islandはこれをしていなかった。ペナルティ係数(TRAVEL_RATE等)は移植しない)
- 所要tickが30を超える行程は当日往復不可: v1では**出発自体を禁止**(その世帯は市場に行けない=遠すぎる配置は経済的に成立しない。E-Stableの悪配置対照はこれを踏む)。泊まり遠征は将来課題として実装しない
**経済層で距離を使う箇所の置換表(flow_island→本エンジン)**:
| flow_islandの式 | 本エンジンでの置換 |
|---|---|
| dist(h)=直線距離 → tripCost=min(max(10,dist×2.2),haul×0.8) | dist→**pathLen(家,市場,'walk')** に置換。係数はそのまま |
| 貯蔵目標 tgtD=max(基本, min(12, dist×0.9)) | 同上(pathLen使用) |
| 雇用先・普請現場の選択=直線距離の最寄り | **pathLen('walk')の最寄り**。ただしpathLen>14(往復+取引が30tick超)の先は候補外 |
| 会社物流(買上げ・蔵出し・注文出荷) | **pathLen('cart')**。∞(非接続)なら物流ジョブを生成しない+イベントログに「道が繋がっていません」 |
| localWood/chopWood(半径5の資源走査) | 変更なし(物理的近傍であり道とは無関係) |
| 相続先(近所3世帯) | 変更なし(直線でよい・経済効果なし) |

### 2.6 建物フットプリント(Nao_u裁可・2026-07-19)
全建物は実寸の占有と**入口タイル1つ**(外周接地・道路隣接辺があれば道路側)を持つ。pathLenは入口間で測る。点建物アダプタは廃止。

## 5. 結合仕様(Step 3)
### 5.1 市場トリップ
世帯の市場往復=**徒歩キャリア**(容量=家族の同行人数×4荷=手荷車換算)。売り荷は出発時にpantryから積み、市場到着時に屋台(市場建物のoutbound棚)へ確定。買い荷は帰宅到着時にpantryへ確定。移動中の飢えはpantryでなくcargoからは食べない(単純化)

市場役割を持つ実在建物が無い間は市場往復を開始しない。`economy.market`の座標だけを見て見えない市場へ移動・取引することは禁止する。
### 5.2 工房の原料
木工房等の生産は**自建物のinput棚**からのみ消費。市場で買った原料は帰宅時にinput棚へ。棚が空なら生産停止(v003の既存規則と同じ)
### 5.3 会社の物流
買上げ=市場の屋台→**蔵(倉庫建物)への荷車便**(会社の荷車・道路限定)。蔵出し=蔵→市場棚への荷車便。注文出荷=蔵→港の荷車便→船。**道路が繋がっていなければ会社物流は動かない**(isConnected必須)——これが「道の意味」の第一実装

会社物流は市場・蔵・港それぞれの実在する役割建物が揃って初めて対応する便を生成する。計画に存在しない市場・蔵を日次処理で自動生成してはならない。空の市場・蔵は撤去可能で、撤去時は役割計画も削除するため自動復活しない。市場往復中の世帯がいる市場は撤去できない。
### 5.3.1 転職=人が動く(Nao_u裁可・2026-07-19)
建物の職種は建設時に固定され、**変わらない・変えられない**。転職とは世帯が**空いている対象職の建物へ移り住む**ことである。
- 空き建物(未入居・空き家)が無い職へは転職できない。その旨をイベントログに残す(絶滅職の再参入は「プレイヤーが建物を用意する」問題として可視化される——罠#2の解はプレイヤーの手に移る)
- 破綻・離散した世帯の建物は**空き家**になり、再入居可能
- 引っ越しの家財は§5.4②の例外(相続と同型)として移送する
- flow_islandの「同じ家のまま職だけ変わる」意味論はここで廃止。地形フィルタは建物の立地が担う
### 5.4 物理運搬に乗らない例外(明示列挙・これ以外の瞬間移動は禁止)
①採集の床(野外採集・記帳のみ) ②相続/家督相続/**引っ越し(転職・流民)**の家財(移動の絵は将来) ③開拓キット(入植船が港に運び、入植者が持って歩くのが理想だが、v1は上陸時にpantryへ直付けでよい——ただし物資出納に「移民持参」として記帳)
※旧③「船の積み下ろし」は§5.5の逐次荷役に置換され、例外から削除された(Nao_u裁可・2026-07-19)

### 5.5 港とヤード(Nao_u裁可・2026-07-19)
港=**汎用建物**(桟橋+荷役ヤード)。商館機能(輸出入の権利・本国注文)は港自体でなく**最初の港に付与された役割**であり、将来「商館ではない港」(漁港・離島航路等)が同じ建物に別役割で載る。港の入口は陸側タイル。
- **輸出入ヤード**: 輸出品は蔵から荷車でヤードに積み上がり、輸入品は船から降ろされてヤードの山になる。ヤードは**積み替え中の荷の一時置きのみ**(恒久保管は不可=蔵を建てる理由を消さない)
- **逐次荷役**: 船は接岸し、tick単位で1品目ずつヤード⇔船を移送する(瞬間移動しない)。輸出売上は船積み完了分から記帳する。山の増減がそのまま経済の可視化になる(A列車の港の絵)

### 5.6 屋台の返品便(Nao_u裁可・2026-07-19)
屋台6日撤収の売れ残りは市場の**引き取り待ち棚**へ移す(屋台の寿命サイクルは不変)。世帯は**次回の市場トリップの帰り荷**で持ち帰る(購入品優先・空き容量分・残りは持ち越し)。生鮮は待機中も通常どおり腐敗する。専用の運搬人は設けない(荷役の専門化はC1商家の本設計で扱う)

## 10. 操作・観測API — ビュー/UI統合の前提(Nao_u裁可・2026-07-19)
エンジンはヘッドレスのまま、`createEngineApi(world)`から次の3面を公開する(段48実装済み):
- **操作API**: `place_building / remove_building / add_road / remove_road / set_stock_target / release_stock / accept_order`。プレイヤーが行えるのはこの面だけ(住民への直接命令は存在しない)。日境界の受諾は次のシミュレーション日の操作として記録する
- **観測API**: `snapshot()`は素のJSONを返し、制御用の軽量scopeも持つ。`events()`はday・tick・座標つきで、操作、出発/到着、取引、接岸/荷役、出生/相続/餓死、転職移住、接続不能等を返す。ビューはこれだけで補間再生できる
- **入力ジャーナル**: `inputJournal()`は操作を`{day,tick,op}`で記録し、`replayInputJournal()`で同シード+同ジャーナル=同結果を再生する
- `mimicPlayerThroughApi`は状態を直接変更せず上記操作だけを使う。150日の直接版/API版/再生版が完全同一状態になり、完全版ではAPI版seed11がT=8年帯を通る

### 10.1 市場・蔵の建設契約(Nao_u裁可・2026-07-20)

- `place_building`の`job: "market" | "warehouse"`は職住区画ではなく会社物流施設を建設する。同じ役割は各1棟までとし、入口と任意の建物原点を通常の実寸配置検証へ通す
- 成功時に会社から`P.BUILD_COST=250`(表示2,500デナリ)を支出し、会社台帳、`co.build`、本土への外部貨幣境界へ同額を記帳する。資金・信用限度を超える時は建物・残高を変更せず、理由をイベントへ残して失敗する
- 市場は`inbound / outbound / pickup`、蔵は`storage`を全容量で持ち、建物IDを物流役割へ登録する。以後の世帯市場往復、会社買上げ、蔵出し、注文出荷は既存の物理運搬規則をそのまま使う
- 操作は通常どおり入力ジャーナルへ記録し、同シード+同配置操作で同じ建物ID、役割、台帳、物流結果を再生する
