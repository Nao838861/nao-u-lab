## 章のテーマ(現行チュートリアルとの接続)
現行v003は食料を輸入に頼り木製品を輸出している(輸出先行)。**この流れは活かす**。
第二章の弧 = 「輸入食料が資金を蝕む → 漁と畑で自給する → 輸入が消え、輸出が純益になる」。
これはそのまま受け入れ試験になる(§Step5)。

## 単位と時間
- 財の単位=荷(既存)。新しい財: 魚(fish)・穀物(grain)。既存: 丸太(log)・木製品(goods)
- 時間: **1日=経済の原子**。エンジンは `world.step()` で1日進む。描画のフレームとは独立(既存の経済更新分離を強化)
- 乱数: シード付きPRNG(mulberry32等)。**Date.now/Math.random禁止**(再現性=テストの生命線)

## Step 0: エンジンの骨格と嘘発見器
**やること**
1. `src/econ/engine.mjs`: `createWorld(seed)` / `world.step()` / 状態は素のオブジェクト(JSON化可能)
2. 既存の会社資金・輸出・輸入をエンジン側の台帳に移す: `world.company = {money, ledger[]}`。全ての金の増減は `ledger.push({day, reason, amount})` を必ず通す
3. **貨幣保存則**: `company.money + Σ世帯.purse - 初期合計 - (本国流入 - 本国流出) === 0`(誤差1e-6)を`step()`の最後で毎日assert
4. **物資出納**: 財ごとに `当日の在庫総量変化 === 生産 - 消費 + 輸入 - 輸出`(輸送中の荷を含めて集計)を毎日検査
**テスト**(`tests/econ.mjs` 新設・`npm test`に追加)
- `testConservation`: シード1,2,3で360日走行、保存則違反ゼロ
- `testLedgerNamesEverything`: 資金変化の総和 === ledgerの総和
**プレゼン課題**: なし(このステップは計器のみ)

## Step 1: 世帯——建物に住民が宿る
**データ構造(このまま実装してよい)**
```js
household = { id, surname, members: 5..9(人数), job: 'logger'|'carpenter'|'fisher'|'farmer',
              buildingId, purse: 60, pantry: {fish:0, grain:20, log:0, goods:0} }
```
**ルール(数値は初期値。較正はテストを通しながら)**
- 食事: 1人0.25荷/日をpantryの食料(fish優先→grain)から。不足分の**75%は採集で凌げる**(記帳: 生産=採集として計上)
- それでも不足の日=飢え。**飢え連続20日で家族が1人減る**。3人未満で世帯消滅(建物は空き家として残る)
- 既存の木こり・木工房の建物に世帯を割り当てる(1建物=1世帯)。生産は世帯が行う(稼働条件は現行どおり+飢えた日は生産半減)
**テスト**
- `testHouseholdEats`: grain20荷の世帯が食いつなぎ、尽きた後に採集で延命し、やがて家族が減る(日数の期待値を書いて固定)
- `testNoMagicFood`: 物資出納が採集込みで一致
**プレゼン課題**: 建物クリックで世帯名・人数・パントリーが見える。飢えの家に🍞アイコン

## Step 2: 食料生産——漁師と畑(自給の供給側)
**やること**
1. 新建物: 漁師小屋(3x3・**水域から2マス以内**・入口は道路——既存の立地制約系を流用)。産出: 魚 6荷/日/世帯
2. 新建物: 畑(3x3)。穀物は**90日ごとに120荷の一括収穫**(それまで0)。※年1でなく季節1回に簡略化(shioji時間スケールに合わせる)
3. 魚は生鮮: 3日で腐る(pantry・平積みとも)。穀物は腐らない
4. 平積み表示は既存の資材ヤード方式をそのまま使う(魚の山・穀物の俵=見た目の見せ場)
**テスト**
- `testFisherFeedsIsland`: 漁師1世帯の産出>自家消費(余剰が出る)
- `testGrainHarvestBurst`: 90日目に120荷が一度に積まれ、腐らず在庫が伸びる
- `testFishRots`: 放置した魚が3日で消え、出納が腐敗として記帳される
**プレゼン課題**: 収穫日の畑の絵替わり・魚の山が消えていく表現(腐敗の可視化)

## Step 3: 市場と価格——3原理の実装(この章の心臓)
**やること**(既存の市場3x3建物を経済の場にする)
1. 毎日1回の市場セッション: 各世帯は余剰(pantry - 家族の2日分)を屋台に出し、不足を買いに来る
2. **売値(原理1+3)**: `原価 = (members × 0.25 × stapleP) / 日産荷数 + 原料費` を床に、`ask = 原価 × (1.05 + rng()×1.25)` を**毎回**抽選(記憶・学習・戦略なし)。原価未満では絶対に売らない
   - stapleP = min(市況grain, 市況fish, 輸入grain価格) を **1.0で床打ち**(名目の錨。罠図鑑#5)
   - 木工房の原料費 = 丸太の市況 × 消費量(チェーンの原価連鎖はこの1行で自動になる)
3. **買値上限(原理2)**: 食料=stapleP×2.2(飢え(pantry<1日分)の世帯のみ上限解除)/ 丸太(木工房)=木製品市況から逆算した採算値 × 0.6
4. 成約のたび `px[財] = px×0.9 + 成約価格×0.1`(公開市況)。初期px: fish 1.0 / grain 1.0 / log 1.5 / goods 3.0
5. 買い物は安い屋台から。世帯の購入額は財布まで(原料仕入れのみ-30まで信用可)
**テスト**(需給応答=創発の確認。ここが第二章の合格ライン)
- `testPriceRespondsToScarcity`: 漁師を止めて10日→fishのpxが1.5倍以上に上がる
- `testPriceRespondsToGlut`: 漁師3世帯で30日→fishのpxが下がる(床1.0×原価則の範囲で)
- `testChainCostPropagates`: 丸太pxを人為的に2倍にした世界で、木製品のaskの中央値が上がる
- `testNoBeliefState`: 世帯の状態に価格の記憶フィールドが存在しない(構造テスト)
**プレゼン課題**: 市場の屋台に品目と山、価格の札。市況パネル(px一覧)。**荷車が市場へ余剰を運ぶ絵は既存の物流系をそのまま使う**

## Step 4: 輸入の経済化——「輸入棚」
**やること**
1. 現行の台本輸入(食料が勝手に届く)を廃止し、**輸入棚**に置き換え: 市場セッションに常設の売り手として「grain @4.0 / fish なし」が並ぶ(懲罰価格・本国からの持ち込み)
2. 世帯が輸入棚から買うと: 代金は会社へ、会社は仕入値2.4を本国へ支払う(差額=会社の口銭。全てledgerに理由つき記帳)
3. 船の絵はそのまま: 定期船が輸入棚の在庫を補充する形にすると既存の船と荷役の見た目が活きる
**テスト**
- `testImportIsLastResort`: 島の食料が足りている間、輸入棚の売上≈0
- `testImportDrainsMoney`: 漁師も畑も無い世界で会社+世帯の総資金が輸入で単調減少する(=第二章の課題設定そのもの)
**プレゼン課題**: 船の荷降ろし→輸入棚の山、が見える(A列車の原体験)

## Step 5: 第二章の受け入れ試験(=章の達成条件そのもの)
`testChapter2Arc`(統合テスト・これが通ったら章完成):
1. 開始: 木こり+木工房+輸入依存(現行第一章の終了状態)
2. 台本操作(プレイヤー操作APIで): 漁師小屋2・畑1を建てる
3. 判定(360日後):
   - 輸入食料の購入量が最初の90日平均の**20%未満**に落ちている(自給達成)
   - 全職業(木こり・木工・漁師・農家)の世帯が生存し、年間収入>0
   - 会社資金が輸出により純増に転じている(輸出先行の弧の完成)
   - 保存則・物資出納の違反ゼロ
**プレゼン課題(ここでチュートリアルを被せる)**: 書状の台本はエンジンのイベントを語る:
「輸入の食費が資金を蝕んでいます(ledgerの実数を差し込む)」→「浜に漁師小屋を」→「畑の初収穫です(実際の収穫イベント)」→「今月、輸入はほとんどありませんでした——島は自分の足で立ち始めています」。
**文言・演出・カメラはGPTの裁量**。ただし書状が語る数字は全てエンジンの実数であること(台本の数字を書かない)
