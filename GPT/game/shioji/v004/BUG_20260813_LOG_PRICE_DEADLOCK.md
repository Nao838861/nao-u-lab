# BUG — 丸太の価格デッドロック（上流再較正の後遺症・優先高）2026-08-13 Mir

**再現**: /Users/Nao_u/Downloads/shioji-day567-20260812.json（Nao_u実プレイ）。丸太が市場に150荷あるのに需給は「不足」、木炭以下が連鎖枯れ。

**実測（day567）**:
- 木こりの原価 1.58/荷 → 店頭ask 1.71〜5.31（ask≥原価×1.05）
- 買い手上限: woodshop 1.40 / charburner 1.00 / cartwright 0.90 — **全員が最低askより下**
- 全買い手のblockersが log:"too_expensive"。px.log=0.55（取引が無いのでEMAが動けず据え置き）
- 会社の市場在庫12荷も放出価格が上限超で売れ残り（会社買上げ→放出は解決策にならない）

**原因**: 上流再較正で Y_LOG 16→8（原価が倍）に対し、買い手上限式（産出価格×0.6/LOG_CHAR 等の固定係数）が据え置き。原価>全上限となり取引が構造的に成立しない。取引ゼロだとpx（価格信念）が更新されず自己回復もしない。

**修正方向（GPT実装・較正はテストで固定）**:
1. 買い手上限の再導出: 少なくとも「産出の実相場から逆算した損益分岐（charなら (px.char−他原価)/LOG_CHAR）」の安全係数を、再較正後の上流原価より上に置く。全品目の連鎖で「上流原価 < 下流上限」をassertするヘッドレス検査を追加（今回の型の再発防止）
2. 取引途絶時の信念適応: 一定日数取引ゼロの品目は、pxを店頭最低askへ緩やかに近づける（可読規則・発散なし）。どちらか一方でも本件は解けるが、1は再発防止として必須
3. パネルの摩擦表示（原因可読パックの追補）: 買い手のblockersがtoo_expensiveで在庫>0の品目カードに「市場に在庫はあるが値が合わない（店頭◯D〜/買い手上限◯D）」。世帯blockersのview_model露出が必要（GPT編集中のため同梱依頼）
4. 修正後、本セーブを読み込んで丸太の取引が再開し木炭連鎖が回復することを受け入れ基準に
