# 出題→回答→採点ループ設計（2026-07-29 Nao_u観点。以後の機能はこのループのどの部品かを明記してから作る）

## 診断
ゲームの基本=課題を出し、回答させ、正解を褒め誤答を罰する。現状は三要素とも欠落: 出題なし(状態の垂れ流し)・回答が受理されない(操作が問いに紐付かない)・採点なし(褒め皆無、罰は無音の崩壊=理不尽)。「適当に置く」はプレイヤーの怠慢でなく、出題されていない試験に答えさせていた結果。

## ループの部品
- **出題**(3源): ①本国要求=月次の外圧(品目+量+期限。生存圧と診断ジレンマ解消と価格差周期を兼ねる) ②島の危機=境界跨ぎを問いに整形(「塩が10日で尽きる」) ③自分への出題=交易便の見積り(自分で立てた問い)
- **回答の受理**: 出題の有効期間中に行った関連操作(配置・値付け・蔵出し・便)を問いへ自動紐付けて記録。何が回答と見なされたかを画面で示す
- **採点**: 期限日にエレナが返す。達成=褒め+報酬(本国の信用・資金)。失敗=帰結+**原因一行**(なぜ届かなかったか。無音の崩壊の禁止)。便は即時損益レシート
- **遊びの想定リズム**: 出題を受ける→需給で診断→回答(数日)→採点日に等速へ戻って結果を見届ける。早送りと停止の呼吸=出題と採点の間隔

## 実行計画（2026-07-29改訂版。これが唯一の実行順。他文書の順序記述はすべて本節に従う）

## 識字テスト第1版（2026-07-29 Nao_u実プレイの未把握ルール原文より。冬・食料編の受け入れ基準）
作者本人と子供が把握できなかった実リスト。各設問に「新規プレイヤーが説明書なしにプレイ中の画面から答えられる」ことが合格条件。答えが住む場所を右に指定する。
1. 魚と野菜は何日で腐るか → 品目行の**日持ち欄**（需給・倉庫・買上げの全画面）
2. 保存食・漬物とは何で、誰がどう作るか → 品目カードに製法一文「魚+塩→保存食（漁師の家が自動で加工）」「野菜+塩→漬物（畑の家が自動）」+建物シートの仕事欄
3. 塩・木炭が切れると保存加工が止まる（豊漁を腐らせる） → 塩・木炭の品目カードに「切れると魚の保存が止まる」+切れた瞬間の一言警告（境界跨ぎの事件化）
4. 冬は漁獲が20→5荷/日に落ちる → 初雪の日のエレナ一言+冬の間の漁師建物表示
5. 冬の必要量は人口×約46荷 → HUD冬計器に「必要◯荷・いま◯荷」を常設（統計の奥から昇格）
6. 足りているかどうかをどう調べるか → 計器が引き算まで済ませて出す:「**不足◯荷 ≒ 麦畑あと◯軒ぶん**」。プレイヤーに暗算をさせない
7. いつから冬か → 常設カウントダウン「冬まであと◯日」+初雪の事件化
検証は完成度ループ規約に従い、全問合格まで自己採点を回してから Nao_u に出す。「わからないことだらけなので適当にやるしかない」状態の解消が、このテスト全体の合格定義である。

## 識字の実装原則: 伝える前に減らす（Nao_u 2026-07-29「説明過剰にするな。今でも数字と謎アイテムの羅列で目眩がする。カイロソフトのように」）
- **段階的開示が本体**: 目眩の原因は18品目×多列の一括表示。需給・買上げ等は**島に登場した品だけ**を表示し、新しい品は初めて現れた日にエレナの一言で登場させる（出会いが説明の代わり）。序盤の画面には魚・野菜・麦・丸太程度しか無いこと
- **文より絵**: 腐敗は日持ち数字より鮮度の見た目変化（実装済みのfreshness art）と初回の腐り演出一回で教える。製法は「野菜+塩→漬物」のアイコン式で、文章にしない
- **数字は隠す**: 46荷/人などの定数は見せない。計器は結論だけ言う（「冬の備え: 足りている／麦畑あと1軒ぶん足りない」）。数値は開いた人にだけ
- **説明は事件の瞬間に一言だけ**（初雪・初腐敗・初保存加工）。平時は無言。常設の説明文・チュートリアル文の追加は禁止
- 識字テスト7項の合格手段はこの原則内に限る。説明を足して合格するのは失格と同義
