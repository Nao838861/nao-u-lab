# 26B 完了報告 — 世帯ごとの実出発位相

## 結果

全建物から同時に人が出る原因だったengineの一括判定を、世帯ID由来の決定的な1〜7tick窓へ分散した。表示だけを遅らせず、実際の`marketCarrier`／`workCarrier`が別々のtickに生成される。市場への到着と約定順もこの実出発に従う。

## 変更

- 数値IDは`1 + id % 7`、旧セーブなど数値でないIDは安定hashから位相を導く。
- 日初の会社処理・棚処理は従来どおり1tick目に一度だけ実行し、世帯の出発判定だけを1〜7tickへ分けた。
- 前日から移動中の世帯は、その日の便を重ねない。
- 個別規則の既存unitは時刻引数を省略すれば従来どおり全世帯を一度に判定できる。

14〜20tick案も先に実測したが、遠い世帯が買った食料を日末の食事までに持ち帰れず、飢餓基準を超えたため撤去した。元の実判定が1tick目だったことと、食料が滞りなく届くことを優先して1〜7tickを採用した。

## 検証

- engine focused 2件: 世帯ID 0〜6が1〜7tickに分かれること、各tickで実キャリアが初めて生成されること、同一seedの決定性、普請便への既存契約を確認。
- 8年×3seed（11・13・14）:
  - 人口: 80〜134
  - 飢餓最大: 7.091日/人
  - 9職: 全年・全seedで存続
  - 物量保存・会社存続: 全seedで緑
  - 価格実測: fish 0.178〜1.838、wheat 0.151〜4.000、log 0.163〜1.470、tools 0.712〜2.457、salt 0.250〜5.000、char 0.477〜3.756

同時約定の解消で旧帯を数％越えたfish上限、log下限、tools下限、char上下限だけを実測理由つきで広げ、再度8年×3seedを完走して全帯緑を確認した。
