# 可視物流 AA〜AC 設計サイクル

作成日: 2026-07-23

対象: `v004.11.1-ch4close-guard` からの描画強化

核の一文: **本当に動いている島の物流と暮らしを、目で見て確かめながら、自分の手で少しずつ変えていく楽しさ。**

この改修では engine の経済規則・tick・経路・在庫を変えない。既存 snapshot にある実在庫、棚区分、品目、運搬元／先、経路、イベントを、盤面で読み取れる形へ戻す。実装前に v003 と v004 を同じ 1440×900 の実 Chrome で確認した。

- v003: `tests/artifacts/material-shapes-desktop.png` と `port-yard-desktop.png`。建屋が敷地の一角にあり、ヤード、矢印、木箱、丸太、荷車が見える。
- v004: `/tmp/shioji_v004_before.png`。地形、樹木、屋根、道路、職別バッジは強いが、建屋が敷地を覆い、在庫は最大5記号へ圧縮される。

## 改修審問

- 改修案: 3×3以上の敷地を「建屋」と「開いた作業ヤード」に分け、棚の各品目を実量に単調追従する荷姿で描く。運搬は既存の実経路・実イベントだけで補間し、出現・消滅も端点から連続化する。
- 消える快感: 建物そのものの大きさと屋根の見栄えは少し下がる。
- 残る／増える快感: 道路、樹木、季節色、職別外観を保ったまま、生産物が増え、荷車が運び、ヤードから減る因果を盤面だけで読める。
- 圧力設計か禁止追加か: ルール追加ではなく、既に動く世界の観測精度を上げる。
- 巻き戻し条件: 3×3で建物種別が見分けにくくなる、在庫が建屋や道路を隠す、描画時間が大きく悪化する場合。
- 巻き戻し案: 建屋寸法は現行へ戻し、ヤードの地面区画と荷姿だけ残す。
- 別解: 建物選択時だけ屋根を透過する。ただし未選択で見えないため AA の受け入れ基準を満たさない。
- 軸を増やす案: 生産・運搬・消費の小さな流れ表示を常設する。ただし盤面の実物を見る核をUIへ逃がすので今回は採らない。

### 筋の良い案

**「同じ荷姿が生産地から港まで移る」**を統合視覚文法にする。工房ヤード、荷車、蔵、港、船が同じ品目形状を使い、地面の短い矢印がinput/outputを示す。数字は選択後の確認だけにする。

## 採用方向

3案は競合せず同じ根を異なる層で解くため、次の最小構成で統合採用する。

1. `pileVisual`を最大5の対数代表から、少量は一荷一記号・大量も単調増加する最大24の荷姿へ変更する。
2. 棚区分の代表一品でなく、各品目を最大6品まで敷地内slotへ置く。
3. 一般建屋を敷地奥へ縮め、手前にヤード地面と入出庫方向を残す。最低3×3は維持し、4×4化はしない。
4. carrierの新規／完了時フォールバックを実from/to端点へ接続する。推測経路・架空作業者は作らない。
5. focused Nodeで量写像の単調性、3×3slot内包、端点補間、第四章null回帰、build query整合を確認する。
6. 実ChromeでPC／スマホ、港・工房・蔵、runtime error、クリック領域、描画時間を確認する。

## 着手前批判レビュー

1. 懸念: 建屋縮小で建物の種類が分からなくなる。**解決可能**。屋根色、切妻、煙突、小物、職別バッジは維持し、PC／スマホ画像で判定する。
2. 懸念: 荷姿24×6品×多数施設で遅くなる。**解決可能**。実在庫がある品目だけ、施設最大6品、単純Canvas図形、同一modelでbefore/afterを測る。
3. 懸念: from/to建物中心への補間が実経路を捏造する。**解決可能**。イベント座標を最優先し、欠落時だけ既存snapshotの実端点を使う。経路の折れ点は新情報なしに推測しない。

3件とも「不可／不明」はないため実装へ進む。
