**Nao_u原文**: 「全体の配置は概ねこんな感じで行ってみようか。まだ不自然だったり持て余してる間のあるところもあるので、動かしながら修正すると思う。まずはこれをゲームに入れてみて」

**目的**: 256×256の設計マップ（[../design/map_b2/b2_map_data.json](../design/map_b2/b2_map_data.json)・v1.0凍結済み）を**遊べる試験モード**として投入し、Nao_uが動かしながらマップを磨けるようにする。完璧な新機構ではなく**最小の忠実な投入**が正解。マップの修正は生成器→JSON再出力→再読込で回る前提（データの手編集禁止）。

## ■意図と設計判断（要約で実装しないこと）
- 島の物語: 母港=枯渇するスターター(森と湾内漁場は約3年・人口上限≒150) → 中盤は魚(1.7日)→鉱(2.4日)→穀(2.5日)の順の相互補完 → 終盤は北の大盆地。詳細な原文と経緯は decisions/DECISIONS_20260814_b2_* 6本を必読
- 峠が唯一の道は生成器のBFN assertで保証済み。**エンジン側でも「mountainは通行不可」が成立しない限りこの設計は嘘になる**——最重要の新規要件

## マップ改変の許可（Nao_u 2026-08-14）
教程の成立に都合がよければ、**コンセプト（枯渇するスターター/魚→鉱→穀の序列/峠が唯一の道/北は約束の土地/全圏自給不能）を守る範囲でマップデータを改変してよい**。例: 母港圏の地形の微調整・開始資材の置き場・教程で使う森や漁場の位置の数タイル移動。改変したら何をなぜ変えたかをHANDOFFへ記録（恒久化はMirが生成器へ還流する）。峠ロックと到達可能性の検証は改変後も通すこと。詳細: [../decisions/DECISIONS_20260814_b2_map_tutorial_adapt.md](../decisions/DECISIONS_20260814_b2_map_tutorial_adapt.md)

## 実装ステップ
### S1. 性能スパイク（最初に。B-0の偵察）
256×256の空地形world（水+草だけ）を生成し、tick時間・描画時間・snapshot時間・経路探索(対角横断)を実測してHANDOFFへ。現行予算(表示更新10ms級)からの乖離と危険箇所を特定。**この結果が悪くても中止せず報告**——最適化の優先順位をMirが判断する
### S2. データ読込と新地形
- b2_map_data.json を読む loader（文字→地形の対応表はJSON内のlegendが正）
- **新地形 `mountain`: 通行不可（tileTravelCost=Infinity・建築不可）**。描画は当面rockの濃色流用でよい（絵はB-1で）
- `f`/`F`(肥沃度)は当面**grass扱い+色だけ変えて描画**（畑の生産倍率への接続は次段。見えることが先）
- `R`/`m`(漁場)は当面**水扱い+魚影の点描だけ**（A-3のローカル漁場接続は次段）
- `-`(浅瀬)は水扱いの色違い。`r`は既存rock、`o`/`c`/`.`/`t`は既存のまま
### S3. 試験開始モード「大きな島（試験）」
- 既存の96×64モードは**残す**（比較用）。新モードは母港位置(JSON markets["1"])に港+市場+開始資材を種付け、他の市場候補地は**空き地のまま**（プレイヤーが育てる。4市場の自動種付けはしない——動かしながら決める）
- カメラ初期位置は母港。全域スクロール・ミニマップは既存機構の範囲で（新規UIを作り込まない）
- セーブ互換: 既存セーブは従来通り。新モードのセーブも通常の仕組みに乗せる
### S4. 受け入れ
- 実Chromeで新モード起動→母港圏で建築・道・市場が通常どおり動く→山を跨ぐ道が引けない(通行不可の実証)→峠経由でP1の先に到達できる
- 1年ヘッドレス: 母港圏のみで自律・餓死ゼロ・保存則緑・journal再生一致
- 性能: S1実測に対し、実プレイ(母港圏に世帯十数軒)でPC実Chromeが体感で遊べる水準（数値目標はS1の報告を見てMirが設定）
- 既存テスト全緑（96×64・48×40への影響ゼロ）
## 禁止
肥沃度の生産接続・漁場のローカル資源化・測量式開示・4市場の自動発展・ミニマップ新設・アート刷新（すべて次段。今回は「マップの上を歩ける」まで）
