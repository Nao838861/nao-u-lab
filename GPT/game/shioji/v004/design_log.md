## 2026-07-20 — Phase V-B後半 / V-C 段9〜12完了

### 段9: キャリア補間

- エンジンtickと描画frameの間に`WorldPresentation`を置き、tickごとの不変描画モデルをキューへ積む。表示側は同じキャリアIDの前後座標を補間し、出発時は`departure`、消滅時は`arrival`座標を端点に使う。エンジン時刻は表示待ちで止めない。
- dayEndで転職・相続などが束になった場合と1区画を超える座標差には最低0.18秒を割り当て、単一frameの瞬間移動をなくした。通常/4倍/1日毎秒では速度に応じて表示時間を短くし、表示キューが経済時間を支配しない。
- 徒歩世帯は人数を最大5人の家族列で、運搬は徒歩便または人が曳く荷車で描く。段9の純粋テストでは途中座標と到着時の残像端点を数値照合した。

### 段10: 港

- 港フットプリント四辺の周辺地形を走査し、水面が最も多い側へ盤サイズ非依存の桟橋位置と沖位置を求める。v003の帆船・港クレーン表現を現港座標へ移植した。
- `docking`イベントのtickは沖から桟橋へ入港し、その後は`portCalls.status=docked`の間だけ接岸表示する。最後の荷役でstatusが`completed`へ変わった表示区間は桟橋から沖へ出港させる。
- 実測seed11では最初の港便が44日目tick1293に到着した。実Chrome smokeはこの便を使い、入港途中・接岸・出港途中がsnapshot遷移と一致することを確認する。

### 段11: 逐次荷役

- `handling`イベント1件を船と港ヤードの間を動く1個の資材ブロック（豆腐）として描く。輸入は船→ヤード、輸出はヤード→船で、財種ごとの色と当該tickの正確な移動量を表示する。
- engine公開イベントは、新規`portCall`を作った同じtickで既に動いた初荷を`docking`だけで通知し、完了後の船について明示的な出港イベントを出さない。engineは変更せず、初荷は`qty - remaining`、出港は前後snapshotの`docked → completed`差分から表示専用イベントとして補完した。2荷目以降は公開`handling`と差分量を毎tick照合する。
- 実便の全荷役tickで移動量が1以下、表示荷量が`remaining`差と一致し、船上`vesselCargo`とヤード区分棚が同tickのsnapshotと完全一致するテストを追加した。

### 段12: 物流の追跡

- キャリア描画モデルに荷、量、運搬元/先の建物・棚区分、経路を含めた。Canvas上の実描画位置をhit testし、クリック/タップで選んだ荷車を金色に強調、経路を地面レイヤーへ点線表示する。
- 追跡パネルに「麦 11」「港 / 輸入 → 市場 / 輸入」のように荷の中身・0.1単位の量・出所・行き先を表示し、移動中はカメラが追う。到着時は追跡を自動終了する。
- 実Chromeで港の初荷を運ぶ荷車を実座標クリックし、選択ID、荷名、経路表示をPC解像度で検証した。スマホ解像度でも既存のタップ/スワイプ契約とviewport内表示を維持した。

## 2026-07-20 — Phase V-D 段13〜16完了

### 段13: 建物の配置・撤去

- 画面下の操作ドックで全15職を選び、地図上の「入口にしたい区画」を押す方式にした。公開snapshotの地形、道路、占有、既存区画、世帯位置、普請中入口、将来予約地を読み、エンジンと同じ候補順で3×3/4×4の実寸敷地を決める。
- ゴーストは地面オーバーレイとして3Dソートより先に描き、全占有セルと入口を緑/赤で表示する。水面、森/岩の直上、職ごとの水際/森際/鉱床条件、道路・建物重複、固定の市場/港、予約地を理由つきで事前拒否する。
- 確定時だけ`place_building`へ入口とゴーストの`buildingX/Y`を渡す。実APIで生成された建物の位置・寸法・入口がプレビューと完全一致するテストを追加した。撤去は空き・非固定・在庫ゼロを事前表示し、最終判定は`remove_building`へ委ねる。

### 段14: 道路と接続

- 1区画タップまたは始点→終点ドラッグを8方向線へ変換し、水面・盤外・建物重複をゴーストで拒否してから`add_road`へ渡す。撤去は完成道路1区画を`remove_road`へ渡す。
- 市場入口から8近傍の道路成分をsnapshot上で走査する。市場成分は従来の黄土色、非接続成分は赤土色にし、各非接続建物の入口へ赤い「道が繋がっていません」を表示する。警告は抽象パネルだけでなく原因の座標に置く。
- 実Chromeで単一区画の敷設→journal→撤去→journalを地図クリックで検証した。建物配置/撤去を含め、変更操作は全てcontroller経由で公開入力ジャーナルへ記録される。

### 段15: 会社パネル

- 会社資金、直近24件の台帳、全財の会社在庫・買上げ目標・16荷蔵出しを一枚のスクロールパネルへまとめた。`set_stock_target`と`release_stock`はボタンから公開操作APIを呼ぶ。
- 注文状は財・量・期限に加え「本国決済単価 / 現在の市場最安値」を同じ欄へ並べる。受諾は`accept_order`を呼び、受諾後は残量を表示する。
- engine §10の操作面には`reject_order`がない。拒否は「プレイヤーが注文状を見送った」というUI状態だけに留め、snapshotと入力ジャーナルを一切変えない。再検討ボタンで同じ注文状へ戻れる。実Chromeで拒否前後のjournal長とorderOffer完全一致、その後の受諾記録を検証した。

### 段16: イベント表示

- 観測APIの12種（operation / departure / arrival / transaction / docking / handling / birth / death / job_move / inheritance / blocked / notice）すべてにタイトル・色・詳細の表示経路を割り当てた。
- 出生、相続、餓死、転職移住、接続不能、船、注文状、最終通告など重要イベントはトーストへ出し、全件を最大100件の「島の出来事」へ残す。ログ行を押すとイベント座標へカメラが移る。
- 早送りで数千イベントを一括取得した場合はトーストを連打せず、重要件数を1件に要約してログへ誘導する。会社/出来事シート表示中はトーストを盤面側へ退避し、スマホでは隠して操作を妨げない。
