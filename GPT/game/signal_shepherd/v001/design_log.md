## 受けた指示

## 判断

今回は新規 v001 として、`Signal Shepherd` を作る。狙いは「予測できる軌跡」「短い周回」「リスクを自分で選ぶ」を同じ画面で検証すること。

過去知見から使うもの:

- `gravity_courier`: 予測線と見える力学があると、プレイヤーが次の入力を自分で考えられる。
- `graze_log` フィードバック: 短すぎる軌跡予測は意味がない。予測は対象全体に一定長で見える必要がある。
- `shot_log`: 単調さを避けるには、複数の対象・リズム・ゲートを画面上に置く。
- PCGRLLM / VeRO 系 shared-reads: 評価は「良い反省」ではなく、diff と probe と検証ログに接続する。

## 仕様

プレイヤーはビーコンを動かす。Space で極性を切り替え、信号粒を引く/押す。各信号粒には色があり、同じ色のゲートに入れると配送成功。ノイズ円に触れると失敗。各信号粒には現在の極性とビーコン位置に基づく短期予測線を表示する。

## 2026-05-16 フィードバック反映

ユーザーから「ビーコン、極性、信号粒、ゲートという説明だけでは、画面上のどれが何か分からない。開始後すぐ死ぬので法則性も掴めない」という指摘を受けた。

対応:

- 説明文とHUDを、専門語ではなく「黄色い大きな丸」「小さい色の丸」「同じ色の輪」「赤い輪」という画面上の見た目に合わせた。
- 開始直後5秒を練習時間にし、赤い輪に触れても即失敗しないようにした。
- 最初から3つ同時に動かさず、1つ成功するたび次の色の丸が動く構造にした。
- 画面内に「あなたが動かす丸」「これを運ぶ」「入ると失敗」を直接表示した。
- headless check に「開始直後に赤へ入っても死なない」「練習時間後は赤で失敗する」を追加した。

意図:

ゲーム内の抽象名詞を先に覚えさせるのではなく、見たままの対象と操作を結びつける。最初の数秒は失敗ではなく観察と入力確認に使わせる。

## 2026-05-16 発展版

ユーザーから「ルールは分かったが説明がかなりくどい。対象が一つだけなら反発にする理由が弱く、複数だと制御不能かもしれない」という指摘を受けた。

対応:

- 初期説明を短くし、常時表示ラベルも「危険」「運ぶ」「あなた」程度に圧縮した。
- ヒント表示は開始直後中心にし、一定時間後はHUDと色・軌跡だけで読ませるようにした。
- 1個目は単体チュートリアルとして残し、1個成功後は残り2個が同時に動く構成へ変更した。
- 1個目成功後のメッセージで「押す操作が重要」とだけ示し、以後は配置と動きで学ばせる。
- headless check に、1個成功後に active 対象が2個へ増える検証を追加した。

意図:

説明で理解させる段階から、短い成功体験の後に複数対象制御へ進ませる。反発は単体対象のためではなく、同時に動く別対象を危険から遠ざける操作として意味を持たせる。

## 2026-05-16 ヘッドレスプレイ検証と完成調整

ユーザーから「本来やりたかった複雑さは3個同時ではないか。ヘッドレス検証だけでなくヘッドレスプレイで成立を確認してほしい」という指摘を受けた。

最初のヘッドレスプレイ結果:

- 3個同時で出すと、単純なルールベースプレイヤーは中央付近で停滞し、100秒経っても1個も配送できなかった。
- これは「複雑さがゲームとして成立している」のではなく、目的地と危険地帯の配置が詰まり、保守的な操作が局所解に落ちる状態だった。

対応:

- 最初から3個同時に動く構成へ戻した。
- 左右のゲートを下側へ移し、各色の主経路を短くした。
- 危険地帯を中央の完全な通せんぼではなく、押す/引くで避ける障害として再配置した。
- `headless_signal_shepherd_v001_playtest.js` を追加し、force配送ではなく `setKey` と `flip` による入力でプレイするロールアウト型ヘッドレスプレイヤーを作った。

最終ヘッドレスプレイ結果:

- 3個同時開始: `maxActive: 3`
- 引く/押す両方を使用: `usedAttract: true`, `usedRepel: true`
- クリア: `cleared: true`
- 失敗なし: `survived: true`
- クリア時間: 20.46 秒

判断:

この版では、本来やりたかった「3個同時に動く対象を、1つの場でまとめて制御し、引く/押すを切り替えて危険を避けながら色別の目的地へ入れる」複雑さは、少なくともヘッドレスプレイ上は成立した。人間にとって気持ちいいか、見た目で同じ戦略が読めるかは次の実プレイ評価対象。

## 2026-05-16 深追い停止判断

ユーザーから「説明が必要で、ルールにルールを重ねないといけないゲームは、そもそも筋が良くないのではないか」「深追いせず次に行く方が学びが大きい気がした」という指摘を受けた。

結論:

- `Signal Shepherd v001` は、実験として得るものはあったが、これ以上の小修正で完成度を上げる対象ではない。
- ヘッドレスプレイ上は3個同時制御が成立したが、人間プレイヤーにとっての第一直感と要求操作がずれている。
- 「黄色い丸を動かす」見た目は、自分のキャラで対象を直接運ぶゲームに見える。
- 実際に要求しているのは、キャラ操作ではなく力場操作である。
- このずれを説明、チュートリアル、接触禁止、危険追加、ボーナス追加で埋めようとすると、ルールのためのルールが増える。

得た学び:

1. 見た瞬間の自然な行動と、ゲームが要求する行動がずれている案は危険。
2. 「説明すれば分かる」は、ゲームの核が良いことの証拠ではない。
3. ヘッドレスでクリア可能でも、人間が「なぜその操作をするのか」に納得できるとは限らない。
4. 独自性を守るために自然な操作を禁止し始めたら、企画を切り直す合図。
5. 直接運ぶ方が自然に見えるなら、直接運ぶゲームにするか、見た目を最初から力場・風・重力の中心として作るべき。
6. ルール追加で疑問を塞ぐより、操作核と画面表現を一致させる方が重要。
7. 実験プロトタイプは、失敗理由が明確になった時点で止める価値がある。

次に活かす判断基準:

- 実装前に「プレイヤーが最初にやりそうなこと」と「ゲームが要求すること」が一致しているかを確認する。
- 一致していない場合、禁止ルールを足すのではなく、操作核か画面表現を変更する。
- ヘッドレス検証は成立性の確認に使えるが、納得感や直感性の代替にはしない。
- 企画を守るための説明が増え始めたら、改善ではなく撤退判断も選択肢に入れる。
