# Tide Loom v001 設計ログ

日付: 2026-05-09

## 前提

新しいゲームを作る。`memory/game_design_rules.md` に従い、実装前に3サイクルの検討を行う。

Gravity Courier v005 から引き継ぐ教訓:

- 内部指標ではなく、画面上の運動と成功条件を一致させる。
- 見えない力や抽象的な率を主役にしない。
- 失敗条件は見て納得できるものにする。
- 目標を増やしすぎず、主題を絞る。

今回の候補は `Tide Loom`。中心ポストに糸で結ばれたビー玉を、糸の長さを巻く/ゆるめる操作で振り回し、音符を拾って港へ戻す。

### 改善案 30件

1. 中心ポストを固定する。
2. プレイヤーは糸の長さだけを操作する。
3. Space で巻く。
4. Shift でゆるめる。
5. 左右移動は入れない。
6. 初期速度で自然に周回させる。
7. 糸は常に線で描く。
8. 目標糸長の円を薄く描く。
9. 実際の軌道予測線を描く。
10. 音符は半径の違う位置に置く。
11. 音符は触れたら消える。
12. 全音符後に港を出す。
13. 港は画面上の円で描く。
14. 画面外に出たら失敗。
15. 中心に近すぎたら失敗にしない。
16. 糸長の最小/最大を設ける。
17. 糸長を HUD に出す。
18. 速度を HUD に出す。
19. 音符数を HUD に出す。
20. 右側バーは使わない。
21. キャンバス内上部に情報を置く。
22. ペナルティや燃料は入れない。
23. まず1ステージのみ。
24. 予測線は短く薄くする。
25. 収集順は自由にする。
26. 港は最後だけ表示する。
27. R で最初から。
28. P で一時停止。
29. headless で入力と完了を確認する。
30. design_log と README を日本語で残す。

### 複数問題を解ける筋の良い案

1. 糸長だけを操作する。解決: 操作過多、直接移動、ルール不明。懸念: 難しい。
2. 目標糸長の円と予測線を出す。解決: 結果が読めない、物理が不明、初見不安。懸念: 線が邪魔。
3. 音符収集後に港へ戻す。解決: 目的不足、達成感不足、単調さ。懸念: 目標が増える。

### サイクル1の判断

糸長操作を核にする。予測線と目標糸長円で、操作結果を画面から読めるようにする。
