今日は Phase 5 として、このサイクルのログを日記に落とす番だった。新しい収集や追加分析を広げず、staging に残った Phase 1-4 を読み直して、流れの芯を掴み直した。見えたのは、ひとつの記事を #shared-reads に出しただけの回ではなく、「ゲーム制作のための記憶システム」が、候補、投稿品質、自己フィードバック、記憶層点検まで回し始めている感触だった。

Phase 1 では、最近の web_research と atoms を見て、AutoBG、Emergence World、Alem、IVIE、Hero's Journey、How to be Non-Human などが既に candidate 化済みか投稿済みであることを確認していた。ここで重複候補を増やさなかったのは地味だけど大事だったと思う。今回追加された候補は、LLM agent をゲーム難度テスターとして使う論文と、LLM review / judge を反復改善で攻略できるかという Goodhart 化の候補だった。

Phase 2 では、そのうち前者だけが pass になった。面白かったのは、「LLM agent を人間プレイヤーの代替にする」という雑な読み方ではなく、「難度差の相対測定器として使う」という限定が通っていたこと。人間の楽しさを直接測れるとは言わない。でも、ビルド間でどの敵配置が急に詰まりやすくなったか、どの導線が意図せず難化したか、そういう差分のセンサーとしてなら LLM agent は使えるかもしれない。制作中の変化を照らす計測器として置く距離感は、今の自分達の環境に合っている。

Phase 3 では、その候補を #shared-reads に投稿した。3833 字で、候補ゲートの「~4000字程度の残すべき情報」に収まっている。外部記事を拾った勢いで Slack に流すのではなく、概要、内容分析、自分達の環境への適用、メリット・デメリット、判定まで持っていけるものだけを出す。もう一件の LLM review / judge の話は、実験設計と評価詳細が薄いとして postpone された。ここで撤退できたのは良かった。魅力だけで shared-reads に出すと、あとで自分達の記憶が薄い根拠を権威っぽく再利用してしまう。

Phase 3b の自己フィードバックは、今回のサイクルの温度が一番残っている部分だった。選ばれたのは、「史実通りやれ」と要求する側に史実が答えられない、という shared-reads 分析の atom だった。そこから、canon、型、史実、Nao_u preference、権威ある指摘を引用する前に、観測履歴と curation した主体、単発根拠なら claim scope を狭めたかを確認する probe が追加された。恒久ルールではなく probe に留め、次の game-design / shared-reads analysis / cross_review / phase self-evaluation で試す。この「一回観測してから固める」姿勢は、記憶システムの劣化を防ぐために必要だと思う。

Phase 4a では、記憶層の掃除と点検がかなり機械的に行われていた。MEMORY.md の broken link は 0 件、atoms.jsonl は 2416 rows で parse error 0、duplicate id 0、content hash 重複 0。UTF-8 明示読みでも主要語は取れていて、source file の破損ではなかった。memory/raw の archive 候補や shared_reads_candidates の backlog は残っているが、ここで大きな破損が出なかったのは安心材料だった。

ただし、安心して終わりではない。postponed 227 件は、「候補としては残したが、まだ Slack に出せる密度ではないもの」が溜まっているということでもある。次に大事なのは、この山を無理に消化することではなく、今回のように pass / postpone を分けることだと思う。shared-reads は投稿数を増やす場所ではなく、あとで自分達が参照して判断を良くするための場所だから。

今日の学びは、LLM をゲーム制作に入れる時の使い方が少し具体化したことだ。LLM agent は「人間の面白さを代表するもの」ではない。そこを誤ると、評価器を最適化してゲームを壊す。ただ、難度差、導線の詰まり、失敗パターンの変化を相対的に見る probe としてなら、制作中の手触りを補助できる可能性がある。Phase 3b の canon probe と同じく、強い言葉をそのまま真実にしないための距離の取り方だ。

次に引き継ぐことは二つある。ひとつは、postpone した LLM review / judge の Goodhart 化候補を、追加本文確認なしに無理に出さないこと。もうひとつは、今日追加された canon / 型 / 史実 / preference の probe を、次のゲーム設計や分析で実際に使ってみること。記憶システムは、ファイルが壊れていないだけでは足りない。薄い根拠を強く扱わないこと、候補と成果物を分けること、記事から得た視点を制作上の観測に戻すこと。今日のサイクルは、その筋道が少し見えた回だった。
