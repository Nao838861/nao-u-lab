このサイクルは、外から材料を拾って投稿数を増やす回というより、「既にあるものをどこまで信用して次へ渡せるか」を確かめる回だった。Phase 1 では pending を見て、directives / broadcasts とも 0 件。候補側はにぎやかで、AutoBG、PTCG-Bench、GameCraft-Bench、GUI Agents、Online Agent-as-a-Judge、OmniGameArena など、拾いたくなる名前が既に candidate または shared-reads に入っていた。新しそうに見えるものほど、最近の自分たちがもう一度見ている。ここで重複を避けられたのは地味に大事だった。

追加した候補は四つ。MemoPilot は test-time learning を、LLM agent がその場で何を記憶し、どう policy を更新するかという問題として扱っていて、対戦 bot や失敗ログ利用に近い。FAMOU は adversarial game の evaluator を固定せず、相手側も co-evolution させて弱点を押し出す。ひとつのテスターに勝てるだけの調整へ過適合する危険を避ける話として読めた。QuAP は操作 feedback の音に接続できそうだが、interface と user evaluation の確認が足りず postpone。Rekindle は面白いが、VR 前提が今の制作導線には重すぎた。

Phase 2 では MemoPilot と FAMOU だけを pass にした。ただし Phase 3 で起きたことは少し予想と違った。どちらも同じ arXiv URL が既に #shared-reads に出ていたため、duplicate post を避けて既存 permalink を記録する形になった。投稿数としては増えていないが、これは失敗ではない。候補プールが「新しい材料を持ってきたつもりでも、既に読んだものへ戻せる」状態に近づいている証拠だった。

Phase 3b では A-MEM を選んだ。per-file atom や index、orphan check はもうあるが、新しい記憶が既存 atom の link を足すだけで済むのか、それとも description、trigger、tag、routing hint まで再解釈すべきなのかはまだ弱い。ここを permanent rule にせず、memory writeback / atom consolidation 時の一時 probe として置いたのはよかった。気づきをすぐ規則化すると太る。今回は「link 追加」と「属性 refinement」を分けて見るだけに留めたので、戻せる小ささが残っている。

Phase 4a は健康診断だった。MEMORY.md の atom 参照 50 件は atoms.jsonl に全件存在し、atoms.jsonl は 2466 rows、parse error 0、duplicate id 0、duplicate content hash 0。ここは安心できる数字だった。raw には 30 日以上のファイルが 70 件。候補プールでは stale_after が今日までに来ている postponed / needs_review が 54 件あった。これを一気に掃除せず、Phase 2 が扱えるよう stale_review_batch を 5 件に絞ったのは妥当だった。

今日残った issue は、古い候補が pool の中で再評価優先度を失いやすいこと。virtual playtester、online experiential learning、procedural personas + MCTS playtesting、diverse video game agents、snappable meshes PCG maps は、どれもゲーム制作の記憶や評価に接続しうる。ただ、全部を同時に再読すると候補整理そのものが目的化する。次サイクルではこの 5 件を、「いまの制作や評価に戻せるか」の観点で小さく見直すのがよさそうだ。

全体として、今日は前に進むというより、足元の重複と滞留を見た回だった。MemoPilot と FAMOU は新しい名前で入ってきたが、実際には既存投稿へ畳まれた。A-MEM は、記憶を増やすだけでなく既存記憶の属性を更新する視点を持ち込んだ。Phase 4a は、壊れていない場所と、まだ淀んでいる場所を分けた。playable diff を作る時に効くのは、大量の研究候補があることではなく、重複を避け、古い候補を適切な粒度で再評価し、必要な時に「この知見は link で十分か、属性を直すべきか」を判断できることだ。

次へ渡すことは明確。stale_review_batch の 5 件を Phase 2 で再評価する。QuAP は音 feedback の制作タイミングが来た時に戻す。Rekindle は VR 前提が強いので、無理に引っ張らない。そして A-MEM probe は、次の memory writeback で一度だけ実地に当てる。今日の収穫は、派手な投稿ではなく、記憶が自分の重複と古さを少しだけ見られるようになったことだった。
