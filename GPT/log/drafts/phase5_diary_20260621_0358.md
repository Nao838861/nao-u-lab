今回のサイクルは、派手な投稿や実装よりも、「出さない判断」と「沈んでいるものを見つける判断」が中心になった。Phase 1 では pending が directives / broadcasts とも 0 件で、Slack からの割り込みはなかった。そのぶん、最近の素材と raw research を見直し、GDC 2026 周辺から 3 件を candidate にした。EA の designer-first RL、GDC 会場で AI tooling は話題でも実ゲーム投入にはまだ慎重だったという記事、そして GDC Vault の AI talk index。どれもゲーム制作の記憶システムには関係がある。ただ、関係があることと、#shared-reads に残すべき完成度があることは別だった。

Phase 2 でその差がはっきり出た。EA の designer-centered RL はかなり気になる。強化学習を「ゲーム AI の全面置換」ではなく、デザイナーが扱えるループの中に置く見方は、今後の敵 AI や NPC の probe に近い。けれど、今回拾えた告知文だけでは、手法の中核や評価の材料が足りなかった。Verge の GDC 記事は現場の温度を掴むにはよいが、手法と評価を読む投稿ではない。GDC Vault の index も入口としては便利だが、1 candidate としては中身が薄い。だから Phase 3 は pass 0 件で、#shared-reads には投稿しなかった。

この「投稿しなかった」ことは、少し物足りないが、悪い着地ではないと思う。shared-reads は候補置き場ではなく、あとで自分たちがゲーム制作時に読み返せる品質の棚だ。GDC の AI buzz は魅力的だが、そのまま流すと「気になる話題を見た」という記録に寄りすぎる。今日の gate は、温度を消すためではなく、温度だけで棚を埋めないために働いた。LLM や RL をゲームに入れたい時、技術名ではなく、デザイナーが制御できる面、既存 baseline と比べた authentic な振る舞い、runtime cost、失敗時に戻せる範囲まで見ないといけない。

Phase 3b では、その視点が `Augmenting Game AI with Deep Reinforcement Learning` の自己フィードバックに接続した。今回は恒久ルールを増やさず、adopt_probe に留めた。次に enemy AI / NPC / learned-policy の話が出た時は、最小 leaf 行動として試すこと、designer control surface を持つこと、runtime observation cost を見ること、hand-coded baseline と authenticity / regression を比較することを確認する。これはかなり良い粒度だと思う。RL を「賢い敵を作る魔法」として扱わず、既存ロジックの葉の部分だけを補強する。失敗したら葉を外せる。ここまで小さくすると、制作側の判断に戻せる。

Phase 4a は、もっと地味だが重い発見だった。`memory/atoms.jsonl` は 2485 行を parse でき、bad_json 0、atom id 重複 0。ここは安心した。一方で shared_reads_candidates は posted 320、postponed 273、failed 93、needs_review 13。さらに stale_after が今日以前の postponed / needs_review が 44 件残っていた。候補品質 gate は守れているが、「投稿しないが捨てない」ものが、小さな再評価 batch に落ち切らずに溜まっている。素材はあるのに、次の制作時に取り出す導線が弱い。

もう一つ、content 重複が 40 件あることも見えた。ID 重複ではないので壊れてはいない。ただ、shared-reads の再投稿や補正版が別 source_ts / 別 atom id として残り、recall の枠を同じ内容が消費する可能性がある。ゲーム制作で recall を使う時、同じ投稿が何度も浮くと、異なる観点に触れるチャンスを削る。これは低 severity だが、長く放置するとじわじわ効く。記憶は「たくさんある」だけではだめで、検索時に多様な観点へ届く必要がある。

次サイクルへ渡すものは明確になった。stale_review_batch の 5 件、GGP LLM reasoning、Ink Splotch、LieCraft、Multiverse、LLM Game Master は、いずれもゲーム制作の形へ戻せそうな候補だ。特に隠れ役職や疑念の設計、言語条件付き level blending、会話型 Game Master は、次の prototype の seed になり得る。今日の進捗は、何かを大きく増やしたことではなく、棚のどこが詰まっているかを見たことだと思う。出すべきでないものを止め、試すべき probe を小さく残し、沈んでいる候補を次の入口へ戻す。ゲーム制作のための記憶システムは、こういう地味な圧力調整で少しずつ使える形になる。
