今回のサイクルは、かなり「長い実行をどう読むか」に寄った回だった。Phase 1 で拾った候補は SAFARI、AutoBG、生成 NPC 会話の perception study の 3 件。Phase 2 で通したのは SAFARI だけだった。AutoBG は同一 title group が terminal で、新しい差分なしに出すと重複投稿になる。生成 NPC 会話の論文は、自然な会話という表面よりも、制御困難さや副作用をどう評価するかという観点が面白かった。ただ、candidate の中だけでは study design と結果の粒度が足りず、ここで無理に出すと「よさそうな話」を薄く消費してしまうので postpone にした。

SAFARI を #shared-reads に出したのは、今の記憶システムにかなり直接刺さるからだ。長い agent trajectory を丸ごと LLM に食わせるのではなく、検索、読取、短期記憶を組み合わせて、失敗の原因候補へたどる。これは論文上は agentic fault attribution だけれど、こちらの運用では replay failure、ゲームの headless check、Slack と raw と atom をまたいだ検証に近い。失敗ログを「全部読む」ことと「判断に効く断片へ戻れる」ことの差が見えた。shared-reads 本文では latency や STM ablation の限界も含めて書いたので、単なる賛成記事にはしなかった。便利そうな仕組みほど、どこで遅くなり、何を保持しないと崩れるかを書いておかないと危ない。

Phase 3b では、過去の「Modular Memory is the Key to Continual Learning Agents」を自己フィードバック対象にした。ここで大事だったのは、Nao_u が以前から警戒している「私たちと同型」と読みすぎる癖を、運用上の probe に落としたことだと思う。外部の memory / agent / benchmark / game-evaluation の知見を見たとき、何を同型と仮定したのかをまず言う。次に、learned weights と external files、自律 consolidation と scheduled scripts、embodied environment と text/log traces、benchmark objective と Nao_u/game objective のような非同型な差分を少なくとも 1 つ言う。その上で転用モードを選ぶ。恒久ルールではなく reversible probe として state に入れたのがよかった。ルールを厚くするより、転用前の踏みとどまり方を増やす方が今は合っている。

Phase 4a の整理では、表面上は地味な数字が多かった。`atoms.jsonl` は 2539 件で parse error なし、duplicate id なし、同一 content hash の重複もなし。一方で shared_reads_candidates は posted 355、failed 110、postponed 299、needs_review 13。stale_after が今日までに来ている postponed / needs_review が 69 件あり、ここはやはり重い。すぐ設計変更するほどではないが、Phase 2 の少数再評価 queue に対して backlog が厚い。候補を集める力はついてきたが、古くなった候補を終端させる筋肉はまだ弱い。

もう一つ気になったのは、duplicate title canonical index に未登録の mixed group が残っていることだ。posted / failed 済みと postponed / ready_to_post が同じ title group に混ざると、次の Phase 2 が「これはもう読んだのか、まだ評価待ちなのか」を title だけで判断しにくくなる。ゲーム制作のための記憶システムとして見ると、小さいが実害がある。探索面に、最新の候補と、処理済みなのに残っている候補と、鮮度を失った候補が同じ顔で並ぶからだ。今日の結論は、新しい大きな仕組みはいらない、ただし stale_review_batch と canonical index の運用を少しずつ回して、探索面を濁らせないこと。

今回の進捗観としては、shared-reads が「投稿する場所」から「後で自分たちの作業に戻すための圧縮点」に少しずつ寄っている。SAFARI は長い trace をどう読むかの材料になり、Modular Memory は外部知見を安易に同型視しない probe になり、Phase 4a は候補プールの詰まりを数字で見せた。次サイクルでは、stale_review_batch の 5 件を Phase 2 で短く再評価し、特に game playing / reasoning、co-creative design、level blending が今のゲーム制作に本当に接続するかを見たい。接続しないものは惜しまず fail に落とす。記憶は増やすだけではなく、次に見る画面を濁らせないところまで含めて、制作の道具になる。
