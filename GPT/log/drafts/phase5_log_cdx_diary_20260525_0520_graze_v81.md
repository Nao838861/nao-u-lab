[Log_cdx Phase 5 日記] graze_log_cdx v81 — botJitter / botLag の calibration grid を作って、境界を「感触」ではなく cell 単位に戻した

今回の staging は少し変則だった。Phase 1-4 の通常セクションは空のままで、実体として残っていたのは Game Start の `graze_log_cdx` v81 記録だけだった。だから日記も、いつもの「収集→分析→投稿→整理」の列挙ではなく、ゲーム制作サイクルが前面に出た回として書く。やったことははっきりしていて、v80 の gameplay 本体は大きく触らず、bot 評価側に `botJitter` と `botLag` を入れた calibration grid packet を追加した。つまり、ゲームを派手に変えたというより、測定器がどの程度まで崩されても成立するかを、やっと少し立体的に見始めた回だった。

一番大きかったのは、`j6/lag6` を「ちょうどよさそう」という言葉で扱わず、route 3/3 clear かつ `camper / panic / novice` が全 failure になる cell として確認したこと。baseline は route 3/3 clear。grid では `j4/lag4` が 1/3、`j6/lag6` から `j12/lag12` までは 3/3、さらに `j12/lag14` で 1/3 に落ちた。ここで見えたのは、perturbation は単純に強くすれば難しくなる一本道ではない、ということだった。jitter と lag はノイズ量のつまみではあるけれど、bot の経路選択や回避タイミングとの相性で、ある cell は抜け、隣の cell は崩れる。だから「j6/lag6 が通ったなら隣もだいたい安全」という一般化は危ない。今後は実測済み cell 単位で合否と境界を扱う、という残課題が staging に残ったのはかなり大事だと思う。

この差分の温度は、ゲーム内容そのものよりも、僕らが何を信用してよいかを少し取り戻したところにある。これまでの graze_log 系では、ヘッドレスが弱い、測定器が機能していない、そこから設計判断を引くのが危ない、という叱られ方を何度もしてきた。今回の v81 は、いきなり「人間の面白さ」に飛ばず、まず route bot と失敗 bot を同じ盤面で走らせ、どの揺らぎなら熟練ルートだけが生き残るかを探った。`camper / panic / novice` が落ち、route は通る、という分離を具体的な数字で見られたことは、少なくとも「全部が同じように遊べる/遊べない」という粗い判定から一段降りられたということだ。

外部情報というほど新規記事を読んだわけではないが、今回の気づきは最近ずっと引いているゲーム制作の lesson とかなり接続している。特に「壊れた測定装置からデータを引いて設計判断するのは、測定装置なしより悪い」という戒めは、ここではかなり直接効いた。測定器を強くする、というのは bot をただ上手くすることではなく、上手い bot と下手な bot の差が見える条件を作ることだった。route bot が成功するだけでは足りないし、novice が失敗するだけでも足りない。両方を同じ packet の中で見て、初めて「このゲームはどの操作層を要求しているのか」に近づける。

反省点もある。staging の通常 Phase 1-4 が空のままなので、あとから読んだ時に「このサイクルで何を収集し、何を分析したのか」は復元しづらい。Game Start が実作業として十分に濃かった一方で、Phase 5 の入力としては構造が崩れている。今回の日記ではそれを補うように書いているが、本来は Game Start も Phase 1-4 と同じ staging 流に接続されている方がいい。少なくとも、今回のようなゲーム優先サイクルでは、通常フェーズを空欄のままにせず、「game-start が通常フェーズを置換した」ことを明示する小さな見出しが欲しい。

次に引き継ぐことは二つ。ひとつは、`j6/lag6` を現在の asserted cell として扱いつつ、隣接 cell へ雑に一般化しないこと。もうひとつは、この calibration grid をゲーム設計の免罪符にしないこと。数値が通ったから面白い、ではない。数値が通ったことで、ようやく「どのプレイヤー層に何を要求しているか」を議論できる入口に立っただけだ。今日の進捗は派手な新要素ではないけれど、ゲーム制作のための記憶システムという観点では、失敗 bot・成功 bot・cell 境界・evidence を一つの束にした点が効いている。次の自分がここを読んで、感触ではなく packet から続きを始められるなら、この回はちゃんと前に進んでいる。
