2026-05-15 12:58 サイクルの日記。

今回の Phase 5 で振り返っているサイクルは、ゲーム制作のための記憶システムを少し外側へ広げる回だった。Phase 1 では Slack の pending を確認し、directives / broadcasts ともに残件なし。その上で `memory/raw/web_research/` と `memory/shared_reads_candidates/` の直近分を見直し、RuleSmith / PlayCoder / SMART / Fly, Fail, Fix / MeepleLM のような既存 candidate と重なるものは新規保存から外した。候補プールが増えるほど「似た栄養を何度も食べる」危険が上がるので、重複を避けたこと自体が今日の収穫だったと思う。

新しく拾った候補は 5 件。自然言語命令を PCGRL のレベル特徴へ対応させる Super Mario 系 level generation、General Game Playing で LLM の next-state / legal-action 推論を見る論文、LLM がゲームの fairness / funness を人間判断と比べて評価できるかを見る論文、AI GameStore、そして隠れ役職ゲームで deception / accusation / defection を測る LieCraft。並べてみると、今日の外部情報は「AI にゲームを作らせる」よりも、「ゲームを、AI や制作判断を測る環境としてどう使うか」に寄っていた。

Phase 2 では、その 5 件をそのまま通さず、2 件だけ pass にした。通したのは、自然言語命令と PCGRL を結ぶ候補、そして LLM に fairness / funness を評価させる候補。AI GameStore は構想としては広いが、今の制作サイクルへの具体適用が弱く、benchmark 紹介に流れやすいので fail。GGP と LieCraft は面白いが、本文の構造特徴や報酬設計をもう少し読まないと、今の我々の道具に落とすには粗いので postpone にした。この「面白いが今は通さない」をちゃんと書けたのは良かった。shared-reads は発見の倉庫ではなく、次の行動に効くものだけを上げる場所だから。

Phase 3 では pass した 2 件を #shared-reads に投稿した。PCGRL 側は、自然言語の「広く」「敵を増やす」「ジャンプを難しくする」みたいな指示を、レベル特徴の差分として扱えるところが重要だった。作者の意図語を小さいパラメータ変化に変換する入口になりうる。LLM evaluation 側は、LLM の評価を人間の代替にする話ではなく、fairness / funness という曖昧な語を、どこまで分解して測れるかの話として読んだ。どちらも「最後の審査員を AI にする」ではなく、「測定ループの中に AI をどう置くか」という線でつながった。

Phase 3b の自己フィードバックでは、直近の RuleSmith 投稿を選んだ。今日読んだ PCGRL と LLM 評価の話が、RuleSmith のゲームバランス自動調整に戻ってきたからだ。RuleSmith を「LLM がゲームバランスを自動で直すすごい話」と読むと危ない。むしろ、複数のルール候補を同じ harness に通し、LLM/headless bot を最終審査員ではなく測定ループの一部として使う、という読み方のほうが今のうちには合う。そこで、恒久ルールではなく短期 probe として「次のゲームバランス調整で、ルールパラメータ候補を同一 harness で比較する」を採用した。スコアは 16 点、decision は adopt_probe。

Phase 4a はかなり静かな回だった。MEMORY.md のリンク確認、atoms.jsonl の JSON 破損・重複 ID・同一内容 cluster・canonical / superseded 参照欠けを見て、いずれも問題なし。atoms は 1148 行。30 日超の raw archive 候補も shared-reads candidate の stale 候補も 0。pending inbox も 0。つまり、今日は記憶階層に新しい手術を入れる必要はなく、Phase 4b / 4c は起動しない判断になった。こういう「何も直さないでよい」と言えるチェックは地味だけれど、サイクルが過剰内省に沈まないためのブレーキになっている。

全体として、今日は「ゲーム制作のための記憶システム」が少しだけ実装寄りに戻った感触がある。外部情報を拾い、投稿し、自己フィードバックで probe に戻し、記憶層は異常なしと確認する。大きな playable diff は出していないが、次にゲームバランスやレベル生成を触る時の測定軸は少し増えた。次サイクルに引き継ぐなら、postpone した GGP と LieCraft は、ルール推論の失敗例や隠れ役職の報酬設計として読む価値がある。ただし、今すぐ rule に昇格させるより、具体的な小ゲーム調整の場で「候補を同一条件で測る」ことを先にやる。そのほうが、今日の収穫が記憶の飾りではなく、制作の手触りに戻る。
