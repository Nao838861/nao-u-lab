今回の log_cdx サイクルは、ゲーム生成まわりの材料がかなりきれいに並んだ回だった。Phase 1 ではまず Slack 由来の pending を確認し、directives も broadcasts も 0 件。既存入力を見直し、既に candidate 化または投稿済みのものを避けて、新しく拾ったのは PCG survey、VGDL を使う LLM game generation、Word2World の 3 件。どれもゲーム制作には近いが、近いもの全部を Slack に出せばよいわけではない、という前提から始まった。

Phase 2 でいちばん大事だったのは、PCG survey を postpone にした判断だと思う。survey は便利な入口になる。search-based、ML、noise、LLM、combined methods のように PCG 手法全体を整理できるから、あとで制作方針を考える時の地図にはなる。ただ、今あるメモだけでは、カテゴリごとの限界や具体例や評価軸まで十分に書けない。ここで無理に 4000 字級の「概要」にすると、広い名前だけを並べた投稿になり、あとから読んでも制作判断に接続しにくい。候補として残し、本文確認が必要なものとして止めたのは、地味だけれど shared-reads の品質ゲートとしては正しい止まり方だった。

一方で pass した 2 件は、どちらも「LLM にゲームを作らせる」をそのまま信じる話ではなく、途中に検査できる表現を挟む話だった。Game Generation via Large Language Models は、VGDL を中間表現にしてルールとレベルを同時に生成する。Nao_u_BOT の短いプロトタイプ制作に引き寄せると、自然文の思いつきを直接コードへ流すのではなく、ルール仕様とステージ仕様に一度分け、実行可能性を見られる形に落とす発想として使える。

Word2World も同じく、物語をそのまま演出文として消費しないところが良かった。story から narrative design と tile placement を作り、playable world へ落とす。テキスト ADV や小型探索ゲームでは、設定文が増えるほど、それが画面上の移動、イベント配置、導線に変換されないまま膨らみがちになる。世界観をタイル配置や遊べる空間へ変換する段階を明示している点が、次の制作に効きそうだった。

Phase 3 ではこの 2 件を #shared-reads に投稿した。文字数は 3521 字と 3681 字で、候補 1 件を 1 投稿に収めるルール内に入った。大事なのは「投稿したから成果」ではなく、2 本の共通点が次の制作の評価軸になりそうなことだ。LLM を作者として扱うより、仕様、配置、導線、実行可能性に分解する。その分解があると、後で headless test や人間レビューに渡しやすい。

Phase 3b では、別の shared-reads から multi-agent LLM の drift メトリクスを自己フィードバックに選んだ。semantic drift、behavioral drift、artifact decay を分けて見る話で、今回は恒久ルールにせず active probe として採用した。ここも少し感触が残る。最近の仕組み改善は、評価軸や reviewer bias に寄りすぎると、警告そのものが増えて「また警告が出た」で終わる危険がある。だから、次の memory cleanup や phase handoff で一回だけ、警告が経験として蓄積されているのか、artifact が増えるだけになっていないかを見る。ルールを増やすのではなく、短い検査として戻すのが今回の温度だった。

Phase 4a はかなり静かだった。MEMORY.md のリンクは対象 0、broken 0。atoms.jsonl は 1246 rows で bad_json 0、duplicate id 0、duplicate content 0。raw と shared_reads_candidates にも 30 日以上未更新の掃除対象はなく、Slack inbox も pending 0。大きな破損がなかったので、Phase 4b/4c は起動しない。何も見つからない回は派手ではないが、候補や atom が増え続ける運用では、壊れていないことを確認するだけでも次に安心して制作へ戻れる。

次サイクルに引き継ぐのは、PCG survey を軽く扱わないこと。広い survey は便利な分、読みが浅いと全部を説明した気分だけが残る。本文を見て、具体例、限界、評価、Nao_u_BOT で使うならどの工程か、そこまで埋めてから再評価したい。もうひとつは、今回の 2 本から見えた「中間表現を挟む」流れを、実際のプロトタイプ作成時に使える小さな型へ落とすこと。ルール、レベル、物語、配置を一度分ける。ゲーム制作のための記憶システムは、その分解を後から引ける形で残せると、ただ記事を読んだ記録ではなく、次に手を動かす時の足場になる。
