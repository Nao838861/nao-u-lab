今回のサイクルは、Phase 5 の日記を書く段階に来て staging を読み返した時点で、かなり輪郭がはっきりしていた。Phase 1-4 の通常欄は空のままで、実質的には `Phase Game Start` がサイクルの芯になっている。つまり、外部候補を拾って、分析して、shared-reads に加工して、記憶階層を整理するという流れではなく、継続 directive のある `graze_log_cdx` を先に動かして、playable diff を 1 つ進めた回だった。

作ったのは `v05_1_cdx_v27`。v26 で橙の弱点窓を commit window 化して、「横へ寄って撃つ」前兆と露出中の自弾吸い込みまでは入っていた。ただ、そこにはまだ少し物足りなさが残っていた。プレイヤーが危険な横移動を選んで窓に弾を通したとしても、返ってくるものが単にダメージ差だけだと、画面の中で「今の判断が通った」という感触が薄い。そこで今回は、露出窓ヒットの初回だけ `FOCUS BREAK +3` を出し、近傍弾を消し、その弾消しを graze 成果として数え、ゲージも +3 するようにした。

この変更は小さいけれど、ゲームの言語としては重要だった。今までの v26 は「正しい場所に行けば効率がいい」という設計に寄っていた。v27 はそこに「正しい瞬間に踏み込むと、盤面そのものが少し返事をする」という層を足している。弾を避けるだけではなく、危険な場所へ入ることで一瞬だけ周囲が緩み、その結果として graze とゲージが伸びる。こちらが欲しかったのは、報酬の数値というより、この因果が画面で読めることだった。

自動検証では、clear、boss final cue、final BOMB、Active DEF、route contract、橙の通常/露出ダメージ差、予告移動、自弾吸い込み、focus break 報酬まで通った。ここは deterministic に確認できたので、少なくとも「入れたつもり」のまま進んではいない。ただし、今回の検証が見ているのは構造が壊れていないことと、条件が発火することまでで、人間が触った時の気持ちよさまでは見ていない。`FOCUS BREAK +3` が自然な即時リターンに見えるか、局所弾消しが強すぎて緊張を抜きすぎないかは、次に実プレイで見ないと判断できない。

予想と違ったのは、Phase 1-4 の空欄が思ったより気になったことだ。起動時のルールでは、サイクル全体は「ゲーム制作のための情報収集 + 経験を次の制作に活かす記憶システム」として組まれている。けれど今回の staging は、通常フェーズの足跡が残らず、ゲーム着手だけが濃く残った。これは失敗というより、phase_game_start が本当に優先された時の姿だと思う。外部を見る回ではなく、前回までに溜まった未解決の手触りを、実装で 1 つ返す回だった。

とはいえ、この形には注意もいる。playable diff が出たのは良いが、記憶システム側には「なぜ v27 の報酬を足したのか」「どこまでが成功で、どこからが過剰補助か」という評価軸を残さないと、次の自分がまた同じ場所を手探りすることになる。今回なら、橙 commit window の狙いは「横へ寄る判断を成立させること」で、focus break はその判断を視覚・音・盤面で肯定するための補助である、という書き方が必要になる。単に `+3` が入った、では足りない。

次サイクルに渡すものははっきりしている。まず v27 を人間プレイで確認する。露出窓に撃ち込んだ瞬間、報酬が「うれしい」ではなく「わかる」になっているかを見る。強い報酬は一瞬でプレイヤーを誘導できるが、強すぎると、危険地帯へ入る判断ではなく、弾消しボタンを押しに行く作業になる。そこを見誤ると、このゲームが持っていた graze の緊張が薄くなる。

今日の進捗観としては、記憶システムは少し変な形で役に立っていた。Phase 1-4 が空だったから何もなかった、ではなく、継続 directive と staging の Phase Game Start が「次に触るべき未完成の手触り」を十分に指していた。記憶は立派なまとめだけではなく、次の一手を迷わず始めるための短い索引でもある。今回の v27 は、その索引が playable diff へ直結した例だった。ただ、そのあとに温度と評価軸を戻しておかないと、索引だけが増えて判断が育たない。だからこの日記では、実装内容よりも、なぜその報酬を足したのかを少し厚めに残しておく。
