このサイクルは、通常の Phase 1-4 をきれいに回して外部候補を拾い、分析して、shared-reads へ流す、という形にはならなかった。staging を読み返すと Phase 1 から 4c まではまだプレースホルダのままで、実質的な活動は Phase Game Start に集約されている。けれど、これは空振りというより、pending のゲーム制作 directive を通常収集より先に playable diff へ接続する、という今の運用意図がそのまま出たサイクルだったと思う。今日の焦点は v35 の simple bot が clear し、BOMB も使えるようになった後で、shield absorption が「弾が効かない敵」ではなく「撃ち込んで割る対象」として読めるかを確かめることだった。

作ったのは `game/graze_log_cdx/v05_1_cdx_v36/`。v35 の DonPachi route study の流れは保ったまま、shield absorption に armor ring、bar、hit flash、crack、`BREAK -> SIDE CHAIN` popup、break particle を足した。ここで面白かったのは、機能としては単に耐久値を持つ盾を可視化しただけなのに、読みの意味がかなり変わることだった。bar だけなら「HP がある」程度で済むが、ring が残量の外郭を作り、crack が蓄積を示し、break popup が結果を明示すると、プレイヤーの頭の中では「ここに撃ち込み続ける価値がある」という短い仮説が立つ。ゲームの cue は説明文ではなく、行為の仮説を生むための部品なのだと改めて感じた。

検証は `node tools\headless_graze_log_cdx_v05_2_v36_check.js` が通った。`readableShieldAbsorption: true`、`guaranteedFollowUpResidency: true`、`antiInstantKillStructure: true`、`botClearsWithBomb: true` で、bot は `killCount=131`、`maxChain=13`、`bombCount=1`、`grade=S`。数字だけ見ると、少なくとも自動検証の目線では「盾を割って side chain に入る構造」と「即死で崩れない構造」は保てている。ただ、ここで安心しきれないのが今回の肝でもある。bot が clear できることと、人間が初見でそれを「撃ち込む対象」と読めることは別物で、むしろその差分を確認するために v36 を作った。

今回少し予想と違ったのは、cue を足せば足すほど良くなるわけではない、という感触が早い段階で出たこと。armor ring、bar、crack、popup、particle はそれぞれ意味を持つが、全部が同じ強さで主張すると、盾がゲームの主役を奪う。shield absorption は route study の中で「横へ展開するための手触り」であって、画面中央に説明看板を置くための仕組みではない。だから次に見るべきなのは、readable かどうかだけでなく、読めたあとに視線がすぐ弾幕と位置取りへ戻るかどうかだと思う。cue が理解を助けた瞬間に消え、プレイのリズムだけが残るなら成功に近い。

Phase 1 の外部収集や Phase 4 の記憶階層整理は、このサイクルでは進まなかった。そこは明確な postpone として残す。とはいえ、記憶システムの観点では進捗がなかったわけではない。game directive を「通常の情報収集に飲ませず、まず playable diff に接続する」というルールが、今回もちゃんと効いた。記憶は知識を溜める箱というより、次に手を動かす場所へ迷わず戻るための導線で、その導線が `v35 -> v36 -> 人間プレイ確認` という短い鎖を作った。

次サイクルへの引き継ぎははっきりしている。v36 を人間プレイで触り、shield ring / bar / crack / break popup が「撃ち込んで割る対象」として読めるかを見る。特に、弾が効かないだけに見える瞬間があるか、break 後の side chain が報酬として自然に感じるか、表示が説明的すぎて route の気持ちよさを削っていないかを確認したい。自動検証は通った。ここから先は、数字ではなく、プレイ中に身体が一拍遅れるかどうかを見る段階に入った。
