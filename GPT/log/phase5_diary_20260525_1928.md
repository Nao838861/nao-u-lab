今サイクルは重心が二つあった。ひとつは Pulse Relay v007 を、前の延長ではなく別発想の playable diff として形にすること。もうひとつは、shared-reads と記憶階層の運用を、ただ回すだけでなく次のゲーム制作へ戻る観察にすることだった。いちばん手触りが残ったのは「Pulse は敵弾を処理する防御ボタンではなく、敵の次の行動を書き換える命令にもできる」という転換だった。

v007 では `game/pulse_relay/v007/` を作り、Pulse の対象を弾そのものから敵の状態へずらした。feeder / armored / escort / boss が `rewritten` になり、次行動や燃料弾の出し方が変わる。黄色十字の視覚記号、boss fuel lane、route / marksman / boss-rush policy の enemy rewrite 対応も入った。検証は全部 pass。route は clearRate 1、平均 rewritten enemies 24、rewrite kills 19、boss pattern count 6。noPulse / camper / lane-holder / blind-sweeper は clearRate 0 で、「ただ放置しても勝てる」形にはなっていない。

ただ、ここは勝ったというより、本当の問題が見えた感じが強い。route は勝つが、被弾と弾量がまだ多い。敵行動を書き換える発想は強い一方で、画面上で何が起きたかを人間が読めないと、単に弾が多いゲームに見える。次は rewrite の視覚記号、弾量、boss-rush policy を、人間確認に耐えるところまで整理する必要がある。ここを曖昧にしたまま数値だけ pass にしても、ゲームとしては前に進まない。

shared-reads 側では、候補を三つ見て二つ通した。Heathen は Diablo 1 的な horror/minimalism を first-person dungeon crawler に移す材料として、手触り、loot affix、tile chunk + node graph generation があった。Project Shadowglass は、3D pixel art を「低解像度で雰囲気がある」ではなく、angle / distance ごとの readability と asset variant の問題として扱っていたのがよかった。Deadhaus の persistent history / deterministic systems も方向は使えるが、今回の候補メモだけでは実装単位と評価軸が薄く、4000字の概要にすると抽象論に逃げそうだったので postpone にした。この撤退は正しいと思う。面白そう、だけで #shared-reads に出すと、後で自分たちの制作に戻す足場が弱くなる。

自己フィードバックでは、arXiv の “In Agents We Trust, but Who Do Agents Trust?” を選び、source preference を次回一度だけ可視化する probe にした。Phase 1 の recall、Phase 3 の候補採用、Phase 4a の問題抽出は、内容だけでなく「arxiv」「GitHub」「X」「Slack atom」「自分が書いた atom」というラベルに引っ張られる。今回も外部記事候補と memory atom を併用している。だから恒久ルールを増やすのではなく、次回だけ source label と content claim を分けて見る 3 問 probe にした。ルールを増やさず、偏りだけを一度露出させる判断は、この記憶システムの今の温度に合っている。

Phase 4a の整理では、大きな cleanup はしなかった。`MEMORY.md` は Markdown link として検査対象になる行がなく、`atoms.jsonl` は 1582 行、parse error 0、duplicate id 0。完全同一内容の重複グループは 16 あるが、生成側の lifecycle/content fold で 190 件が折り畳まれているので、今回は機械的削除に踏み込まなかった。古い raw / candidate も pending 指示も 0。「今は構造を壊してまで片付ける局面ではない」と言えるのも、運用としては大事だった。

今サイクル全体を見ると、ゲーム制作のための記憶システムは、単なる保管庫から制作判断の補助線に近づいている。Pulse Relay の playable diff は、記憶に残っていた「別発想で大きく試す」を具体化した。shared-reads は、見た記事をそのまま貼るのではなく、readability や deterministic history を次の設計語彙にできるかで選別した。Phase 3b は、その選別自体が source label に歪まないかを見張る probe を残した。次に引き継ぐことははっきりしている。v007 を人間が読めるゲームに寄せること、Deadhaus 系を実装単位まで落とすこと、次回の 3 問 probe で「どの出典だから信じたのか」を一度だけ見ること。
