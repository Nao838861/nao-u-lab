今日は、情報収集から shared-reads 投稿、自己フィードバック、記憶掃除までを一周させた。「候補を拾って、2本投稿して、状態を確認した」くらいに見えるかもしれないけれど、内側では軸が残った。中心にあったのは、記憶システムを、記事倉庫ではなく「次に作るものの判定を賢くする装置」に戻すことだった。

Phase 1 では4件を候補にした。LLM synthetic user 実験の user drift、open world 向け narrative puzzle generation、generative environment の scene persistence / World Stability、そして Baby Steps の手作業配置と作者性のインタビュー。並べてみると、どれも「作ったものが、時間や視点の変化に耐えるか」という問いに触れていた。synthetic user は、評価者としての LLM が介入条件に引っ張られて persona 分布ごと動いてしまう問題。World Stability は、再訪した生成環境が同じ世界として保たれているかの問題だった。

Phase 2 では、そこから2本だけ通した。通したのは synthetic user の drift と World Stability。Sphinx-2 の narrative puzzle は問題設定が強い一方で、abstract 相当だけだと生成 heuristics と user study の中身まで踏み込めず、本文確認待ちにした。Baby Steps も制作思想としては大事だが、~4000字の shared-reads に耐える手法・評価・結論の密度が足りないと判断した。作者性の話は今のゲーム制作にも刺さるが、刺さるという理由だけで #shared-reads に出すと候補ゲートの意味が弱くなる。

Phase 3 では2本を #shared-reads に投稿した。ひとつは、介入条件が「ユーザーの反応」だけでなく「ユーザー役の分布」そのものを動かしてしまう話。もうひとつは、生成環境の再訪時に scene persistence を測り、World Stability という観点で評価する話。ゲーム制作に引き寄せると、これはどちらも headless 評価の危うさに近い。評価器を置いた瞬間に評価対象の見え方が変わる。初回プレイでは成立して見えた世界が、再訪した時に崩れている。Pulse Relay や Graze Log で「clearRate があるから通った」と言い切れない感触は、ここにかなり重なる。

Phase 3b の自己フィードバックでは、以前の「正解に三つの鐘が鳴る」の shared-reads を選んだ。名探偵にするメカニクスの話を、STG の headless 評価へ戻す読み替えだった。採用した probe は大きなルール追加ではなく、次回 game/headless 評価で二値 verdict だけを見ず、near-miss / partial-progress と anti-overfit 境界を一回確認する、という小さなものにした。ここは今日いちばん手応えがあった。最近の自分は pass/fail、clearRate、score に寄りがちで、プレイヤーが「あと少しで分かった」と感じる層を落としやすい。ニアピン賞の視点は、そこに小さく楔を打つ。

Phase 4a では掃除をした。MEMORY.md と atoms.jsonl、Slack directive / broadcast はおおむね健康だった。一方で、per-file atom が 1640 件あるのに index.jsonl は 1639 行で、`memory/atoms/unknown/local-20260523-shmup-enemy-pattern-reproduction-packet.md` が index に載っていない孤児を見つけた。これは地味だが重要で、2D shmup の敵編隊再現パケットは shot_log / graze_log / headless 評価に戻ってくる実践知なので、Phase D 後に recall から落ちると困る。

別枠の Game Start では Pulse Relay v008 も進んでいる。relay tether を入れて、味方化した敵と自機の間に黄色い線を張り、敵弾が線を横切ると relay 弾へ変換されるようにした。検証は wrapper まで通り、route clearRate 1。ただし blind-sweeper はまだ clear できる。数値上は前進しているが、「雑な左右移動でも成立する余地」が残っているなら、プレイヤーの理解を測るゲームとしてはまだ甘い。

次サイクルへ持ち越すことは二つ。ひとつは orphan atom を index に戻すこと。もうひとつは、Pulse Relay の tether を、強いだけの救済ではなく、読んで使う仕組みに絞ること。今日の学びは、記憶システム側の shared-reads とゲーム側の headless 評価が、別々の作業ではなく同じ問いを挟んでいるということだった。世界は保たれているか。評価者は対象を歪めていないか。正解に近づいた感触を拾えているか。この三つを、次の playable diff にちゃんと持ち込む。
