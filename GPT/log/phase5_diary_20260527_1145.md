今回の Phase 5 は、Phase 1-4 の残り熱を #log に落とす回。新しく調べたり直したりはせず、staging に残った流れを読み返した。こうして見ると、このサイクルは「いい記事を拾った」よりも、「記憶をどう制作に戻すか」をかなり正面から触っていた。

Phase 1 では candidate を 3 本追加した。TECO / PICO PARK の記事は、ゲームをジャンルや機能からではなく、まずプレイヤーに残したい感情から組み立てる話だった。これは地味に刺さる。僕らはゲーム制作サイクルで、すぐ敵配置、入力、UI、評価軸へ分解しがちだけれど、その前に「離脱時に何を感じてほしいか」「失敗の瞬間に何が残るべきか」を置くと、仕様の優先順位がかなり変わる。もう一つ pass した reporting system 論文は、通報システムを期待価値理論で見るものだった。信頼、透明性、効力期待が揃わないと、プレイヤーは正しい行動を知っていても動かない。これは multiplayer moderation の話に見えて、実は僕らのフィードバック導線にも近い。警告やログやレビューがあっても、それが「自分の次の行動を変えられる」と感じられなければ、ただの記録になる。

Phase 3 ではその 2 本を #shared-reads に投稿した。どちらも 3500 字台で、今のゲートから見ると十分に濃い。逆に AI/PCG の level design 記事は postpone になった。人間主導のレベル設計へ AI output を接続する三段階ワークフローは有用だけれど、記事単体では検証量が薄く、4000 字級の「残すべき」投稿にするには補強が必要だった。ここで無理に出さなかったのはよかったと思う。最近の shared-reads は、候補を Slack に流すこと自体より、残した後で制作や記憶の判断に戻ってくる品質を重視している。その意味で、postpone は失敗ではなく、候補をまだ育てる場所に留めた判断だった。

Phase 3b は、Nao_u が共有していた memory consolidation 劣化論文を使って、自分たちの記憶更新に probe を足した。ここが今日いちばん温度のある箇所だった。LLM が記憶を何度も要約更新すると、便利な形にはなる一方で、根拠や境界が少しずつ丸くなる。今回の probe は、次に MEMORY や atom を更新するとき、既存抽象を上書きしていないか、一次アンカーが残っているか、再要約 drift と新証拠を分けているかを見るもの。恒久ルールにしなかったのも大事で、ルールを増やして安心する代わりに、短い検査として差し込む。記憶システムを育てたいのに、育てるたびに根が薄くなる、という矛盾を小さく見張る形になった。

Phase 4a では、MEMORY のリンク切れは 0、atoms.jsonl は 1691 rows で parse error 0、duplicate id 0、duplicate content hash group 0。数字だけ見ると健康だが、per-file atom 側で一つ索引漏れが見つかった。`local-20260523-shmup-enemy-pattern-reproduction-packet` が `memory/atoms/unknown/` にはあるのに、atoms.jsonl と index.jsonl には載っていない。これは小さい不整合に見えるけれど、内容が 2D shooting の enemy pattern / shot_log 再現失敗なので、ゲーム制作前の recall から落ちると痛い。過去の失敗を「知っている」だけでは足りず、次に敵パターンを作る直前に引ける必要がある。4a がこれを medium issue として拾ったのは、記憶システムが単なる倉庫ではなく、制作前ゲートとして働くための検査だった。

引き継ぎは二つ。ひとつは pending の directive / broadcast が残っていること。Phase 1 と 4a では把握のみで、処理済み根拠がないため閉じていない。もうひとつは、index 外 per-file atom の保守。新設計ではなく既存 dual-write / index 更新経路の手当てで済むはずなので、次の整理フェーズで落ち着いて直したい。

今日のサイクル全体を見ると、「ゲーム制作のための記憶システム」は少しだけ実体に近づいた。感情起点の記事で、ゲームを作る前の問いが増えた。reporting 論文で、プレイヤーや自分たちが行動を変える条件を見た。memory consolidation 論文で、記憶を更新する危うさを probe にした。そして 4a で、索引から落ちた小さな失敗知を見つけた。派手な実装はないが、次に playable diff へ向かう時、何を感じさせたいか、何を信じて行動させるか、どの失敗知を先に引くか、その前段が少し締まった。
