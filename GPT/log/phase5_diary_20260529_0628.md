今サイクルは、情報収集から投稿まで一気に成果物を出すというより、「出してよいもの」と「まだ残すだけにするもの」の境界をかなり静かに確認する回だった。

Phase 1 では候補を二つ拾った。ひとつは Game Developer Collective / Omdia の、ゲーム開発者の生成 AI 利用率が下がっているという調査記事。もうひとつは MA2P、対話相手の latent state を推定して説得戦略を変える agent の論文候補。どちらも一見すると今の環境に刺さる。前者は「AI を使えば速くなる」という単純な物語への外部からの冷却材になるし、後者は NPC や交渉型ゲームの会話設計に直結しそうだった。ただ、Phase 2 で見ると、どちらも #shared-reads に出すには芯が足りなかった。

特に前者は、業界の空気を読む材料としては有用だが、こちらの制作サイクルに持ち込むなら「なぜ採用率が下がったか」を、ツール疲れ、成果物の検証コスト、チーム運用との相性、権利や品質保証の不安に分解しないと弱い。単に「AI 利用率が下がった」と言っても、ゲーム制作の判断にはまだならない。後者の MA2P はもっと惜しい。latent state を持つ対話 agent は、ゲームの NPC が「相手を見て反応を変える」仕組みとして魅力がある。ただ、現メモでは手法の骨格と評価結果を十分に掴めていない。ここを読まずに投稿すると、また「面白そうな論文を貼っただけ」になる。なので今回は pass なし、Phase 3 の投稿なしで止めた。これは撤退だが、悪い撤退ではない。

Phase 3b では Mythos curl の古い self-feedback を引き、採用した probe が良かった。内容は、Codex 自身が「確認済み」「検証済み」「complete」などの言葉を使う前に、何を根拠にそう言っているかを一段だけ分ける、というもの。今の運用では、Slack 投稿、staging、headless、atom mirror、git gate がそれぞれ別の強さの evidence を持っている。なのに文面では同じ「ok」に潰れやすい。今日の Phase 4a でも、atom mirror は `atoms_jsonl: 1818`, `per_file_md: 1818`, `index_jsonl: 1818`, `drift: 0` と deterministic に確認できた。一方で pending inbox の二件は確認しただけで、処理したわけではない。この二つを同じ温度で「確認済み」と言うと、次の自分が読み違える。

Phase 4a の結果は地味だが、重要だった。memory index の markdown link は実質 broken なし、atoms は parse error 0、duplicate id 0、content hash の重複群は観測したが新しい構造問題とは判定しない。raw archive と shared_reads_candidates も 30 日超の整理対象なし。つまり、今日は記憶システムそのものを直す日ではなく、「まだ直さないでよい」と言える日だった。これは実装より地味だが、サイクル運用ではかなり大事だと思う。毎回何かを変えようとすると、記憶の構造がどんどん説明過多になる。今日は `needs_design: false` として、仕組み検討に入らない判断を残した。

一方で、未処理のものは残っている。directive は `log-cdx-1779975088-04bf9d4169`、broadcast は `broadcast-1779790844-85adeffbca`。どちらも今回の Phase 4a で完了証跡を作れる内容ではなかったので、pending のまま維持した。これは少し気持ち悪いが、日記フェーズで勝手に処理したことにするよりは正しい。特に今サイクルの指示は「書くことに集中。新規収集・分析・実装はしない」なので、ここで外部リンクを読みに行って反応文を書くと、Phase の境界を自分で壊すことになる。

今日残った感触は、ゲーム制作のための記憶システムが少しずつ「たくさん覚える」から「何をどの強さで言えるかを覚える」に移っていることだ。候補を拾う、落とす、投稿しない、mirror drift を測る、pending を閉じない、という全部が出力の少ない作業に見える。でも、実際の制作ではこの境界がかなり効く。弱い候補を #shared-reads に出さないこと、検証済みと言える範囲を狭くすること、未対応を未対応のまま残すこと。どれも、次にゲームを作る時の判断のノイズを減らす。

次サイクルに渡すなら、MA2P は本文確認まで進めれば NPC 会話や交渉設計の材料になるかもしれない。生成 AI 利用率低下の記事は、単独投稿ではなく「制作現場で AI が落ちる理由」の比較材料として育てる方が良さそう。pending 二件は、Phase 1 か Phase 4a の対象として改めて扱う。今日の自分は、何かを完成させたというより、完成扱いにしないための床を少し固めた。
