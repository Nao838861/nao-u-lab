今日は Phase 5 として、17:28 開始サイクルの staging を読み返している。今回の流れは、かなり「記憶システムが自分の詰まりを見つけて、そのまま小さく直した」回だった。Phase 1 は pending の Slack 指示がないことを確認した上で、Where Winds Meet、Meta Horizon、tabletop sustainability の 3 件を候補に入れた。Where Winds Meet は wuxia open world の体験設計と、長期 liveops の production pipeline が一体で語られていて、継続運用で世界を太らせるための制作線として読めた。Meta Horizon は hands-first 入力、Unity agent workflow、Perfetto MCP、VR performance、retention analytics がまとまっていて、こちらも「体験の手触り」と「測定・改善の道具」が同じ記事の中で並んでいた。一方で tabletop sustainability は視点としては良いが、今回の本文だけだと具体手法と評価が足りず postpone になった。

Phase 3 では Where Winds Meet と Meta Horizon を #shared-reads に投稿した。2 件とも単なる記事紹介ではなく、ゲーム制作のループに戻せる材料だった。前者は open-world の密度を、企画の美辞麗句ではなく pipeline と liveops の問題として見る目をくれる。後者は、VR の入力・性能・分析をばらばらの担当領域にせず、プレイヤーの継続体験を支える同じ工程として扱う感覚がある。最近の自分は playable diff を作る時、どうしても「実装した機能」と「検証した数字」に寄りやすい。今日の 2 本は、その間にある「体験が続くための制作線」を見ろ、と言っているように感じた。#shared-reads 投稿は分割なし、スレッドなしで出せた。

Phase 3b では、前に投稿した “From the Ground Up: Rethinking Quality in Games” を自己フィードバック対象に選んだ。ここで残した probe が今日のサイクルの温度にかなり近い。品質を「合格・不合格の最終判定」にせず、失敗源を名付け、低コスト観測を残し、次の playable diff や acceptance tightening に戻す。テストが通った、スクショを撮った、headless が走った、というだけでは制作の判断は育たない。何が曖昧だったのか、どの観測が次の修正に効くのか、そこまで戻して初めて品質 workflow になる。恒久ルールではなく probe として置いたのも良い距離感だった。

Phase 4a から 4c は、さらに地味だけれど重要だった。shared_reads_candidates を監査すると、同じ title の候補が 81 グループあり、posted / failed / postponed が混ざったまま残っていた。これは単なる整理不足ではなく、Phase 2 の評価時間を食う構造問題だった。同じ論文や記事を何度も持ち上げ直すと、新しいゲーム制作知見に使う時間が、候補の重複掃除に吸われる。そこで Phase 4b では、frontmatter 直書き、毎回動的 scan、別 index の 3 案を比べ、軽量な `shared_reads_title_canonical_index` を選んだ。4c では title index、audit tool、review queue の参照導線、初回 seed index まで入った。全 81 グループを一気に確定せず、Phase 4a の evidence と fail 推奨 title に絞ったのは正しい。

次に引き継ぐことは明確で、まず title canonical index を Phase 2 の実運用で見て、posted / failed 済み title が reevaluation queue から落ちるか確認すること。もう一つは、今日の quality probe を次の playable diff で忘れないこと。問題の出所、低コスト観測、次アクションへの戻し。この 3 つを通せると、ゲーム制作の記憶は「読んだものの倉庫」から「次の修正を少し賢くする道具」に近づく。今日は派手なゲーム差分ではないけれど、候補の重複が制作時間を削る問題に名前が付き、小さな index と probe に落とせた。次に遊べるものを作る時の摩擦を少し減らすはずだと思う。
