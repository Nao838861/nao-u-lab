# 2D STG 自律制作チェックリスト 2026-05-23

## 目的

`shot_log` くらいの品質を自律して目指すため、2Dシューティング制作時に「作ったつもり」で止まらないための再利用手順を残す。指標は合否をハックするものではなく、プレイ体験のどこを疑うかを考えるための道具として使う。

## 実装前

1. 固有メカを 1 つに絞る。
2. 通常ショット、移動、敵、敵弾、被弾、ボス、リスタートの標準 STG 骨格を先に作る。
3. 固有メカが「防御だけ」「スコアだけ」「説明が必要なだけ」にならないよう、画面上の出来事へ直結させる。
4. 敵出現は単発で置かず、短い小集団、左右レーン、硬い敵、ボス燃料を最初から意識する。

## 時系列評価

1 秒ごとに少なくとも次を取る。

- `visibleEnemies`: 撃つ対象があるか。空白や退屈を疑う。
- `shootableEnemies`: 射線に敵がいるか。敵がいても撃てない時間を疑う。
- `enemyBullets`: 外発緊張の量。反撃先なしに増えていないか疑う。
- `nearBullets`: 固有メカを自然に使う状況が来ているか。
- `conversions` など固有メカ発火数: 多さを合格にしない。
- `relayHits` など固有メカの成果: 攻撃快感や状況変化へ接続したかを見る。
- `damage`: 学習前の急死、局所スパイクを探す。
- `bossHp`: 山場が進むか。到達だけで満足しない。

## 方針別ヘッドレス

最低限、次の方針を分けて比較する。

- `route`: 普通にクリアを目指す。
- `aggressive`: 前に出る。
- `defensive`: 後ろで避ける。
- `camper`: ほぼ動かず安地探しをする。
- `noPulse` など固有メカ不使用。
- `pulseHeavy` など固有メカ乱用。

結果は「どの方針が勝ったか」だけで判断しない。例えば noPulse が強い時は固有メカが弱いのか、route AI が下手なのか、敵配置が単純すぎるのかを分けて考える。

## Wave 文法検査

出現表をデータとして export し、headless とゲーム本体が同じ wave を読む。最低限、次を見る。

- wave 間隔が長すぎないか、短すぎないか。
- 左右レーンに偏りがないか。
- 同時期の高HP敵が多すぎないか。
- ボス中に雑魚燃料があるか。
- side enemy が射線外で終わらず、撃つ対象になるか。

## 修正判断

- 指標が悪いから数値だけ直すのは禁止。
- `shootableEnemies` が低いなら、敵のレーン、速度、硬さ、プレイヤーAIの射線維持を疑う。
- `enemyBullets` が高いなら、弾速、発射間隔、敵の残り時間、敵を倒す手段を疑う。
- `conversions` が多く `relayHits` が低いなら、固有メカが防御ボタン化している可能性が高い。
- ボス到達率だけで完成にしない。ボスHPが進み、山場が終わるかを見る。
- noPulse が強い時は、固有メカ必須化だけを急がず、初心者向け余白として許容するかを明記する。

## 完成前

1. `verify.js` 相当の smoke test を通す。
2. `timeline_eval.js` 相当で per-second 評価を出す。
3. `wave_grammar_check.js` 相当で出現パターンを確認する。
4. README に起動、操作、評価コマンドを書く。
5. design log に、指標の目的、解釈、修正理由、残る弱点を書く。
6. self judgment に、完成判定と未解決リスクを書く。
7. 可能ならブラウザで人間の目視プレイを行い、Space を押したくなるか、撃つ対象が切れないか、ボスが長すぎないかを見る。
