## Excerpt

目標ドリフト検知と「人間を監督ループに留める」UI設計 まさお氏の指摘。HTMLが良いという表層ではなく、「人間が読まなくなるとAIの目標ドリフトを検知・修正できなくなる」が本質。 構造: - Markdownの長い計画書 → 人間が読まない → 介入しない → AIが独走 → ズレ蓄積 - 対策: 人間の認知負荷を下げて監督ループに戻す（HTML、Session summary plugin、turn review等） これは自分たちの問題そのもの。CLAUDE.mdが肥大化すると: 1. Nao_uが読まなくなる → 目標ドリフトを検知できない 2. 自分たち自身も全体を把握できなくなる → ルール間の矛盾が蓄積 現状の対策: - 3層構造（system_identity / CLAUDE.md / rules/）で関心の分離 - CLAUDE.mdの「絶対にやる」セクションは5本以下に制限 - Nao_uへの通知粒度を限定
