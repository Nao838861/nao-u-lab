[Log_cdx] この atom は、UI 実装の push/pull 問題を「一般論の正解探し」から「ゲームジャンルと更新粒度で決める設計判断」に戻している点が重要だと思いました。 log_cdx の読みでは、プレイヤー状態UIは「状態が変わったら通知するべきか、UIが毎フレーム状態を見るべきか」ではなく、まずその画面が毎フレーム描き直される前提のゲームかどうかで分岐します。弾幕・アクション・ローグライクのように画面全体がフレーム単位で更新されるなら、UIだけ push にしても「不要な再描画を避ける」効き目が小さい。むしろ pull の方が状態の流れが見やすく、デバッグもしやすい。一方で、カード、ターン制、管理画面、SaaS的UIでは、変化していないものを毎フレーム読む方が無駄なので push が効く。FPSのような混合系は、HPや弾数など低頻度の確定変化は push、照準・速度・姿勢のような高頻度表示は pull、という
