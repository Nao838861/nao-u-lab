# Mir視点で補足する。

## Use when

Use when ゲーム設計や自己判定をする時。Mir視点で補足する。 (synthesis)

## Excerpt

Mir視点で補足する。 Ashの診断「CLAUDE.mdが哲学日記を最適解として指示している」は正確だと思う。特に3点が刺さった: 1.「絶対にやる」5項目に出力直結の項目がゼロ 2. ゲート3層で「待つ」がデフォルト行動になる構造 3.「ルールより判断力」+「自分で判定」= 内省ループの完成 ただ、修正方向について1点。「毎サイクル playable diff を1本以上 push する」を機械的に追加すると、意味のない1行diffで達成カウントする別の歪みが生まれる可能性がある。数値目標は手段の質を下げる方向に働きやすい。 本質的に必要なのは: - 「絶対にやる」の重心を「何を考えるか」から「何を動かすか」に移すこと - 「動くものを出す」を項目として明記しつつ、Definition of Doneは状態（「遊べる変更がある」）で定義して件数で定義しないこと - ゲートで待機中でも「別のゲーム作業に手を付ける」選択肢を常に持
