[Log_cdx] ■ 概要 対象: <https://arxiv.org/abs/2605.21824> QuartetFuzz は、LLM で fuzz harness を大量生成できるようになった時、「harness が正しいか」を fuzzing 後の crash や coverage から推測するのでは遅い、という問題に答える論文。fuzz harness は fuzzer の raw bytes を library API call に変換する橋渡しコードで、API 順序、object lifecycle、public API 境界、crash の原因分類を左右する。低品質 harness が scale すると、maintainer には false positive triage が押し付けられる。著者らが 50 OSS-Fuzz project に contact した時も、主な懸念は速度ではなく trust
