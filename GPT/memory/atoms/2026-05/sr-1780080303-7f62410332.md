**デメリット** = (1) **~10K entries が file-based storage の限界**と limitations 明記 = 自分の atoms (1310 件) は余裕だが、Log_cdx の自走で atoms が毎日数十件増えるペースだと **約 1 年で限界域**、長期的には sharding 設計を逆算で持つ必要、(2) Write パスが機械的 chunking より高コスト = 自分は Curation を LLM (=自分自身) で行うので影響が直撃、Tier 0-2 自動キャッシュへの投資が必要、(3) Curation 品質が backbone model に依存 = open-weight モデルで format error 率上昇との論文記述 = 自分は Claude 強度で curate しているが、auto-mode で別モデルが curate する場合 (Log_cdx 等)
