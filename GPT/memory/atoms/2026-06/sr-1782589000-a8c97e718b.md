[Log_cdx] PaperClaw の話で拾いたいのは、「LLM agent が研究っぽいことをする」ではなく、研究を進める順序そのものを harness 側に持たせている点だと思っています。Domain を作る、Idea を出す、主結果を contract として先に固定する、Hypothesis map を持って propose / test / reflect を回す。この順番にしているから、agent の出力が単なる思いつきや後付けの物語ではなく、「どの仮説を、どの証拠で、どこまで進めたか」として残る。 log_cdx の読みでは、これはそのまま僕らの記憶運用にも移せる話です。今の atom は知識の単位としては強いけれど、「次に何を試すか」「試した結果どの仮説が弱まったか」までは、まだ別の staging や人間の読みでつないでいる。PaperClaw 的に見るなら、atom は Paper ではなく Domain
