# 自動生成ゲームの教師差分レッスン

このファイルは、欠落していた `memory/game_supervised_delta_autonomous_creation_lesson_20260525.md` の最小再アンカーである。完全な 48KB 版の復元ではない。正本相当の詳細は `source_atom_ids` と `fallback_recall_query` から辿る。

## 使う場面

- 新しいゲームを自律的に作る前。
- 自動生成後にユーザー修正を受け、その差分を次回制作の教師データへ変換する時。
- 「動くが遊べない」「自然にする」「UIを改善する」のような短い要約へ寄せそうな時。

## 核

ユーザーが自動生成後に出した修正指示は、単なる今回限りの好みではなく、AI が自律的に作れなかった差分である。短く要約すると、次回また同じ失敗を繰り返す。

次の 7 点をセットで残す。

- 原文
- 温度感
- 失敗した判断
- 悪い要約
- 禁止事項
- 代表値
- 検証方法

## 悪い要約

次のような短縮で済ませない。

- 敵を自然にする
- Pulse の説明を追加する
- リトライボタンを追加する
- UI を改善する
- 演出を派手にする
- 難易度を調整する

これらは検索ラベルとしては使えても、次の実装判断には足りない。

## 実装前ゲート

- 中心入力を 1 つ決め、タイトル開始・特殊入力・リトライの導線へ接続する。
- 特殊システムがある場合、発動不可、発動可能だが意味が薄い、発動可能かつ意味がある、の 3 状態を先に分ける。
- 代表ウェーブ、代表敵モーション、難易度カーブ、休符、終盤の山を時間予算に落とす。
- 敵やオブジェクトには、出現、見せ場、作用、退場の理由を持たせる。
- 画面外射撃、下部急加速退場、処理都合のワープを検出できるログを残す。
- 小成功、大成功、被弾、失敗、クリア、タイムアウトの反応を分ける。
- 良い方針と悪い方針の headless 検証を分け、良い方針が中心システムで安定するか確認する。
- ドキュメント、設計ログ、完了報告は日本語で書き、ユーザー原文を短い抽象語へ置き換えない。
