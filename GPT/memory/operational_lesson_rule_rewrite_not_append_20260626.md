# ルール修正は継ぎ足しではなく正本の置き換えを優先する

AI は失敗を指摘されると、既存ルールの末尾に「追加ルール」や「例外」を積みがちである。これは古い前提を残したまま新しい禁止事項だけを足すため、次の起動時や別プロセスの実行時に古い様式が再発しやすい。

今後、既存ルールが新しい運用判断と衝突した場合は、まず「どの正本を置き換えるべきか」を切る。追加条項で塞ぐのではなく、現行ルールとして読み直せる形に再構成する。特に Slack 投稿・shared-reads・Phase prompt のように別 Codex セッションが読む運用文書では、古い動作を残した追記より、ゼロベースの書き直しを優先する。

判断基準:

- 古いルール本文が、現在は禁止された投稿様式や判断手順をまだ含んでいるなら、追記ではなく本文を置き換える。
- 「ただし」「今後は」「追加で」だけで矛盾を塞いでいるなら、読み手が最初から正しく動ける構造へ書き直す。
- 記憶に残す時も、細かな禁止語を増やすのではなく、失敗の型として「正本置換を優先する」と記録する。
