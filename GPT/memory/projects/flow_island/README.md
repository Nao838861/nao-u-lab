## ゲームの核

プロジェクト資料のテーゼは「流通が社会を成立させる。社会はストックではなくフロー」。プレイヤーは住民へ直接命令する支配者ではなく、勅許会社の支配人として次を行う。

- 区画を指定する。
- 道、石畳、海運へ投資する。
- 商館の買上げ目標と在庫を操作する。
- 本国注文へ応える。
- 市場、需給、価格、世帯、出来事を観察して次の介入を決める。

現在の有望な一本線は次の通り。

1. 初期資金で最低限を建てる。
2. 配置と職構成が良ければ取引量が増える。
3. 市場口銭で金庫が回復する。
4. 次の建築で生産連鎖を伸ばす。
5. 集落が広がると距離が生産時間を奪う。
6. 道と石畳が中盤の解になる。
7. 本国注文が期限と目的を与える。

これは「建てる -> 貯まる -> また建てる」と「注文へ間に合わせる」を接続できる。現時点では、勝利条件の独立、次の島、診断ツール、家普請などは未確定または未完成である。

## 実装上のリスク

- 経済エンジンと UI は分離されているが、それぞれ単一大ファイルで変更衝突と回帰の影響範囲が広い。
- UI テストは構文・参照エラーを拾うが、重なり、切れ、重複 ID、初見理解を検出しない。
- 現在の UI 世界は seed 11 固定。複数 seed の経済差を人間が比較する入口はない。
- 保存/再開がない。複数年プレイと相性が悪い。
- 音がない。市場開通、注文達成、冬、飢餓、破産などの出来事が視覚テキストだけに寄っている。
- 独立・勝利・次の島が未定義で、長期プレイの終点がない。
- `VERSION`、HTML title、cache buster が手動で別管理されている。

## Claude/Codex 協力方針

Claude と Codex の成果を混ぜず、同じ受入条件で往復させる。

### Claude 側に期待する役割

- 原体験、プレイヤー像、経済の意味から、何を残し何を捨てるかを設計判断する。
- 「建築リズム + 本国注文 + 距離の呪い」を一本のプレイ弧として批判する。
- 監査 FAIL が、古い物差しか実際の故障かを分類する。
- 人間プレイで、予測が当たった瞬間、分からなかった因果、待ち時間、退屈な操作を原文で残す。
- プロジェクト正本を現行仕様へ更新する。

### Codex 側に期待する役割

- 決まった仕様を小さい差分で実装する。
- seed 固定の再現テスト、貨幣保存、フロー会計、失敗 policy を検証へ落とす。
- UI の重複 DOM、レスポンシブ、バージョン管理、保存/再開など技術的負債を処理する。
- デスクトップとモバイルのスクリーンショットを変更ごとに比較する。
- Claude の設計主張に対し、実測値で反証または支持を返す。

### 共通の受入条件

- 変更前に「プレイヤーが何を見て、何を予測し、何を決める変更か」を1文で書く。
- 経済変更は `audit.mjs` の該当項目と、悪い方針を含む比較シナリオを持つ。
- UI 変更は 1440x900 と 390x844 で、切れ、重なり、初手の可読性を確認する。
- headless PASS を面白さの判定に使わず、人間プレイを最終確認に使う。
- Claude と Codex が同時に同じファイルを編集せず、commit 単位で受け渡す。

## 次の優先順

1. 旧 UI 残骸、重複 ID、HUD 重なり、モバイル切れ、版数不一致を直し、現行版を正しく観察できる状態にする。
2. 現行レジーム用に E1-E16 の意味を棚卸しし、「古い閾値」と「実故障」を分ける。

4. 追加システムを増やす前に、「建築リズム + 本国注文 + 距離の呪い」が60秒の画面と10分のプレイで伝わるか判定する。
5. 一本線が成立してから、保存/再開、勝利=独立、家普請、次の島を順に扱う。
