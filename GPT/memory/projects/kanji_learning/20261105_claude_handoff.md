## 1. 何を作りたいか

小学4年生の男の子が、アプリを気軽に遊びながら漢字を覚え、後で手書きする時に形を思い出せるようにしたい。「読めるのに書けない」子を想定する。

ミチムラ式の考え方を重視し、**部品の名前・形・配置の対応を言葉で扱う**ことを中心にする。部首に限定せず、既習漢字なども「部品」として扱う。さかもと式も参考に、つまずいた漢字・部品だけを短く学び直し、再確認できるようにする。

- [ミチムラ式公式の説明](https://kanji.cloud/studymethod/method-features/)
- [さかもと式公式](https://manatera.com/kanji/)

公式教材そのものを再現・転載する企画ではなく、考え方を参考にした独自の試作。公式サイトの効果を、このアプリで検証した効果として扱わない。さかもと式の「見るだけ」は暗記の工程の説明で、原法には書き取りによる確認もある。

### ユーザーが大切にしていること

- 最初から紙に書く準備を要求せず、アプリ内だけで学習サイクルを完了できること。
- プレイヤーに「自分で頭の中で思い出して、できたか自己申告して」と任せる方式にしない。思い出す操作をアプリの入力として扱いたい。
- ペンタブは所持しており、iPadも使える。画面上で書くことは許容される。
- 手書きを必須にせず、形の選択だけでも続けられること。
- 修理ゲームという設定を最適と決めつけない。修理・戦闘などの世界観より、学習の中心操作を先に考える。
- 説明文を読み落とすと操作が無反応になる設計を避ける。作る対象を操作場所の近くに大きく表示する。

## 2. 最初の試作から何を変えたか

初版は、形の候補をドラッグして漢字を組むパズルだった。ユーザーから次の指摘を受けた。

> 遊んでて思ったのは「読めるのに書けない」タイプの人には、読めるから雰囲気で組み立てられるが、それは読むときに使ってる既知の情報を使って組み立てているだけで、記憶に入れるのではなく単に見た目で組み立ててるだけなので、このやり方では記憶には残らないと思った。

これを受け、形を最初から並べる方式から、**ひらがなの部品名で構成を答えてから、形を扱う方式**へ変更した。

形を選べたこと、名前が分かったこと、手書きの形が出せたことは別の成果。選択肢付きの正答を「何も見ずに書けるようになった」とは扱わない。候補を増やすだけで想起や定着を確認できるとも考えない。

## 3. 漢字モードの確定方針・公開済みの流れ

例：「なかま」の「なか」を問う場合。

1. 語例・読み・例文を提示する。完成漢字「仲」は見せない。
2. 「にんべん」「なか」など、**ひらがなの部品名だけ**を候補から選び、左右・上下へ当てはめる。現在の名前候補は6個。
3. 「ひだりに にんべん、みぎに なか」という構成文ができる。
4. その下で、現在のモードに応じて形を出す。
5. 正解・形の確認・見本確認を経て次のお題へ。一回3文字、図鑑から一文字だけでも遊べる。

### 形を出す二つのモード

| モード | 入力 |
|---|---|
| 形から選ぶ | 12個の部品の形から選び、位置へ置く。二部品の漢字では正解2個＋誤答候補10個 |
| ペンで書く | 構成文の下の白い欄へ、形の見本なしで書く |

形の選択肢は「完成漢字12字」ではなく、**部品が合計12個**。前回6個では簡単すぎるという指摘を受けて倍にした。名前ラベルや正解だけの色分けを付けず、候補の並びを混ぜる。

モードに関するユーザーの指示原文：

> 「ペンで書く」か「12個の形から選ぶ」 はモード切替。毎回選ぶものではなく、概念的には暗黙のモードとして。その場でいつでも切り替え可能にはしておくとよいと思った。

最後に使った設定を保存し、次のお題・次回起動でも引き継ぐ。毎問の選択ダイアログは出さない。その場でいつでも切り替えられ、選択中の部品や筆跡を消さない。この仕様は公開済み。

### ヒント

部品ごとに「名前・読み上げ → その部品の形 → その部品の書き順」と段階を踏む。困っているのが一つの部品なら、すぐ漢字全体を見せず、その部品を助ける。部品練習へ移り、元のお題に戻れる。見本で確認して先へ進む経路も残す。

構成文付きの手書きは、言葉を手がかりにする練習。構成文も候補も隠す自由想起テストは未実装で、今回の通常サイクルの必須条件ではない。

## 4. 最新の変更要望：部品練習はクイズを基本にする

最新のプレイ後フィードバック原文：

> 部品の練習は、形に対する読みを当てるクイズが一番やりやすい。6拓でえらぶ。それができたら、読みから形を当てるクイズ(これは手書きするモードにも切り替えれるように)
> この順番で、それが基本がいいと思う。今の辞書みたいなのはあってもいいが、一度に画面に入る選択肢が少なすぎて一覧性が足りないと感じた

必要な体験は次の順番。

1. 部品の形を見る。
2. その読み・名前を**6択**で答える。
3. 正解したら、その読みから形を答えるクイズへ進む。
4. 後半は、形の選択とペン入力をその場で切り替えられる。

部品の練習を開いた時に、まず辞書から部品や出題方向を選ばせる方式にしない。この順番で遊べるクイズを基本にする。辞書的な一覧は補助として残し、カードの余白や常設ボタンを減らし、一画面で多くの部品が見えるようにする。

「同じ部品で形→読み→形を一組にし、3部品で一区切り」「後半の形候補は既存方針を引き継ぎ12個」「形は直接タップして回答」は、この要望に対してGPTが着手した実装案。細部までユーザーが指定した数値・操作ではないので、上の目的を優先して詰めてよい。

### 記録

### 手書き判定の限界

同梱筆画と入力線の形を近似比較する。筆順には依存せず、細かなとめ・はね・はらいを採点する機能でもない。初期の全体的な線の重なり比較では別の漢字も通ったため、筆画ごとの形・端点も比較する処理を追加した。

公開版のテストでは、収録12字間の取り違え、白紙・点・一本線・鏡像・片側だけ・網目の落書きを拒否した。子供の実際の筆跡による校正はしておらず、正しい字の拒否や似た形の誤受理は残り得る。UIでも「形チェック」として扱い、見本確認で先へ進める。
