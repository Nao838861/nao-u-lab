# エディタのパレット塗り操作の相談

2026-10-05。対象は `D:/HomeBrew/FamiBASIC_Turbo_main` のBG Studioとスプライトエディタ。ユーザーの追加発言により、パレット番号は配置時の初期値だけをコピーし、後から参照元の配色に追従しない方針。モードの入口・終了操作の詳細は提案段階。エディタ本体の変更はしていない。

## ユーザー原文

> エディタのパレットの扱いを変えたい。
> BG、スプライトともに、パレットを選ぶと、パレット内の色だけでなく、0-3のパレットセットも選択したことにする。
> BGの場合、パレットを選んでタイルをクリックすると、パレット塗モードに入って、カーソルの形が変わり、タイル単位でパレットを上書きして塗れるモードになる。このモードは、右クリックで終了する。パレット上書きモードの時には、ブロック組み立て欄の各タイルも塗れる。
>
> みたいなモードを作りたいが、ドット絵を描くモードではそのままやると通常の操作とバッティングする。
> ドット絵を描くモードでは、パレット4つそれぞれの右側に「タイルにパレット0を設定」みたいなボタンがついて、それを押したときだけ上書きモードにするか？
> この辺りの仕様を相談させてほしい

## 配色の独立性についての追加原文

> タイルに塗ると、編集用の色が設定される。あくまでその時点での色なので、過去にこのタイルの色が違っているときに塗ったブロックやマップには影響しない。
> ブロックにつけた色も同様。マップに塗る時も同様。タイルやブロックの色は、マップにとってはあくまで初期値でしかない、という扱いが、一番自然でわかりやすいと思った。後から一括で変えられないのは不便だが、それはそういうものとしたい。どうかな？勝手に変わる系は、ブロックとマップの上書きがあるので上書きしたかどうかが判別できない現状だと意味不明になりそうなので。

## 現行コードで確認したこと

- `famibasic/bg_studio.py` の `pick_palette` は色番号とパレット番号を両方選び、タイルモードでは現在タイルの `preview_palettes`、ブロックモードでは現在区画のパレットも即時変更する。固定画面とboss素材では16×16の全区画を変更する。
- `famibasic/bg_interactions.py` の右クリックは単クリックのスポイトと右ドラッグの範囲選択に使われる。パレット塗り中の終了操作は、押下から解放まで通常操作へ渡さない必要がある。
- `famibasic/bg_composer.py` の区画はタイル番号とパレット番号を個別に持つ。タイル割り当ては区画のパレットを保持する。組み立て欄の変更は同じブロックの全使用先に反映する。
- `famibasic/pattern_editor.py` の `pick_palette` も色番号とパレット番号を両方選ぶ。表示は一覧全体に選択したパレットを使い、タイルごとの表示用パレットは現在持たない。
- `famibasic/sprite_resources.py` の出力はパレット番号をOAM／BASIC属性で指定する前提。CHRのタイルごとの配色指定を実行時属性へ反映する仕組みはない。
- 追加確認：マップは `blocks` にブロックIDを保持し、`bg_tiles.tile_cell` は参照先ブロックの区画から配色を読む。そのため、現行の組み立て欄でのパレット変更は配置済みマップへ波及する。`bg_tiles.put_cells` は配置先だけの変更にブロックの複製・共用を使うが、マップ全体の配色独立性を保証するものではない。

## 配色の保存と配置の方針

パレット番号0〜3は、タイル・ブロック内の各区画・マップ上の各配置先に独立して保持する。素材から配置先へのコピーは置く時に一度だけ行い、その後は元のパレット番号を変更しても配置済みの配色を変更しない。後からの一括追従機能は要求しない。

| 操作 | 変更する値 | 影響しないもの |
| --- | --- | --- |
| タイルのパレットを塗る | タイルの編集用パレット番号 | 既存ブロック・既存マップの配色 |
| タイルをブロックへ置く | その時点のタイル配色を区画へコピー | 過去に置いた区画の配色 |
| ブロックの区画を塗る | その区画のパレット番号 | タイルの編集用配色・既存マップの配色 |
| ブロックをマップへ置く | その時点の各区画の配色を配置先へコピー | 過去に置いたマップの配色 |
| マップ上のタイルを塗る | その配置先のパレット番号 | 元ブロック・他の配置先の配色 |

初期値と手動上書きを区別するフラグは設けず、配置先には常に確定したパレット番号を持たせる。未設定時に素材の番号を都度読む方式では独立性が失われる。既存データを移行する場合は、現在画面に見える配色を配置先の値として確定する。

例：タイルAをP0でブロックBへ置き、Bをマップに置く。その後AをP2にしてもBと既存マップはP0を保つ。Bの区画をP3にしても既存マップはP0を保ち、以後新しく置いたBはP3になる。

この方針はパレット番号の割り当てを対象とする。パレット内の実色の編集や、共有タイルのドット編集まで複製する方針は今回の発言から決定しない。現行では実色とタイル画素は共有される。

組み立て欄の配色が全使用先へ反映されるという以前の説明は現行コードの事実であり、今後採用する配色仕様ではない。配色を独立させながら形状やタイル参照をどこまで共有するかは、実装時に別途確認する。

## 提案

色をクリックしたら色番号とパレット番号を選択する。選択とデータへの適用は操作として区別し、ドット編集では色選択だけで既存タイルのパレットを書き換えない。

BGの配置・組み立て操作では、パレット選択後にパレット塗りを待機させ、塗れる場所にカーソルを入れた時点で専用カーソルを表示する。最初のタイルクリックから適用し、左ドラッグで連続して塗る。ドット編集では通常の色クリックは描画色の選択を維持し、各パレット行の右側にある「P0を塗る」などのボタンからだけパレット塗りへ入る。長い説明はツールチップに置く。

塗り中は別のパレットを選んでもモードを維持して番号だけ変更する。右クリックまたはEscで終了し、開始前のツールへ戻る。別ツールや編集画面へ切り替えても終了する。右クリックによる終了と同時にスポイトや範囲選択を実行しない。1回の左ドラッグは1回のUndoにまとめる。

変更対象はパレット番号だけとし、画素の色番号0〜3とタイル番号は保持する。対象タイルの枠、カーソルのパレット番号、状態表示「パレット2を塗る／右クリックで終了」で動作を示す。

## 残る相談事項

スプライトのタイル塗りは、まずタイルごとの編集用配色として導入する案。ゲーム内の配色変更まで求める場合は、スプライトの配置・属性との接続を別途設計する。8×16スプライトの表示用配色を8×8単位で持つか上下を揃えるかも未確定。

マップ上のパレット塗りは配置先だけの変更とする。固定画面の16×16配色制約に合わせた操作単位は実装前に確認する。通常配置とパレット塗りの入口の区別、同じ場所への再配置で配色も初期値へ戻すかどうかは操作詳細として残る。
