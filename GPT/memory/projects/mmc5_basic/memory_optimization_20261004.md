# ROM・BASICのメモリ最適化（2026-10-04）

> 最近作業中にメモリが不足することが増えたので、ROM、BASICともに、無駄なメモリを使っているところがないか調べてメモリ最適化を進めてみて。設計や動作を変えない範囲で。

担当は `perf/memory-footprint-20261004`。open_issues.mdに予約を先にpushして着手。
本流の編集中ファイルを混ぜず、独立した作業コピーで実装した。

- コンパイラBSSを3,257→3,106 Bへ削減。領域3,312 Bの空き55→206 B。I/O記述子8→5個で21 B、テーブルのBANKペアを出力アドレスの未使用2ビットへ入れて128 B、未使用一時変数2 Bを削減。引数・キャッシュ128件・命令・行・シンボル・配列の上限は維持。
- 常駐ROMはmainで71 B、IDEで開いていた比較用ブランチで69 B減。広域で到達しない旧即時実行アクション9を除外。狭域の即時実行・CLEAR領域予約は維持。
- 定数添字のTBYTEを同じROMの値の即値読み込みに置換。不要なテーブルコピーを省き、両ゲームで生成コード9 B減。ソースと素材は変更しない。
- BASIC通常変数は26 B。固定アドレスのゲームRAMや動的DIMの使用量と、コンパイラBSSの空きを混同しない。
- 57回帰＋追加1容量試験、比較用11回帰が成功。同一ゲームのmain前後でMesen結果JSONはROMハッシュ以外すべて一致。更新数・描画・音楽・再挑戦・処理時間を維持。
- 比較用全編は道中7,584更新・ボス1,225更新、待ち落ち0／0、描画不一致0。60fpsを維持。生成コード61,530→61,521 B、最小BANK余裕60 B、再配置0。
- mainの後続ゲーム変更も取り込んだ検証時点は生成コード62,819 B、最小BANK余裕46 B、約9.935秒、再配置0、全編・描画成功。mainと比較用の別ソース条件を混ぜない。
