## 設計判断

- 16×16ブロックは4枚の8×8 CHRと各区画のパレット番号で構成。ブロック定義を共有し、配置後の修正は全参照へ反映。局所変更は複製置換。マップ直接描画は実装しない。
- scroll-v1専用ROMプロファイル。上下固定表示＋独立マップ1領域、位置・高さ8ドット単位、境界帯8ドット、マップ表示高最大224。既定は上固定16＋境界8＋ゲーム216。
- CIRAM0を32×30行リング、CIRAM1を固定表示、マップ時ExRAM mode1／固定表示mode0。境界ではBGのみ抑止しスプライト側render enableを維持。両方止めるとMMC5の走査線計数を壊す。
- STEPは1FRAMEの変位、最大8、複数呼出時も確定位置との差を検査。大移動は画面OFFのSEEK。逆方向も独立行から読める形式。
- bank4先頭5120Bを再利用、64KiB PRG-RAM・保存2枠・STOP退避を維持。そのためscroll-v1では本体の旧CHR/BG編集を無効化し、PCで素材更新する。BASIC編集は維持。
- SAVE format3は素材を複写せずSHA-256 asset IDでROMと結合。ソース長の並行拡張を退行させない。旧bank4素材コピー処理はそのまま使えない。
- PRG256KiB、CHR64KiB（明示設定で128/256）。先頭CHR8KiBはスプライト＋文字。旧コードのkernel bank定数とnative_exportのmapper対応が必要。
- 配置ID、logical block ID、physical CHR番号は別物。FLAGはゲーム連携byteで、破壊描画機能ではない。

## 検証と限界

`python -X utf8 tools/scroll_map_spec_check.py` が合格。462レイアウト×fine Y8、114240移動、14882位置の長距離往復、5120B区画、4016行codec、破損拒否6件。新予約語のtrieは現行435→453ノードで512以内。

32画面マップの非圧縮例は、辞書256種類で15232B、512種類で25472B（root、pointer表、padding、配置を除く）。24KiBは目標に留める。全PRGアセット合計は128KiB。
