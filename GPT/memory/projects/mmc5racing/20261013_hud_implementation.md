# MMC5Racing HUD実装とCPU車への合流条件

HUD実装commitは `bee2fc8`、ブランチは `codex/hud-friction-circle`。<https://github.com/Nao838861/MMC5Racing/tree/codex/hud-friction-circle> へpush済み。作業場所は `D:\HomeBrew\MMC5Racing_hud`。基点はユーザー指定どおり `main` の `77df5af`。

先行するWindowsビルド用commitは `0ea74e9` と `a181509`。本体の `D:\HomeBrew\MMC5Racing` / mainには同等のセットアップ `97f5fdc` があるため、合流時はHUD本体の `bee2fc8` を中心に確認する。mainへのmergeはしていない。

## 今回のユーザー指示原文

> HUDの改善作業をはじめて。他のスレッドでCPUを3台足そうとしているので、そことの整合性に注意しながら進めて。
>
> ・基点は main の 77df5af
> ・他車側は OAM 60〜63 を使用予定。自車 48〜53、ゴースト 4・11、境界マスクは維持
> ・他車用に HUD の 60・61 番を 39・46 番へ移す差分があります
> ・direct-runtime/build_hud.py と OAM 初期配置が合流時の競合箇所
> ・bank 120 の $C000〜$D410 と $DB00〜$DFFF は他車側で使用予定
> HUD 側が使う OAM 番号を決めたら、こちらへ共有してもらえると安全に合流できます。

最初の配置依頼原文は [配置記録](20261013_hud_layout.md) に保存済み。

## 実装

上からLAP n/5、現在周回時間L、合計時間T、4輪摩擦円。時計は既存の `sss.hh`。現在周回と合計の2行だけを更新し、完走後は5周目の確定時間を残す。タイトルのBESTと保存処理を維持した。

円は旧容量（摩擦係数×垂直荷重）テーブル、点は旧 `p_req_long/lat`、赤は `p_req_exceeded`。初期案で「点を制限後の実力に限定」としたのは旧実装確認前の誤った仮定だった。旧仕様の復元を優先して要求力を踏襲した。円の形状と縮尺は同一、点は2×2pxへ統一。

OAM割り当てはこのチャットで共有済み：

| 用途 | 番号 |
| --- | --- |
| 現在周回 | 1・2・3・5・6 |
| 合計時間 | 8・9・10・12・13 |
| 円（左前・右前・左後・右後） | 15/16・17/19・22/23・24/26 |
| 点（同順） | 20・27・29・30 |
| ステータス | 55〜59・39・46 |

他車60〜63へのHUD実行時書き込みなし。自車48〜53、ゴースト4・11、境界マスクを維持。初期OAMは凍結 `ui/oam.bin` を直接書き換えず、最終ビルドで `hud.oam_patch()` を適用する。別スレッドで更新済みの他車用初期レコードを消さない。

追加の合流箇所は `race-src/ghost-draw.s`。39・46のYを255へ書いていた旧2命令を、同じ長さ・同じサイクルのBITへ置換した。この変更を落とすとステータスが欠ける。

bank120は既存 `$D411..$D8FF` 内だけを変更。ユーザーの予約範囲は旧リリースとバイト一致。bank115は既存HUD枠 `$C800..$CFFF`。CHR62ページの自車1〜76ペアと境界116ペア、スプライト表0を保護する。

## 修正した判断

最初は円4輪の枚数とゴーストだけを数え、自車との縦重なりを見落とした。点も、実際の1〜2pxの描画部分だけを見ていたが、8×16の透明枠全体が走査線数に入る。自車の全姿勢を含めた検証へ広げ、全4輪をy167までに終え、点のYをCHR内で表す方式にした。円の領域はHUD3枚＋境界1枚＋ゴースト2枚で最大6枚。

旧円の最小タイルは52であり、64や56からのコピーでは微小荷重の円が欠ける。荷重ゼロはタイル0なので、単純なID加算では自車タイルを表示してしまう。全容量の検証で0・52〜78を確認し、0は透明ペアへ明示的に対応させた。

FCEUXのGD画像をPillowのGdImageFileで読むと黒く見えた。ウィンドウの非表示やPPU設定の問題と断定せず、GD truecolorの11バイトヘッダーとARGBバイト列を直接解釈して解消した。最終撮影は `gui.gdscreenshot(true)`、標準PPUで正常。

自己評価：現在周回と合計の読み取り位置が固定され、4輪を同時に比較できる。右列を16px下げた配置の読みやすさは、プレイヤーの使用感も確認する。CPU車との合流はまだ完了したことにしない。
