# GRIPの制動で曲がらない理由と、増摩擦時の数値不具合

2026年10月14日の依頼原文:

> ブレーキをかけても速度が落ちるだけで思ったほど曲がらず、ブレーキを使わずアクセルオフだけで走る習慣がついているのだが、なぜだろう？さっき摩擦円を大きくしたら、よけい悪化した印象。

原因調査として、実6502物理を3初速×制動／惰性＋2つの進入手順、現行／1.3倍保存版の計960更新で比較した。ゲームのコード・ROMは変更していない。main `59b75c5`に診断コード・結果・説明をcommitしてorigin/mainへpush、終了時clean・同期済み。配布ROMは撤回後のSHA256 `3a4b2e04f4bfdc4d72942b29d92afad2d727afb3c6c3e5bf4ff7c7d1d5643112`のまま。

同じ初速1280・右入力60更新で、アクセルOFFの速度1071.53／車体61.00°／進路24.89°、Bの速度805.89／車体60.65°／進路15.92°。前輪荷重だけを見るとBの効果があるが、外側後輪の荷重6・限界22をBの要求28が使い切り、内側後輪は荷重0になる。前輪の車体横力は125→182へ増える一方、後輪は110→0、4輪合計は235→182へ減る。

GRIPのヨー速度はp_rear_blend=0用の上限192（約1.055°/update）へ達する。Bで回頭モーメントを増やしても回頭増に結びつかず、車体と進路がずれる。Bの後向きの力も車体／タイヤの向きに沿って世界横成分へ入るため、終盤の世界X力は惰性97に対してB-34。20更新だけ制動してBを離してから曲げると、惰性進入16.49°に対し18.82°の利点はあるが小さい。以前の調整試験はこの手順を中心に見ており、Bを押しながら曲がる実感を検証していなかった。

**1.3倍時は調整の相性だけでなく数値不具合があった。** physics/energy-source/physics-steering-mu300.asmのFORCE_PREPは合計力の絶対値の下位8ビットだけをMMC5乗算へ渡す。格納とコメントはsigned16だが、元のmu3.75×総荷重64≒240に依存する前提。1.3倍の惰性＋右では9更新目の合計横力267が11になり、全桁なら世界力X261/Y45なのに実際はX9/Y17。B＋右でも10更新目に259→3になる。60更新中の投影不一致は惰性52・B51、進路角は惰性5.64°／B-5.50°へ悪化した。

速度積分の出力は実際に渡された世界力×11と960更新すべてで一致し、最初の数値化けは**車体→世界座標の変換**で発生する。下流の速度積分にも上位バイトを符号だけに使う同系統の制約があり、将来増摩擦へ再挑戦するなら両方の全桁対応が必要。今回の撤回後8系列では投影不一致0。前回の各輪の摩擦円検査だけでは合計力の範囲を見落としていたことをユーザーへ明示した。

資料は開発リポジトリ`verification/grip-brake-response/README.md`、`probe.py`、`results.json`。Windows Python3.10.6の既存ホスト例外を避け`--trace-host`で実行。初速注入の開ループ診断で、PPU・道・人間の操作・周回タイムの検査ではない。

次の調整を依頼された場合は、無条件の摩擦円拡大やヨー上限だけの変更を先に行わず、GRIPの制動配分・後輪横力・車体と進路の関係を比較する。合計力の範囲の修正は再挑戦する倍率調整と区別する。今回は修正依頼ではなく原因を尋ねられたため、操作感を再変更していない。
