# 木の増設後のガタつきと、自然な回転への修正

## フィードバック原文

> 木を増やしたら、すごくガタガタ動くようになったんだけど、ずれを許容して無理矢理増やしてる？だとしたら諦めて、コース内側と、カーブが曲がり切れなかった時にちょうどぶつかりそうな位置にある外側を優先して残して、自然に回転できる量にしてほしい。

温度感：本数を増やした結果、基本の回転の自然さが大きく悪化した。増設の限界を諦めてよいので、役割のある木を残してほしいという明示的な優先順位の変更。

外した判断：18本を収めるために既存画像を8px単位で移し、位置誤差より断片の少なさ・辞書共有を優先した。最大約5.38pxのずれを許容し、角度ごとに元の個体も変えた。全窓の転送予算とネイティブの保持0が成立しても、画面上の木や建物の位置はガタつく。更新間隔と独立復号の画素一致だけで自然な回転を証明したつもりになっていた。

悪い要約：「木を少し減らす」「60fpsにする」。どちらも角度ごとの位置の跳びと、残すべき木の役割を落とす。今回避けること：辞書を共有するために表示位置をずらす、本数が入ることを体験改善と取り違える、同じ誤った画像の復号一致だけで自然さを判定する。

## 採用した変更

ゲームmainへ `674131c` をpush。基点は別作業で144×168へ拡大された `a2962ba`。既定の高さ168を継承し、以前の160へ戻して原因を隠さない。木18→8本：内側は北西(160,170)、西(136,328)、中央(280,436)、南東(482,502)、北東(500,320)。外側は北西(210,43)、西(168,470)、南東(520,630)。建物2棟(150,260)/(620,245)も残す。

同じ元個体の画素を最も近い整数ピクセルへ移し、8×8パターンへ再分割する。全角度の残す不透明地形の参照集合をquarter別に先に集め、参照されないCHRを再利用。元画像は不変コピーから読む。UIの先頭2ページとsprite/borderの末尾2ページを保護する。木palette1・建物palette2へ統一し、元の境界タイルの色の揺れも取り込まない。CPU3台、HUD、モード、ゴースト、衝突・爆発・再挑戦を継承した。

ROM SHA256 `e502922bc930ace4f18e8daf45fa7ef044660f0fdd6b5156f8273cccd9c41aa9`。辞書19,775 / 20,736ブロック、マップ82,924B / 11バンク。追加RAM0B、PRG/CHR容量を維持。空のソースZIP展開先からの再ビルドもバイト一致。

## 検証と限界

最終ROMから全128角度×10物体の画素中心を独立に測った。各軸誤差は0.499895px未満、距離誤差0.698740px未満、一周の境界を含む隣角度の誤差変化1.221946px未満。全角度で不透明地形293,776タイルの語とCHRを保護。全2,437,120描画窓は最大9,200 / 予算9,273cycles、超過0。実6502の2,228窓が独立NT/ExRAM復号と一致。

Mesenの最重窓8,199レースフレーム、CPU3台・合成ゴースト付きDRIFT turns/full/denseとGRIP turns各1,091更新、自然GRIP1,091更新、自然DRIFT188更新、両モードの衝突終了各944チェックの計9条件で保持・拒否0。測定した締切余裕は最小133cycles。自然DRIFTは衝突で早く終わるので、長時間性能の根拠にしない。GO後188更新を数えるため解析開始280を使用（既定410では100更新未満で失敗した同じ生記録を再解析）。実Mesenの3画面は先頭行を含め独立画素復号と一致。実機と修正後の人の体感確認は未実施。

根拠・実行コマンド・画像はゲーム側 `scenery/README.md` と `verification/scenery/current-*`。自己評価は改善：容量の最大本数から自然な表示と配置の役割へ戻した。位置精度と更新間隔を別々に検査した。
