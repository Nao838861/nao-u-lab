# エンジン音の上がり幅1.5倍

依頼原文：「エンジン音が、最低は今のままで、音程の上昇度合いを1.5倍高い音まで上がるようにして」

開発本体 `D:\HomeBrew\MMC5Racing` のmainをfetchし、作業前に `35dc439` → `7945b80` を早送りした。別スレッドで手動承認された右側削減136×184が最新になっていたため、この版へ音だけを適用した。176版へ戻していない。main `c24c379` をoriginへpushし、終了時はclean・ahead/behindなし。

## 現行ROMと仕様

- 最新：`releases/MMC5Racing_RightCrop_136x184_EnginePitch150.nes`
- SHA256：`64a67db301701602701d3975350b2808e00344dd581bf7191ed4429beb998a33`

`f_new = f_min + 1.5 * (f_old - f_min)` と解釈し、加速・惰性の両方で最低周波数を維持した。加速は最低166.46Hz、上限690.50→956.08Hz。惰性は最低109.24Hz、上限215.12→268.25Hz。APU整数タイマーの丸めにより上がり幅の実比は1.5068／1.5018。音量・速度の量子化／上限・タイマー平滑化は保持。

## 実装・配置・検証

生成器 `direct-runtime/engine-pitch/build.py` は編集可能なソースから再生成して元SHAを検査した採用184へだけ適用する。以前の配布ROMを実装入力として使わない。音phase3のPRG109 `$B943..$B9A1`（実行先 `$6FC2..$7020`）と、固定PRG127の空き `$FA80..$FAD5` / `$EC00..$EC55` / `$EE00..$EE24` / `$F220..$F244` を使う。表246バイト、音関連のROM差分330バイト。配置先FF・ページ非跨ぎを検査。RAM・OAM・マッパー操作・起動処理の追加0。今後のBGM統合や固定ROM最適化は、この追加予約も避けること。

全8位相×256速度×4アクセル／ブレーキ組合せ×2モードの16,384ケースを実6502で実行。音tickは全てJSR込み181cycles、phase3は67cyclesで旧版と一致。両モード各1,024tickの加速／惰性切替も181cycles。音以外のROM・全CHRが一致する。タイヤ音・B制動音・GOビープ・衝突音・物理・時計・HUD・CPU車・ghost・描画は不変。

別フォルダーへZIP展開して凍結基準版と最新版をビルドし、SHA一致。変更後ROMのMesen入力走行1周は1,190 NMI／1,190更新、main遅れ・転送拒否・hold0、ghost OAM上書き0。fixtureは自車が入力のみで、可視ghostは実記録をずらし、CPUのroute phaseは実記録進行へ合わせる既存の有限試験。全状態60fpsの保証へ広げない。採用184の最悪転送不足154cycles・強負荷時main遅れは元のまま。

証拠：開発本体の `verification/engine-pitch/README.md`、`results.json`、`native-lap.json`、`portable-build.json`。聴感評価は行っていない。

ビルドはbundled Python3.12と `CC65_BIN=D:\HomeBrew\CC65\bin`、`PYTHONUTF8=1`。履歴の採用回帰 `verification/right-crop184/verify_adoption.py` は元音指定で承認時そのものを検査する。最新版の通常起動はmanifestの新ファイルを使う。
