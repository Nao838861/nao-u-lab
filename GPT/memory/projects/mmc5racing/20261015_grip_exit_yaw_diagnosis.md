# GRIPで車体が進路へ回ってしまう出口挙動を診断

## ユーザー原文

> むしろ制動中に不自然に曲がる印象を持ってしまったが、回転上限しか変わっていない？制動中によーを左右でうそ回転できる奴が入ってるが、それの影響？ブレーキ中に横を押したら変に曲がるようになった。いままで回転上限で抑えられてたとしたら、すごく回りにくかったって事？今までほとんど回らなかったのはうそ回転のリミットにかかってた？私の理解があっているなら、うそ回転を一回切ってシミュレーションだけで回るようにしてみてほしい。

> ドリフトから戻る時も、気持ち悪くキュっと目の前に戻って、嘘がいろいろ入っていたにしても、以前の最大回転補正が入ってる方がそれっぽい挙動になっていた印象。原因を分析してみて。

> ドリフト中でタイヤがキュルキュルいいながらカーブ進行方向に車を向けて、十字キー左右を離してアクセルを押して、進行方向は上だが車の進行方向がカーブ出口の向きになっているときに、あとはアクセルを踏んでグリップが自然に戻ると車の向きに進行方向が変わることを期待しているのに、車が進行方向に来るっと回転してカーブが曲がれず外側に飛び出すような動き。車の向きに進行方向が変わってカーブを曲がりたいのに車の方が回ってしまう

モードの質問への回答:

> GRIP MODE

温度感は、車体を出口へ向ける操作と、グリップ回復後の進路が結び付かないことへの具体的な違和感。期待は「車体が進路へ戻る」ではなく「進路が車体に追従する」。

## 実コードで確定したこと

GRIPは元から人工ヨー・速度方向補正、A OFF時の角速度減衰、ドリフト用後輪ブレンド、エネルギー回復を使わない。角速度は実タイヤトルク×96の積分と上限制限、車体角はその角速度の積分。人工補正に見える入力依存の回頭も、GRIPではタイヤ力と荷重による回転だった。

前回上限192→288は物理の回転速度にも効く。制動中の回り過ぎだけでなく、復帰時の逆回転も速く許してしまう。低い上限が物理の振れを抑えていた、というユーザーの理解は合っているが、人工補正専用の上限だったわけではない。

補正明示迂回版はPRG113 B200からBBB9..BBCFの23バイトへ飛び、GRIPはA0/E1を0にしてB414のタイヤトルクへ直行する。追加RAM0、診断用基準との差分はPRG113の29バイト。元からOFFなのでGRIP1,336更新で物理状態一致。DRIFT720更新も状態一致、入口13サイクル増。GRIPは2..16サイクル減。最新高速化を含む4条件のMesen検証で保持・拒否0、最小期限余裕76サイクル。

`build_release.py --grip-yaw-limit 288`は旧比較ROMの互換設定で厳密高速化を自動追加しない。今回の比較には`--exact-physics-phase`を明示した。高速化が曲率全域のハッシュを先に検査するため、比較パッチの適用をその後へ移した。ガードを緩めず最新高速化と比較を両立した。

## 出口の操作を再現した結果

初速1280でB＋右60更新→左右・B解放、Aだけ150更新。

| 時点 | 通常192 車体／進路 | 上限288 車体／進路 |
|---|---:|---:|
| 制動の終わり | 60.65°／15.95° | 88.71°／6.33° |
| Aだけ30更新後 | 79.72°／34.84° | 126.23°／9.97° |
| Aだけ60更新後 | 50.82°／52.42° | 79.88°／36.96° |
| Aだけ150更新後 | 51.37°／51.47° | 51.65°／51.62° |

上限288は車体が28更新後に127.08°へ過回転し、その後約52°へ戻る。通常192の最大車体角は83.45°。同じ入力で最終進路はほぼ同じなのに車体の振れ幅が増えるので、旧上限の方がそれらしく感じる指摘に合う。

制動の前後荷重62/2から、加速45更新後8/56へ反転。後輪横力は0→162、前輪は198→30、回転トルクは+234→−165。45更新後の`(30−162)×1.25=−165`が実トルクと一致する。後輪の横力は進路変更と車体の逆回転の両方を起こすが、このモデルでは車体の回転が大きく出る。車体を出口へ向けた姿勢を保って進路を追従させるバランスになっていない。

大きい姿勢差で車体前方速度が小さくなると速度依存操舵も広がり、上限288の制動終了時は22.5°。左右解放後は約8更新で0へ戻る。通常上限は11.51°から約5更新で0。出口へ舵を切り続ける操作ではなく、前輪は車体に沿う向きへ戻る。

28条件・2,352更新でDRIFTも確認したが、後続のモード回答はGRIP。DRIFTの速度方向補正・4更新でのブレンド/上限復帰を、今回のGRIPの主因にはしない。GRIPの指定操作は別途8条件・1,668更新で追跡した。PPU・カメラ・コース外への飛び出しの自然プレイまでは再現していない。

## 教師差分と次回の評価

Codexが外した判断: 前回は回転上限と定常の旋回角を中心に比較し、出口に向けた車体と進路の収束先を評価していなかった。車体の回頭量を増やすことと、出口へ曲がる操作感の改善を結び付けられないまま試作した。

悪い要約: 「ドリフトから戻るのを滑らかにする」。これでは、何を何へ戻すかが逆になっても検出できない。

次回の注意: 車体角を進路へ直接合わせる補正だけで改善したと扱わない。今回の体験目標は逆方向、進路が車体へ追従すること。GRIPは既に補正OFFなので、補正削除で直ると説明しない。摩擦円1.3倍も再導入しない。

検証方法: B＋左右で姿勢を作る→左右/B解放→Aだけ、を代表入力として、車体角・進路角・角速度・前後荷重・前後横力・合計トルクを同時に追う。荷重の極端な振れと回転慣性の係数を、横力で進路を曲げる量との釣り合いとして評価する。強い回転制限を単に撤廃して体感改善と判定しない。

今回は比較ROMと原因分析を完了した。通常版の荷重・慣性・駆動力の数値修正はしていない。期待する出口挙動への改善は次の実装課題として残る。
