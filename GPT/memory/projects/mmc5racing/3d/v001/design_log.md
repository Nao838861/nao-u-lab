# MMC5Racing 3D版の検討ログ

2026年10月16日。今回は仕様検討。ゲームや回路の実装には着手していない。各サイクルの表は、評価30件と、それに対応する改善案30件を記録する。

## 依頼原文

> SuperFXを使って、MMC5Racingの3D版を作りたい。どんな仕様にするのがいいのか検討して。

視点についての返答原文:

> 視点を選べるようにしたい。バーチャレーシングみたいな。

最初に単一の高い追従視点を第一候補として確認したが、ユーザーは選択可能な視点を望んでいる。4視点を後付けの飾りにせず、最小の走行版から成立させる。視点変更が車の物理や操舵の意味を変えないこと、車載の近面と俯瞰の可視範囲を性能条件に含めることへ接続する。

## 検討の判定

第一候補はREADMEの仕様。現行の4輪モデルと2モードを保ち、ユーザーが求める4視点を最小の走行版から含める。最初に解決する実装箇所は、MMC5との同居ABI、60Hz物理と30fps要求の分離、近面クリップ、道路の共通幾何、表示世代の同期になる。

4視点のゲーム性能、2bppの可読性、実機の画面経路は個別の測定・判定対象であり、この仕様検討だけで完成を主張しない。実装へ進む際は、ゲーム制作ルールの着手前調査と試作後の自己判定も適用する。今回の3サイクルは、そのうち仕様の評価と改善案を記録したもので、未実装の操作感を検証済みとするものではない。

## 地面方式についての追加フィードバック

2026年10月16日。依頼原文:

> 私はMODE7的なテクスチャマップも悪くないと思うが、両案実装できる？

直前の回答では空と草の範囲フィル＋道路のフラットポリゴンを提案したが、ユーザーは平面テクスチャによるコース表示も比較候補にしている。「軽量化したい」という要約だけでは、描画表現自体を選びたい意図が落ちる。ポリゴンを唯一の道路描画とする判断を改め、同じ物理・コース・4視点・車と景物で地面だけを選べる仕様にした。

両方式の実装は可能。MODE7風はロール0のカメラと平面地面なら行ごとに一定増分でテクスチャを読める。既存の範囲フィルや単色スパンとは異なり、色の読み出し費用は残る。現行ABI2はGSU ROM経路がないため、テクスチャ格納と待ち時間の追加が先行要件になる。30fpsやポリゴン方式に対する速度優位は未測定。

| 追加評価 | 仕様への反映 |
|---|---|
| 地面だけ差し替えれば同じ運転の見やすさを比べられる | `ground_renderer`を描画要求に入れ、物理・時計・カメラ・物体描画を共通化 |
| 背景と車で透視係数が違うと接地がずれる | 地面の逆投影と物体の投影に同じカメラを使用 |
| コース画像とメッシュを別々に編集すると判定もずれる | 共通幾何から生成し、旧道路マスクとの輪郭誤差を測定 |
| テクスチャは面数を減らしても画素ごとの参照を増やす | 同一解像度とRAM待ちで地面単体／物体込みを測定 |
| 平面テクスチャだけでは坂や丘の隠れを扱えない | 平面コースで両方式を維持し、起伏は地形メッシュへ接続 |
| 色数や解像度が違う比較では方式差を判断できない | 初回比較は256×192、共通4色。軽量設定は別条件 |
| 方式変更にA/Bを割り当てると運転操作を奪う | ゲームではタイトル／設定で選び、比較ビルドに専用入口を用意 |

## 比較試作の実装

範囲確認への回答原文:

> 比較用の試作ROMまで作る

[地面比較v001](../../../../../projects/nes_superfx/demos/ground/v001/README.md)を実装した。Aで地面2方式、SELECTで4視点、Bで停止、停止中の左右で地点を変えられる。既存コースの移植に先立つ楕円コースの比較試作で、車とカメラを共通にした。表示外のRAMへ小画像を置くことでGSU用ROM経路の追加を先送りし、実GSUのRAM命令とPLOTで描画する。

25／50MHzで全4視点・2方式・64地点を画素照合し、実ROMの入力とPPU表示も通過。現状50MHzの採取画像は約15〜20fps。ゲーム本体の30fps達成や、テクスチャ方式の最終採用をこの試作の結果だけで確定しない。実装前の3回の評価と改善、実装経緯、自己判定は試作側に保存した。
