# 古い画面が起動する報告とローカル起動修正

2026-10-19。`D:\HomeBrew\MMC5RacingWeb`、commit `8746cf5` をmainへpush済み。配布版0.2.1。

## ユーザーの原文

> タイトル画面などが付いた最新版になってる？

ROMのハッシュ一致を確認して最新版と返答した後、次の報告があった。

> 手元では前と同じものが起動する

先の確認は同梱ROMと元配布ROMの一致、および検証用ブラウザーでの画面までだった。利用者が開いている実際のページの版は確認できていなかった。成果物の正しさだけを、利用者の起動経路まで正しい根拠にしてはいけなかった。

## 確認した実体と修正

ポート8066の既存Pythonは対象プロジェクトの `tools/serve.py` を実行していた。HTTPから取得したHTMLは新版、ROMもTitlePolish `11ca143f…` と一致した。旧サーバーにはキャッシュ抑止ヘッダーがなく、旧起動スクリプトはHTMLタイトルだけで既存サーバーを再利用していた。ユーザーのブラウザーの内部キャッシュや開いていたURLは直接観測していないため、報告の原因をキャッシュと断定していない。

修正は次のとおり。

- 専用status APIで配信フォルダー・プロトコル・Web全体の内容ハッシュを確認。
- 起動URLを `http://127.0.0.1:8066/__mmc5racing__/build/<内容ハッシュ>/` に変更し、HTMLだけでなくJS・ROM・WASMも同じ版付きパスから取得。
- ローカル全応答をno-storeとし、条件付き要求にも現在の実体を返す。
- 旧サーバー置換時は待受PIDのPythonスクリプト引数が対象の絶対パスと一致することを確認。他アプリを停止・再利用しない。
- 起動処理はWindows PowerShell 5でも読めるASCIIにした。未確認の待受がある時は重複起動しない。検証用の `-NoBrowser` を追加。
- 画面下に `v0.2.1` を表示し、パッケージ生成時に版番号の一致を検査。

ホストとポートは維持するので、名前・タイム・ゴーストの保存先は変わらない。ゲームROM・WASM・リプレイ互換世代2・本番Workerは今回変更していない。

## 検証と現在の起動先

ローカルHTTPの3試験と更新ツールの試験を通過。古いapp.jsを1年キャッシュする応答を実Edgeへ読み込ませ、二度目の取得がキャッシュから返ることを確認。その状態で同じポートを新サーバーへ切り替え、新URLからv0.2.1の自動タイトルを起動した。保存名も維持された。

版付きURLから両モードの走行、ROMダウンロードのバイト一致、初回操作後の音声、名前保存、モバイルUI、通信遮断・保存拒否を確認。版付きURLでリプレイWorkerも動き、両モードを最後まで再生できた。

既存の8066サーバーを置き換え、実際の `tools/play.ps1` から更新版URLを標準ブラウザーで開き直した。作業終了時のURLは <http://127.0.0.1:8066/__mmc5racing__/build/59cb2330ca1eccb4/>。内容が変われば次回の起動URLも変わる。ユーザー用サーバーは起動したままにした。
