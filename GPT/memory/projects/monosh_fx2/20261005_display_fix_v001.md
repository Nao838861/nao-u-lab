# MonoSH FX2：表示修正と最適化のチェックポイント

ユーザーがプレイ後に指摘した5点は、地面の行別横移動、奥行き帯ごとの緑四色、遠景の上下移動、FX画像の縦つぶれ、地面と地上物の高さ。原文と90案の検討は [REVIEW_20261005.md](../../../projects/monosh_fx2/game/v001/REVIEW_20261005.md)。

根本原因はPPUレジスタのBG宛先。BG2の固定V=$2110、地面BG3 H/V=$2111/$2112、遠景BG4 H/V=$2113/$2114を分離した。FB=VRAMの一致だけでは最終合成の誤りを見つけられなかった。今後は `display` の最終RGB照合と原本投影表の照合を維持する。

地面は地上物と同じ65カメラ×81距離LUTの逆引き。ゲーム下端207、地平線111+offsetを共通化し、木・草の0〜3pxのsinkを保持する。512px BGと行別HはworldXと同じ倍率で動く。四つの緑を奥行き帯ごとの異なる2色ペアに分ける。色HDMAはmode 3でCGRAM indexを二度・色low/highを一度ずつ書く。

CPU/GSUの競合を避け、65カメラ×14位相の色表から256byteだけSTOP中にROM→WRAM DMA。Hが同じ行をrunへまとめ、3組の表をnativeで切り替える。CPUのゲームコード・定数・作業領域はWRAM。

Stage更新、敵の描画、自弾判定、EM0経路を65816へ移した。packetは安定ソートを2byte index/keyへ変更、SNES divider、clip積のshift/add、画面内の直接書込を使う。FX2は等倍・半分・1/4の水平UVをpackedで処理し、それ以外は同じQ8.8点参照。Y反転・clipも一致する。

最終ROM SHA256は `ab7781fd9bbd5dbdf728ffd48a56691fbba0d34d98244665f0f46af539af1ef3`。C参照版とnative版は左右・上下・斜め・中立と連射で4,332更新の全状態・有効drawが一致。10試験でFB/VRAM照合2,463回、独立画素照合63場面、低・中・高カメラの最終RGB全画素一致。通常18,000fieldで死亡・復帰、全経路・EM1全状態、自然なボス撃破・次周を確認した。

表示256×180・内部256×192、通常進行平均35.31fps。profile CPU平均10.31ms、通常進行CPU平均11.22ms・最大27.90ms、GSU平均7.99ms・最大18.73ms。全12KiBの56回転送は約5.03msでline 21までに完了。まだ全場面60fpsではなく、処理落ち時はゲーム時間も遅れる。

次の課題は残るCのゲーム更新・ボス・接触判定、任意倍率のGSU描画、最大サイズの原画配置、同色区間描画。現在2枚/bank・高さ128までで近距離に拡大参照が残る。音と実機確認も未実装・未実施。通常DMA量だけ減らしてもCPU/GSU双方の制約は消えない。

再検証は `python -X utf8 projects/monosh_fx2/tools/verify_game.py --equivalence`。起動は [play.cmd](../../../projects/monosh_fx2/play.cmd)、製品ROMと検証標本はプロジェクト内。NES/MSX原本は読み取りのみ。初版の成果は [20261005_playable_v001.md](20261005_playable_v001.md) に保存済み。
