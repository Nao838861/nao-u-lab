# MonoSH FX2：実行可能な移植版 v001

2026年10月5日。ユーザーは「実際にできる範囲で移植を進め」「縦解像度を犠牲にして、画像の一部が切れる形でいい」「表示解像度とフレームレート、滑らかになる縮小以外はほぼ同じ挙動」「ちょっとくらい処理落ちしてもいい」「完成まで一気に進めて」と指示。原文は [REQUEST.md](../../../projects/monosh_fx2/REQUEST.md) へ保存。

[移植ROM](../../../projects/monosh_fx2/releases/MonoSHFX2_v001.sfc)、[起動用play.cmd](../../../projects/monosh_fx2/play.cmd)、[操作・実装](../../../projects/monosh_fx2/game/v001/README.md)、[結果](../../../projects/monosh_fx2/game/v001/RESULTS.md) を作成。Stage 1、地形、EM0/EM1、射撃・反射、転倒・死亡・復帰、9節ボス・撃破・次周まで実装。元のNES/MSXプロジェクトは変更していない。

表示256×180、内部FB256×192・2bpp・12KiB。画像を縦に縮めず上下crop。192行／60fps目標は残る。192行旧プローブでは992bytes不足、実ゲームHDMA付き184行最大量テストでは59bytes不足。180行と固定設定削減で全12KiB・VRAM・guard一致。通常は前後の矩形を32タイル列の縦和集合にして転送し、消去も含める。大きければ1回の全転送へ切替。

CPUコードはWRAM7F、定数・状態は7E。GSU中にCPUが次の更新と安定ソート・UV/clipを準備。地面は普通のBGでカメラ・14相の奥行き帯・グレー階調をHDMA、遠景上段／下段は2速度の横スクロール。可変HDMA表は3組。GSU中にCPUがROM/SRAMへ触らない。

通常進行18,000fieldで9,010枚、平均30.08fps。15死亡・復帰、全9経路、EM1全8状態、敵弾6枠・反射3枠、通常入力によるボス到達・撃破・次周を確認。全8試験で1,359回のVRAM照合、47場面の独立したUV/clip/flipと全49,152画素照合。草の40更新転倒は接触fixture、個別ボス撃破fixtureはHPを書換えず自弾位置のみ設定。Lua fixtureは製品ROMのデバッグ操作とは区別する。

**60fps未達は大きい。** 長時間GSU平均8.25ms・最大19.00ms、通常DMA平均2,426bytes・1.70ms。CPUを分離した2,400fieldでは更新・描画準備が平均18.28ms・最大32.68ms。「CPUは4ms」の仮定はこのC翻訳では成立しない。30fpsへ落ちるとゲーム時間も遅れる。192行化や転送削減だけで解決したと言わない。

GSUは任意倍率の点参照。2枚/bankへ置くため原画の高さ128までで、近距離に拡大参照あり。以前のプローブの同色区間・packed等倍/半分/1/4の最速経路は未統合。CPUのネイティブ化と合わせて次の改善箇所。Mesen2.1.1標準GSU100%、実機未確認。

起動は`play.cmd`。専用Mesen設定で左右矢印、上＝下降／下＝上昇（NES原本どおりリバース）、X連射、Z単発、Enter一時停止。元のMesen設定は変えない。ビルド・全検証・保存は `python -X utf8 projects/monosh_fx2/tools/verify_game.py`。casfxはcommit・SHA固定、通常ビルドは固定済みソースと画像だけで可能。

ROM SHA256 `abad2e99994b8b167d635f64999d1e54bec19defee2ac6135f4bc427090fc4ed`。`build/` / `.cache/` はgit対象外、成果物は`releases/`と`game/v001/results/`へ保存。

検証時の注意：Mesen Luaの`masterClock`はuint32で約200秒でwrap。CPUとGSUの同時起動〜合流をCPU単独やGSU単独として扱わず、CPU終了位置とGSU STOPで分ける。wrapは時間差の剰余で補正。起動初期のWRAMをゲーム状態と数えない。C原本変換の`*bottom_y`と`bottom_y`の置換順に注意し、実接触→転倒のような仕様テストで検出する。
