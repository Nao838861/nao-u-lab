# 2026-10-06 地面の指定RGBと縦列配色の修正

依頼原文：
> 地面の色に違和感があるので直して。
> 暗い方から順に、RGBが
> 114,193,112
> 129,208,127
> 145,223,145
> 160,241,162
> 暗いほうの二色と、明るい方の二色がそれぞれ縦に並んで奥に繋がっていて、　一番暗いのと一番明るいのがとなりどおしにいる配置。詳細は添付画像を見て。

温度感：配色の違和感をRGBと配置で具体的に指摘。失敗した判断は「緑系の四色を置けばよい」と考えて、同じ列に暗色と明色を交互に並べたこと。悪い要約は「地面を明るくする」で、縦列と横隣接の指定を落とす。

build_ground.pyで指定RGBを暗い順に保持し、RGB5の展開値に最も近い色を使う。実際の表示RGBは115,189,115／132,206,123／148,222,148／156,239,165（#73BD73/#84CE7B/#94DE94/#9CEFA5）。8bit指定値との最大成分差4。空は#C673FFのまま。

暗い列は1/2、明るい列は4/3で奥へ続き、横は1/4・2/3が隣接する。奥行き方向の並びは `1 4` → `2 3` → `1 4`。SNESのCGRAM65（pixel1）は明列、67（pixel3）は暗列。14相アニメーションと直線パースの座標を維持する。

次回の注意：四色が揃うだけで完了にしない。指定RGB、縦の明度グループと横のペアも確認する。今回verify_game_display.pyへこの配置の独立チェックを追加した。

検証・自己評価：三カメラそれぞれの最終61,184画素、play360/display720fieldのFX/OBJが一致。65カメラ×14位相・62,790地面行で両色ペアを確認。前版のplay/display全4,177計測レコードが一致し、ROM差分49,932bytesは色定数8bytes・色HDMAの色値・checksumだけ。CPU/GSUコード、幾何、OBJ絵、HDMA構造は同一で処理負荷は増えていない。目視でも暗列と明列が奥へ続き、濃淡と黄味の差が参考に近づいた。

今回ROMは `1dfedc985036b201e5f32cef9a771389027c94fc21e550f56d5b0d9fc7c37bdc`。正本は [RESULTS.md](../../../projects/monosh_fx2/game/v001/RESULTS.md)、[今回の検査](../../../projects/monosh_fx2/game/v001/results/palette_20261006/summary.json)、[依頼・判断](../../../projects/monosh_fx2/game/v001/DESIGN_LOG.md)。配色前の全11試験・長時間57.05fps・全転送の基準hashは7a0a0c5d。以前の試験結果を新ROMで再計測したとは書かない。release manifestは今回play/displayと基準ROMを区別した。

次回の成果同期はnao-u-lab作業ブランチと独立MonoSH_FX2 mainの両方。新しい実装変更をする時も、空の紫・暗列/明列・極端な色の隣接を保存する。
