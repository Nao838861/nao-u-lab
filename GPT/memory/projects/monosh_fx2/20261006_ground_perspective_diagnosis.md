# MonoSH FX2：地面の格子が直線にならない理由

ユーザーの指摘原文：

> 地面のパースがなぜか直線ではないのが気になっている。何か理由がある？

通常BGやFX2の制約ではなく、現在の地面テーブル生成方法に原因がある。今回は原因の確認だけを行い、ROM・描画コードは変更していない。添付画像は目標となる見た目の参照として扱い、その画像を現在の移植ROMの出力とは断定しない。

実装は [build_ground.py](../../../projects/monosh_fx2/tools/build_ground.py:26) で基準行127〜207ごとに、木の接地Yが最も近いZを探す。そのZの原本 `monosh_projection_full_scale` に32を掛け、Q8から整数へ丸めて格子幅を作る。地面の横境界は整数幅の倍数で生成される。幅の増加は画面Yの一次関数になっていない。

|基準Y|現在の格子幅px|地平線127で0、下端207で51となる直線の幅px|
|---|---:|---:|
|127|4|0.00|
|135|8|5.10|
|151|21|15.30|
|175|34|30.60|
|199|46|45.90|
|207|51|51.00|

比較列は歪みを説明するための直線であり、修正仕様として決定したものではない。実データは整数幅が1行で最大3px変化し、格子境界が中心から離れるほど幅の誤差が倍増する。遠端でも幅4pxが残るので、地平線の一点に収束しない。木の接地YからZを最近傍で選ぶ処理と整数丸めも、折れや段差を増やす。

さらにカメラ変更時は、地上物と共通の距離表を逆引きしてBGの行を再選択している。この離散写像も境界の形に影響する。原本の接地・倍率との対応を優先した実装であり、平面の透視投影として整合することまでは保証していなかった。原本NES/MSXの地面そのものが同じ曲がり方をしているとは、この調査では判断していない。

既存の最終RGB検証は「PPUが指定した表どおり表示する」「原本の投影表と対応する」を検証するが、「格子の縦境界が一本の直線」「全境界が同じ消失点へ収束する」は検証していない。

修正時は、画面行と地平線から格子境界を固定小数点の一次式で求め、境界位置で最後に整数化する。カメラ変更時の縦写像と横スクロールも同じ投影に揃える必要がある。地上物の接地を原本のまま保つ場合のずれは別途測定する。通常BG＋HDMAと事前計算表を維持できる方針で、FX2による地面の毎フレーム描画は必須ではない。

確認は生成済み `fx_ground_width` と原本の木geometry／倍率表の読み取り、および保存済み中間カメラ画像の観察。再ビルド・エミュレータ試験は行っていない。
