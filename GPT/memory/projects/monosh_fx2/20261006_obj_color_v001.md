# 2026-10-06 自機・自弾のカラーOBJ化

依頼原文：
> プレイヤーはスプライトにしている？スプライトなら色を付けてほしい。プレイヤーの弾も。

依頼の意図：既にOBJなら、その自由なパレットを使って自機と弾をカラーで見せる。失敗した判断は、OBJ化しても以前のFX用白黒PNGを流用したため、カラーにできる表示資源を活かしていなかったこと。悪い要約は「スプライト化する」で、既にOBJになっている事実と色の追加を落とす。

元NES CHRの色番号を復元し、MSXの上／下半身パレット規則と死亡poseの移動を参照。赤い服・青い脚・肌色・白を固定インデックス原画へ保存し、弾は橙・黄・白。17pose＋弾の元透明マスクを全pixel比較して保存した。4bpp CHRの配置・枚数・有効15,104bytes、毎画像OAM68bytes、priorityと当たり判定を維持する。起動時16色32bytesだけ設定する。

検証・自己評価：play360、display720、objects360、全12KiB＋最大OBJ360fieldを確認。17pose・四反転・16弾サイズ・画面端・点滅の85場面、66実PPU画面・15,649画素・8不透明色とCGRAM全値が一致。三カメラの最終RGB各61,184画素も一致。全転送は20行完了、22行OBJ準備、23行表示。GSU/CPU本体/実行時データは前版とbyte一致。play/display計4,177計測レコードのうち起動直後10件だけ0.01ms未満の位相差、残り4,167件一致。28field以降は全項目一致。目視で赤い服・青い脚と黄色い弾を確認。通常の57.05fpsは以前の長時間試験であり、今回の色ROMで長時間・C/nativeを再計測したとは書かない。

次回の注意：白黒のFX素材とは別に、OBJ用インデックス素材とRGB5パレットを使う。色を変えてもCHRとCGRAMを毎画像で転送する必要はない。地面の指定RGB・列配色と空の紫を保存する。
