# ボス戦最悪負荷と連続60Hzの枠

2026年10月7日。依頼原文：

> ボス戦の一番処理落ちするところは、60fpsまであと何%最適化しないといけないか計測できる？

最新版ROMをD:\HomeBrew\Mesenの同一バイナリ、GSU100%、NTSC、通常パッド入力で観測。通常進行18,000field＋ボス戦で射撃を止める18,000field＋固定設定/OAMの720field。ボス戦11,371画像、FB/VRAM・guard1,768回、別描画とOBJ110場面、時計227,910点を検査した。ROMは入力修正版のまま。性能を改善した結果ではなく、必要改善量の計測。

最悪GSUは19.129431ms。通常進行の同時CPUは8.440085ms、射撃停止では7.757689ms。死亡中だけでなく生存中にもGSU19.078959msがある。最悪はFB3,792bytes/7区間、14コマンド。最も重い60field窓は30画像（約30.05fps）。

単発の現在の締切にはGSU14.845msまで使えるので22.4%短縮となるが、連続60Hzの目標には使わない。220行までのDMA開始猶予を次の画像にも足すと、次の描画開始が遅れることを見落とす。

連続更新は前DMA＋次の描画準備＋max(CPU,GSU)＋合流後の準備＋固定設定/OAMを1fieldへ収める。1field16.639264ms、非並行部分約2.879602ms、GSUの枠約13.759662ms。**GSU時間28.1%短縮（速度39.0%向上）が必要。1行の余裕を入れると28.4%、開発目標は30%短縮（速度42.9%向上）**。30%短縮で13.391ms、約0.369msの余裕。今回のボス全画像ではCPUの必要短縮率は0%、まずGSU全体を改善する。

GSU時間は消去・clip/UV・縮小描画・DMA範囲生成を含む。画素ループだけを改善するなら、その比率を計測する必要がある。最適化後は処理と入力の位相が変わるため、同じ種類の長時間入力で毎field提示を再検証する。全入力や実機の最悪保証ではない。
