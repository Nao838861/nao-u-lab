# 2bppの敵・障害物のカラー化試作

2026年10月8日。ユーザーの依頼は、指定録画から原画を切り出して透明＋3色へ変換し、CPUが奥からネームテーブル属性を上書きして8×8単位の色を再現すること。SELECT切替の対象は、確認への回答原文「2bppの敵・障害物だけ」。自機・地面・空・遠景は対象外。

正本は [結果](../../../projects/monosh_fx2/game/v001/RESULTS_20261008_BG_COLOR.md)、[依頼原文と三巡×30項目の検討](../../../projects/monosh_fx2/game/v001/COLOR_DESIGN_20261008.md)。起動は [play.cmd](../../../projects/monosh_fx2/play.cmd)、SELECTのキーボード割当はSpace。更新後は旧ステートを読まずROMを開き直す。

13素材を録画から切り出し、既存の25原画へカラー番号・透明部分を用意した。爆発の差分と砲台開閉の5ポーズなど、録画で取り直していない形は既存alphaを保持して色を割り当てる。録画hashと時刻・矩形・RGB5の8組は `game/v001/assets/bg_color/source.json`。原画寸法は維持する。ボスの一部は隣の節・地面を除くため既存外形をマットとして併用。

GSUは2bppのまま。CPUはpacket.sの安定ソート順と同じQ8.8・反転・clipで、出力8×8の中心に対応する原画セルのパレットを上書きする。前後の絵が同じセルへ入ると、奥の画素も手前の色組を共有する制約が残る。タイトルと影は灰色パレット0で描画順を守る。OBJは除外。

属性768bytesをCPUで2面保持し、パケットと同時にラッチして世代を揃える。転送は高位byteを1回にまとめる。裏VRAM表へ黒帯で先送りし、FB転送完了時に表を切替。全12KiBと属性が同時に入らず事前準備もできない時は別fieldへ分ける。CGRAMは32〜63番の64bytesだけを切替。

**カラー化は実装したが60Hz未達。通常操作31.62fps、ボス撃破から次周を含む試験33.96fps。CPU負荷によりゲーム進行も遅くなる。モノクロでも属性計算は続く。** 変更前の60Hz検証済みROMは `releases/MonoSHFX2_pre_color_20261008.sfc` に保存。次の優先はCPUの座標準備・行処理の短縮で、現行版へ以前の60.10fpsという評価を流用しない。

最終ROM SHA256は `4ef5a95fec70a4ee3dfcf3b9f39ea38180aa138fd44b7709fed8b21704197025`、2MiB。カラー用WRAM実使用4,508bytes、予約0400..17ff、Cスタック1800以上。CPU CODEは0000..fe75で残量確認が必要。表示256×180、内部FB256×192・2bpp、OBJと地面・遠景を維持。

Mesen 2.1.1・NTSC・GSU100%・追加scanlineなし。同じROMで9試験9,600field。178画像・136,704セルの独立したCPU属性／VRAM照合、CGRAMのカラー→モノクロ→カラー、三カメラの最終PPU全画素、packedの端数、多数矩形と全12KiB、全17pose・反転・自弾16段階、操作・ポーズ、ボス撃破から次周を検証。実機は未検証。全標本・測定は `game/v001/results/bg_color_20261008/`。
