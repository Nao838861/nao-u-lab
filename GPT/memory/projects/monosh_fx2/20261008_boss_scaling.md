# ボス限定の縮小画像と追加最適化

依頼原文：「ボス系のみに変えて、その後最適化を進めて。」

正本は [結果](../../../projects/monosh_fx2/game/v001/RESULTS_20261008_BOSS_SCALING.md)、[実装](../../../projects/monosh_fx2/game/v001/gsu.s)、同所の `results/boss_scaling_20261008/`。コード・測定済みROM・生成Lua・生ログのhashを対応させる。

- 事前縮小はボス胴13・顔14・弾31の幅1..96だけ、406,800bytes。草・木・通常敵の縮小画像は撤去し、最大原画からのQ8.8最近傍に戻した。
- 非ボスは行ごとの透明な左右余白だけを32,536bytes追加。画像ではない。両端だけ省き、内部透明・反転・clipのfallbackと描画順を保つ。合計439,336bytesで約203KiB削減、ROMは2MiB。
- 汎用のROM先読みはPLOT/LOOPに次画素の待ちを重ね、GETCをdelay slotへ置く。scaled/generic/余白省略/準備を511bytesへまとめ、packet展開の前半63bytesだけCBRを変えずcache外から呼ぶ。
- DMA受付はW=bytes+64*区間数+768により203/220/226/233行。六つの上限を専用ROMで意図的に最終受付行から転送し、20行以内の完了・22行OBJ準備を検査する。
- 既存画像で固定523場面2,457画像の全FB/OBJと以前のFBハッシュが一致。通常入力18,000fieldでは全区分で提示遅延0、60.10fps。道中の観測最大GSU16.481→12.880ms、約22%短縮。固定ボス11.459→11.780msの約2.8%増はcache配置の費用。

同時進行の大きい録画自弾・二重遠景は、別ROMとして統合検証する。既存画像版の測定を新画像版の60fps保証へ読み替えない。表示256×180、内部FB256×192・2bpp、ゲーム時間の仕様は変えない。任意の入力・実機・192行表示・音は未解決。
