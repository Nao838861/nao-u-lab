# 二値モノクロと自機の服の透明穴

2026年10月9日。原文・比較・検証は [結果](../../../projects/monosh_fx2/game/v001/RESULTS_20261009_BINARY_PLAYER.md)。ユーザーは「黒ではないグレーのパレットは白にして二値」「ズボンや背中になぜか抜き色になっているところ」を修正するよう依頼。

ローカル親リポジトリは公開mainより古かった。公開main `4a0fa27` のGSUカラー描画最適化・配色整理・SPC BGM第2版を親へ取り込んでから修正した。古い約30fpsのCPU属性版を現行と誤認して差分を積まない。4bpp実験分岐には反映していない。

2bppモノクロは全8組を透明0・純黒1・純白2/3とする。index1はパレット値0でも不透明。SELECT／Spaceは引き続きFX2の敵・障害物だけに効き、自機・自弾の専用カラーOBJはそのまま。

透明穴の原因は背景の紫色相と色差45による抽出で、服の青紫も背景へ分類していたこと。青系の服を保護し、その場合の背景距離を30へ狭めて同じ8フレームから取り出し直した。32×48の176画素を復元、以前の不透明画素と原寸矩形8枚は完全維持。輪郭外や脚間を一律に埋めない。RGBAの透明とPNGパレットのindex、PPU表示を別々に検査する必要がある。PNGとCHRの一致だけでは、壊れた透明マスクまで正解として通してしまう。

検証は服28代表点・透明4対照点、色切替200標本/153,600タイル、17姿勢/四反転/16弾サイズ、実PPU66画面72,664画素、左上＋Y900フィールドで899論理更新。ROM差分は452bytesでmono定数・OBJ CHR・checksumのみ、CPU/GSUと音源領域byte一致。既存126枠/16,128bytesで転送量の増加なし。再生成・再ビルドも一致。新しい長期60Hz測定は今回行っていない。
