# NES版とMSX版の弾XY判定差分

ユーザー: 「NES版に比べて弾のXY判定が大きい気がする。何か違う？」

現在の作業ツリー同士を静的比較した。ゲームコードは変更していない。ROMのASM実行経路とNES側makefileのCOLLISION_USE_ASMを確認。

- NES `src/check_collision.s:394` 付近（C参照実装 `src/game.c:1918`）: 自機弾中心の点と対象の矩形を照合。Xは対象半幅、Yは対象上端〜下端。通常敵・背景物に固定6pxの追加はない。NESのXはVBUF単位なので画面座標との換算が必要。
- MSX `src/monosh_enemy_fast.asm:1131`: Xは画面上の幅/2＋6。Yは高さ＋6を半径として扱い、`:1203` 以下で弾Yと敵下端の絶対差を比較。通常の画面内・8bit加算が溢れない範囲では、敵下端B・高さHに対して `[B-H-6, B+H+6]`。見た目の矩形 `[B-H, B]` より特に下側が大きい。3弾スロットすべて同式。
- MSX背景物 `src/monosh_stage_fast.asm:1328` / `:1474` と代替経路 `:1605`: X半幅＋6、Y上端−6〜下端＋6。遠方でも6pxは固定。
- MSXの通常敵サイズ表は `tools/generate_enemy_data.py:187` のgeometry_by_depthで画面幅・画面高さを生成する。サイズを滑らかに補間するため、NESの離散サイズ表との違いもある。
- Zにも別の差がある。MSX通常敵は `abs(enemyZ2 - bulletZ*2) <= 32`、背景物は同様に16以内。NESは前回から今回までの弾Z区間（速度4、敵は4倍精度への換算）を照合する。横幅だけ変更しても同一判定にはならない。
- 敵弾→自機のXY閾値は一致: Xの差に10を足して28未満、Yの差に20を足して61未満。NES `src/update_bullets.s:449` 付近、MSX `src/monosh_enemy_fast.asm:910` 付近。タイミング等を含む完全同一性まではこの確認で主張しない。
- ボスは専用経路。MSX `src/monosh_boss_prepare.asm:237` 以下は半幅・半高さの矩形で、通常敵の固定＋6・下端中心の式は使わない。

結論: 自機弾について「MSXの方が広い」はコード上の根拠がある。特に通常敵のY範囲はNES移植として不一致。調査のみで修正・再ビルドは未実施。
