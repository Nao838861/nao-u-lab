# MonoSH NESFX v001

2026-11-08、ROGXbox上で作った独立プロジェクト。SFC版 MonoSH_FX2 の2bpp版を参照した、ファミコン用の最初の動作する縦切りです。完成移植ではありません。

## 今回できたこと

- 採用済みMode7 + SuperFX相当回路を変更せず、256×192の立体地面とGSUスプライトを合成。
- 紫の空、緑2色の市松地面。現行の「4色＋抜き」を維持。
- SFCの実素材6種を使用。EM1、顔型ボス、Tree0、自機、自弾、爆発。32×32に縮小してRAM常駐。
- 敵3体の接近・拡大と奥から手前への描画、左右の木、自機移動、4発の連射、当たり判定、爆発、敵弾、得点、残機、ポーズ。
- SFC曲の旋律・伴奏・ベースをMMC5矩形波2ch＋APU三角波へ移植。APU矩形波＋ノイズの試作SE。

移植したのは素材・曲の3声部・描画の考え方です。今回のゲーム進行、判定、地面、6502プログラム、RAM用GSU描画ループは新規です。元ゲームの全ロジック、全ステージ、ボス行動を移したものではありません。木はまだ左右固定のテスト配置です。

## 成果物

- `build/MonoSH_NESFX_v001_UNTESTED.nes`: 1,179,664 bytes。UNTESTEDは実機未確認の意味です。ソフトウェア試験は実施済み。
- `results/runtime/screen.png`: 最終ROMを専用Mesenモデルで動かした画像。
- `src/`: 6502ゲームとGSU描画ソース。
- `assets/`: 元画像の出典・色復元・変換結果・透明マスク。
- `audio/`: 音源移植ソースと検証結果。
- `RESULTS.md`: 試験範囲、測定値、残課題。
- `IMPLEMENTATION.md`: ハードウェアABI・色・メモリ設計。

通常のNROM用ROMではありません。iNES mapper=0のヘッダですが、専用FPGAマッパーが必要です。標準エミュレータでは動作しません。既存ROM、SDカード、RBFには書き込んでいません。

## 操作

- 左右: 自機移動。
- 上: 下降、下: 上昇。参照版の逆上下操作を維持。
- AまたはB: 連射。
- Start: ポーズ／再開。再開時のBGMは先頭からです。
- 残機0で残機3・得点0へ戻る簡易ループ。タイトル／ゲームオーバー画面なし。得点表示は16進2桁。

## 色の扱い

共通slot0=NES $09（暗緑）、slot1=$30（明色）、slot2=$19（緑）。slot3だけ地面=$16（赤茶）、空=$14（紫）。地面textureの生indexは3/2で、回路の変換後はslot0/2です。

このため透明部分を含む8×1区間でも地面の2色は維持できます。一方、物体の赤茶は空側で紫になります。木の暗緑輪郭が暗い地面へ溶けることも表示画像で確認しました。この試作で色の問題が解決したとはしていません。地面3色案や任意8×1属性は未実装です。次段階は、明暗差を強めた木の輪郭と、空／地面を跨ぐ物体のslot3配分を比較することです。

## ビルド

Windows + Python 3 + Pillow + cc65を使用。既存ROGXbox環境では `python build.py`。cc65を別の場所で使う場合は環境変数CC65_BINをbinディレクトリへ設定してください。フォントはWindowsのConsolasをビルド時に読みます。変換済み素材と楽曲を同梱しているので通常ビルドにSFCリポジトリは不要です。

素材や曲を再変換する場合だけ `reference/MonoSH_FX2` に下記コミットを用意し、`python tools/convert_assets.py` と `python audio/build_audio.py` を実行します。各ツールの引数／依存はそのソースを参照。

試験: `python tests/test_cpu.py`、`python tests/test_renderer.py`、`python tests/test_runtime.py`。CPU試験は既存py65、RTL試験は既存GHDLと採用RTL、表示試験は隔離した専用Mesen DLLを参照します。既存ROGXboxパスは各スクリプト先頭に記載。移動先では調整が必要です。runtime DLLは配布ZIPに含めません。
