MonoSH NESFX v017 / 地面の透視・左右スクロール・NES自機色

起動
展開したフォルダの START.cmd を実行してください。Windows 10/11 x64用の専用Mesen同梱版です。
通常のNESエミュレーターやNES実機用のROMではありません。専用DLLとROMを組み合わせて使います。
既存v016、通常Mesenのフォルダ、SDカード、RBFは上書きしていません。

今回の表示修正
・地面は暗緑$09・明緑$29・中間緑$19の3色です。紫の空は$14、背景物体は共通の緑2色＋灰$10を維持しました。
・上下でカメラ高度が変化し、近景と遠景の格子の大きさが変わります。画面を上下へ平行移動するだけの処理ではありません。
・原作のground_offset 0〜32に合わせて高度384〜160、正規化したピッチを使い、元の地平線位置を維持します。
・左右の地面は、原作の操舵量に従って流れ続けます。自機が画面端で止まっても横移動は止まりません。死亡で世界が停止すると地面の横移動も停止します。
・元NESの8x16 PPUスプライトを保持。自機パレット1=$11,$28,$15、パレット2=$21,$33,$11、影は黒、弾も元の色に戻しました。
・背景用の共通色$09を誤って黒にしないよう、PPUの$3F10→$3F00ミラーも考慮しています。
・敵の赤い目はまだ変更していません。

操作
元NESの操作とゲームロジックを保持しています。上下は元ソースの飛行機式リバース操作です（DOWNで上昇、UPで下降）。
左右移動・Aの射撃・START/SELECTの元の意味も保持しています。キー/パッド割当はMesenのInput設定で確認してください。

検証
・601回のpre-core_tick境界でv016と比較。原作151項目850バイト、元OAM256バイト、入力edge、NMI/logic/drawタイミングがすべて一致しました。
・33高度×192行＝6336行で、専用D10の固定幅計算と汎用透視計算が完全一致しました。
・全33高度で地面の出力が3色だけであること、地平線、横移動方向、循環境界の中間補間を確認しました。
・元のCHR2バンクはバイト単位で一致。実PPUパレットRAMも元NESの自機・影・弾色と一致しました。
・preview/ の約16秒動画は実PPUの960fieldを直接記録しています。動画側の補間やフレーム水増しはありません。
・動画は通常の入力だけで動かし、RAM書換えや無敵化はしていません。衝突と死亡・復帰も含みます。静止画4枚は低高度・高高度・左・右の状態です。

制限
今回の優先は見た目です。全編60fpsを保証する版ではありません。元NESゲームロジックは約30.05Hz、表示は60.098Hzの中間補間方式です。
v016では密集場面のCPU負荷による表示欠落が残っています。今回の601境界の一致は全ステージ・全入力の保証ではありません。
確認したのは専用Mesenの機能・タイミングモデルです。FPGA/NES実機、SDカード、RBFへの適用、実機のバス競合や転送速度は未確認です。
今回のカメラは既存のD10レジスタ経路を使い、新しいハードウェア機能は追加していません。モデルの一致を実機実測と混同しないでください。

ソース・再ビルド
source/game が本版のゲームソース、source/custom-core が専用コア差分です。元NESのゲームソースは変更していません。
Python3、Pillow、cc65が必要です。CC65_BINをcc65/binへ設定してbuild.pyを実行します。フォント生成にはWindows Consolasを使用します。
tools/test_visual_v017.pyとtools/compare_v016_v017_controls.pyが今回の検証です。検証には元v016フォルダとローカルMSVC環境を参照する部分があります。
source/Mesen2_host-source.zipはMesen本体ソースです。DLLの再ビルドには同梱core差分と既存のローカルビルド環境が必要です。
