Space Harrier r11 PerformancePass2 SkyA / Windows

ZIP全体を新しいフォルダへ展開しPLAY_R11.batまたはPlay_R11.exeを起動してください。
過去のセーブ状態は互換ではありません。旧ROM/DLLとの混在も避けてください。
操作: 矢印=移動、Z=ショット、X=NES B、Enter=通常/ボス切替、右Shift=無敵切替。

空は採用案A（NES $23 / #C676FF）。地面3色と木草の色は前版のままです。

実測（専用Mesen、固定位置・無敵・同じ射撃入力、6000 NTSCフィールド）
平均表示更新 57.945 → 59.728 fps
遅延カウンタ 205 → 35、表示キュー破棄 9 → 1
敵と木草の密集した固定5秒区間 51.08 → 57.90 fps
別の密集区間 53.69 → 59.10 fps
常時60fpsにはまだ達していません。操作やシーンにより処理落ちは残ります。
同じ実時間入力ですが進行が速くなるため、部分区間は完全に同じ敵配置の比較ではありません。

変更
木草の重複した投影・事前カリング、敵の固定8スロット処理、ボス描画、UVクリップを短縮。
常にゼロの座標上位バイトは起動時に明示的に初期化し、毎フレームの生成/転送を省略。
OAMは5つの不変スナップショットページを使い、二重コピーを削減。NMI中の所有権移動も再確認。
GSUクロック、転送モデル、画像素材、ゲームAI/衝突判定、音楽更新頻度は変更していません。
地面・石・EM0・ボスの既存の見た目と中間位置修正を維持します。

原因
敵と木草が重なる通常場面はCPUのゲーム更新と描画準備が主因です。
元版の代表密集窓はCPU更新+描画準備が平均約17.45ms、16.64msの予算を超えました。
同じ元版密集区間のGSUは最大約7.53ms、アップロード開始〜転送完了は最大約11.32msでした。
ボスではGSU最大約11.63ms、アップロード+転送まで最大約15.43msと余裕が小さくなります。
ただし実測のGSU締切超過は0で、次の描画パケットの生成/アップロード供給の遅れが中心です。

検証
通常3500更新・ボス1000更新で867bytesのゲーム用RAM、カメラ、実OAM、両方で発行された描画パケットを照合。
キュー抑制の異なる更新はパケット比較から明示的に除外。実フレーム数と音楽カウンタは速度差により異なります。
OAMは所有権遷移の割込み位置1451箇所、1500回の実NMIレジスタ/復帰保持、1497回の実DMA等を検証。
命令差分、非ゼロ初期RAM、転送中NMI、移動/射撃、再スタートの確認結果をverificationとsourceに同梱。
実機/FPGAと全ゲーム全条件の長時間検証は未実施です。
ランチャーは再構築とハッシュ埋込みを確認しましたが、GUIを開く起動試験はしていません。
