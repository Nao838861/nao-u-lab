# 最新 v034＋6音声を維持した赤目の独立試作

基準は `MonoSH_Audio_v002_v034`。成果は研究版 r3。**赤目と背景保護の動作は確認できたが、描画負荷が増えたため正式統合は保留**。実機・SDへの操作はしていない。既存ROM、DLL、RBFは変更していない。

## 絵・透明・音の保持

元候補の18素材、31,142テクセルを比較した。敵Em1の瞳16画素、Em0の元SFC画像から得た瞳47画素だけを、既存の暗色3から不透明な追加色4へ変更した。Em1は従来承認済みの瞳座標を高精細画像へ投影、Em0は元SFC画像の赤い目を使用。敵・木の解像度、座標、透明領域、その他の画素値は同一。ボスは瞳の意味領域をまだ確認できていないため、全体の茶色などを目と誤認して変更していない。

8×1ブロックごとに露出する背景を優先し、赤に差し替えるパレット番号3が背景に必要なブロックでは赤を使わない。この場合、目は元と同じ暗色へ戻す。空と地面の共通色をそろえたパレット2の3番だけを `$16` にする。地面の中間緑 `$19` と空の紫 `$14` が露出したブロックは元のパレットを使う。背景を赤くして目を維持する処理はない。

追加色はGSUの低2ビット0＋不透明マスクで表す。色4のときだけCMODE `$11`、通常／透明色は `$10`。オブジェクト開始時も `$10` に戻す。近距離・遠距離で使うbyte samplerの双方に対応。4px級では最近傍縮小が瞳そのものを拾わない場合があり、全距離で赤が必ず見えるという意味ではない。

元の圧縮／非圧縮素材の選択を維持し、RLEの色を3bit化。最長ランを32に分割し、完全一致する行バイト列・部分列を共有した。画像の低解像度化や再減色はしていない。

| 項目 | 使用量 |
|---|---:|
| GSUコード | 482 / 512 B |
| 画像＋メタデータ | 6,930 B |
| うち共有行プール | 2,530 B |
| 画像領域末尾の行キャッシュ予約 | 64 B |

PRG音声バンク89～99とCHR-ROMは元候補とバイト一致。MMC5音声ルーティングを含む `NesRacingFx.h` も一致。元候補の音声関連ファイルなど24入力の保存済みSHA256が変わっていないことを確認した。新ROM上で音声ドライバの2周・29,973フレーム、6チャンネル、7効果音、バンク復帰と優先順位を再検証して合格。最大audio_tick 1,755 CPUサイクル。30秒動画の音声はピーク6,912／32,767、クリップ0、無音ではない。

## 検証と範囲

- `gsu_oracle.json`: 実際にアセンブルしたGSUを専用Mesenの変更していないGSU実行エンジンで実行。全18素材の4～112px、反転弾、元／中間ボス寸法、UV端数、stride境界など215条件、21,135,360画素比較が一致。期待値は圧縮前の独立画素列から計算。
- `compositor_oracle.json`: 現行C++合成式と、実際の `racing_display.vhd` state10から抽出した式の131,072条件、1,048,576画素比較が一致。空／地面の全背景bitplaneパターン、再現可能な前景／不透明マスクを試験。
- `rtl_gsu_oracle.json`: 実際の `racing_gsu.vhd`＋GSU RTLを関連50/25MHzクロックで実行。17×23の小型敵、32×32の別敵、ボス顔／胴、木の5コマンドを描画。全16KiBの面データ＋16KiBの不透明マスク読み出しが独立期待値と一致。赤目マスク36bitを確認。GSU RTLのSHA256はfit済み赤目v2のものと一致。これはPSRAM、PPU外部波形、実機の試験ではない。
- 動画は元のSelect操作だけで無敵を有効化し、同一入力1800フィールドで通常敵→ボス→通常敵を通した。ROMの無敵化パッチやRAMへの制御値書き込みはしていない。音声チャンネルの音量設定はすべて100。

## 負荷の未解決

以前の約27.5msのアトラス／プログラム切り替え処理を使わず、同じアトラスと482Bプログラムのままボスへ入れる。ただしRLE3のラン分割とbyte sampleごとの追加色処理が、赤目のないRLE素材にもコストを足す。

| 同一条件 | 元候補 | 赤目r3 |
|---|---:|---:|
| Em1、112×120、GSU50MHz換算 | 5.391ms | 6.616ms |
| Em0、112×120 | 4.638ms | 5.840ms |
| ボス胴、元寸法80×54 | 2.556ms | 3.184ms |
| ボス顔、112×120（packed） | 5.803ms | 5.803ms |
| 30秒のdeadline_misses最終値 | 20 | 63 |
| queue_drops最終値 | 22 | 72 |
| queue_starvations最終値 | 2 | 9 |
| present_count最終値 | 1786 | 1736 |

全215条件中の最大倍率は回転弾27・112×120反転で1.495倍（4.888→7.310ms）。ボス胴の64元／中間寸法条件を含む全試験値は `draw_cost_by_asset.json` と `gsu_oracle.json` に保存した。packedの木やボス顔はほぼ同じ時間。RLE素材まで一律に追加色処理を通す設計を改善する必要がある。小さい敵の正しい画素が描けても、60fps維持にはそのまま採用できない。

動画の出力周期60.0988HzはPPU記録の周期で、毎回新しい描画が完成する証拠ではない。元候補と同じ操作でも締切／世代／位相が分岐したため、1800フィールドのRGB全体差分2,375,814画素を「目だけの差」とは扱わない。目以外の静的画素保持は素材比較・GSU oracle・背景合成oracleで確認した。実写PPUの赤 `$16` のRGB `(181,49,32)` への変化は元の暗緑 `(11,72,0)` からのみ9,924画素観測したが、全フレームの動作一致は成立していない。

## FPGAの成立範囲と残る実機条件

新しいRLE3はソフトウェアの変更で、GSUの新命令や新回路を要求しない。赤目表示式とGSU RTLは前回fit済みv2と同じ。新たなQuartus fitを実施したという意味ではなく、同一回路の既存結果を再利用している。以前の393/392 LAB超過を解消したseed2回路は、392/392 LAB、6,222/6,272 LE、222,464 memory bits、DSP9 29/30。最小setup 0.736ns、hold 0.123ns。対応する既存RBFはsha `0740d5ff1f7856665484637206e829eca16cf9ef6a57053f67a375e8eec03e9a`。元のsigned-pitch RBFやSDを上書きしていない。

この結果は**赤目合成の回路資源に収まる証拠**であり、最新v034全機能の実機動作証明ではない。最新の山・森林表現には専用Mesen側の処理があり、旧signed-pitch回路にすべて移植済みとは確認できない。最新音源の実機出力も未試験。

外部タイミングはまだ `ppu_oe` クロックと69入力・97出力bitが未制約。内訳・具体ポートは `external_timing_inventory.json` と `unconstrained_ports.csv`。PSRAMのread/write最小最大、NES CPU/PPUのstrobe setup/hold、基板・レベル変換の遅延、SPIのモードとI/O条件が必要。`ppu_oe` は属性ラッチの実クロックなので、仮のfalse pathで消さない。内部STAに正の余裕があっても、これらを除いた外部動作の保証にはならない。

## 採用判断

高精細画像・音の保持と背景への赤漏れ防止、小型敵のGSU／RTL動作は確認できた。残件はRLE負荷の削減、ボスの瞳領域の確定、最新背景処理の実回路への統合、外部タイミングと実機試験。**これらの未解決を理由に研究版のままにし、黒の差し色版はまだ作っていない。**

再検証: `python tools/test_red_detail.py`、`python tools/run_red_tests.py`、`python tools/test_rtl_latest.py`、`python audio/verify_red_r3.py`。ビルドはこの独立コピー内の `python build.py`。いずれも元候補や実機を変更しない。
