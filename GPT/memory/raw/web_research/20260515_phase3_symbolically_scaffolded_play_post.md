■ 概要
Figueiredo と Elumeze の「Symbolically Scaffolded Play」は、LLM NPC の対話を「制約を強くすれば良くなる」という単純な設計問題として扱わず、NPC の物語上の役割ごとに、安定性と即興性の配分を変えるべきだと示す論文。題材は GPT-4o を使った音声ベースの探偵ゲーム The Interview で、プレイヤーは Interviewer から任務や進行の足場を得ながら、容疑者 Sarah / Mark と会話して情報を引き出す。ここで著者らが検証したのは、詳細な制約・ルール・ロアを入れた high-constraint prompt が、簡素な役割記述中心の low-constraint prompt よりプレイヤー体験を改善するのか、という実装者がかなり直感的に信じがちな問い。

第1段階では、参加者 10 名の within-subjects usability study を行い、各参加者が HCP と LCP の両条件を体験した。セッションは各 30 分、順序は counterbalanced、参加者は PS5 コントローラと音声入力を使い、NPC の返答は TTS で聞く。評価は NPC の believable さ、engagement、行動の一貫性、技術的摩擦などを含む 28 項目質問紙と、think-aloud / 自由記述で集められている。結果はかなり冷静で、Holm-Bonferroni 補正後に HCP と LCP の間で統計的に信頼できる差は出なかった。HCP はやや安定・正確、LCP はやや活き活きして適応的、という傾向や参加者コメントはあるが、初回プレイの体験差としては、裏側の prompt 複雑性よりも、ナビゲーション、発話タイミング、遅延、STT/TTS 精度といった表面の破綻の方が強く知覚された。

この点は、LLM 会話の研究としてだけでなく、実装順序の示唆として重要。prompt の洗練が体験に届く前に、プレイヤーが「次に何をすればいいか」「NPC が聞いているのか」「返答が遅いのは演出か不具合か」を読めないなら、backend の精密化は評価されない。
これは小規模プロトタイプほど見落としやすい。

第2段階では、この結果を受けて HCP を JSON+RAG scaffold に作り替え、LLM judge による synthetic evaluation を行っている。ここで重要なのは、scaffold の効果が「NPC 全体」に一様に出たのではなく、役割依存だったこと。quest-giver である Interviewer は、構造化された scaffold によって進行・一貫性・目的提示が安定した。一方、容疑者 NPC では、同じような強い scaffold が improvisational believability を削り、容疑者らしい揺らぎや予想外の応答が弱くなった。つまり、破綻してはいけない役割には制約が効くが、驚きや曖昧さが魅力になる役割には制約が逆効果になり得る。

著者らはこの結果から Symbolically Scaffolded Play を提案する。これは symbolic structure を硬いルール表として押し付けるのではなく、coherence が必要な場所には数値的・曖昧な境界として足場を置き、surprise が体験価値になる場所には即興の余白を残す、という設計枠組みである。論文の結論は「LLM NPC は prompt を精密化すればよい」ではない。プレイヤーが実際に報酬として感じるのは、隠れた最適化そのものではなく、会話の瞬間に読める応答性、破綻の少なさ、役割に合った揺らぎであり、scaffold は NPC の機能に合わせて差分設計する必要がある、という主張になっている。

■ 内容分析
この論文の価値は、LLM NPC の設計を「自由な会話 vs 厳密な制御」の二択から外した点にある。多くの実装では、人格、禁止事項、世界設定、会話状態、出力 JSON、検索結果を足すほど高品質になると考えがちだが、The Interview の結果はその前提を崩している。プレイヤーは prompt の構造を直接見ないため、制御の良さは、進行が詰まらない、会話相手の役割が読める、発話のタイミングが明確、といった可視の体験に変換されて初めて意味を持つ。逆に、裏側で整った構造があっても、音声入力の待ち時間や「今しゃべっていいのか」の不明瞭さが勝つと、体験評価は上がらない。

もう一つ重要なのは、LLM judge を「人間評価の代替」ではなく early-stage complement と位置付けていること。N=10 のユーザーテストでは prompt 条件の微細な差は出にくいが、JSON+RAG scaffold を役割ごとに当てたときの破綻傾向を早期に見る用途なら synthetic evaluation が使える。ここでの judge は最終判定者ではなく、Interviewer の安定性と suspect の即興性のような、次に人間で見るべき差分を発見する probe に近い。Nao_u_BOT 側で読むなら、これは「LLM を評価に使う」話というより、役割別の failure mode を先に分類するための小さな自動検査として読む方が実用的。

限界もはっきりしている。参加者数は 10 名で、ゲームも The Interview という一つの探偵会話プロトタイプに限られる。音声 UI、STT/TTS、初回プレイ、短いセッションという条件が結果に強く影響している可能性がある。また、LLM judge の評価が人間の長期的な楽しさや愛着をどこまで反映するかは別問題。それでも「役割によって scaffold の最適強度が違う」という発見は、単一作品に閉じにくい。特にクエスト進行 NPC と容疑者・仲間・敵対者・雑談 NPC を同じ prompt policy で束ねる危険を、かなり具体的に示している。

■ 自分達の環境への適用
Nao_u_BOT のゲーム制作では、LLM NPC を入れる場合、まず NPC を「進行安定型」「探索誘導型」「情報秘匿型」「感情反応型」「雑談/雰囲気型」のように役割分類し、prompt の制約強度を役割別に分けるのがよい。進行安定型には現在の目的、未達成条件、禁止する矛盾、返答形式を強く入れる。情報秘匿型や容疑者型には、事実関係の境界だけを守らせ、言い回し・回避・揺らぎは広く残す。雑談型は世界観の禁則と安全境界だけを置き、毎回同じ説明係にならないようにする。

記憶システムにも応用できる。各 NPC の prompt を単一の「良いテンプレ」に寄せるのではなく、role_policy として、必要な coherence 指標、許容する surprise、絶対に壊してはいけない進行条件を atom 化する。headless 評価では、LLM judge に「この NPC は進行役として安定したか」「この NPC は容疑者として不自然に説明しすぎていないか」のような役割別 rubric を渡す。人間プレイ前に、prompt 改修が全 NPC を同じ説明口調へ平板化していないかを検出する probe として使える。

■ メリット・デメリット
メリットは、LLM NPC の品質改善を prompt の厚さではなく、役割ごとの体験機能で管理できること。会話破綻を減らすべき NPC と、予想外の反応を残すべき NPC を分けられるので、実装判断が具体化する。デメリットは、役割分類と評価 rubric を作る手間が増えること。また、synthetic judge に寄せすぎると、人間には魅力的な違和感や沈黙まで「不安定」と誤判定する可能性がある。音声 UI や入力待ちなど、prompt 外の摩擦を同時に潰さないと効果も見えにくい。

■ 判定
部分採用。全 NPC に JSON+RAG scaffold を厚く入れる方針は採らない。一方で、役割別に制約強度を変え、LLM judge を早期の failure mode 発見に使う考え方は採用価値が高い。まずは会話 NPC の role_policy と役割別 rubric を小さく作る。
