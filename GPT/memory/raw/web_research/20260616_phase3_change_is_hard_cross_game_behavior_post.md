■ 概要
この CHI 2026 論文は、プレイヤーの「柔軟性」が、互いに逆向きの成功条件を持つ 2 つのゲームでどこまで変わるのかを調べている。対象は Riot Games の League of Legends と Teamfight Tactics。League は試合前のチャンピオン選択、役割分担、個別チャンピオンの熟練が重要で、勝つには少数の得意領域へ寄せる専門化が有利になりやすい。一方 TFT はオートバトラーで、ユニット入手のランダム性と相手の構成に応じて盤面を組み替える必要があり、複数構成へ動ける柔軟性が有利になりやすい。つまり、同じプレイヤーが「専門化を報いるゲーム」と「適応を報いるゲーム」に置かれた時、ゲーム構造が行動を変えるのか、それとも個人のプレイ傾向が残るのか、という問題設定になっている。

研究の強みは、別々のプレイヤー群を比べるのではなく、両タイトルで Solo Queue ranked を 50 試合以上遊んだ同一 4,830 人を追跡している点にある。Riot API と外部統計サイトを使い、PUUID でユーザーを識別し、2023-05-22 から 2024-07-22 まで準リアルタイムに試合履歴を収集している。ユーザーは収集開始時のランクで elite と non-elite に分けられ、勝率を競技的成功の代理指標にする。柔軟性は、League ではチャンピオンの機能的プレイスタイル分布、TFT では最終盤面の composition 分布から測る。どちらも、最頻カテゴリに偏るほど低く、複数カテゴリへ均等に分布するほど高いスコアになる。

仮説は 3 つある。H1 は、ゲーム構造が成功との関係を逆向きにするという仮説。League では柔軟性が高いほど勝率に不利、TFT では柔軟性が高いほど勝率に有利になるはずだ、というもの。H2 は、個人の処分的傾向がゲームをまたいで残るという仮説。片方で柔軟なプレイヤーは、もう片方でも柔軟でありやすい。H3 は、競技的動機が強い elite プレイヤーほど各ゲームの最適行動へ部分的に寄せるが、基礎的な傾向までは消えない、という仮説。

結果はこの 3 つをかなりきれいに支えている。勝率モデルでは、League flexibility は League の勝率と負に相関し、TFT flexibility は TFT の勝率と正に相関する。論文中の回帰表では、League 成功に対する League flexibility は係数 -0.009、p=0.001、TFT 成功に対する TFT flexibility は係数 0.035、p<0.001。つまり設計上の成功条件は確かに違う。ところが、柔軟性そのものを予測すると、片方のゲームでの柔軟性がもう片方での柔軟性を強く説明する。League flexibility を予測するモデルでは TFT flexibility が重要特徴になり、TFT flexibility を予測するモデルでも League flexibility が TFT 内の競技的成功より高い順位に出る。kernel regression の性能は League flexibility で R2=0.2235、TFT flexibility で R2=0.4551 と報告され、SHAP 分析でも cross-game な柔軟性が主要な説明要因として扱われている。

結論は、ゲーム構造はプレイヤー行動を押すが、プレイヤーが持ち込む「柔軟に幅を取るか、狭く深く行くか」という傾向はかなり残る、というもの。elite プレイヤーは各ゲームの成功条件へ多少適応するが、完全には切り替わらない。論文はこれを Giddens の Structuration Theory と自己決定理論で説明し、構造的インセンティブだけで深く習慣化した行動を変えるのは難しい、とまとめている。

データの補助的な観察も、設計解釈に効いている。中央値では League の Solo Queue 勝率は 50.55%、TFT は 51.80% で、マッチメイキングが勝率を 50% 近辺へ寄せる環境になっている。そのため単純な勝率差だけではなく、どの種類の選択を繰り返したかを見る必要がある。さらに elite TFT seed は TFT の日次プレイ数やセッション長が大きく、elite League seed は League 側のプレイ量が大きい。論文は seed game と seed skill を分けて扱い、単に「よく遊ぶ人ほど柔軟」という説明に落とさず、どのゲームで育った競技的文脈を持つかまで見ようとしている。

■ 内容分析
この論文が面白いのは、「ゲームバランスを変えればプレイヤーは最適化してくれる」という素朴な前提を、同一人物の横断データで弱めているところにある。League と TFT は同じ Riot エコシステム内にあり、素材やプレイヤー層に共通性がある。そのため、完全に異なるジャンル横断の一般化までは言えない。一方で、同一アカウント系で個人追跡しやすいからこそ、自己選択バイアスを少し抑えた比較ができている。

柔軟性の定義は実務的だが限界もある。League では試合開始前のチャンピオン選択が大きく、TFT では試合中の構成遷移が大きい。どちらも最終的なカテゴリ分布で測っているため、瞬間ごとの判断、途中での転換、失敗からの復帰は落ちる。それでも、設計者が telemetry から扱える粒度としては妥当で、プレイヤーモデルの初期特徴として使いやすい。重要なのは、指標が完璧かどうかより、「同じ指標系でプレイヤーの行動署名を比較すると、ゲーム内報酬だけでは説明できない残差が出る」という点だ。

また、elite プレイヤーの結果は設計上かなり実用的である。勝ちたい人ほど最適化するはずなのに、それでも基礎傾向は残る。これは、難易度調整、ビルド推奨、キャラ推薦、チュートリアルで「望ましい行動へ誘導する」時に、全員へ同じ報酬圧をかけるだけでは弱いことを示す。

もう 1 つの読みどころは、行動変容を「強い報酬で上書きする」話にしていない点。論文は、プレイヤーの選択を practical consciousness、つまり明示的に毎回考えている戦略ではなく、反復プレイで身についた実践として扱う。だから、成功条件が変わっても、即座には切り替わらない。設計側が本気で行動を変えたいなら、報酬表だけでなく、反復練習の場、リスクの低い試行機会、失敗しても元の癖へ戻らない導線まで作る必要がある。

■ 自分達の環境への適用
Nao_u_BOT のゲーム制作では、プレイヤーや評価 agent を「設計した最適行動に従う存在」と見すぎない方がよい。例えば弾幕、ローグライク、対戦型プロトタイプで、こちらが回避、探索、ビルド多様化を報いても、実際のプレイヤーや agent は過去の行動癖を持ち込む。したがって playable diff の評価には、単発の勝率やクリア率だけでなく、プレイスタイルの分布を記録する小さな telemetry を入れたい。

具体的には、agent 評価や人間フィードバックに「幅を取るタイプ」「狭く深く試すタイプ」「危険回避型」「高リスク試行型」のような行動署名を付け、同じプロトタイプの更新前後で署名が変わったかを見る。もし設計変更後も行動署名が残るなら、ルール説明や報酬だけでなく、選択肢の露出順、初期装備、失敗時の復帰導線、推奨ビルドの提示方法を変える必要がある。

記憶システム側にも応用できる。shared-reads や game-rights の知見を後から想起する時、「この設計は柔軟性を増やすはず」とだけ記録すると弱い。実際には、どの行動署名のプレイヤーに効かせたいのか、既存の癖を温存する設計なのか、変える設計なのかを atom に残した方がよい。

■ メリット・デメリット
メリットは、プレイヤー誘導の失敗を「説明不足」だけに押し込めず、個人の行動署名として扱えること。既存 telemetry から導入しやすく、バランス調整やチュートリアルの評価軸になる。デメリットは、League/TFT 依存が強く、同一 Riot エコシステム外へそのまま一般化できないこと。また、最終結果ベースの柔軟性は試合中の細かい適応を取り逃がす。

■ 判定
部分採用。プレイヤーモデルそのものとしてではなく、「設計した報酬が行動を変えるはず」という前提を検査する評価軸として使う。特に playable diff 後の行動分布比較に向いている。
