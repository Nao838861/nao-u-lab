■ 概要
この CHI 2026 論文は、League of Legends の Champion Select 中にプレイヤーがロビーから抜ける queue dodging を、単なる迷惑行為や毒性行動としてではなく、「予測された悪い体験を避けるための行動」として読み直している。通常、queue dodging はマッチ待ち時間を伸ばし、マッチメイキング品質を下げ、他プレイヤーに再待機を強いるため、運営側からは罰則対象になりやすい。実際、Riot 系の競技ゲームでは dodge に対して待機ペナルティや LP ペナルティを設ける方向で扱われてきた。それでもプレイヤーが dodge を続けるなら、なぜ罰を受けてまでロビーを抜けるのかを見ないと、制度設計がずれる。

研究は 2,932 件の Reddit 投稿・コメントを対象に thematic analysis を行い、queue dodging の主要動機を 4 つに整理している。1 つ目は toxic teammate の回避。Champion Select の会話、ピック宣言、過去戦績、名前や態度などから、このチームでは嫌な体験になると判断して抜ける。2 つ目は不利な matchup の回避。味方構成、相手に見える情報、自分のロールやチャンピオン相性、autofill などを見て、試合前から勝ち目や楽しさが低いと判断する。3 つ目は system mechanics の利用。dodge ペナルティ、MMR、LP、再キュー、匿名化、サードパーティ戦績サイトといった制度の隙間を、損得計算として使う。4 つ目は外的事情への反応。急用、接続不安、現実側の都合、プレイ継続の体力切れなど、ゲーム内の悪意とは別の理由で抜ける。

論文の中心的な主張は、queue dodging が「他者に害を与える toxic act」である場合もあれば、「自分が toxicity や不利な体験に巻き込まれないための防御的戦略」である場合もある、という二面性である。ここが重要で、同じ行動を一律に罰すると、悪質な抜けだけでなく、悪いロビーを察知して自衛したプレイヤーまで罰する。一方で、dodge を全面的に許すと、待ち時間やマッチメイキング品質が悪化し、プレイヤーが試合前の情報を使って都合のよいロビーだけを選ぶ動きが強まる。したがって設計課題は「dodge をゼロにする」ではなく、「プレイヤーが悪い体験を予測し、回避したくなる原因を減らしつつ、dodge 自体が他者への負担や攻撃手段にならないようにする」ことになる。

公開要旨で示されている範囲では、論文は queue dodging を multiplayer safety、toxicity intervention、matchmaking UX の交点に置いている。ロビーは試合前の短い画面だが、実際にはプレイヤーが味方を信頼できるか、試合が成立しそうか、今から 30 分を投じる価値があるかを高速に判断する場になっている。つまり Champion Select は単なる準備 UI ではなく、プレイヤーが将来の負の体験を見積もる「予測インターフェース」でもある。dodge が多いなら、プレイヤーがその予測で何を見ているか、そしてその不安をゲーム側がどう吸収できていないかを読む必要がある。

確認できたメタデータでは、論文は Proceedings of the 2026 CHI Conference on Human Factors in Computing Systems に収録された 17 ページの conference paper で、著者は Wenhao Yi、Jim Kurt Ferras Duco、Howie Lo、Regan L. Mandryk。SIGCHI ページと Crossref では DOI、発行日、参照文献が確認できるが、ACM 本文 PDF はこの環境では Cloudflare に阻まれた。そのため、ここでの整理は公開要旨と候補メモに明示された範囲、つまりデータ数、分析方法、4 動機、設計含意に限定している。本文未確認の細部、たとえばカテゴリ比率や coding 手順の詳細は、後で本文が取れた時に補う余地がある。

■ 内容分析
この論文の価値は、迷惑行為カテゴリを行動名で固定せず、文脈と動機に分解している点にある。queue dodging という表面行動だけを見ると、待たされた他プレイヤーには迷惑で、運営指標でも悪化要因になる。しかし、投稿・コメントの主題分析からは、プレイヤーが「この試合は toxic になりそう」「自分が望まない役割を押し付けられた」「この構成は成立しない」「今プレイを続けると悪い体験になる」と予測していることが見える。

特に toxic teammate 回避と unfavorable matchup 回避は、同じ dodge でも設計要求が違う。前者はコミュニケーション、通報、匿名化、過去行動の可視性、ロビー内の摩擦低減に関わる。後者はロール割り当て、ピック順、チャンピオン相性、スキル差、試合前情報の開示範囲に関わる。system mechanics の利用は、ペナルティ設計そのものが行動を作る領域で、dodge コストが軽すぎると乱用され、重すぎると自衛まで潰す。外的事情は、短時間の離席、接続問題、疲労をどう扱うかの UX 問題になる。つまり対処は 1 つではなく、動機別に設計面が分かれる。

Reddit 由来のデータなので、実際の全プレイヤー母集団を代表するとは限らない。声の大きい熟練者、強い不満を持つ人、特定コミュニティの価値観が過剰に出る可能性はある。ただ、罰則ログや telemetry だけでは見えにくい「なぜそうしたか」を掘る素材としては強い。定量ログでは dodge は中断イベントに見えるが、テキスト分析では負の体験予測の語彙が見える。

設計上は、「予測の材料を隠せば dodge が減る」と短絡しない方がよい。情報を隠すと、たしかに相性や戦績を根拠にした dodge は減るかもしれないが、プレイヤーが感じる不信や制御不能感は増える可能性がある。逆に情報を出しすぎると、選別や差別的回避が強まる。論文の扱いから見るべきなのは、どの情報が自衛に役立ち、どの情報がロビー崩壊を誘発するかの分離である。これは moderation だけでなく、マッチング UI の情報設計そのものの問題になる。

■ 自分達の環境への適用
Nao_u_BOT の制作では、マッチングやロビーがない小規模プロトタイプでも、この視点は使える。プレイヤーがステージ開始前、ビルド選択前、NPC 編成前に離脱したり、リスタートを連打したり、特定選択肢を避けたりする時、それは単なるわがままではなく「この先の体験が悪くなる」という予測かもしれない。

具体的には、playable diff の評価で「開始前離脱」「即リトライ」「装備選択画面での戻り」「NPC 交代」「危険部屋の回避」を、失敗イベントだけでなく予測回避イベントとして記録する。さらにフィードバックには「何を見て避けたか」を聞く。敵配置、報酬の低さ、味方 AI への不信、読みづらい UI、長すぎる拘束時間など、避けた理由が分かれば、罰や制限ではなく不安の発生源を直せる。

agent 評価にも使える。AI プレイヤーがある選択肢を避け続ける時、報酬関数の偏りだけでなく、観測上「この先が破綻する」と読んでいる可能性を見る。例えば味方 NPC の移動が読めない、敵弾の予告が弱い、回復資源が見えない、失敗時の復帰が重い、といった要素は、人間にも agent にも回避行動として出る。回避ログを削除すべきノイズではなく、体験予測のセンサーとして残すのがよい。

■ メリット・デメリット
メリットは、離脱や回避を一律に悪と見ず、負の体験を事前検知する信号として使えること。ロビー、ビルド、部屋選択、NPC 選択の改善に直結する。デメリットは、公開要旨ベースでは詳細な coding 手順やカテゴリ間の比率まで確認できていないこと。Reddit 分析なので、実行ログと合わせて読む必要がある。

■ 判定
採用。特に「離脱を罰する前に、何を予測して避けたのかを見る」という評価軸を、マッチング系だけでなく通常のプロトタイプ検証にも入れる。
