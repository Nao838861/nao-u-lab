■ 概要
対象: Simulation-Driven Balancing of Competitive Game Levels with Reinforcement Learning
URL: https://arxiv.org/abs/2503.18748

この論文は、対戦型2人ゲームの非対称レベルを「人手で遊んで調整する」作業から切り離し、シミュレーション結果を報酬にした PCGRL で自動調整する方法を提案している。問題設定は、単に新しいステージを生成することではなく、すでに playable なタイルベースのレベルを、両プレイヤーの勝率などの目標バランスへ近づけることにある。著者らは処理を3つに分ける。まず level generator がランダムノイズからプレイヤー2人と到達可能経路を満たす playable level を作る。次に balancing agent がそのレベルを受け取り、タイルを置換するのではなく2つのタイル位置を swap する。最後に reward modeling simulation が、ヒューリスティックなプレイヤーエージェントでそのレベルを複数回プレイし、勝率の変化から報酬を返す。

中核は swap-based representation である。従来の PCGRL のようにタイルを別種へ置き換えると、途中状態でプレイヤー数や通路制約が壊れ、報酬を計算できない unplayable level が発生しやすい。そこで著者らは narrow/turtle/wide の各表現を swap 版に拡張し、1ステップで2タイルの位置だけを入れ替える。これにより、タイル総数を保ったまま既存レベルを微修正でき、生成器の仕事である「全面的な作り直し」と、調整器の仕事である「バランス微修正」を分離する。swap-narrow は2つのランダム位置に対して swap するかを選ぶだけ、swap-turtle は2点を移動しながら swap し、swap-wide は全体を見て任意の2位置を選ぶ。wide は行動空間が大きいが性能重視、narrow は高速でグリッドサイズ非依存という整理になっている。

報酬設計は、勝率を公平性指標に接続する点が特徴的である。著者らは statistical parity の考え方をゲームバランスへ移し、プレイヤー1の勝率が目標値 b にどれだけ近いかを balance state として扱う。b=0.5 なら両者が同じ勝率、b=0 や 0.1 なら特定プレイヤーに有利なレベルも意図的に作れる。報酬は前ステップから目標値へ近づいたかで正負が決まり、完全一致時には追加報酬を与える。評価環境は Neural MMO を簡略化した6x6の資源収集・生存競争で、森や水を得ること、石や水で通れないこと、食料や水不足で体力が減ることが勝率に影響する。プレイヤーは同じ scripted Forage-agent だが、資源リスポーンなどの確率要素があるため、1回ではなく複数回シミュレーションして勝率を推定する。

結果として、初期実験では swap-narrow と swap-wide が balanced level 48.1%、improved 63.3%/64.1% を達成し、従来 PCGRL narrow の balanced 30.4%、improved 36.7% を上回った。従来表現では最終状態の38.8%が unplayable だったのに対し、このドメインの swap 表現は playable を保った。拡張実験ではプレイヤー1/2のspawn tileを区別し、学習更新を増やすことで b=0.5 の balanced が68.0%、improved が88.9%まで上がった。また b=0.0 から0.5まで異なる目標値でも全て改善が確認され、平等なバランスだけでなく、子ども対大人、装備差、役割差の補正のような「意図的な非対称バランス」へも開けている。hill climbing との比較でも、S-wide PCGRL は同じ変更数制限内でより多くのレベルを目標に近づけ、単純な narrow hill climbing は unplayable が多く残った。さらに swap 頻度の分析から、この環境では森と石、森と水の入れ替えが勝率に強く効き、spawn位置の交換は予想ほど選ばれなかった。結論は、シミュレーション報酬を使うRL調整は計算量が重いが、既存レベルの小変更に限定すると、バランス改善と設計要素の影響可視化を同時に得られる、というもの。

■ 内容分析
この論文の価値は「AIでレベルを作る」よりも、「バランス調整を、遊びの結果から逆算する編集問題に落とした」点にある。人間のレベルデザイナーは、森を増やす、遮蔽物を動かす、spawnをずらす、近道を塞ぐといった編集を、プレイ感と勝率の両方から判断する。この手法はその編集単位を swap に制限し、勝率変化だけを報酬にすることで、どの地形要素が実際に効いたかを後から読める形にしている。特に「生成」と「調整」を同じRLに押し込まず、generator と balancing agent を分けた判断は実装上も設計上も重要で、完成済みステージを壊さずに局所修正するパイプラインへ近い。

一方で、評価は scripted agent の行動モデルに強く依存する。論文自身も、同じ腕前のプレイヤー同士を仮定した勝率であり、別の skill、別の archetype、別の探索癖なら balance state が変わると述べている。これは欠点であると同時に使い道でもある。人間一般の公平さを一気に測るのではなく、「このbot群に対して何が壊れているか」を測るなら、Nao_u_BOT の headless 評価と相性が良い。さらに、報酬が sparse で、各swapごとに複数シミュレーションが必要なため、複雑なゲームへそのまま持ち込むとコストが先に破綻する。著者らが述べる surrogate reward model や数ステップ後報酬は、実用化時の必須課題になる。

■ 自分達の環境への適用
Nao_u_BOT では、まずRLまで入れずに「swap-based balancing probe」として使うのがよい。対象は2D対戦風、資源配置、敵配置、遮蔽物、回復、spawn、wave順序など、局所編集で勝率・到達率・生存時間が変わるプロトタイプ。Phase 1/2 で候補を読むだけでなく、Phase 3b/4a の小さな probe として、headless bot を20〜100回走らせ、変更前後の勝率、平均生存時間、到達率、被弾数を記録する。編集操作は最初から生成にせず、「既存 playable diff の要素を1つ入れ替える」「座標を少し移す」「敵タイプを同コスト内で交換する」に限定する。

実装上は、game_memory_task_lens_index に「balance objective」「editable elements」「simulation budget」「accepted range」を残すと次回に使える。特に b=0.5 だけでなく「初心者botが45%勝てる」「近接型が遠距離型に対して即死しない」など、意図的な目標値を置ける点が重要。これは単なる公平化ではなく、作品の狙いに合わせて緊張感を設計する道具になる。

■ メリット・デメリット
メリットは、バランス判断を感想ではなく反復シミュレーションの差分として残せること、編集単位が小さいため playable な既存案を壊しにくいこと、swap頻度から「どの要素が勝敗に効いているか」を設計知見として回収できること。デメリットは、評価botの偏りをそのまま最適化すること、報酬計算が重いこと、勝率の公平さが面白さや読み合いの質を直接保証しないこと。複雑な意味を持つタイルやイベントでは swap がルール破壊を起こしうる。

■ 判定
部分採用。RL本体より先に、swap/局所編集 + headless simulation + 目標バランス値の記録を採用する。ゲーム制作サイクルでは「公平にする」ではなく「目的指標へ近づける編集ログ」として使うのが有効。採用時は必ず、評価botの種類と試行回数を本文ログに残し、勝率だけで面白さを代替しない。
