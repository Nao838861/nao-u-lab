■ 概要
対象は “Gamification with Purpose: What Learners Prefer to Motivate Their Learning” (https://arxiv.org/abs/2512.08551)。教育向け gamification を、points / badges / leaderboards を足す話ではなく、学習目的と動機づけを崩さない game design elements (GDEs) の選択問題として扱った研究。問題意識は明快で、教育現場では gamification が広く使われる一方、実装要素は PBL 三点セットに偏りがちで、学習者が何を好み、なぜそれが効くのか、さらに複数要素をどう組み合わせたいのかが十分に検証されていない。外発的報酬を強くしすぎると内発的動機を削るリスクもあるため、著者らは purpose-driven gamification、つまり教材・学習目標・学習者の動機づけ要求と結びつく要素を探す。

手順は三段階。まず ACM Digital Library、ERIC、IEEE Xplore、JSTOR、SpringerLink などを対象に systematic literature review を行い、348件の候補から基準に合う18件、snowballing で追加3件を得て、合計21件から学習動機に効きそうな GDE を整理した。そこから achievements、badges、progress bars、feedback、storytelling、leaderboards、points、virtual currency、avatars の9種を選び、さらに通常は instructional scaffold として扱われる concept map を「学習領域の接続と進行を見せる progression GDE」として加え、合計10種にした。各要素は名前だけで比較せず、オンラインコースでの利用を想定した visual prototype と説明文を作って参加者に提示している。

評価は 125 participants の survey。中心は best-worst scaling (BWS) で、10種の GDE から4種ずつを含む choice set を15回提示し、各回で最も動機づけになりそうなものと最も弱いものを選ばせる。各要素は合計6回ずつ出現するため、単純な Likert 評価よりも相対的な順位とトレードオフが出る。BWS 後には、自由に組み合わせるならどの GDE を選ぶか、選んだ中で何が最も学習動機を高めるか、なぜそう思うかも聞いている。分析は best / worst のカウントと standardized mean、回帰による確認、組み合わせ頻度、相関、自由記述の iterative coding で構成される。

結果は、progress bar が明確な1位。standardized mean でも raw frequency でも他を大きく引き離し、best として選ばれた回数は363回で、次点の feedback 263回より約70%多い。続く上位は achievements、feedback、concept map、points。下位は avatar と virtual currency。性別、ゲーム嗜好、年齢で大きな差はないが、15-19歳では points の選好が高く、concept map と feedback は年齢が上がるほど好まれる傾向がある。組み合わせ分析でも progress bar は参加者の7割超に含まれ、achievements、concept map、feedback が続く。参加者の9割超が上位4要素の少なくとも1つ、8割超が2つ以上を選び、PBL 三点セットより progress bar + concept map + feedback の組み合わせが強く出た。

自由記述からは六つの motivational drivers が抽出される。visual progression、effective learning、goals、structure、showcase、relevance。特に progress bar と concept map は「進み具合が見える」「全体構造と接続がわかる」理由で選ばれ、feedback は改善に直結するため、achievements / badges は達成を後から認識し目標を保つために評価される。結論は、学習者は報酬単体ではなく、学習プロセスを可視化し、次に何をすればよいかを返し、教材内容との関係が切れない GDE を好む、というもの。著者らは progress bar、concept map、achievements、feedback を起点にし、必要に応じて badges、storytelling、points、leaderboards を足す設計を勧めている。

■ 内容分析
この論文の強い点は、GDE の好みを「好きな報酬ランキング」に閉じず、可視プロトタイプ、BWS、組み合わせ、自由記述をつなげていること。progress bar が勝った、で終わるなら既知の話に近いが、concept map を GDE として扱った点が面白い。単なる地図 UI ではなく、領域間の接続、未到達領域、現在地、次の展開を見せる装置として読める。これは points より派手ではないが、学習者に「自分が何を理解し、次にどこへ行けるか」を返す。

BWS の結果と自由記述の対応も重要。上位要素は外見上ばらばらだが、理由を見ると progress と feedback に収束している。achievements / badges も、単体のメダルではなく、学習成功を見える形にし、到達目標を保つ時に意味を持つ。逆に virtual currency や avatar は、教材との関係が弱いと動機づけにはなりにくい。つまり「ゲームっぽさ」を濃くするほどよいのではなく、学習行為の意味を短い周期で返すほどよい。

限界もある。参加者は125人で、年齢分布は20代前後に寄っている。オンラインコース想定の選好調査なので、実際の長期利用、成績、離脱率、難易度の高い教材での持続性までは示していない。また visual prototype を見て選ぶ調査であり、実装品質や演出の気持ちよさは別問題。ただし、だから弱いというより、実装前の設計判断として「どの報酬要素に意味を持たせるべきか」を絞る用途に向いている。

■ 自分達の環境への適用
Nao_u_BOT の小型ゲーム制作では、ゲージ、実績、スコア、ヒントを「報酬 UI」として足す前に、何を見える化するのかを決める。たとえばプレイヤーが失敗を繰り返すゲームなら、単に残機や点数を出すのではなく、直前の入力、避けられた危険、次に試すべき行動を feedback として返す。探索ゲームなら concept map 的に、未踏エリアだけでなく「獲得した能力で意味が変わった場所」を見せる。成長ゲームなら achievements は収集物ではなく、プレイヤーが身につけた判断や操作の節目に紐づける。

記憶システム側にも使える。Phase 3b/4a の自己フィードバックでは、candidate の量を points 的に増やすより、progress bar 的に「どの評価軸が埋まったか」、concept map 的に「どの制作課題と接続したか」、feedback 的に「次の probe は何か」を表示する方が、後続作業に効く。shared-reads 候補も、採点だけでなく、制作上の未解決領域マップに貼ると再利用しやすい。

■ メリット・デメリット
メリットは、ゲーム的要素を入れる判断を「見栄え」から「上達と次行動の可視化」へ戻せること。特に progress bar、concept map、feedback の組は、小規模プロトタイプでも低コストに検証できる。デメリットは、教育文脈の選好であり、娯楽ゲームの緊張、驚き、隠された情報、損失感にはそのまま外挿しにくい点。可視化しすぎると発見の余白を潰す可能性もある。

■ 判定
部分採用。UI 報酬を増やす指示ではなく、プレイヤーの理解、進捗、次行動を返す設計軸として採用する。特に progress / map / feedback を、次の小型ゲームと記憶 UI の評価チェックに入れる。
