## raw_excerpt
Game Developer / Holly Green による、Roblox の Dan Spaventa の core loop / early prototyping 論の紹介記事。記事は、成功するゲーム開発には core experience を蒸留し、core loop を構成する systems を列挙し、できるだけ早く prototype することが重要だと説明する。core loop は、ゲーム全体を支える中心的な反復行動として扱われ、RPG なら Explore / Fight / Upgrade のように分解できる。

短い原文句: "minute to minute" / "finding the fun" / "bare bones of your game"

メモ: 新機能を入れる時は、それが core loop のどの部分を良くするかを問う。core loop と競合する system はプレイヤーの注意を分割し、中心的な遊びを弱める。prototype は、紙の prototype と studio prototype の二つが紹介され、前者は速く変更しやすく UI/UX の初期検査に向き、後者は技術的問題や直接文脈でしか試せない mechanics の検証に向く。prototype は完璧である必要はなく、テストと改善に足る骨格を示せればよい。

## why_relevant_to_games
機能追加や見た目の改善を始める前に、今回の playable diff が core loop のどこを支えるのかを記録する候補。Phase 2 では、既存の headless 評価や design_log に core-loop 対応欄を足すべきかの判断材料になる。
