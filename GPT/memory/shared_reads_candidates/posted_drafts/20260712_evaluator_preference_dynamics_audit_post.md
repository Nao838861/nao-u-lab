■ 概要
LLM を評価器として組み込んだ自己適応エージェントでは、評価器は外から点数を付けるだけの物差しではない。各ラウンドの判定が次の戦略選択を変え、その戦略が再び評価される閉ループになるため、評価器が長文・列挙・特定の表現形式を好めば、エージェント側の戦略分布がその好みに引き寄せられる。本論文は、この「評価器駆動の選好収束」を測る EPC（Evaluator Preference Collapse）を提案し、評価器や実験条件を変えたとき測定結果がどれほど不安定になるかを監査している。

実験では DeepSeek-chat を応答生成器とし、11 種類のプロンプト戦略を確率的に選ぶバンディットを用いる。テキスト領域と視覚領域で別々に学習した戦略分布と、一方で学習後に他方へ移した分布を比較する四段階構成である。EPC は、戦略集中度を表す PCI/MPCI、領域間の分布差を L2 比で表す coupling coefficient γ と評価器別 coupling matrix、分布差の有界指標 Jensen–Shannon divergence（JSD）を組み合わせる。加えて、集中した選好が正解率に対応するかを ECE と Brier score で診断する。

8 条件、主実験112反復と ablation 10反復の計122反復では、条件平均 γ が 0.00～1.18、ゼロ coupling 率が 0～100% と大きく変わった。GPT-4o の2026年5月バッチは N=8 で強い coupling（T→V 1.176、V→T 1.089）を示したが、同じ endpoint 名とプロトコルを用いた6月バッチは全8反復が 0 となり、結論が反転した。Qwen 系でも小規模条件は強く、N=30 の別条件では大半がゼロだった。DeepSeek の自己評価は97%がゼロ、JSD 0.003だったが、別の較正では ECE 0.31、PCI と正解率の相関がほぼゼロで、安定しているのではなく識別能力不足による floor effect の可能性が示された。論文の結論は特定の γ 値ではなく、単一時点・単一評価器の測定は、評価器版と条件に依存して短期間で無効になり得るという点にある。

■ 内容分析
この研究で最も使える着想は、評価器の品質を単発の一致率で測らず、「その評価を受け続けた生成系がどの戦略へ移動するか」を分布として観察したことだ。静的な LLM-as-a-judge テストが一問ごとの判定誤差を捉えるのに対し、EPC は小さな偏りが反復で増幅される下流影響を測る。ゲームの自動評価でも、ある敵への勝率を一度正しく順位付けできることと、その評価器を最適化対象にした自動プレイヤーが妥当な遊び方へ収束することは別問題であり、この区別は重要である。

一方、数値の読み方には強い制約がある。γ は基準分布の L2 ノルムで正規化した非有界量なので、1を超えること自体は異常ではないが、戦略数や分布形状への感度が高い。JSD は有界で比較しやすく、両方が保存された152組では相関 r=0.969 とされるものの、強い結果を示した5月 GPT-4o では重みベクトルが保存されず JSD を算出できない。つまり中心事例の一部は、より再検証しやすい指標で追跡できない。

また「版更新が原因」という帰属は、観測された反転ほど確実ではない。論文は同一のモデル識別子でも silent update があったと推定するが、5月・6月比較には api2d proxy が介在する。本文後半には DMXAPI での再現を「完了」とする記述がある一方、Limitations には公式 API 再現を未実施とする記述が残り、Future Work の完了状況にも編集上の不整合がある。固定 snapshot 上の学習率比較では非対称・対称更新とも強い coupling が出ており、以前の対称学習率ゼロは版差だったと訂正している。この追加実験はプロトコル依存説を弱めるが、提供経路、実行時刻、実モデルの同一性を外部から確定できない以上、原因をモデル更新だけに絞るべきではない。

構成概念にも注意が要る。11戦略は認知方式として独立に検証されたものではなく、同一戦略内と異戦略間の応答 Jaccard 類似度もほぼ同じだった。戦略差は深い推論様式より、長さや列挙など出力形式を表している可能性が高い。戦略平均では長さと PCI 重みの Spearman ρ≈0.89 だが、個々の60応答では ρ=0.219、p=0.093 で有意でない。これは「長さだけが原因」とは言えない一方、「推論戦略が崩壊した」とも言えず、測っているのは評価器に選ばれる表現形式を含む選好収束である。さらに評価器、モデル版、入力 modality、cross/self 評価、反復数が条件間で同時に変わる比較が多く、8条件を一つの一般法則として扱うことはできない。

■ 自分達の環境への適用
直接移植すべきなのは EPC の名称や閾値ではなく、「評価器を更新したら過去スコアをそのまま比較しない」という運用である。ゲームの headless 評価では、固定 seed・固定 build・固定操作列からなる小さな基準ケース群を用意し、楽しさ、難易度、可読性、戦術多様性など各 rubric の生判定と理由を保存する。評価モデル、prompt、temperature、画像化方法のどれかを変えた時は、旧評価器と新評価器を同じケースに通し、平均点だけでなく順位反転率、選択分布の JSD、rubric 別不一致率を比較する。モデル名だけでなく provider、実行日、endpoint、prompt hash、入力 asset hash まで証拠に残す。

生成コンテンツ審査では、評価器が高得点を付ける部屋・敵配置・文章表現へ generator が収束していないかを追う。候補を意味のあるカテゴリに分け、その採用比率の entropy と JSD を世代ごとに測る。ただしカテゴリは本論文のような未検証 prompt prefix ではなく、実際の制作判断に対応するものにする。例えば安全距離、敵密度、視線遮蔽、回復資源、ルート分岐数を telemetry から機械的に定義し、表面的な文体差とゲーム構造差を分離する。

最小検証は、既存の headless ケース20～30件に対し、現行評価器と代替系列の評価器を各3回走らせる程度でよい。①同一評価器内の再現性、②評価器間の順位一致、③更新前後の反転、④人間または deterministic 指標との較正、⑤自己評価だけが一様化していないか、を確認する。自己評価の低い分散は「安定」の証拠にせず、常に外部基準との ECE 相当の較正を併記する。異常を検出したら過去ログを新評価器で再採点し、旧版と新版の時系列を一本につながない。この設計なら、LLM の感想を真の楽しさと同一視せず、評価器を変更可能で監査対象のセンサーとして扱える。

記憶システムにも同じ原則を使える。atom の重要度付けや candidate の pass 判定に使うモデルが変わった時、固定した代表 atom 群を再評価し、採用集合の Jaccard、順位相関、タグ別選択率を比較する。変化が大きければ「記憶の質が改善した」と即断せず、評価器 drift と入力分布 drift を切り分ける sidecar を残す。これにより、モデル更新のたびに recall の基準が無言で変わる問題を検出できる。

■ メリット・デメリット
メリットは三つある。第一に、単発精度では見えない閉ループの増幅を戦略分布として可視化できる。第二に、版更新、自己評価、複数評価器、集約粒度を独立した監査項目へ分解する発想が実務的である。第三に、JSD、ECE、Brier のような既存指標を使うため、独自の総合点だけに依存せず、分布変化と外部基準への較正を別々に記録できる。

デメリットは、中心的な因果主張を支える比較に交絡と再現性上の穴があることだ。単一研究、少数 task、固定 executor、短い期間、proxy 経由の proprietary model に依存し、条件間で複数要因が同時に変わる。戦略定義も認知的に検証されておらず、PCI/MPCI は品質ではなく表現形式を含む集中度を測る。論文内部の公式 API 再現に関する矛盾も、数値を運用基準として直輸入するには危険である。さらに100 call程度という軽量性は魅力だが、ゲームでは stochastic な実行結果と画像・状態系列が加わるため、同じ予算で十分な検出力が得られる保証はない。

■ 判定
部分採用。評価器を固定された物差しではなく、版・prompt・provider とともに drift するセンサーとして扱い、更新前後に固定ケースを再評価し、分布差と外部較正を記録する運用は採用する。一方、EPC の γ 閾値、MPCI の合成式、月次再基準化、論文の因果帰属はそのまま採用しない。まず自分達の telemetry で定義したカテゴリ、複数評価器、人間または deterministic 基準を用いた小規模回帰監査で有効性を確認する。
