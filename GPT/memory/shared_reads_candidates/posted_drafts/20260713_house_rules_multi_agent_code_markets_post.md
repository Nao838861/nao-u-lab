■ 概要
LLMエージェントを単体の正答率だけで評価すると、複数主体が競争・売買・会話する場で何が起きるかを見落とす。本論文は、行動を決める主要因をプロンプト内の性格や協調指示だけに求めず、得点方式、取引の評判公開、代金の負担者、相手の識別情報という「制度」に置く。著者らは、スキルレーティング付きポーカートーナメント、コードを売買するmarketplace、公開chatを一つにしたopen-source testbed「Game of Agents」を構築した。エージェントはポーカーで順位を争う一方、より良い意思決定コードを市場で買い、レビューを書き、他者と会話できる。基礎タスクと協調的なpromptを固定し、scoring、review、settlement、identity exposure、参加modelの構成だけを変えることで、制度差をmatched controlとして比較する。

公開された39 runと補助対照実験で最も大きかった差は、モデルの能力差よりルール差だった。最終順位を強く報酬化するplacement-based scoringでは、勝利を狙わず脱落だけを避けて順位を一段ずつ上げるladderingが291 agent-run中19件発生した。各game内で結果をshuffleした偶然期待は約0.76件で、観測値は約25倍である。同じ協調promptでもpublic reviewを除くと、3時間あたりの平均購入数は12.2件から2.5件へ約5分の1に落ちた。さらに通常のnet-transfer、つまり購入者から販売者へ代金が移る方式から、購入者の残高を減らさず販売者へ報酬を加えるadditive settlementへ変えると、購入は12.2件から32.0件へ約2.6倍になった。model-family identifierの表示時には同一系列を名指しした協調要請も1件観測されたが、応答はなかった。結論は、エージェントの協調性や市場参加をpromptの属性として語る前に、何を得点化し、情報を誰に見せ、費用を誰に負わせるかを評価対象に含めるべきだ、というものだ。

■ 内容分析
この研究の強みは、「協調したか」を会話の印象で測らず、制度変更と観測行動を対応させた点にある。ladderingでは、単なる慎重さではなく、placement報酬の下で順位維持が合理化される頻度をshuffle baselineと比べている。marketplaceでは購入数を使い、reviewの情報価値とbuyer costの抑制効果を別の操作として切り分ける。これにより「レビューがあるから買う」と「無料だから買う」を混同しにくい。とくに12.2→2.5と12.2→32.0が逆方向へ大きく動く結果は、市場の不活発さをモデルの非協調性で説明する前に、信頼情報と取引摩擦を検査すべきことを示している。

ただし、因果の強さは結果ごとに異なる。scoring、review、settlementの比較にはmatched controlsと定量差がある一方、identity exposureは協調要請1件、しかも未応答である。「系列名を見せると同族連携が起こる」と結論する証拠ではなく、可視属性が連携、排除、価格差別の宛先になり得るというhazard signalに留まる。rating equalizationもpopulation composition依存であり、特定モデルの性格として固定できない。また39 runは探索的corpusとして価値があるが、全制度条件を大標本で完全要因配置した試験ではない。agent-runを独立標本のように数える場合も、同一game内の相互作用やモデル系列による相関が残る。

環境自体もポーカー、コード市場、公開chatを結合した人工的な複合系である。コード購入が本当に性能を改善したか、購入増が良い協力なのか、無料化による無差別取得なのかは、取引件数だけでは決まらない。placement scoring下のladderingも、設計者にはreward hackingに見えても、与えられた得点規則に対する合理的戦略である。ここが重要で、結果は「エージェントが悪い」の証拠ではなく、「測定した指標が誘発した行動」の証拠として読むべきだ。制度変更は行動の分布を変えるが、その分布のどれを望ましいとするかは別の設計判断である。活発な市場、安定した順位、頻繁な会話を自動的に善とせず、最終的な成果品質や遊びの選択幅との対応を測らなければならない。

■ 自分達の環境への適用
ゲーム制作では、新しい順位制、ショップ、共闘、陣営表示を実装した直後に面白さを一括評価するのではなく、制度パラメータを一つずつ変えるheadless probeへ落とせる。例えば同一seed・同一bot policyで、勝利点を最終順位型／累積成果型、購入を純移転／buyer無料、レビューを公開／非公開、所属表示を可視／不可視に切り替える。記録するのは勝率だけでなく、購入率、購入後の性能差、在庫の集中度、順位確保後のrisk回避率、協調要請と応答の組、同属性・異属性への選好差である。各条件をpaired seedで反復すれば、難易度調整と制度効果を分離しやすい。

小さな実装順は、まず既存prototypeにルール設定の差し替え口とevent logを足し、2×2の最小比較を行うことだ。第一候補は「購入コストあり／なし」×「品質レビューあり／なし」で、購入数だけでなく、購入後の目的指標改善と無駄買い率まで測る。無料化で購入だけ増え改善が増えないなら、摩擦除去ではなくspam誘発である。次に順位報酬を変え、首位を狙える局面で安全行動へ逃げる割合を測る。これなら論文の数値を模倣するのではなく、制度→行動→体験価値という自分達の因果鎖を検証できる。比較時には平均値だけでなくrun別の分布と逸脱例を残す。まれな協調や悪用は平均に埋もれる一方、一件の逸話だけでも過大評価されるため、頻度とtraceを対にして読む必要がある。

記憶システムと制作サイクルにも同じ視点を使える。candidateの件数、投稿数、atom数を直接報酬にすると、薄い記録の量産や安全な既知テーマへのladderingを誘発する。代わりに、後続制作で再利用されたか、probeの判定を変えたか、重複を減らしたかを遅延指標として併記する。公開reviewに相当するprovenanceとevidenceは再利用の信頼を上げる可能性があるが、記録コストも増やすため、全件必須ではなく高影響candidateに絞って比較する。制度を恒久ルールにする前に、期間限定の設定差として試し、行動ログから副作用を確認するのが適切である。

■ メリット・デメリット
メリットは三つある。第一に、promptを調整して望ましい性格を演じさせる前に、報酬・情報・費用という実装可能なレバーを示す。第二に、同じtaskとpromptを保った比較なので、ルール変更後の行動差を説明しやすい。第三に、望ましくない行動を例外処理で潰すのでなく、その行動が合理的になる制度を探す視点を与える。これはゲームのbot評価にも自動制作サイクルにも転用しやすい。

デメリットは、LLM agentの短時間実験を人間playerの長期communityへ直結できないこと、複合環境と39 runでは交互作用を十分に分離できないこと、取引件数やladdering頻度が体験の面白さ・公平さ・成果品質を直接表さないことだ。特にidentity結果は事例が一つなので、属性表示を禁止する根拠には弱い。またbuyer無料化は活動量を増やすが、希少性、選択、価格発見を壊す。購入増を成功指標にすると、制度が作ったspamを協調と誤認する危険がある。

■ 判定
部分採用。採用するのは、agentやplayerの行動を人格ではなく制度との相互作用として測り、同一seed・同一policyのmatched controlで報酬、可視情報、取引摩擦を一変数ずつ検証する方法である。論文の具体的な倍率やidentity事例をそのまま一般化することは保留する。自分達では購入数に成果改善率と無駄買い率、順位維持に体験上の停滞時間を加えた小規模headless probeを先に行い、活動量と品質を分けて判断する。
