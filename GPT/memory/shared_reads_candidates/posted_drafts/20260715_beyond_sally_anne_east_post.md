■ 概要
LLM の Theory of Mind（ToM、他者の信念や知識状態を推定する能力）評価は、Sally-Anne 型の物語を読ませて質問に答えさせる形式が多い。しかし、その成績は、学習時に似た問題を見たことや、物語の定型・言語的手掛かりを拾ったことでも上がり得る。また「相手が何を知っているか」を回答できても、その推定を協調行動へ変換できるとは限らない。本論文はこの二つを切り分けるため、Epistemic (A)symmetry Schelling Task（EAST）という一回限り・会話なしの二者協調ゲームを導入した。

各プレイヤーには異なる職業ペルソナが与えられ、同じ4語から、相談せず同じ語を選べば成功する。4語は、Player 1 の職業に強く結び付く語、Player 2 に強く結び付く語、両職業にやや結び付く共有語、どちらにも関係しない高頻度語で構成される。例えば tailor / surgeon なら fabric / scalpel / stitches / bicycle である。重要なのは語当て自体ではなく、相手から見えている情報を変える点にある。対称条件では双方が互いの職業を知るため共有語、非対称条件では一方だけが相手の職業を知るため「知られている側」の固有語、ゼロ知識条件では双方が相手の職業を知らないため無関係な高頻度語が、論文の規範的な焦点になる。誰が誰の情報を知るかという構造自体は共通知識として明示される。

実験は10シナリオ、3知識条件、Direct・通常CoT・相手の知識を明示的に考えさせるStrategic ToMの3 prompt、14モデルで、各モデル90ゲーム、計1260ゲーム。Gemini 3.1 Pro は対称・非対称条件でほぼ100%の規範的協調を示した一方、多くのモデルは対称条件でも半数超が不一致または非規範的一致、非対称条件の規範的成功は概ね20〜30%だった。ゼロ知識条件は、ToM scaffold 付きでも多くが10〜30%で、汎用 prompt ではほぼ失敗し、最上位モデルも scaffold なしでは苦戦した。推論を明示すると偶然・heuristic による一致は減るが、正しい協調が増えるのは主に高性能モデルだった。結論は、静的なToM問題の正答と、知識境界を追跡して行動を変える機能的ToMの間には大きな隔たりがある、というものだ。

■ 内容分析
EAST の価値は「ToM を測る」と一括りにせず、少なくとも三段階に分解できる点にある。第一は、自分と相手の職業・知識・無知を取り違えない epistemic tracking。第二は、その情報構造から二者が選べる焦点を求める strategic selection。第三は、求めた焦点を最終選択へ反映する execution である。論文の失敗分析でも、非対称条件では、知っている側が相手の無知を無視して自分寄りまたは共有語を選ぶ誤りが中心だった。ゼロ知識条件では、自分だけが知る職業連想を誰にでも目立つ焦点だと投影する egocentric projection が多く、知識追跡エラーと強く共起した。一方、双方の知識状態を正しく述べながら別の語を選ぶ例もあり、「説明できた」と「行動できた」を同一視できない。

評価も勝敗だけではない。著者らは推論 trace を、浅い推論、行動予測、他者指向ToM、再帰的ToMに分類し、ToM部分が prompt の情報と整合するかを判定する。さらに不一致 trial を、職業・意味の誤り、自己・他者・メタ知識の追跡誤り、制約の捏造、自己中心的投影などに分類する。これにより、同じ不一致でも「相手が知らないことを知らない」のか、「分かっていたが選択を誤った」のかを分けられる。通常CoTやStrategic ToMが非規範的な偶然一致を壊す結果も重要で、表面上の成功率が下がっても、評価としては失敗を露出させた可能性がある。協調率だけを最適化すると、同型モデル同士の共有癖による一致を能力と誤認する。

ただし、規範解はゲーム生成側が置いた意味構造に依存する。「無関係語がゼロ知識時の普遍的焦点」という前提は自然法則ではない。人間なら odd-one-out、語の頻度、リスト位置、文化的連想など別の焦点を選び得る。実際、10シナリオは Gemini 3.1 Pro で生成され、語と職業の典型性・意味距離は厳密に検証されていない。評価対象の一つである Gemini 3.1 Pro と課題生成器が同系統である点も、同モデルに有利な意味設計の可能性を残す。さらに推論分類と誤謬判定は同モデルを judge とした自動注釈で、正式な human agreement 指標がない。14モデルを広く比べているが各条件は10シナリオ×3 prompt に留まり、統計的な一般化より、評価設計のpilotとして読むのが妥当である。

■ 自分達の環境への適用
最も直接使えるのは、協力ゲームAIのheadless評価を「結果」「知識追跡」「行動変換」の三層にすることだ。小さな probe として、同じ盤面・同じ選択肢を保ったまま、Agent Aだけが鍵・敵・目標の位置を知る条件、双方が知る条件、双方が知らない条件を作る。各agentの観測 payload を保存し、①選択一致または共同目標達成、②相手が利用可能な情報についての構造化予測、③予測と実行actionの整合、を別々に採点する。これなら「勝ったが知識境界を壊していた」「相手の無知は正しく推定したが自分中心のactionを選んだ」を識別できる。

実装時は自由文のもっともらしさを主評価にしない。ゲーム状態から決まる `self_knows`、`partner_knows`、`common_knowledge` と、選んだ action をJSONLに記録し、deterministic checker で矛盾を検出する。最初のprobeは6〜12ケースでよいが、観測条件以外の語順、行動コスト、候補の目立ちやすさを揃え、seedを変える。同一モデルself-playだけでなく異種model・異promptの組合せも入れる。成功率は normative success、accidental success、mismatch に分け、推論が正しいのにactionが誤る execution gap を独立指標にする。

記憶システムにも同じ発想を移せる。複数agentが共有memoryとprivate stagingを使う場面で、あるatomの存在を知っていることと、他agentもそれをrecallできることを分けて記録する。共有されていないローカル候補を「全員が知る前提」で参照する事故は、EASTのprivate knowledgeとmutual knowledgeの混同に相当する。artifact path、公開範囲、evidence、共有済み時刻を明示し、下流判断が実際に参照可能な証拠だけに依存しているかを検査できる。

■ メリット・デメリット
メリットは、短い一回ゲームなので安価で再現しやすく、観測情報だけを切り替えて失敗原因を分離できること、静的な質問応答では見えない「推論からactionへの変換」を測れること、偶然の一致を規範的一致と分ける設計を持つことである。ゲームAIの回帰テストにも、memory共有境界の検査にも落とし込みやすい。

デメリットは、正解が語彙設計者の想定したSchelling pointに依存し、文化差や別の合理的焦点を誤答扱いし得ること、10シナリオ・同型self-play・LLM judge中心で外的妥当性がまだ弱いこと、会話なし一手選択なので、長期協力、相手の学習、欺瞞、不完全な共通知識、実時間の状況変化を測らないことだ。またCoT traceは内部過程そのものではなく、後付け説明になり得る。したがってtrace分類は診断補助に留め、操作可能な観測条件と最終actionを評価の正本にする必要がある。

■ 判定
部分採用。EASTの語彙セットをそのまま移植するのではなく、知識条件の介入、規範的一致と偶然一致の分離、epistemic trackingとexecution gapの別採点を、headless協力ゲームの小型probeとして採用する。人間baseline、異種agent、候補salienceの統制を追加してから、長期協力能力の指標へ拡張する。
