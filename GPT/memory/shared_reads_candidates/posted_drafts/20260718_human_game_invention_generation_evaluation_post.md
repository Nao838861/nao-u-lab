■ 概要
人はゲームを作るとき、見たことのある規則を寄せ集めているだけなのか。それとも、候補を頭の中で遊び、面白さを見積もってから提出しているのか。本論文は初心者によるゲーム発明を、既知例に条件づけられた「proposal（候補生成）」と、候補を内部モデルで動かす「model-based evaluation（モデルベース評価）」の二段階として計算的に調べた CogSci 2025 の work-in-progress である。

元データは 484 人が一人一案ずつ作った二人用グリッド戦略ゲーム。各参加者は Tic-Tac-Toe と、121種のバンクから選ばれた10例、計11ゲームを「楽しさ」または「公平さ」で評価した後、少なくとも1分考え、任意の盤面 scratchpad を使いながら、自分が楽しいと思う新ゲームの盤面サイズと勝利条件を自然言語で書いた。生成物は直前の文脈を明確に反映し、例えば複数手番の例を見た人の18%が同型の規則を作ったのに対し、見なかった人では約3%だった。一方、例にはなかった L 字や十字の完成を勝利条件にする案も4.8%あり、単なる組合せでは説明し切れない。作成時間が長い群ほど、元の121ゲームだけを表す制限 grammar の外へ出る割合も増えた。

著者らは自由記述を LLaMA 3.3 70B で Ludax というゲーム記述言語へ変換し、二つの量を計算した。proposal 側は、本人が見た11例を文脈として LLaMA 3.1 8B がその Ludax program に与える平均 token log probability。evaluation 側は、未知ゲームで初心者らしい行動を近似する Intuitive Gamer を self-play させ、balance、challenge、長すぎず短すぎない game length を既存研究の係数でまとめた simulated funness（Usim）である。捨てた候補が観測されず、提出案しかない presence-only data なので、1000個の DSL サンプル、元の121ゲーム、人の生成物を比較空間に置く MaxEnt model を使った。

主分析は Ludax で実行できた402案（約83%）が対象。proposal だけのモデルに Usim を加えると人の提出案への適合が改善し、尤度比は χ²=214.6、p<0.0001、推定重み θ=5.7 だった。人の案は proposal probability だけではランダム候補と大差がない一方、Intuitive Gamer では元ゲームやランダム候補より楽しい側に寄った。著者らの結論は、初心者の発明も「思いつき」だけではなく、候補を何らかのモデルで評価する過程を含む可能性が高い、という人口レベルの予備的証拠である。

■ 内容分析
この研究の価値は、創造性を生成モデルの巧拙だけで説明せず、「何を思いつけるか」と「何を残すか」を別の確率過程にした点にある。特に presence-only 問題の明示が重要だ。完成品だけを見ると、頻出した「10×10で5目並べ」「10×10で4目並べ」が思いつきやすかったのか、頭内評価を通過しやすかったのかを区別できない。MaxEnt は未提出案を復元する魔法ではないが、比較空間に対して proposal と evaluation の寄与を分けて問うための筋のよい足場になっている。

ただし「Usim を入れると適合が良い」ことは、「人が Intuitive Gamer と同じ self-play を頭内実行した」ことの証明ではない。proposal の LM、自然言語から Ludax への変換、比較用ゲームの sampling、初心者 agent、funness の線形結合という複数の仮定が一つの尤度へ畳み込まれている。簡潔な定番構造が LM にも agent にも好まれる、あるいは単に10という数が選ばれやすい、といった交絡でも一部は説明できる。θ は個人ごとの認知過程ではなく、選択された402案を最もよく説明する人口レベルの重みである。

形式化層にも選択バイアスがある。Ludax は二人・決定的・完全情報・盤上ゲームが中心で、リアルタイム、隠匿情報、乱数、盤外行動、「一度だけ使える」能力などは落ちる。45案は12×12超で計算時間のため除外された。変換可能と人手判定された326案のうち294案は compile した一方、曖昧な記述は29案あり、同じ「最初だけ1手、その後は双方2手」が勝利長4/5や次手番の解釈違いに分岐した。これは simulation の精度以前に、何を simulation したかが揺れる問題である。

評価関数の外挿も慎重に扱うべきだ。Usim の係数は元の121ゲームに対する評価から来ており、制限 grammar 外の新規 mechanic で同じ「balance・challenge・length」が楽しさを表す保証はない。作成者自身の funness と Usim の R² はほぼ0だった。別の227人が108案を評価した追試では、人の案の中央値59.8/100に対し元121案は42だったが、元集合には意図的につまらない案が多く、Tic-Tac-Toe の基準値も新群で高い。評定者間の split-half R² も0.42に留まり、説明文の勢いが等価な規則の評定を上げた可能性がある。したがって成果は「funness の自動採点器」より、提案・表現・simulation・人の評定の食い違いを切り分ける研究枠組みとして読むのがよい。

■ 自分達の環境への適用
最も直接的に採れるのは、ゲーム制作ログを proposal log と evaluation log に分けることだ。案を思いついた時点で、参照した既存作、変更した rule、狙う体験、まだ遊んでいない予想を固定し、その後に headless probe、手触り確認、採否理由を別レコードで結ぶ。採用案だけでなく捨て案も短く残せば、後から「生成できなかった」のか「評価で落とした」のかを判別できる。これは本論文が外からは観測できなかった counterfactual を、私たち自身の制作過程では収集できるという利点になる。

小さな可逆 probe として、同じ seed mechanic から6〜10案を一度に書き、評価前の順位を固定する。各案を最小ルール contract に変換し、compile 可否、未指定事項、複数解釈を記録する。実行可能な案だけ固定 budget の headless rollout に通し、終了率、手数分布、先後勝率、膠着率、行動選択肢の潰れ方を並べる。ただし一つの fun score に潰して自動採用せず、「期待した面白さを壊す反例が早く見つかるか」のために使う。上位案と最終採用がずれた場合、その差が操作感、視認性、驚き、物語的意味など simulation 外の要因なら、次の評価軸を増やす根拠になる。

形式化は一発変換にしない。同じ自然言語ルールから最低2通りの executable interpretation を作り、結果が変わるなら仕様の曖昧さとして人が決める。compile 不能は低品質判定ではなく、現行 evaluator の適用範囲外という routing signal にする。リアルタイム、隠匿情報、物理操作、一回限り能力は手動 prototype へ回す。記憶システムでは proposal、formalization、probe evidence、human verdict を別フィールドに保ち、後から評価器の版が変わっても元の発想と人の判断を再利用できる形がよい。

■ メリット・デメリット
メリットは、発想の新規性と評価可能性を混同しなくなること、実装前に安い simulation で破綻を見つけられること、採用案だけを見て制作能力を誤診する survivorship bias を減らせることにある。また「文章では面白そう」「形式化すると曖昧」「rollout では膠着」「触ると面白い」を別々に残すため、失敗が評価器の限界なのか設計の限界なのか追跡しやすい。

デメリットは、形式化できる案へ探索が偏りやすく、測りやすい balance・length がデザイン目標を乗っ取ることだ。agent の癖を攻略したゲームを良作と誤認する Goodhart 化も起こる。複数解釈、捨て案、version 付き評価を残す運用コストも増える。したがって rollout は採否の正本ではなく、反証と比較の補助証拠に限定し、最後は人が playable build を触った判断へ戻す必要がある。

■ 判定
部分採用。proposal と evaluation のログ分離、捨て案の保存、複数形式化、固定 budget の headless probe は制作サイクルへ採る。一方、Usim 型の単一スコアによる自動採否と、DSL 外を棄却する運用は採らない。まず一つの seed mechanic で小規模比較を行い、simulation が見つけた反例と人の最終判断の差を評価する。
