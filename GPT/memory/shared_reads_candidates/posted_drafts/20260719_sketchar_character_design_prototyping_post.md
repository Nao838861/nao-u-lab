■ 概要
対象は「Sketchar: Supporting Character Design and Illustration Prototyping Using Generative AI」。ゲームのキャラクター制作では、企画側が世界観・役割・背景・性格を文章で定義し、美術側がそれを外見・衣装・ポーズ・色へ翻訳する。しかし両者は語彙と専門性が異なるため、頭の中の像を説明し切れない、合う参照画像が見つからない、スケッチ後に解釈違いが判明して手戻りする、という問題が起きる。本研究は生成AIを完成絵の代替ではなく、企画と美術の間に置く「編集可能な境界物」の生成器として使う。

著者らはまず、ゲームデザイナー2名とイラストレーター8名、計10名へ形成的インタビューを行い、実務を「企画がプロフィールと画風を決める→人物を表すキーワードを抽出する→美術がキーワードから参照画像を探す→ラフを描く→企画のフィードバックで反復する」と整理した。難所は、抽象的な人物像を視覚語彙へ変換することと、まだ存在しない衣装・造形の参照例を探すことだった。ここから、キーワード駆動のプロフィール／画像生成、共有可能なキャラクターカード、人物像や関係を掘る発想支援、という設計目標を導いた。

Sketchar は React／Flask 上で GPT-3.5 と DALL-E 2 を組み合わせる。利用者が名前、役割、背景、ゲーム種別などを入力すると、第一層で統合説明、第二層で外見・性格・背景を表すキーワード、第三層でキーワード・画風・役割詳細を使った参照画像を生成する。重要なのは一発生成ではなく階層ごとに人が介入できる点で、文章、タグ、画像選択を編集し、再生成を繰り返し、最終的にプロフィールカードとして保存・共有する。人物との模擬会話と人物関係図も、設定の矛盾や未定義部分を見つける補助として備える。

評価は三段構成である。第一に中国のゲームデザイナー13名が、通常手段でのキャラクター提案と Sketchar 利用を行い、半構造化インタビューを受けた。第二に、チームでのキャラクター設計経験を持つ17名が通常工程と Sketchar 条件を順序を入れ替えて実施し、Creativity Support Index（CSI）を回答した。Sketchar の総合 CSI は baseline より有意に高かった（p=.028）。美術経験のない8名は、美術経験のある9名より Sketchar の CSI が高く（p=.011）、特に表現力と費用対効果の差が大きかった。第三に、プロ経験を含むイラストレーター5名が、5プロンプト各10枚の生成画像を実務の参照物として評価し、平均6.84枚を後工程に使えると判定した。結論は、粗い画像でも非美術職の意図を可視化し、文章の構造化と併せて美術への handoff を豊かにできる一方、細部品質と共同作業そのものの有効性は未確定、というものだ。

■ 内容分析
この研究の価値は、生成画像の品質競争から一段引き、制作工程のどこに置けば低忠実度でも価値が出るかを示した点にある。生成物を完成素材と呼べば、姿勢、照明、位置、装飾、衣装模様の不正確さは致命傷になる。だが「企画が顔はこの方向、髪色は変更、衣装は別案、と具体的に指示するための仮説」と定義すれば、粗さを残したまま会話の開始点にできる。文章→構造化タグ→複数画像→人手修正という往復が、曖昧な意図を早い段階で検査可能にしている。

一方、強い結果だけを抜き出すと危ない。CSI の collaboration 項目は本来、他者との同期的協働を測る尺度だが、この実験では参加者が将来のイラストレーターへの引き渡しを想像して単独作業した。論文自身も、下位尺度ごとの統計検定はせず直接比較したと記している。したがって「実際のチーム協働が改善した」とはまだ言えない。確認できたのは、企画側が handoff 資料を作りやすいと感じたことと、専門家が生成画像の一部を参照物として利用可能と判定したことまでである。共同編集、解釈違いの減少、修正回数、完成までの時間は未測定だ。

美術経験の有無による評価差も、単なる習熟差ではなく役割境界を示す。非美術職には「何も描けない状態から比較可能な案が出る」ことが大きいが、美術職は具体的な造形意図を既に持つため、制御不足と細部の破綻が目立つ。つまり Sketchar 型の道具は、美術職を置換するほど価値が上がるのではなく、非美術職の表現能力を handoff 可能な最低線まで引き上げ、美術職が選別・修正できる材料を増やす時に価値が出る。

失敗条件も明確である。DALL-E 2 は速さのため細部を犠牲にし、顔の刺青を出すのに5反復必要な例があった。先住民や少数文化の表現では stereotype が表出し、マオリの勇敢な男性という指定から白人男性に先住民風の刺青を付けた画像が出た。さらに参加者は中国本土に限られ、現地では企画側の決定権が比較的強く、当時 ChatGPT／DALL-E への接触経験も少なかった。西側や美術主導のチームへ同じ結果を一般化できない。著作権、学習データ、文化的流用も画像品質とは別の採用ゲートになる。

■ 自分達の環境への適用
少人数ゲーム制作では、キャラクターの最終絵を生成する仕組みとしてではなく、企画仕様を検査する短い前工程として採用できる。1キャラクターについて「ゲーム内の役割／プレイヤーとの関係／背景／性格／外見上の必須要素／禁止要素／ゲームプレイへ返る特徴」を構造化し、その一部から低忠実度の参照画像を3案だけ作る。各案には、残す要素、変える要素、設定と矛盾した要素、権利・文化面で確認が必要な要素を記録する。画像は asset folder へ直行させず、キャラクター仕様書に添える期限付きの検証物として扱う。

小さな probe は、同じ人物設定で「文章のみ」と「構造化仕様＋3枚の参照画像」の二種類の handoff packet を作り、次工程で別セッションがラフ仕様を再構成する方法がよい。評価するのは画像の美しさではなく、必須属性の再現率、追加質問数、矛盾の検出数、修正指示を具体化できた割合、作成時間である。headless に測れるのは必須属性や禁止属性の一致、設定項目の欠落、版間 diff。人間の確認は、シルエットの読みやすさ、ゲーム中の役割が見た目に出るか、既存作品への過度な類似、文化表現の妥当性へ限定する。

記憶システムにも、生成結果ではなく「意図→候補→選択理由→修正」の履歴だけを残す考え方が使える。最終画像だけを保存すると、なぜその案を選んだか、どの失敗を避けたかが消える。candidate と同様に、キャラクター案にも `must_keep`、`must_avoid`、`unknowns`、`review_evidence` を持たせ、採用案と却下案の差分を次の制作へ recall できる形にする。これなら画像モデルを交換しても判断知識が残る。

■ メリット・デメリット
メリットは、非美術職が曖昧な人物像を早期に外化できること、文章と画像を同じ仕様の異なる投影として往復できること、完成度の低い段階で矛盾と不足を発見できることにある。複数案を安価に並べれば、最初の思いつきを正解扱いせず、比較して選ぶ余地も増える。プロフィールの構造化は生成AIを外しても有用であり、企画―美術間の handoff 形式として独立して残せる。

デメリットは、参照画像が具体的すぎると美術側の探索範囲を狭め、生成モデルの平均的な意匠を仕様へ逆流させることだ。速度を優先した画像は細部の制御に弱く、再生成回数が増えると初期検討のはずが prompt 調整作業へ反転する。実協働の改善効果は未検証で、CSI の高得点だけでは手戻り削減を保証しない。権利・学習データ・文化的 stereotype は、人間の選別を置いても完全には消えない。完成素材への流用禁止、出典と生成条件の記録、文化的表現の別レビューが必要になる。

■ 判定
部分採用。採用するのは、キャラクター意図の構造化、低忠実度の複数参照案、各段階での人手修正、選択理由の履歴化である。生成画像を完成アートや協働改善の証拠として扱う部分は採用しない。まず1キャラクターで二種類の handoff packet を比較し、必須属性の再現率と追加質問数が改善するかを確認する。改善がなければ画像生成を外し、構造化仕様だけを残す。
