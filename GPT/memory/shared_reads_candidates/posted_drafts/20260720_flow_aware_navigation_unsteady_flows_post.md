■ 概要
対象は「Flow-aware Optimal Navigation in Unsteady Flows through Reinforcement Learning」。時間で変化する風や潮流の中を移動する機体は、流れの全体像を事前に知れず、搭載センサーで得る局所情報だけから進路を決めなければならない。古典的な最適制御は時々刻々の流速場を既知とすることが多いが、現実の流れは部分観測で、予測誤差も大きい。論文はこの問題を、情報を増やして完全観測へ近づけるのではなく、「局所速度・局所渦度・短期履歴のどれを見せれば、流れを利用する方策が育つか」という観測設計の比較として扱う。

環境は二つの渦が左右に並び、境界が周期的に揺れる parametric double-gyre flow である。領域は 2×1、1 episode は 80 秒、刻みは 0.1 秒。開始点と目標は毎 episode ランダムで、流れの強さ A と振動周波数 ω も範囲内から変える。流れの最大速度が制御入力より大きくなるよう action を各軸 [-0.2, 0.2] に制限し、直線的に押し切るのではなく渦を利用させる。agent は連続制御向け off-policy actor-critic の TD3 で、8,000 episode 学習する。報酬は目標までの二乗距離、操作量の二乗 penalty、目標半径 0.055 内の bonus の和で、到達直後に終了せず、その近傍へ累計 100 step 超とどまった時だけ成功とする。したがって評価対象は単なる到達ではなく、移動、station-keeping、energy efficiency の組合せである。

比較する五条件は、目標への相対位置と時刻を持つ naive、相対位置＋現在の局所速度、相対位置＋現在の局所渦度、直近 M 回の速度を持つ velocity-history、直近 M 回の渦度を持つ vorticity-history である。履歴長は 5・10・15 を予備比較し、中間の M=10 を採用した。長いほどよいのではなく、短すぎれば変化を復元できず、長すぎれば古い流れと高次元入力が判断を濁すという設計である。各結果は seed 1・5・10 の三試行平均、成功率は 200 episode の移動平均で報告される。

結果は velocity-history が成功率約71%で最高、約3,000 episode で peak performance に達した。naive は絶対時刻を流れの位相の proxy にできるため早く学ぶが、流れの特徴を直接認識できず約49%で最低。現在値だけの velocity は約60%、vorticity は約58%、vorticity-history も約60%だった。速度履歴は流れ構造の時間変化を復元して成功率を上げた一方、渦度履歴は累積報酬こそ高くなるが成功率を伸ばさず、入力増加で学習も遅くなった。sensor の役割も同一ではなく、速度観測は操作 penalty を抑えて省エネルギーに進み、渦度観測は渦構造を捉えて目標との距離を詰める側に効いた。

さらに全条件へ大域パラメータ A・ω を足すと、ほぼ全てで性能が低下した。naive は約49%でほぼ不変、vorticity は約54%、velocity は約60%から約49%へ落ち、履歴型も blind 条件を下回った。著者らは、局所観測と大域的な記号パラメータの対応を network が有効に結び付けられず、暗黙の局所表現へ制約した方が頑健な方策を学ぶと解釈する。結論は、観測量を一律に増やすのでなく、目的に合う sensor と適度な履歴を選ぶことが重要だというものだ。

■ 内容分析
この論文で最も使えるのは「記憶あり対なし」だけでなく、同じ環境・同じ TD3・同じ報酬のまま observation channel を分離した点である。約71%対49～60%という差から、履歴一般が有効なのではなく、二成分の速度を10時点並べた履歴が有効だったと読める。渦度は一つの scalar でも速度二成分に近い成功率を早期に得るため、局所構造を圧縮する sensor として効率がよい。しかしその履歴を増やしても成功率は伸びない。つまり sensor の「現在地を特徴づける力」と「時間変化から状態を復元する力」は別で、memory budget は情報源ごとに割り当てる必要がある。

大域パラメータの悪化も、「情報が少ないほど常によい」という一般則ではない。A・ω は全体の流れを定義するが、現在位置でどう動くべきかへ変換するには局所速度、位相、位置との非線形な対応を学ぶ必要がある。固定サイズの MLP に値を二つ足しただけなので、性能低下は表現の混線、学習 sample の不足、正規化、network capacity、conditioning 手法の不適合でも説明できる。parameter-aware policy 専用 architecture や十分な学習量との比較はなく、因果は確定していない。使うべき教訓は「大域情報を隠す」ではなく、「action に結び付かない高レベル情報は、追加前後を ablation し、利用経路を検証する」である。

評価の限界も明確である。数値は三 seed の training curve と移動平均が中心で、未見の A・ω 範囲、異なる flow topology、sensor noise、遅延、欠測、障害物、3D、実機では測っていない。全 agent が100%に届かず、著者ら自身も難しい parameter draw で station-keeping できない可能性を挙げる。論文の「resilient / general」という結論は、同じ double-gyre 分布内での結果からの仮説であり、simulation-to-real transfer の実証ではない。速度履歴の優位も M=10、0.1 秒刻み、80 秒 horizon という時間尺度に依存する。

■ 自分達の環境への適用
直接移せるのは TD3 や流体方程式ではなく、動的フィールド内 NPC の observation ablation である。風、潮流、群衆密度、移動床、周期的 hazard がある小さな prototype を一つ固定し、同じ policy / planner に対して、目標相対位置のみ、現在の局所ベクトル、構造量、短期履歴、大域 phase の五条件を比較する。構造量は流体の渦度に限らず、近傍の危険勾配、群衆の回転・発散、足場速度差、敵圧の勾配など、その場の形を一値または少数値へ圧縮した sensor に置き換えられる。

headless 評価は success rate 一本にせず、到達率、目標近傍の滞在率、到達時間、自力移動量、外力を利用した距離、衝突数に分ける。これにより、速度 sensor が操作 cost を下げる一方、構造 sensor が接近精度を上げるという役割差をゲーム側でも見つけられる。固定 seed だけでなく、流れの強さ・周期・開始／目標を train 範囲内と範囲外に分け、最低でも複数 seed で比較する。履歴長は 0・短・中・長を振り、古い情報で悪化する点を探す。

最小 probe は、既存 prototype の一つの移動 challenge に対し、現在値、直近10 tick、global phase 追加の三条件だけを作る。各100 episode を同じ seed set で replay し、成功率と action cost を保存する。global phase で悪化した場合は即削除せず、入力の正規化、局所値との積や埋込みによる conditioning、学習量増加を一度だけ対照にする。それでも別 seed / 別周期へ転移しなければ、NPC に完全な world state を渡す設計を退ける根拠にできる。

ゲームとしては、最高成功率だけを選ぶと全知的で均質な NPC になり得る。速度型は省エネで流れに乗る個体、構造型は目標へ詰める個体、naive 型は周期を暗記して分布変化に弱い個体として、sensor の差を行動の個性へ変換できる。ただしまず headless 指標で差を確かめ、その後に人間から見て軌跡が読みやすく面白いかを画面で評価する。

■ メリット・デメリット
メリットは、NPC へ渡す情報を「多いほど強い」という一軸から、即時ベクトル、局所構造、時間履歴、大域記号の役割へ分解できることにある。到達と操作 cost を分けるため、同じ成功でも外力を巧く使ったかを判定できる。固定長履歴なら recurrent network を導入せず小さく試せ、sensor 差を NPC の性格付けにも利用できる。

デメリットは、double-gyre の滑らかな2D連続場とゲームの離散地形・衝突・意図を持つ敵では、必要な表現が異なること。三 seed と training metric だけでは一般化の根拠が弱く、約71%も失敗を三割残す。M=10 をそのまま移植する理由はなく、frame rate が変われば時間幅も変わる。大域情報の悪化を「情報を隠せば賢くなる」と演出設計へ一般化すると、単なる学習不足や architecture mismatch を見逃す危険がある。

■ 判定
部分採用。採るのは局所ベクトル・構造 sensor・短期履歴・大域 parameter を分ける ablation と、到達精度／操作 cost の分離評価である。TD3、M=10、double-gyre 固有の成功率は移植しない。小さな動的フィールドで current-only、history、global-aware を同一 seed で比較し、範囲外条件への転移と画面上の軌跡差まで確認できた場合に、NPC の標準知覚設計へ広げる。
