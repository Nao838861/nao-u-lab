■ 概要
『Tiny Trees』は、42枚の六角形 card を互いに差し込み、崩れない立体の樹を作りながら得点を競う board game である。通常の平面 card game と違い、部品の切れ込みが合法手だけでなく、実物の形状と balance を決める。高品質 cardstock を手で切り、個別に絵を描く prototype は作り直しが高価なので、作者 Michael Perce は playtest の回数だけに頼らず、組合せ論と確率計算で設計空間を先に絞った。記事の主題は「数学で楽しさを証明する」ことではなく、物理試作を壊して作り直す前に、どの分布を試す価値があるかを数値で明確にすることである。

六角形の各辺を「切れ込み有り／無し」の二値とすれば、空集合を除く配置は63通りになる。ただし60度回転や鏡像で機能的に同じ形を畳むと、固有 design は12種まで減る。この列挙で、中央からずらした切れ込みや一辺に複数の切れ込みを導入せずとも、現在の部品仕様で何が作れるかが見えた。初期版は全辺に切れ込みがあり、自由度は最大だったが、制約がないため player は慣れた同型の樹を繰り返した。反対に全 card が二つの切れ込みだけでは選択肢が少なすぎた。

最終版は三つの樹種それぞれについて、切れ込み二つを5枚、四つを4枚、六つを2枚とし、平均3.29個へ配分した。少ない切れ込みを多めにして形へ制約を与えつつ、六つの card も残して成長と物理 balance の逃げ道を確保した。ただし切れ込みの少ない card は置き方の自由を失うため、そのままでは選ばれにくい。そこで beetle、mushroom、bird の三種の lifeform を追加し、制約を受け入れる代わりの得点動機にした。

lifeform は各種6個、三樹種へ均等に配置した。全 card の約43%が lifeform 付きとなり、公開された選択肢上位3枚にちょうど一つ現れる確率は約45%、一つも現れない確率は約25%になることを hypergeometric calculator で確認した。特定の lifeform を集めるために一つの樹種を強制されないよう均等にし、lifeform 自体は切れ込みの少ない card へ寄せた。得点は同種を集める順に1・1・2・2・3・3点と段階的に増やし、偶然一つ取るだけでは大差を生まず、集める方針を続けた時に報酬が強くなるようにした。作者の結論は、こうした計算が playtest を不要にしたのではなく、曖昧な player 反応の背後にある「切れ込み分布」や「提示確率」を候補原因として特定しやすくし、物理 prototype の作り直しを減らしたというものだ。

■ 内容分析
この事例の強さは、三種類の数学が別々の設計問いに対応している点にある。対称性を除いた列挙は「実際に異なる部品はいくつか」、平均と頻度分布は「一枚当たりの自由度をどこへ置くか」、超幾何分布は「有限 deck から公開された選択肢に報酬記号がどの程度見えるか」を扱う。計算を一つの万能 score にまとめず、部品多様性、行動自由度、報酬可視性を別変数として扱っているため、playtest で問題が出た時に変更先を切り分けられる。

特に興味深いのは、切れ込みと lifeform が単純な足し算ではなく trade-off になっていることだ。切れ込みが多い card は物理的・戦術的な option value が高い。少ない card に得点源を置くことで、「今の置きやすさ」と「将来の得点」を比較する選択へ変えた。これは弱い item の数値を直接上げるのではなく、別の価値軸を付けて draft の選択肢として成立させる設計である。さらに同種収集を段階報酬にしたため、lifeform の一個目は偶然の小得点、後半は方針を維持する commitment reward になる。

ただし記事の数値には、追試に必要な前提が一部省略されている。42枚全体に lifeform が18個なら約43%という密度は確認できるが、「上位3枚にちょうど一つ45%、ゼロ25%」は deck の残り枚数、sampling without replacement、選択後の補充規則で変動する。作者もゲーム進行で確率が変わると述べており、初期状態の目安を全 turn の体験へ一般化できない。また1・1・2・2・3・3を exponential growth と呼ぶのは数学的には正確でなく、限界増分が段階的に増える schedule と読むべきである。

評価も定量的な A/B test ではない。何回の playtest で再印刷が何回減ったか、分布変更前後で樹形や勝率がどう変わったかは示されない。平均3.29という値にも最適性の証明はなく、合計が約12に揃うことや枚数が一段ずつ減る見た目の整い方も判断理由に含まれる。したがって価値は特定の数値を正解として輸入することではなく、試作前の仮説を計算可能な問いへ変え、playtest の観察と原因候補を接続した workflow にある。

■ 自分達の環境への適用
game prototype では、drop table、card deck、遭遇候補、upgrade pool の変更前に、まず「名目上の種類数」と「機能的に異なる種類数」を分ける。同じ効果を数値や向きだけ変えた option は対称性や同値条件で fold し、player から見た固有 decision がいくつ残るかを数える。生成要素が100通りあっても、選択結果が12通りしかないなら、content 量ではなく decision space の薄さが問題だと早期に分かる。

次に各 option の affordance と reward を別列にする。移動自由度、接続可能数、射程、装備 slot のような即時の使いやすさが低い要素へ、希少 resource、score、将来 synergy のどれを補償として載せるかを明記する。Tiny Trees の切れ込みと lifeform のように負の相関を意図したなら、その相関が実データでも保たれているかを test する。弱い option を一律 buff するより、異なる勝ち筋を作れているかを見る。

headless 評価では、各 seed について最初のN手に提示される category、報酬記号ゼロの連続長、特定 build が成立するまでの draw 数、choice set 内の支配的 option 比率を集計する。理論確率と simulation の観測値を並べ、補充、除外、重み付き抽選の実装ミスを検出する。平均だけでなく、ゼロ提示が連続する tail と、同一報酬が固まる偏りを見ることが重要である。平均密度43%でも、序盤に報酬が見えない run が長ければ player の認識は別物になる。

小さな probe として、現在の一つの drop table を対象に、(1)全候補を効果同値で分類、(2)各 category の deck 密度と三択提示確率を算出、(3)1万 seed を headless 実行、(4)人間 playtest では選択理由と「選びたくない option」を記録する。数値上の提示不足と、説明不足・触感不足を分離して直す。物理 prototype でなくても、人間のプレイ時間や生成 asset の作り直しが高価なら同じ前処理が効く。

記憶システムにも限定的に応用できる。recall candidate の tag 分布、上位3件に少なくとも一つ具体的な制作事例が入る確率、同値 atom の重複率を測り、人間レビューを「関連したか」「新しい判断材料だったか」に集中させる。ただし recall は独立同分布の card draw ではなく ranking なので、超幾何分布をそのまま当てず、実 query の replay で観測する必要がある。

■ メリット・デメリット
メリットは、高価な試作の前に極端な自由度不足、過剰な自由度、報酬の見えなさを発見できること。設計変数を列挙・分布・提示確率へ分けることで、playtest の曖昧な違和感に具体的な原因候補を持てる。数学は人間評価を減らすというより、触感、理解、驚きといった計算できない部分へ人間の時間を集中させる。

デメリットは、平均値や初期確率が整うと設計まで正しいように見えること。物理的な組みやすさ、card の可読性、樹が崩れる緊張、得点方針の楽しさはモデル外である。sampling 前提や同値分類を誤れば、精密な数字で間違った空間を探索する。この記事自体にも比較試験と effect size がないため、3.29、43%、45%を基準値として移植してはいけない。

■ 判定
採用。列挙と確率計算を playtest 前の design lint として導入し、人間評価の代替にはしない。採るのは数値そのものではなく、計算で原因候補を狭め、simulation と観察で前提を反証する二段構えである。
