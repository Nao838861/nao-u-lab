■ 概要
『POPOCHINKO』は、pavro_o が Ice Climber jam の8時間で制作した、固定画面を突破して high score を狙う arcade game である。出発点は Nintendo Land の pachinko mini-game だった。画面上部から弾を落として標的を消す骨格を借りつつ、cursor を自由に動く Popo へ換えたため、静止標的では狙撃が簡単すぎるという問題が生じた。作者は標的を動く野菜にし、さらに UFO 50『Star Waspir』の文字列 pickup を参照して、「野菜を取った順序で3個一組の効果が決まる」combo system を中心に据えた。野菜を全て取ると画面が終わり、次へ進む。

事前設計では、自由照準なら連射で解けるので弾数を制限し、弾数制だけでは慎重に狙い続けられるので timer を置き、途中で注意を奪う追跡敵を出し、一定画面ごとに全体速度を上げる、という圧力の連鎖を考えた。しかし作者はこの連鎖が patch の積み重ねと scope 超過へ向かっていると気づき、feature の優先順位と明示的な試遊点を jam 前に決めた。約1時間で一周する loop を作ると、発射中に Popo が停止するだけで連射には十分な機会費用があった。弾数制は時間不足で削られた面もあるが、試遊によって不要だと確信でき、むしろ追加すれば情報 noise を増やした可能性が高いと結論している。

combo は、同種3個の基本 combo、時間を増やす組合せ、全野菜を敵へ変える悪役 combo、突出して高得点な秘密 combo、その他の並びに対する300点から成る。出現率の高い lettuce は同種 combo にしか使えず、eggplant と carrot は時間 combo と秘密 combo の両方に必要で、出現率の低い turnip が秘密 combo の軸になる。この rarity と用途競合によって、turnip が見えた瞬間に「時間を足すか、秘密 combo に賭けるか」という画面固有の判断が立ち上がる。秘密 combo と悪役 combo は一覧で伏せられ、数回の試行と発見を促す。

完成後の観察で、作者は面白さの核を、画面開始時に layout、野菜、候補 combo を一度に読み、timer と敵の圧力下で短い計画を立てて実行することだと捉えた。上下に重なった野菜は取得順を物理的に制約し、欲しい turnip の上に lettuce があれば、先に別の3個組を完成させる必要がある。悪役 combo は初見では危機を生む surprise だが、理解後は魅力の薄い盤面を敵の接近で素早く掃除する reroll として働く。ただし高速時に野菜が多い画面で使えば、敵の群れが致命傷になる。

速度上昇は一つの run を二相に分けた。序盤は combo を精密に選び、点と時間を貯蓄できる。反応限界を越える終盤は、貯めた時間を使って combo を捨て、何画面生き延びるかへ目的が切り替わる。観戦からは、弾の落下中に次の標的へ移動する、敵の出現地点へ予防射撃する、画面終了時の敵死亡を二重計上する bug を得点技にする、といった未設計の戦略も見つかった。作者は一部を直せばゲームが悪くなると見る一方、score 更新を望まない人には緊張がほぼ成立せず、record 演出、50,000点の目標、秘密の空欄も動機付けとしては軽い、と限界を認めている。

■ 内容分析
この postmortem の重要点は、8時間で多くを実装したことではなく、「圧力を生むには制約を足す」という机上の因果を、最初の完全 loop で反証できたことにある。発射時停止は一見小さな操作仕様だが、狙う行為へ位置取りの中断、敵への露出、timer 消費を同時に課す。つまり弾数という別 resource を増やさなくても、既存 action の opportunity cost が連射を抑えていた。ここを見ずに弾数、補給 action、弾数回復 combo まで実装すると、同じ問題を複数系統で解き、読み手の注意と調整項目だけを増やしていた。早い loop の役割は仕様確認ではなく、仮説に必要な変数そのものを減らすことだと読める。

combo system は単なる「揃えると bonus」でもない。画面開始時の候補集合、野菜の rarity、上下の access 順、timer、敵、現在速度が、小さな planning problem を毎画面生成する。eggplant と carrot の用途競合は将来価値を持つ resource allocation であり、turnip の出現はその場の優先順位を変える event になる。さらに悪役 combo は、同じ操作の utility が知識と局面で反転する。初見では罰、学習後は低価値盤面の短縮、高速・多野菜時には再び自殺手となる。この「効果が多い」のではなく「状態によって意味が変わる」性質が、少数 mechanic から厚みを作っている。

加速も数値的な難度上昇以上の仕事をしている。序盤に稼いだ時間が終盤の生存 resource へ変換され、丁寧な score planning と反射的な画面 clear が一つの run 内で交代するため、game over 後の再開には再び低速の計画 phase へ戻る contrast がある。ただし、作者が確認したのは主に友人の競争と観戦から得た質的 evidence で、速度境界、各 combo の選択率、初心者が秘密を発見する率、継続率、score 志向でない人の離脱率は測っていない。二重得点 bug も、上達の余地を作る harmless な技か、他の判断を無価値にする dominant exploit かは未検証である。面白さの因果仮説は具体的だが、一般則ではなく次の計測対象として扱うべき資料である。

■ 自分達の環境への適用
短時間の arcade prototype では、最初の milestone を「主要 feature が揃った状態」ではなく、「開始、1画面の判断、成功または失敗、次画面、game over、restart が一周する状態」に置く。その上で、圧力を追加する前に、既存 action がすでに払わせている時間、停止、位置、照準、被弾 risk を列挙する。連射が問題なら即座に ammo を足すのではなく、発射中停止の有無だけを切り替え、shot 間隔、停止時間、被弾、無駄弾、clear 時間がどう変わるかを見る。制約は「実装できたか」ではなく、重複する摩擦がないかで削る。

headless 評価へは、各画面の seed、候補 item、上下の依存辺、現在速度、残り時間、敵数、計画した combo、実際の取得列、reroll 使用、画面 clear 時間を一行の episode log として残せる。低速 policy は combo 得点と時間貯蓄を、高速 policy は生存画面数を優先させ、速度を上げた時に選択が本当に切り替わるかを比較する。全速度帯で同じ greedy policy が勝つなら、数値だけが難しくなって二相化していない。逆に序盤の貯蓄が終盤の生存へ寄与しなければ、phase 間の接続が切れている。悪役 combo 型の mechanic は、「盤面を壊す即時損失」「次画面へ進む時間利益」「敵得点」「高速時の死亡 risk」を別々に記録し、特定の選択が常時最善になっていないか deterministic seed で検査する。

小さな probe としては、既存 prototype の一画面に3種類の取得物、順序 combo、上下 access、一つの破壊的 reroll、二段階の速度を仮置きし、有限 ammo あり／なし、発射時停止あり／なしを ablation するだけでよい。見るべきなのは score の絶対値より、序盤に複数の計画が残るか、高速化後に優先順位が変わるか、reroll の価値が局面で反転するかである。記憶へ残す単位も「ammo は不要」のような結論ではなく、「連射防止仮説→早期 loop→発射停止という既存摩擦を観測→ammo 削除→観戦で別戦略を発見」という因果列にする。これなら別 genre でも、制約を足す前に既存 cost を探す判断として再利用できる。

■ メリット・デメリット
メリットは、第一に、短時間制作でも早い完全 loop と試遊点を設計すれば、scope を守るだけでなく不要な system を自信を持って捨てられること。第二に、combo、rarity、access 順、速度という少数要素が互いの意味を変え、説明量より局面差で深さを作っていること。第三に、作者が意図した仕様だけでなく、観戦で生まれた予防射撃、先行移動、bug 利用まで「実際の遊び」として評価していること。第四に、加速が序盤の計画と終盤の生存を接続し、一 run 内の rhythm を変えていることである。

デメリットは、high score を内発的な目的として受け入れない層には、設計の大半が作動しないこと。秘密 combo は発見時の所有感を作る反面、知らない初心者へ不透明な点差を与え、発見前に離脱する可能性がある。random な候補と上下配置は毎画面の問題を作るが、解の質が seed に偏れば競争の公平性を崩す。高速化が強すぎると、育てた planning を終盤で捨てさせるだけになり、二相ではなく一方の遊びの消失になる。emergent bug を残す判断も、skill expression と dominant exploit を play data で区別しない限り危険である。8時間の単一作品、少人数観察、定量指標なしという evidence の狭さも移植時の限界になる。

■ 判定
部分採用。採るのは、1時間程度で完全 loop を閉じて追加制約の必要性を反証する手順、同じ mechanic の価値を局面で反転させる設計、速度変化の前後で player policy が変わるかを log で測る方法である。野菜 combo や high-score 動機をそのまま模倣せず、既存 action の摩擦で問題が解けているか、破壊的 reroll が常時最善になっていないか、低速の計画が高速の生存へ実際に接続するかの3点を小さな ablation で確認してから使う。
