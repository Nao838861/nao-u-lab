■ 概要
『Despelote』は、2001年のエクアドルで少年 Julián が町を歩き、サッカーボールを蹴りながら人々の会話を聞く slice-of-life 型の narrative game である。Game Developer の記事は、開発者 Julián Cordero の GDC Festival of Gaming 2026 講演を基に、作品の生活感が「精密な再現」ではなく、単純な遊びと現実の人々の即興を往復させる制作工程から生まれたことを説明している。

出発点は、ボールを蹴り返す行為を、言葉がなくても相手との距離や関係を作れる「普遍的な言語」とみなす着想だった。Cordero は、世界各地の路地や空き地でサッカーをする人々を写した写真集『Magnum Football』と、自身がエクアドルで育った記憶を重ね、初期 prototype では NPC voiceover を置かず、蹴ることだけで共同体と接触させようとした。しかし、それだけでは gameplay 上の考えや2001年の土地の文脈を伝えにくかった。producer の Gabe Cuzzillo と議論した結果、dialogue を試す代わりに「台本を書かず、すべて即興にする」という条件を設けた。

最初の test は、友人を video call に集めて普段どおりの会話を録音し、プレイヤーがボールを蹴る場所の隣へ置くという小さなものだった。これが成立したため、家族や友人にサッカー、政治、日常生活などの scenario だけを渡し、なるべく自然な場所で話してもらう方式へ広げた。ここで重要なのは、録音を既存 scene の背景音として消費しなかったことだ。子どもたちがプレイヤーに恋人がいるとからかう即興が面白かった時、開発側はその台詞を残すため、子どもたちがプレイヤーの周囲へ集まり、誰かが恋人らしき人物を見つけたふりをする NPC behavior と asset を追加した。現実の録音が、game design 側を逆向きに変更したのである。

Cordero はこの工程を、photorealism や厳密な simulation とは別の neorealism と捉える。Robert Yang が提唱した video game neorealism は、realism を高価な画面表現から切り離し、明確な社会的文脈、歴史的な現在性、現実由来の素材、非職業的な演者、物語の「間」に留まる時間によって場所を感じさせようとする考え方である。『Despelote』では、代表戦の映像、当時を知る人の証言、両親や友人の記憶、即興会話が documentation として作品へ入り、制作者があらかじめ設計できなかった texture や小さな物語まで残った。記事の結論は、真正さを作るのは写実度だけではなく、現実の人・場所・記憶が game の構造を変えられる制作関係だ、というものだ。

■ 内容分析
この事例の核は「即興を使うこと」そのものではなく、設計と収録の因果を一方向にしなかった点にある。通常の ambient dialogue は、完成に近い level や scenario に合う台詞を発注し、録音後は尺と演出へ合わせて整える。『Despelote』は反対に、まず蹴るという最小動詞が成立する場を作り、そこで聞こえる現実の会話を録り、その会話が要求する行動や小道具を game 側へ足した。即興は polish 用の素材ではなく、未知の scene を発見する design probe として働いている。

ボールを蹴る動詞も単なる省コストではない。プレイヤーが会話を止めて正面から聞くのではなく、遊びながら声の近くを通過できるため、dialogue を説明装置から環境の出来事へ戻している。聞き逃しや寄り道を許す操作と、主筋に整理されない会話が同じ設計思想を持つ。Yang のいう「物語に必要な瞬間だけを切り出さず、間の人物と時間を残す design of duration」が、操作、audio、NPC staging の三層で実装されたと読める。

ただし、記事の「authenticity」は測定された性能ではない。報告される評価は、最初の prototype が開発 team 内で成功と受け止められ、全 dialogue を即興にする方針へ進んだことと、完成作が記憶に残る体験として受容されたという制作側の説明である。scripted dialogue との比較、player study、理解度や没入感の定量評価は示されない。また、友人や家族との共有経験を持つ作者だから選別できた素材を、外部の制作者が手順だけ模倣しても同じ結果にはならない。neorealism は「生の素材なら自動的に本物になる」という保証ではなく、誰の現実を、誰が選び、どの編集で残したかを含む作者性の強い方法である。

もう一つの失敗条件は、即興を採用した後の制作費を見落とすことだ。恋人をからかう短い会話だけでも、NPC の位置取り、注目対象、群がる timing、新しい asset が必要になった。録音量が増えるほど、採用判断、音質の均一化、字幕、翻訳、scene との同期、同意範囲の確認が後工程へ波及する。自由な収録は安価な content generator ではなく、面白い偶然を拾う代わりに設計変更を受け入れる production commitment である。

■ 自分達の環境への適用
小規模ゲーム制作へ移すなら、「地方の記憶を扱う大作」を始める必要はない。先に一つの最小動詞と一つの滞在場所を作り、現実由来の会話が scene を変えられる短い縦切りで検証できる。例えば、物を転がす、飲み物を渡す、椅子を動かす、店番を手伝う、といった反復可能な動詞を一つ選ぶ。次に、2～3人へ結末付きの台本ではなく「昔この場所で起きたこと」「この道具の使い方で揉める」程度の scenario を渡して会話してもらい、録音から一つだけ予想外の相互作用を選ぶ。その一件に合わせ、NPC behavior、asset、camera、動詞の反応のどれかを実際に変更する。

検証の焦点は音声の自然さだけに置かない。第一に、会話がなくても最小動詞は触り続けられるか。第二に、会話を聞くために操作を止めさせていないか。第三に、録音から生じた変更が scene を固有にしたか、それとも説明量を増やしただけか。第四に、採用した偶然が別の seed や別の play path を壊していないかを見る。headless 評価で確認できるのは、NPC が所定の範囲へ集まる、会話中も動詞が有効、event が deadlock しない、字幕と音声 cue が欠落しない、といった構造条件までである。「その場に人が暮らしている感じ」は、最後に短い人間 playtest で、記憶に残った行動と会話を自由記述してもらう必要がある。

制作サイクル上は、prototype → 収録 → 実装という直線ではなく、動く prototype → 小規模な即興収録 → 一件だけ game 側へ逆流 → 再プレイ、という短い loop にする。記憶システムには、磨いた教訓だけでなく「録音のどの偶然が、どの behavior / asset / scene 差分を生んだか」を provenance 付きで残す。これにより後から、単なる雰囲気の感想ではなく、外部素材が playable diff を生んだ因果として recall できる。

■ メリット・デメリット
メリットは、少人数でも土地固有の語彙、間、言い淀み、関係性を得られ、writer が想像だけで共同体を均質化する危険を下げられることだ。最小動詞が先にあるため、会話を聞かせるだけの展示になりにくく、録音を design probe にすれば、机上では出なかった NPC 行動や小道具が見つかる。さらに、realism を asset 解像度から documentation の密度へ移すので、低予算の表現選択を弱点ではなく作品の原理にできる。

デメリットは、素材の自然さと作品としての妥当性が一致しないことだ。現実の会話には退屈さ、内輪性、聞き取りにくさ、偏見、第三者の情報が混ざる。採用には編集が不可欠であり、編集した瞬間に「無加工だから本物」という説明は成立しない。収録参加者の同意、撤回、報酬、クレジット、声や家族史をどこまで公開するかも、通常の仮 voice より重い。翻訳では言葉の意味だけでなく、重なり、間、距離感をどう保つかという追加課題も出る。

また、収録のたびに game 側を変更すると scope が膨張する。採用枠を一 iteration 一件に絞り、「面白い録音」ではなく「既存の最小動詞と同じ場で playable な変化を生む録音」を選ぶ必要がある。この記事一件から、即興が scripted dialogue より常に優れる、あるいは文化的真正性を保証すると一般化してはいけない。強いのは universal recipe ではなく、作者自身の記憶、協力者との関係、動く prototype が閉じた feedback loop を作った実例である。

■ 判定
部分採用。最小動詞を先に成立させ、即興収録から一件だけ NPC behavior や scene を逆流更新する制作 loop は、小規模 prototype で試す価値が高い。一方、即興を低コストな台詞生成や authenticity の証明としては採用しない。同意管理と scope 上限を先に置き、headless の構造検証と人間の記憶テストを分けて評価する。
