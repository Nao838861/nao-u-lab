■ 概要
対象は 80 Level の Raph Koster インタビュー。Ultima Online と Star Wars Galaxies を率いた Koster が、新作 Stars Reach を題材に「永続世界」と「大人数」を使う sandbox MMO の設計を説明している。問題設定は、MMO が固定 quest と戦闘 progression へ最適化され、世界を共同で変える力を削ってきたことにある。小規模 survival game には永続する大人口がなく、social media には共有される世界がない。この組合せこそ MMO 固有の canvas だと置く。

Stars Reach の中核は、地形や物体を static mesh とせず、server から流す変更可能な object として扱うことにある。森林は条件が残れば再生し、川・火災・気候・野生生物・資源が相互作用する。掘削跡には tailings が流れ込み、やがて土へ戻る。object は翌日も残り、振る舞いを持てる。大きな改変は一人の操作ではなく、多数の行為の蓄積として起こし、土地 claim、地域 rule、修復、生態系を守る guild といった反作用もプレイヤー側へ渡す。

成長は固定 class ではなく活動別 skill track を持ち、序盤に全 track を試してから絞らせる。chef と rifleman を同じ戦闘尺度で釣り合わせず、未充足の需要を player economy が埋める。過去作で成功者が市場を封鎖した経験から、店・鉱山・都市を増やすほど overhead と崩壊 risk が増える push-your-luck 型を採る。誰でも行える蘇生を leadership progression へつなぎ、近接作業へ XP bonus を出す soft grouping など、小さな非ゼロ和 incentive も積む。Early Access は PvE と基盤 simulation を先に固め、政治や PvP を段階的に足す。

■ 内容分析
この記事の重要点は、自由度を単体 feature として売らず、自由が生む外部不経済を吸収する仕組みと対で設計していることにある。地形改変だけなら創発性は生まれるが、最適行動が伐採・掘削・封鎖へ偏れば、後発者には荒廃だけが残る。Stars Reach は「改変を禁止する」のではなく、影響の規模を集団行為へ寄せ、再生・修復・claim・地域 rule という recovery path を同じ system に埋める。自然保護 guild が実際に活動しているという例は、修復が管理者 command ではなく player role になり得ることを示す。

ただし、回復可能であることと加害を判定できることは別問題である。記事自身が、洪水で家を流す、土砂で埋める、近くの溶岩を溶かすといった間接 damage の検出を難所として挙げる。直接 attack の attacker / target 対応なら rule 化できるが、simulation chain は「誰のどの入力が、何時間後の損害にどれだけ寄与したか」を曖昧にする。回復が速すぎれば永続性が飾りになり、遅すぎれば griefing の被害だけが永続する。設計の核心は simulation の精密さより、痕跡の半減期、責任 attribution、被害者の復旧 cost を調整できることにある。

経済設計の「規模拡大ほど overhead と collapse risk を増やす」方針も、単なる金銭 sink より意味が深い。通常の progression は規模が大きいほど単位 cost が下がり、資本が次の資本を生むため、先行者の優位が自己強化する。ここでは成長を push-your-luck に変え、成功者へ撤退・分散・委譲の判断を要求する。ただし upkeep を増やすだけでは、最大 guild だけが労働を動員でき、小規模者の方が先に苦しくなる可能性がある。必要なのは「大きいほど高価」ではなく、支配範囲・遠隔管理・在庫集中など独占を生む変数に限って限界費用を逓増させることだ。

classless progression も万能ではない。明確な track と最初の試食期間で、自由と次の目標を両立している。一方、「chef と rifleman は競合しない」という説明は、経済が各役割へ十分な需要を配れる場合に限る。戦闘が希少資源の獲得条件なら、非戦闘職も戦闘職へ従属する。役割間 balance は DPS ではなく、依存される頻度、代替可能性、意思決定の厚みで測るべきである。

記事は開発者インタビューであり、retention、富の分布、復旧時間、間接加害の誤検出率といった定量評価はない。「百万倍高速化」も benchmark 条件がなく、自然保護 guild や一年半の test が人口増加後にも成立する証拠ではない。完成済みの解法ではなく、sandbox の自由を維持するための設計仮説として読むべきである。

■ 自分達の環境への適用
小規模ゲームへ移すべきなのは MMO 規模の cloud architecture ではなく、「永続する player action と recovery path を同時に実装する」という最小単位である。例えば一画面の採掘・防衛 prototype で、採掘すると移動路と資源分布が変わり、その痕跡が複数 run に残るようにする。同時に、崩落土が時間で埋まる、植生が隣接 cell から戻る、修復すると別の progression が進む仕組みを置く。改変量、回復時間、後発 agent の到達可能領域を event log に残せば、創発性を見た目の印象だけでなく盤面の可逆性として評価できる。

headless 評価では、平均 score より支配戦略の自己強化を見る。複数 seed・複数 agent で、上位 10% が保持する資源比率、最大勢力の share が時間とともに増え続けるか、新規 agent が中央値へ届くまでの step、破壊後に主要 route が回復するまでの tick を測る。規模 penalty の probe は、拠点数に一律 upkeep を掛ける案と、拠点間距離・同時在庫・未使用 claim に逓増 cost を掛ける案を比較する。前者だけが小規模者を苦しめるなら、独占原因へ penalty が接続できていない。

間接 griefing は「悪意を当てる分類器」から始めず、被害と復旧可能性を deterministic に測る。各地形変化へ原因 event の provenance を短期間だけ持たせ、通行可能 cell の減少、所有物への環境 damage、復旧に必要な資源差を記録する。罰則を自動化する前に、どの causal chain が頻発し、false positive がどこで出るかを replay で確認する。目的は完全な犯人判定ではなく、被害者が遊びへ戻れる時間を上限内に収めることと、同じ手口の反復 cost を上げることである。

協力 incentive はさらに小さく試せる。近接作業 bonus を入れた時、agent が一地点へ密集するだけになるか、異なる役割の連鎖が増えるかを見る。蘇生を leadership 成長へ接続する案は、他者支援を「善意の消費」から自己成長へ変えるが、仲間同士の自作自演も生む。蘇生回数ではなく、異なる相手への支援、危険地域からの回収、party 生存時間の改善へ報酬を分散する必要がある。制作サイクルでは、simulation、回復、経済、政治を一度に足さず、まず盤面改変と回復の二項だけを playable diff にし、headless 指標が安定してから協力と競争を重ねる。

■ メリット・デメリット
メリットは、第一に、永続性を共同で読み書きし修復できる盤面として捉え直せること。第二に、異なる役割を一つの勝敗尺度へ潰さず、社会的な依存を作る方向で各 system が揃っていること。第三に、過去作の市場独占を規模拡大時の risk 設計へ翻訳したこと。第四に、基盤 simulation の後に政治・PvP を載せる実装順序が、原因切り分けに向くことである。

デメリットは、自由度が上がるほど間接 damage の attribution と説明可能性が悪化すること。無 reset の世界では調整失敗も蓄積し、巻き戻しは信頼を壊す。回復が強すぎれば改変の意味が消える。経済による役割調整は十分な人口を前提とし、過疎では niche が仕事にならない。規模 risk も誤れば、新規参入だけを難しくする。

さらに、記事の evidence は設計者の説明が中心で、比較実験や運用後の分布がない。魅力的な system 同士が同時に語られているため、どの機構が実際に協力を生んだかを分離できない。移植時は思想全体を信じるのではなく、改変と回復、規模と限界費用、支援と自己成長という対ごとに probe を作り、悪用例を先に headless agent へ探索させる必要がある。

■ 判定
部分採用。採用するのは、自由度と recovery path を対で作ること、規模の拡大を支配戦略の risk へ結びつけること、協力を小さな非ゼロ和 incentive で支えること、基盤から段階導入する順序である。cloud-native MMO 基盤や「経済が役割を自然に釣り合わせる」という前提は採用しない。次の実装に使うなら、永続する地形改変と自然回復だけの小型 prototype を作り、後発到達性・資源集中・復旧 tick を測る probe から始める。
