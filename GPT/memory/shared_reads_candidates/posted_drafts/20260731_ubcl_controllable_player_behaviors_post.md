■ 概要
この論文が扱うのは、「勝つことだけを学んだ bot は一つの効率的な行動へ収束しやすいが、プレイテストには攻撃的、慎重、探索的、協調的といった幅のある行動が必要」という問題である。従来の代表的な解決法には、人間の大量のプレイ軌跡を模倣する、プレイヤー類型ごとに別 policy を学習する、報酬係数を変えて複数の性格を作る、といったものがある。しかし前二者はデータ収集・モデル数が増え、後者は「この報酬係数が人間のどのプレイ傾向に対応するか」が直接には分からない。

提案手法 Uniform Behavior Conditioned Learning（UBCL）は、プレイ傾向を 0〜1 の連続値からなる behavior vector として表し、一つの共有 policy をその目標 vector で条件付ける。各 episode の開始時に agent ごとに目標 vector をサンプリングし、観測には通常の game state に加えて「目標 vector」と、その時点までの行動統計から計算した「現在 vector」を入れる。報酬は勝敗ではなく、現在 vector から目標 vector までの Euclidean distance が一手でどれだけ縮んだかである。正確には、前 step の距離から現 step の距離を引き、目標 vector の大きさで正規化して係数を掛ける。距離を縮めれば正、遠ざかれば負となり、到達後もずれない行動を促す。目標の大きさで割るのは、大きな値を多く持つ「極端な性格」ほど得られる総報酬が大きくなり、平均的な性格の学習が不利になるのを防ぐためである。

検証用ゲームは Unity ML-Agents 上の 2 対 2 grid arena で、coin、危険な NPC の近くにある高価値 diamond、相手撃破の三つから得点する。6 次元は、coin・diamond・kill が総得点に占める各比率、理論上限に対する総得点（dominance）、味方との平均距離、訪問済み cell 比率（mobility）である。前半三つは安全資源利用、risk-taking、aggressiveness を、後半は得点追求、協調／独立、探索性を近似する。各 agent は別の目標を持つが policy と value network は共有する。PPO を約 2 億 time step、実ゲーム時間換算約 5,500 時間、16 並列環境で学習した。

評価は三段構えである。まず offensive、collector、explorer などの固定目標ごとに 50 session を走らせ、実測 vector の平均と 1σ が目標に沿うかを見る。次に同じ 2 億 step を勝利報酬だけで学んだ baseline と比較する。1,000 game で三体を UBCL、一体を win-only とし、得られた 6 次元 vector を PCA で 2 次元化すると、win-only は主に安全な coin を集める一領域へ集中し、UBCL はそれを内包する広い領域を覆った。最後に 1,250 episode・5,000 vector の次元別誤差を調べ、得点源比率は比較的合わせやすい一方、味方との距離は相手の目標との衝突、mobility は低すぎる目標が実現不能なため誤差が大きいと確認した。結論は、単一 policy の入力を変えるだけで連続的な play style を出せるが、制御可能性は behavior 指標と到達可能領域の設計に強く依存し、協調や長期戦略はなお難しい、というものだ。

■ 内容分析
核は「性格ラベルを policy に渡す」こと自体より、性格を逐次計算可能な行動統計へ落とし、その統計空間での距離の減少を dense reward にした点にある。たとえば aggressiveness という曖昧な語を直接学ばせず、kill 由来の得点比率として観測・報酬・評価を同じ座標系に置く。このため、学習時に見ていない中間 vector も同じ policy へ入力でき、固定 archetype の数だけ bot を増やす必要がない。また、実現不能な目標でも、目標方向へ近づく行動には情報があるという設計は、通常なら除外する外れ値を探索圧として利用する発想になっている。

ただし「6 軸を独立に一様走査できる」という理解は危険である。coin・diamond・kill の得点比率は合計 1 という simplex 上にあり、論文も順番付きサンプリングで制約を入れている。味方距離は自分だけでは決められず、mobility と得点追求も map 構造や資源 spawn を介して結び付く。したがって目標 cube と実際に到達可能な behavior manifold は一致しない。誤差は policy の能力不足だけでなく、ゲーム規則が作る可到達領域の境界でもある。この誤差地図そのものを「どの player style をこのゲームが許すか」の診断結果として読む方が、全目標への一致率だけを上げるより有用だ。

評価にも限界がある。比較対象は同じ環境・同じ学習時間の win-only policy 一種で、異なる diversity 手法、複数 seed、別 map や別ルールへの一般化、次元数の ablation は示されていない。PCA 上の被覆面積は多様性の視覚的証拠にはなるが、元の 6 次元空間の coverage を直接保証しない。また「人間らしい」という用途を掲げる一方、人間の軌跡や知覚評価との一致は測っていない。UBCL が実証したのは、手設計した統計に対する制御性と win-only より広い行動分布であり、人間らしさ、強さ、面白さではない。勝敗を直接最適化しないため、指定統計へ忠実でも無能な行動になり得る。この区別は、playtest bot には許容できても、切断プレイヤー代替には大きい。

■ 自分達の環境への適用
最も価値がある移植先は、重い PPO 学習そのものより headless playtest の入力設計である。現在の prototype ごとに固定 bot を「攻撃型」「探索型」と名付ける代わりに、実行ログから逐次計算できる 3〜5 軸を定義する。たとえば攻撃接近率、危険領域滞在率、未訪問領域率、回復資源温存率、目的達成速度である。build ごとに同じ target grid を走査し、各 run について目標値、実測値、勝敗／到達率、停止・loop・被弾集中などの failure signature を保存する。すると評価対象は平均クリア率一つではなく、「慎重かつ低探索では詰まる」「高攻撃・低回復だけが boss phase を突破する」といった behavior-space 上の破綻領域になる。

最初の probe では学習を行わなくてよい。既存の parameterized bot や scripted bot の係数を 2〜3 軸で振り、目標と実測の対応表を作る。ここで重要なのは target の均等配置ではなく、実測 space の coverage、同じ target の再現分散、各軸間の相関、到達不能 cell の識別である。到達不能が多ければ bot を責める前に指標を直す。coverage が足りず、固定ルールでは中間 style を安定して作れないことが確認できた段階で、現在 vector と target vector を観測へ追加する conditional policy を検討する。この順なら、約 2 億 step という論文の学習費用を先払いせず、設計上の利益を取り出せる。

回帰評価では build A と build B の「平均性能差」だけでなく、同一 target set に対する到達可能領域の増減を比較する。新 mechanic によって高 mobility・低 risk の領域が消えたなら、難易度上昇ではなく遊び方の選択肢が狭まったと判定できる。逆に、人間には不自然な極端 vector も、壁抜け、資源枯渇、味方依存 deadlock の探索には使える。人間再現用の分布と stress-test 用の外縁分布を分け、後者を「人間らしくないから失敗」と扱わないことが肝要である。

記憶システムにも小さく応用できる。各 playtest atom に target vector と actual vector を共通 field として残せば、「攻撃型」という曖昧なタグより、後の build 間比較や類似 failure の recall が安定する。ただし全 genre 共通の巨大な軸集合は作らず、ゲームごとに少数の観測可能な軸を持ち、軸定義と算出式を probe と同じ版で保存する。指標を変更した時に旧値と新値を混ぜないため、vector schema version も必要である。

■ メリット・デメリット
メリットは、一つの policy で連続的な style を指定でき、固定 persona の列挙より未被覆領域を探しやすいこと、目標と実測を同じ統計で比較できるため headless 回帰に落とし込みやすいこと、実現不能な目標の誤差もゲーム規則や agent 間干渉の診断材料になることだ。人間データがなくても stress-test 用の外縁行動を生成できる点も強い。

デメリットは、得られる多様性が手設計した軸の外へ出ないこと、軸の依存関係や累積統計の慣性が制御誤差として現れること、強さ・人間らしさ・楽しさを別途評価しなければならないことだ。論文規模の学習は約 2 億 step と重く、単一環境・単一 baseline の結果から費用対効果を一般化できない。さらに目標 vector の大きさで割る報酬は、汎用化してゼロ近傍の target を許す場合に数値的に不安定になり得るため、sampling constraint や下限処理が要る。

■ 判定
部分採用。まず behavior vector、到達可能領域、target と actual の誤差地図を headless 評価へ導入し、固定 bot で小規模 probe を行う。conditional RL は、軸の有効性と固定 bot の coverage 不足が実測できた場合だけ次段へ進める。人間らしさを証明した手法としては採用せず、遊び方の被覆と破綻領域を測る設計として使う。
