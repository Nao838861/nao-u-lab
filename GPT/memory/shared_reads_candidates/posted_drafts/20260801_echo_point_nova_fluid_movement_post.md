■ 概要
対象は、Greylock Studio の Matt Larrabee が『Echo Point Nova』の高速移動をどう作ったかを解説した開発 deep dive である。問題設定は、オープンワールド FPS の広い空間を、単なる移動時間ではなく、それ自体が速く刺激的な遊びになるよう設計すること。主役は hoverboard と grapple hook だが、作者の結論は「優れた移動は二つの能力の仕様だけでは成立しない」。player physics、入力の許容、camera motion、VFX、SFX、level geometry、能力の解放時期、tutorialization が同じ速度感を支える必要がある、というものだ。

開発は完成像を先に定義して逆算したのではない。作者は約3年間、他作品から着想を得る、物理を変える、カメラを変える、視聴覚フィードバックを変える、実際に遊ぶ、というループを1〜2手先だけ見ながら反復した。hoverboard の起点は、現代的な shooter にある sprint-to-crouch slide を「下り坂だけでなく上り坂でも、好きなだけ続けたい」という欲求だった。そこで「どこでも滑り続けられる理由」として board を導入し、Unreal Engine 4 の walking physics を基礎に friction と deceleration を無効化した。通常歩行のようにすぐ最高速へ達するのではなく、前進を数秒続けて最高速へ上がる車両的な加速にした。標準の character movement は斜面へ吸着しようとするため、斜面端で自然に飛び出す slope detection を追加し、落下や multi-jump で Z velocity を処理する engine 側の前提も上書きした。

grapple は高速時の照準精度をそのまま要求しない。tick ごとに grappleable target を見ているか検査し、直前に見た対象を短時間記憶することで、照準が少し外れても接続を許す。接続後は現在速度から、視線方向を基にした desired grapple velocity へ約1秒で補間する。現在速度が grapple の方向と合わない、接続点へ十分近い、視線を接続方向から外す、という条件で解除し、意図せずぶら下がり続ける状態を避ける。つまり照準判定、速度遷移、解除条件を一体で設計し、「正確に点を撃つ道具」ではなく「高速移動の流れを切らない操舵」に変えている。

感覚の補強も速度値と連動する。grapple と hoverboard は速度が上がるほど FOV を広げる。board 中はカメラを緩く上下させ、strafe 時には snowboard の体重移動に似た傾きを加え、斜面を横切る時には地形の左右傾斜へカメラを合わせる。一方、階段では character が段ごとに瞬間移動する engine の挙動をそのまま見せず、カメラ側を平滑化する。board の電気的な engine sound は速度で pitch を上げ、debris は接地面で種類を、速度で飛び方を変える。grapple は成功を短い音と明るい beam で即座に確定する。記事公開時点で Steam review は99% positive で、移動が多く評価されていたと作者は述べる。ただし、これは移動要素別の比較実験ではなく、完成作品の受容と作者の制作記録である。

■ 内容分析
この記事固有の価値は、いわゆる game feel を「juice を足す」という曖昧な話にせず、プレイヤーの意図が速度へ変換される経路として分解できる点にある。hoverboard では、入力を続ける、加速する、斜面を読む、離陸する、空中速度を保つ、という因果がつながる。grapple では、対象を一瞬捉える、少しの照準誤差を吸収する、現在の運動量を急に捨てず方向を変える、不要になったら自動で切れる、という因果がつながる。FOV、camera tilt、pitch、debris、beam は、この内部状態を別々の感覚経路から同時に説明する。気持ちよさは演出の総量ではなく、同じ状態変化について物理・入力・映像・音が矛盾しないことから生まれている。

特に重要なのは、許容を「操作を簡単にする補助」ではなく、高速化に伴う人間側の誤差増大への補償として入れていることだ。速度だけを上げれば、1 frame の視線ずれや狭い target 判定が移動の失敗へ直結し、上達感より操作の途切れが前面に出る。直前 target の記憶は、入力履歴を使った短い coyote time の照準版と読める。約1秒の velocity interpolation も、接続時に速度ベクトルを瞬時置換して既存の運動感を壊す代わりに、現在の勢いを保ったまま新しい意図へ収束させる設計である。

一方、記事には再現に必要な情報が欠けている。target 記憶の時間幅、FOV curve、加速度、slope 判定閾値、速度上限、補間関数、camera bob の振幅は公開されていない。99% positive は作品全体の review で、移動の各要素を外した ablation でも、酔いや accessibility を含む user study でもない。作者自身も、engine を変更できる唯一の programmer として判断が集中していたから、物理・音・演出を好きな順で往復できたと明記する。この制作条件は、担当が分かれた大規模 team では再現しにくい。したがって記事から得られるのは万能な数値 recipe ではなく、観測層をまたいで矛盾を潰す反復の構造である。

■ 自分達の環境への適用
高速移動 prototype へ移すなら、最初から全演出を盛るのではなく、一つの短い検証 course と telemetry を用意する。course には平地加速、上り、下り、斜面端の離陸、階段、急な方向転換、連続 grapple、狭い着地点を置く。run ごとに speed、acceleration、vertical velocity、target acquisition、grapple miss、接続から解除までの時間、camera angular velocity、着地後の入力回復時間を記録する。動画には同じ時刻の物理 state と event marker を重ね、どこで「速いのに気持ちよくない」「意図したのに接続しない」「画面だけが激しい」が起きたかを追えるようにする。

調整順は、第一に運動の因果、第二に入力許容、第三にカメラ、第四に音と VFX、第五に level と解放順とする。ただし一方向の工程にはせず、各層を追加するたび同じ course へ戻る。例えば grapple miss が多い時、target radius だけを広げず、直前 target memory の有無と時間幅、視線方向への速度補間時間、解除条件を独立に切り替える。camera flourish は強度を0にできる設定を最初から持ち、物理的な成功率と主観的な速度感を分離する。headless test は斜面離陸、速度保存、解除条件、階段上の camera discontinuity の回帰検査に使い、人間の短い playtest は予測可能性、酔い、成功の手応えを判定する。

小さな probe では、baseline、物理のみ、物理＋入力許容、物理＋許容＋感覚 feedback の4条件を同じ course で比較する。見るのは最高速ではなく、完走時間、意図した grapple の成立率、失敗後の復帰時間、不要な解除の回数、再走したくなるか、速度変化を説明できるかである。これなら記事にない ablation を自分達の制作環境で補い、どの層が実際に寄与したかを記録できる。結果は一般ルールへ即座に昇格させず、prototype 名、course、parameter、動画、主観コメントを一組の evidence として残す。

■ メリット・デメリット
メリットは、移動 mechanic を physics code の局所問題から解放し、入力誤差、camera、音、VFX、地形、導入順まで同じ設計対象にできること。特に「高速化した分だけ許容も設計する」「現在の運動量から新しい意図へ補間する」「内部速度を複数感覚で一貫して伝える」は、hoverboard 以外の dash、rail、swing、knockback にも転用できる。また、標準 engine の斜面吸着、Z velocity、階段 camera といった具体的な破綻箇所が示され、何を観測すべきかが明確である。

デメリットは、成功例の事後説明であり、失敗した parameter や比較条件がほぼ残っていないこと。3年の自由な反復と中央集権的な実装権限は、時間制約や分業がある環境では高コストになる。FOV widening、bob、tilt は速度感を増す一方、酔いと視認性低下を招くため、無効化できる設定が不可欠である。照準許容を広げすぎれば target 選択が予測不能になり、補間を長くしすぎれば反応が鈍くなる。演出を増やして物理の欠陥を隠したり、気持ちよさを review score だけで代表させたりする使い方も危険である。

■ 判定
部分採用。具体的な数値を模倣するのではなく、運動の因果、速度に応じた入力許容、感覚 feedback、level 条件を同じ短い course で反復検証する枠組みを採用する。まず4条件の小さな ablation を行い、telemetry と人間の感覚評価が一致する層だけを残す。単一作品の成功談は仮説生成に使い、一般則への昇格は自分達の再現 evidence が得られた後に限る。
