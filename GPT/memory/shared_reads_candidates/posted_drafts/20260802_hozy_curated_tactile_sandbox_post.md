■ 概要
Come On Studio が、掃除・修理・家具配置を行う neighborhood restoration game『Hozy』をどう設計したかを説明した制作インタビュー。出発点は、家具配置 simulator と掃除 game を組み合わせ、現実の道具のように触れて反応し、音が返る体験を作ることだった。複数 level を結ぶ設定は浸水都市や時間旅行も検討した末、忘れられた neighborhood の再生に定めた。ただし中心にあるのは物語上の達成ではなく、手を動かす過程そのものだ。timer、score、失敗状態、正しい配置、経済的報酬を置かず、美しさを採点する beauty points も早期に撤回した。開発中の呼称は「curated sandbox experience」で、player は用意された空間と道具の中で流れに入り、level 内の大半の object を捨てる選択さえできる。

低緊張度を支えるのは機能の削除だけではない。mop は単に cursor に追従せず、移動方向を向き、速度で傾き、床に濡れ跡を残し、押し潰され、状態に応じた音を返す。家具を持った時も、大型なら遅く小さく傾き、小物なら速く大きく反応する。絵は壁へ自動的に向き、object は壁を貫通せず、大型家具同士は積めない。つまり「自由」は無制約な物理 simulation ではなく、意図が読みやすく、見た目の破綻を起こしにくい補助と制約の上に成立している。

environment 制作では、camera angle に合う間取り、複数階と階段が掃除 mechanic に適するか、部屋間の壁をどう示すか、気持ちよい汚れと不快な汚さの境界など、非自明な問題を複数回の R&D で先に解いた。部屋の外縁は単色、平面、警告色、ぎざぎざ、筆致表現を試した後、欠けた煉瓦や屋根材、突き出た pipe を含む少し荒れた動的境界へ収束した。moodboard 後の concept は直接3Dで作り、scale、照明、material、必要な散乱物の量を見積もってから engine 上で部屋の狭さや天井高を検証する。

重要な変更は environmental storytelling の後退である。初期 map は落書き、gnome、theme 付きのごみで散らかった状態から住人の物語を強く語ろうとした。しかし player は、気に入った物を捨てることや、良い落書きを塗り潰すことを嫌がった。そこで制作側は、再生のために過去を消させる構成を簡潔なものへ変更した。背景も level より目立たせず、どの背景でも level 単体が成立することを原則にした。窓外の詳細環境は Unreal Engine での工数に見合わず棄却。一方、人物史、状況、気分、player への態度は大量に書いたが、説明文として全部見せず asset 制作の判断を揃える内部資料に使った。各 level で player が触る hidden content と mechanic は通常30〜40%程度だという。結論は、cozy を課題の欠如ではなく、反復操作の密度、自己決定、所有感を傷つけない制約、見せる情報と制作を支える情報の分離で作る、という設計である。

■ 内容分析
この記事の核は「低 stakes なら簡単でよい」への反例にある。timer と失敗を消すと外発的な圧力が減るため、一回ごとの入力に方向、速度、変形、軌跡、音という複数 channel の feedback を積み、操作自体を報酬へ変えている。mop の挙動は装飾的 animation の一覧ではなく、入力速度から姿勢、床の状態変化、音まで因果が連続する小さな interaction model である。UI 制作経験を「game 内の object も interface」と捉え直した点が、この一貫性を支えている。

curated sandbox も、何でも置けることとは違う。壁向きの自動補正、collision、大型家具の積載禁止は可能性を狭めるが、player が意図していない失敗と見苦しい破綻を減らす。正解は採点しない一方、操作結果を予測可能にする規則は強く持つ。この「目的は開くが局所的な文法は閉じる」という分業が、自由度と安心感を両立させる。逆に制約が不可視なら、置けない理由が分からず自由を奪われたと感じるため、補正の自然さと拒否 feedback が成否を分ける。

初期の environmental story の失敗はさらに重要だ。制作者には散らかった物が過去を語る記号でも、player が選んで残したい物になった瞬間、掃除 objective は所有感と衝突する。これは「作者がごみと分類した object」を player も同じ価値で見るという前提の破綻である。変更は物語を薄めただけではなく、restoration を強制的な消去から自己決定へ戻した。cozy らしさは色調より、player の愛着を system が勝手に否定しないことに現れている。

制作面では、裏設定と可視 content を分けた判断がよい。人物史は直接読ませなくても、prop の選択や不揃いな家具、portrait、色調に一貫性を与えられる。一方、窓外の詳細は体験への寄与が低く、有限の工数を使わない。これは「見えないものは不要」ではなく、下流の制作判断を変える非表示情報と、完成画面を埋めるだけの非表示工数を区別している。

ただし評価 evidence は弱い。player が物を捨てたくなかったという反応の人数、条件、変更前後の比較は示されず、30〜40%も計測方法、母数、触られなかった content の種類が不明である。触られないことも sandbox の選択余地なら直ちに浪費とは言えない。記事は有力な設計仮説と制作判断の記録であり、timer なし、固有 prop、温かな照明が retention や満足度を改善したという因果実証ではない。

■ 自分達の環境への適用
小規模 prototype では、core loop を増やす前に一つの反復 micro-action を選び、入力、予備動作、接触、状態変化、残留痕、音、解除までを一本の feedback trace として実装する。たとえば掃除なら、cursor 移動量だけで進捗値を増やさず、速度で道具の傾きと音を変え、通過箇所を state map に残し、同じ場所への再入力で差が読めるようにする。最初の検証は一部屋、一道具、三種類の surface でよい。無 feedback 版と多層 feedback 版を同じ操作時間で触り、「入力と結果の対応を説明できるか」「目的がなくてももう一度動かしたいか」を取る。

headless 評価は、軌跡の連続性、collision 違反、配置可能面、状態遷移、処理時間を固定 seed で検査する。ただし触覚的満足は数値だけでは閉じないため、replay と音付き capture を残し、人間が前後差を判定する。配置補助は自動修正量、拒否回数、最終配置までの操作数を log にし、補助が意図を助けたか、勝手に奪ったかを短い playtest で確認する。

所有感の保護は object ごとの作者分類ではなく player action から扱う。一度拾った、移動した、注視した、保留箱へ入れた object は自動廃棄や必須上書きの対象から外し、塗装や破棄の前に preview と取消を用意する。「残したため未完了」にならない completion 条件も必要だ。これにより clean-up goal と player の収集・保存意図を競合させない。

environment R&D では、完成 asset の前に灰色箱で camera、階段、部屋境界、操作可能領域を試す。背景は silhouette と明度差を測り、level の可読性を侵食する案を捨てる。裏設定は各 asset の形、材質、配置の少なくとも一つを変える時だけ残し、何も変えない lore は制作 backlog にしない。hidden content は単純な接触率だけで削らず、発見者の体験差、制作時間、再利用、必須導線の妨害を併記する。30〜40%という記事の値を目標値にはしない。

記憶には「温かい色」などの表層ではなく、残したい物の強制破棄が不評だった観察、どの設計を撤回したか、代替案、再検証条件を結んで保存する。次の制作では、低緊張度を評価する probe として、操作 feedback の再実行欲、意図しない破壊、選択を撤回できる割合、触られない content の工数を同時に見る。

■ メリット・デメリット
メリットは、timer や失敗を除いても、操作 feedback と予測可能な制約で濃い loop を作れること。正解を採点せず局所文法を整える考え方は、sandbox の自己決定と実装上の破綻防止を両立する。player の愛着を設計変更へ反映した事例、3D concept で scale と asset 量を早期検証する工程、見せない設定を asset 判断に限定する運用も、小規模制作へ移しやすい。

デメリットは、object ごとの反応、固有 prop、animation、音、collision 調整が content 数に比例して膨らむこと。触られない要素が多い sandbox では、その手触りの投資が観測されないまま埋没する。自動補正は強すぎると試行錯誤を奪い、固有 object の徹底は組合せの再利用性を下げる。開発者証言だけなので、player 反応や30〜40%を一般則として採るのも危険である。

■ 判定
部分採用。反復 micro-action の多層 feedback、正解を置かず破綻だけを防ぐ配置文法、player が残したい状態を壊さない ownership 保護、灰色箱での environment R&D は採る。固有 asset の大量制作や接触率30〜40%は模倣せず、一部屋の probe で操作再実行欲、補正の納得度、hidden content の工数を測ってから拡張する。
