■ 概要
Game Developer が2026年8月3日に公開した、シリーズプロデューサー岡本基と game director / lead writer の Jon McKellan への取材。記者は near-final build も試遊している。『Silent Hill: Townfall』は1996年の架空のスコットランド離島 St. Amelia が舞台で、Simon Ordell が不可解に島へ戻り、恋人 Zoe を探す。町では労働組合と企業組織の対立が破綻し、孤立した共同体を怪異が覆い、現実と妄想が徐々に混ざる。制作側が狙うのは、単なるカメラ変更ではなく、個人と町社会の関係、過去に囚われた主人公の脆弱さ、その瞬間の精神状態を一人称の操作へ結び付けることだ。

Simon は怪物を全て倒すのでなく、戦闘を選び、忍び、部屋へ逃げて扉を施錠する。発話は抑え、画面上の inner thoughts で即時の認識を示す。人物も一度交差して去る存在ではなく、Simon、Zoe、冒頭の別人物が、本人たちにはまだ分からない因果で接続される。McKellan はこれを slow-burn の intelligent thriller と説明し、自然な内面表現から人物への共感を作ろうとしている。

中心となる道具は携帯 television である。従来作の radio のように怪異を警告するだけでなく、霧や壁の向こうの敵を映し、正しい周波数へ real time に tuning して初めて十分に働く。pharmacy の場面では、建物内の数字を cryptic recording として流し、security passcode の謎解きに使う。さらに Zoe の clue と通信も同じ画面へ載る。つまり危険察知、索敵、探索、謎解き、人物関係、物語理解を一つの不完全な装置へ束ねている。

この設計には McKellan が『Alien: Isolation』で古い技術の外観と motion tracker を設計し、Screen Burn の前身が『Stories Untold』で analog horror を扱った経験がある。ただ VHS 風の映像を装飾的 gimmick にせず、世界内で生存に必要な道具にするのが今回の更新点である。記事の結論は、一人称、lo-fi feed、信頼し切れない旧式機器への依存により、世界を見る行為自体を心理ホラーへ変えられるというものだ。ただし根拠は短い試遊と開発者の説明であり、プレイヤー比較、完遂率、恐怖や共感の測定は報告されていない。

■ 内容分析
重要なのは「analog な見た目」ではなく、情報取得の摩擦を操作にした点だ。通常の HUD は危険、目的、通信を即時かつ並列に表示する。携帯 TV は、取り出す、向ける、周波数を合わせる、歪んだ feed を読むという直列処理に変える。プレイヤーは敵から目を離して情報を得るため、知ること自体に時間と注意の費用が発生する。装置は世界を説明する窓であると同時に、行動を遅らせる障害になる。この二重性が survival loop と物語 motif を接続している。

また、同じ装置が異なる情報種を運ぶことにも意味がある。敵影、暗号、Zoe の言葉が同じ画面に現れれば、プレイヤーは「今は安全情報か、手掛かりか、人物の声か」を映像形式だけで判別する。Zoe を理解したい欲求と、生き残るため装置を確認する必要が同じ操作へ収束するため、物語を任意の音声ログとして脇へ置きにくい。mechanic と narrative の統合として強い。

一方、機能を束ねるだけでは統合にならない。警告と会話が競合して重要情報を取り逃がす、tuning が毎回同じ手順になり作業化する、歪みが可読性だけを下げるなら、一つの UI に複数画面を押し込んだにすぎない。記事は装置を inherently unreliable / janky technology と表現するが、確認できる具体例は調整不足や歪みであり、偽情報を意図的に出す設計までは示していない。「不完全」を「嘘をつく」に拡張すると、公平な危険察知と物語上の不信を混同する。

一人称と inner thoughts の組合せにも条件がある。一人称は視野を Simon に拘束するが、画面テキストが正解や感情を過剰に言語化すれば、プレイヤーの解釈を狭める。反対に少なすぎれば、無口さが共感ではなく情報不足になる。記事は人物が深く接続される構想を説明するが、その因果がゲーム中の選択、探索順、敵回避へどう返るかは不明である。設計意図と体験効果を分けて読む必要がある。

■ 自分達の環境への適用
最初の probe は、ホラー探索 prototype の一部屋と短い廊下に限定する。世界状態は通常の deterministic state として保持し、携帯端末はその情報を遅延・欠落付きで読む presentation layer にする。機能は三つだけに絞る。近接する脅威の方向、部屋内の暗号断片、離れた人物からの短い通信である。各 channel に固有の音、走査線、周波数帯を与え、画面を開いたまま移動できる代わりに視野と操作精度を落とす。

比較条件は、A: 危険 indicator・謎 hint・通信を別 UI にする、B: 一台へ統合するが tuning は自動、C: 一台へ統合し手動 tuning と軽い歪みを入れる、の三つにする。同一 map、敵経路、seed、手掛かり配置で、区間完遂率、被弾、索敵開始から発見までの遅延、誤った channel 切替、暗号再確認回数、装置を見ている時間、重要通信の見逃しを event log に残す。headless agent には真の敵位置を見せず、実際の表示 event だけを observation として渡す。

ただし headless 成績だけでは恐怖、読みやすさ、Simon への共感は判定できない。少人数の人間 playtest で、緊張が「情報不足への興味」だったか「UI が読めない苛立ち」だったか、Zoe の通信を自発的に追ったか、inner thoughts が解釈を助けたか奪ったかを、直後の短い再話と5段階評定で取る。操作ログと発話を timecode で対応させれば、成績悪化を演出成功と誤認しにくい。

実装上は device state を closed / scanning / locked / interrupted に分け、物語通信が危険警告を上書きしない優先順位を deterministic にする。偽陰性や誤誘導は初版では入れず、遅延と不鮮明さだけから始める。C が B より緊張を上げても、見逃しと離脱が増え、情報の意味を思い出せないなら tuning を削る。逆に B が A と同等の完遂率で、端末確認と人物通信を同じ探索 rhythm に組み込めた時だけ、統合の価値があると判定する。

■ メリット・デメリット
メリットは、世界観の小道具を情報 architecture の中心にできること、危険を見る操作と物語を見る操作を同じ習慣にできること、情報取得中の無防備さから combat を増やさず緊張を作れることだ。画面効果、音、周波数を変えれば、一つの実装を敵、謎、会話へ再利用できる。inner thoughts と組み合わせれば、外界の不鮮明さと主人公の主観を別 layer で示せる。

デメリットは、一装置の使いにくさがゲーム全体の使いにくさへ直結することだ。小画面、ノイズ、色差、音依存、頻繁な tuning は視覚・聴覚・運動面の accessibility を悪化させうる。全情報を集めるほど装置が menu hub 化し、危険時に narrative が邪魔になる。first-person の視野制限も motion sickness と探索漏れを増やす。記事は発売前取材で、設計者の意図と記者の好印象が中心なので、保持率や緊張の持続を証明してはいない。

■ 判定
部分採用。採るのは「不完全な diegetic device へ危険察知・手掛かり・人物通信を束ね、情報取得の注意費用を遊びにする」構造である。VHS 表現、一人称、手動 tuning を一括採用せず、分離 UI / 自動統合 / 手動統合の小さな比較から始める。完遂率と可読性を壊さず、装置確認が探索と物語理解の共通 rhythm になった場合だけ拡張する。
