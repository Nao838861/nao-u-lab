■ 概要
『Puzzledorf』は、色付きブロックを同色の印へ押す Sokoban 系パズルである。作者 Stuart Burfield の課題は、パズル経験者を退屈させず、ジャンル未経験者や普段ゲームをしない人にも、操作と規則を短時間で確実に覚えてもらうことだった。過去作では文章付き tutorial を用意しても、多くのプレイヤーが読み飛ばし、終了後に Undo や Restart の存在を質問した。そこで本作では、操作一覧だけを全 level の左上から再表示できる静止画として残し、規則説明の文章を廃止した。規則は「読ませる情報」ではなく、正しい操作を実行しないと先へ進めない盤面へ埋め込む。

Tutorial 1 は通路を一本に絞り、まず赤ブロックを赤い cross へ押し、次に青ブロックへ別角度から回り込んで角の向こうへ押す以外に進めない。ここで色と goal の対応だけでなく、後の全 puzzle の基礎となる「押したい方向の反対側へ回り込む」「一手先だけでなく接近方向を考える」を、ほぼ失敗不能な短い経験として教える。Tutorial 2 も一方向の導線を使い、行先を持たない白い boulder を導入する。二個を同時には押せない、別方向から押す必要がある、白は goal へ運ぶ対象ではなく道を空ける障害物である、という三つを一つの盤面で経験させる。続く通常 level 1 で初めて、白を壁際へ押すと Undo または Restart が必要になる小さな失敗を許し、tutorial で覚えた知識を自力で再適用させる。

正しい行動には多層の feedback がある。押せる物体へ近づくと明るく点滅し、block が goal に乗ると明るい効果音と particle が出て、その block の animation は止まる。次に扱う block が点滅し、level 完了時にはさらに大きな音と particle が勝利条件を示す。作者は開発中、non-gamer、熟練者、puzzle fan、非 fan を混ぜ、初回起動から遊ばせ、規則習得までを観察した。助けを求められても、製品版では作者が隣にいないため答えず、詰まりを設計へ戻した。その結果、幅広い層が状況を理解し、高い割合が最後まで進んだと報告している。ただし人数、完走率、習得時間、比較条件は示されておらず、これは統制実験ではなく一作品の反復設計記録である。

■ 内容分析
この記事の中核は、単なる「文章を減らす」ではない。伝えたい命題を、盤面制約、行動、結果の feedback へコンパイルしている点にある。たとえば「青ブロックは角を回して押せる」という説明を表示する代わりに、他の進路を閉じ、回り込んで押した瞬間だけ進行できるようにする。学習者の正解はボタンで閉じる説明画面ではなく、実際のゲーム状態として残る。このため tutorial の通過と操作実演が同じ出来事になり、「読んだが実行できない」を減らせる。

設計順序も重要である。最初の二面は失敗を排除するが、完全な自動進行にはせず、別角度から押すための小さな停止を残す。次の通常面で初めて可逆な失敗を入れる。この並びは、①制約下で正しい action を一度生成する、②視聴覚 feedback で正解を確定する、③似ているが自由度の高い場面で再生する、④失敗時に Undo で局所的にやり直す、という足場掛けになっている。Tutorial 1 単体の完了だけでは理解と偶然を区別できないが、level 1 の転移で同じ原理を再使用させるため、最低限の確認問題まで含んでいる。

操作表示を全 level に残す判断も、規則学習と参照情報を分離した点でよい。Undo のキー割当のような恣意的情報は盤面から推論できないため、無理に textless 化せず常時参照可能にする。一方、色対応や押す方向のようなゲーム内因果は経験で教える。この境界があるから、「文字を使わない」こと自体が目的化していない。色覚 option と点滅も併用され、色だけを唯一の手掛かりにしない点も整合している。

注意すべきは、強い誘導が理解を保証するわけではないことだ。一本道では、規則を把握しなくても目の前の物体を押し続ければ通過できる。著者の成功主張には標本数も分布もなく、「高い割合で完走」の定義もない。さらに block-pushing puzzle は状態数と action が小さく、正行動を空間制約へ写しやすい。リアルタイム action、複数 system が同時に動く game、文章でしか伝えにくい抽象ルールへ、そのまま一般化はできない。価値があるのは textless tutorial という表面ではなく、命題ごとに「観測可能な行動」と「後続場面での再現」を設計した部分である。

■ 自分達の環境への適用
新規 prototype の冒頭を作る時、まず説明文を書くのではなく、プレイヤーに覚えてほしい命題を一つずつ列挙する。各命題について、正しく理解した時にだけ現れる action、誤解した時の action、成功を確定する状態変化を定義する。そのうえで tutorial beat を「一つの新規概念」「ほぼ失敗不能な実演」「即時 feedback」「自由度を一段上げた再確認」の四点セットにする。複数概念を一画面で教える場合も、Puzzledorf の白 boulder のように同じ因果鎖上にあるものだけへ絞る。

headless 評価では、画面説明の有無を直接評価するより、event log に `first_valid_action_time`、`invalid_action_count`、`undo_before_transfer_clear`、`hint_or_restart_count`、`transfer_level_clear` を残す。最初の誘導面を通過できたかだけでなく、次の自由度が高い面で同じ原理を再現できたかを合否にする。一本道をランダム入力でも抜けられるなら、tutorial clear は学習指標にならないため、scripted random agent の基準値も取る。人の初見 playtest では介入せず、声掛けの代わりに「停止した時刻」「見落とした cue」「誤って形成した規則」を記録する。終了後に操作理由を短く説明してもらい、行動 log と自己説明が一致するかを見る。

小さな検証として、同一 prototype の冒頭を A＝説明文、B＝盤面制約＋feedback の二版にし、各版で tutorial 後の転移面まで測る。比較するのは tutorial 自体の速さではなく、転移面の初回成功率、誤操作、Undo、クリア後の規則説明である。B が tutorial を速く終えても転移で崩れるなら、誘導に従っただけで学習していない。逆に B の tutorial が少し長くても、転移の誤操作が減れば設計上の価値がある。記憶へ残す単位も「textless が良い」ではなく、「命題→制約→feedback→転移課題→観測指標」の検証可能な組にする。

■ メリット・デメリット
メリットは、学習を本編と同じ action で成立させ、説明の読み飛ばしや翻訳量を減らせること、詰まりを作者の補助ではなく盤面の欠陥として観察できること、成功 cue と次の対象が一貫しているため初見の認知負荷を抑えられることにある。失敗不能から可逆な失敗へ段階化するため、初心者を排除せず、経験者にも長い説明を強制しにくい。操作参照を後から呼び戻せる設計も、忘却を onboarding の失敗と混同しない。

デメリットは、一本道の通過を理解と誤認しやすいこと、過剰な点滅や particle が探索や自力発見を奪うこと、視覚 cue へ依存すると視認性・色覚・聴覚差への別経路が必要になることだ。盤面で表現しにくい抽象 system では制作コストが膨らみ、特殊な tutorial 専用ルールを作ると本編との一貫性も壊れる。記事の evidence は定性的な作者報告であり、対象人数や失敗例がないため、効果量や他 genre への外的妥当性は判断できない。

■ 判定
部分採用。説明を消すことではなく、学習命題を制約された実演へ変換し、次の自由場面で転移を測る設計を採る。無介入 playtest と常設の操作参照も採る。一方、「textless の方が常に優れる」「tutorial 通過は理解を示す」という一般化は採らず、headless log と初見観察で転移まで検証する。
