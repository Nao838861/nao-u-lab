## 何の教材か

`shot_log\v01` は、縦スクロールシューティングの完成プロトタイプであり、特に次の教材価値が高い。

1. 快感要素を先に固定する教材。
2. 良い v01 を一度完成扱いにする完成判定の教材。
3. ミニマル実験に余計な要素が混入する危険の教材。

## コアコンセプト

実装の中心は `index.html` の 1 ファイルゲーム。

- 画面: 420x620 の縦長 canvas。
- 操作: 矢印/WASD で移動、SPACE でゲージ MAX 時に BOMB、通常射撃は自動。
- ループ: 敵が出る -> 自弾が当たる -> アイテムが出る -> ゲージが上がる -> 弾数が増える -> より敵を倒しやすくなる。
- ゲージ段階: 1way -> 2way -> 3way -> MAX/BOMB。
- もっとも楽しい瞬間: MAX/3way で密集敵を壊し、得点とエフェクトが跳ねる瞬間。

教師情報:

- シューティングを作る時は、敵や罰より先に「撃って気持ちいい瞬間」を決める。
- 強化は、プレイヤーがすでに楽しい行為をもっと楽しくする方向に置く。
- ゲージは、行動の報酬として上げる。時間経過で減らす罰は、確信がない限り避ける。

## 快感要素ファーストの実装知

`shoot()` はゲージ段階に応じて弾を増やす。Lv1 は 1way、Lv2 は 2way、Lv3 は 3way。同じ移動/射撃行為を続けるだけで、画面上の当たりやすさと破壊量が増える。

`step()` では、アイテムがプレイヤーに近づくと吸い寄せられ、回収でゲージが上がる。敵を倒した後の報酬を取りに行く行為が、磁力による気持ちよい回収につながる。

教師情報:

- 強化の差は、数字説明より画面上の手触りで分かるようにする。
- アイテム回収は苦行ではなく、磁力や吸着でテンポを作る。
- 強くなるほど敵を倒しやすくなり、敵を倒すほど強くなる循環は、短時間で快感を伝えやすい。

## BACKLASH / 反撃弾の教師信号

敵を倒すと revenge bullet が出る。これは「倒すほど危険も増える」方向のルールだが、近距離で倒した時に理不尽になりやすい。Nao_u のフィードバックでは、子どもプレイで近距離反撃に死ぬ問題が指摘され、近距離の反撃弾は弱くする、プレイヤーを狙わない、猶予を伸ばす方向が提案された。

実装では `spawnRevenge()` に MERCY が入っている。

- small は広めの近距離で、プレイヤー方向の安全コーンから弾を逃がす。
- medium は近距離で狙い弾を横向きに変える。
- large/boss は設計上の遠距離脅威として mercy を弱くする。
- BOMB kill でも近距離は弾を逸らす。
- mercy 発動時はシアンのリング/ハローで見える。

教師情報:

- 「倒した結果として危険が出る」ルールは、快感を邪魔しやすいので近距離救済が必要。
- 救済は内部処理だけでなく、画面上のフィードバックで説明する。
- 小さい敵ほど理不尽死を避け、大型敵ほど危険として成立させると、直感に合いやすい。

## ペナルティをすぐ入れない教材

ゲージはプレイヤーの行動で上がり、行動の快感を増やすものとして設計されている。快感要素が立つ前にペナルティを足すと、遊びの核がぼやける。

教師情報:

- 「うまく遊べないと損する」より「うまく遊ぶともっと気持ちいい」を先に作る。
- 罰を入れる時は、その罰が快感循環を強める証拠が必要。
- 説明コストだけ増える要素は、v01 では削る候補にする。

## UI/表示の教師信号

Nao_u のフィードバックとして、反撃弾が敵弾と同色で見づらい問題、`Saving...` の中央揃えテキストが文字数で揺れる問題が記録されていた。実装では、反撃弾を暗めにする/早く消える方向、Saving/Loading のドットを固定幅で描く方向が入っている。

教師情報:

- 危険・報酬・演出は色や寿命で役割を分ける。
- UI テキストの揺れは小さくても品質を落とす。
- アニメーションする文字列は最大幅基準で固定する。

## headless 検証から見えること

`headless.py` は JS のゲームロジックを Python で近似したシミュレータで、複数ポリシーを走らせる。今回の実行では、中心維持型が平均 98.6 秒、平均スコア 489.3、3way 時間 60% と最も安定した。aggressive は平均 35.2 秒、defensive は 42.6 秒、sweeper は 5.9 秒で早く死ぬ。

教師情報:

- headless 検証では、人間の上手さを完全再現する必要はない。
- 複数の単純ポリシーを比べるだけでも、ゲームがどの行動を報酬/危険として扱っているか分かる。
- 中心維持が強いなら、ゲームが画面中央で敵を処理する設計になっている。
- sweeper がすぐ死ぬなら、横移動の快感と安全性が不足している可能性がある。

## 完成判定の教師信号

この v01 は「良いゲームデザインが人間のフィードバックに耐えたら、一度完成扱いにする」教材である。改良点が残っていても、核となる快感が成立し、フィードバックを受けて明確な修正ができたなら、その版を閉じる判断が必要。

教師情報:

- プロトタイプは永久に改善し続けない。
- 目的だった快感要素が成立したら、次は同じゲームを膨らませるより、別プロトタイプで学びを試す。
- 「閉じる」判断も design_log に残す。

## 今後の使い方

この教師情報は、シューティング、弾幕、アーケード、スコアアタック、ゲージ強化、反撃弾、近距離死、視認性問題、headless バランス検証を扱う時に想起する。

短い原則:

- 快感要素を先に作り、目標や罰は後から足す。
- 強化は説明ではなく、画面上の当たりやすさ・壊しやすさで伝える。
- 反撃やリスク報酬は、近距離理不尽を必ず検査する。
- ミニマル実験に余計な要素が混入したら、核に戻す。
- 成立した v01 は閉じる。次の学びは別プロトタイプで試す。
