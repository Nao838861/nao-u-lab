# ポリゴンとMODE7風の地面描画比較

通常ランチャーは[MMC5Racingコースのv002](../v002/README.md)を起動する。以下は楕円コースのv001の記録。旧版は`python tools/launch_ground.py --version v001`で起動できる。

2026年10月16日。対象は、MMC5Racing 3D版で道路の見やすさと描画費用を比較したい開発者。**Aで地面の描画方式、SELECTで4視点を切り替える試作ROMを実装した。** 同じ平面コースと箱型の車をGSUで描き、PPUが完成した描画RAMを直接表示する。

比較用コースは16分割の楕円。現行MMC5Racingのコース・4輪物理・レース進行の移植は次段階。カメラと自車の位置・方位は64地点の共通周回表を使い、GSUが毎画像、頂点変換・透視投影・近面／遠面クリップ・面塗り、または地面のテクスチャ走査を実行する。

## 起動と操作

- [50MHz版の起動](../../../run_ground_compare.cmd)：標準の比較条件。外部RAMの待ち時間と範囲フィルは25MHz版と同じ実時間。
- [25MHz版の起動](../../../run_ground_compare_25mhz.cmd)：同じROMをGSU 25MHz相当で比較する。
- [配布ROM](../../../releases/GSU_GroundCompare_v001.nes)：mapper 0ヘッダー。専用GSUマッパー`n8pro-gsu-abi2`とモード4に対応するコアを明示選択する。
- [4視点の比較画像](results/comparison.png)、[実ROMの動作GIF](results/interactive_50mhz.gif)。

| パッド | 未割当時に設定するキー | 操作 |
|---|---|---|
| A | Z | ポリゴン／テクスチャを切り替える |
| SELECT | 右Shift | 車載→近い追従→高い追従→俯瞰を順送り |
| B | X | 自動周回の停止／再開 |
| 左／右 | 左右矢印 | 停止中に1地点ずつ戻る／進む |

初期状態はポリゴン方式、高い追従視点。**Xで止めてZで方式を変えると、同じ位置・同じ視点で直接見比べられる。** ランチャーは専用Mesenの既存キー割り当てを保ち、未割当だけを補う。パッドはMesen側で設定したものを使用できる。

下段のPはポリゴン、Tはテクスチャ、Vは視点番号、CはGSU基準MHz。FはクリアとGSU処理中にまたいだNES field数で、fpsの値ではない。

## 2方式の実装

共通の道路輪郭から、48個の地面四角形と64×64のコース画像を生成する。道路16面、内外の縁石32面。自車と固定車は共通の箱型モデルを使う。空・草・灰色の路面・白の4色を画面全体で共有し、車の側面には空色も使う。

ポリゴン方式はRAM範囲フィルで空と草を用意し、GSUで道路と縁石を描く。各面をカメラ空間の近面2・遠面144の位置で切り、投影した凸多角形の左右の辺からスパンを作る。画面の外を除外し、面の縦範囲だけを初期化する。道路には今回追加した凸多角形の走査器を使っており、既存v003の高速三角形走査との統合は今後の最適化対象になる。

MODE7風は平面の地面を画面行ごとに逆投影する。ロール0、固定した4視点の傾きに対する行係数をROMに置き、方位・位置から開始座標と増分をGSUで計算する。行内では固定小数点座標を加算し、RAMから画像の色を読み、`PLOT`で描く。画素ごとの除算は使わない。マップの外は草、地平線より上は空、描画距離を超える行は単色の草となる。

両方とも、地面の後に同じ車を描く。方式や視点の変更で周回位置をリセットせず、完成画像とラベルをVBlankで交換する。入力はNMIで60Hzに取得し、押下イベントをキューへ入れる。停止中は地点番号を保ったまま方式や視点を変えられる。

テクスチャにはセンターラインと疎な草模様も入れた。画像は1画素あたり世界座標2単位の最近傍表示なので、近くの縁石は太く角張り、遠くの模様はちらつく。テクスチャ座標の増分は8bitの小数で、行内の丸め誤差も残る。高解像度のコース画像、座標精度、遠方用の縮小画像は次の画質改善候補になる。坂道は地形メッシュで扱う。

## RAMと表示の契約

既存ABI2の40KiB RAMを使い、メモリー容量とGSU ROMの経路は変更しない。`$5FE0=4`を256×192表示として追加した。モード1〜3の表示は従来どおり。下48行の背景は色0となり、通常CHRのスプライト文字を載せる。

各16KiBバンクの表示外領域へ、64×64・1画素1バイトの画像を保持する。ネイティブOBJ配置では末尾64行が2つの領域に分かれる。

| バンク内のオフセット | 用途 |
|---|---|
| `$0000..$27FF` | 表示領域の一部、範囲フィルで初期化 |
| `$2800..$2FFF` | テクスチャ前半2KiB |
| `$3000..$37FF` | 表示領域の残り、範囲フィルで初期化 |
| `$3800..$3FFF` | テクスチャ後半2KiB |

画像は両バンクへ起動時に配置し、描画時はbackバンクの表示外領域から読む。RAM上の画像はu方向を外側の添字にして、`MERGE`からアドレスを短く計算する。表示領域12KiBの草フィル後、視点ごとの空の範囲を塗る。単色の12KiBは25MHzで0.49152ms。空の上書きとコマンド発行も含めた費用は、下記の測定と実ROMの提示間隔で扱う。

この小画像は既存RAMに収まるため、先の3D仕様書で検討したGSU用ROM経路の追加を先送りできた。本番コースの高解像度画像やゲームの常駐データには、正式なROM経路・メモリー割り当てが引き続き必要になる。モード4のRTL、MMC5同居、実機でのRAM調停は今回の実装範囲に含めない。

## 測定結果

GSU命令・キャッシュは固定版Mesen由来。25MHzと50MHzともCLSR=1、MS0=1。50MHzでも外部RAMの待ち時間と25MHzの範囲フィルは同じ実時間を保つ。以下は全64地点のGSU開始からSTOPまでで、範囲フィルと6502側の準備時間は含まない。

| 視点 | 25MHz ポリゴン | 25MHz テクスチャ | 50MHz ポリゴン | 50MHz テクスチャ |
|---|---:|---:|---:|---:|
| 車載 | 31.66〜40.09ms | 58.45〜65.10ms | 26.75〜34.25ms | 36.30〜40.88ms |
| 近い追従 | 34.90〜45.21ms | 61.21〜70.07ms | 29.69〜38.74ms | 37.99〜44.07ms |
| 高い追従 | 37.87〜49.67ms | 65.11〜75.69ms | 32.34〜42.83ms | 40.50〜47.42ms |
| 俯瞰 | 48.87〜54.78ms | 78.16〜91.13ms | 41.76〜47.00ms | 49.67〜57.15ms |

**現状の比較版は30fps未達。** 実ROMで採取した各視点・方式8画像ずつの提示間隔は、50MHzで3〜4 fields（約20〜15fps）。25MHzではポリゴン3〜4 fields、テクスチャ4〜6 fields（約15〜10fps）だった。CPU準備と空の複数フィル発行を含む提示間隔なので、GSUの時間だけより遅くなる。

この実装ではテクスチャの色参照・全地面画素の処理が重く、単色道路の方が速かった。近遠面クリップ、整数除算、作業RAMへの頻繁な読み書きにも改善余地がある。値は今回の走査器と64×64画像の費用を示す。既存の小型ポリゴンベンチマークの面数上限、最終ゲームの処理時間、FPGA実機の上限とは別に評価する。

次の性能改善は、ポリゴン側の高速スパン走査との統合、共通数学処理のキャッシュ／RAMアクセス削減、テクスチャ側の行係数と内側ループの短縮を候補にする。テクスチャ走査の専用回路を検討する場合も、今回のRAM参照費用を基準にする。単色スパン回路の速度向上をテクスチャへそのまま適用しない。

## 確認と再現

- ネイティブGSU：25／50MHz × 4視点 × 2方式 × 64地点、合計1,024画像・50,331,648画素が独立した整数幾何参照と完全一致。表示外の画像と行係数の保持、front保護も確認。
- 実Mesen：両クロックで各64画像、合計128画像・7,864,320 RGB画素を照合。GSU RAM、192行表示、下段ラベルが一致。
- パッド入力：A長押し、SELECT一周、B停止、停止した位置でのA変更、左右1地点送り、入力キューのあふれなしを確認。
- 既存のABI1／ABI2／範囲フィル／cubeの4 contractが通過。既存v003の代表条件4画像も画素一致・2 fields提示・missed=0。
