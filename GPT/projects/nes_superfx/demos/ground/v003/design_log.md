# 車体と物理座標の接続

2026年10月16日。地面比較のデータと接続部を改修する。操作と描画方式はv001の設計評価、コースはv002の検証を引き継ぐ。レース本体や物理エンジンの新規実装は行わない。

## フィードバック原文

> 車のサイズと元のコースの幅の比率を合わせて、元の挙動を移植できるようにして。

前版ではコースだけを原寸比へ合わせ、仮の車体は16×30px相当のまま残した。これは元の車と道路の関係を変えてしまう判断だった。「車を小さくする」という要約ではなく、元の車体・道路・物理座標を同じ尺度で扱う修正として記録する。今後、既存ゲームのコースを移すときは車体寸法も一緒に照合し、カメラの見かけの大きさで補正しない。

## 実装前の評価と改善

| 評価・懸念 | 採用する改善 |
|---|---|
| 16×16は画像の枠で、透明余白も含む | 現行GRIPの影を除いた不透明外形12×13pxを採用 |
| 旧3D車の長さ30pxは道路に対し過大 | 元の64pxアスファルト、80px路肩幅と同じ1/5縮尺 |
| 車体高は2Dからは決まらない | 仮の4px相当と明示し、平面寸法と区別 |
| 前後の外形は元の回転中心に対して非対称 | 中心をずらさず前6px、後7px、左右6pxへ配置 |
| 64地点のテーブルでは物理位置を受け取れない | 6502で元のsigned16.8座標を毎回変換 |
| 元の車体角と速度方向はドリフト中に異なる | 車体角とカメラ角を独立した入力にする |
| 元の位置を整数へ丸めると低速でがたつく | 小数8bitを含む24bit値を変換境界まで保持 |
| 物理のZPや状態を書き換えると移植を妨げる | 読み取り専用スナップショット、物理ZP $40..$FFを保護 |
| 描画の処理落ちに物理を結びつけたくない | sim tickをリクエストに残し、描画側では進めない |
| 自動経路だけでは外部状態入力を確認できない | ROMに外部状態モードを設け、経路外位置・横滑り角でも実行検証 |

元の摩擦、タイヤ力、速度、1tickの積分は変更しない。今回の自動周回は描画比較用のままで、60Hz物理が動くゲームとは扱わない。元ゲームの現行GRIP画像をモデル外形の基準とし、DRIFT専用の車体外形は後続のモデル差し替え対象とする。

## 検証方針

元データの出典hashと車体外形を保存する。実6502の変換を独立計算と照合し、原座標の誤差、角度一周、カメラ角と車体角の分離、物理状態の非変更を確認する。実ROMの外部状態モードで任意位置を送り、GSUリクエストと画素を照合する。通常の2方式・4視点も既存の独立参照と比較する。

## 実装後の確認

車幅12.03125px、車長13.0078125px相当となり、公称寸法との差はQ9.7の丸め以内。実6502の5,219条件、物理ZP不変、元ABIからのコピー、範囲外拒否が通った。方向係数の積は最大9bitと分かっているため、カメラ変換の乗算を9回にして最大4,986cyclesへ減らした。

外部状態の実ROM試験で、GSU実行中に比較方式を書き換えた際、既に始まった旧方式の画像へ新しいラベルが付いたフレームを誤採取した。注入後に2回以上の画像更新を待ち、物理tickと方式を確認してから採取するよう試験側を修正した。実際のパッド入力は従来通りNMIのキューへ入り、GSU停止後に消費される。任意8状態×2方式の16画像がその後すべて一致した。

25／50MHz・全4視点・2方式・64地点の1,024画像と、実ROM128画像のPPU RGB・比較操作が通過。v001／v002の再生成hashも不変。車体高や形を作り込む前に、道路との寸法関係と元状態の接続を優先するという今回の修正目的を満たした。
