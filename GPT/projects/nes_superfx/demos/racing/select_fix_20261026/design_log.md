# Selectによる4視点切替の復旧

## ユーザーの原文

> このバージョン、セレクトボタンの視点変更って機能してる？

> 何が原因？修正して。

通常の操作で使えるはずの機能を確認し、原因説明だけで終わらせず直す依頼。今回の不足はキー設定ではなく、入力が届いた先のゲーム側処理だった。「操作説明を追加する」という要約では修正内容を取り違える。

## 原因

固定入力はMMC5Racingの `a8d2a2d01fefc39665f01d22b80c80207ce088f7`、ROM SHA256 `b893f680e22fbd38b5aa47516bc7aef3564fb8e292b0403ab38aa33cba3b74dc`。

NMIはパッドを `$0640` へ読み、立上りを `$0642` に生成する。しかし固定PRGバンク0の `$E5F2` は `JMP $E633` で共通ゲーム処理へ飛び、旧版のSelectによる `$0650`（希望視点）の更新を通らない。`$0650` は初期値2のままで、前景処理の `$E174..$E17B` が読む視点も変わらなかった。

4種類のカメラ表、視点を反映する座標変換、地面とGSUへのアップロードは残っていた。エミュレーターの表示だけを拡大したり、入力を偽装したりする修正は不要だった。

## 修正

`src/fx_racing_select_fix.s` の28バイトを、固定PRGバンク0の未使用領域 `$FE16..$FE3F` 内に置く。`$E5F2` の分岐先をこのヘルパーへ変更する。

ヘルパーは `$0642 & 4` のSelect立上りと `$4FE0 == 4` の3D表示を条件に、既存の `$0650` を4で循環させ、元の `$E633` へ戻る。タイトルの表示モード5では何もしない。A・X・Yやゲーム状態を新しい作業RAMへ退避する処理は追加していない。次の共通処理がAとフラグを上書きするため、接続位置にそれらの引継ぎ依存はない。

希望視点の更新はNMI、カメラの確定と描画は既存の前景処理へ任せる。新たな物理・入力ポーリング・カメラ別実装を追加しない。変更はROM全体の30バイトに限られ、他のPRGバンクとCHRは完全に不変。元の公開ROMは保持し、別名の修正版ROMを生成する。

## 検証と判定

`tools/verify_fx_racing_camera_fix.py` は、修正前後の実ROMを、モード0・1でそれぞれコールドブートし、同じパッド入力で1900フレーム実行する。タイトルのSelectによるモード選択、レース中の短押し4回、長押し80フレーム、解放後の再押下を通す。

- 修正前：視点はすべて2、カメラは1種類。
- 修正後：`2 → 3 → 0 → 1 → 2 → 3 → 3 → 0`。地面カメラは4種類、長押しでは1回だけ変化。
- 両モードとも、共通ゲーム更新1667回の自車・敵車・レース・ゴーストの採取範囲が修正前と完全一致。
- 各採取点のGSU／DSPエラーなし。
- 4視点の実PPU画像を確認。高い追従、俯瞰、車載、近い追従で道路・景物・自車の見え方が切り替わる。

操作と表示が再接続されたので、この範囲の修正は合格。ここから恒久的な新しい運用ルールは追加しない。今回のテストは停止車両の同一入力比較であり、全コース・全入力の実機タイミングの証明ではない。
