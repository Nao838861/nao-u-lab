# 道路・車の配色と空パレットの分離

`run_racing_3d.cmd` の標準をv003に更新。直線の白線をなくし、カーブの縁を赤白、車体を赤、車体後部を赤とグレーの市松模様にした。音ありv002の物理・音を維持する。

道路メッシュの直線5区間は両端の帯を灰色にし、白線があった幅まで舗装を広げる。カーブの帯はポリゴン表示では各区間を道路方向に2分割し、赤・白の単色四角形を交互に描く。画面座標による縞描画は廃止した。テクスチャ表示では道路方向の原座標32px周期を維持し、両方式の模様の位相は一致しない。走行判定・車体寸法は変更しない。車体後部にはGSUの標準ディザ機能を使い、1画素ずつ赤とグレーを交互に描く。

縁石28区間を各2枚にするため、全コースの候補四角形は62枚から90枚になる。共有頂点84個を変換した後、縁石の四隅をカメラ空間の境界箱（AABB）でまとめて判定する。視野外の区間は2枚すべてを省き、残った区間だけ補間・near/farクリッピング・投影する。球の半径計算は不要。境界箱は保守的な除外にのみ使い、画面端の正確な処理は従来どおり各ポリゴンで行う。

親四隅と補間状態は未使用の `$8F00..$8F2B` に保持し、元の頂点・面テーブルの上限を増やさない。コードは16バイト境界に配置して4KiBに収める。隣り合う小片は同じ端点と補間式を使う。

開始位置の4視点で、縁石をまとめて除外する場合／しない場合の画像が完全一致。木を追加した版のポリゴン表示ではGSUクロックは約19〜29%削減（50MHzエミュレーション）。これは分割後の除外なし実装との比較で、旧画面縞方式との速度比較ではない。地面2方式を含む8画像を検査し、操作テストも通過。全走行位置の性能を保証する測定ではない。数値は `results/kerb_comparison.json`。


縁石の長さを2倍にする変更では、分割数を4から2に減らした。変更前との開始位置4視点の比較でGSUクロックを18〜26%削減。50MHz設定のGSU描画部分は34〜55msで、CPU処理・表示同期は別途必要。詳細は `results/kerb_length_comparison.json`。区間除外後も残る面には個別クリッピング・投影・走査線塗りつぶしを行うため、この変更だけでは30fpsに届かない。

## 木の代替三角錐

2D版 `MMC5Racing` の revision `6b2b648220e407f5c67a301693fe0e3302789886`、`scenery/build.py` の `TREES` と同じ8座標に三角錐を配置。座標・寸法は `trees.json`。側面2枚に緑＋灰色、緑＋赤の市松模様を使い、残りの側面も緑＋灰色の市松模様にし、緑単色の面は作らない。底面は描かず、1本につき頂点を共有する三角形の側面3枚を描く。三角形は頂点を重複した四角形として既存描画器へ渡す。

高さは原座標11.25px、底面は原座標で中心から±11pxの範囲。低い視点でも空の専用パレットへ入らない高さにした。4頂点を `$8F70..$8F87` へ1本ずつ変換し、中心の奥行きで遠い順に描く。半径4ワールド単位で包んだ範囲を使い、視野外の木は頂点変換前に除外する。自車は最後に描く簡易的な重ね順で、木との厳密な遮蔽・衝突は未実装。

4視点×地面2方式と、木8本を個別に見る画像を採取。木の一括除外の有無で16画像が完全一致した（`results/tree_comparison.json`）。空パレット、音と物理の更新数、操作テストも通過。木追加後の開始位置4視点は50MHzで約42.9／49.1／50.9／71.1ms。CPU処理と表示待ちは含まない。上記 `kerb_length_comparison.json` の34〜55msは木追加前の記録。

## 空の専用パレット

道路・車のBGパレット0は赤・緑・グレー・白。空のBGパレット1は共通背景色の赤に加えて、緑・白・青を持つ。パレットRAM `$3F05/$3F06/$3F07` が `$1A/$30/$21`。現在の空領域は青で塗る。下段HUD背景はグレー。

専用マッパーに次の開発用レジスターを追加した。この表示には更新した専用コアが必要。

- `$4FF4` 書込み：次の表示画像の空の高さ。8画素単位、上限192。読取り：現在表示中の高さ。
- `$4FF5` 読取り：対応コアは1を返す。
- `$4FE2` のVBlank画像交換時に、空の高さも同時に確定する。

ネームテーブル読取りで保持した8×8タイル座標から、attribute読取り時にパレット0/1を選ぶ。通常の固定attribute表とは異なる専用マッパー側の選択である。空と地面の境界を8画素に揃え、4視点の空の高さを88/72/56/0にした。端数の空行は遠景の緑になる。道路や車が空パレットへ入らないようにしている。状態保存には表示中／予約中の高さと有効フラグを含む。

## 確認

4視点×地面2方式で撮影し、空の全画素が青、専用パレットの緑・白・青が設定済み、表示中の視点と空の高さが一致することを検査。表示faultは0、物理と音の更新数は一致。視点・地面・モード切替、START、範囲外からの復帰も通過。画像と記録は `results/`。

```powershell
python tools/build_racing_colors.py --cc65-bin <cc65のbinフォルダー>
python tools/build.py
python tools/setup_runtime.py --mesen-dir <Mesen2.1.1のフォルダー> --rom <診断ROM>
python tools/verify_racing_colors.py
python tools/verify_racing_kerbs.py --cc65-bin <cc65のbinフォルダー>
python tools/verify_racing_controls.py --version 003
```

GSUのアセンブルには固定版casfxの `casfx.inc` が必要（既存 `build_cube.py` と同じ版・ハッシュ）。v001/v002 ROMは保持し、`tools/launch_racing.py --version 002` で音移植時の表示に戻せる。
