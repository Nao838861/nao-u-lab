# Mode7地面＋SuperFXポリゴン

原版の走行挙動を残した試走版。地面は640×640・2bpp画像を専用サンプラーで読み、SuperFXは車と8本の三角錐だけを描く。地面用のポリゴン・頂点変換・テクスチャ画素ループをGSUの実行経路から外した。

`run_racing_3d.cmd` または親ワークスペースの `play_mmc5racing_3d.cmd` で起動。Z＝加速、X＝ブレーキ／ドリフト、左右＝操舵、右Shift＝視点、下＝GRIP/DRIFT、Enter＝リセット。上は比較用のFX表示オン／オフ（車と木を隠して地面だけを確認）。表示オンが標準。

## 抜き色とパレット

FXの色0は描画なし、色1〜3は描画あり。8×1のビットプレーンを `F0,F1`、地面を `B0,B1` とすると、`M=F0|F1`、`O0=(B0 & ~M)|F0`、`O1=(B1 & ~M)|F1`。追加アルファプレーンは使わず、元の背景画素をそのまま残す。灰色による穴埋めは行わない。FXでは色0を不透明に描けない。

|用途|色0（共通）|色1|色2|色3|
|---|---|---|---|---|
|BG0地面・パレット0|白|赤|緑|灰|
|BG1空・パレット1|白|赤|緑|水色|
|BG0＋FX・パレット2|白|赤|緑|灰|
|BG1＋FX・パレット3|白|赤|緑|水色|

8画素すべて抜きならパレット0/1、一つでも描画ありなら2/3。現在は対応するBGとFX用パレットを同色に設定し、背景の色がブロック境界で変わらないようにする。FXの白は使用できない。空にかかる色3は水色になるため、色3の意味はその行のBGパレットに従う。

## 行テーブル生成ユニット

DSP-1命令互換は持たない。入力はカメラX/Z/高さ（Q9.7）、yawのcos/sin、pitchのcos/sin（Q8係数）。焦点距離128画素、画面中心128/96、256×192画面、ロールなし。yaw係数のノルムも使って逆変換する。

各行にQ16.16の `u0,v0,du,dv` とBG選択・地面有効フラグを生成し、`u=u0+x*du, v=v0+x*dv` で640四方の画像を参照する。画像外と遠方（深度144より先）は草地、地平線より上は空。色は最近傍で取得し、遠景のちらつきを消すフィルタは未実装。

入力は開始時にラッチし、裏のテーブルへ生成する。テーブル・FX画像は共通のカメラスナップショットと物理tickを持つ。GSU終了、テーブル生成完了、VBlankの条件を満たした時だけ同時採用する。CPUはカメラ14バイト等を渡すだけで、行テーブルの全転送は行わない。

|CPUアドレス|内容|
|---|---|
|`4FA0..4FAD`|カメラ7成分、signed16 little endian|
|`4FAE`|裏テーブル／FX画像番号0または1|
|`4FB0`書込み1|入力をラッチして生成開始|
|`4FB0`読取り|bit0 busy、bit1 ready、bit2 error、bit3 表示有効|
|`4FB1`読取り|対応する拡張ROMなら1|
|`4FB2..4FB3`|次の表示世代（物理tick）|
|`4FB4..4FB5`読取り|現在表示中の世代|
|`4FB6` bit0|比較用FX非表示、開始時にラッチ|
|`4FE2`|従来のVBlank交換。新方式ではテーブルも同時採用|

PPUのnametable fetch時に対応する8×1を先読みし、attributeとpatternを同じ結果から返す。前走査線321dot以降の先読みは次行へ対応させる。通常のスクロール0・BG table0・sprite table1の表示契約を維持する。

## 原版画像とROM

`ground.2bpp` は原版の基準角度のタイル地図から復元。原点144/144から640四方を切り出す。原版の単色ブロックはカタログを展開し、地面パレット0/3を残し、景物パレット1/2を除く。元の配色を4色へ対応付け、パレット3の黒は草色へ寄せる。原版の白線、赤白縁石、スタートライン、コーンを含む。木・建物の焼き込み画像は除外し、木は引き続きポリゴン表示。

PRGは2MiB。前半1MiBのCPUバンク構成を維持し、後半の先頭に `M7R4` ヘッダーと102,400バイトのpacked 2bppを配置。CPUは従来どおりバンク0..127のみを切り替え、サンプラーが追加領域を直接読む。元のPRGバンク4..127とCHRはバイト一致をビルド時に検査する。

## 実測と検証

開始位置、GSU 50MHz相当。演算ユニットには仮の25MHz・1行1024clockモデルを置き、192行で7.86432ms。この生成とGSUを並行実行する。

|視点|v003 FX描画|v004 FX描画|v003→v004 実表示fps|
|---|---:|---:|---:|
|1|23.42ms|5.57ms|30→60|
|2|27.01ms|8.71ms|20→60|
|3|28.96ms|9.32ms|20→30|
|4|45.20ms|12.45ms|15→30|

- 単体合成2,097,152画素を全照合。0は常にBGを残す。
- 64方向×4視点の有効行を独立した投影式で検査。128,768点、最大誤差約0.029画素。
- 実Mesenの4視点×FX表示有無の393,216画素を、地面の逆参照と画素単位の色0判定で完全照合。
- 生成途中の採用拒否、入力ラッチ、表示テーブル保護、生成時間、世代、リセットを検査。
- GRIP/DRIFT各1,000更新の物理状態が比較元と一致。元のカメラ方向と音更新数を維持。
- 操作・視点・表示切替・リセット・範囲外復帰を確認。
- 新コアでもv003の8画像が保存済み画像と完全一致。v003のROMと旧runtimeは保持。

画像と結果は `results/`。ソフトウェアとして動作する専用エミュレータ版であり、RTLの実装・Fit・実機測定は行っていない。DSP時間は仮定であり、サンプラーの実メモリ待ち時間も未検証。上記fpsを実カートリッジの性能保証には使わない。

自己評価：以前のポリゴン縁石より原版の道路模様が安定し、抜き色による草地の欠損を避けられた。開始位置の実表示も改善した。遠景の最近傍サンプリングによるちらつきと空をまたぐFXの色数制約は残る。

## 再生成

```powershell
python tools/extract_racing_ground.py --source <MMC5Racingソース>
python tools/build_racing_colors.py --cc65-bin <cc65のbin>
python tools/build_racing_mode7.py --cc65-bin <cc65のbin>
python tools/build.py
python tools/setup_mode7_runtime.py --core <新しいMesenCore.dll> --mesen-dir <Mesen2.1.1のフォルダー>
python tools/verify_racing_colors.py --version 004 --measure-fps --results build/racing/v004/check
python tools/verify_mode7_pixels.py --results build/racing/v004/check
python tools/verify_racing_controls.py --version 004
python tools/verify_racing_camera.py --version 004
```

`mode7_contract.cpp` はPPU非依存のC++17単体検証。CMakeターゲット `nesfx_mode7_contract`。カメラ比較は従来の `build/racing/v003/camera-test/before.nes` と `before.lbl` を使う。

旧版：`python tools/launch_racing.py --version 003`。保存タグは `mmc5racing-3d-v003-pre-mode7-20261016`。
