# MMC5Racing 3D v005

木を幹つきの針葉樹、車をキャビン・窓・タイヤつきの赤い車、家を切妻屋根・壁・扉・窓のあるポリゴンモデルに変更した。面の向きで単色と2色市松模様を使い分ける。車の後部は赤＋灰の市松模様を維持した。

`run_racing_3d.cmd` の既定版。`--version 004` で前版、`--version 003` でMode7導入前へ戻せる。v003の資料用録画・保存版には変更を加えていない。

## 形状と色

|対象|近景の頂点／面|遠景の頂点／面|配置|
|---|---:|---:|---|
|車|32／14|同じ|元の物理状態に追従、幅2.4・長さ2.6 world|
|木|11／7|5／4|原版の8本と同じ位置|
|家|24／10|同じ（LODなし）|原版の2棟と同じ位置|

近景の木は四角錐の樹冠と三角柱の幹。家は切妻屋根を持ち、窓・扉もポリゴン。タイヤは左右に前後2個の側面ポリゴンを置く。

家の屋根は赤一色、三角形の妻壁と広い壁は灰色一色、狭い壁は赤＋灰色の市松模様。屋根の頂点を壁から独立させ、四方に0.35 world（元画像の1.75画素相当）のひさしを設けた。面数は10面のまま。

地面はv004の640×640・2bpp画像とMode7サンプラーをそのまま使用。FXの色0は透明、色1〜3は赤・緑・灰。市松模様は非零色同士で構成し、背景の穴埋めはしない。空側のパレットでは色3が青になるため、地平線をまたぐ面の灰成分は青になる。

木はカメラ深度24 worldから幹だけを省略する。樹冠の5頂点・4面・配色は近景と同じデータを参照し、向きも世界座標に固定する。家は距離による簡略化を行わず、屋根・壁・窓・扉を保つ。

## 初版の性能と検証

以下は旧LODを使う初版（ROM SHA-256 `1f3feb65…`）の記録。現在の形状・LOD変更後の再測定は後述する。

測定は専用Mesen・GSU 50MHz設定。地面DSPはv004と同じ仮の25MHz・1行1024clockモデルで、GSUと並行実行する。

- コース64地点×4視点×車体角度差3種＝768条件。
- 木8本・家2棟の周囲×4視点×8方向×2距離＝640条件。
- 合計1,408条件でGSU命令を実行し、最大 **24.838ms**。
- 各視点の重い走行地点・近接地点と外観確認地点、計19場面を実PPUで各120 VBlank計測。GRIP・DRIFTの両方、計38測定で最低 **30.0494fps**。
- 開始地点の4視点はFX約11.15／9.02／8.70／9.13ms、表示約30／60／60／60fps。
- 4視点×FX表示／非表示の393,216画素を、独立した地面逆投影と透明合成式で照合して一致。
- 操作切替、リセット、エラー復帰、物理と音の更新数一致を確認。
- 除算の短縮経路をGSUで実行し、5,888入力でPythonの整数除算と商・余りが一致。

結果は `results/`。走査した条件での実測であり、全座標・全入力のフレーム時間保証ではない。25MHz設定は30fps目標の対象外。

## 屋根・配色・LOD変更後の性能

現行ROMは `cb62bb356af4c86632ea061c7f1132b36f6d0502ff8de4bdf8a804802aa41a75`。家のLOD廃止と木の樹冠維持で描く面が増え、同じ1,408条件でGSU最大34.904msになった。重い場面では約20fpsとなり、30fps維持には届いていない。

世界モデルの頂点変換に命令キャッシュを適用し、変更直後の最大37.419msから短縮した。この最適化前後は1,408条件すべてでフレームバッファが一致。形状を省略する最適化は追加していない。再測定・画像は `results/house-lod/` に分け、旧結果は初版の記録として残した。

負荷上位を含む19場面をGRIP／DRIFT双方で測定し、最低20.0329fps。開始位置の4視点はFX約11.06／13.72／14.33／16.57ms、表示は各30.0494fps。透明合成393,216画素が参照計算と一致し、音と物理の更新数・表示世代の同期・FX/DSPエラーなしを再確認した。

## 描画処理

1. 景物中心を変換し、各モデルを包む半径で近遠・画面外を判定する。
2. 景物を中心深度の遠い順に描く。遠い木は幹のみ省略する。
3. 面の平面式を事前生成し、見えない面を頂点投影前に除外する。
4. モデル単位で近遠クリップの要否を判定し、不要なら面ごとのコピー・境界走査を省く。
5. 未クリップ面は頂点番号で投影結果を共有する。三角形の重複4頂点目は処理しない。
6. 短い辺の除算は8bit経路・商0経路を使う。
7. 最後に車を描き、v004の世代同期で地面とFXを同時表示する。

道路の旧GSUテクスチャ処理・縁石分割コードはv005から除去した。物理・音・CPUのコード、地面画像、エミュレータコアはv004と同一。Zバッファや景物との衝突は追加していない。

## 再生成と検証

v003→v004のビルド済み入力と専用runtime_mode7が必要。`CC65` はcc65のbinディレクトリ、`PROBE` は `src/racing_profile.cpp` から作った実行ファイル。

```text
python tools/build_racing_scenery.py --cc65-bin CC65
python tools/verify_racing_colors.py --version 005 --results build/racing/v005/initial-test --dump-gsu --measure-fps
python tools/verify_mode7_pixels.py --results build/racing/v005/initial-test
python tools/verify_racing_scenery.py --probe PROBE --emulate
python tools/verify_racing_scenery.py --emulate --drive-mode 1
python tools/verify_racing_divide.py --probe PROBE --cc65-bin CC65
python tools/verify_racing_controls.py --version 005
python tools/verify_racing_camera.py --version 005
```
