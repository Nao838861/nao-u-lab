# C02 ファミコンのCPUは3D計算が苦手
（ここからC05までは第二部の構成・音声案。まず背景の木を例に、疑似3Dの見え方からテーブル化へ順に説明する。敵の軌跡、8bit／16bitの使い分け、2フレームへの処理分散は後続で扱う。）
（実機映像を背景に、「かけ算・割り算の命令がない」を表示。その後、「基本命令を組み合わせる → 計算に時間がかかる」と示す。数式やCPU命令の一覧は出さず、課題を短く伝える。）

- 音声案
    ファミコンのCPUには、かけ算や割り算の命令がありません。
    足し算やビットのシフトなどを組み合わせれば計算できますが、そのぶん時間がかかります。
    そのため、たくさんの物体の位置や大きさを毎回計算する3Dの処理は、大きな負担になります。
    そこで、スペースハリアーの画面の特性に合わせて、計算を減らしました。

# C03 奥行きは「位置」と「大きさ」で表せる
（背景の木を1本だけ使った模式図に切り替える。最初は同じ大きさの木を左右・上下に動かしてX・Yを示し、次に奥行きZを加える。）
（カメラの向きと高さを固定した例にする。木が奥へ移動すると、画面内の位置が地平線上の消失点へ近づき、同時に小さくなる。近・中・遠の3位置を順に見せる。Xは画面中央へ、Yは地平線へ寄ることを別々の矢印で示す。）
（このカットではテーブルを出さず、奥行きによって何が変わるのかを見せる。）

- 音声案
    スペースハリアーのような疑似3Dでは、画面に置く絵の位置と大きさを変えることで、奥行きを表せます。
    横のX、縦のYに加えて、奥行きを表すZを持たせます。
    たとえば背景の木は、奥へ行くほど横位置が画面中央へ、縦位置が地平線へ近づき、絵も小さくなります。
    このように見え方の条件を絞れば、奥行きに応じてどう変わるかを、あらかじめ用意しておけます。

# C04 奥行きによる変換をテーブルにする
（C03と同じ木と消失点の図を使い、左に「奥行きZ → テーブル参照」、右に結果の位置を表示する。表は56行すべてを並べず、近・中・遠の代表行だけを拡大して、選ばれた行と木の位置を連動させる。）
（「背景の奥行き：56段階」と表示。「横位置に使う倍率」「地面上の高さ」の2項目を順番に見せる。横位置は「元の横位置 × 表から取り出した倍率 → 画面中央からの距離」、地面上の高さは「Z → 高さ」とし、両方とも最終座標を直接引くだけ、という図にはしない。）
（説明対象は地面に立つ背景の木。プレイヤーの上下移動で地平線が変わる場合は、対応する高さの表に切り替えることを制作側で把握し、このカットではカメラ高さを固定して説明する。）

- 音声案
    今回の背景オブジェクトでは、奥行きを56段階に分けています。
    それぞれの奥行きについて、横位置に使う倍率と、地面上の高さをテーブルに記録してあります。
    ゲーム中はZの値で表を引き、取り出した倍率を横位置に適用し、地面上の高さと合わせて表示位置を決めます。
    横位置の計算は残りますが、奥行きから倍率や地面の高さを求める計算を、毎回行う必要はありません。

# C05 絵の大きさもZから選ぶ
（C04の図に「絵のサイズ」の表を追加する。Zの同じ行から、位置に使う値とサイズ番号が選ばれる様子を順番に見せる。）
（前回紹介した16段階の画像を並べ、Zに対応する1枚を強調する。「56段階の奥行き → 16段階の画像」と表示し、56枚の縮小画像があるようには見せない。）
（最後に説明図から実機映像へ戻し、「奥行きに応じた表の参照＋必要な計算」で奥行きのある表示になることを見せる。第一部のコンパイルドスプライト解説は繰り返さず、画像を選ぶ部分だけを扱う。）

- 音声案
    キャラクターの大きさも、同じZの値からテーブルで選びます。
    前回紹介した16段階の画像のうち、どれを表示するかを、奥行きごとに決めてあります。
    実行中に絵を縮小するのではなく、用意した画像を選ぶだけです。
    このように、奥行きに応じた位置の変換や画像の選択をテーブルにすることで、計算量を抑えながら、奥行きのある画面を作っています。
