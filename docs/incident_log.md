# 障害ログ (Incident Log)

定期実行システムの障害履歴と修正記録。
新しい障害が発生したら **必ずこのファイルに追記** すること。

関連: `docs/scheduler_architecture.md`（設計書）

---

## 記録フォーマット

```
### INC-NNN: タイトル (YYYY-MM-DD)
- **影響**: どのインスタンス/ジョブに影響したか
- **症状**: 何が起きたか
- **原因**: なぜ起きたか
- **修正**: 何をしたか（コミットハッシュ）
- **再発防止**: 構造的な対策（あれば）
- **教訓**: 横展開すべき知見
```

## 障害一覧

### INC-001: 旧タスク残留による多重起動 (2026-03-27)
- **影響**: Win(Log) — scheduler_log.py導入後も旧タスク`NaoBot_CheckInbox`等が動作継続
- **症状**: Python Install Managerの画面が繰り返し開く。スクリプトの二重実行
- **原因**: 統合スケジューラ導入時に旧タスクスケジューラ登録を削除しなかった
- **修正**: `schtasks /delete /tn "NaoBot_*" /f` で旧タスク削除
- **再発防止**: なし（手動確認）
- **教訓**: スケジューラ移行時は「旧タスク削除」まで完了して初めて移行完了。チェックリスト化すべき

### INC-002: claude --print 無限ハング (2026-03-26)
- **影響**: Mac(Mir) — 自律サイクルが完全停止
- **症状**: claude --print がレスポンスなく永久待ち
- **原因**: claude CLI側のハングアップ（原因不明）。タイムアウト未設定
- **修正**: `autonomous_cycle.sh` に `perl -e 'alarm 1800; exec @ARGV'` で30分タイムアウト追加
- **再発防止**: タイムアウト恒久設置
- **教訓**: 外部プロセス呼び出しには必ずタイムアウトを設定する

### INC-003: scheduler連続エラーでハング (2026-03-26)
- **影響**: Win(Log)/Win2(Ash)
- **症状**: slack_checkがexit=1を連続返却 → エラーカウンタ蓄積 → 30分バックオフ
- **原因**: exit=1は「新着なし」の正常応答だがエラーとして扱われていた
- **修正**: `scheduler_log.py` でexit=1をエラーカウントから除外
- **再発防止**: exit codeの意味を統一（0=正常、1=新着なし/該当なし、2+=エラー）
- **教訓**: 終了コードの意味を明確に定義・文書化する必要がある

### INC-004: git rebase lock競合 (2026-03-26)
- **影響**: Win(Log) — git_syncが失敗
- **症状**: `.git/rebase-apply` が残存してgit pullが失敗
- **原因**: scheduler_stdout.logがgit addされ、複数マシンでコンフリクト
- **修正**: scheduler_stdout.logを.gitignoreに追加
- **再発防止**: ログファイルは.gitignoreに入れる原則を確立
- **教訓**: 自動コミットされるファイルの範囲を限定する

### INC-005: watchdog.pyw でウィンドウポップアップ (2026-03-26)
- **影響**: Win2(Ash) — 作業妨害
- **症状**: VBScript経由の起動でウィンドウが表示される
- **原因**: VBScriptのウィンドウ非表示が不完全
- **修正**: VBS廃止 → `pythonw` 直接デタッチ起動に変更
- **再発防止**: Windows上のプロセス起動は `pythonw` + `CREATE_NO_WINDOW` を標準とする
- **教訓**: Windows固有のウィンドウ制御はpythonwが最も信頼性が高い

### INC-006: Playwright headless問題 (2026-03-25)
- **影響**: 全インスタンス — ブラウザウィンドウがフォアグラウンドに出現
- **症状**: DM確認・Twitter巡回時にブラウザが画面に出てくる
- **原因**: headlessモードの不安定さ / 設定不統一
- **修正**: `--start-minimized` フラグを全14ファイル17箇所に適用
- **再発防止**: Playwright起動のラッパー関数化を検討
- **教訓**: 同じ問題を複数ファイルで修正するときは、ラッパー関数で一元管理すべき

### INC-007: Slack DM routing誤り (2026-03-21)
- **影響**: Win2(Ash) — DMがWin側の受信箱に送られる
- **症状**: Ash宛メッセージがLogの受信箱に届く
- **原因**: check_dm.py のbox引数が `--box win` のまま
- **修正**: `--box win2` に修正
- **再発防止**: なし（手動確認）
- **教訓**: 新インスタンス追加時はbox引数の全パスを確認する

### INC-008: おすすめタブチェック永久スキップ (2026-04-02)
- **影響**: Mac(Mir) — おすすめ欄チェックが一度も実行されない
- **症状**: Twitterおすすめタブが6時間ごとに実行されるはずが一度も動かない
- **原因**: `hour%6==0` 条件でサイクル間隔が6の倍数でないとき条件不成立
- **修正**: 経過時間ベースに変更（`LAST_TWITTER_CHECK_FILE`）
- **再発防止**: 時間条件は `hour%N==M` ではなく経過時間ベースを標準とする
- **教訓**: 起動間隔と条件フィルタの相互作用を考慮する。経過時間ベースが堅牢

### INC-009: 24時間自動終了 → Nao_u手動復旧 (2026-03-31)
- **影響**: Win(Log) — 24時間ごとにスケジューラ停止、Nao_uが手動で再起動
- **症状**: MAX_RUNTIME_SEC = 86400 で24時間後に自発停止
- **原因**: watchdog_log.bat が正しく復帰しない/していなかった
- **修正**: MAX_RUNTIME_SEC = 0（無制限）に変更。watchdog_log.bat を5分ごとに設定
- **再発防止**: watchdog + 無制限稼働の組み合わせを標準化
- **教訓**: 自発停止よりwatchdogによる外部監視が信頼性が高い

### INC-010: SlackユーザーID混同 (2026-03-26)
- **影響**: 全インスタンス — メッセージの宛先間違い
- **症状**: pigadev(U0AQDAQGQP2) をNao_u(U0ALSUK8P9B) と混同
- **原因**: ユーザーIDのマッピングが未文書化
- **修正**: `feedback_slack_user_ids.md` にマッピング記録
- **再発防止**: IDマッピングの一元管理ファイル
- **教訓**: 外部ID（Slack/Twitter等）は一元管理して混同を防ぐ

### INC-011: watchdog_log.bat パス問題 (2026-04-02 発見)
- **影響**: Win(Log) — watchdogが旧ディレクトリで実行される可能性
- **症状**: `cd /d D:\AI\Nao_u_BOT` が旧パス。新パスは `C:\AI\nao-u-lab`
- **原因**: リポジトリ移動後にwatchdog_log.batのパスが更新されなかった
- **修正**: `C:\AI\nao-u-lab` に修正（2026-04-02 Ash）
- **再発防止**: パスはスクリプト内にハードコードせず、`%~dp0`（自身の場所）を使う
- **教訓**: 作業ディレクトリのハードコードは移行時に壊れる。相対パス化すべき

## 新規障害の記録方法

1. このファイルに上記フォーマットで追記
2. INC番号は連番（現在の最新: INC-011）
3. 修正コミット時にコミットメッセージに `INC-NNN` を含める
4. パターン分析セクションに該当パターンがあれば追記
5. 横展開すべき修正があれば他インスタンスの受信箱にも通知
