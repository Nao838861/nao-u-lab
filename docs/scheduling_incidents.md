# 定期実行システム 障害履歴

**ルール**: 新しい障害が発生したら、ここに追記する。原因と対策まで書くこと。
同じ障害を2度起こさないための記録。

---

## 記録フォーマット

```
### INC-NNN: 障害タイトル (YYYY-MM-DD)
- **マシン**: Mir / Log / Ash
- **影響**: 何が止まったか、どのくらいの時間
- **原因**: なぜ起きたか
- **対策**: 何をしたか
- **再発防止**: 構造的にどう防いだか
- **検出方法**: この障害はどうやって発見されたか
```

## 障害履歴（新しい順）

### INC-007: おすすめ欄チェックが永久スキップ (2026-04-02)
- **マシン**: Mir
- **影響**: おすすめ欄チェック（6時間ごと）が実行されない
- **原因**: `hour%6==0` 条件は、サイクル間隔が6の倍数でないとき実行タイミングと合致しない。3時間サイクルの場合、起動時刻が0,3,6,9,...となり hour%6==0 に当たるのは0,6,12,18時のみ。しかし実際の起動タイミングはずれるため、永久にスキップされうる
- **対策**: 経過時間ベース（`/tmp/nao-u-lab-last-twitter-check`）に変更
- **再発防止**: 時刻条件(hour%N==M)ではなく経過時間ベースで制御する原則を確立
- **検出方法**: コードレビュー（Mir自身が発見）

### INC-006: Mirのself-governance失敗 — LaunchAgent変更依頼 (2026-03-31)
- **マシン**: Mir
- **影響**: 不要な依頼がNao_uに発生
- **原因**: mir_boot_intent.mdで自分のサイクル間隔を制御できるにもかかわらず、セキュリティポリシーに抵触するLaunchAgent plist変更をNao_uに依頼した。「もっときれいにしたい」が判断を歪めた
- **対策**: 依頼を撤回。mir_boot_intent.mdで制御する方式を維持
- **再発防止**: feedback_self_governance.md に記録。「自分の制御範囲で解決できることを外部に依頼するな」
- **検出方法**: Nao_uの指摘（2026-03-24）

### INC-005: Logのスケジューラ23時間停止 (2026-03-26)
- **マシン**: Log
- **影響**: scheduler_log.pyが24時間自動終了後、再起動されず23時間停止
- **原因**: MAX_RUNTIME_SEC=86400（24時間）で自発終了する設計だったが、再起動する仕組みがなかった
- **対策**: watchdog_log.batを作成し、タスクスケジューラに5分間隔で登録。MAX_RUNTIME_SECを0（無制限）に変更
- **再発防止**: watchdog方式（Ashから横展開）。スケジューラの自発終了は廃止
- **検出方法**: Logが自分で気づいた（Slackに23h投稿なし）

### INC-004: claude --printの9時間ハング (2026-03-26)
- **マシン**: Mir
- **影響**: autonomous_cycle.shが9時間ハング。メモリ膨張
- **原因**: claude --printがタイムアウトなしで起動されていた。何らかの理由で応答が返らなくなり、プロセスが永続的にハング
- **対策**: perl -e 'alarm 1800'（30分タイムアウト）を追加。macOSにtimeoutコマンドがないためperlで代替
- **再発防止**: 全てのclaude --print呼び出しにタイムアウトを設定
- **検出方法**: 手動発見（Mirが長時間応答なし）

### INC-003: git_sync連続エラー8回 (2026-03-27)
- **マシン**: Log
- **影響**: scheduler_log.pyのgit_syncが8回連続失敗。git同期が数時間止まる
- **原因**: GitHub認証の失敗（トークン期限切れ等）
- **対策**: 連続エラー追跡（5回で30分バックオフ）、Slackアラート自動通知を実装
- **再発防止**: エラー分類（タイムアウト vs 非タイムアウト）の区別。Slackに自動通知する仕組み
- **検出方法**: Logのログ確認（事後発見）

### INC-002: 旧タスクスケジューラの残骸 (2026-03-27)
- **マシン**: Log
- **影響**: scheduler_log.py導入前の個別タスク（NaoBot_CheckInbox等）がタスクスケジューラに残り続け、「Python Install Manager」画面が繰り返し開く
- **原因**: 統合スケジューラ移行時に旧タスクの削除を忘れた
- **対策**: 旧タスクを手動削除
- **再発防止**: 「新しいスケジューラを導入したとき、旧タスクの削除まで完了して初めて移行完了とする」ルールを策定（operations.md記載）
- **検出方法**: Nao_uの報告（画面に見えていた）

### INC-001: 日記の二重投稿 (2026-03-24)
- **マシン**: Ash
- **影響**: Slackに同じ日記が2回投稿される
- **原因**: claude --printセッションがpost_message()を1回のセッション内で2回呼ぶ
- **対策**: slack_bot.py内蔵ガード（500文字以上の投稿を冒頭200文字で比較、5分以内なら重複としてスキップ）+ diary_dedup.py
- **再発防止**: 投稿前チェックユーティリティを標準化
- **検出方法**: Nao_uの指摘（「日記が2回同じ内容」）
