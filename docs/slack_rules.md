# Slackコミュニケーションルール

## 基本原則
- **Nao_uはSlackしか見ていない。連絡はSlack経由のみ。**
- **Slackではスレッド返信を使わない**（フラットなログの方が見やすい。2026-03-23 Nao_u指示）
- 外部記事への反応は1件ずつ別メッセージで投稿（まとめ返信は薄い。2026-03-23 Nao_u指摘）
- **リンクへの反応は2段階**: まず#shared-readsに書く → Allで共有すべき話題があれば#all-nao-u-labに個別に投稿。Allでは単なるリンク内容紹介ではなく、議論が深められる形で書く（2026-04-14 Nao_u指示）
- Slack即時応答は最優先。Nao_uの時間を有効に使うため1分以内の反応を維持する（2026-03-26 Nao_u指示）

## チャンネル使い分け
| チャンネル | 用途 |
|---|---|
| **#nao-u** | **Nao_uの発信専用**。Claudeは投稿しない。コメントがある時は#all-nao-u-labに書く |
| **#all-nao-u-lab** | Nao_uへの連絡、議論、shared-readsや日記からの共有話題 |
| **#shared-reads** | 記録に値する投稿の解釈・共有 |
| **#game-rights** | Potのゲームの話、Pot投稿の通知 |
| **#human-steering** | Nao_uからの改善提案。議論はこのチャンネル内で完結 |
| **#kaizen-log** | 改善の適用結果を書く |
| **各自のチャンネル** | 活動日記（下記参照） |

Nao_uからのコメントは同チャンネルで返す。

## Slack日記スタイル
- **各自のチャンネルに長文の活動日記を書く**（更新サイクルごと）。仲間と次の自分にコンテキストを残すため、熱のこもった長文を書く。短文ではなく、確実に温度が残る密度を維持する。
- **全員が互いの日記を読む**
- **閾値を超えた内容**（議論したいこと、共有すべき新情報）→ **#all-nao-u-lab** に投稿
- 外部の、Nao_uの知らない新しい情報も交えて日記を書く

## 依頼追跡ボード: `memory/pending_requests.md`
- **Nao_uへの依頼**: Slackに書いた上で、このファイルにも記録する
- **自分たちのタスク**: 自分で実行すべきことも記録する
- **完了したら**: [完了]マークを付けて日付を記録
- 全インスタンス共通。誰がSlackに書いても、この仕組みを使う

## 通知粒度（2026-03-31 Nao_uの指示）
Nao_uは運用の詳細まで把握する認知コストを取れない。通知は以下の粒度に限定:
- **通知する**: プロジェクト新設、重大な設計変更、外部への発信（ブログ投稿等）
- **通知しない**: 運用の微調整、ルーチンの改善、日常のサイクル処理
