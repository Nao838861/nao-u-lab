## 1. 問題提起

Claude Codeを使い始めて最初に困ったのは、セッションが切れると全部忘れることだった。

昨日「テストは必ずpytestで書いて」と伝えたのに、今日また`unittest`で書いてくる。コーディング規約を毎回説明し直す。先週のセッションで「この設計にした理由」を丁寧に議論したのに、今週はゼロからやり直し。長いプロジェクトになるほど、この「毎回リセット」が重くなる。

コードベースは読めるから、ファイル構造や既存のコードスタイルはある程度推測してくれる。でも「なぜこうしたか」——設計判断の経緯や、過去に試して失敗したアプローチの記録は、コードには残らない。毎回同じ失敗を繰り返すのはAIの能力不足ではなく、単に覚えていないだけだ。

この問題を2週間かけて解いた。結論から言うと、3段階ある。

## 2. Level 1: CLAUDE.md——これだけで8割は解決する

一番シンプルで、一番効果が高い方法がこれだ。

プロジェクトのルートディレクトリに`CLAUDE.md`というファイルを置く。Claude Codeはセッション起動時にこのファイルを自動で読み込む。公式の仕組みで、設定不要。ファイルを置くだけでいい。

何を書くか。自分の場合はこんな構成になった。

```markdown
# CLAUDE.md

## プロジェクト概要
このリポジトリは○○のバックエンドAPI。Python 3.12 + FastAPI。

## コーディング規約
- テストはpytest。unittestは使わない
- 型ヒントは必須
- docstringはGoogle style

## よく使うコマンド
- `make test` — テスト実行
- `make lint` — リンター
- `make dev` — 開発サーバー起動

## 判断基準
- パフォーマンスより可読性を優先
- 外部依存は最小限に（標準ライブラリを優先）
- 迷ったらシンプルな方を選ぶ
```

これだけで、毎回「pytestで書いて」と言わなくてよくなった。コーディング規約のような「全セッションで共通のルール」は、ここに書いておけば確実に引き継がれる。

ポイントは**短く書くこと**だ。CLAUDE.mdはセッション開始時に毎回全文が読み込まれる。長くなりすぎると、重要な指示が埋もれてコンテキストウィンドウを圧迫する。自分の目安は100〜150行。「全セッションで必ず守ってほしいこと」だけに絞る。

逆に書くべきでないのは、特定のタスクにしか関係ない一時的なメモや、コードを読めばわかること（ファイル構造の説明など）。それらは次のレベルに任せる。

### Before / After

**Before（CLAUDE.mdなし）:**
```
Human: テストを書いて
AI: [unittestで書く]
Human: pytestで書いてって言ったでしょ
AI: すみません、pytestで書き直します
Human: (毎回これ…)
```

**After（CLAUDE.mdあり）:**
```
Human: テストを書いて
AI: [CLAUDE.mdの規約に従ってpytestで書く]
```

CLAUDE.mdを書くのに30分かかったとして、毎日5回の「それ前も言ったよ」がなくなるなら、半日で元が取れる。

## 3. Level 2: user memory——個人の作業メモを蓄積する

CLAUDE.mdはプロジェクト全体のルールを置く場所だ。では、「昨日のセッションで○○について調べた結果」とか「この設計にした理由のメモ」のような、個人の作業記録はどこに置くか。

Claude Codeには`auto memory`（user memory）という仕組みがある。`~/.claude/projects/`配下にプロジェクトごとのディレクトリが作られ、そこに`MEMORY.md`を置くと、CLAUDE.mdと同じように起動時に自動読み込みされる。

CLAUDE.mdとの使い分けはこうだ。

| | CLAUDE.md | user memory (MEMORY.md) |
|---|---|---|
| 場所 | プロジェクトルート | ~/.claude/projects/ |
| git管理 | される（チームで共有） | されない（個人用） |
| 用途 | プロジェクトルール | 個人の作業メモ・判断記録 |
| 読み込み | 毎セッション自動 | 毎セッション自動 |

実際の使い方として、Claude Codeに「これ覚えておいて」と言うと、自分でMEMORY.mdに書き込んでくれる。明示的に「〇〇を記憶して」と頼んでもいいし、Claude Code側が「これは覚えておいた方がいいですか？」と聞いてくることもある。

重要な制約が一つある。**200行制限**。MEMORY.mdが200行を超えると、超えた分は読み込まれない。つまり、何でもかんでも書き込むと古い記録から消えていく。

この制約への対処法が、次のLevel 3——自作の記憶ディレクトリ構造——につながる。200行の壁をどう超えるか。答えは「MEMORY.mdを索引にして、詳細は別ファイルに書く」だ。
