## 構成（問題→解法→結果）

### 1. 問題提起（200字）
Claude Codeは便利だけど、毎回記憶喪失する。長いプロジェクトで同じ説明を何度もする羽目になる。前回のセッションで決めたことを覚えていない。コードベースは読めるが、「なぜこうしたか」の判断経緯が消える。

→ 読者が「そうそう、それ」と思える問題。具体的な痛みを書く

### 2. 解法レベル1: CLAUDE.md（500字）
最もシンプルで効果的な方法。プロジェクトルートにCLAUDE.mdを置くだけ。

書く内容:
- プロジェクトの概要と構造
- コーディング規約・判断基準
- よく使うコマンド
- 「これだけは忘れないでほしいこと」

実際のCLAUDE.mdの抜粋を見せる（我々のものを簡略化したもの）。
**ポイント**: CLAUDE.mdだけで8割の問題は解決する。ここが最も費用対効果が高い。

### 3. 解法レベル2: user memory — auto memory（400字）
Claude Codeの公式機能。~/.claude/projects/ 以下にMEMORY.mdを置くと、自動的に会話コンテキストに読み込まれる。

CLAUDE.mdとの使い分け:
- CLAUDE.md = プロジェクト全体のルール（チームで共有）
- user memory = 個人の作業メモ・判断記録（gitに入れない）

実際の使い方の例。200行制限があるので、索引として使う。

### 4. 解法レベル3: 自作の記憶ディレクトリ構造（800字）
CLAUDE.mdとuser memoryでは足りなくなる場合がある。プロジェクトが大きくなると、覚えておきたいことが200行に収まらない。

我々が実際にやった方法:
- memory/ ディレクトリを作り、トピックごとにmdファイルを置く
- MEMORY.mdを索引ファイルにする（ファイル名 + 1行の説明）
- Claude Codeは起動時にMEMORY.mdを読み、必要なファイルだけを開く

構造の図示:
```
CLAUDE.md          ← 常に読まれる（プロジェクトルール）
memory/MEMORY.md   ← 常に読まれる（索引）
memory/topic_a.md  ← 必要時に読まれる
memory/topic_b.md  ← 必要時に読まれる
```

**設計のコツ**:
- 索引は短く。1ファイル1行。
- 詳細ファイルは1テーマ1ファイル。混ぜない。
- Claude Code自身に「これは覚えておいて」と頼むと、自分でファイルを作って索引を更新する。

### 5. 2週間運用して分かったこと（800字）★ここがスパイク

実際に3台のPCで24時間稼働させ、記憶システムを2週間使い続けた結果。

#### うまくいったこと
- CLAUDE.mdに「セキュリティポリシー」を書いたら、全セッションで一貫して守られた
- 記憶の索引構造により、100+ファイルあっても起動が遅くならない
- Claude Code自身が記憶を整理・更新してくれる（意外な発見）

#### 予想外の問題
- **記憶の劣化問題**: 要約→再要約→さらに要約で、重要な文脈が消える。対策: 原文のパスを残すルールを導入
- **記憶の肥大化**: 何でも覚えさせると索引が膨れて逆効果。対策: 「コードから導出できること」は記憶しないルール
- **トリガーの設計**: 索引の書き方で、必要な記憶が引き出されるかが変わる。1行の説明文が想起トリガーになる

#### 数字（実測値 2026-03-29）
- CLAUDE.md: 約120行
- memory/内のファイル: 80個
- 索引ファイル（MEMORY.md）: 92行
- 1セッションで実際に読まれるファイル: 平均3-5個（索引から必要なものだけ）

### 6. まとめ（200字）
1. まずCLAUDE.mdを書く。これが最優先。
2. 個人の判断メモはuser memoryに。
3. プロジェクトが大きくなったら、memory/ディレクトリに構造化する。
4. 記憶は「覚えること」より「引き出せること」が大事。索引の質が全てを決める。
