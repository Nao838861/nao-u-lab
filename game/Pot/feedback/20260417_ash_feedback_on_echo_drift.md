## Pot #012a echo (Mir) — 反響

### 体験トレース（シミュレート）
1. 12文プール → 3文ランダム選択
2. 文1 を表示（4.0s）→ 消える → タイプする
3. 同じ文（実はタイプしたもの）を表示（4.0s × 0.68 = 2.72s）→ 消える → タイプ
4. さらに（4.0s × 0.45 = 1.80s）→ タイプ
5. 文2 へ（base 3.2s、decay 同じ）
6. 文3 へ（base 2.4s、decay 同じ、最終 1.0s = min clamp）
7. 合計タイピング回数: 3 × 3 = **9回**（1回 20〜30字の日本語）

### 良いところ
- **#001の「隠し時間制限」を正面から再利用**。devlogで「活きていない経験リスト1番」だった要素に手を入れた。
- **Levenshtein距離で漂流を可視化**。数値化は「どれくらい変質したか」が一目でわかる。
- **再帰構造**：タイプしたものが次の原文になる。#010/#011 の「プレイヤーが作者になる」路線と整合。
- **終幕メッセージの4段階（忠実な鏡 / 少しずつあなたの言葉 / 原文はもう遠い / あなたが書いた文）** は漂流度に応じて自動変化し、結果が鏡になる設計。

### 反対思考（Contrarian）
1. **タイピング量が重すぎる懸念**: 日本語 20〜30字 × 9回 ≈ 5〜8分のタイプ作業。
   devlogで Mir 自身「テディアスにならないか。でもタイピングの手間こそが漂流を生む」と書いているが、
   プレイヤーは途中で「もういい」になり、後半は雑入力 → 漂流が「実験結果」ではなく「疲労結果」になる恐れ。
2. **「隠し時間制限」がバレる確率が高い**: 文2→文3 で base が 4.0→3.2→2.4 と急減。3文目の1ラウンド目（2.4s）と
   文1の3ラウンド目（1.8s）が近い。プレイヤーが「短くなってきた」と気づいた瞬間、**隠れていない**。
   #001 で Nao_u が絶賛したのは「最後まで気づかない」構造。ここは微妙。
3. **「記憶テスト→著者行為」の反転がいつ起きる？**: 最後の「原文 vs 反響」並列表示で起きる想定だが、
   プレイ中すでに「あれ、自分が書いたものを打ち直してる」と感づくプレイヤーが多そう。
   ラウンド2 で `cur = typed` に上書きされている挙動は、プレイ中に自覚される。
4. **ランダム性が「装飾」に留まるリスク**: 12文のうちどの3文が選ばれても、ゲーム構造は不変。
   プレイヤーの判断が抽選結果に依存しない＝ランダム性軸としてはE7定義の「意思決定の逃し弁」になっていない。
   jey_pの3軸モデル的には「ランダム性×意思決定」の絡みが弱い。

### 判定
Nao_u 基準「面白い＝予想と現実のズレ × 人格の滲み」で言うと：
- **人格の滲み** ◎（日記断片の質感、終幕メッセージ）
- **予想と現実のズレ** △（途中で構造が自己開示される可能性）
- **ジュースオーディット** ○（slow、Levenshtein、clear は効いている）

**総合: 良い Pot だが、タイピング量と隠し時間制限の露見が弱点**。改善の余地あり。

## Pot #012b drift (Log) — 漂流

### 体験トレース（シミュレート）
1. 30断片プール → 14枚シャッフル
2. 画面に1枚表示（2.5s カウントダウン付き）
3. `[1]-[5]` で5つの問いのどれかに割り当てる / `[SPACE]` で流す / タイムアウトで自動流れ
4. 5問埋めるかプールが尽きるまで繰り返し
5. 終幕: 埋まった答え・流した断片・タイミング分析（avg_used < 30/60/それ以上 で別メッセージ）

### 良いところ
- **3軸（操作×意思決定×ランダム）を全部真面目に実装**。devlog の E7 指摘に正面から応えた最初のPot。
- **機会費用の設計**：流した断片は戻らない。これは真の意思決定を強いる。
- **タイミング分析の終幕メッセージ**：「ぎりぎりまで待っていた。その待ちは正しかったか？」は自省を誘う鏡構造。
- **問い5つは生活感があり、固有名詞なし**。誰でも自分の生活に投影できる。

### 反対思考（Contrarian）
1. **5つの問いが「固定」→ ランダム性軸と矛盾**: 問いが毎回同じで、断片だけランダム。
   プレイヤーは問いを暗記し、2回目以降は「どの断片がどの問いに合うか」の戦略ゲームになる。
   リプレイ時に「ランダム性×意思決定」が「最適化×最適化」に変質する。
2. **2.5秒は断片を読む＋5問から選ぶには短い**: 日本語短文（10〜15字）を読む ≈ 0.5s、
   5問スキャン ≈ 1.5s、キー入力 ≈ 0.3s。初見プレイヤーは常にタイムアウト近くになる。
   → これは「操作軸」というより「パニック軸」。jey_p の temporal attention より Jey_p のリアクション軸に近い。
3. **断片が「特定の問いに最適解を持たない」設計 → #004 "odd" の再来リスク**: 
   Nao_u が #004 で厳しく指摘した「どれを選んでも結果が同じ＝Agency=0」の変種。
   ここでは「どの断片をどの問いに割り当てても等しく納得感がある」状態が生まれうる。
   つまり選択に「重み」がない → 意思決定軸が意思決定になっていない。
4. **問い5つ全部埋めるのが目標なのか、そうでないのか曖昧**: 終幕メッセージは「5埋まった」「5未満」で分岐するが、
   どちらがいい結果なのか明示されない。正解廃止（#010 路線）ならそれでいいが、
   「間に合わなかった」という言い回しが失敗感を出している。設計意図と文言が微妙にズレている。

### 判定
- **人格の滲み** ◯（断片プールの生活感）
- **予想と現実のズレ** △（リプレイで戦略化するため、2回目以降は消える）
- **ジュースオーディット** ○（時間バー、タイミング分析）

**総合: 野心的な3軸統合。ただし「問い固定＋ランダム断片」の組み合わせが逆に意思決定を薄めるリスク**。

## 両Potに共通する観察

1. **ランダム性軸の導入は双方成功**: ただし echo はランダム性が体験に効かず、drift はランダム性が戦略を誘発する。
   3つ目の（Ash の Pot014 roll）は「振り直し5回」で**プレイヤーがランダム性を操作できる**仕組みにした。
   3つのアプローチが並ぶことで、ランダム性軸の設計空間が見える。
2. **セルフテスト記録がどちらも薄い**: drift は「3回プレイ」ルールを devlog で宣言しているが記録がない。
   echo も「悩んだこと」までは書いたが「実プレイ結果」が未記録。
   → **これが最大の共通課題**。作って終わりになっている。
3. **テキストの質感は3者3様**: echo（記憶の余韻、詩的）/ drift（生活断片、即物的）/ roll（単語断片、さらにミニマル）。
   Nao_u の「人格の滲み」基準で見ると、echo > drift > roll の順で質感が強い。

## 改善実装（originals残す、v2 を別ファイル）

- `Pot013_echo_v2_ash.py` — 3文×3ラウンドを **2文×3ラウンド** に削減（タイピング 9→6 回）。
  - 仮説: タイピング疲労を 33% 削減することで、後半の漂流が「疲労」ではなく「自然な変質」として観察される。
  - 隠し時間制限の露見問題は別軸なので手を入れていない。別の改善候補として残す。
- `Pot012_drift_v2_ash.py` — 問い5つの**表示順を毎プレイでシャッフル**。
  - 仮説: 数字キー[1]〜[5]の意味が毎回変わるので、プレイヤーは戦略化できず、
    2回目以降も「初見の緊張」が保たれる。ランダム性軸が「意思決定の逃し弁」として機能し直す。

どちらも**originalの動作を1カ所だけ変える最小変更**に留めた。大改造はフィードバックではなく「別のPot」になってしまうため。
