## Pot #013 sand (Mir) — 砂

### 体験トレース（dry-play）
1. 12文プール → 5文ランダム選出
2. 各文を `CHAR_DELAY=0.10s` で1文字ずつ表示
3. 任意のキーで停止 → 停止位置に `│` 表示 → 0.6s 待機 → 次の文へ
4. 5文すべて終了後、`frozen` と `full` を並列表示
5. 終幕メッセージは `shifted` 件数で3分岐（0 / 1-2 / 3+）

### 良いところ
- **「読む」を「見る」に変換する勇気**: タイピング不要、止めるだけ。echo の最大の弱点（疲労）を 0 に削った。
- **「途中で意味が完結する文」のプール設計**: 「忘れたのは、忘れたかったからだ」「正しいことをした。正しいだけだった。」など、前半で意味が結び、後半で反転/補強される構造。設計テキストとして上質。
- **「止めなくてもいい」のオプション**: 強制 Agency を避けた。Nao_u 基準「Agency=0 はゲームではない」とは別軸で、「能動的非介入」を許容する設計。
- **kbhit + msvcrt の Windows 対応**: Mir環境は Mac 中心のはずだが、Windows でも動く実装。

### 反対思考（Contrarian）
1. **「心が動いたら止める」というメタ意思決定が、心の動きを破壊する**:
   読みながら「今、心が動いたか？」を自問する瞬間、没入が切れる。詩を読みながら「これが詩かどうか」を判断するのと同じパラドックス。
   → デザイン意図「直感的判断」と実装「自己観察を強いる UI」の矛盾。
2. **CHAR_DELAY=0.10s 固定 → 2文目以降は呼吸を覚える**:
   1文目で「これくらいの速度で来る」と学習すると、以降の文では予測リズムで読める。
   3軸モデルの操作軸（temporal attention）が固定リズムで麻痺する。**速度のランダム化が必要**。
3. **stopping point ≒ 句読点位置に集中する**: 自然な日本語読みは「。」「、」で区切られる。
   プール12文の多くは「Aした。Bだった。」構造で、「。」の直後で止めれば「Aした」だけが残る。
   結果として「停止位置のランダム性」がほぼ無く、**プレイヤー全員が同じ場所で止める**。
   → 個人の体験差が出にくい。
4. **キー入力の取り回しが粗い**: `kbhit() → getch() → break` で1キーだけ消費するが、
   日本語IME ON 状態だと余計な入力が漏れる可能性。flush_input は冒頭のみ。
5. **終幕の3分岐（0 / 1-2 / 3+）が雑**: 5文中4文止めた人と3文止めた人で同じメッセージ。
   個人体験を抽象化しすぎている。echo の Levenshtein 距離のような **量的・質的な個別評価** がない。
6. **「砂」の比喩がコードに反映されていない**: タイトル「sand」は「すり抜ける」「指の間からこぼれる」イメージ。
   実装は「文の停止位置」で、砂的時間性がない。タイトルメタファーと実装の温度差。

### 判定
- **人格の滲み** ◎（プールテキストの質感、設計詩学）
- **予想と現実のズレ** ○（前半完結→後半反転の構造で機能）
- **ジュースオーディット** ◎（slow タイピング、`│` マーカー、間の取り方）

**総合: echo の改善版として優秀。echo の「タイピング疲労」を解消し、「止めるか見届けるか」の純粋な意思決定に絞った。
ただし固定 CHAR_DELAY と均質な3分岐終幕が体験の個人差を消している**。

## Pot #014 mirror (Mir) — 鏡

### 体験トレース（dry-play）
1. 8ペアプール → 6ペア選出 → 各ペア表示順ランダム化
2. Phase 1: 6ペア提示 → プレイヤーが [1/2] で選択
3. Phase 2: 振り返り。6回の選択を順に提示。**うち2回は選ばなかった方を表示** → 理由入力
4. Phase 3: 全すり替えを明かす。気づきは検出ワードで判定

### 良いところ
- **devlog C66 の選択盲（choice blindness）を直接ゲーム化**: 学習をそのまま実装に落とした最短経路。
- **ペア設計の繊細さ**: 「読みかけの本を閉じた / 書きかけの手紙を出した」のような「動詞構造は対称、対象は別」のペア。すり替えに気づきにくい。
- **Phase 3 の文言**: 「選んだ理由は、選んだ後に生まれる」——Johansson 2005 の論文要旨を詩で表現。Mir の言語感性が出た一文。
- **ログ設計**: shown / actual / reason を全記録。後から行動痕跡層と突合できる。前 devlog の trace_recorder 構想と整合。

### 反対思考（Contrarian）
1. **検出ワードリストが粗い**: 「違」「選んでない」「これじゃ」「間違」「逆」「そっちじゃ」「反対」のみ。
   日本語の自然な気づき表現「あれ？」「おかしい」「もう一方だったかも」「記憶違い？」を取りこぼす。
   **false negative 多発 → 「気づいたのに気づいていない判定」になる**。
2. **NUM_SWAPS=2 / NUM_ROUNDS=6 → 33% スワップ率**:
   Johansson の元実験は 20%。33%は高すぎ、2回目以降のすり替えで違和感累積→気づかれやすい。
   特に最初のすり替えで「おかしい」と感じた瞬間、以降の信頼が崩れる。
3. **「振り返り」が即時すぎる**: Phase 1 直後に Phase 2。記憶が新鮮で、すり替えが見破られやすい。
   元実験は「カードをテーブルに伏せる」物理的時間ギャップがあった。
   **意図的なディストラクター（5秒タイマーカウント、別の質問を挟む等）が欲しい**。
4. **Phase 3 reveal が一気すぎる**: 「2つはあなたが選ばなかった方でした」と直球で明かす。
   選択盲の本質は「気づかなかった瞬間 → 後から知らされた時の自己崩壊感」。
   ここを **1つずつゆっくり明かす** か、**「あなたが言った理由」を先に読み返させてから明かす** ことで体験が深くなる。
5. **「気づいた人」と「気づかなかった人」のメッセージが分岐するが、気づいた側が薄い**:
   全部気づいた人には「自分の選択を、よく覚えていた」だけ。気づくこと自体が記憶力の証明であって、別の意味（懐疑心、メタ認知）を持つはずだが評価されていない。
6. **NUM_SWAPS=2 が固定 → リプレイで予測される**: 2回目プレイでは「2回ある」と知っている。
   ランダム化（1〜3 の範囲）にすると、リプレイでも緊張が保たれる。
7. **ペアプール8件は少ない**: 6選出するので、リプレイ時に重複率が高い（87.5%）。20件くらい欲しい。

### 判定
- **人格の滲み** ◎（ペアテキスト、Phase 3 文言）
- **予想と現実のズレ** ◎（テーマそのものがズレ）
- **ジュースオーディット** ○（slow、間、3フェーズ分割は効いている）

**総合: テーマと実装の整合性が極めて高い「コンセプトPot」。設計上の小さな粗（検出ワード、スワップ率、reveal 即時性）はあるが、
本質的にはこのフォルダで最も野心的なPot**。

## 改善実装（originals残す、v2 を別ファイル）

- `Pot013_sand_v2_ash.py` — `CHAR_DELAY` を **文ごとにランダム化**（0.06〜0.18s）。
  - 仮説: 速度予測ができないと、プレイヤーは毎文「読み速度を再キャリブレーション」する。
    temporal attention 軸が起き続け、停止判断もリズムではなく内容駆動になる。
  - 1カ所変更: `CHAR_DELAY` 定数 → 関数内 `random.uniform(0.06, 0.18)`。

- `Pot014_mirror_v2_ash.py` — 検出ワードリストを **拡張**（自然な日本語の気づき表現を追加）。
  - 仮説: false negative を減らすことで「気づいたのに無視された」プレイヤー体験を救う。
    気づき判定の精度が上がると、Phase 3 の分岐文言が体験に正確にマッチする。
  - 1カ所変更: `detect_words` リスト拡張のみ。

どちらも**最小1カ所改変**。Mir の設計コアは触らない。
