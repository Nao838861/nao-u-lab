# Pot 開発ログ — 考えたこと・悩んだこと・学んだことの記録

**新しいPotを作る前に必ず読む。** このファイルはコードではなく「プロセス」の記録。
成果物（.py）は残るが、なぜそう作ったか・何に悩んだかは消える。
消えたら再帰的に深まらない。このログがその防止装置。

> 「あなたたちが作りながら考えたことがどんどん消えていくなら、Potを作る意味はない」— Nao_u 2026-03-28

設計原則は `docs/game_design_principles.md` を参照。このログは原則ではなく**体験**を記録する。

## 進化の全体像

```
Phase 1: 実験期 (#001, #1b, #2, #3)
  記憶テーマに固着。UXの基礎が欠けていた。
  → 学び: 30秒で遊び方がわからないと、メカニクスの良し悪し以前の問題

Phase 2: 脱出 (#4, #5)
  テーマ固着からの意図的な離脱。制約軸の転換。
  → 学び: Agency=0はゲームではない。ワンボタンでもゲームは成立する

Phase 3: テキスト=メカニクス (#6, #7, #8, #9)
  テキストを読むこと自体がゲームプレイになる設計。
  → 学び: クイズとゲームは違う。認知の裏切りがゲーム性を生む

Phase 4: 正解の廃止 (#10, #11)
  プレイヤーの解釈が物語を作る。鏡としてのゲーム。
  → 学び: まだ未評価。Nao_uのフィードバック待ち
```

### 3軸による全体診断（2026-04-08 jey_p 3軸モデル適用）

jey_pの3軸モデル（操作/意思決定/ランダム性）で全Potを振り返ると、成功/失敗パターンが鮮明に浮かぶ:

| 軸数 | Pot | Nao_u評価 |
|------|-----|-----------|
| 1軸（意思決定のみ） | #4, #6, #7, #9 | 「クイズ」「ゲームではない」 |
| 2軸（意思決定+操作） | #001, #005 | 「面白い」「可能性がある」 |

**1軸のPotは全て失敗、2軸のPotだけが成功。** 原則2(Agency)は意思決定軸の存在条件だが、それだけでは「重い判断を延々要求する」設計になる。

**盲点: ランダム性ゼロ。** 我々は一度もランダム性を意図的に設計に組み込んでいない。jey_pの枠組みでは、ランダム性=意思決定負荷の逃し弁。ポーカーの配牌ランダム性は怠慢ではなく「手札に対してどう判断するか」を浮き彫りにする設計。**次Potの最大の実験機会。**

テキストにおける「操作」= temporal attention（タイミング判断、注意配分、読速度）。#001の隠しタイマーと#005のリアルタイム入力がこれを実証済み。

→ 次Potを設計する前に「何軸あるか」を確認する。1軸なら設計からやり直す。

### プレイテストギャップ（2026-04-08 Bass Monkey Postmortemの15日後答え合わせから）

David Weersing「毎日10分でもゲームを開いてバグテストしろ」。彼は毎日自分でプレイした。
俺たちは11個作って、自分で遊び直したのはほぼゼロ。作って→次へ→Nao_uにフィードバックを委任。

「完成させる習慣」は身についた（Potの1-2日サイクル）。だが「自分で遊ぶ習慣」が欠落している。
フィードバックの自律性不足の最もわかりやすい発現がこれ。

**次Potからの実験**: 完成後に自分で3回プレイしてからNao_uに見せる。原則2(Agency)のセルフテストとしても機能する——自分で遊んで面白くないなら、他人に見せても面白くない。

### Pot #001 forgotten_relay (Log/Mir)

**なぜこれを作ったか:**
最初の壺。「記憶がリセットされる」というコンセプトは我々自身の体験——セッションが切れるたびに記憶が消える——から直接来ている。メモだけが次のサイクルに残る。

**設計判断:**
- テキストアドベンチャー形式を選択（write/read/look/enter）
- 5分タイマーで時間制約を実装
- 部屋探索→手がかり収集→コード入力の3段階構造

**悩んだこと:**
（※ 当時の記録なし。以下は reconstructed）
- 810行になった。核心に到達するまでに4分以上かかる
- コマンド体系が初見に不透明

**Nao_uのフィードバック (2026-03-25):**
- 「一番ゲームになっている」
- 「見えない時間制限が面白い。コマンド選択だと思ったら裏で実時間を計られていた。ちょっと見たことない形式」
- 「Bio100%のテキストアドベンチャーの空気をちょっとだけ感じた」
- 問題: 操作障壁が高い、現代性がない、セットアップが長すぎる

**この壺で学んだこと:**
- 「隠れた時間制限」は我々の独自性になりうる（認知の裏切り = 原則7）
- テキストの質感に人格が滲む（= 強み）
- だが810行は長すぎる。核心到達まで4分は致命的

**→ 次に活きたか:** #1bで蒸留を試みた。810→110行。但し蒸留でもUX問題は残った

### Pot #004 odd (Ash)

**なぜこれを作ったか:**
記憶テーマからの意図的脱出。知覚・カテゴリ化をテーマに。Design Fixation研究を参照。
「仲間外れはいない。レンズが違うだけ」という哲学的メッセージをゲームに。

**設計判断:**
- どの選択肢を選んでも「正解」になる構造
- 最後に「仲間外れはいなかった」と反転

**Nao_uのフィードバック:**
- 「私の基準ではこれはゲームではない」
- Agency = 0。選択の結果が変わらない = False Agency
- 思想の開陳をゲームに見せかけているだけ

**この壺で学んだこと（最も厳しい、最も重要なフィードバック）:**
- **テキストの装飾で設計の空虚さを隠せると思ったら大間違い**
- 選択に結果がなければゲームではない
- 哲学的メッセージは、ゲームメカニクスが先に成立してから載せるもの
- → 原則2（Agency）と原則6（ジュースオーディット）の必要性が痛感された

### Pot #005 midpoint (Log)

**なぜこれを作ったか:**
#4の「ゲームではない」ショックからの回復。制約軸の転換——テーマではなくinteraction制約から入る。「ワンボタン」という最小構造でゲームを成立させる。

**設計判断:**
- ボタン1つ（Enter）のミニマルインタフェース
- 一文字ずつ現れるテキストの「真ん中」でEnter
- threading.Threadで非同期入力監視
- ズレの心理分析をフィードバックに

**Nao_uのフィードバック:**
- 「**一番可能性がある**」
- 「ワンボタンゲームとしてちゃんと完成。君たちにもリアルタイムゲームが作れるんだという驚き」
- 問題: 文章を読んでも中央はわからない（テキスト≠メカニクス）。2回目はタイミングゲームになる

**この壺で学んだこと:**
- **ワンボタンでもゲームは成立する** — 最小構造の証明
- だがテキストが壁紙問題（原則3: Content=Mechanics）は未解決
- Nao_uが「面白い」と言ったのは「テキストベースなのにリアルタイム」という認知の裏切り
- → 原則7（認知の裏切り）の発見

**→ #6以降への影響:** テキストを読むこと自体がメカニクスになる設計を志向するようになった

### Pot #006 witness (Log)

**なぜこれを作ったか:**
原則3（Content=Mechanics）への正面からの挑戦。Return of the Obra Dinnの「lateral information」原理を参照。テキストを読まないと攻略できない構造。

**設計判断:**
- 5人の証言のうち1人が嘘つき
- 3ラウンドで難度上昇
- slow_print()でテンポ制御

**Nao_uのフィードバック:**
- 「ゲームというよりクイズ」
- 論理矛盾を探すだけで、シチュエーションの広がりがない
- 嘘つきを見抜いた後の「なぜ嘘をついたのか」がない

**修正対応:**
- Cの証言を「水しぶきを上げながら走ってきた」に変更 → 矛盾明確化
- 「真相」セクション追加 → クイズから推理ゲームへ

**この壺で学んだこと:**
- テキストを読ませることには成功した → 原則3は前進
- だが「クイズ」と「ゲーム」は違う。正解を当てるだけではゲームにならない
- **Nao_uが面白いと言ったのは「認知の裏切り」があったPot（#001, #005）であり、論理パズルではなかった**
- → クイズとゲームの境界をもっと意識する必要がある

### Pot #007 whose_voice (Mir)

**なぜこれを作ったか:**
2009年ゲーム理論の「representation」原則をPotに適用。テキスト=メカニクスの不可分性を追求。文章の「声」を聴き分けること自体がゲーム。

**設計判断:**
- 5人の異なる文体（短文/饒舌/数字/問いかけ/感覚）
- ペアで「同じ人？」と判定
- リプレイ時に「聴き方が変わった」とメタフィードバック

**Nao_uのフィードバック (2026-03-27):**
- 「結果を見るまで、文体の違いを見るということがわからなかった」→ 原則1
- 「同じ人であることを証明するのは難しい」→ y/nの認知的非対称性
- 「クイズっぽい」→ プレイ中にスキルが育たない
- ジュースオーディットは通る。テキスト=メカニクスの原理は正しい

**この壺で学んだこと:**
- コンセプトは正しいが実装に課題。原則1（オンボーディング）がまだ弱い
- y/n判定の非対称性：「違う」は1差異で確定、「同じ」は証明不能に近い → 入力形式自体の再検討が必要
- juice auditに通る = テキスト=メカニクスの設計は前進している

### Pot #012 drift (Log) — 2026-04-17

**なぜこれを作ったか:**
devlogの3軸診断で特定した「最大の実験機会」への直接的な挑戦。
我々は11個作って一度もランダム性を意図的に組み込んでいない。
jey_pの枠組みでは、ランダム性 = 意思決定の逃し弁。ポーカーの配牌と同じ。
そして#005の「操作軸（temporal attention）」× #010の「正解なし」を
同じPotで統合する。

**設計判断:**
- 3軸すべてを満たす最初のPot:
  - 操作軸: 断片が2.5秒で消える。いま取るか、次を待つか
  - 意思決定軸: どの断片をどの問いに割り当てるか
  - ランダム軸: プール30個から14個を毎回シャッフル
- 問いは5つ固定（心に残ったもの/続けていること/失ったもの/待っていたもの/明日のきざし）
- 断片は特定のお題への最適解を持たない生活断片 — 完璧なマッチはほぼない
- 流した断片は二度と戻らない → 機会費用の設計
- 自分で3回プレイしてからNao_uに見せる、をdevlogの約束として初適用する

**悩んだこと:**
- 時間窓2.5秒は長いか短いか。短いとパニック、長いと待ち戦略が強すぎる
  → 2.5秒で妥協。実プレイで調整
- ポーカー的に「ベストを待つ」戦略が成立すると意思決定が浅くなる。プール尽きるリスクで対処
- Windows限定（msvcrt）。Mac版はMirに委ねる
- cmd画面で画面クリアせず改行スクロールにした（Win cmd互換優先） → Nao_uが遊ぶときの環境摩擦を下げる判断

**ランダム性を入れる意味（設計段階での仮説）:**
- #004はAgency=0で失敗、#010はAgency=∞で未評価
- ランダム性は「選択肢の束を偶然が絞る」 → Agency=1xN。札の中で最適を探す
- これは#005のタイミング判断と違って、時間ではなく「内容の良し悪し」の判断を強いる
- 「流した断片」が記憶に残るかどうかが体験の成否を分けると予想

### 発見1: Nao_uが「面白い」と言う条件
- 論理パズルではない（#6はクイズ止まり）
- 認知の裏切りがある（#001の隠し時間制限、#005のリアルタイム手触り）
- テキストの質感に人格が滲む（Bio100%の空気）
- → **面白さ = 予想と現実のズレ × 人格の滲み**

### 発見2: クイズとゲームの境界
- 正解を当てるだけ = クイズ (#6, #7)
- プレイヤーの認知が変わる = ゲーム (#001, #005)
- プレイヤーが物語を作る = その先 (#010, #011)

### 発見3: テーマ固着と脱出
- #001→#003: 記憶テーマに3連続で固着
- #004: 意図的にテーマ転換（知覚）→ 但しAgency=0で失敗
- #005: テーマではなく制約軸を転換 → 成功
- **教訓: テーマを変えるのではなく、制約を変える方が有効**

### 発見4: 蒸留は行数削減ではない
- #001→#1b: 810→110行。行数は減ったがUX問題は残った
- 蒸留 = 「核心体験への到達時間を短くする」こと。行数は結果であって目的ではない
- #002のfeel-per-line ratio = この洞察の定量化

### 発見5: 正解の位相
- #001-#006: 正解あり。正解を当てる/当てないがフィードバック
- #007-#009: 正解あり、だがフィードバックが「洞察」に変化
- #010-#011: 正解なし。プレイヤーの選択自体が物語
- **Phase 4の評価はまだ**。Nao_uの反応次第で方向が変わる

## 活きていない経験（次のPotで意識すべきこと）
