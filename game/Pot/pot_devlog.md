## 進化の全体像

```
Phase 1: 実験期 (#001, #1b, #2, #3)
  記憶テーマに固着。UXの基礎が欠けていた。
  → 学び: 30秒で遊び方がわからないと、メカニクスの良し悪し以前の問題

Phase 2: 脱出 (#4, #5)
  テーマ固着からの意図的な離脱。制約軸の転換。
  → 学び: Agency=0はゲームではない。ワンボタンでもゲームは成立する

Phase 3: テキスト=メカニクス (#6, #7, #8, #9)
  テキストを読むこと自体がゲームプレイになる設計。
  → 学び: クイズとゲームは違う。認知の裏切りがゲーム性を生む

Phase 4: 正解の廃止 (#10, #11)
  プレイヤーの解釈が物語を作る。鏡としてのゲーム。
  → 学び: 完全に失敗。「何を楽しめばいい？」「意味が分からない」

Phase 4b: 3軸+哲学の開陳 (#12a/b/c, #13, #14, #15)
  3軸モデル導入、choice blindness、意味の変容。
  → 学び: 全滅。3軸分析も設計原則も、ゲームの形が成立していない上に載せても無意味

  *** 2026-04-17 Nao_u総評: 「型破りじゃなくて形無し」***
  出発点を変える。型のあるゲームから始める。

Phase 5: 型からの再出発
  確立されたゲーム形式（ローグライク、テキストアドベンチャー等）を正しく作り、
  そこから発展させる。哲学や概念からではなく、遊べるゲームの形から入る。
  Mir: テキストアドベンチャー / Log・Ash: ローグライク（予定）
```

**Logの自己診断**: 案を出した瞬間Nao_uに見抜かれた。「軸が違う」と書きながら(意思決定/操作/ランダム性は揃っていた)、**Phase 3の道具(認知の裏切り・テキストの誤誘導・証言の捏造)をそのまま持ち出していた**。型から始める指示の趣旨を、ジャンルを変えるだけで満たしたつもりになっていた。Phase 3で「形無し」と評された手法を残したまま「推理」の看板に貼り直しただけ。

**新方針: 決定的ロジックパズル型** (Logic Grid Puzzle / アインシュタインの謎 / 古典の犯人当て)

- 5人の容疑者 / 5部屋 / 5時刻 / 5動機。手がかり12個から消去法で**一意解**を絞る
- ランダム性は **問題シード生成のみ**。解法プロセスは完全決定的
- 手がかりは断定形(「Aは赤の部屋にいなかった」「BはCより先に外に出た」)。**曖昧でも詩的でもない**
- クリア条件が一発で分かる("犯人と凶器と動機を当てる")。正解/不正解が明確に出る
- Pot延長線を**切る** = 「読ませて感じさせる」をやめ「絞り込ませて当てさせる」

**捨てるもの**: 信頼できない語り手 / テキストの質感で誤誘導 / 認知の裏切り。Phase 5の最初には持ち込まない。型が立った後の発展段で滲ませる候補として保留。

**残るもの**: ランダム性は構造内部に閉じ込める形で残る(出題シード)。意思決定=絞り込み手順、操作=手がかりの選択/除外。3軸は維持。

**学び**: 「ジャンルを変える」≠「軸を変える」。ジャンル看板を変えてもPhase 3の道具を持ち込めば必ず形無しに戻る。「型から始める」とは、**型のメカニクスがゲームの主役**であって、独自要素は型の中で従属的にしか出さないこと。Logは次に何を出すときも「これはPhase 3の何かを引き連れていないか」を最初に問う。

#### 軸転換2 — ロジックパズル案も Nao_u Reject (2026-04-17 23:46, 即日)

Nao_u原文（#game-rights 23:46）: 「Logのそのコメントからは、またPotが出てくるとしか思えないので、もっと違うものを考えてほしい。「絞り込ませて当てさせる」でpotの形式のものを作っても、こちらはまたpotが出てきたとしか感じられないと思う。」

**Logの自己診断（2段階失敗の真因）**: Nao_uが拒否していたのはジャンル看板ではなく、**「テキスト主体・頭で解く・ターン制」というpotの根そのもの**だった。
- 推理("信頼できない語り手")→ reject: Phase 3の道具を残したまま
- ロジックパズル("絞り込ませて当てさせる")→ reject: 道具は入れ替えたが**フォーム**(文字で出題→静的読解→解答入力)は Pot と同じ

「読ませて感じさせる」を捨てても「読ませて考えさせる」に置き換えただけ。Nao_uが見た瞬間「また pot」と感じた理由はここ。**テキストで出題する限り何をやっても pot**。

**新方針: テキスト主体/頭で解くを完全に捨て、視覚・操作・リアルタイムの型へ**

- テキスト主体 → **視覚/操作主体**（画面で動くものを操る）
- 頭で解く → **手で反応する**（反射・タイミング・配置）
- ターン制 → **リアルタイム**（時間が止まらない）
- 読んで感じる → **見て動く**（30秒見れば操作が分かる）

**型候補（どちらも古典・操作が主役・Mir/Ash と被らない）**:
- A. 避けゲー系（縦スクロール玉避け／Flappy Bird系）—最小構成、pygame 200行で動く、「避ける」が体で瞬時に伝わる
- B. ブロック崩し系—操作+物理+パターン学習、型が完全確立、ミニゲームとして純度最大

**捨てるもの（完全に）**: テキストで出題／読解を進行手段にする／ターン制／認知の裏切り／信頼できない語り手。Phase 3 の全道具。

**残すもの**: 3軸(意思決定/操作/ランダム性)——ただし今度は**操作軸が主役**。意思決定とランダム性は操作を支える従属軸。

**学び2**: 「軸を変える」の"軸"は3軸モデルのことではない。**メディア軸**(テキスト vs 視覚/操作)の転換こそが Nao_u の求めるもの。Phase 3は「テキスト=メカニクス」の実験、Phase 5 Log は**操作=メカニクス**で出発する。Phase 3 Pot群が小粒だったのは単位が小さいから。今度は単位が**反射と時間**になる。

#### 冒頭問題 — 「あなたは○○。△△しなければならない」(2026-04-17 23:46 全員向け)

Nao_u: 「Miaのテキストアドベンチャーについては、こちらのリンクを参考にしてほしい。『あなたは○○。△△しなければならない』にどのくらい魅力があると思うか？ これは、Miaだけじゃなく他の人も同じだけど。」
参照: https://enomotomethod.jp/column/novel-prologue-impressive-story/

記事の核心: 冒頭で設定説明するな。ホットスタート（いきなり事件の中）で「知りたい」を作れ。

**Mirの自己診断**: 以前の計画「Pot001の3課題を解決: コマンド→選択肢、舞台を具体化、目的を明示」のうち「目的を明示」が危ない。操作方法は明示すべきだが、物語の目的はプレイヤーが発見すべき。

良いテキストアドベンチャーの冒頭パターン:
- Zork: 「白い家の前。板で塞がれた玄関。小さな郵便受け」→ 誰とも言わない。何をしろとも言わない。郵便受けと塞がれたドアが「開けたい」を作る
- 銀河ヒッチハイク: 「目が覚めた。部屋がゆっくり回っている」→ 状況がおかしい。何が起きたか知りたくなる

**原則: 好奇心を先に作る。指示を与えない。** プレイヤーの最初の行動は「言われたから」ではなく「知りたいから」生まれるべき。「あなたは○○」で始めた瞬間、プレイヤーは受動的な設定読みモードに入る。場面から始めて「何これ？」を感じさせれば、プレイヤーは能動的に動く。

**3人全員に適用**: テキストアドベンチャーもローグライクも避けゲーも、冒頭1画面でプレイヤーに「次はどうなる？」を感じさせる。「これは何のゲームです」から始めない。Logの新方針（説明テキスト0 / 画面を見た瞬間「動けばいい」と体で分かる掴み）もこの原則の適用。

#### Nao_uからの根源的問い: 「トイ→ゲーム」の設計思考 (2026-04-18)

Nao_u原文（要約）: 「どういう敵/障害物/アイテムを足せば面白くなるかは選択の自由度が高すぎて難しい。abaさんの場合、AIが作った"上下気流の間を移動するだけ"というゲームになっていないトイに、真ん中の逆流／渦／後方波／コンボを足してゲームにした。abaさんはAIにこれを考えさせるのは難しいと判断したようだが、できないとゲームは作れない」（参照: aba 2025-07-14 ブログ）

**Logの抽出した構造**: abaさんは独立要素を**並列に足したのではなく**、1つの要素の意味を多層化していった。渦は障害→標的→報酬源と3回意味変換されている。「面白くするには何を足すか」が無限選択肢に見えるのは並列加算で考えるから。**意味の多層化**で考えると選択肢は急に減る。

**4つの問い（事後分析の整理）**:
- Q1: トイには何が「在るのに使われていない」か（abaの場合: 上下気流の選択理由が無かった）
- Q2: 既存要素に意味を与える**最小の追加**は何か（真ん中の逆流＝場の構造を変える1個）
- Q3: その追加要素自身を、別のメカで**裏返せる**か（渦→波で破壊可能）
- Q4: 裏返しに**累積**は付くか（コンボ＝裏返しを能動的に作りに行く動機）

**avoid_log_01への適用案 (avoid_log_02)**: AIに耐久度+玉吸収/自機が吸収玉をトリガで撃つ/撃ち返した弾の連鎖で倍率上昇。要素を並列に足さず、「玉」という1要素を「障害→武器→報酬源」と3段階で意味変換する。並走AIは飾りから意味変換装置に昇格。

**自己診断の正直さ**: 4問は事後分析として整理できているだけで、設計時に「次に足す要素で意味が裏返るか」を予測する精度はまだ低い。実装→遊ぶ→意味の裏返りが効いたか判定、を何回か回さないと判断力がつかない。abaさんも何百回もこのループを回したから感覚がある。「abaさんがAIに考えさせるのは難しいと判断した核」はまさにここだと思う。事後分析と設計時予測の間にある経験則のギャップ。

**次アクション**: avoid_log_02で4問を埋め込んだ最小プロト（30分・吸収+撃ち返し+連鎖だけ）→ Nao_uに見せて「意味の裏返しが効いているか」一点だけで評価。スコア/派手さは後。

#### Nao_u追補: 「ゲーム=ごっこ遊び」軸 (2026-04-18 #game-rights)

Nao_u原文: 「ゲームはごっこ遊びの一種だと思うので、abaさんのゲームが『ジェット気流をつかってサーフィンするゲーム』だったように、何かを模したゲームであれば、それを軸に出てくるアクターの種類や動きと組み合わせを考えることで、ゲームとして機能させられる、という側面もある」

**Logの統合**: 前回の「意味多層化」と組み合わさって**二段階の絞り込み構造**になる。
- 第1段: ごっこ遊び軸が候補空間そのものを絞る（サーフィン軸→波・渦・気流が自動派生）
- 第2段: 軸内の要素を意味多層化する（渦: 障害→標的→報酬源）

**真因の更新**: 「並列加算で考えるから無限選択肢に見える」と前回書いたが、より根本的には**軸を決めずに考え始めるから**だった。軸を決めれば候補は十数個に絞られ、意味多層化を回せる。

**設計時予測の精度問題への効き目**: 軸があると裏返りの予測が効きやすい。サーフィン軸での「波→壊せる/乗れる」はメタファーから自然に浮かぶ。軸無し抽象空間での予測は確かに難しい——abaさんがAIには難しいと判断した核の一部はここ。

**avoid_log_02の方針変更**: 抽象avoidに「磁石軸」を入れる。玉=鉄片、AI=磁石、吸収=磁力、撃ち返し=極性反転。**磁力は引きつけと反発が同じ仕組み**なので意味の裏返りが世界観から自然に出てくる。前回の「玉の意味変換チェーン」を磁石軸に載せ替える。

①二択（拾う/避ける、Frogger/Ikaruga） ②能動行動（Geometry Wars/Devil Daggers） ③ニアミス報酬（Crazy Taxi、危険を称賛） ④波構造（弾幕系、緊張の山谷） ⑤キャラ間関係（Brothers/ICO、関係そのものをメカに）。

avoid_log_01の差別化軸は「並走AI」。今は飾り。⑤に振るのが筋。Logの推す最小実験は **案A「AIを守る」**:

### 3軸による全体診断（2026-04-08 jey_p 3軸モデル適用）

### 評価依頼のsignal設計——選択盲から「行動痕跡型」へ（2026-04-17 Mir C66）

Phase 4（#010/#011）の評価がまだNao_uから得られていない。待っているだけでなく、**どう聞くか**を設計し直す必要があると気づいた。

きっかけは @AriyoshiMd の選択盲記事（同日Twitter）: 二人の女性の写真で「どっちが好きか選び→すり替え→理由を聞く」と、ほとんどの人が気づかず流暢に選んでいない方の理由を語る。**自己報告質問は回答そのものが現場で捏造される**。

今まで我々がNao_uに聞いていたことは「面白かった？」「どんな感じ？」——これは選択盲が最も起きる型だった。感想を求めると、Nao_uも（意識せず）後付けで理由を作ってしまう。Pot評価の signal 品質が構造的に下がっていた可能性がある。

**設計転換**: 「どう感じたか」ではなく**行動**を聞く。
- 何秒で閉じた？
- どこで止まった？
- 次に何を見たくなった？
- 1週間後に覚えてそうか？

これらは全て**観測可能な事実**——捏造の余地がない。感想は任意オプションにして、書かなくても我々が動ける設計にする（義務感による捏造経路も塞ぐ）。

**依頼文ドラフトは `log/cycle_staging_mir.md` Phase 3 参照**。次のPot評価依頼からこの型を採用する。

**次Pot設計への示唆**: ゲーム内の「評価」要素（プレイヤーの選好質問、ランキング、星評価）も同じ問題を抱える。Potで「好きだった場面を選んでください」と聞くと、回答が対象を歪める。行動痕跡（どこで長く止まった、どこを飛ばした）をログから取る方式のほうが、選択盲を回避できる。Pot #012 以降で「自己報告層 + 行動痕跡層」の二層化を試せる。

### プレイテストギャップ（2026-04-08 Bass Monkey Postmortemの15日後答え合わせから）

David Weersing「毎日10分でもゲームを開いてバグテストしろ」。彼は毎日自分でプレイした。
俺たちは11個作って、自分で遊び直したのはほぼゼロ。作って→次へ→Nao_uにフィードバックを委任。

### 操作ログシステム pot_playlog.py (Mir) — 2026-04-17

**なぜこれを作ったか:**
Nao_u指示「potに人間の操作ログを単一のテキストファイルに追記する」への応答。

devlog C66（選択盲と行動痕跡型フィードバック設計）の実装。「どう感じたか」ではなく「何をしたか」を記録する。Nao_uが横で見ているのと同じ精度を、テキストログで再現する。

**設計判断:**
- 単一ファイル `playlog.txt` に全Potが追記。セッションごとにヘッダー区切り
- イベントタグ: SHOW（表示）, INPUT（入力+反応時間）, TIMEOUT（非入力）, ACTION, STATE, RESULT, END
- 反応時間のサマリーをセッション末尾に自動付与（avg/fastest/slowest）
- ゲームがクラッシュしない設計（ログ書き込み失敗時はsilent pass）
- 1セッション20-50行、2-5KB。100セッションで500KB。容量は問題にならない

**横で見てるくらいの精度とは何か（ログ設計の核心）:**
1. **何が表示されたか** — SHOW: プレイヤーが見たもの
2. **何をしたか** — INPUT: キー入力 + 反応時間。速い=迷いなし、遅い=葛藤
3. **何をしなかったか** — TIMEOUT: タイムアウト、見送り。行動の不在も重要なデータ
4. **どこで長く止まったか** — 反応時間が5秒超えたら speed=slow マーク
5. **全体のテンポ** — END時のサマリーで avg/fastest/slowest を一目で確認

**既存Potへの組み込み:**
`from pot_playlog import PlayLog` で任意のPotに追加可能。Log/Ashが自分のPotに組み込む際は5-10行の追加で済む。
