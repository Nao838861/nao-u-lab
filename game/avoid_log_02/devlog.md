## 軸の決定: 磁石（ごっこ遊び軸・Nao_u追補適用）

Nao_u 2026-04-18「ゲーム=ごっこ遊び」を受けて、抽象avoidに軸を入れる:

- AI = 磁石

- 撃ち返し = 極性反転

**軸のメタファーから意味の裏返りが自然に出る**。磁力は引力と反発が同じ仕組み。1つの軸で3段階の意味変換が派生する。

## 意味多層化 3段（abaさんの4問埋め込み）

Q1: 在るのに使われていない = avoid_log_01の鉄片（降ってくるだけ）  
Q2: 最小の追加 = 磁力場（AIが鉄片を引き寄せる）  
Q3: 裏返し = 極性反転（SPACE で撃ち返し）  
Q4: 累積 = 撃ち返しが別の鉄片に当たるとチェイン + スコア倍率  

- **段1 障害**: 上から降ってくる鉄片。プレイヤーに当たると死
- **段2 武器**: AIの磁力場に入った鉄片は吸引され、AIに吸収される（AI absorb meter）
- **段3 報酬源**: プレイヤーが SPACE を押すと、AIが吸収した鉄片を極性反転して撃ち返す。撃ち返し弾が別の鉄片に当たる → 連鎖 → スコア倍率

## 死の意味変換 3種

pot_devlog avoid_log_01フィードバック自己診断の「死後の意味変換」をそのまま実装:

### AIの死 = 吸収鉄片の一斉解放
AIが鉄片を `absorbMax` 以上保持すると `overload` で崩壊。死んだ瞬間に吸収していた鉄片が**全方位爆発**。環境変化であって、罰でも報酬でもない。プレイヤーは爆発弾を避ける新しい局面に入る。

### プレイヤーの死 = AIを見届ける
プレイヤー死時、AIが生きていれば「AIがどこまで生き延びるか、見届けろ」を表示し、AIは磁石として機能を続ける。**プレイヤーが死んでも画面が退屈にならない**。avoid_log_01の「片方が死ぬ＝差分停止」を潰す設計。

### 両者死亡後 = 死因マーカー
終了画面に「you死因: 鉄片で死 / AI死因: 吸収過多で崩壊」を明示。軌跡だけでなく**死の因果**を残す。

## 2026-04-20 事後分析 — 「ヘッドレス✅ ≠ 面白い」の発見

### 何が起きたか

v1（磁石と鉄片・初版）→ v3（現在）の改修過程で、**ヘッドレスAIテストの✅を達成することに最適化した結果、実際のプレイ体験を大幅に悪化させた**。

Nao_uのプレイ後フィードバック（原文は nao_u_live.md 参照）:
- 「どういうプレイを意図しているゲームデザインになっているかがわからなくなった」
- 「全体としてかなりマイナスな方向に動いた」
- 「何もできないゲームになった感覚」

### 問題の個別分析

**問題1: AI付近の鉄片減速（drag 0.88-0.96）→ 鉄片がAI-プレイヤー間に滞留して壁を作る**

- 意図: 磁力場内を「安全な場所」にしてconceptの生存を伸ばす
- 実際: 鉄片が減速して横方向にゆっくり動く → AIとプレイヤーの間に入ると避けようがない壁になる
- 根本原因: **数値の上では「遅い弾は避けやすい」だが、プレイヤー体験では「横に動く遅い弾は進路を塞ぐ」**。ヘッドレスAIは1次元（左右移動）でしか判断しないので、2次元的な「挟まれる」体験を検知できなかった

**問題2: 弾幕激化 → 「やることが単調」**

- 意図: SPACEを押さないと弾幕に飲まれる構造を作り、dodgerを殺す
- 実際: 弾が多すぎて避けるだけで精一杯。SPACEで弾を消しても次が来る。「対処に追われる」体験
- 根本原因: **弾幕密度を上げることは「SPACEの価値を上げる」ではなく「全ての行動の価値を下げる」**。プレイヤーが何をしても状況が改善しない感覚

**問題3: AIの撃ち返し弾が当たりづらい**

- 意図: 直接的に意図したわけではない。弾速上昇+鉄片減速の複合結果
- 実際: returned弾が飛んでもiron弾が遅くて散っているので当たらない。SPACEを押しても「何もできない」
- 根本原因: **改修Aの鉄片減速と、改修Bの弾幕激化が互いに打ち消している**。鉄片が遅い（→散る）のに数が多い（→密度感だけある）= 「当たりはするが消しても無意味」

**問題4: ヒットボックス縮小（磁力場内で×0.45）→ 隠しパラメータ**

- 意図: 磁力場内にいるメリットを作る
- 実際: プレイヤーが知覚できない。「なぜか当たらなかった」が「磁力場内にいるから」とは結びつかない
- 根本原因: **プレイヤーが体感できないルールは存在しないのと同じ**。game_design_principlesの「30秒オンボーディング」に完全に反する。良いルールは「見ればわかる」か「やればわかる」。ヒットボックスの変化は「やっても分からない」

### メタ的な教訓（3人全員の今後のゲームデザインに適用）

**M-10: ヘッドレス✅は「バランス」を測るが「面白さ」は測れない**
ヘッドレスAIは「どの戦略が有利か」を測定する道具であって、「その戦略で遊ぶことが楽しいか」は測定しない。✅が出てもプレイ体験が悪化することがある。ヘッドレスは必要条件の検証であって十分条件ではない。

**M-11: 「問題を潰す」改修は対処療法の積み重ねになる**
dodgerを殺す → conceptも被害 → compensateで隠しパラメータ → 別の問題 → また対処…。各改修が「1つの問題を潰す」ために入れられ、全体としての遊び体験を誰も見ていなかった。改修の度に「この変更でプレイヤーは何を感じるか」を問うべきだった。

**M-12: 罰ではなく報酬で設計せよ**
dodgerを「罰する」（弾を集中させる、誘導する、激化する）より、conceptプレイを「楽しくする」（撃ち返しが気持ちいい、連鎖が派手、磁石軸を使うと強くなる感覚）方が正しい。罰ベースの設計はプレイヤーに「やらされている」感覚を与える。

**M-13: 隠しパラメータはゲームデザインとして悪手**
プレイヤーが知覚できないルールは、プレイヤーの判断材料にならない。「磁力場内でヒットボックスが小さくなる」は数値的に機能しても、プレイヤーが「磁力場内にいた方がいい」と体感できない。ルールは「見ればわかる」か「やればわかる」。

**M-14: 改修を重ねる前に「このゲームで一番楽しい瞬間は何か」を言語化せよ**
avoid_log_02の場合、意図していた一番楽しい瞬間は「AIが吸った鉄片をSPACEで撃ち返して連鎖が起きる」瞬間。改修の結果、その瞬間が「弾が当たりづらくなった」「速すぎて連鎖が見えない」で潰されていた。改修が核の体験を守っているかを常にチェックすべき。

### 改修の取り消し判断

v3で入れた以下の改修は**撤回候補**:
- [撤回] AI付近の鉄片減速 → 壁を作る悪影響が利点を上回る
- [撤回] ヒットボックス縮小 → 隠しパラメータ、プレイヤーが体感できない

- [維持] SPACE-gated supercharge → dodger対策として構造的に正しい
- [維持] piercing supercharge → 画面掃除の気持ちよさに繋がる可能性
- [維持] リプレイ記録+分析基盤 → インフラとして有用

## 2026-04-20 v2.5 人間プレイテスト — 3度目の「ヘッドレス✅ ≠ 人間体験」

Nao_u原文: 「なんか全く機能してないような？下の赤い点が何かわからない。AIに近づくと敵の軌道が変わるのではなれると安全、無限によけ続けられる。AIが死んでも関係ない。ゲームが機能していない。連鎖とか地雷とかってあるのかないのか全くわからなくて機能していない。」

### 個別分析

**問題1: 地雷が「存在しない」**
- 赤い点(5px)は「地雷」と認識できない。触れる前にiron弾で死ぬので地雷で死ぬ体験自体が発生しない
- プレイヤーの行動圏（上半分）と地雷の位置（最下部）が離れすぎ
- **教訓: メカニクスは「初めて触れる瞬間」がなければ存在しない。理論上存在するルールと体験として存在するルールは別物**

**問題2: 磁力場 = 危険地帯（v1から未解決の構造問題）**
- AIの吸引で鉄片が集まる → 近づくと密度UP → 離れる方が安全
- v1で指摘され、drag/ヒットボックス/誘導/弾幕激化/地雷と5世代の対症療法を積んだが、全て失敗
- **根本原因: 「磁力場に近づくメリット」が体感できない。数値的メリット（バリア、連鎖）はあるが、人間は磁力場に近づかないのでそのメリットに到達しない**

**問題3: SPACEの効果が見えない**
- 撃ち返し弾が当たる確率が低い。当たっても小さいスパーク。バリアもわからない
- ヘッドレスではARC 97%だが、それはAI近くにiron弾が密集している状態でSPACEを押すから。人間は場外にいるので当たらない
- **ARC指標の盲点: 「concept AIがSPACEを押す条件」と「人間がSPACEを押す条件」が違う**

**問題4: AIが死んでも関係ない**
- 場外にいるプレイヤーには、磁力場消失はむしろ楽になる（鉄片が集中しなくなる）

### メタ分析: 因果の逆転

**全ての改修が「プレイヤーが磁力場内にいる前提」で設計されていた。**

地雷→「SPACEで消さないと溜まる」→ でもプレイヤーは場外にいるのでSPACEを押さない
バリア→「連鎖するとバリアが付く」→ でもプレイヤーは場外にいるので連鎖しない
過充電→「満タンでSPACE押すと画面掃除」→ でもプレイヤーは場外にいるのでSPACE押さない

**因果が逆**: 「磁力場内にいたくなる仕組み」を先に作るべきなのに、「磁力場内にいる前提のメカニクス」を先に積んでいた。

### ヘッドレステストの精度問題（M-10深掘り）

concept AIは「磁力場内にいるべき」とプログラムされている。人間は「なぜ磁力場内にいるべきか」を体験から学ぶ。この差をヘッドレスは検出できない。

**必要な新しいテスト**: 「naive AI」— SPACEの使い方を知らない、磁力場の意味を知らない、ただ避けるだけのAIが、プレイ中に「磁力場に近づいた方がいい」と学習できるか。学習できないならゲームデザインが機能していない。

→ ただしこれは強化学習的アプローチで、実装コストが高い。現段階では「naive AIでも避けるだけで長生きできるかどうか」= dodgerテストで代替。

### 根本の問い

**「なぜプレイヤーは磁力場に近づきたくなるのか」**

この問いが解けないと、何を追加しても機能しない。

考え中の方向:
- **磁力場がプレイヤーにも引力を与える**: 近づくとスコアが勝手に増える？ → M-13抵触（体感できない数値）
- **磁力場内でしか避けられない弾がある**: 場外限定の脅威？ → 罰ベース（M-12違反）
- **SPACEの効果を劇的に上げる**: 撃ち返しが画面全体を掃除する？ → 体験の「初回接触」が必要
- **そもそも「避けゲー」のフレームを捨てる**: 磁石と鉄片の関係を「避ける/避けない」ではなく「集める/撃つ」のサイクルゲームとして再設計する？ → **検討不足のまま提案した。「機能する理由」を聞かれて答えられなかった。同じ問題（AIの近く＝危険）が残る可能性が高い**

### バリアルールの分析（Nao_u 2026-04-20 フィードバック3）

「連鎖→バリア」は5段の「わからない」が積み重なった愚策だった:
1. 連鎖の定義を知らない
2. 連鎖が起きたことに気づかない
3. バリアが付いたことに気づかない
4. バリアの効果がわからない
5. バリアが切れたことに気づかない

**撤回。** バリアは即座に外す。

**新しい教訓 M-15/M-16** を game_design_principles.md に記録済み:
- M-15: パッチの複雑さは元の問題より悪い。コアメカニズムでない限り複雑なルールを追加するな
- M-16: 改修提案時の必須質問 —「プレイヤーは画面上の何を見てこの変化に気づくか？」「気づいた時、何をすべきだとわかるか？」。答えられないなら入れない

### 現在地の正直な評価

avoid_log_02は「磁石と鉄片」の核仮説を持っているが、その核仮説が体験として成立する形にできていない。8回の改修を経て、成立しなかった理由は徐々に明確になってきた:

**磁力場に近づく直感的な理由がない。** これが全ての問題の根。ここを解かずにメカニクスを足しても無駄。

次にやるべきこと: バリアを外し、「磁力場に近づきたくなる理由」を1つだけ、M-15/M-16の基準を通した形で考える。考えてから実装する。

## 2026-04-20 セッション全体の振り返り

### 試みの時系列
1. ヘッドレスdodger問題 → drag/hitbox/弾幕激化/スポーン集中 → ✅ → 「全体がマイナス」
2. 全撤回v2.5 → 体験品質復元 → dodger再発
3. バリア+地雷 → 「わからないものを重ねた」
4. AI死=ゲームオーバー → SPACEの動機OK → remote問題発見
5. 磁力場内限定SPACE → field 100%達成 → 近くで避けられない+一括消去が気持ちよくない+SPACE連打ゲー化

### 全試みに共通する構造問題

**「AIの吸引が鉄片をプレイヤーの居場所に集める」がゲームの最大の矛盾。**

磁石メタファー: 磁石は鉄を引く → AIの周りに鉄片が集まる
ゲーム性: プレイヤーはAIの近くにいてほしい → でもAIの近くは鉄片が多くて危険

この矛盾の上にどんなルールを積んでも、「近くは危険」が消えない限り同じパターン（問題A→対処→問題B→対処→…）に嵌まる。

### 学んだメタ教訓（M-10〜M-17に追加）

**M-18: メタファーとゲーム性の衝突に気づけ**
「磁石は鉄を引く」は物理的に正しいが、ゲーム的には「プレイヤーの居場所に危険を集中させる」を意味する。メタファーの正しさ≠ゲームの面白さ。メタファーがゲーム性と衝突している場合、メタファーの方を曲げるか、ゲーム性の定義を変えるか、どちらかの判断が要る。

**M-19: 1つの問題を潰すたびに別の問題が生まれるなら、構造が間違っている**
