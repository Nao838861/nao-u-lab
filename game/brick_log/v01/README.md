## 重心（先出し）

**落ちかけたボールをパドルで救って跳ね返す → ブロックを削る → クリア** の Breakout 最小ループ。**外発緊張**（落下軌道に向かうボール）が起点。罰駆動なし、自発リスクのコア化なし（M-30 / feedback_self_risk_core_pitfall.md 反映）。

## Q-H シート（feedback_shu_first_clone_baseline.md 準拠・必須）

### Q-H-1: 何の型か

**Breakout / Arkanoid 型**（パドル + ボール + 破壊可能ブロック群、画面下端で失敗）。1979年から続く既知ジャンル、ルールはほぼ標準化。

### Q-H-2: クローン元の参照ゲーム

| タイトル | 発売年 | 何が面白いとされているか |
|---|---|---|
| **Arkanoid (Taito)** | 1986 | **第一参照**。Breakout 改善型として要素が豊富（パワーアップ、多段ブロック、マルチボール、ボス DOH）。派生検討の種が多い。Nao_u 2026-04-28 21:34 #game-rights メソッド指定 |
| Breakout (Atari) | 1976 | 型の最古層。パドル位置→跳ね返り角度の物理が直感的、ブロック消去の連続が達成感。Arkanoid の前提として参照 |
| Alleyway (任天堂) | 1989 | パドル当たり位置で角度可変、ステージ構成バラエティ。GB 携帯機実装の代表参考 |

第一参照を Arkanoid 1986 に切替（C145 内、Nao_u メソッド受領）。Slack #game-rights 投稿（2026-04-28 21:55 ts=1777383149.363069）で良16／悪18＝計34項を列挙済み。

### Q-H-3: 一般的要素（型の本体）

**v01 で実装する Arkanoid 共通要素（必須・型の核）:**

1. **パドル左右移動**: 矢印キー / WASD / マウス / タッチで画面下のパドルを左右へ移動
2. **ボール反射 + パドル当たり位置で角度変化**: 中央=垂直、端=斜め（Slack 良#1）
3. **ブロック破壊（多段含む）**: ボールがブロックに当たり残耐久 -1。色/段/硬度差で得点差（Slack 良#3）
4. **失敗条件**: ボールが画面下端を通過したらライフ -1（初期 3）。ライフ 0 でゲームオーバー
5. **クリア条件**: 全ブロック破壊で次面 / 勝利

**Arkanoid 拡張要素（v01 では未実装、v02 以降検討）:**

- パワーアップカプセル（Slack 良#4）／マルチボール（良#5）／レーザー（良#6）／エキスパンド（良#7）／キャッチ（良#8）／ステージレイアウトの個性（良#9）／ボス DOH（良#10）／敵キャラ侵入（良#16）

これらが揃って初めて「Arkanoid クローン」と呼べるが、v01 は **Arkanoid 共通要素5項** を最低限とし、拡張要素は v02 以降に1つずつ載せる（守破離の守、独自要素は別枠で1つだけ＝Q-H-4）。1つでも v01 必須5項が欠けたら M-35 違反。

### Q-H-4: 独自要素（**1つだけ**）

**「裏抜けカウンタ」**: ボールがブロック群の **裏側** に回り込んでいる時間帯（ブロック群の上半分以上を一度通過した状態）を UI 上部に弧状ゲージで表示し、その状態中の連鎖破壊数を倍率表示する。

- 表示のみ。**ゲーム機構には介入しない**（パドル幅変化、追加ライフ、特殊弾などは v01 では追加しない）
- 「ボールが裏に回り込んで連鎖破壊する瞬間がコア快感」という Arkanoid の構造的な見どころを言語化＆強調する装置（Slack 良#2「裏抜け時の連鎖快感」の可視化）
- **どの悪を治す手段か**: Slack 悪#4「裏抜けの再現性が低い／学習しにくい」＋ 悪#13「上達の実感が遅い」の交点。裏抜け状態の可視化で「今この状態が良い瞬間だ」を学習素材化する。Slack 投稿（2026-04-28 21:55）の「自己観察」末尾参照
- 出典: GameDev.net "Breaking Out of Breakout"（2026-04-28 Phase 1 §6 外部検索で取得、独自要素検討候補として参照、kaizen #106 内容強制利用禁止条項を遵守し devlog 1行メモから採用）
- **Q-H-6 への自己回答**: 機構非介入＝型破壊しない。型のうえに載る装飾＋計測装置として位置づく

### Q-H-5: 一般要素 vs 独自要素 の比率

**v01: 5 : 1**（Arkanoid 共通5項 / 独自要素 1項 = 約 83% : 17%）。

- v01 では Arkanoid 拡張要素（パワーアップ／マルチボール／レーザー等）を入れない。守の段階で「型の核」だけを動かしてから、v02+ で拡張要素を1つずつ載せる
- BACKLASH (Mir、唯一閾値超え) の比率分析は task_assignment.md で別タスク化中（feedback_shu_first_clone_baseline.md L57-62）。**比率上限基準は分析完了まで仮置き**
- shot_log v01（Log の前作 STG）が「敵+弾+撃破+被弾+ライフ + Backlash 機構（撃破でゲージ蓄積→BOMB）」のおおむね 5:1〜6:1 だった（実装後の体感、未数値化）。それと同等で「独自に膨らみすぎない」自己制限とする
- 数値はクローン土台が動いた後（v01 完成時）に再測する

### Q-H-6: 独自要素は型のうえに載るか、型を破壊するか

**型のうえに載る**（破壊しない）。

- 機構変更ゼロ。物理パラメータ・スコア計算・失敗条件は古典 Breakout のまま
- 「裏抜けカウンタ」は **観察 UI**（プレイヤーの行動を見て可視化する装置）。プレイヤーの操作可能性は変えない
- 破壊判定の自己審問: 「この独自要素を外したら Breakout として遊べるか?」→ **Yes**（むしろ 100% 遊べる）。これが「型の上に載る」基準
