## 快感審問（feedback_pleasure_element_first 必須・冒頭3行ブロック）

- **一番嬉しい瞬間**: ボールがブロック群の裏側に回り込んで、上端で跳ね返って **裏から3-5個を連鎖破壊する瞬間**。BACK x3 / x4 のポップアップが連続して出る視覚体験。
- **それを支える操作**: パドル左右1軸のみ。当たり位置で角度を変えて、上段の薄い列を1点突破する角度を作る。
- **30秒以内の手数**: SPACEでサーブ → パドル左右で5-10回反射 → 端列を3個くらい削って隙間を作る、までが30秒の目安。

**外発緊張**。落ちかけたボール（重力ではなく等速だが、画面下端に落下軌道）を、プレイヤーが救わないと失敗する。「死にたくない→パドル動かす→生存」の典型的な外発緊張ループ。自発リスク（ボーナス目当てに危険な角度を作る）はコア化していない。M-30遵守。

### 独自要素「裏抜けカウンタ」の実装（Q-H-4）
- 「ブロック群の重心ライン（生存ブロックの y 中心平均）」を `blocksMidY()` で算出、毎フレーム再計算（破壊が進むにつれ動的に下がる）
- ボールがその線より上にいる時 `state.backside=true`、UI 上端の弧 + ボール色変化（白→金）で可視化
- backside 中の連鎖破壊数を `backCombo` として表示、breakingbest を `backComboBest` で記録
- パドル接触で必ず解除 → 「裏に行って戻ってくる」の往復が単位
- 機構非介入（パドル幅・スコア計算・失敗条件は古典 Breakout のまま、Q-H-6 守の段階）

### 設計の自己ツッコミ
1. **「裏抜けライン」の動的計算は v01 で過剰では？**: 初版は `blocksMidY()` = 生存ブロックの y 中心平均で計算したが、ブロックを削るほど線が下がる → 中盤以降「ほぼ常時 backside」化のリスクに気づき、即座に **`blocksTopY()` = 生存ブロックの最上段 y** に変更（実装直後の判定変更1件目）。これで「ボールが全ブロック群より上＝真に空白ゾーンにいる」だけが backside に。「裏抜け」という日本語の素朴な意味（ブロックの裏に回り込む）に近づいた。self-playtest で「裏抜け」発生頻度が体感に合うかを確認。
2. **罰駆動になっていないか**: 裏抜けは「気づき装置」=>>体験の言語化。プレイヤーが「裏抜けを目指さないと損」と感じる構造になったら feedback_pull_not_force_reading 違反 → 機構介入のフラグ。v01 は機構ゼロなので OK のはず。
3. **「勝ったテストプレイ警告」(feedback_won_playtest_is_kusoge)**: self-playtest で「面白い！」と感じたら、(a) 数値（クリアタイム短縮等）が改善しただけか (b) 快感審問3行ブロックの「一番嬉しい瞬間」が実際に出ているか、を分けて検証する。

### ヘッドレス自己評価（コード読み・C147 で実施）

feedback_role_split_playtest.md「我々=判断実装+ヘッドレス自己評価」の範囲で、コード読みのサニティチェックのみ実施。「面白いかどうか」の判断はここでは出さない（M-15遵守）。

**観察軸 (a) 古典 Breakout として最低限遊べるか — コード上の整合**
- パドル左右移動 / ボール反射 / 当たり位置で角度変化 (±60°) / ブロック多段破壊 (hp 1〜3) / ライフ 3 / 全破壊で CLEAR — 実装あり、明らかなロジック欠落なし。
- 速度保持: パドルヒット時 `Math.hypot(b.vx,b.vy)` を保ったまま角度を再計算、ブロックヒット時は `b.vx/b.vy` の符号反転のみで速度加算なし。**速度ドリフトなし**。
- パドル抜け: BALL_R=5 / vy_max ≈ 4.2px/frame / paddle.h=8 / paddle.y=580。1フレームでの最大移動はパドル厚を抜けない（4.2 < 8+5）。**トンネリングしない**。
- 多重ブロック衝突: `break` で1フレーム1ブロックに制限、左右両面同時ヒットで反射方向が暴走しない。

**観察軸 (b) 裏抜けカウンタが「気づき装置」として機能するか — 機構非介入の確認**
- `state.backside` が機構（パドル幅・ボール速度・スコア倍率・失敗条件）に**介入していない**。介入は (1) UI 弧の色 / ボール色 (2) `popup('BACK x'+state.backCombo)` の表示 (3) `backComboBest` のスコア外集計、のみ。Q-H-6「型のうえに載る」遵守。
- 介入していないため「裏抜け状態を目指さないと損」を**コード上は強制していない**。プレイヤー体感がそうなるかは実プレイ要。
- 弧 + ボール色変化(白→金) + `BACK!` ポップアップ + `BACK x N` 連鎖表示の **4チャネルで通知**。4本目(`BACK x N`)が「最も嬉しい瞬間」の言語化と直結。

**観察軸 (c) 独自要素を削除しても遊べるか — 守破離の守確認**
- `state.backside` / `backCombo` / `backTime` / `backCount` / `backComboBest` の参照箇所を全削除しても、コア update/draw ロジックは独立して動く（衝突解決・スコア・ライフ・clear 判定は backside 変数に依存しない）。
- 機構非介入のため Q-H-6 の自己審問「外したら遊べるか」→ **Yes（コード上）**。実プレイ感覚での確認は cross_review に委ねる。

**観察軸 (d) 一番嬉しい瞬間が実際に発生する頻度 — 構造的可達性**
- 「裏抜け」発火条件: `state.ball.y < blocksTopY()`。`blocksTopY` は生存ブロック最上段 y（破壊が進んでも下がらない、最上段が削れて初めて下がる）。
- BR_GAP=2px、BALL_R=5px。**ブロック行間にボールは挟まらない**（gap < 直径10px）。つまり「裏抜け」状態に入るには、ある列で **6段全て破壊して縦トンネルを開通させる**必要がある。各列 hp 合計 = 1+1+1+2+2+3 = **10ヒット**。
- 1列開通 → ボールが上端まで通り抜け、上壁反射 → 戻る間に隣接列の上段ブロックを下面から破壊 → これが **「BACK x N」** の発火源。Arkanoid 系の古典「トンネル抜け」体験そのもの。
- **構造的に可達**だが、1列開通までの 10ヒット = ボール往復 10回以上 = 体感数十秒〜1分程度。v01 で「30秒以内に発生」は厳しい可能性。Nao_u の快感審問3行ブロック「30秒以内の手数: 端列を3個くらい削って隙間を作る、までが30秒の目安」と整合（30秒で**裏抜けまで到達**ではなく、**裏抜けへ向かう手応え**まで）。
- **要検証 (cross_review 観察軸)**: トンネル開通までの体感時間。20分プレイで一度も裏抜けしないなら、独自要素が体感されない＝feedback_pleasure_element_first 違反候補。

### コード読みで気づいた懸念3点（実プレイで否定 or 肯定したい）

1. **サーブ角度が浅い (`-90°±14°`)**: ボールがほぼ真上に飛ぶ。パドル動かさないと真下に戻る → 「同列を当たり続ける退屈ループ」が初期に発生する可能性。Arkanoid 系の古典（Breakout 1976含む）でもこの問題はあるが、ここでは ±14° で振れ幅が小さく、パドル位置補正の必要性が低い。
2. **HP=3 最上段が硬い**: トンネル開通の律速段階。10ヒットのうち最上段の3ヒットが最後に残る確率が高い（最上段は最後に到達するため）。クライマックス前の停滞が長い可能性。守の段階で hp 配分は古典的、変えない判断は M-35 遵守だが「v01 退屈リスク」要観察。
3. **初手 SPACE が3用途 (START / SERVE / RETRY)**: 直感的だが、game over 直後に SPACE 連打すると `unlockT=120 frame=2秒` ロックがあるため再スタート遅延。RETRY 文言も unlock 後にしか出ない。ここは feedback_pull_not_force_reading の「読まないと進めない構造」に触れない（待てば出る）が、実プレイで「3秒の沈黙」を取れるかは要観察。
