## v01 凍結を踏まえた v02 の起点

v01 (裏抜けカウンタ) は ★1「裏抜けの再現性化」を **最小事後可視化版** に降格させた選択だった。理由は「v01 は独自要素1つ最小単位 = 機構非介入の事後可視化、★1 強化は v02 で」と階段化したこと。Nao_u 直指摘 (03:01) で確定:

- **「最も筋が良いと判断した案を v01 で実装する」が原則**。最小化＝弱体化として後送する判断は誤り
- ★1 は **「角度視覚化＋軌道予測」** が本体であって「裏抜けカウンタ」は本体ではない
- 「初見でもスーパープレイ」を可能にするガイドラインを Breakout 系で初めて入れる試みとして独自性十分

→ v02 では ★1 を本体として正面実装する。事後可視化（カウンタ・BACK!）は **不採用**（v01 で全否定済）。

## 重心（先出し・更新）

**落ちかけたボールをパドルで救って跳ね返す → ブロックを削る → クリア** の Breakout 最小ループ（v01 と同一）。
**コア快感**: 裏抜け = ブロック群の上端を抜けて上から連鎖破壊。
**v02 の独自要素**: 裏抜けの **再現性化** = 「自分が起こした」と認識できる学習可能な技術への変換。

外発緊張（落下軌道）が起点。罰駆動なし、自発リスクのコア化なし（M-30 / feedback_self_risk_core_pitfall.md 反映継続）。

## 仕様候補一覧（M-36 批判レビュー対応）

各仕様候補は「角度視覚化」「軌道予測」「視野ノイズ」「狙う操作との連動」の4軸で評価する。

### Spec A: 反射角プレビュー線（パドル直上常時表示）

**実装**: パドル中央〜端に沿って、現在のパドル位置で当たった場合の出射角を半透明矢印 or 短い線として常時表示。ボール飛行中も継続。

| 観点 | 評価 |
|---|---|
| 角度視覚化 | ◎ 連続表示で位置→角度が直結 |
| 軌道予測 | △ パドル直上の短い矢印のみ、その先は不明 |
| 視野ノイズ | △ 常時表示でやや邪魔 |
| 狙う操作連動 | ○ パドル動かすと矢印も動く |

**懸念**:
1. 「常時表示」が pull_not_force_reading 違反候補（ガイドを読まないと損する構造化）
2. 矢印の先が出ないので「裏抜けまで届くか」は脳内処理依存

**M-36 解決可能性**: 1=不明（常時表示の害は実プレイ依存）、2=不可（矢印短いなら届かない）。

→ **不採用**。「短い矢印」が ★1 の射程を満たさない。

### Spec B: 接触瞬間〜次反射までの軌道予測線（事後ヒント）

**実装**: パドル接触の瞬間に、出射角に従って次の壁/ブロックヒットまで薄い線を表示（0.3-0.5秒）。

| 観点 | 評価 |
|---|---|
| 角度視覚化 | △ 結果のみ |
| 軌道予測 | ○ 1反射まで線で見える |
| 視野ノイズ | ◎ 接触瞬間のみで最小 |
| 狙う操作連動 | ✗ 結果可視化のみで「狙う」フェーズには関与しない |

**懸念**:
1. 結果表示なので「狙って通す」を学習可能にしない
2. 「自分が起こした」確認装置にはなるが、再現性化は脳内処理依存

**M-36 解決可能性**: 1=不可（事後可視化は v01 と同根の罠）。

→ **不採用**。「狙う」フェーズに事前情報を提供しないなら ★1 の核心を満たさない。

### Spec C: 連続軌道予測（次1-2反射）

**実装**: ボール飛行中、現在の進行方向から次の壁/ブロック/パドル衝突点までを薄い線で連続表示。パドル接触後の出射角もパドル位置に応じて事前計算→次衝突点まで延長。

| 観点 | 評価 |
|---|---|
| 角度視覚化 | ○ 軌道線で間接表現 |
| 軌道予測 | ◎ 1-2反射まで完全可視化 |
| 視野ノイズ | ✗ 線が画面を埋める |
| 狙う操作連動 | ◎ パドル動かすと予測線も動く |

**懸念**:
1. 視野ノイズ大（線だらけ）
2. 「ボールがどこに行くか予想する」楽しさが消失する可能性
3. ガイド ON で楽しい / OFF で楽しくない（ガイド依存）になり得る

**M-36 解決可能性**: 1=可（薄さ・短さ調整で緩和、ただし「次1反射のみ」に絞ると Spec B と同等に劣化）、2=不明（予測する楽しさは予測しない楽しさと同居できないかも）、3=不明（実プレイ判定）。

→ **採用候補**（次1反射のみに絞る、視野ノイズ抑制設計が必須）。

### Spec D: パドル本体に角度メーター（縦縞マーキング）

**実装**: パドルに 3-5 本の薄い縦縞を入れ、各縞の位置で出射角を視覚的に示す（中央=垂直、端=±60°）。線で出さず、パドル本体を情報装置化。

| 観点 | 評価 |
|---|---|
| 角度視覚化 | ◎ 位置→角度が直接読める |
| 軌道予測 | ✗ 軌道線なし、ブロック群との衝突点は脳内処理 |
| 視野ノイズ | ◎ パドル本体への統合で画面に追加情報なし |
| 狙う操作連動 | ◎ パドル動かすと縦縞も動く |

**懸念**:
1. パドル見た目変化で「ごちゃごちゃ」リスク
2. 軌道予測なしで裏抜け狙いに足りるか不明（Nao_u が言う★1の半分）
3. 「角度メーター」が pull_not_force_reading 違反候補（読まないと角度わからない）

**M-36 解決可能性**: 1=可（縦縞数3本に絞る、薄いアルファ）、2=不明（D 単独で射程足りるかは実プレイ判定）、3=可（パドル本体は元々視認対象、追加読書負荷なし）。

→ **採用候補**（最小最強、racing line 直接対応の最小版）。

### Spec E: パドル接触直前の予測線（タイミング限定）

**実装**: ボールがパドルに接近して残り 0.3-0.5秒以内になったら、現在のパドル位置で接触した場合の次反射軌道を予測線で表示。それ以前は表示なし。パドルを動かすと予測線も動く。

| 観点 | 評価 |
|---|---|
| 角度視覚化 | ○ 予測線で間接表現 |
| 軌道予測 | ◎ 1反射まで明示 |
| 視野ノイズ | ○ 接触直前のみで限定的 |
| 狙う操作連動 | ◎ パドル動かすと予測線も動く |

**懸念**:
1. 0.3-0.5秒のウィンドウが「狙う」操作のリアルタイム性を保てるか
2. 1反射のみで裏抜け（3-4反射先）が予測できない
3. ボール接近時のみ発火＝発火前は情報ゼロ＝学習素材にならない

**M-36 解決可能性**: 1=可（タイミング調整）、2=不可（1反射限定）、3=不明（D と組み合わせれば常時情報＋直前予測の二段構え）。

→ **採用候補**（D との組み合わせ前提、単独では裏抜け予測に届かない）。

### Spec F: 軌道トレイル（過去軌道のみ）

**実装**: 予測ではなく過去軌道を半透明で残す。

| 観点 | 評価 |
|---|---|
| 角度視覚化 | ✗ 結果のみ |
| 軌道予測 | ✗ なし |
| 視野ノイズ | ◎ 過去のみで邪魔最小 |
| 狙う操作連動 | ✗ 連動なし |

→ **不採用**（Nao_u 言う「事前ガイド」の趣旨に反する、racing line 対応にならない）。

採用候補は Spec D / Spec E / Spec C（次1反射のみ）。これら3案について「予測可能な懸念」を全面展開し、解決可能性を判定する。

### 候補1: Spec D 単独（パドル角度メーター）

**懸念リスト**:
- 懸念1: パドル見た目が「ごちゃごちゃ」になる
  - 解決可能: 縦縞 3 本に絞る、薄いアルファ（0.3）、地味な色（白系）
- 懸念2: 軌道予測なしで「裏抜けまで届くか」が脳内処理依存
  - 解決可能性: **不明**（D 単独の射程は実プレイで判定）
- 懸念3: 「縦縞を読まないと角度がわからない」が pull_not_force_reading 違反候補
  - 解決可能: パドル本体は元々視認対象、追加読書負荷なし。縦縞は「位置の幾何」として直感認識される（数字を読む形式ではない）

**判定**: 懸念2が不明。M-36 厳格なら捨てだが、Nao_u 言う「やってみないとわからないのでやってみる価値がある」=「不明懸念は実プレイ価値あり」と Nao_u が事前明言した範疇。**採用可能**だが、D 単独では ★1 の「軌道予測」要素が欠けているため、Nao_u 趣旨を半分しか満たさない。

### 候補2: Spec D + Spec E 組み合わせ（パドル角度メーター + 接触直前予測線）

**懸念リスト**:
- 懸念1: 視野ノイズ二重化（パドル本体 + 接触前線）
  - 解決可能: D=パドル本体に統合、E=接触瞬間 0.3秒前 = 重なりなし、視野上の独立
- 懸念2: D だけで足りるなら E は冗長
  - 解決可能: D で「位置→角度」、E で「角度→次衝突点」と機能分担、両者は学習段階が異なる（角度を学ぶ→軌道を学ぶ）
- 懸念3: ガイド ON で楽しい / OFF で楽しくない（ガイド依存になる）
  - 解決可能性: **不明**（実プレイ判定対象、Nao_u 言う「やってみる価値」範疇）
- 懸念4: 「予想する楽しさ」が消えるか
  - 解決可能: E が「接触直前 0.3秒のみ」発火、それ以前のボール飛行は予測情報なし → 予想フェーズは保存される
- 懸念5: 1反射しか予測しない場合、裏抜け（3-4反射先）はやはり脳内処理
  - 解決可能: D で角度を読む→「この角度で打てば 3反射目で裏に抜ける」を脳内シミュレート→ E で「次1反射」が事前可視化されて確認できる、の二段階。これが「学習可能な技術」になる経路

**判定**: 懸念3が不明。Nao_u が事前に「やってみる価値あり」と明言したので採用可能。**最有力候補**。

### 候補3: Spec C 単独（連続軌道予測 次1反射のみ）

**懸念リスト**:
- 懸念1: 視野ノイズ（連続表示の線）
  - 解決可能: 次1反射のみに絞る、薄さ・短さ調整
- 懸念2: 「予想する楽しさ」消失
  - 解決可能性: **不明**（連続表示は予想フェーズに侵入する）
- 懸念3: 角度視覚化が間接的（線から推測）で位置→角度の直接学習がしにくい
  - 解決可能性: 不可（線から角度を読む間接表現、D の直接性に劣る）

**判定**: 懸念3が不可。**不採用**（Spec D の直接性に劣る）。

**決定: 候補2 (Spec D + Spec E) を v02 として実装する。**

### なぜこれか

1. **★1 の射程を完全に満たす**: 「角度視覚化」(D) + 「軌道予測」(E) の両輪、Nao_u 03:01 投稿の言葉どおり
2. **視野ノイズ最小**: D=パドル本体統合、E=接触瞬間限定、画面が線で埋まらない
3. **学習段階が二重**: D で位置→角度を学ぶ、E で角度→次衝突点を学ぶ。中級プラトーが砕ける経路
4. **巻き戻し容易**: D の縦縞描画 + E の予測線描画を消せば素 Arkanoid に戻る（機構非介入は v01 と同様維持）
5. **「予想する楽しさ」保存**: E が接触直前 0.3秒限定発火、それ以前のボール飛行中は予測情報なし

### なぜ Spec D 単独でないか

- Nao_u 03:01 は「角度視覚化＋軌道予測」と両方明示。半分にすると ★1 の射程を満たさない
- D 単独では「裏抜けまで届くか」が脳内処理依存で再現性化が不十分

### なぜ Spec E 単独でないか

- E 単独では「角度視覚化」の事前情報が欠ける、ボール接近時のみ発火＝学習素材としての常時情報がない

### なぜ Spec C でないか

- 連続予測線は視野ノイズ大、「予想する楽しさ」を侵食、間接表現

### なぜ「ガイド ON/OFF トグル」を入れないか

- 守破離の守の段階で機能分岐は過剰

- ガイド OFF が楽しいなら別 v で分岐検討、本 v は ガイド ON 一択で検証

## v02 仕様（実装定義）

### 1. パドル角度メーター（Spec D）

- パドルに **3 本の縦縞**を描画（左 / 中央 / 右、それぞれ ±60° / 0° / ∓60° に対応する位置）
- 縦縞は **薄い白色（rgba(255,255,255,0.3)）**、幅 1px、パドル高さ全体
- 中央縞は若干太く（2px）か、別色（薄い水色 rgba(140,200,255,0.4)）にして「中央 = 垂直反射」を強調
- パドル本体（既存色）の上にレイヤとして重ねる、機構介入なし

### 2. 接触直前予測線（Spec E）

- ボール `y >= paddle.y - 80` （= パドル接触まで残り約 0.3-0.4秒）になったら発火
- 現在のパドル位置とボール位置から、接触時の出射角を予測計算（パドル当たり位置の x オフセットから ±60° 内）
- 出射点（パドル接触予定 x 座標）から、次の壁 or ブロックとの衝突点まで **薄い線（rgba(255,200,100,0.35)、幅 1.5px）** を描画
- パドルが動くと予測線も即時更新（リアルタイム連動）
- 接触瞬間に予測線消失（過去を残さない＝視野ノイズ最小）

### 3. 機構非介入

- ボール速度・パドル幅・スコア・ライフ・クリア条件は v01 と同一
- ガイド表示は完全に **観察 UI**、削除しても素 Arkanoid として遊べる
- v01 の「裏抜けカウンタ」(BACK xN ポップアップ等) は **全削除**（Nao_u 21:36 全否定済）

### 4. 不変仕様（v01 から継承）

- パドル左右移動（矢印 / WASD / マウス）
- ボール反射（パドル当たり位置で角度変化、中央±0、端±60°）
- 多段ブロック（6段、HP=1〜3、6色）
- ライフ 3、ボール下端落下で -1、0 で GAME OVER
- 全ブロック破壊で CLEAR
- SPACE で START / SERVE / RETRY
