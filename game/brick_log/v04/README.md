## v04 採用案: F-1 + F-2 を束ねる「動的標的化」

brainstorm.md F-1〜F-10 のうち、確信度 ★3 + Nao_u 04:37 直接指摘 (B1 死ななくなった) への直接回答は **F-1「動く標的を狙わせる」** + **F-2「標的が応答する」** の a) 系統。両者を束ねて1つの独自要素として実装する。

### v04 の核

ブロックが微小に左右揺れる。揺れは決定論的（ブロックごとに固定の位相と周期）。予測ガイドは現フレームのブロック位置で再計算するため、ブロックが動いていると **「狙ったその瞬間にブロックが半個分ズレている」** という外発緊張が生まれる。

- 揺れ振幅: 5px（ブロック幅 36px の約14%、ボール直径 10px の半分）
- 揺れ周期: 240 frames = 4秒
- 位相: 行 r と列 c の合成で決定論的に分散 (`phase = r * 0.7 + c * 0.4`)
- 動きの方向: 左右1軸のみ (上下動はガイドの追従難度を不可侵に保つ最小条件として除外)
- ガイド: 現フレームのブロック位置で再帰反射シミュレート（v03 から不変）→ ブロックの未来位置は予測しない

これにより：
- **B1 死ななくなった** → 揺れに合わせて狙いをタイミング調整する必要が出る、外発緊張復活
- **B2 静止標的** → 標的が動く、双方向の対話化
- **B16 反応しない** → 動きはボール接近応答ではないが「環境が能動」になる
- **G1 狙えるようになった** → 揺れは決定論的なので学習可能、達人プレイは「動きを読む」に進化（毀損ではなく拡張）

| # | 懸念 | 解決可能性 | 設計対応 |
|---|---|---|---|
| 1 | 揺れでガイドが予測不能になり、ストレスになる | **可** | 振幅を 5px に抑制、揺れ周期を 4秒にしてガイドの追従誤差を限定的にする |
| 2 | 揺れが予測可能すぎて緊張にならない | **可** | ガイドは現フレーム位置を使うため、ブロックが動いている瞬間に必ず誤差が出る。完全予測にはならない |
| 3 | G1 (狙えるようになった) を毀損し、Nao_u v3 評価の中核が崩れる | **可** | 揺れは決定論的（毎ゲーム同じ）なので学習で予測可能、達人プレイは「動きを読む」に進化する。完全コントロールから「動く相手を狙うコントロール」へ移行 |
| 4 | 揺れがボール反射の物理に影響して衝突判定がバグる | **可** | 当たり判定は「描画位置」で行う。ブロックが動いてもボール側の挙動は v03 と同一。位相を毎フレーム更新するだけ |
| 5 | M-30 自発リスクのコア化（プレイヤー入力で緊張増減） | **回避** | 揺れはプレイヤー入力に応じない、純粋に環境側の能動性。外発緊張のみ |
| 6 | feedback_pull_not_force_reading 違反（揺れを見ないと損） | **可** | 揺れはガイドに反映されないので「ガイドだけ見ても勝てない、本体も見る」になる。これは「読まないと損」ではなく「見るほど精度が上がる」報酬構造 |
| 7 | feedback_no_passive_punishment 違反（時間経過で揺れる＝受動ペナルティ） | **回避** | 揺れは時間経過で発生するが、プレイヤーに「減るもの」を与えない。難度の一部として扱われる |
| 8 | 揺れが視覚的に騒がしくて長時間プレイで疲れる | **可** | 振幅を抑え、周期を長めにする。微妙に揺れる程度に留める |

## 実装仕様

### 1. ブロックデータ追加

```js
// initBlocks() 内で
state.blocks.push({
  ...,
  phase: r * 0.7 + c * 0.4,  // 決定論的位相
  baseX: BR_X0 + c * (BR_W + BR_GAP),  // 揺れの基準位置
});
```

### 2. 揺れ計算（共有関数）

```js
const SWAY_AMP = 5;        // 振幅 px
const SWAY_PERIOD = 240;   // 周期 frame
function blockSwayX(blk, t) {
  return blk.baseX + SWAY_AMP * Math.sin(2 * Math.PI * t / SWAY_PERIOD + blk.phase);
}
```

`blk.x` フィールドは update 開始時に書き換える（衝突判定とガイド計算が同じ位置を使うため）。

### 3. 衝突判定・ガイド・描画 すべて `blk.x` 経由

- `update()` の冒頭で全ブロックの x を `blockSwayX()` で更新
- ボール衝突判定は v03 と同じ（更新後の x を使うので無修正）
- ガイドの再帰反射シミュレートも v03 と同じ（同じく更新後の x）
- 描画も同じ
- → ブロックの x が毎フレーム揺れているだけで、コードの主流は v03 から不変

### 4. パドル / ボール / スコア / ライフ / クリア条件 不変

機構非介入の維持。

### 5. v03 からの差分は最小

`game/brick_log/v04/index.html` は `v03/index.html` をベースに揺れ計算 + `blk.baseX` 追加 + `update()` 冒頭の x 更新の3箇所のみ。
