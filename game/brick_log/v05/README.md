# brick_log v05 — 動的標的化 振幅拡大（v04の5px→22px）

## 起点（Nao_u 2026-05-01 09:46 #game-rights）

> フィードバック、、移動が小さいのでプレイ感覚がまったく変わらない

v04 で「動的標的化（揺れる標的）」として振幅 5px / 周期 240f を実装したが、Nao_u プレイで「揺れていることが認識できない＝v03 と区別がつかない」状態だった。揺れの量がプレイ感覚の変化を生む閾値を下回っていた。

## v04 の失敗（M-39 違反の自己診断）

M-39（人間プレイ前 結果予測ゲート）に違反していた。

- v04 README の「着手前批判レビュー」では「揺れが予測可能すぎて緊張にならない」（懸念2）と「視覚的に騒がしくて疲れる」（懸念8）の **両方向の過剰** は警戒したが、**「人間が認識できる量か」** の予測が抜けていた
- 5px = ブロック幅 36px の14%、ボール直径 10px の半分。「狙ったその瞬間に半個分ズレる」と書いたが、実際は半個ではなく **1/7 個分**（5/36 ≈ 0.14個）しかズレない
- ガイド計算上の追従誤差は出るが、人間の視覚では「ほぼ静止している」と認識される量
- 「実プレイで判明したら直す」を素通りで Nao_u に出してしまった = δパターン（β「実プレイ判定」延伸形）

実装後に「人間がプレイした時、この量で『動いている』と認識できるか」を1分でも自問すれば、画面上で 5px の左右往復を mental simulation すれば気づけた。M-39 は M-37 の下流ゲート、プレイ依頼直前の最終確認装置。

## v05 の核

振幅と周期を以下に変更。設計の枠組み（決定論的位相、左右1軸、ガイドは現フレーム位置で再計算）は v04 から不変。

| パラメータ | v04 | v05 | 根拠 |
|---|---|---|---|
| 振幅 SWAY_AMP | 5px | **22px** | ブロック幅 36px の **61%**、隣ブロック間隔 38px の **58%**。視覚的に「左右に振れている」と即時認識できる量 |
| 周期 SWAY_PERIOD | 240f (4秒) | **180f (3秒)** | 短くしてボール飛翔中（≈2.4秒）に揺れが約 3/4 周期進む。ガイド予測位置と実位置の差が最大 20px 近くに達する |

## v05 で起きるべきこと（人間プレイ前 結果予測 / M-39）

### 30秒以内予測

- **0〜5秒**: タイトル → SPACE → サーブ。ブロックが左右にゆっくり揺れている動きが画面上端で即座に認識される（v04 と即区別がつく）
- **5〜30秒**: 1〜2発を打って、ガイドが指す位置と実際のブロック位置にズレが出ることを認識。「揺れに合わせて狙う」感覚が立ち上がる
- **30〜60秒**: 動く標的への裏抜けが v03/v04 より難しくなる。ガイドだけで完全コントロールできた v03 から、「ガイド + 揺れの読み」の二重視認が必要に進化。ライフ1〜2消費で動的標的化に慣れる

### 観点別予測

- **テンポ**: v04 から大きく変わらない。揺れ周期 3 秒なのでボール飛翔とテンポは同期せず、独立した時間軸で動く（フローを破壊しない）
- **初動**: 揺れの量が即視認できる ≠ 「うざい」。ブロック幅の61%なので「動きすぎ」になる懸念は実プレイで再確認必要
- **停滞**: 揺れの読みが定着すると再び「達人プレイ」レベルで死ななくなる可能性あり（v03 → v04 → v05 の延長）。これは v06 以降の課題（応答型・進行型へ進む）
- **解釈負荷**: 揺れの位相は決定論的だが、6行×10列で同期しない位相分散があるため「全体としてどう動くか」を読み切るのは v04 より複雑
- **終局**: 全破壊クリア / 3 機落ちは v04 と同じ

### 遊ぶ前にわかる懸念3点

| # | 懸念 | 実装側で潰したか |
|---|---|---|
| 1 | 振幅 22px は隣ブロックと衝突しないか（位相差 0.4rad で最大相対変位 8.7px、ギャップ 2px なので最大 6.7px の重なり） | **潰し済**: 衝突判定は描画位置でフレーム独立に行うので、ブロックが視覚的に押し合っても判定はバグらない。ただし見た目の違和感は残る可能性 |
| 2 | 揺れが大きすぎて狙うこと自体が困難になり、Nao_u v3 評価の中核「狙えるようになった」を毀損 | **潰せていない**: 22px が「読み甲斐のある」量か「狙えない」量かは実プレイ依存。v06 で 12〜18px の中間値を試す可能性あり |
| 3 | パドル制御で左右移動を要求される量が増えて手が疲れる | **潰し済**: パドル仕様は不変。揺れに対する追従はパドル移動ではなく「狙うタイミング調整」（ガイドが目標位置を通る瞬間を待つ）で行えるよう、ガイド機構が v03 から不変 |

### 自明な問題はプレイ依頼前に潰せたか

- ✗ 懸念2「揺れが大きすぎて狙えない」は「実プレイで判明する」性質——これ自体は M-37 で「不明」と判定すべき項目だが、v04 の失敗は「小さすぎ」だったので逆方向の同パターンに陥らないため、まず 22px で出して反応を見る方が情報が早く集まる
- ✓ 懸念1（衝突判定）と懸念3（疲労）は構造で潰した
- → 「自明な問題は出す前に潰す」は満たしている。1点（揺れ量の調整）だけ実プレイ依存
