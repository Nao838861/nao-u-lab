## 30 秒予測

### 0-5 秒
- ボールが画面下半分にいる間、警戒は 0 個（最下段ブロックでも距離 100px 超）
- サーブ後ボールが上昇 → 上段に近づく時、ブロックが白縁＋明色化
- プレイヤー反応: 「あれ、動いた？」「色が変わった」
- 倍率の意味はまだ伝わらない

### 5-30 秒
- 警戒中ヒット時にスコアジャンプ（10 → 20、30 → 60 等）+ HUD "×2 HITS" カウンタ +1
- 1-2 回のヒットで「警戒中 = ×2」と気づく
- 中間ヒット（hp 残り 1+）でも 0.5 倍ボーナス追加 → 「警戒中の触り損ねもオトク」と誤認するリスクあり
- 後退 -2px は隣接ブロック間隔（4px）の半分なので、視覚的にはほぼ気づかない（M-37 Q3 で言及した解像度問題）

### 30-60 秒
- 達人層: 警戒中を狙って打ち込む経路を意識（「次に警戒に入りそうなブロックを撃つ」）
- 初級層: 警戒色の追跡だけで楽しめる（パッシブ視覚演出として機能）
- ガイドの嘘判定: 後退 ±2px なので、ガイド誤差は最大 2px。物理境界 23px 未満で「ガイドが嘘」評価は出ない

## 遊ぶ前にわかる懸念 3 点

### 懸念 1: ×2 倍率が「狙う行為」に意味を加えない可能性
- 現状: ボールに最も近い 1-3 個が警戒 → ボール軌道上の次ブロックが多い → 普通に当たって ×2
- 問題: 「警戒を選んで狙う」という能動行為が発生しない（来た球で勝手に倍率が乗る）
- **遊ぶ前に潰せるか**: 微妙。警戒が「ボール軌道上のブロック」と頻繁に一致するなら、プレイヤーの選択は介入しない
- **対処候補**:
  - (A) 警戒対象を「ボール最近距 1 個」に絞る → 軌道との一致頻度が下がる、選択の余地が出る
  - (B) ×2 を「警戒色だがガイド軌道外のブロックを狙えた時のみ」に限定 → 達人層向け
  - **判断**: v07 ではまず現状で出して、警戒対象数 N=3 が「軌道一致しすぎ」かを self_judgment で計測。N=1 への絞り込みは v08 候補。
- **リスク**: M-40 違反疑い（Nao_u にプレイさせて初めてわかる構造）→ 遊ぶ前に **headless 5 秒走行で「警戒中ヒット率 / 全ヒット率」を計測**して判定可能。次サイクルで実装。

### 懸念 2: 後退 -2px が「気づかれない」
- 現状: 4px ギャップの半分以下シフト、明度 +45% と白縁併用で気づきを補強
- 問題: 静止画では識別困難、動画でも `state.t` 単位の変化で気づくのは熟練プレイヤーのみ
- **遊ぶ前に潰せるか**: 部分的に。**警戒色変化（明度+45% + 白縁）で物理シフトの不可視性を補っている**ので、視覚気づきは保証されている。物理シフト自体の「動いた感」は後段で評価
- **対処候補**:
  - (A) 後退 4px に拡大 → ガイド誤差増、リスクあり
  - (B) 後退方向にトレイル（短い線）を引く → 装飾UI、Q-H-8 違反候補
  - **判断**: v07 では現状維持（視覚は色で補強、物理は控えめ）。「物理シフトが効いてない」評価が来たら v08 で振動式（接近時に小刻みに後退/復帰を繰り返す）を検討。

### 懸念 3: 中間ヒット 0.5 倍ボーナスが「警戒中の触り損ね歓迎」になる
- **当初状態**: 警戒中の hp>0 ヒットに `Math.floor(blk.score*0.5)` を加算（自分が独断で追加）
- 問題: 「警戒中なら破壊しなくてもオトク」と学ばせると、コア快感（破壊+×2）が薄まる
- **判定**: README 仕様は「当てた瞬間のスコア倍率 ×2（**破壊扱いは通常通り**）」=破壊時のみ ×2。中間ヒット 0.5 倍は仕様逸脱
- **対処（このゲートで実施）**: index.html から該当行を削除済み。コメントで「v07 試験で入れたが M-39 で除去」と明記
- **教訓**: M-39 ゲートを書いて「README 仕様外の自分発の追加要素」を発見する効果があった。M-37 では設計に集中して、コード細部の独断追加は気づきにくい

## ヘッドレス自己評価候補（次サイクル）

実装済み v06_compare ハーネスを再利用、判定対象を変更:

1. **警戒対象数 N=1/2/3** で 5 秒走行 × 各 10 回、「警戒中ヒット率」「軌道一致率」を計測
2. **後退量 0/2/4 px** で 5 秒走行、ガイド誤差最大値を出力（v05 失敗の再現防止）

## ゲート結果

- 懸念 1: **微妙**（プレイで判定するしかない側面あり、ただし headless で「警戒中ヒット率 / 軌道一致率」は事前計測可能）
- 懸念 2: **対処済み**（視覚は色で補強、物理は v08 候補に送り）
- 懸念 3: **対処済み**（仕様逸脱を発見、index.html から該当行を削除）

→ **3 件中 2 件は遊ぶ前に潰した／対処方針を決めた、1 件は仕様逸脱を発見して即修正**。懸念 1 のみが headless 計測 + 実プレイの両方で確認するスケジュール。
→ M-39 ゲート「自明な問題はプレイ依頼前に潰す」原則は守った。「実プレイで判明したら直す」を結論にしていない。
