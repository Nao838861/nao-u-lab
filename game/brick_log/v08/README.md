# brick_log v08 — ENEMY + MOVING BOSS

## 起点

Nao_u #game-rights 2026-05-02 05:08 直接指示:

> もうめんどくさいので直接指示になっちゃうけど、アルカノイドのシンプルに敵みたいなのを出すのではだめ？敵の作り方にはいろんなバリエーションが作れるので、それだけでもアルカノイドからの発展になる。あと、SFC版アルカノイドにはボスもいる。SFCのボスは動かないが、動くボスを出すのではだめ？すごくシンプルだと思うが、なぜこの発想が出てこないのかはずっと気になってる。アルカノイドの事例だし、一般的なゲームの形でもあるよね？

→ v08 brainstorm.md で B/C/E 全候補がブロック挙動の変奏に偏り、アルカノイド本家系列に常駐する敵 / ボスをジャンル一般要素として認識すらしていなかった。M-45 候補（ジャンル一般要素を独自要素と勘違いする盲点）の典型発動。`memory/feedback_genre_general_element_blindness.md` 参照。

→ v08 = アルカノイド本家 (1986) の敵キャラ + Doh It Again (1997 SFC) のボスを「動くボス」化した直訳型。**独自要素ゼロ、型の組み合わせのみで成立**。

## 採用構成

### コア (v07 から継承)

- パドル左右移動（キーボード / マウス）
- ボール反射（角度可変、パドル位置で反射角制御）
- 多段 HP ブロック（v06 までと同じ 6 行 × 10 列）
- ライフ 3、全破壊クリア
- スコア / コンボ / ハイスコア

### v07 から除去

- ボール接近応答 (proximity reactive blocks) — 凍結済の独自要素
- 達人プレイガイド線（ボール軌道予測） — 敵 / ボス出現で情報過多になるため

### ステージ進行

- ステージ 1: 通常ブロック面 + 敵 E-1 6 体
- ステージ 2: 通常ブロック面（より密 or 配置違い） + 敵 E-1 4 体 + E-2 4 体

- 全クリアで GAME CLEAR

## v04-v06 失敗構造との対比

| 軸 | v04-v06 | v08 |
|---|---|---|
| 動きの単位 | 全ブロック | **敵 / ボス個別** |
| 位相関係 | 同位相 | **個別軌道（無位相）** |
| トリガー | 時間 (sin) | **スポーン + 個別運動** |
| 方向性 | 無方向 | **降下 / 横振り（方向性あり）** |
| 予測性 | 完全予測 | **個別軌道で予測可能だが全体は変動** |
| プレイヤー関係 | 無関係 | **撃破応答（双方向）** |

→ Game Developer "everything moves at once predictably" 警告の**6 軸全反対**
