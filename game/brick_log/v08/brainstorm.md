## v6 の反省で掘った先行事例の使い方 (Nao_u 18:08「先行事例掘った結果はどうした」への直接回答)

v06 反省で集めた先行事例:

- Game Developer "Breaking Down Breakout" (2014年 ABA + 別著者): mechanism/hole/wedge 3軌道型 + Progressive/Split/Peek-a-boo 3動的配置型 + Game Token Priority + Be Clever (新規発明より既存特徴の再結合)

## 「最良」確信宣言 (希望的観測語禁止)

### v08 = 候補 B (隊列横スライド / Arkanoid Doh It Again 直接型) を「最良」と判断する根拠

1. **M-41 通過の純度が最も高い**: ブロック崩しジャンル内に Arkanoid Doh It Again (1997, 28年前) という**直接型前例**がある唯一の選択肢。Space Invaders (1978, 47年前) の同型も成立。「素直に過去のゲームにあった要素を型として組み合わせる」(Nao_u 20:51) を最も純度高く実行
2. **M-37 5/5 全て可**: C は #1 (no_passive_punishment 境界) が能動報酬化前提で「△→可」、E は 3件不明。**B のみ全件即座に「可」**
3. **「素っ頓狂で型のない要素」(20:51) ではない**: 1997 年と 1978 年の確立型を組み合わせるのみ。新規発明ゼロ
4. **Q-1 コア快感「予測線→操作→確定」を破壊しない**: 線形運動で完全予測可能、ガイドが現位置を反映する限り達人プレイ (狙ったルートで裏抜け) は維持。動く相手を狙う技能が加わるだけ
5. **守破離の守 (M-35) 維持**: 独自要素1つ (隊列横スライド)、Doh It Again のクローンに留める。ボール/パドル物理不変、ガイド機構不変、ブロック側 X 座標のみ更新
6. **v04-v06 失敗構造の "all" を破る**: "everything moves at once predictably" の "all" を「行ごとに方向違う」で部分反転、"predictably" の中の方向性 (sin → 線形運動) を反転
7. **C は v09 で被せる候補に格下げではなく並列保留**: B 単独で B1「死ななくなった」を解決できないため、B が機能を確認した上で v09 で C を被せる順序が安全。E は M-41 純度が落ちるため v10 以降で再評価

→ **v08 は構造的に B (隊列横スライド) が最良。実装に進んでよい**

### B が C を上回る決定的根拠

C は MPS 6 で B (MPS 4) を上回り、B1 を直接解決する強みがある。**しかし**:

- C は M-41 通過しても M-22 (no_passive_punishment) との境界例で、能動報酬化の体感は実装後でないと確かめられない
- C 単独で v08 を作ると、B1 解決のために M-22 違反リスクを抱える形
- B が機能した上で C を被せれば、B の動的標的化の上に「降下リセット」を能動報酬として組み込める = 「攻撃→降下リセット→次の動く層へ」の流れが成立しやすい

→ **段階順序: v08 = B 単独 → v09 = B+C → v10 以降で E**

## v08 README で確定すべき仕様の項目

1. 横スライド速度 (px/sec) — ガイド追従可能な範囲、初期値候補: 全行同方向 0.5 px/frame (= 30 px/sec)
2. 行ごとの方向 — 全行同方向 OR 行ごとに反転 (Doh It Again は行ごと反転)
