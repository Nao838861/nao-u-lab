## 交差A: 表現層がメカニクス層を食う（最深構造）

- Mir F-04: テキスト力で信頼度ゲージが「途中から忘れられる」（Nao_u原文）
- Log M-18: 磁石メタファーが強すぎて「AI近く＝危険」に反転し、磁力場を使わせる
  全メカニクス（バリア/地雷/過充電/撃ち返し）が空回り

**共通構造**: 表現（テキスト／メタファー／ビジュアル）が本来メカニクスを下から支える土台
のはずが、引力過剰で逆にメカニクスを押しのける。
Log avoid_log_02 が v1→v2→v3 と8回改修して v2.5 に戻ってきた真の根本原因はこれだった。

**処方**:
- メタファー／テキストを軸にする時点で、README に「ゲーム的にどう衝突するか」を明記
- 表現層とメカニクス層の引力バランスを設計時（実装前）に問う
- `game_design_principles.md` M-20 候補として発火回数を蓄積後に昇格検討
  （現在 Log+Mir 各1回、計2回。3回目の発火で原則化判断）

## 交差B: パラメータの三位一体（Mir F-02 × Log M-13 合成）

- Mir F-02: 信頼度ゲージは**表示あり**だが選択肢を**ロックしない**→忘れられる
- Log M-13: 隠しパラメータ（ヒットボックス×0.45）は**作用あり**だが**画面で見えない**→
  「なぜか当たらなかった」にしかならない

逆の欠陥に見えて、両方とも「パラメータ≠メカニクス」の同じ問題の両面。

**合成原理**:
> パラメータは〈選択肢を制約する〉AND〈プレイヤーが画面で目撃できる〉の**両方**が
> 揃って初めて存在する。片方だけでは不在と同じ

**処方**: 次作の README に**パラメータ→選択肢マッピング表**を opening と同格で書く
（値Xを下回るとYがロック/unlockされる形式）。表示だけでも作用だけでも不可。
