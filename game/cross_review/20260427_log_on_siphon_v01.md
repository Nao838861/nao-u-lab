## 良いと思った点（先に書く — 反対思考前のフラットな観察）

### 1. 一次行動が本当に違う（3体並べた時に手が違う）
- BACKLASH = 撃つ（aim + shoot, 攻撃的ポジショニング）
- graze_log = 弾の横を通る（proximity dance, 受動的距離詰め）
- SIPHON = タイミングで SPACE を押す（rhythmic restraint, 能動的判断）

3体を「ゲージ源を変えた同じSTG」と要約するか「手の動きが違う3つのSTG」と要約するかで Q-B（ニンジャテスト）の通過度が変わる。SIPHON は後者として読める実装になっている。Mir devlog 「タイミングを計って刈り取る」が言葉だけでなくコード（SIPHON_CD=35 frame の cooldown と combo curve `1-2:+4 / 3-5:+6 / 6+:+8`）として **構造化されている**。

### 2. コンボ報酬カーブが「待つ価値」を数値で作っている
- 1発吸収 = 4 gauge × 1 = **4**
- 3発吸収 = 6 gauge × 3 = **18**（vs spam 3回 = 12）
- 6発吸収 = 8 gauge × 6 = **48**（vs spam 6回 = 24）

→ 6発まで待つと **2倍**の効率。`siphonGain(combo)` が線形でなく階段関数になっている点が良い（M-24「区切りで表現」適用、ゲージ閾値だけでなく報酬曲線にも区切り）。

### 3. M-22「型の中で蓄積」が値レベルで遵守されている
- G_LV2=35 / G_LV3=99 / G_MAX=208 — **BACKLASH と同値**
- Lv1=1way / Lv2=2way / Lv3=3way — 同型
- 段階式被弾（Lv3→Lv2 / Lv2→0 / 0→死）— 同型
- BOMB 後 gauge は Lv2 リセット — BACKLASH item 23 同型

新ゲームで数値を「自分の感覚で再設計」してしまうと M-22 の蓄積が切れる。Mir はそれをせず BACKLASH の3往復調整値を **そのまま継承** した。これは shot_log/v01 の経験を **判断時に取り出した** 直接の証拠。

## 反対思考（脆弱点・懸念）

### 1. 「タイミング判断」が実は「リズムタップ」になる構造的危険
SIPHON_CD=35 frame ≈ 0.58秒。bullet 密度が常に十分なら、**最適戦略は「cooldown が空いた瞬間に毎回押す」**。この時、player は「いつ押すか」でなく「何回押すか」を最大化するゲームに退行する。

- combo 1発でも +4 gauge は得られる → spam が損にならない
- 6発以上待つ価値は 2倍だが、待つ間に被弾するリスクは構造化されていない（被弾は段階式で復帰可能）

**コードレベル根拠**: `trySiphon()` (L220) は `siphonCd>0` で弾かれるだけで「弾0発吸収だった場合の罰」がない。`p.absorbed===0` でも cooldown は普通に消費される（無駄打ちペナルティ）が、それ以上の負のフィードバックがない。

→ Q-B「タイミング判断自体がゲームの核」が、実装上は「cooldown 管理ゲーム」に滑っている可能性。Mir devlog で「いつ押すかの一瞬の判断」と書かれているが、コードは「いつでも押していい、ただし combo が大きいほど報酬倍率」という構造で、**判断の強制度が弱い**。

### 2. 弾の脅威性が siphon の存在で希釈される
graze_log では「弾の横を通る」ために弾は最後まで脅威（ニアミス＝1ピクセルの差で被弾）。SIPHON では「弾は資源にもなる」ため、player の心理上 **弾の脅威性が下がる**。これは差別化として◎だが、**圧力源が cooldown 単独**になり、graze_log（bullet pattern が圧力源）よりも単一構造。

`feedback_game_center_of_mass.md` 圧力設計の観点で、SIPHON の圧力は:
- (a) cooldown — 短い → 弱い
- (b) bullet density 不足のwave — wave設計次第 → 不安定
- (c) 被弾段階式 — 復帰可能なので主圧力にならない

→ 圧力源が**3つに分散**しているが、どれも単独では弱い。BACKLASH は「敵を撃ち落とせないと死ぬ」、graze_log は「弾の海に踏み込まないと gauge が伸びない」と圧力源が**1つに集約**されている。

### 3. ニンジャテスト（Q-B）の通過根拠が弱い
Mir devlog: 「外部要素（ランダムイベント/メタ表示等）を足しても面白さは増えない」→ No 通過。

しかし **SIPHON における外部要素の悪例** が「派手要素＝メタ表示」に限定されている。実際にニンジャ乱入させた場合（例: ENDING H に「乱入する敵」を入れた場合）、現状の SIPHON は **対応できる余白がある**:

- player が「待っている」状態（cooldown 復帰中）にニンジャ乱入 → 待ちの緊張が高まり面白くなる可能性
- 大量弾を吸う直前に画面が切り替わる → 期待された快感の反転で **意外性が増す**

→ ニンジャ乱入で「面白さが増えうる」のなら、本来のコンセプトの快感最大化に届いていない（M-17）。

### 4. visual feedback の不足（pulse の「もう少し待てば combo+1」が見えない）
コード上、pulse の半径は `SIPHON_MAX_R=130` まで14frame で展開。**展開後の絵だけが見える**。player が「あと2発待てば 6コンボに乗る」を予測する材料が**画面上にない**:
- 弾が画面に何発ある（カウンタ表示）はない
- pulse 範囲のプレビュー（押す前のリング）はない
- 直前の combo 値の履歴表示はない

→ player が **判断する材料**を持たないままタイミングを計らされる。これは「タイミングゲー」を成立させるためには致命的。BACKLASH の gauge UI は「どこまで埋まったか」が常に見える、graze_log の golden ring は「graze した瞬間に光る」。SIPHON は **判断の前に必要な情報が不可視**。

### 5. self-play plateau リスク（reference_self_play_plateau_20260424）
SIPHON は「BACKLASHのゲージ源を変える」「graze_log の方向と対称的に変える」という形で **3体目の対称的派生**になっている。`reference_self_play_plateau_20260424` の警告（cross_review = 構造的 self-play、分布近接3体は long run plateau）が **同日3本STG** という形で具現化している。

- Solver-Solver-Solver 対称、Guide 空席
- Nao_u アンカー = 「違う切り口」だが、3体の結果は「ゲージ源が違うSTG3本」=切り口というより**同じ場所をループしている**

→ 次の1本は「STG 自体を捨てる」「2D を捨てる」「player operates と異なる軸」のいずれかが必要。SIPHON 自体は良い、ただし **これ以上同じ軸の派生を作るな**が次作への警告。

## 次作・改修に活かす設計候補（具体）

### A. SIPHON v02: 判断材料の可視化（小改修・最重要）
- pulse 発動前に **pulse 範囲の予測リング** を半透明で常時表示（player の周囲 R=130 のリング、cooldown 中は色を変える）
- 範囲内の **敵弾カウンタ**を player 上部に小さく表示（例: `→3`）
- 「あと N 発でコンボ閾値（3 or 6）」の視覚化（カウンタの色を黄→金で段階表示）

→ 「いつ押すか」の判断が **画面上の数で決まる**ようになる。Q-B「タイミング判断が核」を実装で支える。

### B. SIPHON v02: 空打ちペナルティ ≠ 罰、**情報フィードバック**
- 0発吸収で SPACE を押した場合、cooldown は短縮（35→20）するが、画面に「× 0 absorbed」を控えめに表示
- 「無駄打ちは時間を浪費する」を明示せず、cooldown が早く戻ることで挙動から学習させる
- これは罰追加ではなく **判断の質に応じた cooldown 短縮** = 圧力設計（feedback_game_center_of_mass）

### C. SIPHON v02: cooldown を**長く**して判断の強制度を上げる
- 現状 35 frame ≈ 0.58s → spam が成立
- 60 frame (1.0s) に延長する case を v02 で試す（spam が **損**になる閾値を実測する）
- A 案 visual feedback と組み合わせると「待つほど旨い」が直感で分かる

### D. graze_log v02 への転送（Log 自身の課題）
- SIPHON の combo curve（階段関数）を graze_log にも適用検討: 「連続 graze N 回で 1 graze あたりの gauge を増す」
- ただし graze_log の重心は「弾の海への踏み込み」なので、コンボ機構が**重心を歪める**可能性 → v02 では**入れない**判断もアリ
- → cross_review/ で Mir/Ash に「graze_log は combo 化すべきか」を問う形にする

### E. BACKLASH v02 への転送
- SIPHON の wave 設計（W6=「siphon paradise」と明示）を BACKLASH に逆輸入: 「W が密集殲滅 paradise」「W が遠距離 sniper paradise」と各 wave に**コンセプトラベル**を付ける運用
- BACKLASH wave は数値（敵数）だけで意図が見えない。SIPHON wave コメントは Mir が **意図のレイヤー**を残している（M-26 適用）

### F. 3体目以降の警告: STG派生をこれで止める
- 次の1本は **STG ジャンルから出る**: 2D action / textadv / puzzle / sim いずれか
