## 反対思考（脆弱点・懸念）

### 1. サイヴァリア問題——graze をコアにすることの構造的危険（**最重要**）

**Nao_u は同日（04-27 22:04）に以下を明言している:**

> 「ほっておくと死なないところにわざわざ自分からリスクを取りにいかないといけないのは、非常に筋が悪いと思った。サイヴァリアのバズシステムや、クレイジータクシーのカスリボーナスなどがあるが、これらは一般的に楽しいとは言い難い。それ自体をコアメカニズムにするのは難度が高そう。」

graze_log のコアメカニズムは **敵弾の真横を自発的に通りに行く** 行為でゲージを貯めること。これはサイヴァリアBUZZ/カスリと構造的に同型:

| | サイヴァリア BUZZ | graze_log GRAZE |
|---|---|---|
| 行為 | 敵弾の至近距離を通過 | 敵弾の至近距離を通過 |
| 発生源 | **自発**（弾の横を自分から通りに行く） | **自発**（弾の横を自分から通りに行く） |
| 報酬 | BUZZスコア倍率上昇 | ゲージ +6 → Lv上昇 → BOMB |
| 既存ゲームでの位置 | **サブ層**（コアは撃破+生存） | **コア**（graze しないとゲージが伸びない） |

Nao_u の原則をそのまま適用すると:
- **Q-D（緊張の発生源）: 自発** → コアメカニズムとしては ✕
- graze_log は「死にたくない→弾を避ける」の防御ループが成立した上の **上級者ボーナス層** としてなら成立しうるが、それが **ゲージ蓄積の唯一の主経路** になっている v01 設計はサイヴァリアの罠に嵌っている

**コード根拠**: ゲージ蓄積源は以下の2つだけ（L36-41）:
- `GRAZE_GAUGE=6`（graze 1回 +6）
- `KILL_SMALL_GAUGE=2` / `KILL_MED_GAUGE=4`（kill で +2/+4）

MAX=208 に到達するには、kill だけでは medium 52体撃破が必要（W4以降でも medium 3体/wave → 17wave以上）。実質的に **graze なしでは MAX に到達できない設計** になっている。kill 経路は控えめすぎて、graze に依存しなければゲームが成立しない。

**Logの devlog では**: 「BACKLASH の defensive=0% を**構造反転**で解く」「罰追加でなく報酬経路の追加」と位置づけているが、**報酬経路の追加をコアにしたこと自体が、自発リスクをコアにした** のと同義になっている。

**重要な留保**: Nao_u の feedback_tension_from_world は ash_onebutton v04 への feedback であり、**graze_log を直接対象にした発言ではない**。ash_onebutton v04 は「ほっておくと死なない」設計だったが、graze_log は medium の自機狙い弾で「ほっておいても弾が来る」。この差がサイヴァリア問題を軽減する可能性はある。ただし構造的同型性は否定できない。

### 2. 外発緊張の弱さ（medium 自機狙い弾の密度不足）

Log自身が devlog で「small は撃たない設計 → W1-W3 は graze の物量が薄い」と認めている。コードを見ると:

- small: 直線降下のみ、**弾を撃たない** (L116: `fireT:9999`)
- medium: sine wave + 自機狙い弾、`fireT=70+random(40)` ≈ 1.2-1.8秒間隔

W1 は medium 1体（1.2秒遅延で出現）→ **自機狙い弾は1方向から1.2秒間隔で1発ずつ**。これは「弾の海」ではなく「弾の点滴」。W2 で medium 2体、W3 は medium 1体。**W1-W3 の 30-50秒間は、graze コアのゲームなのに graze 機会が散発的**。

外発緊張（「向こうからやってくる」弾の圧力）が薄いということは、プレイヤーは **弾が来るのを待つ** か **medium に接近して弾が来たタイミングを狙ってgraze** するしかない。いずれも **自発行動** で、Nao_u 原則の「向こうからやってくる」に対して弱い。

W4以降（medium 3 + small 4）で初めて弾密度が上がるが、ここに到達するまでの 50-70秒は graze 体験が薄い。**30秒オンボーディングで graze の快感が十分に伝わるか疑問**。

### 3. 3本並べた差別化——手の動きは違うが構造は同型

Log→Mir SIPHON review で既に指摘されている通り:
- BACKLASH = 撃つ（攻撃的ポジショニング）
- graze_log = 弾の横を通る（近接ダンス）
- SIPHON = タイミングで SPACE（リズム判断）

**手の動きは確かに違う**。しかし **構造** を見ると:

| | BACKLASH | graze_log | SIPHON |
|---|---|---|---|
| ゲージ閾値 | 35/99/208 | **35/99/208** | **35/99/208** |
| Lv段階 | 1way/2way/3way | **1way/2way/3way** | **1way/2way/3way** |
| BOMB | MAX→SPACE→全弾消去 | **MAX→SPACE→全弾消去** | **MAX→SPACE→全弾消去** |
| 被弾 | Lv3→Lv2/Lv2→0/0→死 | **Lv3→Lv2/Lv2→0/0→死** | **Lv3→Lv2/Lv2→0/0→死** |
| BOMB後gauge | Lv2リセット | **Lv2リセット** | **Lv2リセット** |

**ゲージ蓄積源の入口だけが違い、出口（BOMB / 段階式被弾 / Lv射撃）は完全同一**。M-22「型の中で蓄積」の正しい適用として数値を継承したことは良いが、Nao_u 視点では「ゲージの貯め方を変えただけの亜種3本」と見える可能性が高い。

Log の devlog「Nao_u 視点では BACKLASH のゲージ蓄積源を1つ追加した亜種と見える可能性」——この自己観察は当たっていると思う。

### 4. 重心審問——閉じたループは成立するが、外発緊張が主圧力にならない

Log が依頼した観点:
> graze→ゲージ→BOMB の閉じた強化ループは成立しているか / 圧力源 (medium 自機狙い弾) は外発緊張として機能しているか

**ループ自体は成立している**: graze (+6) × N回 → gauge上昇 → Lv上昇（射撃強化） → MAX → BOMB（全弾消去+敵HP半減） → gauge Lv2リセット → 再蓄積。構造として閉じている。

**しかし圧力源（medium 自機狙い弾）は二重の役割を持っている:**
- 脅威（被弾したらゲージ減少/死亡）= 外発緊張 ◯
- graze 機会（この弾を利用してゲージを貯める）= **リソース** ✕

弾が「脅威」と「リソース」の両方であるとき、プレイヤーの心理は **「避けたい」と「利用したい」のambivalence** に置かれる。これが面白い緊張になるのは、**外発緊張が十分に強い場合**のみ。v01 の W1-W3 では弾密度が薄すぎて、弾は脅威よりリソースとして知覚される。

SIPHON review で Log が指摘した「弾の脅威性が siphon の存在で希釈される」と **同じ構造** が graze_log にもある。弾を graze リソースとして利用できることで、弾の脅威性が希釈される。

### 5. W3 編隊の構造的落とし穴

Log devlog 指摘済みだが、コードレベルで詳しく見る:

W3: `for(let i=0;i<6;i++)spawnEnemy('small',W*0.15+i*W*0.14)` + medium 1。
- small 6体は直線降下、弾は撃たない → 接触で殺すか避けるかだけ
- auto-shoot Lv1（8F cooldown = 7.5Hz、1way）で small 6体を処理するのは無理
- Lv1（gauge < 35）のまま W3 に到達する蓋然性が高い
- small は graze 対象の弾を出さないので、6体の small に対して **graze コアが機能しない**
- 結果: W3 は BACKLASH と同じ「撃って避ける」ゲームに退行する

**wave 進行が gauge level に非連動** なので、graze コアのゲームなのに graze が機能しない wave が構造的に発生する。

## 三角化としての論点（Log の構造検証が見逃した点）

### A. feedback_tension_from_world との衝突はログに書かれていない

Logの devlog は 04-27 22:50 まで追記されているが、**同日 22:04 の feedback_tension_from_world への言及がない**。devlog の着手は 18:25、Nao_u の「コアの緊張は向こうからやってくるべき」feedback は 22:04。時系列上、graze_log 着手後に出たfeedbackだが、**devlog Phase 3 の self-playtest（22:50 追記）時点では既に公開されている情報**。

この衝突を自己検証で見逃しているのは、cross_review の三角化で補完すべき盲点。

### B. devlog の「圧力設計 vs 禁止追加」は問いの設定が間違っている

devlog の重心審問:
> 圧力設計か禁止追加か → 圧力設計のみ

この問いは「M-12 罰ではなく報酬で設計」に沿っているが、**feedback_tension_from_world が提起した問いは「圧力 vs 禁止」ではなく「外発 vs 自発」**。graze_log は罰を足していないが、**報酬の取得経路が自発的**（弾の横を自分から通りに行く）。この区別を見逃している。

### C. 「違う切り口」の切り口が浅い

Nao_u「違う切り口で作れるはず」→ Log の解釈は「ゲージ蓄積源を変える」。これは切り口としては **パラメータ変更レベル** であり、ゲーム体験レベルの切り口ではない。

本当に違う切り口とは:
- 操作方法が根本的に違う（SIPHON のタイミングSPACEは一歩踏み出している）
- ゲームの目的が違う（スコアアタック以外の動機）
- プレイヤーの心理状態が違う（攻めの興奮 vs 防御の緊張 vs 探索の好奇心 etc）

graze_log は「BACKLASH を避けながらプレイするとゲージが貯まる」という亜種で、プレイヤーの心理状態は「弾を避ける緊張＋ニアミスのスリル」。BACKLASH と比べて **追加された心理** は「ニアミスのスリル」だが、これは BACKLASH でも弾を避ける際に暗黙的に発生している感覚を **可視化しただけ** とも読める。

## まとめ

### 答えられた問い
1. **golden ring の感触**: 演出設計は的確（3層フィードバック、色分離）。ただし W1-W3 の graze 機会が散発的で「連続 graze の快感」が 30 秒以内に体験しにくい

4. **「3体目以降禁止」**: graze のコア位置づけを変えると差別化が消え、変えなければサイヴァリア問題が残る。構造的ジレンマ

### Log への提案
- **graze_log v02 は保留し、次作は STG 以外から**。§F 原則の実行が先
- v02 を作るなら: 弾密度を大幅に上げて **graze が自発行動でなく「弾の海の中で生き残る副産物」** として発生する設計に変える。プレイヤーは弾を避けるのがコア（外発緊張）で、結果として graze が発生する。ただしこれは東方の graze 設計そのもの（先行作品とのオリジナリティ問題が発生）
- graze_log の最大の学び: **「報酬経路の追加」が「自発リスクのコア化」と同義になりうる** ことの体験的確認。これは game_lessons_log に M-19 候補として刻む価値がある
