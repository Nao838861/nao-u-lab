### Q-A 快感最大化 = △ 1文で書けているが実装で割れている
- devlog 冒頭ブロックで「ゲージMAX付近の3wayショットで降ってくる敵をまとめて消す瞬間」と1文で書けている
- だが index.html の実装ではゲージが**攻撃強化（弾数 1→2→3）と防御（シールドで敵弾吸収・ゲージ-20）の2役**になっている
- 被弾でゲージが減る = 弾数が減る = 快感ループが反転する。**ゲージの意味が分裂**

### Q-B ニンジャテスト = ✗ 不合格（既にニンジャを呼んでいる）
- v01 README/devlog では「自機左右移動・SPACE弾・敵降下・ゲージ→弾数」の最小実装範囲だった
- 実装では: 8方向移動 / 敵3種(small/medium/large) / 敵弾(radial revenge + aim) / 中サイズsine波 / 大サイズhoming / アイテムドロップ / シールド機構
- **「最小実装で30秒快感ループ確認」のv01段階で、既に複数の派手要素を後付けしている**
- F.W.ブリッジ「ニンジャ乱入で面白くなる=元シーンの引力が弱い」がv01着手中に発生していた
- 結論: 元コンセプト（撃つ→ゲージ→弾増）の引力に自分が確信を持てず、敵パターン/ホーミング/シールド等を「あった方がよい」と足し続けた = 穴塞ぎの先行

### Q-C 罰なし版 = ✗ 罰でゲームが成立している兆候
- 罰系3つ存在: ①敵 leak で gauge-8 / ②敵弾被弾で gauge-20 / ③ゲージ0で被弾 → game over
- 自然減衰は削除済（feedback_no_passive_punishment 反映、これは正しい）
- 罰3つを全部抜くと: 撃破でゲージ単調増加 → 30秒で MAX 固定 → 常に3way → 緊張感喪失で30秒以上触らない
- **罰でゲージ降下を作っているから「ゲージが意味を持つ」状態。罰なし版はコンセプト破綻**
- これは「コンセプト段階での快感最大化が未設計だから罰で補っている」M-17 そのもの
