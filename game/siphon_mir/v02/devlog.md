## C148 (2026-05-01): BOMB温存圧の最小実装 — SPACE/KeyB 分離

### 実装内容
v02/index.html を4箇所改修（既達回避: 起動時点でKeyB処理は不在と確認済）:
1. **L221-228 `trySiphon()`**: `gReady() → fireBomb()` の自動分岐を削除。SPACE は常に siphon 試行（gReady 状態でも siphon 可能、ゲージは G_MAX で clamp されるため数値的に温存される）。
2. **L498-504 update()内**: `keys['KeyB']` の押下エッジ検出を追加、`gReady()` 時のみ `fireBomb()` 発動。`bPressed` フラグで連打防止（`spacePressed` と同型）。
3. **L218 グローバル**: `let bPressed=false;` 追加。
4. **L17 操作説明** + **L760 HUD**: `BOMB READY [SPACE]` → `BOMB READY [B]`、操作 paragraph に `B BOMB(gauge MAX)` 明示。

### 設計意図（温存圧の構造化）
**問題の再定義**: C147以前の設計では gReady 状態で SPACE を押すと自動で BOMB が発動 → プレイヤーが「siphon を続けたいのにゲージMAXで打つしかない」状況。これは「自動消費」であり「温存判断」が存在しない。BOMB を温存するには SPACE を押さず操作の手を止めるしかなく、これは弾源吸収の停止＝ジレンマを生まない。

**変更後の構造**: SPACE と KeyB が分離されたことで、gReady 状態でも (a) siphon を続けて弾源を吸い続ける（だが clamp されゲージは増えない＝コンボ得点のみ伸びる）、(b) 危機時に KeyB で BOMB を爆発させる、の二択が生まれる。**プレイヤー側に温存/解放の判断点ができた**。これが「温存圧」の最小定義。

### Q-A 快感最大化視点
SIPHON のコアは「敵弾→自分のゲージ増加」の能動吸収。BOMB は緊急回避＋全敵半減で局面を切り替える解放感。両者を SPACE 一本に束ねていたのは UI 簡素化が動機だったが、「最も気持ちいい瞬間（BOMB炸裂）を温存する選択」を奪っていた。分離後は「ゲージMAXまで siphon で耐え続けて、最終wave で BOMB を切る」というアーク（蓄積→解放）が描ける。

### 残課題
