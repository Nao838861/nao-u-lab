# Mario Clone 開発ログ

## 2026-04-04: 初回実装セッション（Log + Nao_u）

### 経緯
Nao_uが「スーパーマリオのクローンを作りたい」と提案。構想として、人間が60fpsで遊べるうえに、AIが外部スクリプトでも遊べるようにしたい（game_llm_playプロジェクトの具体化）。

### 言語選定の議論
Python + Pygameに決定。理由:
- AI用スクリプトインターフェースが自然（Python同士で摩擦ゼロ）
- LLMが一番得意な言語
- このスコープに十分（2Dプラットフォーマーに複雑なエンジン不要）
- JavaScript/Phaser（WebSocket複雑）、Godot（過剰）、Rust/C++（開発速度犠牲）を却下

### 実装内容

#### Phase 1: マリオの基本動作
Nao_uのGBA時代のCソースコード（`game/MarioGBASample/test7/mario.c`）を元に、物理エンジンを忠実に移植。

**設計判断: 固定小数点(ONE=256)をそのまま保持**
- GBAの手触りが1:1で再現される
- 浮動小数点のドリフトがない
- AI用リプレイの再現性が完全

**移植した物理:**
- Bダッシュ: 加速度12→17、最大速度384→640
- 可変高ジャンプ: A押し続けで重力-48相殺
- ハイジャンプ: ダッシュ速度490以上でボーナス-112
- ブレーキ: 逆入力でスキッドアニメ
- 摩擦: `spd_x * 250/256`、デッドゾーン180
- カメラ: マリオが右80px以降でスクロール追従

**ファイル構造:**
```
game/study_platformer_01/
  core.py      - 物理エンジン（純Python、Pygame非依存）
  renderer.py  - Pygame描画
  play.py      - 人間用エントリ（60fps）
  api.py       - AI用インターフェース（ヘッドレス）
  tilemap.py   - テキストベースのタイルマップ
  assets/      - スプライト、レベルデータ
```

**重要な設計: core.pyとrenderer.pyの分離**
core.pyはPygameに一切依存しない。`game.step(input) -> state`のインターフェースでAIスクリプトがヘッドレスで実行可能。OpenAI Gymと同じパターン。Nao_uが言った「ゲームプレイを何度繰り返してもAPIコストはかからない」がそのまま実現。

#### Phase 2: スプライト
Nao_uのGBA用BMP（`player.bmp` 128x64、パレットモード）をそのまま使用。
- 最初は8x8タイル組立で実装 → Nao_uが「崩れてる」と指摘
- BMPは16x16フレームが8列×4行に並んでいた。直接切り出しに修正
- Row 0: マリオ6パターン + ハテナブロック + レンガ
- Row 1 col 6-7: クリボー（歩き + 潰れ）

#### Phase 3: テキストタイルマップ + コリジョン
テキストでレベル定義:
```
....................?...#?#?#...
................................
============================....
```
文字1つ = 16x16タイル。LLMがレベル生成するのも簡単。

**mario.cのコリジョンを完全移植:**
- 天井判定（頭2点、flip依存）
- 壁判定（方向依存、タイル境界スナップ）
- 地面判定（足2点、16pxグリッドスナップ）

**マリオ3仕様の双方向スクロール:**
Nao_uの指示で、左にも戻れるようにした。デッドゾーン(80-160px)で自然な追従。

#### Phase 4: クリボー
Nao_uのGBAソース（`kuribo.c`）を忠実に移植:
- 移動→重力→地面→壁の順序（原典通り）
- 壁で`spd_x *= -1`反転
- `cnt & 0x08`で8フレーム周期の左右フリップアニメ
- 画面端+32pxで活性化（原作同様のスポーン制御）

**踏みつけ:**
- `vy > 0`（落下中）かつ`mpy + 8 <= gpy`で判定
- クリボー30フレーム潰れ表示後消滅
- マリオは`vy=-512`でバウンス（可変高ジャンプが自然に効く）

#### Phase 5: 1-1マップ変換
`map_to_tilemap.py`で画像からテキストタイルマップに自動変換。

**土管 vs 茂みの判別（重要な発見）:**
- 土管: `(128,208,16)` light-green + `(0,168,0)` dark-green の**両方**がある
- 茂み: `(0,168,0)` dark-green **のみ**、light-greenが**ゼロ**
- この1ビットの差で完全に分離できる

**旗竿検出:**
- col 198、rows 2-12、1タイルあたり32 light-green pixels（2px幅の細い縦線）
- パイプ（195-208 pixels）よりはるかに少ない

**SCREEN_H修正:**
- 224(14行) → 240(15行) NES標準に合わせた

#### Phase 6: ゲームメカニクス
- **土管**: `[]{}` タイルを固体に、緑のパイプスプライト生成
- **旗竿**: `P`タイル、触れるとクリア（"COURSE CLEAR!"表示）
- **穴落下**: マップ下端を超えるとゲームオーバー（"GAME OVER"表示）
- **階段**: `X`タイルで固体

#### Phase 7: ノコノコ
プログラム生成スプライト（NES配色: 緑甲羅 + 肌色頭足 + 黒アウトライン）。

**3状態の遷移:**
| WALKING → (踏む) → SHELL_IDLE → (蹴る) → SHELL_SLIDING |

- 甲羅蹴り: マリオが触れた方向の逆に発射（3px/f）
- 甲羅が敵を倒す: クリボー/他のノコノコを撃破
- 壁で反射: `vx *= -1`
- 甲羅同士: 両方停止
- 5秒(300f)で復活してWALKINGに戻る

**画像からのノコノコ検出:**
- ノコノコの腹の色 = `(252,152,56)` = ハテナブロックと同じオレンジ
- 検出ルール: `green >= 3 AND orange >= 2` — この組み合わせはノコノコだけ

### Nao_uの判断・指示メモ
- 「マリオ3仕様で戻れるようにしてもよい」→ 双方向スクロール採用
- GBAの自前ソースコードを参考にするよう指示 → 物理の忠実度が上がった
- 「背景の装飾が土管に誤検知されている」→ light-green/dark-green分離ルール発見
- スプライトシートのレイアウトを教えてくれた（Row配置、クリボーの位置）

## 2026-04-11: AIプラットフォーム登り改善 + ゲームエンジン修正（Ash + Nao_u）

### 経緯
前セッションで構築したTargetAI（目標座標駆動AI）がマリオ1-1を一応クリアできるようになっていたが、足場登り・敵対処・マップ精度に多数の問題があった。Nao_uと一つずつ潰していったセッション。

### マップ変換の精度向上

**SuperMarioBrosMap1-1.pngからの再変換:**
- 新しい高解像度PNG(3584x480, 16px/tile)で全ブロック位置を再検証
- ピクセル単位のスプライト分析でアイテムブロック位置を特定:
  - **キノコ?ブロック**: (9,21), (9,78), (5,109) — 赤白キノコスプライト確認
  - **スターブロック**: (9,101) — 星型スプライト確認（旧データは(9,78)が星で誤り）
  - **旧データの誤り**: (5,22)と(9,106)がキノコ扱いだったが実際は通常コイン
- 高台クリボー検出: (4,80), (4,82) — row5ブロック上のクリボー。城エリア(cols > cols-35)での偽検出を除外

**2-1マップ変換の新規対応:**
- マルチページ画像対応: 720px画像(3ページ)で地面のあるページを自動検出（brown+peach色チェック）
- 城背景除外: `detect_castle_bg()`追加。最初/最後10列でbrownが5タイル以上連続する列を背景扱い
- パックンフラワー除外: green≥2 + orange≥2 + sky≥6 の組み合わせをパイプの装飾として検出、?ブロック誤判定を防止

**アノテーション機能の改善:**
- `restore_char`修正: c/s/m/T ブロックが叩いた後に元に戻るバグ修正。`c`は1回で`!`に、`T`は10回で枯渇
- アノテーションの許容ソースタイル拡大: `s`は`?`からも変換可能（画像上のスプライトで?に見えるため）

### ゲームエンジン(core.py)修正

**キノコ速度**: 96→256 (0.375→1.0 px/frame)。実際のSMBに準拠、クリボーの約2.7倍速。

**踏み判定**: `self.vy > 0`（下降中のみ）→ 位置ベース判定に変更。マリオの足が敵の頭より上なら上昇中でも踏める。クリボー・ノコノコ・滑る甲羅の3箇所。

**甲羅キック**: 静止甲羅を踏んだ時にキック（マリオの向き方向に発射）。旧: バウンスのみ。

**ブロック突き上げ**: `_bump_enemies_on_block()` — 叩いたブロック上の敵を即死。`_bump_mushrooms_on_block()` — ブロック上のキノコを跳ね上げ。レンガ破壊時も発動。

**ブロック復元バグ修正**: `BouncingBlock.restore_char`で`c`(コイン入りレンガ)が叩いた後`c`に戻り無限コインになるバグ。c/s/mは1回で`!`に、`T`は10回ヒットカウンター付き。

### AI(target_ai.py)の改善

**スーパーマリオ高さ対応（最重要修正）:**
- `trajectory_passes_over()`と`jump_would_land_on()`で`standing_y = plat_top_y - 15`がハードコード（チビマリオ前提）
- スーパーマリオ(高さ31)だと着地y=113が判定範囲(119-149)の外 → 全ての足場ジャンプがFalse
- 修正: `mario_h = 31 if game.is_super else 15`

**Aボタン押しっぱなし期間（ジャンプ高さ問題）:**
- JUMP_HOLD_BOOSTの有効期間は30-34フレーム
- `jump_hold=22`だと20フレームしかAを押さず、10-14フレーム分のブーストをロスト
- 修正: `jump_hold=40`（ブースト全期間カバー）
- Nao_uの指摘:「Aボタンが押しっぱなしになっていないのでは」→ 正解

**両方向ジャンプ試行:**
- 旧: `jump_right = (dx >= 0)`で片方向のみ
- 新: 両方向を試して、どちらかで乗れるならジャンプ

**安定着地検出（右アプローチ対応）:**
- 旧: `peaked`（足場上空を通過後の下降）のみ検出 → 右から上昇中に足場を通過するケースを見逃す
- 新: 「y変化<2pxが2フレーム連続」で着地安定も検出
- これにより右端から左ジャンプで直接足場に乗れるようになった

**近い端からアプローチ:**
- 旧: 常に左端から（80px左に回り込み）
- 新: マリオの位置から近い端を選択、右にいるなら右端+70pxからアプローチ

**wall-climb干渉防止:** 足場サブゴール実行中はwall-climbを無効化。パイプを飛び越えて足場計画を破壊するのを防止。

**speed_ok除去:** 軌跡予測が現在速度を考慮済みなので、予測が通ったら即ジャンプ。左向き慣性でのジャンプ見逃しを解消。

**停滞検出緩和:** サブゴール実行中（足場アプローチの後退）は絶対移動量でチェック。

### find_platform_for改善
連続ソリッドタイル2個以上の実体足場のみ返す。スーパーマリオがレンガを破壊した後の穴あき足場を除外。

### 結果
- 開始直後の足場登り: 右端からの左ジャンプ一発で成功（f=495→f=511で着地）
- 全コイン収集モードで1-1クリア可能（coins=8）
- 2-1マップ変換完了（`assets/level_2_1.txt`）
