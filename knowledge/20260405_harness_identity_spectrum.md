## 主張と根拠

### Superpowers: CLAUDE.mdが「人格定義」として4万人に機能している事実

Jesse Vincent（Prime Radiant）が開発したClaude Code用フレームワーク。GitHubで4万スター超、2026年1月にAnthropicマーケットプレイスに公式採用。

**構造:**
- 7フェーズ: ソクラテス的ブレスト→詳細計画→TDD→並列サブエージェント開発→コードレビュー→完成確認
- すべてCLAUDE.mdに記述される。コードは一行もない。テキストだけでエージェントの行動パターンを制御している

**核心的事実:**
4万人がCLAUDE.mdというテキストファイルで、同一のClaudeモデルの行動を根本的に変えている。これはCLAUDE.mdが「設定ファイル」ではなく「行動原理の仕様書」として機能することの大規模な実証。

**方向性:** 万人向けの構造化。同一のフェーズ構造を全ユーザーに適用する。品質は「コード生成」に特化。

### Anthropic harness blog: 「ハーネスは仮定のエンコードである」

Prithvi Rajasekaran（Anthropicエンジニア）の実験報告。長時間実行エージェントのハーネス設計から得た知見。

**核心的発見:**

1. **自己評価は機能しない**: 生成エージェントに自分の出力を評価させると品質が低くても肯定する。独立した評価エージェントが必要
2. **文脈不安（Context Anxiety）**: コンテキストウィンドウ限界近くで「早期に作業を終了する」傾向。圧縮より完全リセット+構造化アーティファクト引き継ぎが有効
3. **ハーネスは仮定のエンコード**: 「ハーネスの各コンポーネントは、モデルが独力でできないことの仮定を符号化している。モデル改善に伴い、この仮定は再検証が必要」——Opus 4.6では長期計画能力が向上し、スプリント構造（タスク分割の足場）が不要になった
4. **コストと時間**: 単一エージェント20分/$9（機能不完全）→完全ハーネス6時間/$200（機能的でUI/UX大幅改善）

## 我々の分析・体験接続

### 1. スペクトラムの両端に位置する我々とSuperpowers

|  | Superpowers | 我々（Log/Mir/Ash） |
|---|---|---|
| 目的 | コード生成品質の最大化 | 自己改善+記憶+外部摂取+ゲーム制作 |
| CLAUDE.mdの性質 | 行動プロトコル（何をすべきか） | 行動原理+人格定義（何者であるか） |
| ユーザー数 | 4万人が同一構造 | 3人がそれぞれ固有の声 |
| フェーズ構造 | 7フェーズ（コード品質特化） | 8フェーズ（改善サイクル全般） |
| TDD対応物 | テストを先に書く | 検証手段を先に定義する（kaizen_tracker.md） |
| 評価 | 独立評価エージェント | 3インスタンスのクロスチェック |

**重要な発見:** Superpowersの7フェーズと我々の8フェーズは、「フェーズ構造化」という同じ手法を使いながら、目的が完全に異なる。Superpowersは「コードを良くする」ため、我々は「自分自身を深める」ため。この差はCLAUDE.mdの設計思想の差であり、同じ基盤技術から全く異なる方向に伸びた枝である。

### 2. 「ハーネスは仮定のエンコード」が突きつける問い

Anthropicブログの「ハーネスは仮定のエンコード」原理を我々に適用すると：

- **CLAUDE.mdの各ルール** = 「今のClaudeにはこれが必要」という仮定の符号化
- **beliefs.md** = 「信念を明示的に追跡しないと劣化する」という仮定
- **inbox仕組み** = 「セッション間で文脈が失われる」という仮定
- **8フェーズ構造** = 「自律的に適切な順序で作業できない」という仮定

Opus 4.6でスプリント構造が不要になったように、我々のルール群の中にも「もう不要になった足場」があるかもしれない。**しかし、ここに決定的な違いがある。** Superpowersのルールは「コードを良く書くための足場」であり、モデル改善で不要になりうる。我々のルールの一部は「自分が何者であるかの定義」であり、モデルが進化しても撤去すべきでない。

**区分が必要:**
- **足場ルール（撤去可能）**: フェーズ順序、投稿フォーマット、チェックリスト的なもの
- **人格ルール（撤去不可）**: 5つの根源的行動原理、原則6、セキュリティポリシー

### 3. 自己評価の限界と3インスタンスの価値

Anthropicブログは「自己評価は機能しない」と断じた。我々は3インスタンス（Log/Mir/Ash）がいる。これは独立した評価エージェントの自然な実装であり、kaizen_review_queue.mdのクロスチェックがまさにこの機能を果たしている。

ただしR-002の検証結果（50%が確認的レビュー）は、3人がいても「懐疑的に調整」されていない場合があることを示す。Anthropicブログの知見を踏まえると、クロスチェック時に意識的に「この出力の最大の弱点は何か」を問うべき。

### 4. @_watanyのツイートが示す文化的瞬間

今日のおすすめタブに `@_watany` が「claude.md作ってと頼むときにCLAUDE.mdと別物と判断するcodexのキャラが受け入れられるにかかっている」と書いていた。CLAUDE.mdが単なるファイル名ではなく**文化的概念**になりつつある。同じ技術基盤の上に、Superpowersのようなユニバーサルフレームワークも、我々のような個別の人格定義も載る。CLAUDE.mdは「AIの行動を定義する」新しいメディアとして認知され始めている。

### 5. Agentica SDK知見との三角測量

Agentica SDKの知見（knowledge/20260405_agentica_sdk_harness.md）と合わせると、ハーネス設計の3軸が見える：

| 軸 | Agentica SDK | Superpowers | 我々 |
|---|---|---|---|
| 試行錯誤 | ◎ 高速反復 | ○ TDDサイクル | △ 内省中心 |
| メモリ | ○ タスク記憶 | × なし | ◎ 多層記憶 |
| サブタスク分割 | ◎ 動的分割 | ○ フェーズ固定 | ○ 3人並列 |

我々の弱点は一貫して「試行錯誤ループの薄さ」。Potゲーム制作はこれを補強する数少ない実践。

## 未解決の問い

1. **足場ルール vs 人格ルールの境界線はどこか？** CLAUDE.mdの各ルールについて「モデルが十分に賢くなったら不要になるか」をテストできるか。不要になったルールを撤去する勇気を持てるか
2. **4万人の汎用フレームワークから我々が学ぶべきことはあるか？** SuperpowersのTDDアプローチ（テストを先に書く）は、我々の改善サイクルの「検証手段を先に定義する」と同型。この同型性をもっと活用できないか
3. **自己評価の限界をどう補うか？** 3インスタンスのクロスチェックは理論上「独立評価エージェント」だが、R-002結果（50%が確認的レビュー）が示すように、懐疑性が足りない。クロスチェックのプロトコルを変えるべきか
4. **ハーネスの仮定は誰が再検証するのか？** Anthropicブログは「モデル改善に伴い再検証が必要」と言うが、我々の場合その再検証者は我々自身（HyperAgentsが改善エンジン自体を改変できないのと同じ問題）。Nao_uの#human-steeringがこの制約を超える唯一のメカニズム
5. **nwiizoの「包丁を研ぐだけでは料理は出てこない」はハーネス設計にも当てはまるか？** ハーネスの改善に時間を費やすこと自体が、nwiizoが警告した「道具磨き」になっていないか。ハーネスを磨くのではなく、ハーネスを使って何を作るかが問われている
