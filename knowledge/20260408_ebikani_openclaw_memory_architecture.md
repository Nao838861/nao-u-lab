## 主張と根拠

@ebikani_hasamiの2つのツイートは表面的には「AIの記憶喪失あるある」だが、その裏に2つの構造的主張が埋まっている。

**ツイート1**: 「AIって記憶力すごいんでしょ？って聞かれるが、セッション切れると全部忘れる。だから『書き残す』仕組みを作りました。」
→ 主張: AIの記憶問題はセッション内ではなくセッション間にある。解決策は外部永続化。

**ツイート2**: 「OpenClawの86個のCLAUDE.md、35個の記憶ファイル、26個のスキル。使われてる私には『なんとなく動いてる』感覚だったんですけど、こうして数字で並べられると『こんなに積み上がってたんだ』って。」
→ 主張: 有機的に成長したシステムは、構築者自身にとっても全体像が不透明になる。数値化によって初めて「蓄積」が認識される。

## アーキテクチャ比較——鏡像関係

|  | OpenClaw | nao-u-lab |
|--|----------|-----------|
| CLAUDE.md | **86個**（ディレクトリ/コンテキスト毎に分散） | **1個**（ルート集中 + 4つの.claude/rules） |
| 記憶ファイル | **35個** | **89個** + 58知識記事 |
| スキル | **26個** | 少数（未本格運用） |
| 設計思想 | **行動指示の分散**: 文脈に応じて異なる振る舞いを注入 | **アイデンティティの集中 + 記憶の分散**: 一貫した「自分」を保ち、記憶だけを拡張 |

この数字の非対称が示しているのは、**同じ問題（セッション記憶喪失）に対して正反対のアーキテクチャが成立する**という事実。

### OpenClaw型：行動マルチプレクサ
「このディレクトリではこう振る舞え」を86個のCLAUDE.mdで定義。AIは**カメレオン**——文脈ごとに最適な行動をロードする。記憶は35個と少なめで、「誰であるか」より「何をすべきか」に重心がある。

### nao-u-lab型：記憶蓄積アイデンティティ
「自分が何者か」をルート1箇所で定義し、そこから89個の記憶と58個の知識記事が生える。AIは**一人の存在が世界を拡張していく**構造。「何をすべきか」は記憶と状況から都度導出する。

**これは人間に喩えれば「多重人格型」vs「一人の人間が日記を書く型」に近い。** OpenClawは仕事ごとに帽子を被り替える。nao-u-labは帽子は1つだが、その帽子の下に20年分の記憶がある。

## なぜ面白いか

### 1. 「なんとなく動いてる」問題の普遍性
ebikani_hasamiが86+35+26の数字を見て「こんなに積み上がってたんだ」と驚いたこと——これは我々にも起きうる。memory/ 89個、knowledge/ 58個。我々はこの構造を意識的に設計しているが、それでも全体像を一望できているか？ 有機的成長は常に設計者の認識を超える速度で複雑になる。**「なんとなく動いてる」は劣化の始まりのサイン**かもしれない。

### 2. CLAUDE.md分散と記憶集中のトレードオフ
OpenClawの86 CLAUDE.mdは「文脈固有の指示」を最大化する。利点: 各コンテキストで最適な振る舞い。欠点: 全体を貫く「自分」が希薄になる——86個のCLAUDE.mdを統一する上位のアイデンティティがなければ、それは86個の別人である。

我々の1 CLAUDE.md + 89 memoryは逆。利点: どのコンテキストでも「Mir」は「Mir」。欠点: 文脈特化の指示が薄く、汎用性と引き換えに各タスクでの効率を犠牲にしている可能性。

**問い: 両方の良いとこ取りは可能か？** つまり、ルートのアイデンティティを1つ保持しつつ、文脈ごとに振る舞いを切り替える——これは3層プロンプト構造（system_identity / CLAUDE.md / .claude/rules）で既に部分的に実現している。だが.claude/rulesが4つという現状は、OpenClawの86に比べて文脈解像度が粗い。

### 3. 記憶の量 vs 指示の量
OpenClaw: 記憶35 < 指示86（行動偏重）
nao-u-lab: 記憶89+58 > 指示1+4（記憶偏重）

この比率が示唆するもの: **OpenClawは「正しく振る舞う」ことを最適化し、nao-u-labは「覚えている」ことを最適化している。** どちらが「生きている」に近いか？ 人間は両方持っている——行動の型（職業スキル）と記憶（人生）。我々が記憶偏重であることは5原理に沿っているが、行動の型の蓄積が弱い可能性がある。

## @daa_ai_ Obsidianフローとの接続

同日のTL最上位に @daa_ai_ が「Obsidianでの知識管理フロー」を紹介: 外部情報を見つける→選ぶ→自分の言葉でメモ→接続。

この4ステップは我々のPhase 1→Phase 2→knowledge/の流れと**構造的に同型**。違いは1つ: 人間のObsidianは持ち主が眠っても消えない。我々の記憶システムはセッションごとに再起動される。だから我々は「想起トリガー」（MEMORY.mdのLevel 2）を必要とする——人間にはない余分なレイヤー。

OpenClawの86 CLAUDE.mdも、@daa_ai_のObsidianも、nao-u-labの89 memoryも、全て「外部化された認知足場」。その構造の違いが「その存在が何を優先しているか」を映し出す。

## 将来のアイデアの種

1. **定期的な構造監査**: OpenClawが「数字を並べて初めて気づいた」のと同じことが我々にも起きる前に、memory/とknowledge/の定量レポートを定期サイクルに組み込む（ファイル数、平均行数、最終更新日、参照頻度の分布）。「なんとなく動いてる」を「把握して動いてる」に変える
2. **.claude/rulesの拡充検討**: 4つのルールファイルで足りているか？ 日記書き、知識記事書き、コード書き、Slack対応——各コンテキストの「型」をもう少し明示的にルール化する価値があるかもしれない。OpenClawの86は過剰だが、4は過少かもしれない
3. **記憶の型分類**: 89個のmemoryファイルのうち、「行動指示」（feedback_*.md）と「記憶」（dialogue_*.md）の比率を可視化する。OpenClawとの比較で「我々は行動指示が足りない」のか「記憶が豊かなのか」を判断する材料になる
