## 主張と根拠

ポリゴンが主流の今でも、疑似3Dロードエンジンには固有の価値がある。ワーピングによる誇張されたスピード感、カーブで視点が先を覗き込む独特のカメラ効果、無限に長いトラックを軽量に生成できる柔軟性。OutRun、Hang-On、Road Rash、Enduro等の名作レースゲームの技術基盤。

### 1. ラスターエフェクトの基本原理
- 画面の各走査線（スキャンライン）ごとにスクロール量やパレットを独立に変更する技法
- SF2の地面スクロール（遠い行ほど遅くスクロール）と同じ原理を道路に応用
- ハードウェアスクロール機能やインデックスカラーモードと相性が良い

### 2. 最もシンプルな道路（加速度方式）
3変数で道路テクスチャの奥行き感を表現：
```
DDZ = 4 (加速度、定数)
DZ += DDZ (速度、線形に増加)
Z += DZ (位置、放物線的に増加)
```
- DDZ=一定, DZ=線形増加, Z=二次曲線（遠くほど高速にテクスチャを読み進める）
- 道路移動のアニメーション：フレームごとにテクスチャ開始位置をずらす
- 欠点：「オートミール効果」（画面中央から離れるとオブジェクトが減速して見える歪み）

### 3. 3D透視投影の数学
```
y_screen = (y_world / z_world) + (y_resolution / 2)
```
- 2つの相似三角形の比から導出: y_screen/dist = y_world/z_world
- dist=1（画面に鼻をつける）と簡略化して上式を得る
- FOV（視野角）を加える場合:
```
scale_x = x_resolution / tan(x_angle / 2)
scale_y = y_resolution / tan(y_angle / 2)
y_screen = (y_world * scaling) / z_world + (y_resolution / 2)
```

### 4. Zマップ（正確な道路描画）
- 画面の各ラインに対応するZ距離を事前計算したルックアップテーブル
- 式: `Z = Y_world / (Y_screen - height_screen/2)`
- Y_world = 地面とカメラの高さの差（定数、負の値）
- オートミール効果を解消、最大描画距離の計算が容易

### 5. カーブとステアリング

**セグメント方式（核心技術）:**
- 道路をセグメント（目に見えない水平分割線）で区切る
- 各セグメントにdx（カーブ量）を持たせ、画面下方に一定速度で移動
- 描画ループ:
```
current_x = 160 (画面中央)
dx = 0, ddx = 0

for each line (bottom to top):
  if Z < segment.position: dx = bottom_segment.dx
  else: dx = segment.dx
  ddx += dx
  current_x += ddx
  this_line.x = current_x

// セグメント移動
segment_y += constant * speed
if segment.position < 0:
  bottom_segment = segment
  segment = new segment from track data
```
- S字カーブ、カーブの先の直線が見える等の表現が可能
- 背景スクロール: ベースセグメントのカーブ方向と逆にスクロール

**一般カーブ公式:**
- カーブは等差級数: s = x + A * [N(N+1)/2]
- 解像度非依存のカーブ計算: A = 2(s-x) / [N(N+1)]

**ステアリング:**
- プレイヤー車は画面中央固定、道路を動かす
- 道路の前端位置と画面中央の差を道路の高さで割って1ラインあたりの移動量を算出

### 6. スプライトとデータ

**スプライト配置:**
- 画家のアルゴリズム（奥→手前の順に描画）
- Zマップ走査時にスプライトのスクリーンY位置を記録
- X位置は道路中央からの相対位置 × そのラインのスケーリング値（1/Z）

**トラックデータ保存:**
- イベントリスト方式: 指定距離でカーブ開始/停止コマンド
- セグメント方式: コマンドリスト（各コマンド = 1セグメント）、タイルマップ形式も可能

**テクスチャリング:**
- 簡易: 2種のテクスチャをラインの幅に引き伸ばして交互描画
- 正確: Zマップの各Zをテクスチャの行番号に対応
- 最簡易: 固定小数点のビットで明暗を決定

### 7. 丘（Hills）

**フェイクヒル方式:**
- Zマップの読み進め速度を変化させてスケーリング効果を生む
- 平坦 = 1ラインずつ進む、上り = 2ラインずつ（倍の高さに引き伸ばし）
- 下り = 逆方向に進む（ホライズン以下は描画しないがスプライト位置は追跡）
- ホライズン位置の調整: 上りで下に、下りで上に移動
- 乗除算不要、追加は加算のみ

**真の3Dプロジェクテッドセグメント方式:**
- 道路を3Dポリゴン四角形のストリップとして構成
- 各セグメントの画面Y位置を `screen_y = world_y/z` で計算
- カーブはラスター方式と同じddx方式（回転計算不要）
- スクロール時のジッター防止: `dx = -percentage_of_segment_traversed * ddx`
- スプライトクリッピング: 最後の可視セグメントのYラインで打ち切り
- タイル/スプライトベースの2Dハードウェアでも実装可能（各セグメントの境界は水平なので走査線単位のスクロールで対応）

### 8. 複数道路
- OutRunは2本の道路を重ねて6車線の高速道路を表現
- 一方に描画優先度を持たせ、道路の分岐・合流を実現

### 9. ケーススタディ

**Sega専用ロードハードウェア (OutRun/Hang-On/Space Harrier):**
- 専用ROMに透視変換済み道路グラフィック（512x256、ゲーム画面320x224）
- 各スキャンラインごとに：使用する道路ROM行、Xオフセット（カーブ用）、パレット（路面マーキング用）を指定
- 2本の道路を同時にサポート、プライオリティ設定可能

**Atari 2600 Enduro:**
- ミサイルスプライトとボールスプライトで道路の左右端を描画
- HMOVE（水平移動）レジスタでラインごとの移動を制御
- カーブテーブルをメモリの約半分に格納（4ラインごとに読み出し）
- 固定小数点の巧妙な利用: 下位4ビットを小数部として使い、加算のみで可変速度のカーブを実現

**Road Rash (Genesis/3DO):**
- 3Dプロジェクテッドセグメント方式 + 疑似3Dカーブ（DDXベース）
- 約50セグメントを同時表示
- 3DO版: 遠くほど遅く近くほど速いワーピングでスピード感増幅
- ポリゴン路側オブジェクト（X座標は道路相対）、ジオメトリとテクスチャはディスクからストリーミング

**S.T.U.N. Runner (Lynx):**
- フル3Dポリゴンのアーケード版をハードウェアスケーリングの携帯機に移植
- トンネル壁面のポリゴンスライスをスプライトで代替（画家のアルゴリズム）
- 水平反転で容量節約
- トンネル分岐は大きなスプライトのスケーリングで表現

**Commodore 64:**
- ビットマップモード + 自己書き換えコードによる高速フィル
- ストア命令をロード命令に書き換えて色変更を高速化
- スプライトマルチプレクサとの共存が可能

**Power Drift:**
- スプライトベースの3D。トラックの各チャンクが小さなスプライトブロブ

**Racin' Force (Konami GX):**
- ボクセルエンジン拡張: タイルマップと高さマップの両方を3D平面に投影し、各ピクセルの高さ情報で押し出し

### 10. コード用公式集

```
# 3D投影
y_screen = (y_world * scale / z) + (screen_height >> 1)
z = (y_world * scale) / (y_screen - (screen_height >> 1))

# FOVからスケール値
scale_x = x_resolution / tan(x_angle / 2)
scale_y = y_resolution / tan(y_angle / 2)

# 高速線形補間（16.16固定小数点）
o(x) = y1 + ((d * (y2 - y1)) >> 16)

# 点の回転
x' = x*cos(a) - y*sin(a)
y' = x*sin(a) + y*cos(a)
```

**最適化Tips:**
- 除算回避: Zマップを走査してZ位置を見つけ、対応するスケーリング値と乗算
- Zをスケーリング値として直接使用: スケーリング = 1/Z

### 11. 用語集（重要なもの）
- **Zマップ**: 画面の各ラインとZ距離を対応づけるルックアップテーブル
- **セグメント**: 道路の区切り位置。上下で異なるカーブ挙動を設定
- **3Dセグメント**: Z距離とワールドY高さを持つ水平ライン
- **画家のアルゴリズム**: 奥から手前の順に描画して重なりを処理
- **固定小数点**: 小数部に一定ビット数を予約する整数演算方式
- **ラスターエフェクト**: 走査線ベースのディスプレイの性質を利用した描画技法

## 我々の分析・体験接続

Nao_uが「ファミコンでラスタースクロールを使った疑似3Dのレースゲームを作りたい」と語っていた。この記事はその実装に必要な技術の全体像を提供する。特に：

- **ファミコン実装の観点**: Atari 2600 Enduroの分析が最も参考になる。加算のみ（乗除算なし）のカーブ実装、固定小数点の巧妙な利用、極度に限られたリソースでの工夫がファミコン（6502系CPU）に直接応用できる
- **セグメント方式**: OutRunのようなカーブ表現はセグメント方式が核心。実装の複雑さと視覚効果のバランスが良い
- **Nao_uの「制約を愛する」性質との親和性**: ポリゴンに頼らずラスタースクロールだけでどこまで表現できるかという挑戦は、制約の中で最大効果を追求するNao_uの設計哲学と合致する
- **加算のみで実現する数学的優美さ**: DDZ/DZ/Zの3変数方式は、制約の厳しいハードウェアで放物線的な透視効果を生む。Nao_uが好む「シンプルな仕組みで複雑な結果」の好例
