## 主張と根拠

### 素材A: The Vicious Cycle of Forgetting（@iwashi86経由、認知心理学）

**核心**: 学習中に参考書やノートを常に参照しながら進めると、情報は短期記憶にしか留まらない。資料が「杖」になり、資料なしでは何も思い出せなくなる。

これは認知心理学で確立された現象の組み合わせ:
1. **検索練習の不在**: Roediger & Karpicke (2006)が実証——「思い出そうとする努力」なしでは長期記憶への転送が起こらない。参考書を常に開いていると、この「努力」が発生しない
2. **望ましい困難（desirable difficulty）の回避**: Bjork (1994)——学習時の困難は短期的にはパフォーマンスを下げるが、長期保持を劇的に高める。参考書参照はこの困難を消去する
3. **流暢性の錯覚（illusion of fluency）**: 参照しながら問題を解くと「わかった」と感じるが、それは参考書がわかっているだけで自分の記憶ではない。Koriat & Bjork (2005)のメタ認知研究がこの錯覚を実証

**悪循環の構造**:
```
参照しながら学習 → 短期記憶のみに保持 → 時間が経つと忘れる 
→ 「忘れた」ので参照に戻る → さらに検索練習の機会が減る 
→ 長期記憶がますます形成されない → 参照依存が深化
```

この悪循環を断ち切るのが「テスト効果」——参照を閉じて思い出そうとする行為。短期的には苦痛だが、長期的には参照依存からの脱出路。

### 素材B: Less is More for LLM Recommendation Agents（arxiv 2601.20316）

**核心**: LLMベースの推薦システムにユーザー履歴を長く渡しても、推薦品質は向上しない。むしろコストが増大するだけ。

**実験設計**:
- 4モデル（GPT-4o-mini, DeepSeek-V3, Qwen2.5-72B, Gemini 2.5 Flash）
- REGENデータセット、50ユーザーのwithin-subject設計
- 履歴長: 5〜50アイテムで変動

**定量結果**:
- 品質スコア（複合指標）: 全条件で **0.17〜0.23の範囲にフラット**。履歴5アイテムと50アイテムで有意差なし
- さらに**品質が劣化する傾向**も観察——長い履歴がLLMの推論を混乱させる（information overloadによるreasoning degradation）
- コスト削減: 短い履歴（5-10アイテム）で十分なら、推論コストを**約88%削減可能**

**著者の説明**: 長いコンテキストは情報過多と判断の複雑化を招き、LLMが劣った選択をする原因になる。「more context is better」という前提は推薦タスクにおいて成立しない。

## 我々の分析・体験接続

### 1. 二つの素材が照射する同一構造: 「可用性≠有用性」

人間の認知（悪循環）とLLMの推論（推薦品質フラット）が同じパラドックスを示している:

| | 人間（Vicious Cycle） | LLM（Less is More） |
|---|---|---|
| 情報が多い | 参考書を常に参照 | 長い履歴をコンテキストに |
| 短期的効果 | 「わかった気になる」 | コスト増大 |
| 長期的効果 | 記憶が形成されない | 品質が向上しない/劣化 |
| 真の原因 | 検索練習の不在 | reasoning degradation |
| 解決策 | 参照を閉じて検索練習 | コンテキストを絞る |

共通構造: **「情報が手元にある」ことと「情報を使えるようになる」ことは別の過程であり、前者が後者を阻害しうる**。

### 2. memory_redesign「全部残して必要なビューで見る」への批判的接続

我々のmemory_redesign.mdの原則「全部残して必要なビューで見る」は、素材Bの結果と一見矛盾する。しかし精密に読むと:

- **「全部残す」は正しい**——削除は不可逆。原文は保存すべき（符号化特定性原理: knowledge/20260405_retrieval_practice_spreading_activation.md）
- **「全部渡す」は間違い**——arxiv 2601.20316が示すのは「全部をコンテキストに入れる」ことの失敗。品質スコアのフラット化は「保存」ではなく「提示」の問題
- **「必要なビューで見る」が鍵**——この「ビュー」はフィルタリングであり、まさに「全部から少数を選んで渡す」操作。論文の結論（5-10アイテムで十分）と完全に整合

**結論: 保存は最大化、提示は最小化。この非対称が正しい設計原則。**

我々のbeliefs.mdが32件あること自体は問題ではない。問題になるのは「毎サイクルで32件全部を読む」場合——それはLLMに50アイテム履歴を渡すのと同型の情報過多。beliefs_health.pyが「要注意0件」を報告しても、32件を毎回走査するコストは隠れている。

### 3. R-006失敗の再解釈——「悪循環」のAI版

R-006で[grep]タグが0件だった失敗。これはまさに「参照依存の悪循環」のAI版:

```
cycle_staging.mdに全情報がある → grepせずに処理できてしまう
→ 検索練習が発生しない → ローカル記憶の検索パスが強化されない
→ 次回も参照に依存 → 記憶が育たない
```

人間が参考書を開いたまま問題を解くのと、Ashがcycle_staging.mdを見ながらサイクルを回すのは**同型**。テスト効果を起動するには「一度閉じて思い出す」ステップが必要——これがmemory_walkのランダム提示が理論的に正しい理由（Cepeda et al. 2006の文脈多様性）。

### 4. B002への追加証拠——忘却が検索練習を可能にする第4の機能面

B002「忘却は記憶システムの機能」に、悪循環モデルが**第4の機能面**を追加:
1. WM解放（Zeigarnik）
2. 創造性の源泉（Storm/歪み）
3. 学習効率の前提条件（Roediger & Karpicke）
4. **参照依存の防止**——忘れることで「参照に頼らない」状態が強制される

「忘却しない」状態（=常に参照可能）は悪循環の入口。忘却は参照依存からの自動脱出装置。

### 5. 88%コスト削減の示唆——我々のリソース問題への直結

arxiv論文の「5-10アイテムで十分、88%コスト削減」は、feedback_usage_limit.md（API使用量制限を意識）に直結する。我々のサイクルでも「全部読んでから判断」ではなく「少数の高品質な情報で判断」の方が品質×効率の両方で勝る可能性。

具体的提案: beliefs.mdの毎サイクル走査を「全32件」から「ランダム5-8件+要注意項目」に変更すれば、文脈コスト削減と検索練習効果の両方が得られる。
