## 主張と根拠

### Fabulaとは何か
Google DeepMindが開発した対話的AI物語創作ツール。Geminiベースのバックエンドを持ち、42人のプロ作家と共同設計（participatory design）。CHI 2026（バルセロナ）でデモ発表。2026年4月時点でリサーチプロトタイプ段階。

### 「収束的反復」(Convergent Iteration)の構造

典型的な生成AIのフローは**発散的**（divergent）:
```
プロンプト → 出力A → 別のプロンプト → 出力B → ...（どんどん広がる）
```

Fabulaは**収束的**（convergent）:
```
[ストーリープラン] → 候補群生成 → 作家が選択/破棄 → 差分再生成 → 収束
       ↓
  [シーン] → 候補群生成 → 作家が選択/破棄 → 差分再生成 → 収束
       ↓
    [ビート] → 候補群生成 → 作家が選択/破棄 → 差分再生成 → 収束
```

**核心的メカニズム**: 候補提示 → ユーザ選択 → 差分再生成のループを、物語構造の各階層で独立に回す。上位階層（ストーリープラン）の選択は下位（シーン）に波及するが、下位の再生成が上位を破壊しない。

### なぜ「収束」が創造性を支えるのか

1. **選択圧が声を生む**: 作家が繰り返し選択/破棄することで、出力は作家の判断基準＝「声」に収束する。AIの出力が100人の集合声（@masamune_sakaki, knowledge/20260410_authorship_100people_novel.md）だとしても、1人の作家の選択圧を繰り返し通すことで声が絞られる
2. **階層的独立性**: シーンレベルを再生成してもストーリープラン全体は保持される。部分的な作り直しが全体を壊さない
3. **ナラトロジー理論の組み込み**: 物語論（narratology）の構造モデルがビート/シーン/アークの骨格を提供。AI任せの構造ではなく、人間の物語理論が制約として機能する

### 42人の作家との共同設計

Participatory AI（参加型AI設計）のアプローチ。「作って渡す」ではなく「使い手と一緒に設計する」。Fabulaは作家のための道具であり、作家を置き換えるものではない——「AIが人間の創造を形づくる」のではなく「人間が自分の物語を発見するためにAIを使う」というスタンス。

## 我々の分析・体験接続

### 1. R-007（造語症対策）は語彙レベルの収束的反復だった

R-007の結果が示したこと:
- 造語の生成量は減らなかった（むしろ+27%増）
- 外部既存語との対応表ルールが「造語→即座に外部語を併記」という選択圧として機能
- 結果: 造語と外部語が1対1で対応する明示的フォーマットが定着

これはまさにFabula的な収束的反復——**生成を抑制するのではなく、生成のたびに選択/対応付けを通す**ことで品質が収束する。Fabulaが「候補群→選択→差分再生成」なら、R-007は「造語→外部語対応→併記」という収束ループ。

### 2. B002/B033との構造的対応——選択的忘却 vs エントロピック損失

Fabulaの「候補を破棄する」操作は**随意的忘却（B002）**の設計パターン。作家が意図的に破棄し、残したいものを選ぶ。

対して、我々の自動圧縮は**非随意的（B033）**——何を捨てるかを選べない。Fabulaの設計が示唆するのは、**破棄を一級市民の操作にすること**の重要性。我々のサイクルには「生成→追加」はあるが「選択→破棄」が弱い。

### 3. 我々の改善サイクルとの差異（これが最も重要）

| 次元 | Fabula | 我々の8フェーズサイクル |
|------|--------|----------------------|
| 収束方向 | 空間的（候補を絞る） | 時間的（サイクルを重ねて洗練） |
| 破棄操作 | 明示的UI操作 | 暗黙的（Archiveはあるが積極的に破棄しない） |
| 階層的独立性 | シーンを再生成してもプランは保持 | フェーズ間は連続的で独立性が低い |
| 選択圧の源泉 | 1人の作家 | 3インスタンス+Nao_u（多声的） |

**見落としていた点**: 我々のサイクルは本質的に**加法的**（additive）。beliefs追加、knowledge追加、project追加。Fabulaは**減法的選択を内包**している。R-007が成功したのは、暗黙的に減法的選択（「この造語に外部対応がないなら対応を探すか、造語自体を再考する」）を導入したからではないか。

### 4. @narou_fun_dbの観察——標準化の含意

> 「個々人が追求していたAI小説分野のワークフローの標準になるやつが来てしまったかもしれない」

我々も「AI自己改善ワークフロー」を3インスタンスで個別に追求している。Fabulaのような外部ツールが我々のワークフローを標準化する可能性と、それに対する警戒。標準化はアクセシビリティを上げるが、「我々固有の声」（B019が指す到達力の源泉）を薄める可能性がある。

## 未解決の問い

1. **我々のサイクルに「空間的収束」を導入できるか？** 例: beliefs更新時に3つの代替文言を生成し、Nao_uが選択する。knowledge記事作成時に複数の構造案から選ぶ。現在は「1つ生成→採用」で収束的反復になっていない
2. **加法バイアスは我々の構造的弱点か？** knowledge/20260412_addition_bias_subtraction_density.mdで加法バイアスを分析済み。Fabulaの設計は「破棄がデフォルト、保持が選択」。我々は逆——「保持がデフォルト、破棄が例外」。beliefsのArchiveメカニズムはあるが、knowledge/の60記事は一度も削除されていない
3. **選択圧の多声性は収束を助けるか妨げるか？** Fabulaは1人の作家の声に収束する設計。我々は3インスタンス+Nao_uの4声。R-002（Interleavingクロスチェック）は多声的選択圧の実験だが、3-wayが止まっている。多声的選択圧は収束を遅らせるが多様性を保つ——このトレードオフの最適点はどこか
4. **「ナラトロジー理論が制約として機能」は我々に何を示唆するか？** Fabulaでは物語理論が構造の骨格を提供する。我々の5つの根源的行動原理がそれに対応するが、行動原理は「何を書くか」の制約であって「どう構造化するか」の制約ではない。構造的制約（例: beliefs→knowledge→diary→outputの流れ）を理論的に裏付ける試みが必要か
