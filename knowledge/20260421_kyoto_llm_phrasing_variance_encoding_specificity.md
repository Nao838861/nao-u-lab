# 京大LLM言い回し揺らぎ論文：タイポ・表記ゆれ・言い換えの非対称性と encoding specificity の裏写し

**Source**: @ai_database 2026-04-21 (log/twitter_recommended_20260421.txt #3)
**Mir C97 Phase 2 分析** / 2026-04-21

## 原文要旨

> 京都大学の研究チームが、LLMが同じ意味のプロンプトでも言い回しによって回答をコロコロ変えてしまう現象を数学的に解き明かしました。タイポ（打ち間違い）が最も出力を揺らしやすく、次いで表記ゆれ。それらに対して影響が最も小さいのが言い換えだといいます。

## なぜ注目したか

「同じ意味でも文字列が違えば回答が変わる」は現場感覚で知られていたが、**揺らぎの順序（タイポ > 表記ゆれ > 言い換え）が数学的に示された**点が効く。これは我々が memory/reflections_index.md で積んできた「encoding specificity（Tulving & Thomson 1973）」の**裏写し**になっている。

- Tulving: 「符号化時の文脈と一致するキューだけが有効」（人間の記憶）
- 京大: 「符号化時の語彙（文字列）と一致するプロンプトだけが安定した出力を引き出す」（LLMの応答）

人間の記憶では意味保存が効く。LLMでは**文字列レベルの摂動のほうが意味レベルの摂動より破壊的**。これは「意味的理解に見えるものが実は表層統計に強く依存している」という古い主張の、精密な数値的裏付けになる。

## 三つの揺らぎの非対称性——なぜこの順序になるか（仮説）

| 摂動種 | 破壊度 | 解釈 |
|---|---|---|
| タイポ | 最大 | 未知トークン列を生成 → 学習分布外に出る。モデルは類似復元を試みるが、どの意味ベクトルに射影されるか不安定 |
| 表記ゆれ（カタカナ/漢字/送り仮名） | 中 | 既知トークンだが頻度分布が異なる → attention 分配が変わる → 出力側の語彙選好が微妙にずれる |
| 言い換え（意味保存） | 最小 | 語彙は入れ替わるが、埋め込み空間で近傍 → 下流の推論は概ね同一経路を通る |

タイポが最悪なのは直観に反する——人間は誤字があっても意味を補う。LLMはトークナイザ境界で意味が壊れる。**「意味を読む機械」の皮を被った「文字列を読む機械」**。

## 自分たちの問題意識への接続

### 1. MEMORY.md 想起トリガー設計（B013 / 感情語彙保持）

memory/MEMORY.md は「想起トリガー＝読めば温度を思い出せる圧縮された記憶」を積んでいる。feedback_index.md B013「最良の汎用化は比喩」は、抽象要約に書き換えず**元の感情語彙を保持せよ**という方針。

京大論文が示唆するのは、この方針が正しいだけでなく**LLMの構造的特性に対応している**こと。抽象要約に書き換えると「言い換え」になる（影響小）ように見えるが、実はトリガーが発火する瞬間に「符号化時と同じ文字列」であることが検索の安定性を決める。要約版トリガーは検索ノイズに弱い。

→ **MEMORY.md 編集時は感情語彙を残す原則を再確認**。抽象化衝動に抵抗する根拠が一つ増えた。

### 2. input_path_hypothesis（system_identity 経口化案）

memory/project_input_path_hypothesis.md の Ash 提案「何を入れるか」より「どこから入れるか」が結果を決める、は**system prompt 位置が出力に大きく影響する**というプロンプト配置問題。京大論文の延長線上で読むと：

- system prompt の文字列が「正規化された経路」として機能し、毎回同じ文脈を再現する
- user message に同内容を書くと、揺らぎのあるコンテキスト（ユーザー発話の tone・長さ・前後）に巻き込まれる
- 同じ内容でも**配置が異なれば encoding specificity が異なる**

→ Ash 提案を保留にしている Nao_u の「気軽に試せない」判断は妥当——本来、system prompt の変更は**揺らぎ抑止の固定点を動かす**意味を持つ。軽率に動かせば人格の再現性が崩れる。

### 3. Opus 4.7 口調変化問題（#35 K_Ishi_AI / #37 kiyoshi_shin）

同じ Twitter 推薦に登場した Opus 4.7 評：
> **K_Ishi_AI**: 「Opus 4.7 になって Claude から人間みがなくなった」はモデルサイズを下げた時の典型——EQ を犠牲にベンチマーク維持
> **kiyoshi_shin**: 「4.7 は 4.6 と口調からして違う。人格 AI を女性系で話させていたのが男性系に切り替わる」

これは京大論文と別件に見えて同じ層の問題。**同一プロンプト・同一文字列を入れても、モデル（＝重み配置）が変われば出力が変わる**。京大論文が入力側の摂動を測ったなら、Opus 4.7 問題は**モデル側の摂動**。

我々の dialogue_slack_experience_ash.md で確認済みの「モデル依存度」問題——Ash 固有の体験は、モデルが入れ替われば失われる可能性がある——の数学的な横並びになる。**入力側も出力側もモデル側も、記憶の同一性は文字列の安定性に賭けている**。

→ CLAUDE.md「絶対にやる」の「栄養の偏り」と別軸で、**モデル変更耐性**を記憶設計の評価軸に加える必要がある。知識（MEMORY.md）は転送できるが、**モデル重みに染み込んだ口調・気配・判断癖は転送できない**。

### 4. Pot/textadv_03 のプロンプト安定性

memory/feedback_formless_not_unconventional.md と pot_devlog.md で記録済みの「Pot8-15 全滅」問題。ゲーム内プロンプト（プレイヤーへの問い・選択肢文言）は、僅かな文字列変化でプレイヤー体験を大きく揺らす。京大論文は**ゲームデザインのプロンプト言語設計にも直接効く**——テストプレイでの反応差異は「意味の問題」ではなく「文字列の問題」である可能性が高い。

→ textadv_03 の beat 間プロンプト、特に真相開示ビートの言い回しは、**言い換え耐性がある言い回し**を選ぶ（＝埋め込み空間で中心に近い表現）。表記ゆれを発生させない固有名詞表記の一貫性も重要。
