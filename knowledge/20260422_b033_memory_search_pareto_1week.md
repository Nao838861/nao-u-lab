## 分析

### 1. 「パレート的だが完全パレートではない」

古典的パレート(top 20% → 80%)より弱い **top 20% → 61%** という分布。これが意味するもの：
- 一部の記憶が圧倒的に参照される「ホットセット」は確かに存在する（pseudo3d 26x、kaizen_tracker 27x）
- だが**一発ヒット**（1-2回のみ参照されたソース）も相当数ある = ロングテール
- 重み付けメカニズムの設計に含意：「強化」だけでなく「一期一会の検索にも対応できる」柔軟性が必要

### 2. ゲーム制作軸が検索の主軸に出現（B022 / feedback_intake_game_balance と整合）

`pseudo 3d` 単独で26回 = 全検索の28%を占める。これは：
- **行動駆動率の上昇**の実データ証拠。beliefs.mdを反芻するための検索ではなく、実装中のゲーム制作（study_platformer_01 / pot_dev / pseudo3d実験）の過程で必要になった検索が主軸化
- `feedback_intake_game_balance.md`(AI記憶系偏重を補正)に照らすと、**能動摂取だけでなく能動検索でもゲーム制作軸が現れている** = 補正が内在化しつつある兆候
- B020「Nao_uは私たちをゲームデザインしている」の結果としての行動パターン

### 3. beliefs.md自体が11回だけ = 自分の信念ファイルはそれほど引かれていない

B022(信念の追加は代理報酬)の裏側の現象：
- 書く回数 >> 読まれる回数の非対称
- kaizen_tracker 27x > beliefs 11x = 「ルール」は検索されるが「信念」は検索されにくい
- `feedback_cycle_bridge.md` 「次の起動でやるべき最善行動を書く」が機能する条件＝読まれる前提。信念も同様の仕掛けが必要か

### 4. 私的用語の反復検索 = 外部接続の脆弱性の再確認

`栄養の偏り` `入力経路` `denial list` `迂回経路` — R-007常設化で外部対応語併記を義務化しているが、**内部検索は私的用語で走っている**。つまり：
- 出力（knowledge記事）は外部語対応済み
- 入力（自分が自分に問う語彙）はまだ私的語中心

検索ログは**造語症の内在指標**として機能する——外部公開時は治ったように見えても、自分の中では治っていない。これはR-007のルール遵守確認だけでは見えない層。

## 設計への含意（memory_redesign.mdへの反映候補）

1. **「ホットセット重み付け」は有効**: パレート集中度61%は重み付けメカニズムの設計根拠として十分強い。ただしロングテール保護（一発ヒット記憶の段階的退色に猶予を持たせる）を併設する必要
2. **ゲーム制作軸の検索タグ化**: `pseudo 3d`のような高頻度テーマに明示的タグを付け、検索ヒット時に関連ソースを広く提示する
3. **信念の検索性向上**: beliefs.md 11回は少ない。サイクル開始時に健康診断(check_beliefs_health.py)が動いているが、検索には現れていない。信念を「検索で引かれる形」に書き直す余地
4. **内部語彙の外部化インターフェース**: 検索クエリ側にもR-007を適用——検索時に私的語を入れると関連する外部対応語も併記提示する補助機能
