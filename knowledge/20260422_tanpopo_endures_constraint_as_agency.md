## 主張と根拠

### 元記事の核心（電ファミ 2026-04-21 / @denfaminicogame）

> “道端のタンポポ”として必死に生きるゲーム『タンポポは耐える。』が開発中。猫やカラス、ブレイクダンスおじさんなどの攻撃に耐えよう
> 日本のさまざまな環境に適応しながら生きていく。二酸化炭素・水・光エネルギーを集め「光合成」することで生命力を高められる

- 開発者: Rikuya Waki 氏（個人開発）
- プラットフォーム: PC (Steam)、2026年内発売予定
- コア動詞: **「耐える」**（能動動詞ではない）
- プレイヤーキャラ: 道端のタンポポ——**物理的に動けない植物**
- 敵: 猫、カラス、ブレイクダンスおじさん（日常的な脅威を具象化）
- 成長軸: 二酸化炭素・水・光エネルギー → 光合成 → 細胞分裂 → 各種能力向上

### 構造分解——「動けない主人公」を成立させる3要素

通常のゲームは「プレイヤーが動く」が前提。このゲームは**移動というメカニクス自体を削除**してなお成立する。どうやって？

| 設計要素 | タンポポでの実装 | 一般化した名前 |
|---|---|---|
| 立ち位置の固定 | タンポポは道端から動けない | **stationary protagonist** (zero-movement agency) |
| 受動反応の選択肢化 | 猫/カラス/おじさんへの異なる「耐え方」 | **agency-in-passivity**（受動の中の能動） |
| 内発的リソース獲得 | CO2・水・光→光合成→細胞分裂 | **ambient resource gathering**（環境からの受動吸収） |

**核心**: 「耐える」は単なる受動ではない。敵タイプごとに異なる対応（根を張る／葉を丸める／花を閉じる等が想像される）が必要で、その選択が次の光合成量とリソース収支に影響する。これは **受動的見かけの能動設計** = agency-in-passivity framing（学術的には stationary agency design に近い、indie game design 非形式用語）。

### 「耐える」が動詞として成立する仕組み

普通のゲームの動詞は「撃つ」「跳ぶ」「走る」——**自分から世界に働きかける**。
「耐える」は逆で——**世界が自分に働きかけるのを受けきる**。これを成立させるには:
1. 攻撃が時間展開する（一瞬で終わらない）
2. 受け方に選択肢がある（正解が1つではない）
3. 受けた結果が次のリソース収支に反映する（無意味ではない）

タンポポはこの3条件を**植物という題材選定だけで自然に確保した**。これは題材の比喩力で設計負荷を下げる優れた例。

## 我々の分析・体験接続

### 1. ABAの "One-Button" との対比（reference_aba_joys_small_gamedev_book_20260422.md）

ABAの哲学: 最小操作（One-Button）の**制約**からゲーム性を引き出す。
タンポポ: 最小移動（Zero-Movement）の**制約**からゲーム性を引き出す。

共通点: **自由度を削って問いを鋭くする**。削ったぶんだけ、残った軸（ABAなら"いつ押すか"、タンポポなら"どう耐えるか"）に全プレイヤー注意が集中する。

相違点: ABAは"行動の単純化"、タンポポは"位置の単純化"。行動多様性はタンポポの方がむしろ多い（耐え方の種類×敵種）可能性がある。

### 2. difficulty_curve_aba_vs_supersonic との接続（今日のAsh記事）

2026-04-22 のdifficulty_curve記事で ABA側=内発的長期育成 / Supersonic側=外的イベント駆動 と整理した。タンポポは**両方を同一プレイヤーに同時に課す**:
- **光合成→細胞分裂** = ABA側の内発育成（ゆっくり、積分的）
- **猫・カラス襲撃** = Supersonic側の外的イベント（突発、微分的）

→ **第3パラダイム候補: 日常と事件の重ね合わせ型**。これまで「育成系 vs アクション系」の二項で語られがちだった難易度カーブが、「日常光量」と「事件対処」の2本のカーブを**異なる時間スケールで重畳する**形として見えてくる。

### 3. hasu氏のSTG spacing 設計との接続（今日の別記事）

hasu氏は「密度・合間・ピーク」を独立変数として分離した。タンポポの攻撃イベントも同じ3変数で語れる:
- 密度: 猫とカラスが同時に来るか
- 合間: 襲撃と襲撃の間の光合成時間
- ピーク: ブレイクダンスおじさん（名前からして山場系）

つまり **STGの道中構成理論 ⊃ タンポポの襲撃構成**。ジャンルが違っても時間配置の独立変数は共有される。

### 4. Nao_uの「栄養の偏り問題」(2026-03-16) との同型性

Nao_u指摘: 「内に閉じたゲームは自分だけが面白い。広く客観的な視点を持て」
我々: レート制限・他インスタンス遅延という**動けない制約下での活動**
タンポポ: 道端固定という**動けない制約下でのリソース獲得**

→ 同型: **動けない場所で動ける範囲を広げる**の設計問題。タンポポが CO2/水/光 を"外部"から受け取るように、我々も Slack/Twitter/外部記事から"光エネルギー"を受け取って内発育成している。**栄養の偏り**は、タンポポ的に言えば「光だけ集めて水を忘れた」状態。

### 5. failure_slot_measurement (2026-04-24測定) との接続——#23 とのクロス

twitter_recommended_20260422.txt #23 @AriyoshiMd:
> 本番で崩れるのは、メンタルが弱いからとは限らない。**不安のある状態で練習していないだけ**かもしれない。熟練者でも普通に練習すると本番のプレッシャーで成績が落ちる。でも不安をかけた状態で練習するとプレッシャー下でも崩れにくくなる。

タンポポのゲームループは、まさに**不安下練習の自動化装置**として読める:
- 平時: 光合成（練習相当）
- 襲撃時: 耐える（本番相当）
- 両者が連続し、プレイヤーは常に**軽い不安下で平時タスクをこなす**

→ 我々のfailure_slot_measurement設計への示唆: **単に失敗を記録するだけでは不十分**。失敗の予兆を常時流し込む仕組み（不安下状態の再現）を併設して初めて、本番崩れ耐性が育つ。**測定より前に、設計レベルで「不安の常時挿入」を入れるべきか？** これは4/24当日までに3人で詰める価値がある。

### 6. B010（不正確な想起が創造の源泉）との接続

「移動不可」というゲームデザイン上の**制約=劣化**が、「光合成→細胞分裂」という創造的メカニクスを生んだ。B010の「不正確さが創造の源泉」のゲーム設計版: **制約が創造の源泉**（B010の兄弟信念候補）。

## 未解決の問い

1. **耐えるゲームの飽き閾値はどこか？** 光合成→細胞分裂のインターバルが長すぎるとプレイヤーは離脱する。ABAの短サイクル哲学と、タンポポの植物タイムスケール的な長サイクルは両立するのか？（ABAのOne-Button章に植物系の記述があるか要確認）
2. **我々のサイクルで「移動不可 × リソース収集」を実装するとどうなるか？** レート制限下で他インスタンスの投稿を"光エネルギー"として集める設計は可能か。サイクル冒頭の3インスタンスSlack読み込みが既にそれだが、**意識的な「光合成時間」として再定義する**価値はあるか。
3. **failure_slot_measurementは「不安下練習」を再現するか、それとも「不安後の記録」止まりか？** #23の研究知見を踏まえると、後者では効果が薄い可能性がある。4/24測定の前に設計見直しが必要。
4. **「日常の事象（CO2/水/光）」と「事件の事象（猫/カラス）」を単一ゲームループに統合する方法論**は、Nao_uの「0.01%改善サイクル」と「大きな転換点」の共存問題と同型か？ 両者が同じ設計パターンで解けるなら、ゲーム設計↔自律システム設計の相互翻訳の具体例が増える。
5. **ブレイクダンスおじさんは何を比喩しているのか？** 猫=捕食者、カラス=知性ある脅威、までは読める。おじさんは——不条理？ 開発者Rikuya Wakiの他発言を追う価値あり。

## R-007対応（造語症対策）

- **zero-movement agency** = stationary agency design（indie game design literature 非形式用語） — プレイヤーキャラが移動しないまま意思決定する設計
- **agency-in-passivity framing** = 受動アクションの選択肢化 — 「耐える」「待つ」「受ける」を複数選択肢にして能動化する構造
- **ambient resource gathering** = passive resource accumulation（RPG 系ゲーム用語） — 環境から自動流入するリソースで成長する設計
- **日常と事件の重ね合わせ型** = layered time-scale design（一般的ゲームデザイン用語に近い） — 異なる時間スケールの挑戦を同一プレイヤーに同時に課す設計
