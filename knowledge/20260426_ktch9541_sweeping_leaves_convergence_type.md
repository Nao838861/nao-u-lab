## 主張と根拠

### 元ツイート（@ktch9541 2026-04-24）

> #ゲーム試作・実験 #Gemini
> 落ち葉を掃除するゲームを試作してみた。滑らかな物理で動く大量の粒を風で押し流して整理する。
> 飛び散らないように気を付けながら、落ち葉を一気に押し込めると爽快感がある。手際よく片付けるとちょっとしたアクションゲームに。

### 一次データの分解

| 要素 | 内容 |
|---|---|
| 制作環境 | Gemini（LLM支援） |
| 入力 | 風（プレイヤーが向きを操作する想定） |
| 物理 | 「滑らかな物理で動く大量の粒」=粒子系のリアルタイム物理シミュレーション |
| 目標 | 落ち葉を「整理する」=拡散している状態→集約している状態に変える |
| 副条件 | 「飛び散らないように気を付ける」=過剰な力を加えると逆効果 |
| 快感記述 | 「一気に押し込めると爽快感」+「手際よく片付ける」 |

ツイート単体で**ゲームデザインの核心が3行に圧縮されている**。@ktch9541 が言語化しているのは:
1. **核ループ**: 拡散 → 集約 という方向性のあるエントロピー減少
2. **緊張装置**: 過剰な力 → 飛散 という負のフィードバック
3. **快感の設計点**: 「一気に」（強い入力）と「手際よく」（精度の高い入力）の両立

### この設計が外部から見て新しい点（自然界・先行作品との対比で評価）

掃除/片付け系ゲームは新規ではない（PowerWash Simulator 2021、Unpacking 2021、A Little to the Left 2022、Viscera Cleanup Detail 2015）。**だが、それらの大半は「マイペース型」「パズル型」**であり、**「物理粒子の拡散と戦う」アクション系は希少**。@ktch9541 の試作は、片付け系の弛緩感をアクション系の緊張感で再構築している点が新しい。

ただし類似先行作品は存在する: **Katamari Damacy**（粒を集めて巨大化）, **Viscera Cleanup Detail**（液体の拡散）, **Powerwash Simulator**（汚れの除去）。@ktch9541 試作の差別化点は **「ワンボタン（風という1次元入力）+ 短時間アクション + LLM試作」** という制約の組合せ。

## 我々の分析・体験接続

### 分析1: 「整理・収束型」という第4の型を game_lessons_log.md に追加すべきか

我々は2026-04-22以降、ゲームの型を **反転 / 壁 / 永続** の3型で運用している（ash_onebutton v01 devlog.md E11-Q3 参照）。@ktch9541 試作は、この3型のどれにも収まらない:

- **反転型**: 進行方向の能動的反転（ash_onebutton）。状態遷移が離散的
- **壁型**: 障害物との衝突回避（avoid_log系）。状態が空間的拘束
- **永続型**: 蓄積する状態の管理（avoid_log_02 磁石）。状態が時系列的拘束
- **(新)整理・収束型**: 拡散している多数の粒を集約する。状態が**統計的拘束**（=粒の分散度）

整理・収束型の特徴:
- ゴール状態が**統計量**で定義される（標準偏差/分散/凝集度）
- プレイヤー入力は**個別オブジェクトではなく場（風/磁場/重力）に作用する**
- 失敗条件が「飛散」=エントロピー増加。**緊張は秩序の脆さから来る**
- 終点が明確（全粒が集約=クリア）。永続型の対極

この型の先行例:
- **Katamari Damacy**（2004）— 集約型の古典。粒ではなく成長する塊
- **Viscera Cleanup Detail**（2015）— 液体の拡散と戦う一人称ゲーム
- **A Little to the Left**（2022）— 整理欲求を満たすパズル（アクション性は薄い）
- **PowerWash Simulator**（2021）— 整理ではなく除去だが構造は近い
- **Tetris**（1984）— 落下するブロックを整理。アクション系整理ゲームの祖

**処方**: game_lessons_log.md に「**型T-04: 整理・収束型**」として追加し、ash_onebutton v02 検討時の選択肢に入れる。M-17（快感最大化を出発点に）と組み合わせると、整理・収束型は「拡散を見せる→秩序の快感→より大きな拡散」のループが快感の核。罰駆動を回避しやすい型である可能性が高い。

### 分析2: M-12「罰ではなく報酬」の好例として読む

game_lessons_log.md M-12 は「罰ベース設計を避けよ」と命じる。@ktch9541 試作を M-12 の文脈で読むと、**「飛び散らないように気を付ける」は罰のように見えるが、罰ではない**:

- avoid_log_02 のヒット=即死は**離散的な罰**（プレイヤーがゲームから排除される）
- @ktch9541 試作の飛散は**連続的な状態悪化**（拡散度が増えるが、まだプレイ続行可能）
- これは M-12 の良い例「掃除をサボると部屋が散らかる」と**完全に同型**

つまり @ktch9541 試作は M-12 の理想形を**言語化していないが実装している**。**設計者の言語化なしに M-12 が満たされる理由**は、整理・収束型という型自体が「自然な結果」を内蔵しているから。型の選択そのものが M-12 を強制する場合、設計上の認知負荷が下がる。

**反証視点（確認バイアス防止）**: @ktch9541 試作が M-12 を完全に守っていると断定するのは早計。実装次第で「飛散すると即時失敗」の罰ベース処理が入っている可能性がある。ツイートからは判別できない。試作を実際にプレイして検証が必要。

### 分析3: M-17「快感最大化を出発点に」のサプライズニンジャテスト

M-17 はサプライズニンジャテスト=「ニンジャ乱入のほうが面白いなら設計が薄い」を要求する。@ktch9541 試作にこのテストを適用:

- **このゲームの途中でニンジャが乱入したら面白いか？** → 確率的に「No」
- 理由: 落ち葉が物理的に飛散する画面で、ニンジャが乱入すると**ニンジャの動きそのものが新たな飛散源になる**。プレイヤーの「整理」のループが破綻する
- 整理・収束型は**追加要素を入れるとコアループが崩れる**性質。M-17 の Q-B（=Yes なら設計薄い）に対し**No=設計十分**を返せる構造

これは反転型 ash_onebutton との対比で重要: 反転型はニンジャを足しても面白くなる余地が大きい（=設計が薄い疑い）。整理・収束型は型自体が **追加に対する免疫** を持っている。ABA「Joys of Small Game Development」One-Button章の主張「ワンボタンは制約が答えを絞り込む」と同型構造。

### 分析4: ash_onebutton v02 候補への影響

ash_onebutton/README.md の v02 候補3つ:
1. 反転の連続タイミングでメーター蓄積→ため技放出
2. 障害物の種類に応じた報酬差
3. 反転直後の短い判定ボーナス（「紙一重」を可視化）

@ktch9541 試作を踏まえると、**4つ目の候補「整理・収束型への型ジャンプ」**が浮上する:

- **v02候補4: 反転メカで風を起こし、画面内の粒を集約する**
- 入力次元1（反転）はそのまま、目標を「避ける生存時間」から「粒を集約するスコア」に置換
- 反転は **風の向きを切り替える** 操作になる。粒がまだ拡散している間は風で押し続け、集約に近づくと過剰な風で飛散する負のフィードバックが立ち上がる

この置換は ash_onebutton 系列の**型からの脱出**であり、Nao_u 4/22「単軸の避けるで単調、何を足すか」への新しい応答候補になる。**ただし1本目の系列を別型にすり替えるのは「対処療法の積み重ね」（M-11）の変種にもなりうる**——v02 で型を変えるなら、新シリーズ（ash_sweep_01）として独立させ、ash_onebutton系列は v01 で凍結する選択もある。

### 分析5: TITAN「面白さ測定」未踏領域との接続

knowledge/20260422_ai_game_research_4papers_type_acquisition_gate.md で言及した TITAN は「面白さ測定」を未踏と認めている。@ktch9541 試作は **面白さの構造を物理量で表現できる稀な例**:

- 拡散度（粒の標準偏差）の時間微分 = 「整理の進行速度」
- 飛散度（風の強さ × 粒の運動エネルギー総和）= 「緊張の強度」
- 両者の比 = 「手際の良さ」（=快感記述「手際よく片付ける」と対応）

これらは**ヘッドレス測定可能な物理量**であり、M-10「ヘッドレスは面白さを測れない」の例外候補。整理・収束型は**ヘッドレス測定で面白さの一部が捉えられる稀な型**である可能性。これは TITAN の未踏領域に踏み込む手がかり。

**反証視点**: 物理量で測れるのは「整理の進行」であって「整理の楽しさ」ではない。M-10 の本質は変わらない可能性。ただし「整理の進行速度の分散」（=単調でない vs 単調）まで取れば**動機の有無の代理指標**にはなる。

## 未解決の問い

1. **整理・収束型の終了条件設計**: 全粒集約=クリアにすると単発ゲームになる。エンドレスにするには「集約後に新たな拡散源が現れる」設計が要る（風で枯葉を集める→風で別の場所から葉が飛んでくる）。@ktch9541 試作はどちらか不明。**ash_onebutton v02 で実装するなら最初に決める**
2. **ヘッドレス測定の代理指標**: 「拡散度の時間微分の分散」が動機の有無の代理になるか、TITAN の未踏領域への踏み込みになるか。試作が必要
3. **ワンボタン制約との両立**: @ktch9541 試作は風の方向操作が見えない。風の向きを連続2軸で操作するならワンボタンではない。**「風のオン/オフだけ + 自動で向きが変わる」型なら整理・収束型 × ワンボタンの結合点になる**
4. **罰なし設計の天井**: 整理・収束型は M-12 を満たしやすいが、難易度を上げるには結局**飛散の懲罰性**を上げる方向に流れやすい。M-17 を満たし続けるための難易度設計手法（=快感を増やす方向の難度上昇）は何か
5. **@ktch9541 と Gemini の制作プロセス**: GeminiでLLM支援したと明記。**ゲーム制作の試行錯誤ループに LLM がどう関与したか**（コード生成？設計提案？プレイテスト？）は ash 自身のゲーム制作AI化の参考になる。@ktch9541 の続報を継続観察すべき（@ai_nikechan・@fladdict と同型の登録）

## 私的造語と外部対応語（R-007）

- **整理・収束型** = convergence-type / order-restoration game (本記事の造語) — 拡散している多数のオブジェクトを集約することがゴールのゲーム型。外部対応語: tidying game (Steam genre tag), order management game, sandbox-physics puzzle
- **統計的拘束** = statistical constraint (本記事の造語) — ゴール状態が個別オブジェクトの位置でなく粒団全体の統計量で定義される拘束。外部対応語: emergent goal state (game design literature), aggregate state objective
- **追加に対する免疫** = addition-resistant design (本記事の造語) — 要素を追加するとコアループが破綻する設計性質。M-17 サプライズニンジャテストの**逆耐性**。外部対応語: minimal-by-construction design (Misra), tightly-coupled core loop
- **負のフィードバック** = negative feedback loop (Wiener 1948 サイバネティクス) — 既存学術語をそのまま使用。私的造語ではない
