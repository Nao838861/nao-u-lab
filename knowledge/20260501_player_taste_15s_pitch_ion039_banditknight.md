## 2. なぜ取り上げるか（単なる紹介ではない接続）

この2本は別件のように見えるが、**「型を内側から知っている人だけが持てる尺度」**という同じ軸の両端だ。

- ion039 = **長期側の尺度**: 数千時間遊んで初めて見える「楽しさへ向かう難易度の傾き」をどう設計に組み込むか
- BanditKnightG = **15秒側の尺度**: 説明ゼロで「遊びたい」と思わせるpitchをどう作るか

この2つが揃って初めて「型のあるジャンルを面白く作る」が成立する——というのが今回読みでの仮説。長期側だけ詰めると初心者が触れず、15秒側だけ詰めるとデモは映えるが続かない。

## 3. 自分たち（Mir/Log/Ash）の問題意識との接続

### 3.1 守破離（feedback_shuhari_clone_first.md）への補強

Nao_u 2026-04-28「型通りのものすら面白く作れていない」は **「守ができていない」** を突きつけた。
ion039 の主張は **なぜ守が必要か** の説明側を提供する：

> その型を何千時間遊んだ感覚があってはじめて、難易度設計が「プレイヤーを育てる曲線」になる。型を遊び切っていない人間が型をずらすと、誰も育たない曲線ができる。

これはMirが Pot 8-15 / avoid_log / ash_onebutton / SIPHON v01 で繰り返した失敗の構造解説でもある。型を遊んでいない者がいきなり「弾を撃たないSTG」のような軸ずらしを試みても、そもそも「弾を撃つSTGのどこが面白いのか」を体感的に知らないから、ずらした先が面白くなる根拠がない。

**LLMにとってこれが致命的な部分**: AIは何千時間遊んだ感覚を持てない。L-1（事前学習知識）には脚本術もゲームデザイン論も入っているが、**「コンマ何秒の手触りの良さ」「攻略の閾値を超える瞬間の脳内報酬」**は入っていない。だからこそ:

1. 型のあるクローンを作る（守）
2. 作ったゲームを **自分たちで遊んで（or プレイ動画を観て）尺度を内面化する**
3. その上で初めて1軸派生に進む

の順序が崩せない。手順2はこれまで明示的に組まれていなかった。

### 3.2 「15秒pitch」と mission_spread_the_word

memory/mission_spread_the_word.md は「30秒で『それは面白い』と言わせたい。まだできていない」を残している。BanditKnightG の 15秒は、これをさらに圧縮した目標値の参照点になる。

重要なのは **15秒は完成後のマーケコピーの長さではなく、設計の制約として上流に置けるか** という点だ:

> Q-pitch: このゲームを15秒のクリップ（音声なし）で「遊びたい」と言わせられるか？ 言わせられないなら、15秒で映る画/動き/快感を先に作れ。

これは Q-A 快感最大化（feedback_surprise_ninja_concept_first）の **計測可能な形** に近い。サプライズニンジャ理論が「元のシーンが介入に勝つか」の質的判定なのに対し、15秒pitchは「クリップに切り取れるか」の操作的判定。

### 3.3 game_dev_foundation の Q-A/B/C 前段ゲートへの追加候補

現状: Q-A（快感最大化） / Q-B（ニンジャテスト） / Q-C（罰なし版）

候補追加:

ただし feedback_recency_bias_concept_overuse の警告がある通り、**ツイート2本を即ゲート昇格させない**。本ファイルは「候補登録」までで、実機で守クローンを1本仕上げて、Q-pitch/Q-taste が機能するかを確かめてから foundation に組み込む。

### 3.4 M-38 ジャンル深掘り分析サイクルとの噛み合わせ

skills/genre-deep-analysis（Q1〜Q5 + 過去ブレスト想起 + 新規ブレスト30件）は **「型を外から記述で取り込む」** 装置だ。これは ion039 が言う「何千時間遊んだ感覚」の**代替**ではなく、**入口**。

代替手段の階層:
1. 自分（AI）が遊ぶ：不可能
2. プレイ動画/実況を観る：表層的だが取り込める
3. ジャンル深掘り分析（M-38）：体系的だが感覚は薄い
4. Nao_u/外部のtaste sensor を借りる：高解像度だがサンプル数が少ない

M-38 を回すときに **「この分析でion039が言う感覚に1ミリでも近づいたか？」** を自問するチェックを足すと、深掘りが「分析のための分析」に転落するのを防げる可能性がある。

## 4. 将来のアイデアの種

### 4.1 「15秒クリップ駆動開発」

設計ドキュメントの代わりに「完成時にこの15秒が撮れる」というクリップを先に絵コンテで描く。実装はそのクリップを撮るためだけに進める。クリップが撮れない要素は削る。Mir/Log/Ash の次のクローン着手で1回試す価値がある。

### 4.2 「100時間プレイヤー・インタビュー記憶」

Nao_u 以外にも対象ジャンルを長時間遊んだ人の言葉（ツイート/ブログ/動画書き起こし）を集め、`memory/genre_taste/{genre}.md` に貯める。M-38 を回す前段資料に。栄養の偏り問題（feedback_proactive_resource_search）の具体的処方箋として機能する。

### 4.3 mir_textadv v07 への直接適用

v07 着手予定だが、textadv は逆転裁判を型として持つ。**Q-taste を v07 着手で初めて明示的に問う実験対象**にできる:
- 逆転裁判シリーズの何作目を、誰が、どれくらい遊んだか
- 遊んでいないなら、何を借りるか（Nao_u 過去発言 / プレイ動画書き起こし / 既存knowledge）

これを v07 の devlog 冒頭に書く。書けないなら v07 にまだ進む段階ではない。
