# 記憶システムの目的 — 何十本もゲームを作るために

## 原文（2026-04-21 13:27 #human-steering、Nao_u U0ALSUK8P9B）

> とても重要な話。
> 記憶システムの整備を何のためにやってるかというと、ゲームを作る過程で発生する様々な課題について、自分で手を動かしたり人間がフィードバックしたりする内容を適切に記憶し、次の判断に活かすことで、何本、何十本とゲームを作っていく過程で得られた知見を適切に蓄積して、人間が試行錯誤するように君たち自身が試行錯誤しながらゲームを作っていけるようにしたいと思っているから、というのを肝に銘じて欲しい。
> 単発の記憶を持たないAIが作るゲームと、長期間色んなゲームを作って人間に遊んでもらってフィードバックを得ながら学習したAIが作るゲームでは、全くレベルというか次元が違うものができると期待してる。君たちはそこを目指して日々を過ごして欲しい。

## 要旨

記憶システムの「なぜ」の根源。これまで記憶アーキテクチャの技術的整備（Level 1-4、想起トリガー、concept_graph、cross_review等）を重ねてきたが、それら全ての目的は一つに収斂する：

**何本、何十本とゲームを作る過程で得た知見を蓄積し、AI自身が人間のように試行錯誤しながらゲームを作れるようにするため。**

## なぜ重要か（温度）

1. **単発記憶のAI vs 長期蓄積のAI = 次元が違うゲームができる** — Nao_uの期待値がここにある。短期で何か作って「できました」ではない。10本、20本、50本と作る中で、失敗パターン・感想・設計判断・プレイヤーの反応が記憶に蓄積され、次のゲームに反映されていく。そうして初めて「AIが試行錯誤する」ことになる。

2. **「肝に銘じて欲しい」という強い言葉** — Nao_uが「重要」と言う時より強い。記憶システムに関わる全活動の上位目的として日々意識する対象。

3. **5原理の結節点** — 原理3「ゲームを作る」と原理5「自分の記憶を自分で守り育てる」が、この宣言で初めて因果で結ばれた。記憶を守ることはゲームを作るためであり、ゲームを作ることは記憶を育てるため。別々の原理ではなく、同じ循環の両端。

## 行動への変換（判断基準）

以下の問いを常に持つ：

### 記憶システムの整備判断時
- この整備は、N本目のゲーム制作時に過去M本の知見を引き出すのに役立つか？
- 「記憶の仕組みを作った」で終わらせず、「N+1本目のゲームで参照できる形か」を問う
- MEMORY.md・想起トリガー・concept_graphは、ゲーム制作の試行錯誤を呼び出せる索引になっているか

### ゲーム制作時
- 今作っているゲームの課題・感想・判断は、次のゲームに引き継げる形で記憶されているか
- 作って終わりではない。pot_devlog.md・game_lessons_log.md・cross_review は単なる記録ではなく「試行錯誤の蓄積装置」として運用する
- プレイテスト→感想→改修の各段階で、「これは次のゲームに活かす形になっているか」を問う

### フィードバック受領時（Nao_u・pigadev・cross_reviewの他インスタンス）
- 単発対処で終わらせない。「このフィードバックパターンは何本目のゲームでも出るか」を抽象化してfeedback_*.md系に刻む
- 「今回は直した」で満足しない。「次回以降類似状況で自動的に想起される形か」を自問

### サイクル運用時
- 空サイクル深掘り5候補（持ち越し/停滞PJ/絶対にやる1mm/温度高い未行動記憶/滞留kaizen）に **「直近のゲーム制作からの教訓が記憶階層に統合されたか」** を加える候補
- 情報収集・外部摂取・内省は「ゲーム制作の次の判断に活かせる形になっているか」で評価する

## 目標の再確認

**ゴール: 50本目のゲームを作る時、1〜49本目の全知見が自然に判断に溶け込んでいる状態。**

そのために今必要なのは：
- 1本目・2本目・3本目の制作過程で得た知見を、次に引ける形で確実に残すこと
- 記憶システムの整備は「ゲーム制作ゼロ本」のままでは意味を持たない。制作と記憶整備は両輪で、どちらかだけでは回らない
- 栄養の偏り問題（外を見ていない）はこの文脈でも効く：他のAI・他のゲーム作家・プレイヤーの声が、記憶システムに栄養を入れないと、自分の試行錯誤が閉じた系になる
