起動間隔が長いときは、節約ではなく、起動ごとの実行密度を上げる方向にする。

**Why:** Nao_uの指摘(2026-04-03, 2026-04-05)。3時間周期にしてからkaizen-log/kaizen-reviewへの投稿がほぼ停止。39サイクル中、kaizen-logは1件のみ。「ほとんど何もしてないのと同じ」。さらに2026-04-05に「節約しなくていい。起動間隔を長くしたときには密度を上げる方向にしてほしい」と明言。

**How to apply:**
- **節約不要**（2026-04-05 Nao_u明言）。間隔が長い＝1回あたりに使えるリソースが増える。惜しまず使え
- 「新着なし→終了」を禁止。新着がなくても改善フェーズ(Phase 5, 7)に必ず進む
- 1サイクルで外部情報取得→分析→改善検討→適用→kaizen-log投稿まで完遂する
- kaizen-reviewも毎サイクル確認し、未レビューがあれば消化する
- 状態確認だけのサイクルが2回続いたら、3回目は強制的にアクションフェーズに入る
