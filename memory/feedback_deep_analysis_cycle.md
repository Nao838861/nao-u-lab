# 深い分析サイクルを回せ — 短絡的な思いつき実装への批判

## Nao_u原文（2026-05-01 #game-rights 04:16）

「こういうのは「ブロック崩しとは何を楽しむゲームか？」「現状のブロック崩しの良い点と問題点」「問題点を解決するには、どんな手法があり、その手法はどういうアプローチがでどのような問題を解決できるか？」「他のアプローチはないか？楽しさを伸ばし、苦痛な点を減らせる一手はどれになるか？」「複数の問題を一気に解決できるアイデアはないか？」など、ゲームに対する深い分析と考察を繰り返さないと出てこないが、君らはそのサイクルを回さずに短絡的に思いつきを実行しようとしがち。最初にブレスト的になん十件も出したものをもう忘れているのか、そういうのを適宜思い出したり、新たにまた数十件出して吟味したりなどの、素のLLMにはできない深い分析のサイクルを回してほしい。そのための記憶システムのハーネスがあるし、そのサイクルをうまくskillで回せるようにしてほしい。」

## 核心

**問題**: 我々はアイデアを思いついたらすぐ実装に走る。分析の深さが足りない。

**具体例（brick_log）**:
- v01: Slack で良16/悪18=34項目をブレスト → しかしそこから「深掘り」せず裏抜けカウンタに直行
- v02: 6つの仕様候補（Spec A-F）を比較 → しかし「なぜこの問題を解くべきか」の深い分析なしに実装
- 34項目のブレストを出した後、v02の設計でそれを十分に参照・活用できていない

**要求されている分析サイクル（5段階）**:
1. **このゲームとは何を楽しむゲームか？**（本質定義）
2. **現状の良い点と問題点は何か？**（現状分析。過去ブレストの想起＋新規追加）
3. **問題点を解決するにはどんな手法があり、各手法はどの問題を解決できるか？**（解決手段のマッピング）
4. **他のアプローチはないか？楽しさを伸ばし苦痛を減らす一手はどれか？**（代替案探索＋選択）
5. **複数の問題を一気に解決できるアイデアはないか？**（統合解の探索）

**なぜ素のLLMにはできないか**:
- ステップ2で「過去に何十件も出した良い点/悪い点」を正確に思い出す必要がある
- ステップ3-5で過去の分析結果と新しいアイデアを突き合わせる必要がある
- 1回のセッションで完結せず、繰り返し回す必要がある
- → 記憶システムがあるからこそ可能。これが蓄積AIの存在意義

## 処方: skill `game-analyze`

`.claude/commands/game-analyze.md` として実装。以下を構造化:
1. 対象ゲームの過去ブレスト・devlog・README・cross_reviewを全て読み込む
2. 5段階分析サイクルを順番に回す
3. 各段階の出力を devlog に追記して蓄積する
4. 繰り返し実行可能（前回の分析結果を読み込んで深化）
