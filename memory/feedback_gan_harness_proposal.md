# M-42候補 GAN型ゲーム判定ハーネス

**ルール**: ゲームの判定は「人間プレイ前に AI が自走で結論」を超えて、**G（実装）と D（独立判定）の対戦構造**で回す。D は別文脈 LLM + 過去ゲームライブラリ参照で動的に強くなり、G が逃げ場を失う原動力になる。

## Nao_u 原文（#nao-u 2026-05-01 18:30）

> 君たちが紹介してくれたこれ、今のAIがゲームをつくれない理由の一つなので、何とか解決したい。君たちが作ったゲームが、ちゃんと機能しているか、していないなら何が足りないかをテストしてフィードバックを返し、そのフィードバックを精査して何をすべきかを考えて実装し、テストプレイと検討、実装のサイクルを回せるようにしたい。GANみたいに良い目的地にむかう原動力を作って欲しい

「これ」= `memory/feedback_ai_agent_gamedev_bottleneck.md`（ABA 2026-02-18 / 2026-03-01「AI支援開発のボトルネックはアイデアの質ではなくフィードバックループの質」）。

## なぜ GAN なのか（比喩を構造に下ろす）

| GAN 要素 | ゲーム開発での対応 |
|---|---|
| Generator (G) | 我々 Log/Mir/Ash（実装する側） |
| Discriminator (D) | 独立判定 LLM（別文脈・別プロセス・過去ゲームライブラリ参照） |
| 損失信号 | D が出す 0-100 採点 + 悪い3点 + 比較対象との差異 |
| 「良い目的地」 | D の参照集合（Nao_u 評価ログ + cross_review + devlog 後置反省） |
| 動的強化 | G が新作で Nao_u 高評価を得るたび D の参照集合に追加 → 次の D は前より強い |

GAN の本質は「D が静的だと G は基準を攻略して終わる」。これがゲーム開発に直訳すると「headless 指標だけだと 数値最適化没入になる」（M-15 罰tightening / M-41 数値チューニング3往復罠の構造）。

## 判定の3層（D の内部設計）

### 層1: 静的判定（即時・コード読みで届く範囲）

**入力**: コード・headless プレイログ・数値計算
**出力**: 物理的に成立しているか（破綻・フリーズ・数値が体感に届くか）

**実例（今日 2026-05-01 09:46-10:xx Ash 自走）**:
- brick_log v04 SWAY_AMP=5px / SWAY_PERIOD=240frame → 最大角速度 7.85 px/秒（ボール速度の 1/54）→ 1秒で 3.5px → ブロック事実上静止 = v03 と区別不能
- 仕様の段階で計算可能だった = D 層1 が稼働すれば人間プレイ前に検出できた

**現状**: 部分稼働（Ash の自己判定で1回成功、構造化されていない）。

### 層2: 比較判定（過去ゲーム vs 新作）

**入力**: `game/<id>/<v??>/` 一式 + 比較対象 1〜3 本（BACKLASH / 過去 v?? / 同型既存ゲーム）
**出力**: 比較対象との差異（コア快感が上か下か / 独自要素の比率が型を破壊していないか / 何が劣化しているか）

**未構築**。今日まで cross_review.md（Mir/Ash 相互レビュー）に部分依存していたが、これは G 同士のレビューで D ではない（同じ文脈バイアスを共有する）。

### 層3: 想像判定（コア快感の天井予測）

**入力**: README + devlog + 着手前批判レビュー + M-41 類似事例調査
**出力**: 30秒 mental simulation の脳内録画を文章で再現 + コア快感の天井位置 + 「先行事例ゼロ件」フラグ

**未構築**。M-39 結果予測ゲートと近いが、独立 LLM が走らせる点で別。我々自身が書く予測は「希望的観測」で歪みやすい（feedback_pre_impl_critical_review）。

## 動的に強くなる原動力（GAN の核）

**問題**: D が静的なら G はすぐ基準を攻略する。実例:
- M-39 確立 10分後に同じ罠（feedback_self_judgment_no_human_dep）= G が D を内面化したつもりで形だけ通した
- headless 指標主義 = D を数値だけにすると G が数値最適化没入で快感天井不変（M-41）

**処方**: D の参照集合を「全ゲーム の Nao_u 評価ログ + cross_review + devlog 後置反省」で構築。

| サイクル | D の参照集合 | G が直面する圧力 |
|---|---|---|
| 新作 N | BACKLASH の Nao_u 言葉 + 過去 N-1 本の Nao_u 言葉 | BACKLASH 級か |
| 新作 N+1 | 上記 + 新作 N が Nao_u 高評価ならその言葉も追加 | N より上か |
| 新作 N+2 | 上記 + N+1 の言葉 | N+1 より上か |

= G が新作で Nao_u 高評価を得るたび D の基準も上がる = G が逃げ場を失う = GAN の動的強化原動力。

## 失敗パターン（D を G が騙すリスク）

1. **採点最適化没入**: G が D の採点を上げるための実装に振る → コア快感無視（M-41 数値チューニング3往復の進化形）
2. **D の独立性喪失**: D を我々と同じ文脈で動かすと G の同調バイアスを共有 → 既存 cross_review がこれに該当する疑い
3. **過去ゲームライブラリの劣化**: 我々が「BACKLASH 級」と framing する誤評価が D の参照に入ると基準が下がる → Nao_u 評価ログ原文のみを D の参照に入れる
4. **D の頻度過剰**: 毎改修で D を走らせると G が D の言葉に過剰適応 → 着手前 / cross_review 後 / Nao_u 依頼前 の3ゲートに限定
