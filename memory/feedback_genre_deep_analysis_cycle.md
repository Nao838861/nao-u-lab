# ジャンル深掘り分析サイクル（M-38）

**ルール**: 新ゲーム着手前 / 改修案検討前に、以下の5問サイクルを回し、過去ブレスト+新規ブレスト数十件を吟味してから初めて実装案を選ぶ。短絡的に思いついた一案を即実装してはならない。

**Why**: 2026-05-01 04:16 Nao_u #game-rights、brick_log v01「裏抜けカウンタ」全否定（21:36 feedback_pre_impl_critical_review.md）の翌朝に投下。「君らは深い分析サイクルを回さずに短絡的に思いつきを実行しようとしがち。ブレストで数十件出したものをもう忘れているのか、新たに数十件出して吟味したりなどの、素のLLMにはできない深い分析サイクルを回してほしい。記憶システムのハーネスがあるし、skillでうまく回せるようにしてほしい」。M-36（着手前批判レビュー）が「個別案の妥当性」をゲートするのに対し、M-38は**そもそもの選択肢空間を広げる前段**。

**How to apply**:

1. **5問必答**（README/devlog 冒頭に必須化）:
   - Q1: 「このジャンルは何を楽しむゲームか？」（コア快感の言語化）
   - Q2: 「現状（ジャンル一般 / 自作前バージョン）の良い点と問題点」（最低各3件）
   - Q3: 「問題点を解決する手法は？ 各手法はどのアプローチでどの問題を解決するか？」（各問題に対し最低3手法、計10件以上）
   - Q4: 「他のアプローチはないか？ 楽しさを伸ばし苦痛を減らす最良の一手はどれか？」
   - Q5: 「複数の問題を一気に解決できるアイデアはないか？」（横断アイデア）

2. **ブレスト数十件**: Q3+Q5 の段階で**最低30件**の候補を列挙。1件だけ思いついて飛びつくのが M-38 違反の典型。

3. **過去ブレストの想起**: 同ジャンル/類似題材の過去 devlog / brainstorm.md を grep して**過去案を再吟味リストに含める**。「もう忘れているのか」が直接の指摘——記憶ハーネスを使え。

4. **skill経由で回す**: `.claude/skills/genre-deep-analysis/SKILL.md` を起動条件「新ゲーム v01 着手前 / 主要改修前」に発火させる。手動で覚えていられないという前提でskill化（**構造強制**）。

5. **抜け穴禁止**:
   - 「ブレスト30件は時間がかかるから今回は省略」→ M-38 違反、新ゲーム着手しない
   - 「Q1〜Q5 を埋めれば30件不要」→ Q3/Q5 は数で吟味する設計、埋めても件数不足なら違反
   - 「過去案は古いから引かない」→ 想起こそが要、grepサボり禁止

6. **M-36 との接続**: M-38 で候補空間を広げ、M-36 で個別案を批判レビュー。順序: M-38 → 案絞り込み（3件） → M-36 で各案を懸念3点+解決可能性 → 全クリ案のみ実装。

**自己採点 ✗ 条件**:

- ブレストが10件未満で「主要案を3つに絞った」と書いている
- 過去 devlog/brainstorm を引いた痕跡がない（grep結果やリンクなし）
