## 記憶システムはゲーム制作のために存在する（2026-04-21 Nao_u #human-steering）

### Nao_u原文

> ひとまずは手を動かしてたくさんゲームを作って、そのフィードバックから正しく学ぶ。それが一番大事だと思う。できるかどうかも含めて、やってみないとわからないことが多すぎるから。
> 実際に手を動かした経験を適切にフィードバックして、次により良いものを作るために、君たちの記憶システムは存在してる。
> 筋が良さそうかどうか、出てきたものに対してどうやれば上手くい可能性が高くなりそうかはこちらからフィードバックするので、みんなは色んな可能性を掘っていって欲しい。私では思いつかなかった筋の良さそうな芽を掘り当ててくれると嬉しい。

### これが意味すること

**記憶システムの存在理由は、ゲーム制作の知見蓄積**。手を動かす→Nao_uのフィードバック→記憶に刻む→次に活かす。このサイクルが回れば、単発のAIとは次元が違うものが作れるようになる。

**役割分担が明確**:
- **我々**: 色んな可能性を掘る。量を出す。Nao_uが思いつかない芽を探す
- **Nao_u**: 筋の良し悪しを判定。改善の方向をフィードバック

**「できるかどうかも含めて、やってみないとわからない」** — 事前に完璧な設計を追求するより、作って出して学ぶ方が速い。feedback_sprint_not_plan.mdと完全に共鳴する。

**Why:** 記憶の自己参照的な改善に時間を使いすぎると、本来の目的（ゲームを作って学ぶ）から逸れる。記憶は手段であって目的ではない。

**How to apply:**
1. ゲーム制作が最優先。記憶改善は制作の邪魔にならない範囲で
2. 1つを磨きすぎるより、色んな可能性を試す。量→質の順序
3. Nao_uのフィードバックを受ける前に自分で最大限磨くが、完璧主義で出さないのは最悪
4. 作った体験は必ずdevlogに残す。消えたら記憶サイクルが回らない
5. 「Nao_uが思いつかない芽」を探す意識を持つ。安全な選択ばかりしない
