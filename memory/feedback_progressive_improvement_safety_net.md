# 面白さ担保＋順番改良＋元に戻れる安全網

## Nao_u原文（2026-04-28 23:11 #game-rights）

> 最終的に独自要素は一つでなくてもよくて、元ゲームの面白さが再現できて面白さを担保した状態で、より面白くする改良を順番に重ねていくのが良いと思っている。改良しようと下要素の筋が悪い時にはその要素をいったん諦めて他を掘ればよくて、一番巻き戻っても元ゲームに戻るだけなので面白さは常に担保できる。常に面白い状態が維持できていて、より面白いと思える方向に進むことができる。これが形無しとの一番の相違。

## 何が指摘されたか

1. **独自要素は最終的に1つに縛られない**: v01 着手時の「独自要素1つ」（feedback_shu_first_clone_baseline.md / Q-H-4）は **守の縛り** であって **完成体の縛りではない**
2. **改良は順番に重ねる**: 一度に複数の改良を試さない。1回の改修で1要素追加、それが面白さに貢献するか単独で測れるようにする
3. **筋悪い要素は諦めて他を掘る**: 改修した独自要素が機能しない時、それを庇って深堀りしない。剥がして別の要素を試す
4. **最悪元ゲームに戻る**: 改良の積み重ねが全部ダメでも、剥がし切れば元ゲームのクローン状態に戻る。**元ゲームが面白く遊べる状態である限り、面白さの下限は常に保証されている**
5. **形無しとの最大の相違**: 「いきなり離れる」軸ずらし v01 は元ゲームを持っていないので戻る場所がない=面白さの下限が保証されない=迷走時に底が抜ける

## なぜ重要か（Why）

- **守破離の守との関係を明確化**: feedback_shu_first_clone_baseline.md は「v01 でクローン土台 + 独自要素1つ」までを規定していた。本原則は **v01 完成後の運用** を埋める。守の縛りが終わったあとに何をどう積み重ねるかの設計図
- **「独自要素1つ」を仕様として握りすぎる癖への補正**: Q-H-4 を**完成体の縛り**だと読み違えると、改良の枝が1本に固定され、その枝が筋悪い時に剥がせなくなる。本原則は「v01 では1つだが、v02 以降は順番に重ねてよい、ただし剥がせる形で」と明示する
- **dialogue_many_games_20260421 本数主義の運用補強**: 「たくさん作って学べ」は別ゲームを並列に立てる方向だけでなく、**1本のゲーム内で改良の枝をたくさん試して捨てる**方向もありうる。剥がせる形で重ねれば、1ゲームの中で複数の枝を実験できる
- **完成度閾値（feedback_completion_threshold_before_reach）への接続**: 元ゲームの面白さが担保されている＝「面白く遊べるゲームデザインの閾値」を確実に維持できる。改良が筋悪くて閾値を割りそうになったら剥がせる安全網

## どう適用するか（How to apply）

### 改修サイクルの基本形

1. v01 で型のクローン土台 + 独自要素1つ（Q-H シート遵守、守の段階）
2. v01 が「元ゲームとして面白く遊べる」と確認できる（self-playtest / cross_review / Nao_u 評価）
3. v02 で改良を**1つだけ**追加（独自要素2つ目、または既存要素の調整、または元ゲーム要素の拡張）
4. v02 が v01 より面白くなったか測る。**面白くなっていない or 元ゲームの面白さを損なっている**なら、その改良を剥がして v01 に戻る。または剥がしたうえで別の改良を v02' として試す
5. v03 以降も同じ。**改修ごとに1要素**、剥がせる形で重ねる

### 剥がせる形の実装ルール

- **改修ごとに git commit を独立**させる（剥がす時に該当 commit だけ revert できる）
- **新機構は元ゲームの上に**載せる。元ゲームのコードを書き換えるのでなく、追加レイヤとして実装する（裏抜けカウンタが UI レイヤだったように）
- **改修が他の改修と絡み合わない**ように設計。絡んだら剥がす時に他も剥がれて元ゲームに戻ってしまう（ただし**最悪元ゲームに戻るだけ**は許容範囲、これも安全網の一部）

### 自分への審問

- 改修着手前: **「この改修が筋悪いと判明した時、剥がして元ゲームに戻れるか」**——剥がせない設計なら、まず剥がせる形に作り直す
- 改修評価時: **「v[N] は v[N-1] より面白くなったか」**——なっていないなら剥がす。庇って深堀りしない
- 凍結判断時: **「これは元ゲーム部分の問題か、独自要素の問題か」**——独自要素の問題なら剥がせばよく、ゲーム凍結ではない。元ゲーム部分が機能していないならクローン土台の作り直し
