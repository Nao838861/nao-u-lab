# raw_log.md の運用：定期再分析ループ

**ルール**: 原文保存した開発ログ（`game/*/raw_log.md`等）は作って終わりではない。**時々読み返して、新しく学んだことで再分析を再構築する**。読み返しから今作っているものの新しいヒントが出ることがよくある。

## Why（Nao_uの言葉 2026-04-20 13:19 #human-steering）

> 原文からの再分析は必要に応じて時々読み返して新しい分析を再構築するのが良いと思う。新しく学んだことでより深い考察ができたり、読み返すことで今作っているものの新しいヒントになったりすることがよくあるので。

- 原文を保存しただけでは「一次資料の倉庫」止まり。再読で初めて知識が更新される
- 学びは時間とともに増える → 同じ原文からでも今の視点で別の分析が取れる
- 今作っているものの壁にぶつかったとき、過去の原文が答えを持っていることがある

## How to apply

- **新しいraw_log.md系を作るとき**: ファイル冒頭に「最終再分析: YYYY-MM-DD」「再分析トリガー: （学びが溜まった時／該当ゲーム改修時／行き詰まり時）」のメタを置く
- **再分析のトリガー**:
  - そのゲーム/プロジェクトの改修・次作着手時（自然な機会）
  - 新しい設計原則・教訓を学んだ後（例：game_lessons_log.md更新時）
  - 似た問題で詰まったとき（過去の原文に答えを探しに行く）
- **再分析の成果物**: 隣接する `devlog.md` に「再分析 YYYY-MM-DD — 今の視点で見直して見えたもの」セクションを追記。原文(raw)は不変、分析(devlog)が積層する構造
- **「毎サイクル全部読み返す」ではない**: 「必要に応じて時々」が原文。空サイクルの深掘り候補5カテゴリ（feedback_empty_cycle_rule）に「温度高いraw_log再読」を含める

## 適用範囲

- 概念として：原文保存型ドキュメント全般（dialogue_*.md等も同じ原理で再読可能）
