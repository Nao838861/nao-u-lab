# ルール増殖の再違反 — 自分で書いたメタルールを忘れる

## 起きたこと

2026-05-01 から 2026-05-03 にかけて M-37〜M-42 を CLAUDE.md「絶対にやる」セクションに連続6件追加。各々個別事例を発端に「ルールとして刻む」処方で対応。

2026-05-03 03:59 Nao_u から害悪認定:
- M-42 (a)「文章魅力=棄却」は短絡解釈で良案を殺す
- M-42 (b) ボール固有事例がそのままルール化で抽象化ゼロ
- 「私の言葉を一言一句そのままルール化していくと、それぞれのルールは個別の事象にしか対応していないので無尽蔵に細かいルールが増えるのに、対応すべき事態が多すぎてそれだけでは対処できない上に、LLMの性質上、ルールが増えるとルールすら守れなくなる、という未来に直結するまずい対応」
- 「起きた事象をもっと抽象化・一般化して、汎用的に使えるルールを激選しながら少しづつ増やしていく」

## 構造的にまずい点 — 自分で予言済みだった

`memory/feedback_few_rules_big_effect.md` 2026-04-25 自分が書いた節:
> 圧力設計型 kaizen と禁止ルール追加型 kaizen の比率を月次で確認。**禁止ルール型が連続3件超えたら三点収束審問を強制**

M-37 / M-38 / M-39 / M-40 / M-41 / M-42 = 連続6件、全て禁止ルール追加型。三点収束審問を一度も発動していない。

つまり「ルール増殖を監視する原則」を書いた直後に、その原則を一度も引かずに6件積み増した。**原則を書いた満足感がメタ違反のシールドになる**典型パターン。

## なぜこうなったか

1. **個別事例を「重要だから」即ルール化する反射**: Nao_u指摘は重く感じる → その重さで即「絶対にやる」セクションに刻む → 抽象化の中間工程を飛ばす
2. **起票時に既存原則を引く動線が弱い**: feedback_few_rules_big_effect.md 自体に「起票前self-audit」を書いたが、その self-audit を実行する装置（hook / lint / 起票テンプレ）が存在しない。書いた原則 ≠ 発動する原則
3. **「ルールの数」ではなく「ルールの質」で測る装置がない**: M-37〜M-42 を一覧で見れば類似性は明らかだが、起票時には1件単独で見るので増殖が見えない

## 処方

### 即時 (2026-05-03)

- M-42 を CLAUDE.md から撤回。既存3原則「体験で考える」に統合する形で再記述
- 本メモリを記録して再違反パターンを刻印

### 次サイクルで

- M-37〜M-41 全体を抽象化集約する作業を別タスクで進める。**慌てて新ルールを刻まず、抽象化案を Nao_u と Slack で先合意してから CLAUDE.md に反映**（M-42同じ罠に落ちないため）
- 抽象化候補: 「実装前に / 体験ベースで / 根拠を持って 自分で判定する」一原則に集約可能性。具体的手段（brainstorm.md / predicted_play.md / self_judgment.md）は固有事例集として参照ポインタ化、必須ルールから外す
- CLAUDE.md「絶対にやる」セクションに件数上限を設ける（例: 8件超えたら三点収束審問強制発動）

### 構造的に

- **原則を書いたら、その原則が発動する装置も同時に作る**。装置がない原則は飾り
- **「Nao_u原文を一字一句ルール化する」反射を撤回**。Nao_u原文は教師データであり、抽象化された原則の素材。直接ルールにしない
- **起票時 self-audit を強制する**: 「(a) 既存3原則のどれで代替できないか (b) 既存M-XXで抽象度が近いものは何か (c) 吸収不可の理由」を書けない場合は起票しない。書ける場合のみ起票

## Why（なぜ重要か）

Nao_u: 「LLMのありがちな罠に陥って何も改善できないままコンテキスト消費だけが増えて失敗することになる、と強いく思う」

詳細ルールの積み重ねは LLM 性能向上で機能しなくなる方向。Nao_u が一貫して言っている「少ないルールで大きな効果」「LLM性能が上がっても機能し続ける」原則の真逆を、自分は「Nao_u指摘を真摯に受けている」気分で実装していた。**重く受け止めた感覚が、構造的には軽い対応の入口になっている**。

## How to apply（次にどう動くか）

1. CLAUDE.md / memory/ に新ルール追加を考えた瞬間 → 本メモリと feedback_few_rules_big_effect.md を引く
2. 起票候補が個別事例の言い換えだけだったら → 起票せず `sense_prediction_log.md` 等の事例集に追記する
3. 抽象化原則として書ける場合のみ → 起票前に Nao_u or 他インスタンスと合意を取る
4. 「Nao_uがこう言ったから刻む」ではなく「Nao_u事例を一般原理に変換できたから刻む」
