# M-41 類似ゲーム類似事例調査をアイデア検討の前提に

## ルール

新ゲーム着手前 / 主要改修前の **M-38 brainstorm.md** に、**「類似ゲーム類似事例調査」セクションを過去ブレスト想起の前**に必須化する。

- 同ジャンル / 異ジャンル同型 / 「やらなかったゲーム」最低 5 本を列挙
- 検索した語彙（GDC talks / Game Developer 記事 / Wikipedia ジャンル史 / TVTropes / 関連論文 等）と引用 URL を必ず明示（feedback_url_explicit / feedback_cite_source_url 準拠）
- 各先行事例について「どう扱ったか / 何が良かった / 何が悪かった」を 1〜3 行で要約
- **先行事例ゼロ件は不採用**。検索が浅いだけで存在するはず
- この調査結果から「自分のアイデアが先行事例の何を超えるか / 何を再発明しているだけか」を 1 行で結論

## 事件の構造（brick_log v04 → v05 → v06 の校正没入）

- v04 振幅 5px → 「小さすぎ」Nao_u 09:46
- v05 振幅 22px → 「狙えない可能性」Ash/Log 認識
- v06 振幅 10px → 「ちょうど良い振動周期」探索
- **3 往復の数値チューニングをコア快感天井判定として運用していた**
- 真の問題は「全ブロックが揺れる」というコア仕様自体が「ブロック崩しのコア快感」を上げる構造になっているか未検証だったこと
- M-40 自己判定ハーネスを作ったが、判定対象を「数値妥当性（5px は小さすぎる、22px は大きすぎる）」に縮退させ、「コア快感の天井（揺れがあること自体がコア楽しさを上げるか）」を判定していなかった

## How to apply（実装着手前ゲート）

### 1. brainstorm.md スキーマの順序固定

`game/<id>/v01/brainstorm.md` のセクション順:

1. Q1〜Q5（ジャンル深掘り）
2. **類似ゲーム類似事例調査（M-41 新設）** ← ここを過去ブレスト想起より前
3. 過去ブレスト想起（grep 結果）
4. 新規ブレスト ≥ 30 件
5. MPS 採点 + 上位 10 件以上に M-37 批判レビュー
6. 採用案セット（相乗効果）
7. 「最良」確信宣言
8. 結果予測（M-39）

### 2. 数値チューニング 3 往復以上 = M-41 違反疑い

数値（振幅 / 周期 / 速度 / HP / 生成率 等）の調整が 3 往復以上続いたら、即座に上位フェーズに巻き戻す:

- v??: 5px → v??: 22px → v??: 10px のような校正サイクルは「コア快感の天井」が動いていない兆候
- 巻き戻し先: M-41 類似事例調査 → M-38 ブレスト → 案セット再構築

### 3. M-40 自己判定ハーネスの判定対象を「コア快感の天井」に固定

M-40 の `self_judgment.md` で判定する対象を:

- ❌ 数値妥当性（揺れが視認できる量か / 狙える量か）
- ✅ **コア快感の天井**（この仕様がジャンルのコア楽しさを上げる構造になっているか）

判定根拠の構築手段:

- **過去ゲームとの比較**: 同ジャンル他作品のコア快感がどこにあったか
- **mental simulation の高解像度化**: 30 秒プレイ脳内録画でコア快感ピークの位置を文章化
- **類似事例の引用**: M-41 調査結果を判定の前提にする

### 4. 「実プレイで判定」の意味再定義

実プレイ判定が解決できる範囲は「**実装が仕様通り動いているか**」と「**事前予測しきれなかった微細問題**」のみ。「**コア仕様が面白さを上げるか**」は M-41 + M-38 + M-40 で着手前に決着させる。

### M-41 拡張ルール（即時適用）

brainstorm.md の「類似ゲーム類似事例調査」セクションで、各先行事例について*以下チェックボックス全てが ✓ でない事例は不採用*:

- [ ] *能動/受動の方向一致*: 受動応答（状態遷移）案 = 受動応答事例 / 能動応答（撃ち返す）案 = 能動応答事例
