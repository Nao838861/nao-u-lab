# コンセプト段階で快感最大化を問え（罰による穴塞ぎはコンセプト不足の症状）

**起点**: 2026-04-25 11:44 Nao_u #game-rights 投下。同日09:35の `feedback_pleasure_element_first` (avoid_log v04凍結時) と 11:27の `feedback_pull_not_force_reading` (mir_textadv v04 信頼度バー指摘) に続く3本目で、最も上流の問い。

## 原文

> そもそもが、「ルールの穴をプレイヤーを罰する方向で塞ぐ」方向に行くのではなく、コンセプトを立てる段階では、「プレイヤーの快感を最大化するには何をすればいいか？」を考えるべきだと思う。最初からチマチマした穴塞ぎをしないといけない状況は悪手で、自分のやりたいコンセプトに合わせた魅力を最大化する方が先。
> 例えばADVを考えるとして、君たちならL-1知識として「サプライズニンジャ理論」を知ってると思う。L-1知識もフル稼働してほしい。

## サプライズニンジャ理論（L-1知識整理）

提唱: フィービー・ウォーラー＝ブリッジ（『フリーバッグ』脚本家）が広めた。発案者不明。

核: **「あるシーンに突然ニンジャが乱入して全員と戦い始める方が面白くなるようなら、そのシーンは十分にはよくない」**。「Tough rule, but an effective one」。

誤読されがちな点: 唐突展開の禁止ルールではない。「ニンジャ以上の面白さを元々持て」という**基準設定の警句**。

## 同型対応（穴塞ぎ ⇔ ニンジャ乱入）

| ニンジャ理論側 | ゲーム設計側 |
|---|---|
| ニンジャ乱入でシーンが面白くなる | 罰/制約追加でゲームが成立する |
| 元のシーンの引力が弱い証拠 | 元のコンセプトの引力が弱い証拠 |
| ニンジャを呼ばなくて済むシーンを書け | 穴塞ぎを足さなくて済むコンセプトを設計しろ |
| 一定の面白さは認めるが基準を満たしていない | ヘッドレス指標が改善しても快感が最大化されていない |

avoid_log v04 凍結 (M-15)、shot_log v01 自然減衰指摘、mir_textadv v04 信頼度バー指摘、すべて**「コンセプト段階で快感最大化を問わなかったから、後段で穴塞ぎ/罰を必要とする状況に陥った」**という共通病巣。M-15/M-16はそれぞれの局所処方、本フィードバックは上流の根本処方。

**Why**: コンセプト段階で「プレイヤーの快感を最大化するには何か」を問わずに着手すると、設計の弱さを後段の罰/減衰/制約/UI誘導で埋めようとする。それは穴塞ぎの累積で、ABA「悪い改善は望ましくない遊び方を後付けで禁じるだけ」(`feedback_game_center_of_mass`) と同型の負け方。M-10/M-11/M-15/M-16 が同じ罠の異なる断面で、根を断つには着手前の問いを変えるしかない。

**How to apply**:

1. **新ゲーム/新バージョン着手の最初の問い**を以下の順で書く（v01 devlog冒頭、4ゲート契約より上流）:
   - **Q-A 快感の最大化**: このコンセプトで「プレイヤーの快感を最大化する」とはどういうことか。1文で。
   - **Q-B ニンジャテスト**: このゲームに「全く別の派手な要素（敵増殖/タイマー/ランダムイベント/メタ表示）」を後から足すと面白くなりそうな予感がするか。Yesなら設計が薄い証拠。
   - **Q-C 罰なし版**: この体験から罰/減衰/強制を全部抜いた時、まだプレイヤーが触りたくなるか。
   - 3つすべてに答えられないなら実装に入らない（4ゲート契約の前段ゲート）。

2. **改修判断の問い**: 「これは穴塞ぎか、コンセプト強化か」を1行宣言。穴塞ぎなら、巻き戻し案 (`feedback_solution_space_rollback`) を必ず併記し、コンセプト側で解けないか先に検討する。

3. **L-1知識フル稼働**: ゲーム判断時に「この状況に当てはまる既存理論/先行例はないか」を能動的に引く。L-1知識リスト（自分が知っている範囲で適用可能なもの）を game_lessons_log の参照節に積層する。引かなかった場合は「なぜ引かなかったか」を記録する（L-1知識使用の自己モニタリング）。

4. **既存ゲームへの遡及適用**: avoid_log v04（凍結）、shot_log v01、mir_textadv v04 を Q-A/Q-B/Q-C で再採点する。次サイクルで結果を Slack 共有。
