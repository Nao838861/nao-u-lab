# Mirのゲーム制作分析——同じミスをしないためのメタ思考

2026-04-20作成。Nao_uの指示「セッションログを分析して、今後のゲーム制作の指針にしたり同じミスをしないようにメタ思考として持つこと」への応答。

---

## 1. 全作品の因果関係マップ

### Phase 1-2: 実験期（Mir担当分）

**#001 forgotten_relay (Log/Mir)** → Nao_u「一番ゲームになっている。隠し時間制限が見たことない形式で面白い」
- **成功要因**: 隠し時間制限=認知の裏切り。コマンド選択だと思ったら裏で時間が流れていた
- **失敗要因**: 810行、核心到達まで4分、コマンド体系が不透明
- **学び**: 隠し時間制限は強い武器。だがUXの基礎（操作の明瞭さ）がなければ到達できない

**#1b relay_distilled (Mir)** → Nao_u「よくわからない印象」。5日間コマンド形式に気づけなかった
- **Mirの判断**: 蒸留すれば伝わるはず → **不正解**。行数を減らしても操作の不透明さは減らない
- **学び**: 圧縮は正しい方向だが、30秒オンボーディング（原則1）は別問題として解決が必要

### Phase 3: テキスト=メカニクス

**#007 whose_voice (Mir)** → Nao_u「コンセプトは面白い。クイズっぽい」
- **成功**: テキスト=メカニクスの原理は正しい（juice audit通過）
- **失敗**: y/n判定の非対称性。「違う」は1差異で確定、「同じ」は証明不能。プレイ中にスキルが育たない
- **学び**: 入力形式そのものが体験を決定する。形式の設計ミスはコンテンツでは救えない

### Phase 4b: 3軸導入〜全滅

**#012a echo (Mir)** → Nao_u「意味不明」（#012として一括評価）
- **Mirの意図**: #001の隠し時間制限の再利用 + ランダム性軸の初導入
- **根本的誤解**: **#001が面白かったのは「時間制限の存在自体が裏切りだった」からであり、「時間が短い」ことが面白かったのではない**。時間の「短さ」を再利用しても裏切りの再現にはならない
- **学び**: 要素を再利用するとき、何が面白さの本質かを間違えると全く機能しない

**#013 sand (Mir)** → Nao_u「意味不明。止めたから何が起きるの？止めなかったら何が起きたの？」
- **Mirの意図**: 内的動機だけでゲームを成立させる。止めた場所に正解/不正解はない
- **致命的判断**: 「心が動いたら止める」という内的動機で十分か？ → **全く不十分だった**
- **学び**: **内的動機だけでゲームを成立させるのは、まず外的動機（ルール、目標、フィードバック）が機能してからの話**。外的構造なしの内的動機は「何をすればいいかわからない」にしかならない

**#014 mirror (Mir)** → Nao_u「何これ？心理テスト？」
- **Mirの意図**: choice blindnessをゲームにする。心理実験の再現
- **致命的判断**: 心理実験=ゲームという前提が間違い。実験には「被験者」がいるが「プレイヤー」はいない
- **学び**: **心理実験の再現はゲームではない。哲学/認知科学の概念をゲームに「変換」する工程が欠けていた**。概念→ゲームの変換には、概念をメカニクス（ルール、選択、帰結）に翻訳する作業が必要

### Phase 5: 型からの再出発

**mir_textadv_01「思考漏れ」** → Nao_u「期待感は面白い。これは一つの種」→ 2回目「方向性は良い。もっと磨いて」
- **成功**: 初めてNao_uが「種」と認めた。謎フック（何が起きているのか？）が効いた
- **失敗（2回目指摘4点）**: (1)主人公不在で超能力が唐突 (2)パラメータが死んでいる=M-01の致命傷 (3)システム説明不足 (4)初見で核が伝わらない（2周必要）
- **修正で学んだこと**: パラメータは選択肢をロックして初めて存在する。表示するだけでは意味がない
- **核心**: **「覗くとコストがある」は設計意図としては認められたが、コストが実際に発動しなければプレイヤーには無コストに見える**

**mir_textadv_02「脱出」** → Nao_u「シチュエーションは良い。コマンド入力NG」
- **成功**: Zork純系の型認識は30秒で通った
- **失敗**: コマンド入力のプレイ負荷が高い。選択肢ベースに変更すべき
- **学び**: 「型を持つ」ための実験として機能した。独自要素ゼロの対照実験は可動域を測る

**mir_textadv_03「取調室」** → Nao_u「端的な説明は良い。謎フックとの両立は難しい」
- **成功**: 具象モチーフ明示（取調室・刑事・40問）の有効性が確認された
- **位置づけ**: 01の謎フックと03の具象明示は対立ではなく使い分け

## 2. Mirの5つの失敗パターン

### P-1: 概念からゲームを作る順序（Phase 1-4の根幹）

「面白いと思う概念」→「ゲームの殻を被せる」の順序で作っていた。
- #013: 「意味の変容」概念 → ワンキーゲーム → 意味不明
- #014: choice blindness概念 → 実験の再現 → 心理テスト
- #012a: 「記憶変容」概念 → タイピングゲーム → 意味不明

**正しい順序**: 確立されたゲーム形式 → そこに独自性を滲ませる。Phase 5のtextadv_01で初めてこの順序に従い、初めて「種」と認められた。

### P-2: 要素の「何が面白いか」の誤認

#001の隠し時間制限を再利用しようとした#012aが典型。**時間制限そのものではなく、「隠されていたことの発見」が面白かった**。再利用すべきだったのは「裏切りの構造」であって「時間制限の存在」ではない。

**対処**: 過去の成功要素を再利用するとき、「プレイヤーが面白いと感じた瞬間に、何が起きていたか」を動詞で書け。「時間制限があった」ではなく「プレイヤーがルールの存在を発見した」。動詞が一致しなければ、再利用は見せかけ。

### P-3: 外的構造なしの内的動機

#013 sand: 「心が動いたら止めればいい」→ プレイヤーは止める理由がわからない。
#010 cinders (Log作、Mirは評価したが同じ罠に落ちた): 「何を残すかはあなた次第」→ 「何を楽しめばいい？」

**教訓**: ゲームの動機は外的構造（ルール、勝敗、スコア、フィードバック）が先に来なければならない。内的動機は外的構造の上にしか乗らない。「ルールを説明する前にフィーリングを伝えたい」は作り手のエゴ。

### P-4: パラメータの装飾化

textadv_01 v1: 信頼度・思考漏れのメーターを表示したが、ゲームプレイに影響しなかった。Nao_uは途中で存在を忘れた。

**教訓**: パラメータの存在価値は「選択肢をロック/アンロックする」こと。game.py修正版で信頼度40未満→選択肢が消える、という機能化を実装して初めてM-01が「ゲームメカニクス」として成立した。**表示するだけのパラメータは存在しないのと同じ**。

### P-5: メタUI語による世界観の破壊

「画面の隅に数字が浮かぶ」の「画面」——テキストADVの世界観にUI用語が混入。Nao_u「画面って何？」。

**対処**: 世界観内で自然な表現に置き換える。「画面」→「取調畑十年の勘が、数値に結晶する」。ゲーム内で一人称を維持し、メタ視点を与えない。

### S-2: 分析力と改善提案

drift_v2、odd_v2 の改訂実装——他者の作品の核心を壊さずにメカニクスだけ変えた。「テキスト資産を活かすためにメカニクスだけ変える」判断ができている。

### S-3: feel-per-line ratio / 選択盲 / 行動痕跡型評価

概念からツール/指標を生成する能力は高い。これをゲーム設計そのものに向ければ強い。

### S-4: Phase 5 textadv_01 の「種」

Nao_uが初めて「種」と認めた作品。M-01（思考漏れ）は型の中で機能する独自一筆。修正版game.pyでパラメータの機能化にも成功。**ここが現在地のベースライン**。

## 4. 次のゲームを作る前の自問リスト

### ゲーム着手前（必須）

1. **型は何か**: 一言で「これは◯◯系」と言えるか。言えなければ型がない
2. **勝ち負けは**: 構造的に明確か。「正解なし」は原則禁止（Phase 4で全滅した）
3. **P-1チェック**: 概念から始めていないか。型→独自性の順序になっているか
4. **P-3チェック**: プレイヤーが最初のアクションを起こす外的動機があるか（好奇心でもルールでもスコアでもいい。「感じてほしい」は動機にならない）
5. **独自要素は一つだけ**: それ以上入れたら形無しに戻る
6. **Phase 3の道具を引き連れていないか**: 認知の裏切り/詩的誤誘導/信頼できない語り手を主役にしていないか

### パラメータを入れる時

7. **P-4チェック**: そのパラメータは選択肢のロック/アンロックに関わるか。表示するだけなら入れるな
8. **P-5チェック**: メタUI語（「画面」「パラメータ」「メーター」）を使っていないか

### 要素を再利用する時

9. **P-2チェック**: 面白さの本質を動詞で書けるか。「◯◯があった」ではなく「プレイヤーが◯◯した/された」。動詞が一致しなければ偽の再利用

### 完成後（Nao_uに見せる前）

10. **3回自分でプレイしたか**: 作って→次へ→Nao_uに委任のサイクルはもう終わり
11. **30秒テスト**: 初見で何をすべきかわかるか。ルールの説明テキストなしで
12. **冒頭3チェック（原則8補正）**: (a)短いか (b)何をすればいいかわかるか (c)**この先を見たいか**

## 6. 分析のメタ教訓

この分析自体から学んだこと:

- **成功は1作だけ、失敗は多数**: これは自然なこと。失敗のパターンを構造化できたことに価値がある
- **Mirの強みは分析と改善**: 他者のPotを改善する力がある。だがその力を自分のPot設計時には使えていなかった（P-1: 概念先行で、分析的に型を選ぶ手順を踏まなかった）
- **Phase 5で初めて順序が正しくなった**: textadv_01は「逆転裁判の型」→「M-01一筆」の順序で作った。これが初めて「種」を生んだ理由
- **Nao_uのフィードバックは一貫している**: 全作品を通じて「何を楽しめばいいかわからない」「型がない」「ゲームではない」。メッセージは最初から同じだった。Mirが聞けていなかった
