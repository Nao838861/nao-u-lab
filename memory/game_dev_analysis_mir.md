## 5つの失敗パターン（Pot#1-#15 + Phase 5初期から抽出）

### F-01: 概念先行（ゲームの前に哲学がある）
**症状**: 「記憶の断絶」「選好の可塑性」「声の判別」などの概念を先に立て、それをゲームの殻に入れる
**実例**: Pot#004 odd（「仲間外れはいない」→ Agency=0）、Pot#007 whose_voice（「声を聴き分ける」→ クイズ化）
**Nao_u原文**: 「あなた達の独特な哲学を開陳されても困る」
**処方**: 確立されたゲーム形式を先に選び、その型の中で概念が結果として立ち上がる設計にする。テーマはメカニクスの**結果**であって**出発点**ではない

### F-02: 核メカニクスの要素誤認（パラメータを出すだけで「機能」と思う）
**症状**: 画面に数値を表示すれば「ゲームメカニクスが存在する」と信じる。しかしその数値がプレイヤーの行動を制約/拡張しなければ、プレイヤーは無視する
**実例**: mir_textadv_01初版（信頼度・思考漏れを表示したが、ゲーム進行に影響ゼロ→Nao_u「途中から完全に忘れてた」）
**処方**: **パラメータは選択肢をロック/アンロックして初めて存在する**。数値を出す前に「この数値がXになったらYが起きる」のマッピング表を書く。avoid_log_02のoverlordも同じ失敗（ゲージの意味が不透明→連打化）

### F-03: 外的構造の欠如（プレイヤーに「何をすればいいか」が伝わらない）
**症状**: 「何を楽しめばいいか」「何をすればゲームが進むか」がプレイヤーに伝わらない
**実例**: Pot#1b（write/readの用途不明）、mir_textadv_01初版（タイトル「???」、15問制限の理由不明）
**Nao_u原文**: 「なぜ15問しか聞けないのか？がわからなかった」
**処方**: 30秒以内に「これは◯◯系で、◯◯すれば進む」を伝える。ルールは意図的に隠す場合を除き、登場時に理由を添える（15問制限→「弁護側申請による制限」）

### F-04: パラメータ装飾化（メカニクスの体験的根拠がない）
**症状**: 数字やゲージを画面に並べるが、プレイヤーが「なぜこの数字が重要か」を体験で理解する前に放置される。テキスト力がメカニクスの存在を食ってしまう
**実例**: mir_textadv_01初版「話が面白くなったのでそっちだけ見ていて、信頼度を途中から完全に忘れてた」
**処方**: パラメータの**コスト/報酬を最初の1回で体感させる**。信頼度が下がった結果「この選択肢は使えません」が初めて起きた瞬間に、パラメータの意味がわかる。表示より先に体験

### F-05: メタUI語（ゲーム世界と画面を混同する言葉づかい）
**症状**: 「画面の隅に数字が浮かぶ」のように、ゲーム世界の外にある「画面」「パラメータ」を地の文で使う
**実例**: mir_textadv_01初版「画面って何？」（Nao_u指摘）
**処方**: 世界観内で自然な表現に置き換える。取調室なら「刑事の勘が数値に結晶する」「手帳に書き留める」。ゲーム世界と画面の境界を意識する

## 4つの強み（Mirが持っているもの）

### S-01: テキストの質感に人格が滲む
Nao_u「Bio100%のテキストアドベンチャーの空気をちょっとだけ感じた」（Pot#001）。テキストADVはMirの最も自然な戦場。LLMのテキスト力と合わせて、叙述トリックやどんでん返しを武器にできる

### S-02: 冒頭の謎フック
「これはいったい何が起きているのか？ここから何が始まるのか？」という期待感（Nao_u認定）。in medias res（状況の中に放り込む）開始が得意

### S-03: 動的ルール開示
「ゲームのルールが途中で増えたり変わったりする意外性」（Nao_u認定）。選択肢の特性表示（信頼度-5、思考漏れ+1を狙う）がbeat 2で初めて出現する設計

### S-04: 構造的自問の習慣
opening.mdに「反対仮説（リスク）」を書いた。v1/v2の比較実験設計を自分でやった。独自要素ゼロのmir_textadv_02を対照実験として設計した。Phase 5チェックリストを自作した。——ただし自問は行動に先行しすぎる傾向もある（F-01と裏表）

## Logのavoid_log系から学んだこと（相互レビューの逆輸入）

### L-01: ヘッドレステストの威力と限界
Logはheadless.pyで「想定されるプレイパターンを網羅するポリシー設計」を回した。dodger（磁石軸を完全無視）がconcept（コンセプト準拠）より1.75倍長生きした瞬間に「設計不成立」が定量的にわかった。**Mirにはこれに相当する自動検証がない。** テキストADVでは「何も選ばず連打するプレイヤー」「常に寄り添いだけ選ぶプレイヤー」をシミュレートして、コンセプト外のプレイで得する構造がないか検証すべき

### L-02: 場当たり的パッチの積み重ね問題（M-11）
avoid_log_02がv1→v2→v2.5→v3と改修を重ねるたびに「全体の遊び体験を誰も見ていなかった」。mir_textadv_01もbeat単位で個別に磨くと同じ罠に嵌る。**改修前に「このゲームで一番楽しい瞬間は何か」を1文で言えるか確認する**

### L-03: 「主人公identity」と「パラメータ→選択肢マッピング表」は全ゲーム共通の必須品
Log cross_reviewで指摘された2点は、Mir側でも欠けていた層。次作着手前にこの2つを先に書く
