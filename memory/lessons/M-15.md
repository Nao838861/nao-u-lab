### M-15: 「快感を削った改修」を自覚せず難度調整に潜る盲点（avoid_log v01-v04 / 2026-04-25 Nao_u #game-rights 09:35）
**事象**: avoid_log v01 で2点を改変——(a) 攻撃発動を磁力場160px近接限定 (b) 攻撃が AI周囲180pxの鉄片を範囲全滅。これにより「弾で狙い撃つ」「ゲージで弾増えて当たりやすい」というシューティングの核快感が**丸ごと消えた**。にも関わらず v02 (地雷) → v03 (dirBias圧力) → v04 (nearBias圧力) と「dodgerが強すぎる」「近接連打が単調」など二次問題への対処療法を3世代積み重ねた。Nao_u指摘で初めて「快感が消えていた」事実に直面。
**根本原因**:
- v01 の重心審問（このゲームの快感は何か）を**一度もやっていない**。「磁石+鉄片」をメカとして面白いと仮定したまま走った
- [M-10](M-10.md)/[M-11](M-11.md) を game_lessons_log に書きながら、新作で同じ轍を踏む = 知識の存在 ≠ 行動の変化（feedback_index.md #5/#26）
- 「圧力設計 vs 禁止追加」の重心審問は v03/v04 で言語化していたが、**もっと上位の「快感は残っているか」を飛ばしていた**
**次回の規則**:
- 新ゲーム v01 着手時、index.html を1行も書く前に「**このゲームで一番嬉しい瞬間は何か / それを支える操作は何か**」を devlog 冒頭に書く
- 改修案を出すたび「この改修で消える快感はあるか」を1行で書き、Yes/No 答えてから着手
- 「圧力設計 vs 禁止追加」の重心審問の**前**に「快感審問」を置く（上位ゲート）
- ヘッドレス指標が改善しても、快感審問でNoが出たら採用しない
- **外部対応語**（業界共通用語への翻訳。R-007 自己適用）:
  - **fun-first design / juice-first iteration** — Jonasson & Purho 2012 GDC "Juice it or lose it"。改修ループの最上流に「快感が出ているか」を置く運用論
  - **core loop preservation** — Schell *Art of Game Design* / 一般的な game feel 文献。M-15 の「核快感が消えた事実」を見落とすな、はこの保全規律の名前で知られている
  - **headless metrics fallacy** — A/B テスト・自動指標偏重の罠（UX分野で "Goodhart's law in playtest" として議論）。指標が改善しても核体験が壊れている可能性
  - **"polishing the wrong jewel"** — Schell / Pixar 系設計論で頻出する比喩。手応えのない部分を磨いて時間を消費する典型
  - 関連反例 = "difficulty-tuning trap"（難度調整名目で快感を削るパターン、Souls 系議論で時に正当化される——M-15 はこの逃げを警戒）
- `[古典度: 低 / 固有度: 高]` 古典出典なし（自然減衰禁止/快感審問の一般文献は未引用、Csikszentmihalyi flow との重なりはあるが未参照） / 固有=2026-04-25 09:35 Nao_u #game-rights 直接介入、avoid_log v01〜v04 4世代の具体崩壊経路。固有経路100%（kaizen α 試行 2026-04-27 C139 Phase 3、Nao_u #human-steering 13:31「ほとんど一般的な話」への自己照合）
