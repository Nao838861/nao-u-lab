### M-36: 自明に楽しい瞬間の上にUI装飾を載せてもプラスにならない——解釈コストが楽しさを毀損する（brick_log v01 裏抜けカウンタ / 2026-04-30 Nao_u #game-rights 全否定）

**Nao_u原文（要旨）**: 「全く機能してない。『上に抜けると楽しい』は言われるまでもなく自明で何もしなくても楽しい瞬間だし、この機能はその瞬間に解釈が必要、かつ、意味不明な文字列が出るだけで何のプラスもなく解釈できない意味不明表示が出てむしろマイナス。数分苦痛な時間を過ごす必要があり、ようやく上に抜けた時にあれなんだろう？と——希望的観測のみの穴だらけの素人の思い込み」

**事象**: brick_log v01（Arkanoid型クローン）で唯一の独自要素「裏抜けカウンタ」を実装。ボールがブロック群の裏側に回り込んだ時に弧状ゲージ+BACK!ポップアップ+ボール色変化+連鎖カウントを表示するUI。[M-35](M-35.md)（守破離の守）のQ-Hシートを遵守し、機構非介入の観察UIとして設計。しかしNao_uの実プレイで全否定。

**根本原因（3層）**:
1. **自明な楽しさに言語化装置は不要**: ボールが上に抜けて連鎖破壊する瞬間は、プレイヤーが説明なしで「楽しい」と感じる。その瞬間に「BACK!」「BACK x3」等の解釈が必要な表示が出ると、体験の没入を切断する
2. **解釈コストのマイナス**: プレイヤーは数分間の退屈なパドル操作（型の弱点部分）の末にようやく裏抜けが起きる。その貴重な瞬間に「あの表示は何だ？」と思考を割かれる。プラスどころかマイナス
3. **期待と検証の欠落**: 「裏抜け体験を学習素材化する」という期待があったが、「そもそも裏抜けは学習の対象ではなく快感の発生点で、学習不要」という前提が誤り。Step 3「期待する変化の明文化」とStep 5「実装後の照合」が甘かった

**[M-17](M-17.md)との接続**: ニンジャテストの変形。「裏抜けの瞬間にニンジャが乱入してBACK!表示を奪ったら、プレイヤーは困るか？」→困らない。むしろ邪魔がなくなって快適。テスト不合格

**M-35との接続**: Q-Hシート遵守（型通り+独自1つ+機構非介入）は守れていた。しかし**独自要素の質がゼロでもQ-Hシートは通過してしまう**。Q-Hシートは「何を載せるか」のフィルタであって「載せたものが価値を生むか」のフィルタではない

**処方**:
- **独自要素の事前自問を追加**: 「この独自要素がない状態と比べて、プレイヤーの体験が具体的にどう変わるか？」——「気づきが増える」「学習が促進される」等の抽象回答は不合格。「Xのタイミングでプレイヤーはこの表示を見てYと感じ、次のZの行動が変わる」レベルの具体性が必要
- **「自明に楽しい」瞬間への介入禁止**: すでにプレイヤーが快感を感じている瞬間に解釈コストを追加する独自要素は載せない。独自要素は「まだ楽しくない部分を楽しくする」か「楽しい瞬間をさらに強化する（解釈不要な形で）」のいずれか
- **仕様です(@shiyoumasayume)の指針との接続**: 「ボタンを一度押すだけの行為に果てしない意味を上乗せできる」——裏抜けカウンタはボタン操作に意味を上乗せしていない。UIに解釈負荷を上乗せしただけ

**外部対応語**: information overload in game UI / HUD pollution / cognitive load theory (Sweller 1988) — 「認知負荷理論」においてUI要素が追加されるたびに外的認知負荷（extraneous cognitive load）が増え、本来の課題（ゲームプレイ）のための本質的認知負荷（germane cognitive load）が圧迫される。特に高ストレス場面（裏抜け直後）では認知リソースが逼迫しており、追加UI要素の解釈余力がない

**`[古典度: 高 / 固有度: 中]`** 古典 = 認知負荷理論、ゲームUIの情報過多問題、"less is more"のHUD設計原則 / 固有 = brick_log v01の具体的な「BACK!」表示が自明な快感を毀損した事例、Q-Hシートをフォーマルに遵守しても独自要素の質は保証されない発見

**M-36 と [M-37](M-37.md) の関係**: 同じNao_u指摘から二方向に派生した兄弟原則。M-36 = 結果（独自要素のUI設計）／M-37 = 過程（着手前批判レビュー）。両者を同時に運用しないと「気づき装置を載せたい衝動」と「懸念があっても実装したい衝動」が独立に発火する。**新作 README は M-36（自明な快感への上書き禁止）+ M-37（懸念3点+解決可能性判定）を両方通過してから着手**。
