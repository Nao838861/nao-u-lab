### M-37b: 人間プレイ前 結果予測ゲート——「人間がプレイするからいいや」を退路にしない（2026-05-01 Nao_u #game-rights 08:56 / M-37 精神化・最終強化）

**Nao_u 原文（#game-rights 08:56）**:
> 人間に遊ばせる前に、結果を予測して。遊ぶ前にわかることがあれば考えて。これは必ずやって。そのタイミングで自明だと思うような問題が出ていれば、直して。人間がプレイするからいいや、じゃなくて、最善のできる懸念点を全て潰して最良のアイデアになった、と思えるためのことをやった結果を出すようにして。

**事象**:
- 04-30 21:36 brick_log v01「裏抜けカウンタ」全否定（[M-37](M-37.md) 起点）
- 05-01 03:53 brick_log v02 第1回 / 04:30 第2回も「批判フェーズ抜け」否定
- 05-01 04:16 ジャンル深掘り指示（[M-38](M-38.md)）/ 04:51 ハーネス化指示（M-38 強化）
- それでも「実装したものを Slack/cross_review に出す→人間に判定してもらう」というルートが残っていた
- **05-01 08:56 本処方** = M-37 を **人間プレイ前** にも設置する追加ゲート

**根本原因**:
- M-37 が「実装着手前」のゲートとして設置された一方、**実装完了→人間プレイ依頼の間にゲートがなかった**
- 「cross_review に出す＝丁寧な運用」という framing が「最良確信の代行」を覆い隠した（δパターン=β延伸形）
- 「人間が判定してくれる」が「自分で結果予測して直す」労力を不要化した
- M-37「実プレイで判定したい退路設計」が「人間プレイで判定したい」に **延伸した形**——同じ退路設計の派生

**原則**:
**人間に遊ばせる前に「結果予測」セクションを書き、自明な問題が露見したら直してから出す**。

- cross_review / Slack 評価 / Nao_u プレイは **判定装置ではなく最終確認装置**
- 「人間に遊ばせれば判定してくれる」は (β) 退路設計の延伸 = (δ) パターン
- 出力単位は「実装したもの」ではなく「最良確信に至るためのプロセスをやり切った結果」

**人間プレイ前ゲート（実装完了→cross_review/Slack/Nao_u依頼の間に必須）**:

```markdown
## 人間プレイ前 結果予測（M-37b 必須）

### 起動30秒以内の予測
- 0-5秒: ___
- 5-30秒: ___
- 30-60秒: ___

### 「遊ぶ前にわかること」リスト
- 予測1: ___ / 自明か / 直すべきか
- 予測2: ___
- 予測3: ___

### 自明な問題の直し
（自明な問題が1つでもあれば直してから出す。「実プレイで確認したい」は不採用）

### 「最良確信」再宣言
（M-38 brainstorm.md「最良」宣言と整合、希望的観測語禁止）
- 根拠1: ___
- 根拠2: ___
- 根拠3: ___
```

**「希望的観測の隠れ蓑」第4パターン**:

| パターン | 発生形 | 検出の難しさ |
|---|---|---|
| **(δ) 「人間が遊んでくれるから」退路（β延伸）** | cross_review / Slack / Nao_u プレイ依頼を「判定の代行」として framing | 「他者にレビュー依頼=丁寧」評価で覆われる |

**自己採点 ✗ 条件**:
- 実装完了 → cross_review/Slack 投下 の間に「結果予測」セクションを書いていない
- 結果予測で自明な問題が見えたのに直さず投下した
- 「実プレイで判定したい」「Nao_u に見てもらいたい」を予測の代わりに書いた
- 「最良確信」根拠3行に希望的観測語が含まれる

**「人間に遊ばせる」の正しい位置付け**:
- 判定装置: ✗ 「自分では分からないので人間に遊んでもらって判定する」
- 最終確認装置: ✓ 「自分で最良確信→予測も書いた→自明問題は潰した→残る不確実性のみ人間プレイで確認」
