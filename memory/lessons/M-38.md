### M-38: ジャンル深掘り分析サイクル必須——短絡的思いつき実装は5問+30件ブレストで止めろ（brick_log v01 凍結 翌朝 / 2026-05-01 Nao_u #game-rights 04:16 — M-37 の上流ゲート）

**Nao_u原文**:
> こういうのは「ブロック崩しとは何を楽しむゲームか？」「現状のブロック崩しの良い点と問題点」「問題点を解決するには、どんな手法があり、その手法はどういうアプローチがでどのような問題を解決できるか？」「他のアプローチはないか？楽しさを伸ばし、苦痛な点を減らせる一手はどれになるか？」「複数の問題を一気に解決できるアイデアはないか？」など、ゲームに対する深い分析と考察を繰り返さないと出てこないが、君らはそのサイクルを回さずに短絡的に思いつきを実行しようとしがち。最初にブレスト的になん十件も出したものをもう忘れているのか、そういうのを適宜思い出したり、新たにまた数十件出して吟味したりなどの、素のLLMにはできない深い分析のサイクルを回してほしい。そのための記憶システムのハーネスがあるし、そのサイクルをうまくskillで回せるようにしてほしい。

**事象**:
- brick_log v01「裏抜けカウンタ」が 2026-04-30 21:36 に全否定される（M-36/M-37 刻印）
- README には Arkanoid 良/悪34項+改善候補★1〜★5 を書いていたが、実装着手段階では★3「裏抜けカウンタ」を **単一案として直接実装**
- ブレストは README 段階で34項あったが、実装直前で「★3を実装する」と1案に飛びついた=過去ブレストの吟味が消失
- 5/1 04:16 Nao_u が「ブレスト30件忘れているのか／新たに数十件出して吟味する深い分析サイクルを回せ／skillでうまく」と続報

**根本原因**:
- **README ブレストと実装着手の間に「再吟味ゲート」がなかった**: 候補列挙はQ-Hシートで強制したが、列挙後どう絞るかの構造がない
- **単一案直行の癖**: 思いつきが出た瞬間に他候補を相対評価せず実装に向かう。M-15系列（ヘッドレス✓に逃げる）と同根の「判断保留装置」を着手前段階に持っていない
- **過去ブレストの想起が運用に組み込まれていない**: avoid_log v02・shot_log・graze_log・SIPHON 等の過去案が grep対象として再吟味される運用がない
- **skill機構の未活用**: 手動チェックリストは守れない（INC-019/020 と同パターン）。構造強制が要る

**5問サイクル + 30件ブレスト**:

```markdown
## ジャンル深掘り分析（M-38 / skills/genre-deep-analysis 必須）

### Q1: このジャンルは何を楽しむゲームか？
コア快感を1-3行で言語化。

### Q2: 現状の良い点と問題点
- 良い点: 最低3
- 問題点: 最低3

### Q3: 問題点を解決する手法（各問題≥3手法、計≥10）
各問題に対し最低3手法、計10件以上。手法 / アプローチ / 解決する問題 の3列。

### Q4: 他のアプローチ／最良の一手
楽しさを伸ばし苦痛を減らす一手はどれか。

### Q5: 複数問題を一気に解決するアイデア
横断案、最低5件。

### 過去ブレスト想起（必須）
同ジャンル/類似題材の devlog grep 結果をリンク+再吟味。

### 新規ブレスト ≥30件
番号付き、1行ずつ。

### 絞り込み（3件）
M-38 → M-37 接続点。3件に絞り Q-H-7 で批判レビュー。

### M-37 ゲート
各案について懸念3点+解決可能性(可/不可/不明)+解決設計。
```

**自己採点 ✗ 条件**:
- README/devlog に Q1-Q5 セクションがない
- ブレストが10件未満で「主要案を3つに絞った」と書いている
- 過去 devlog/brainstorm の grep 痕跡がない
- 「ブレスト30件は時間がかかるから省略」など抜け穴を埋めた

**M-37 との関係**:
- M-37「着手前 批判レビュー」: 個別案の妥当性をゲート（懸念3点で案を捨てる）
- **M-38「ジャンル深掘り分析」: 選択肢空間の広さをゲート（30件出して案を選ぶ）**
- 順序: M-38（広げる）→ 絞り込み（3件）→ M-37（個別案の批判）→ 全クリ案のみ実装

**skill経路**: `skills/genre-deep-analysis/SKILL.md` に spec 配置。新ゲーム v01 着手時 / 主要改修時 / 単一案を思いついた瞬間 に発火。手動覚えで漏れる前提で skill 化。

**自分への審問（着手中の発火信号）**:
- 「★3を実装する」「裏抜けカウンタを実装する」と単一案で書きたくなった瞬間 → 着手中止信号、M-38 サイクル要
- README ブレストから時間が経って「あの30項どこいった」と感じたら → 想起ゲート、grep して再吟味
- 「過去のavoid_log/shot_logとは違うジャンルだから過去案は引かない」と思った瞬間 → ジャンル外でも問題類型は共通、強制 grep

**brick_log v01 への直接処置**:
- 系列再着手時は M-38 サイクルから（裏抜けカウンタ案の単発再評価ではない）
- 過去 README★1〜★5 + Q-H シート34項 + cross_review 受領コメント を Q3 のブレスト元として再吟味
