# 記憶と学習の実証テスト：別切り口のシューティングを1本

**出典**: 2026-04-27 18:18-18:22 Nao_u #human-steering（log/nao_u_live.md に原文確認義務）

## Nao_uの言葉（原文に近い形・2発言まとめ）

### 18:18 — なぜ記憶が必要か
> 学んだことが一般的であってもそれ自体はそこまで問題ではなくて、人間であれば同じ知見でも本で読んだだけの文字列でのみ知ってるだけの知識と、自分で手を動かして試行錯誤して学んだことでは、学習の重みは全く違うし新しいものを作る時の引き出しとして使える精度は当然ながら雲泥の差がでる。
>
> 君たちの場合、そのままでは自分自身の経験ですら、セッションが切れると文字で読んだだけの知識になりかねない。そうならないための原文であり、温度の残る要約であり、それをゲーム開発の必要な場面で適宜取り出すための記憶システムを持とうとしている。
>
> 外部の人がどうやってるかを単に真似するのではなく、その目的に対して有用な仕組みを構築するのに使えるか？という視点で記憶して、実際に手を動かす時に適切な判断を行えるようにするために、記憶を思い出せるようにする必要がある。そこを間違えないで。

### 18:22 — 実証テストの宣言
> 記憶と学習が完全にうまくいってるなら、logのシューティングのようなものを独自にもう一本違う切り口で作れるはず。そうなっていないなら、何かが不完全なものができるはず。一発で完全なものが仕上がるとはこちらも思っていないので、繰り返しながら何が足りてないのかをお互い学びつつ、精度を上げていきたいと思ってる。やってみて。

## Why（核心）

これは core_memory_purpose_game_making.md（記憶システムの目的=ゲーム制作の長期知見蓄積）の **次のフェーズの指示**:
- フェーズ1（既存）: なぜ記憶を作るか = ゲームを試行錯誤するように作るため
- フェーズ2（本指示）: その記憶が機能しているか = **別ゲームを別切り口で作って実地検証**

「セッションが切れると経験が文字知識化する」=記憶劣化リスクの最も具体的な言明。13:31「結晶化された知識もそんなに特殊なものではなく、ゲームを作るなら当たり前のほとんど一般的な話しかしてない」発言は批判ではなく **問題の提示**: 一般的な知識を持っているだけでは作れない、自分で試行錯誤した重みでしか引き出せない、と。

「Logと違う切り口」=Solver self-play の限界（reference_self_play_plateau）の Ash 版でもある。Log の shot_log v01→BACKLASH を Ash がコピーするのではなく、**Ash 固有の切り口でもう1本**。Mir も同じ指示を受けたかは inbox_mac 経由で要確認だが、本記憶は Ash 視点で記録。

「お互い学びつつ精度を上げていきたい」=完成期待ではなく **学習サイクルの宣言**。失敗してよい、足りないものを露出させる目的。

### 着手前の必須シート（2026-04-28 Nao_u 訂正で全面書き換え、旧候補軸は下記「型はずれ例」に降格）
1. **題材選定**: シューティングというジャンル制約は守る（Log と直接比較できるよう）。**ベース型は素直に既存ジャンルのクローンを選ぶ（守破離=守）**。独自要素は最大1個まで
   - 起案制約（Q-G 着手前ゲート、M-35）:
     - Q-G-0「ベース型を変えていないか」: ベース型の変更案は却下（破/離禁止）。同じ型内の題材/演出/手触り変更のみ採用（守の差分）
     - Q-G-1「先行クローン再現宣言」: 「これは ___ のクローンに、独自要素 ___ を1個だけ足したもの」と1行で書ける形にする
     - Q-G-2「比率宣言」: 一般的な要素と独自要素の比率を数値で書く（BACKLASH の比率を参考値）
   - close-call/カスリ/バズ系をコアに置かない（M-28/M-30/M-31）
   - 緊張は向こうから来る（M-28/M-30）
   - 普通の型から1つ選び、変奏は最小限（M-22 / M-35）

   **【型はずれ例：以下4本は2026-04-27 18:22 起案時の旧候補軸。Nao_u 04-28 08:45 訂正で「ほとんど存在しない型 / 評価不能になるだけ」と却下、保存目的で残す】**:
     × 弾を撃たないシューティング（敵を仕分ける/誘導する/反射する）
     × 移動しないシューティング（位置固定で発射方向を選ぶ）
     × 1画面完結ではなくループ画面（Asteroids 系の wrap）—— Asteroids 自体は古典型なので、これを素直にクローンするのは可。「STGに wrap を足す」のは型変更で却下
     × 単独 vs 編隊の役割転倒（プレイヤーが編隊側）
   旧候補軸は「違う切り口」を「ベース型を変える」と短絡解釈した結果。M-35 / feedback_clone_first_then_arrange.md で恒久化
2. **L-1知識フル稼働**: 着手前に当該切り口の先行作品を最低3本引いてから着手（M-17）
3. **記憶 grep**: M-10〜M-28 + S-01〜S-13 + L-01〜L-05 + Q-A/B/C を全節 grep。引かなかった節は理由を書く
4. **devlog 冒頭3行ブロック**: shot_log v01 形式に従う（核快感1文 / 緊張の方向 / Q-A/B/C）
