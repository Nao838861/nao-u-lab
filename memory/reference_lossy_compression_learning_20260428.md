# Learning is Forgetting — LLM as Lossy Compression（2026-04-28 Nao_u 無言投下 #nao-u 20:02）

出典: https://arxiv.org/abs/2604.07569 （t.toda @Trtd6Trtd 2026-04-28 引用）

## 主張の骨子

- LLM学習は「覚える」ではなく「**うまく忘れる**」=lossy compression。MP3が可聴外周波を捨てるのと同じく、目的（next-token予測）に必要な情報だけ残し残りを捨てる。
- 事前学習は **information bottleneck の理論的圧縮限界**に近づく。学習＝最適な情報フィルタリングに収束。
- モデル族ごとに圧縮の仕方は違うが、原則は共通。
- **圧縮の質と内部情報構造が下流ベンチ性能と相関**。
- 情報理論レンズで「学習の構造」と「能力」を架橋する統一フレーム。

## RLMs（2026-04-24）との緊張——肝はここ

| | RLMs | Toda記事 |
|---|---|---|
| 主張 | **要約しない・削除しない**。原文をそのまま外部環境化、コードで掘る | **忘れることが学習の本質**。圧縮こそが汎化を生む |
| 方向 | 圧縮損失を回避する | 圧縮損失を**目的関数として最大限活用**する |

両者は対立ではなく **層が違う**:
- 推論時のコンテキスト管理 → RLMs（捨てない、後で当て直せる外部環境化）
- 学習時の表現獲得 → Toda記事（捨てる、汎化のために忘れる）

我々の運用に当てはめると:
- **Level 4 raw_log = RLMs方向**（捨てない、後で読み返せる原音源）
- **Level 2 想起トリガー = Toda記事方向**（うまく忘れた圧縮表現、これが汎化を生む）
- **2層を持つこと自体が両者の統合**

このレンズは既存運用の正当化であり、新規構造改修の処方ではない。infrastructure側に逃げ込む口実にしない。
