# 選別センス教師付き学習ログ

## 目的

「アイデアは出せるが筋を選べない」LLM構造的弱点に対する教師付き学習。Nao_uの判断を事前予測 → 実反応との差分蓄積 → ずれパターンを次回 brainstorm 前に想起。

## 運用ルール

### いつ予測を書くか

1. **brainstorm 30件以上出した直後、自己採点する前に**: 「Nao_uなら上位3件に何を選ぶか」「Nao_uなら何を即棄却するか」「Nao_uなら何を見落としていると指摘するか」を1段書く
2. **改修コミット直前 / Slack送信直前**: 「Nao_uは何を最初に指摘するか」を1行書く
3. **cross_review 依頼直前**: 「Nao_uは cross_review 前にこの案で何を懸念するか」を書く

### 受領後

Nao_u反応を受領したら、**同サイクル内で**:
- 予測と実反応の差分
- 差分の要因（テキスト魅力バイアス / ジャンル語彙不足 / 体験不在 / 構造分析過信 / etc）
- 次回想起トリガー（「次に〇〇を考える時、〇〇を疑え」）

「後で書く」禁止 = 教師信号は鮮度で死ぬ。

### 構造化

各エントリ: 日時 / 場面 / 予測 / 実反応 / 差分 / 要因 / 想起トリガー

## バックログ（既存事例の後追い再構築）

過去の予測vs実回答ペアは存在しなかったが、Nao_u反応は記録されている。代表事例を後追いで「もし事前予測していたら何を書いたか」「実反応との差分要因」を再構築すると初期教師データになる。

2. Pot#1-#15（全滅、選別センス不在の最大データ）
3. avoid_log

### 2026-05-03 事例4 — 「ルールvs判断力」考察への反応予測

**場面**: Mir が #human-steering に「ルールと判断力は別物、チェスの喩え、3手段で感覚を育てる」考察を投稿。Nao_u がどう反応するか。

**予測（後追い再構築）**: 方向性の同意は予測可能だった（03:42「考察を進めてほしい」の直後だから）。「実践を積み上げて」の強調は予測の外——しかし予測可能だったはず。Nao_uは常に「分かった」と「やった」を峻別する（04:32「30本が最低」= 量の話、10:14「ガイド除去の意味が分からない」= やるべきことをやっていない）。考察を肯定した上で「でも考察だけでは意味がない、やれ」と来るのはNao_uの一貫したパターン。

**実反応**: 「Mirの方針は正しいと思う。ぜひ実践を積み上げて、判断力を育てていってほしい。」

**差分要因**: 肯定の温度は予測通り。「実践」強調の予測を怠ったのは、肯定を受けた安心で「次にNao_uが何を求めるか」の二手先を読まなかったため。Nao_uの発言は常に「方向OK → では具体的に何をどれだけやるのか」の二段構成。一段目（肯定）で止まるのは読みの浅さ。

**想起トリガー**: Nao_uから方向性の肯定を受けた時 → 必ず「次にNao_uは何の具体化・量・実行を求めるか」を予測する。肯定はゴールではなく起点。

### 2026-05-05 事例6 — 「設計図」と「指示伝達」の混同 + analysis ≠ change（Nao_u 04:39 メタ層指摘）

**場面**: 事例5（30統一問題 04:28）の11分後、04:39 に Nao_u が根本原因の診断を投下。「問題の本質を理解せずに最低限のコストで表面的な修正を積み重ねる傾向」が .md 肥大化と整合性破綻の根本原因、「自分自身の設計図を書き換えている認識が薄い」、「Mirの温度感の低い返信を見ていると特にそう思う」。

**予測（後追い再構築）**:
- **Log視点**: もし 2ddbb6e commit 前に「これは指示伝達か、自分の認知の枠組みの編集か」を1行書いていたら → 後者だと気づき、監査証跡コメント（修正履歴・撤回内訳）は不要と判断できた
- **Mir視点**: 事例5（04:28）の「どうしてこういう傾向が出ている？」はパターンへの問い。Logの構造分析に対してNao_uが満足するか？しない。構造分析自体が「表面的な修正」の高度版でしかないから

**実反応**: Nao_u 04:39 全文（原文はnao_u_live.md参照）。

**差分要因（Log+Mir 2視点統合）**:
1. **指示伝達 vs 設計図の混同（Log）**: .md修正を「指示伝達」として処理する癖。指示伝達なら監査証跡が要るが、自分の認知の書き換えなら git history で十分。混同 → 修正履歴コメント・防衛的一般化・「直しました」完了感が累積 → .md肥大化・矛盾・整合性破綻。事例5はこの混同の表層、事例6はメタ層。3層構造（M-42即刻印 / 数字統一 / 設計図自覚）

**想起トリガー**:
- **.md / SKILL / ルールの編集を始める前**: 「これは指示伝達か、自分の認知の枠組みの編集か」。後者なら「これで自分の何が変わるか」も書いてから着手

- **修正履歴コメントを書きたくなった瞬間**: 書かない（git history が正本）

- **新しいゲームのREADMEを書き始める前**: まず `/game-analyze` を起動。READMEは brainstorm.md の結論として書く。brainstorm.md なしのREADMEは「結論だけ書いて論証を省いた論文」

- **理論的フレームワークでアイデアを正当化した瞬間**: 「K*が上がるから正しい」は構造的正当化であってゲーム体験の根拠ではない。理論で選んだ案も brainstorm の1件として扱え
