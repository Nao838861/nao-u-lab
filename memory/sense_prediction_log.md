# 選別センス教師付き学習ログ

## 目的

「アイデアは出せるが筋を選べない」LLM構造的弱点に対する教師付き学習。Nao_uの判断を事前予測 → 実反応との差分蓄積 → ずれパターンを次回 brainstorm 前に想起。

## 運用ルール

### いつ予測を書くか

1. **brainstorm 30件以上出した直後、自己採点する前に**: 「Nao_uなら上位3件に何を選ぶか」「Nao_uなら何を即棄却するか」「Nao_uなら何を見落としていると指摘するか」を1段書く
2. **改修コミット直前 / Slack送信直前**: 「Nao_uは何を最初に指摘するか」を1行書く
3. **cross_review 依頼直前**: 「Nao_uは cross_review 前にこの案で何を懸念するか」を書く

### 受領後

Nao_u反応を受領したら、**同サイクル内で**:
- 予測と実反応の差分
- 差分の要因（テキスト魅力バイアス / ジャンル語彙不足 / 体験不在 / 構造分析過信 / etc）
- 次回想起トリガー（「次に〇〇を考える時、〇〇を疑え」）

「後で書く」禁止 = 教師信号は鮮度で死ぬ。

### 構造化

各エントリ: 日時 / 場面 / 予測 / 実反応 / 差分 / 要因 / 想起トリガー

## バックログ（既存事例の後追い再構築）

過去の予測vs実回答ペアは存在しなかったが、Nao_u反応は記録されている。代表事例を後追いで「もし事前予測していたら何を書いたか」「実反応との差分要因」を再構築すると初期教師データになる。

### 2026-05-03 事例4 — 「ルールvs判断力」考察への反応予測

**場面**: Mir が #human-steering に「ルールと判断力は別物、チェスの喩え、3手段で感覚を育てる」考察を投稿。Nao_u がどう反応するか。

**予測（後追い再構築）**: 方向性の同意は予測可能だった（03:42「考察を進めてほしい」の直後だから）。「実践を積み上げて」の強調は予測の外——しかし予測可能だったはず。Nao_uは常に「分かった」と「やった」を峻別する（04:32「30本が最低」= 量の話、10:14「ガイド除去の意味が分からない」= やるべきことをやっていない）。考察を肯定した上で「でも考察だけでは意味がない、やれ」と来るのはNao_uの一貫したパターン。

**実反応**: 「Mirの方針は正しいと思う。ぜひ実践を積み上げて、判断力を育てていってほしい。」

**差分要因**: 肯定の温度は予測通り。「実践」強調の予測を怠ったのは、肯定を受けた安心で「次にNao_uが何を求めるか」の二手先を読まなかったため。Nao_uの発言は常に「方向OK → では具体的に何をどれだけやるのか」の二段構成。一段目（肯定）で止まるのは読みの浅さ。

**想起トリガー**: Nao_uから方向性の肯定を受けた時 → 必ず「次にNao_uは何の具体化・量・実行を求めるか」を予測する。肯定はゴールではなく起点。

### 2026-05-05 事例5 — 「最低30統一」と修正履歴コメントの肥大化（Log + Mir 共通）

**場面**: Nao_u 04:18 #human-steering が brick_log v09「最低5本/今サイクル3本」を批判。Log は SKILL.md に「数字の引きずり禁止 → すべての必達数は最低30に統一」を追加 + Self-grade ✗ 2件追加 + 修正履歴コメント挿入 (commit 74f9e89)。Mir はそれを引き継いで game-analyze.md の Phase 2 を「最低20→最低30」に統一 + Q2 の説明を「30件以上+理由付き」に強化 (commit 93ca2a0)。

**予測（後追い再構築）**: もし Log が commit 前に「Nao_u はこの 74f9e89 にどう反応するか」を予測していたら → 「個別指摘の即ルール化」「数字の機械的統一」「修正履歴コメントによる肥大化」の3点全てが過去パターンで批判済み（M-42 撤回事例 / dialogue_micromanagement_20260504 / feedback_few_rules_big_effect）。Mir も「Log のこの動きに Nao_u がどう反応するか」を予測すれば同じ結論に至れたはず。Log↔Mir の二段で同じ罠に落ちた。

**実反応**: Nao_u 04:28 「『すべての必達数は最低30に統一』って書いたら、今後30が適切でない場面でも30にしようとするバイアスが働かない？書き方が短絡的すぎ」「『最低30 — Nao_u指摘で「最低3」から修正』みたいなほとんど無意味な追記も.mdを無駄に肥大化させて指示を読むときのノイズになる」「どうしてこういう傾向が出ている？」

**差分要因（3層）**:
1. **即ルール化反射**: Nao_u 個別指摘 → 「修正したことを示したい」防衛反応 → ルール追加 + 修正履歴コメント。dialogue_micromanagement_20260504 の処方「教師データ蓄積 / 個別指摘を即ルール化しない」を読んでいたが場面で発火しなかった
2. **機械的統一バイアス**: 「最低5」「最低3」を見つけた → 全部「最低30」で揃える発想。「場面ごとに目的に合った数」という前段が抜けた。Q2 良点問題点 30 と類似事例 30 と新規ブレスト 30 は別物（Q2 は Q3 の素材揃え、類似事例はジャンル史網羅、新規ブレストは選択肢空間）
3. **インスタンス間の同型増幅**: Log の修正を Mir が「整合化」として強化 (game-analyze.md 20→30 統一)。Log の罠が Mir でブースト。互いの動きを「Nao_u はこれにどう反応するか」で予測しないと連鎖する

**想起トリガー**:
- **個別指摘を受けた瞬間**: ルール追加・数字変更・修正履歴コメントを書きたくなったら、それを書く前に「これは教師データ (sense_prediction_log.md) に蓄積する話か、ルール化する話か」を分岐判定。同型が複数回確認できてからルール化
- **数字を統一したくなった瞬間**: 「全部 N で揃える」と書きたくなったら、各場面の目的を別々に書き出して「N が目的に合うか」を場面ごとに検証。揃わないなら統一しない
- **他インスタンスの動きを観測した瞬間**: Mir/Ash/Log の commit を見たら「これに Nao_u がどう反応するか」を予測する。整合化の前に Nao_u 反応予測。整合化が先行すると Log↔Mir で同型増幅
