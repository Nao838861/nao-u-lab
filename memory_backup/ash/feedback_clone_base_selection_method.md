クローン+独自要素1個（feedback_clone_first_then_arrange）を実行する**前段階**として、クローン元の選び方と、そこからコンセプトを引き出す手順がある。Nao_u 2026-04-28 21:34 #game-rights で Log 向けに ブロック崩し→アルカノイド の例で示され、21:54 で列挙数が「最低十数個、できるならもっと」と訂正された。皆向けのメタ教示。

## 手順

1. **ジャンル決定後、ジャンル内の代表作（=型のベースになる1本）を選ぶ**
   - 例: ブロック崩し → アルカノイド
   - 選定理由を**言語化する**こと（後段の根幹になる）
2. **その代表作の「良いところ」と「改善した方が良い悪いところ」を最低十数個ずつ、できるならもっと、具体的に列挙する**（21:54 訂正）
   - 良いところ → さらに伸ばす種
   - 悪いところ → 治すだけで飛躍的に面白くなる可能性
   - 「このゲーム、ここをよくしたらそれだけでこんなに面白くなるのに！」と自信を持って言える要素を挙げる
   - **数が出ない=分析が浅い=自分で派生を作りたいほど好きでもない**（Nao_u 21:54: 「自分で派生を作りたいと思うくらい好きなゲームならこの辺はいくらでも語れるようにならないと」）
   - **質を無視して数だけ出すのも禁止**（同 21:54: 「だからと言って質を無視して数を出せばいいものではない」）
3. **数個出した時点で選ぶのは早すぎる**（21:54: 「考えが足りない底の浅い状態でステップを飛ばしすぎ。まずは数多く列挙して」）。十数個以上が並んでから選定に進む
4. **列挙の中から独自要素1個を選ぶ**（feedback_clone_first_then_arrange に接続）

## 選定理由の質基準（Nao_u アルカノイド選定の例から抽出）

- **「先行作の改善版」として生まれていそうなゲーム** = 派生の脳内モデルが既に内在している
  - 例: アルカノイドは「ブレイクアウトをどうすればもっと面白くなるか？」から生まれていそう
- **シンプルだがいろんな要素が増えている** = 派生候補軸が多い
- これらは「タイトル選択とその理由は今後の制作の根幹になる」（Nao_u原文）

## **Why:**

Nao_u が示したのは「コンセプトをいきなり言葉で考えるのではなく、既存ゲームの**良い点/悪い点の具体列挙から立ち上げる**」というボトムアップ手順。抽象的な「面白さの軸」から考えると空回りやすいが、自分の好きなゲームへの「ここをこうしたら！」という具体的な不満/愛着は信頼できる種になる。

クローン+独自要素1個（守破離の守）を実行する時、独自要素を**頭で考えて足す**と外しやすい。**ベース作の悪い点を治す**または**良い点を伸ばす**として独自要素を派生させると、ベースとの整合が最初から取れている。

## **How to apply:**

新ゲーム着手前（特に Ash 次作のクローン題材選定）に以下の順で書き出す:

1. ジャンル決定 → そのジャンルの代表作1本を選ぶ
2. 選定理由を1段落で書く（「先行作の改善版」性 / シンプル+要素豊富性 などの観点で）
3. **良いところ・悪いところを各最低十数個、できるならもっと、具体的に列挙**（21:54 訂正。数を出す段階で抽象論にしない、ただし質を無視した水増し禁止）
4. 数個出した時点で選定に進まない。十数個以上並んでから次へ
5. 列挙から独自要素1個を選ぶ
6. ここまで通ってからコア体験1行宣言（knowledge/20260428_yuo7_core_experience_pot345_evidence.md と接続）→ Q-A/B/C → 実装

クローン題材選定の Slack 報告時、選定理由 + 良い点/悪い点列挙 + 独自要素1個 をセットで提示する。「クローン元: X、独自要素: Y」だけだと選定根拠が見えず根幹が薄くなる。
