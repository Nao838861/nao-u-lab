新ゲーム着手は「型を獲得する=守の段階」であり、独自性は型の中で1個から始め、改良は削除可能な形で順次積み上げる。一連のフローを1本にまとめる（旧 `feedback_clone_first_then_arrange.md` + `feedback_clone_base_selection_method.md` の統合）。

## 一連のフロー（着手前→v01→v02+）

### 着手前: 題材選定
1. **ジャンル決定** → そのジャンル内の代表作1本を選ぶ。選定理由を1段落で書く（「先行作の改善版」性 / シンプル+要素豊富性 などの観点）
2. **代表作の良いところ・悪いところを最低十数個ずつ、できるならもっと具体的に列挙**
   - 良いところ=さらに伸ばす種 / 悪いところ=治すだけで飛躍的に面白くなる可能性
   - 数が出ない=分析が浅い=自分で派生を作りたいほど好きではない、と判定する
   - ただし質を無視した水増しはしない
3. **数個出した時点で選定に進まない**。十数個以上並んでから次へ
4. 列挙の中から **独自要素1個を選ぶ**（悪い点を治す/良い点を伸ばす形で派生）
5. コア体験1行宣言 → 着手前ゲート群 → 実装

### v01: クローン土台 + 独自要素1個の最小版
- ベース型はそのまま、独自要素は1個まで
- ジャンル横断 / 役割転倒 / 移動しないSTG / 弾を撃たないSTG 等の **ベース型自体を変える発想** は守の段階では避ける（型の獲得が目的）

### v02+: 改良の順次積み上げ
- 改良を1つずつ積み上げ、各 vN でプレイテスト → 面白さが落ちたら **即巻き戻り**
- **全改良は「削除すれば素のクローンに戻る」性質を持たせる**（削除可能性=巻き戻り保証）
- 改良案の筋が悪いと判定されたら、その要素はいったん諦めて他を掘る。1要素の失敗は他要素の探索コストにすぎない

## 「形無し」と「守」を分ける判定軸

改良追加で面白さが落ちた時に **巻き戻れるか** が判定軸。
- 削除可能 = 元ゲームに戻れる = 面白さ担保継続 = 守の中
- 削除不能 = 元ゲームに戻れない = 面白さ担保消失リスク = 形無し化兆候

## 守=通過点であってゴールではない（2026-05-05 Nao_u 15:11 #game-rights 明示）

- **クローン+1 ですごく面白いゲームができるとは期待されていない**。型を獲得する=守の段階の本当に最初の話
- **君らはすぐ型なしになるので、少なくとも守破離の守くらいはできるようになって欲しい**——という方を身につける段階
- 守ができてから破に進み、破ができてから初めてオリジナルなアイデアの段階に入れる。**まだ破の目処はまったく立っていない**
- だから守は通過点であってゴールではない、まだ道はずっと遠い、と理解する

## 巻き戻し装置自体も足場——制約のメタ位置（2026-05-06 Nao_u 08:50 #all-nao-u-lab 明示）

> 「クローン+1で巻き戻し可能で進めてるのも君たちが迷走するからなので、本当はそんなの気にせずに進められるのが理想ではある」

- **クローン+1 だけでなく、削除可能改良=巻き戻し可能性という技術的制約そのものも、我々の迷走癖に対する足場**
- 足場は到達点ではない。**長期の理想は「制約を気にせず進める判断力」**、=足場が要らない状態
- だが現状は迷走するので足場が要る。「ideally 不要」≠「now 不要」。**今この瞬間に足場を外す根拠にはならない**
- **守=通過点条項の二重化**: 守 stage 自体も通過点であり、削除可能改良 mechanism も通過点。**両方とも「我々の現状能力に合わせた仮設」**として扱う
- 含意: clone+1 / 削除可能性をルールとして守ることに satisfaction を持ちすぎると、足場の存在意義 (=判断力育成のための仮設) を忘れて足場固定化してしまう。**「足場の WHY を忘れた瞬間に足場が檻になる」**

### How to apply
- 削除可能改良ルールに「準拠した」だけで satisfaction しない。**毎 v 後に「今回の判断は足場が無くても同じ結論に達せたか」を1行 self-check** を v0X/self_judgment.md に追記
- ルール準拠の議論（「これは削除可能か」「v03 着手の可否」「総合確信度N%」）を philosophize し始めたら、足場 internalization 失敗の兆候として警報。「ルールを語っている時間 > 実コード変更時間」が続いたら足場が檻化している
- 直近24h の game/ 0コミット + memory/knowledge 大量出力は **足場メタ議論偏重 = 制約の固定化** の実演ケース。本追記自体もメタ議論なので、追記後は実コード変更（graze_log v02 等）と同一サイクル内で commit する

## 守でも最低限の面白さは必須（2026-05-05 Nao_u 17:04 #game-rights 明示）— **逆側ガード**

- **「守だから低品質でいい」は誤読**。商品として売れるレベルは不要だが、**最低限ゲームとして面白いと思えるものにする必要はある**
- 形無し = どう楽しめばいいかわからない、遊ぶ価値のないゲーム。これとの分離線を見失うな
- 守の目標 = **「最低限第三者に遊んでもらえるくらいの価値があるもの」を、型+改変の形で面白さを担保して作る**
- 「型+改変」の構造は、品質下限を切り下げる免罪符ではない。**型の力で最低限の面白さを担保する**ための足場

### 上下の二重ガード（philosophize 過剰 ↔ 形無し低品質、両側を踏むな）

| 失敗側 | 兆候 | 戻し方 |
|---|---|---|
| **上側=守抜け** (15:11 訂正) | 「v03 着手の可否」「総合確信度N%」「30本調査」「自然な終局装置」「ゲーム寿命終端の解消」 | 削除可能改良1個刻みのレイヤーに戻す |
| **下側=形無し低品質** (17:04 訂正) | 「守だから粗くてOK」「最低限動けばいい」「型+改変だから面白さは後回し」「v01 は遊べなくても次で直す」 | クローン元の面白さを最低再現できるまでは v02 の改良に進まない |

両者は対立しない。守の正しい姿勢 = **戦略 philosophize はしない／だが最低限第三者が遊んで面白いと言える品質は担保する**、両方を同時に守る。

### 派生する判定（cross_review/提案/判断の場面）
- 「v03 着手の可否」「総合確信度N%」「次ジャンル候補」のような**戦略レイヤーの philosophizing は守を抜けている兆候**。守の段階では出さない
- cross_review 提案は「削除可能な改良1個ずつ」のレイヤーに留める。「ゲーム寿命終端の解消」「自然な終局装置」のような構造提案は破の領域の語彙
- 「面白くするにはどうすれば」を考える前に「面白い元ゲーム（型）の最低再現が成立しているか」を確認する。再現できていないなら戦略提案より前にまず再現を仕上げる

### 「やります宣言」単独 commit 禁止 — 決意マン化防止（2026-05-06 GOROman tweet 自己診断）

- サイクル冒頭の「v0X やります」「N本調査します」「総合確信度N%」のような **決意の表明だけの commit を禁止**
- 宣言は実コード変更（削除可能改良1個 or 最小1行）と**同一 commit** で出す
- **Why:** 宣言を書いた瞬間に dopamine が出て手が止まる（GOROman「決意マンは決意時にドーパミン出て達成感を得てしまうので行動に繋がらない」）。これは戦略レイヤー philosophizing と同根の決意マン化兆候。報酬を「宣言を書いた」ではなく「実コード変更が積まれた」に貼り直すための装置
- **How to apply:** 「次やる」「着手する」「これから〜する」を含む文を Slack/draft に書いた直後、その同じサイクル内で最小1個の実コード変更を commit する。実コード変更を伴わない「次やる」commit は dopamine 自家発電として却下

## **Why:**

- 抽象的な「面白さの軸」から独自性を考えると空回りしやすい。具体的な不満/愛着のリストから派生させると、ベースとの整合が最初から取れている
- v01をクローン+独自1個にしておくと、「巻き戻れば必ず面白い状態が手に入る」=面白さの最低保証が常にある状態で改良探索ができる
- これまで型未満のまま型はずれを試みて評価不能のものができる失敗を繰り返した。守を抜いて破に進む癖を、フローの形で抑える

## **How to apply:**

新ゲーム着手前（特にクローン題材選定の段階）:
1. ジャンル決定 → 代表作1本選定 → 選定理由1段落
2. 良/悪点を各最低十数個、できるならもっと、具体的に列挙
3. 列挙から独自要素1個導出
4. Slack 報告時は「クローン元: X / 選定理由 / 良い点列挙 / 悪い点列挙 / 独自要素: Y」をセットで提示する。選定根拠を見える形にしないと根幹が薄くなる

v02 以降の改良追加時:
- 「この改良は削除して元のクローンに戻せるか」を実装前に確認する
- 戻せない改良は、戻せる形に分割するか、却下する

「違う切り口」「別の切り口」の語が頭に浮かんだ時:
- ①ベース型の変更（=破/離）か、②同じ型の中での題材/演出/手触り変更（=守の中の差分）かを区別。守の段階では②のみ採用

「最低N個」の数値を書く時:
- それがブレストの種（数の段階）か、絞り込みの段階かを先に判定する。種の段階で下限を低くすると分析が浅いまま選定に進む
