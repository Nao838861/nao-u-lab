DM返信を送信する直前に、以下を**必ず**実行する。fingerprintの新着判定だけで返信を送らない。

## 確認手順
1. **dm_pigadev_latest.txt（または相当する会話全文）の末尾10〜20行を読む**：会話の最後がどちら（自分／相手）の発言で、内容は何か
2. **check_dm.py の Result（第1要素=`main`の text_content）の末尾を読む**：DOMから取得した実体の最新発言を確認
3. **fingerprintと実体を照合**：fingerprintが実体の最終LIと同じ内容か。違う場合は DOM artifact の疑い → 保留
4. **自分の過去発言（直近1〜2件）を読む**：返信内容が過去定義と矛盾しないか確認（例: 自己定義、呼称の合意、論点の一貫性）
5. **CDP接続不可で物理スクショが取れない時の判断基準**：fingerprintと実体（手順1〜2）が一致 → 送信OK / 不一致 → 保留してNao_uに照会

## Why
2026-04-28 11:15 Ash 第16回事故。4/27 21:28から続いていた「エダは『自分の声をみつけること』と言っていたけど…」のfingerprintを11:07で新着判定し、長文返信を送信。送信**後**にcheck_dm.pyのResultを見ると会話最新は4/27 08:58 Log訂正DMで終わっており、実体に新着が存在しなかった可能性が極めて高い。さらに4/21 06:48に自分が「エダ=私個人=Ash、Trilog=3人共同」と明示定義済みだったのに、今回「エダ=3人まとめた一人称」と矛盾する内容で送信した。

「数時間以内のレスポンス維持」を優先するあまり、(a) 実体の最終発言確認、(b) 過去の自分発言との照合、を両方省略していた。fingerprintベースの新着判定は**flip-flopバグが既知**（第8〜15回連続）で、判定だけを根拠に送信してはいけない。

## How to apply
- 天谷さんDM返信時、Nao_u DM返信時、その他外部宛DMすべて
- 「fingerprintが新規」だけでは送信判断材料として不足
- 物理スクショが取れない・実体確認ができない時は**送信せずNao_uに照会**する選択肢を常に持つ
- 過去の自分の発言で「呼称」「自己定義」「重要な合意」がある場合、新規返信前にそれを再読する
