# Rule
新ゲーム着手前 / 新機能設計前 / 大きな修正の cross_review 前に、以下のハーネスを必ず通せ:

1. **複数案生成**: 角度を変えて複数候補を出す（最低3案、できればもっと）。実装は一瞬なので、思考に時間を使う
2. **時間をかけて吟味**: 1案目に飛びつくな。複数案を寝かせ、別角度から見直す
3. **批判的レビュー**: 各案について「予測可能な懸念点」を列挙（feedback_critical_evaluation_before_implement.md と直列に適用）
4. **相乗効果探索**: 案同士を組み合わせると複数の問題を一度に解決しないか確認する
5. **最良選択の確信**: 「これが最良」と思える段階に達してから初めて実装着手

# How to apply

**新ゲーム着手前**:
- 候補ゲーム/題材を最低3案、できれば5案以上書き出す（クローン元の選定にも適用、feedback_clone_base_selection_method.md と整合）
- 各案について「良い点 / 悪い点」を最低十数個ずつ列挙（既存の feedback_clone_base_selection_method.md の方法論を流用）
- 案同士の組み合わせ・差別化要素の相乗効果を探索
- 「これが最良」と確信した1案にのみ独自要素1個を載せて v01 を出す

**新機能設計前**:
- 「この機能で解決したい問題」を3行で書く
- それを解く複数アプローチを最低3案出す
- 各案に対し「複数の問題を同時に解決するか」を確認（解決するなら筋が良い兆候）
- 各案に予測可能な懸念点を列挙、批判的にレビュー
- 最良案が確定してから実装

**cross_review/レビュー時**:
- 提案者が1案しか出していない場合 → 「他の角度の案はあるか？」を必ず問う
- 「この案はどんな問題を同時に解くか？1問題1案になっていないか？」を最後に確認

**サイクル開始時の自問** (feedback_means_ends_reversal_check.md と並列):
- 「このサイクル、自分は思い付き1案で動こうとしていないか？」
- Yes なら 5分でも候補を3つ書き出してから着手
