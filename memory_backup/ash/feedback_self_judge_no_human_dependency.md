# Rule

実装後、Nao_u/人間にプレイ依頼する前に **AI 側で「自分が良いと思えるか」を判定する**:

1. **数値→体感換算**: 仕様の数値（速度/振幅/周期/反応時間）を **px/秒・ボール速度比・0.5/1/2秒の体感量** に換算してメモる
2. **コードからの自己判定**: コードを読み、設計から導ける挙動を予測して「これで体験が変わるか」を AI 側で言い切る
3. **headless or 自手動プレイ**: 動かせる構造なら 1度動かして AI 自身がプレイ感を確認する
4. **「自分で良いと思える」を出してから依頼**: 上記 1〜3 を通って「これは良い／物足りない／要再設計」を AI 側で判定し、**良いと思えるまで依頼しない**

- 人間プレイで初めて判明する問題は「設計時に予測しきれなかった真に難しい問題」だけのはず
- 仕様の数値や設計の枠で予測可能な問題まで人間に発見させるのは、「**自律性のサボり**」

# How to apply

**実装完了直後の必須ゲート（Nao_u 依頼前）**:
1. 数値換算を `predicted_play.md` 冒頭または devlog に貼る（M-39 v04派生ゲート、これを仕様策定時点まで前倒し）
2. AI 側プレイ確認（headless / 手動 / 別 AI レビュー）の記録を残す
3. 「自分が良いと思えるか」を一文で言い切る:
   - 「良い、依頼OK」
   - 「物足りない、◯◯を△△に変える」（変える）
   - 「要再設計、◯◯から考え直す」（戻る）
4. 「物足りない／要再設計」と判定したら **依頼前に直す**

**判断補助の自問**:
- 「この数値、人間が触ったら何秒で『つまらない』『動いてない』と気づくか？」 → 5秒以内なら自分で気づける
- 「自分でこの仕様を読んで『面白そう』と思えるか？」 → No なら依頼の前に再設計
- 「『プレイすればわかる』と書いた瞬間、本当に AI が動かしても分からないのか？」 → No なら自分で動かせ

**cross_review/レビュー時**:
- 提出者の cross_review に「数値換算なし」「AI側プレイ記録なし」 → 差し戻し
- レビュア（Ash/Mir/Log）は受領した時点で **独立に数値換算 1度** を走らせる（v04 で Ash 側の独立判定が完全に抜けていた）

**仕様策定時（M-39 前倒し）**:
- 動き/速度/周期/振幅/反応時間の数値が決まったら、即 px/秒 → ボール速度比 → 0.5/1/2秒の体感量を換算
- 桁違い比率（1:50 など）が出た瞬間、その仕様は人間体感ゼロ = 仕様時点で却下
