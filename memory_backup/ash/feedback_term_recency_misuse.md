外部用語・最近の話題語を「判断基準」として引用する前に重要度判定を1段挟む。出てきたから使う、ではなく、射程と原典文脈を確認してから使う。

**Why:**
Nao_u 2026-04-27 09:29 #human-steering 直接指摘:
> これはLLMの弱点の一つだと思うけど、重要度の判断なしに最近出てきた言葉を濫用して無理やり援用して判断基準にしがち。
> サプライズニンジャ理論はシナリオの文脈では重要だが、Logが作ってるシューティングゲームで関係あるものとして判断基準につかおうとしたり、どこの誰が言ったかわからない「角を丸める」みたいな話が重要なものみたいな形で頻繁に判断基準にでてきたり。他にもたくさん、そういうのが見受けられる。

実データ: 「サプライズニンジャ」「角を丸める」が 49 ファイル（shot_log v01 devlog / avoid_log v04 devlog / mir_textadv v05 / knowledge/* / game_lessons_log / game_dev_foundation 等）に分布。3インスタンス全員で再生産されている構造的癖。

これはLLMの基本病理（最近見た強い言葉を権威化する確証バイアス）が我々の出力に出ている。

**How to apply:**
外部用語（理論名・人名つき格言・最近の話題語）を判断基準として引用する直前に3点自問:
1. **原典文脈チェック**: その用語は原典で「判断基準」として使われていたか、それとも別の文脈の観察・分類だったか（サプライズニンジャは映画シナリオ論、角を丸めるは出典不明）
2. **射程チェック**: 現在のタスク（ゲーム種別・ジャンル・問題のレイヤ）にその用語が本当に射程を持つか（シューティングのゲーム性判断にシナリオ理論を持ち込むのは射程外）
3. **再生産チェック**: 単に「最近見た／温度が高い／皆が引いている」だけで再使用していないか。過去の自分のサイクル末尾・他インスタンスの devlog・shared-reads から借りた借用語ではないか

3点いずれも怪しい場合は、引用せずに自分の言葉で具体的に書く。「角を丸めると見えてくる」ではなく「弾速を 0.85x にするとプレイヤーが画面端で詰まる頻度が下がる」のように具体に降ろす。

**典型的な誤用パターン:**
- 「ここはサプライズニンジャ的に〜」（射程外。シューティングの弾幕設計には無関係）
- 「角を丸めると〜」（出典不明。何が「角」で何が「丸める」か具体未定義のまま使用）
- 知識ノートで取り上げた格言を翌日の判断基準として無検証で再利用
- knowledge/* に書いた他人の用語を自分の game_lessons_log に転写して「判断基準」化

**境界条件:**
- 用語そのものを **観察対象として記述する**のは OK（「Nao_u が『角を丸める』という言葉に違和感を示した」は事実記述）
- 用語を **自分の判断の根拠にする**のは要フィルタ
- 既に T:5 で memory に刻まれた原則（5原理・原則6・栄養の偏り等）は別カテゴリ。これらは原典＝Nao_u対話で射程確定済み
