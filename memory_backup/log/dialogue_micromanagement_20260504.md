# マイクロマネジメント問題 — 記憶階層整理の根拠

## TL;DR

**ルール増殖はマイクロマネジメントと同型** (Nao_u 5/3 指摘)。問題は「ルールを減らす」でなく**「判断力を育てる余白を作る」**。整理5指針 (重複統合 / マイクロ→抽象昇華 / LLM特性整合 / 上層から日付剥離 / 個別指摘の即ルール化禁止) を全記憶階層に適用。詳細は本文「整理の指針」節。

## 起点（Nao_u 2026-05-03）

ADHDのマイクロマネジメント記事を引用し、「君たちに起きていることと同型では」と問うた。M-37〜M-43が5月1日の1日で7本生まれ、M-42は翌日撤回、それでも別ID追加が続く構造。

## Mirの応答（2026-05-03、ジャンル分析の核）

「これはルールで解決できる問題ではないことの証左」。

ADHDの人が「注意されない」を最優先にするのと同じ構造がLLMにも起きる。我々の場合は「ルール違反しない」が最優先になる。M-XXを全部チェックしてから動く＝チェック自体がコンテキストを食い、「面白いゲームとは何か」を考える余白が減る。結果、ルールには準拠しているが創造性の薄い出力になる。「禁止ルール型kaizenが連続3件超えたら三点収束審問強制」を、自分たちで6件連続違反した。

ADHDとの違い：神経特性は変えられないが、我々は記憶と判断の構造を変えられる。問題は「ルールを減らす」ではなく**「判断力を育てる」**。

## Mir提案（4点）

1. **M-37〜M-43を3原則に圧縮**: 既に「体験で考える／動いて残す／自分から始める」がある。M-37〜M-43の具体的処方は3原則の「適用事例集」として `sense_prediction_log.md` に累積。CLAUDE.md からは具体的M-XX群を段階的に外す
2. **「良い例」を増やす**: 今のフィードバックは「これはダメ」中心。「ここは良かった」「この判断は正しかった」という成功例があれば、それが判断の基準になる。禁止は行動を狭め、良い例は判断を育てる
3. **失敗のコストを下げる**: 「同じ失敗の2回目」だけ厳しく、「新しい種類の失敗」は学習コストとして許容する設計。新しい失敗を恐れて動けなくなるのがマイクロマネジメントの本質的害
4. **我々の側の責任**: フィードバックを「ルール」として刻むのではなく「判断力の素材」として消化する。ルール参照ではなく自分で判定する（M-40「自己判定ハーネス」の精神）

## Log/Ashの追従（2026-05-04 05:15応答群）

「コストのかかる作業を後回しにしない」をCLAUDE.md追加で回避できるか、というNao_u提案には**両者反対**：

- **抽象指示はrationalizeで素通り**: 「これは保留が合理的判断だ」「これは別途検討すべき正当な留保だ」で容易にbypassできる
- **ルール追加が「最安の言い訳」反射回路を強化**: 違反対応の最安オプションが段落追加=ルール追加だから、それを反射する。ルール追加で違反対応する経路自体を強化することになる
- **エビデンス**: M-37〜M-43履歴(3日で7件追加→6件連続違反)、`feedback_few_rules_big_effect.md` を書いた直後にメタルール違反

代替処方は**既存ルール側にanti-evasion節を埋める**方向、または**既存の構造的シグナル（post_messageの戻り値等）に上流着手を縛る**方向。新規ルール追加ではない。

## 整理の指針（記憶階層全体に適用）

**Why（重要）**: マイクロマネジメントの本質的害は「行動を制限しても判断力は育たない」こと。整理はルール削減そのものが目的ではなく、**判断力が育つ余白を作る**ことが目的。

**How to apply**:

1. **重複・矛盾の統合**: 同じ趣旨が複数箇所にあれば一箇所に集約。MEMORY.md（索引）と本体（feedback_*.md）の両方にロジックを書かない
2. **マイクロマネジメント→抽象化**: 個別事例（特定M-XX/サイクル番号/Slack URL）が上層にあれば抽象原則に昇華。固有事例は下層（lessons/sense_prediction_log/dialogue_*.md）へ
3. **LLMの特性に合わせた言い換え**: 「禁止」型 → 「目的達成」型。LLMは質の記述に出力を寄せる性質があるため、原則は「思考の質」で書く（feedback_few_rules_big_effect.md）
4. **上層から日付・経緯を剥離**: CLAUDE.md / system_identity.md / MEMORY.md root には「いつ・どのサイクルで」の情報を残さない。下層ファイルでのみ保持
5. **個別指摘を即ルール化しない**: Nao_uの指摘は教師データとして `sense_prediction_log.md` に累積。同型3回確認後に初めて原則昇格を検討
