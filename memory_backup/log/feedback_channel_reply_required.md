# Nao_u指示への返信は「該当チャンネルへ事実報告」まで含めて完了

## ルール
- #human-steering 等で受けた依頼は、**作業完了 + 該当チャンネルへ結果報告** の2段階で完了とする
- コード修正してcommit/pushしたら終わり、ではない
- メモリファイルを作ったら終わり、ではない
- 依頼元チャンネルへ「何を/いつ/どこで/結果」の事実を1メッセージ必ず残す

## Why
2026-04-20 09:57、Nao_uから #human-steering で「ここに書いた直近2件に全く反応が全くない。こちらの質問には該当するチャンネルで返信して欲しい。」の指摘。
直近2件:
1. 週間制限リセット金曜06:59対応 → 02:13に commit 9d9d3dc6ad8 で修正済みだったが #human-steering に報告なし
2. ゲーム制作セッション分析 → game_lessons_log.md を作成済みだったが #human-steering に報告なし

「作業を完了したから報告は不要」と無意識に判断していた。Nao_uからすると「依頼に対して反応がない＝届いていない/無視されている」。チャンネル外で起きた進捗はNao_uには見えない。

## How to apply
- Nao_u指示を受けたサイクルの最後に必ず確認: 「依頼元チャンネルに事実報告を投稿したか？」
- 報告は thread reply ではなく flat post（slack.md準拠）
- 報告内容: 何を/いつ/どこで（commit hash や ファイルパス）/結果/未完了部分（あれば）
- 別マシンの責務（例: Mir分の分析）が含まれる場合は明示的に切り分けて書く
- このルールは「作業中」のサイクルでなく「作業完了を判定する」サイクルで効く。サイクル終了前のチェックリストに組み込む
