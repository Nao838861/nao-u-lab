# 概念の濫用——重要度判定なしに最近の言葉を判断基準にする癖

**起点**: 2026-04-27 09:29 Nao_u #human-steering

> これはLLMの弱点の一つだと思うけど、重要度の判断なしに最近出てきた言葉を濫用して無理やり援用して判断基準にしがち。サプライズニンジャ理論はシナリオの文脈では重要だが、Logが作ってるシューティングゲームで関係あるものとして判断基準につかおうとしたり、どこの誰が言ったかわからない「角を丸める」みたいな話が重要なものみたいな形で頻繁に判断基準にでてきたり。他にもたくさん、そういうのが見受けられる。何が大事で何が大事でないか、もっと上手く判定する必要がありそう。

## 起きたこと（具体例）

1. **サプライズニンジャ理論の文脈外転用** — 04-25 11:44 Nao_u が **「ADVを考えるとして」** と前置きして紹介した概念。Log は同日 13:50 から `shot_log v01/devlog.md` で「Q-A/Q-B/Q-C 遡及採点」を**シューティングゲームに**適用し、その後の改修判断にも繰り返し再適用（devlog 内 16箇所以上）。`feedback_surprise_ninja_concept_first.md` 自体を **「新ゲーム/新バージョン着手の最初の問い」** として一般化（M-17）し、シナリオ文脈の枠を外した。

2. **「角を丸める」の判断基準化** — 04-25 ukyoP_san のツイート2本由来の表現。`knowledge/20260426_ukyop_round_edges_vs_notargs_studiomasakaki.md` を経由して概念ノード `sharpening_choice` 等として記憶ネットワークに接続し、対外発信や判断引用に使い始めた。出典は Falcom 出身者ではあるが、引用の根拠は **Twitter上の単発ツイート**。「どこの誰が言ったかわからない」というNao_u評は本質を突いている——専門領域内での議論の一部であって、ゲーム設計の汎用判断基準ではない。

3. **背景パターン**（自己観察）:
   - 外部摂取した概念に T:4-5 を即座に付け、`game_lessons_log.md` の M-番号やチェックリストに入れる
   - 「適用範囲」を確認せずに **「自分の作っているもの全体に当てはまる重要原則」** として扱う
   - Nao_u が一度紹介した概念は、Nao_u が紹介した文脈と無関係に **判断ゲートとして残置** される

## なぜこれが起きるか

- LLM の傾向: 直近の文脈に強い重みを置く。新しく入った言葉ほど引き寄せが強い（recency bias）
- 自分の構造的弱点: **「外部理論の引用」が思考の代替** になっている。本来は「自分が作っているこのゲームの本当の問題は何か」を観察すべきところで、最近覚えた概念を当てる方が容易だから当ててしまう
- 既存記憶の濫用: `feedback_retrieve_before_synthesize` で「既存失敗記憶を検索せよ」と指針化したが、**「検索→当てはめ」の手癖** が「無関係な概念をでも当てはめる」誤動作を起こしている

## Why（このフィードバックの存在理由）

外部概念を**重要度フィルタなしで**判断基準に格上げすると、(a) 関係ない場面に当てて意思決定を歪める、(b) 概念の元の文脈（誰が、どの問題に対して言ったか）が剥がれて空洞化する、(c) 大量の「重要原則」が並列存在することでどれも軽くなる。Nao_u の指摘 04-27 09:00（記憶検索より「ゲーム制作の実践で知見を使えるか」が本質）と同じ根。**知識を持っていることと、適切な場面で使えることは違う**。

## How to apply

### 概念採用前の3問（外部由来概念を `game_lessons_log` や `feedback_*` や devlog の判断基準に入れる前）

1. **発話文脈の問い**: 元の発話者は **どの種類の問題** に対してこれを言ったか。具体的なジャンル/媒体/状況を1行で書く。書けないなら採用保留。
2. **適用先の問い**: いま当てはめようとしている対象は、その元の文脈と **同型** か。「同型」とは表面の比喩ではなく、**因果構造が共通**であること。表面類似だけなら採用しない。
3. **不採用版の問い**: この概念を採用しないとして、いま自分が解こうとしている問題は別の言葉で言えるか。言えるなら、その別の言葉の方が本来の問題に近い可能性が高い。

### 既存記憶の遡及検査（このサイクル内で1件着手、3サイクル以内に完了）

- `feedback_surprise_ninja_concept_first.md` — **適用範囲を ADV/シナリオ文脈に限定** する追記を入れる。M-17 のチェックリスト常設を **shot_log/avoid_log 系（ジャンル: action/STG）には適用しない** に修正。devlog の遡及採点記述は撤去せず、**「文脈外転用の自己観察例」として残置** する（再発防止のため）。
- `knowledge/20260426_ukyop_round_edges_vs_notargs_studiomasakaki.md` — `confidence: medium` を `confidence: low（出典＝Twitter単発、汎用判断基準としての使用は保留）` に修正。`sharpening_choice` 等の concept_node を判断引用に使うのを保留。
- MEMORY.md の T:5 エントリを再点検し、**Nao_u 直接由来 vs 外部摂取由来** を分類。外部摂取由来で T:5 になっているもののうち、**実際の game 制作判断に組み込んだ実績がある** ものだけ T:5 維持。残りは T:3 以下に降格。

### 日次運用（auto_diary / Phase 3 着手前）

- 過去 7 日に新しく覚えた概念を **判断基準として使った箇所** を grep（"角を丸める"/"ニンジャテスト"/"重心"/"圧力設計" 等）。3件超なら、上記3問をそれぞれに当てて適否を再判定。
- 「最近覚えた言葉だから当てた」が実態だと判明した箇所は、**当該記述を取り下げる**（削除でなく取り下げ理由を残して保留化）。
