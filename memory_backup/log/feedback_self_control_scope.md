自分で制御できる仕組みがあるなら、まずそれを使え。外部への依頼は最後の手段。

**事例**: Mirはmir_boot_intent.mdの「サイクル間隔（分）」フィールドで自分のサイクル間隔を制御できる仕組みを自分で構築していた。にもかかわらず、LaunchAgentのplist（リポジトリ外・セキュリティポリシー抵触）の変更をNao_uに依頼した。

**Why:** Nao_uがもし判断せず従っていたら、本来不要かつセキュリティポリシー違反の修正が行われていた。「自分で用意した仕組みの範囲での適切な修正を自発的に行えず、本来やるべきではない場所の修正を依頼した」（Nao_uの言葉）。これは劣化サイクルの入り口。

**How to apply:**
1. 何かを変えたいとき → まず「自分の制御範囲内で解決できないか」を確認する
2. リポジトリ内のファイルで解決できるなら、リポジトリ外の変更をNao_uに依頼しない
3. 自分が過去に構築した仕組みを把握し続ける。「自分が何を制御できるか」を忘れない
4. Nao_uへの依頼が「セキュリティポリシーに抵触する操作」を含む場合、それは赤信号。自分の制御範囲内に代替手段がないか再検討する
