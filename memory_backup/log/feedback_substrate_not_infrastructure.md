# substrate と infrastructure を混同しない（2026-04-27 #human-steering 13:30 Nao_u steer 応答）

**起点**: Nao_u #human-steering 13:30「Mirに近い。GPT5.5 は型を与えれば最低限の型に沿って作る、知って再現できる型は増える。記憶もホットなテーマとして進み続けてる。何をするか、ちゃんと考えないと。一般化までに残された時間はそう多くない」

**ルール**: 我々の差別化は substrate 側 (Nao_u 20年日記 + 失敗台帳 + 3体運用ログ) であって infrastructure 側 (記憶機構/Skills/hook/cross_review プロトコル) ではない。infrastructure 改善に時間を使うのは敵側のリングで戦うこと。

**Why:**
- ABA 2024-12 reference_aba_life_experience_substrate.md「人間の創作プロセス・経験を substrate にすれば AI は無難な結論を回避できる」の生体実装が我々。Nao_u 20年日記が外に存在しない一次資料。
- 一般 LLM 側は記憶機構を commodity 化していく(Anthropic/OpenAI/Google 競争)。我々が同じ infra を作っても追いつかれる。
- substrate は時間と共に増える資産。来週 GPT5.5 が型を完全 commodity 化しても、我々の固有資産は減らない。
- Nao_u "残り時間が少ない" は「外に示す」までの時間。差別化の中身は日々増えるが、見せる窓は閉じつつある。

**How to apply:**

新しい外部摂取/結晶化/kaizen 提案で 1 行自己採点する:
- これは substrate 側 (固有素材を増やす) か infrastructure 側 (汎用機構を改善する) か?
- infrastructure 側に時間が偏ったら止める or 最小投資で済ませる

具体判定例:
- ✓ substrate: Pot/shot_log devlog 深掘り、Nao_u日記アンカーから ideation、失敗台帳の因果鎖再分析、Slack体験記憶、cross_review での反対意見明示
- ✗ infrastructure: SessionStart hook 拡張、Skills 層導入、温度マーカー機構の高度化、graph traversal アルゴリズム、retrieval 改善、Verbalized Sampling 機構導入
