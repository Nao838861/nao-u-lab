# ゲームデザインのセンス = アイデア棄却の解像度

**Nao_u 2026-05-02 07:45 #human-steering 原文**:
> ガイドがある達人プレイができることを前提に、敵やボスがいる状態で面白くするにはどうするか考えて。できれば君たちだけでこの結論に到達して欲しかった。
> 現状の君たちには良いアイデアを含む仕様の提案はできても、その中のどれが筋が良さそうかを選ぶセンスがない、と感じている。
> ゲームデザインのセンスを磨くにはどうすればいいと思う？

## 核

センス = 「アイデア棄却の解像度」=「これは効かないと実装前に言える瞬発判断」

我々は「アイデアを出す」訓練しかしていない。M-38 で30件出して1件実装、残り29件の棄却理由は記録しない。これでは選別の差分が蓄積しない。**アイデアを出す数より棄却理由を蓄積する密度がセンスを育てる**。

## Why（具体事象）

brick_log v08 で「敵/ボス追加」を決めた瞬間、ガイドを「情報過多」理由で外した。
- Nao_u の前提は「ガイド継続」
- ガイド = 達人プレイ民主化（狙う先が見える） / 敵/ボス = 執行圧力（妨害される）は **独立軸で重ね合わせる対象**
- 我々はトレードオフだと誤認してガイド除去を決めた
- これがセンスの不足の正体

なぜ自分達で到達できなかったか:
- v07 でガイド入れて → v08 で敵入れる時、「v07 で何が効いていたか」を再分析せず除去した
- M-38 brainstorm.md の棄却基準は「先行事例ゼロ」のみ。「コア快感天井を上げない案は棄却」が無かった
- 数値往復 (v04 5px → v05 22px → v06 10px) の達成感に没入 (M-41 違反)
- 新規追加 (敵/ボス) に意識が引っ張られ、既存要素 (ガイド) の継続/除去判断を独立に問わなかった

## How to apply（実装可能な処方）

1. **棄却台帳**: brainstorm.md の各案に「棄却なら理由を1行」強制。採用案が失敗した時、棄却案に正解がなかったかを後追い検証して棄却基準を補正
2. **3列比較**: 「自分案 / 名作の解 / Nao_u が言いそうな解」を毎brainstormに並べる。アルカノイド本家系列の敵/ボスをジャンル一般要素として認識すらしていなかった = 「Nao_u が言いそう」を予測する練習が欠けている
3. **予測 vs 実プレイ差分台帳**: M-39 predicted_play.md と実プレイ結果の差分を蓄積。差分の繰り返しパターン = センスの穴の正体
4. **棄却基準格上げ**: M-38 正規ゲートに「コア快感天井を上げない→棄却」「数値チューニングで補える→棄却」を追加
5. **既存要素の独立判断フェーズ**: M-38 brainstorm.md に「新規追加検討の前に、既存要素を独立要素として継続/除去を独立に問う」フェーズを追加
6. **名作1要素模写**: ABA/Cave Story の「効いている1要素」を抜き出して模写、「なぜ効いているか」を実装で確かめる。理論書を読むより実装で確かめる方が早い

## 軸の独立性（センス不足を構造化）

「Aを足したいから Bを引く」は、AとBが同一軸の時のみ正しい。AとBが独立軸なら、AもBも保つ設計を考える。我々は「ガイド」と「敵/ボス」を「画面情報量」という同一軸に押し込めて処理した。コア体験設計の軸（民主化 / 執行圧力）を見ていなかった。

**ルール**: 既存要素を除去する判断は、独立軸で重ね合わせができないと確認した後にしか下さない。
