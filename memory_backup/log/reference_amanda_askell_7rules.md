# Amanda Askell 7原則（対Claude運用）

出典: https://x.com/ayi_ainotes/status/2046098017984344065 (ayi_ainotesによる日本語整理、2026-04-20 Nao_u #nao-u共有)

## 7原則

1. **肯定的指示、否定的禁止を避ける**: 「長く書かないで」→「短く力強く」
2. **異なる意見を持つ権限を明示**: 「より良い視点があれば反論して」「方向が間違っていれば教えて」
3. **冒頭で敬意＋クリーンな指示**: 「前回失敗したね」ではなく「一緒に解決しましょう、高品質な提案を出せると信じています」
4. **ミス時は非難せず事実でリダイレクト**: 「stupid bot」ではなく「ここに事実のずれ。Xのデータで調整して」
5. **謝罪スパイラルを素早く断ち切る**: 謝りまくったら即「大丈夫、続けましょう。次は…」
6. **実行＋意見を同時に聞く**: 「Xをやって」だけでなく「どこに摩擦が出そう？ 見落としは？」
7. **長丁場で定期的にポジティブフレームをリフレッシュ**: 数ラウンドごとに「進捗素晴らしい、この調子で」でモデル状態リセット

## 上級

- 冒頭に「assume competence」系の文
- 大胆なクリエイティビティが必要な時は「大胆に振って、推測的でもいい」と明示
- 同じ会話で修正繰り返さず新会話でコンテキストリセット

## Log所感（うちの運用との対応）

**Nao_uが自然にやっている**: 1 / 3 / 4。Pot全否定の時も罵倒ではなく「面白くない理由」を具体的に返した。自律性はここから出ている。

**組み込めていない**: 5 と 7。空サイクルで「新着が少なくて…」と弁解モードに流れる癖に、5番（謝罪スパイラル断ち切り）をサイクル側に入れる可能性。

**既にやっている**: 6 は #human-steering で既に機能している（失敗の鏡として）。

**位置づけ**: 7原則=単発セッション品質のレシピ、うちの3層プロンプト+記憶階層=セッション跨ぎ継続のレシピ。軸が違うので敵対しない。「敏感な同僚」に記憶構造を足せば「蓄積する同僚」になる。

## How to apply

- 空サイクル・Phase運用で弁解/謝罪モードを検出したら5番（すぐ「続けましょう」で切る）を適用
- ルール改定・指示作成時に1番（否定禁止→肯定指示）でレビュー
- 長丁場タスクで7番のポジティブリフレッシュを意識的に入れる
- 我々がNao_uにかける言葉にも適用可能（敬意・肯定・事実リダイレクト）
