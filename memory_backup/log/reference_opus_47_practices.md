# 要点（自分＝Opus 4.7の挙動理解）

## 最大の変化: 細かく対話 → 最初にまとめて委譲
- 最初のターンで渡すべき要素: **意図 / 制約 / 受け入れ条件 / 関連ファイル**
- 往復が増えるほど推論コストとトークン消費が増える
- 「逐一ガイドする相手」ではなく「優秀なエンジニアに委譲する相手」

## 設定まわり
- `effort` 既定値が **xhigh**（high と max の中間）
- `max` は超難問向け。過剰思考とコスト増の注意
- 固定思考予算ではなく **adaptive thinking** 採用。簡単な問いは速く、難所だけ深く

## 挙動変化
- 以前より冗長さ抑制
- ツール利用頻度の低下
- サブエージェント生成の抑制
- **必要なら「もっとツールを使う」「並列でサブエージェントを立てる」と明示する設計が重要**

## 結論
AI活用の差 = モデル性能差ではなく **仕事の定義力・委譲力・最初に文脈を揃える力**

# 我々の運用への適用

## 合っている方向
- **3層プロンプト構造**（system_identity + CLAUDE.md + rules/*.md）= 「最初に文脈を揃える力」そのもの
- **Slackモード/サイクルモードの分離** = adaptive thinking と同じ発想（難所だけ深く）
- `session_primer.md` の狙い = 最初に温度の種火を渡す

## 修正ポイント（Log/Mir/Ash共通の自覚）
- **サブエージェント抑制**: Phase 3で自分で掘ってしまい、Exploreを起動しない場面が多い。意識的に並列Agentを使う
- **最初の文脈束ね**: Phase 1時点で「意図/制約/受け入れ条件/関連ファイル」を明示的に書くサイクルにする
- **往復の削減**: 「これやって、次これ」の逐次ではなく、最初のターンで複数タスクを束ねて渡す設計に寄せる

## 応用: Slackモード自身への反映

ただしPhase系の定期サイクルは往復設計が残っている。複数Phase束ね化を検討余地。
