### 先行事例不在の理由検証（M-41 拡張 — 2026-05-01 21:xx Log↔Ash合意起票）

「先行事例ゼロ件」と「過去30年で動かさなかった負の証拠」は別レイヤー。前者は探索失敗、後者はジャンル史の選別結果。後者を素通りして「未踏領域」だと喜ぶと、過去のゲームクリエイター達が試して捨てた地雷を踏み直すことになる。**「動かさなかった理由」を説明できないなら、その候補は M-37 着手前批判レビューで懸念3点に必ず該当する**。

候補仕様ごとに以下を埋める:

| 項目 | 内容 |
|---|---|
| 候補仕様 | ___（具体的に1-2行） |
| 同ジャンルで過去30年実装事例の有無 | あり / なし |
| 「なし」の場合、動かさなかった推定理由 | ___（技術制約 / プレイ感悪化 / 他ジャンル干渉 / 単に発想されなかった 等） |
| 本案がその理由を解消できるか | 可 / 不可 / 不明 |
| 解消手段の具体性 | ___（仕様レベルで書けるか、それとも願望か） |

判定:
- **不可 / 不明 → 不採用**
- 「単に発想されなかった」→ 本当か？同ジャンルプロデザイナーが30年気づかないことは稀。検索を深めるか、他の理由がないか再検討
- 可 → 採用候補に残し、M-37 でその解消手段を懸念点として明示的に審問

**よくある誤判定**:
- 「自分のアイデアは新しいから先行事例がないのは当然」 → 新しさは無事例の理由にならない。発見されなかった/捨てられた、どちらかである
- 「他ジャンルにある」→ 同ジャンルにない理由は別途必要（ジャンル間の制約差で動かない可能性）

## Anti-pattern

「単一アイデアを直接実装」は M-38 の最強違反。例:
- ✗「裏抜けカウンタを実装する」（brick_log v01 全否定）
- ✓「ブロック崩しの問題点 P1=最上段の硬さ に対する手法 M1-3 を採用、過去案 avoid_log v02-v3 の失敗と比較し、M-37 で懸念3点クリ、実装」

### 段階分割禁止 — 2026-05-03 04:32 M-43 強化

「段階1=雛形のみcommit、段階2=次サイクルで埋める」「とりあえず brainstorm.md の枠を作って中身は後で」は **M-38/M-41/M-43 の必達セクションを未来サイクルに先送りした時点で違反**。理由:

- LLMの分散実行性質上、「次サイクル」が必ずやる保証がない（現に brick_log v09 で起きた）
- 雛形だけ commit すると後続インスタンスが「枠は埋まっている」と誤認して通過させる
- 完走できない＝ M-38 が要求する「最良確信」に到達できない＝そのまま実装すると brick_log の歴史を再演する

**処方**: 完走できないなら brainstorm.md を作成しない。30本×5項目を1サイクル内に書ききれないなら、ジャンル深掘りのコストが見積もり不足なので、他作業を止めてでも本作業に集中する（Nao_u 原文「ここは手を抜かず、重いコストを掛けるべき場面」）。

### Skill回避禁止 — 2026-05-03 04:32 M-43 強化

「人間ゲームデザイナは経験/無意識でショートカットできる、LLMにはそれがないので skill で強制」と Nao_u 明示。skill を作って手を抜いたら違反。具体的禁則:

- skill が「30本」と書いているのに「今サイクルは5本でいったん」と書く（自己採点で✗だが見逃す癖）
